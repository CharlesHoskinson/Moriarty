# Sherlock optimization lane 06 — chunking, fused microsteps and continuation storage

**Status:** proposal only; baseline Candidate A SHA-256 `57d830f46fee57c56ed8b854d21f5dd7a695d2977d061b1ef6905eaecd7de30e` verified. No architecture adopted, model/backend/proof executed or performance measured. Priority P2 after reference transition/cost and boundary interfaces are reconciled; specify the grouping adapter now. UIREQ-024 preserves outcomes/work and UIREQ-026 requires Lean/Clean correspondence. No private integration material is used.

**Source facts.** RISC Zero defines a session trace split into independently handled segments [R, “Continuations,” “Segment,” “Session”]. This illustrates trace segmentation, not financial settlement. SP1 describes instruction-indexed trace tables and shard proofs [S, “Shard Proofs”]; its proof-system design is not imported. Plutus's versioned budgeting source distinguishes CPU/memory, charges machine reductions and treats input-sensitive builtin costs separately [P, “Budgeting”]. These precedents suggest separating logical execution from physical proof organization; they supply no Sherlock cost result.

**Three alternatives.** Start with arbitrary technical cuts around unchanged reference steps and compact checkpoint storage. Compare fixed-capacity microbatches that realize several reference steps in one physical transition. Treat aggregation of already produced proofs as a separate backend option, subject to the existing native recursion/custom-decider interface. None chooses a foreign proof system, VerifyProof dependency or ledger10 prerequisite. Fewer physical steps/proofs are desirable only if total costs and complete outcomes improve under the same execution envelope.

**Proposed microbatch API.** `advance_m(machine,cutPolicy) -> {next,activeCount,stepLabels,logicalDelta,stopReason}` for fixed maximum m, initially comparison candidates1/2/4/8. Its meaning is the earliest reference terminal outcome or source-visible boundary encountered while realizing at most m reference computational steps. Technical cuts can end the group earlier without changing that machine state. Zero-cost publication/observation rules follow their reference precedence; padding occupies physical capacity but performs no logical work. `stepLabels` and intermediate-state correspondence are specification/diagnostic data, not a prescribed public statement or circuit implementation.

**Skipped-prefix outcome problem.** Computing only a final fused arithmetic result can skip an earlier exhaustion, return context or source boundary. If a run has enough fuel for two reference steps but not a third, a four-step group must expose the same two-step prefix and subsequent reference exhaustion outcome. It must not execute the fourth operation and charge retrospectively. A value with empty frames at zero fuel still publishes success under current K; other zero-fuel controls exhaust, while explicit errors publish. Stack-limit error4 remains that fragment's outcome until reconciled, rather than being normalized by batching. Reference costs and stopping positions are observable even when intermediate states are not serialized.

**Continuation image.** Compare a bounded flat frame vector with an immutable shared frame pool. Proposed checkpoint fields are control phase, expression/value reference, environment image, frame image/top, code/profile reference and remaining/consumed work, plus future pending/financial-prefix fields. Persist partial control such as scheduled push or pending return, not merely an expression PC. Compact wire encoding may omit unused capacity while the Clean image remains fixed-size. Reusing frame storage must restore the same lexical environment and pending operands; node IDs/storage layout are representation details, not source identity.

**Preservation predicate.** For admitted program/input and unchanged bounds, every grouped run must decode to a reference trace with identical outcome class/reason, structural result, ordered effects and financial boundaries, folded financial state, residual duties, pending/checkpoint meaning and cumulative reference work. Logical group cost is the sum of realized reference charges; a technical cut resets neither budget nor frame context. Pure chunking cannot create a financial commit. Future lowering must preserve existing `/2` typed-await successful-prefix effects/duties/checkpoint atomicity; exact universal Commit/Yield/Await opcodes remain OPEN. No new policy follows from batching.

**Required correspondence and gaps.** K defines the reference microsteps; Lean must define fuel-based iteration and the grouped-step decoding map. Clean needs separately bounded intermediate/control/frame encoding and the matching step interface before compiler/native integration. Existing ledger-9 custom-decider reuse is an interface premise, not measured integration. K pure has no waiting/finance; Quint's scalar15 factorial/list/tree abstraction has a pending-return checkpoint but no matching K wait or general evaluator. Their tick/fuel schedules differ. K helper lookup/matching/equality traversal is unmetered, so limiting m does not establish bounded physical work.

**Normal discriminators:** factorial3→6 cut before/after pending multiplication; tree45→9 cut while the right subtree is pending; list123→6 with different group sizes; exact-threshold fuel prefixes after independently freezing counts; Quint's pending-factorial-return/false-observation/resume specimen, labeled unmatched to K. Future `/2` prefix and two-segment financial witnesses remain adapter obligations, not executed evidence.

**Counterargument and measurement plan.** Larger groups may increase padding, peak witness/state memory, checkpoint latency and circuit rows more than they save recursive overhead. Compare m1/2/4/8, flat/shared frames and early-cut frequency using the same normal traces. Report logical work, active/padded steps, bytes, rows, proof count/size, prover/verifier time, memory and DUST separately. All measurements, native compatibility and correspondence results remain open.
