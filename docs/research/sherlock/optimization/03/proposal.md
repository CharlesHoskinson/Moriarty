# Sherlock optimization lane 03 — recursive data representation

**Status:** design proposal, priority P1 after the reference traversal/cost interface is frozen. Candidate A SHA-256 `57d830f46fee57c56ed8b854d21f5dd7a695d2977d061b1ef6905eaecd7de30e` was verified. No architecture is adopted, source changed, model run or cost measured. UIREQ-024/026 govern preservation and the required Lean/Clean stage. No private integration content is used.

**Source facts.** Lurk's historical 2022 circuit specification describes host interning, tagged references and a Merkle-DAG store [L, “Store implementation”]; this is a representation precedent, not a selected Sherlock hash scheme or equality operation. Aiken documents recursive lists, constructors/pattern matching and distinct `Constr`/list encoding choices [A, “List,” “Customizing Encoding”]. Clean's public `ProvableType` describes fixed-length field vectors, with `ProvableVector` and `ProvableStruct` interfaces [C, public-core receipt]. These sources motivate separating semantic data from storage; none supplies Sherlock correspondence.

**Alternatives.** Retain direct structural K trees as reference: they expose inductive meaning without an addressed store. Compare an immutable indexed arena with optional sharing as its implementation. Keep nested tree serialization as the baseline and packed arrays as a later dense-vector alternative. Sharing can reduce physical nodes while preserving all semantic occurrences. It is not automatically a reduction in logical work. Hash-consing is an optional host representation technique, not a new source primitive or selected circuit operation.

**Candidate interface, design only.** For fixed capacity N, propose `ArenaImage={format,usedNodes,root,nodes[N]}` and a fixed-size Clean `ProvableStruct`-style `NodeRecord={kind,limbs[4],child0,child1}`. Kinds cover UInt, Bool, Nil, Cons, Leaf and Branch. UInt stores four little-endian 32-bit limbs; Bool uses a scalar payload; Cons stores its UInt head inline and tail in child0; Leaf stores its UInt payload; Branch uses both children. This fits the concrete dedicated UInt list/tree fragment; it does not introduce nested lists or generic ADTs. Type-general records need another explicit layout.

Reference widths follow capacity: `w=ceil(log2(max(2,N)))`; count needs `ceil(log2(N+1))` bits. Proposed wire fields are format version, count, root, then active tagged records with specified limb/child order and zero-filled unused fields. Circuit records retain fixed capacity/padding; wire bytes need not contain unused slots. Field placement and actual packing remain open—four 32-bit limbs are a mathematical encoding proposal, not an existing checked UInt128 circuit. Layout versions and complete byte-cap admission must be explicit.

**Semantic decoding.** Define partial `D(A,i,T)` over finite well-typed arena images. UInt decodes to Σ limbs[j]·2^(32j); Nil to the empty UInt list; Cons to its inline head followed by `D(child0,ListUInt)`; Leaf to its payload; Branch to the ordered pair of recursively decoded children. Bool has its own type. In the proposed topological domain, child references precede their parent, so decoding unfolds finite terms. Multiple incoming references unfold multiple semantic occurrences. Node numbers and sharing disappear from the result. Outside the domain, decoding reports a distinct format/type/reference outcome; its implementation and separately owned acceptance requirements are not performance conclusions.

**Traversal and equality.** A fold visits each logical occurrence: sharing `t=Leaf(4)` in `Branch(t,t)` still sums two leaves. Structural equality compares constructor shape, ordered children and scalar contents, rather than allocation IDs. Any memoization must retain the reference's declared logical charges; a faster host comparison alone cannot change budget behavior. Current K validation/matching/equality helpers recurse outside semantic fuel. Record helper visits and physical work separately; adding per-comparison charges requires explicit cost-profile reconciliation, not a claim that today's fuel already meters them. Invalid-input diagnosis/cost is a separate inventory from admitted-program performance; no hostile scenarios are proposed here.

**Preservation predicate and stage.** For each admitted program/input and unchanged bounds, require identical outcome class/reason, structural result, ordered effects/financial boundaries, folded financial state, residual duties, pending/checkpoint meaning and cumulative reference work. Preserve intermediate stopping positions. Allocation order, node sharing and bytes may differ only through a declared representation map; tightening capacity/admission is a profile change. K→Lean must relate inductive values and fuel-based runs; Lean→Clean must relate those values to this bounded encoding. Circuit/native mapping and exporter compatibility remain open. No new Commit/Yield/Await semantics follows.

**Normal discriminators:** shared/unshared Branch(Leaf4,Leaf4)→8; Node(Leaf4,Leaf5)→9; list[1,2,3]→6; two roots sharing suffix[2,3], whose sums remain6 and5; equal trees built in different allocation orders compare true. Compare occurrence visits, reference work, pending frames and complete outcomes, not just results. These are unexecuted expectations.

**Counterargument and cost gaps.** Uniform records waste scalar/leaf fields, tiny trees gain reference overhead, and unfolded equality/serialization may dominate. Measure active/padded nodes, wire bytes, decoding, allocation/lookup work, rows, witness/prover memory, time and DUST separately. Every cost remains unmeasured; direct trees may win. Adopt no representation before those comparisons and the required correspondence work.
