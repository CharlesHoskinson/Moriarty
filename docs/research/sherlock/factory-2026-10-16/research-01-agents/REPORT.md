OpenAI’s Agents API guidance supports a narrow role for lower-cost Luna agents: delegate independent, bounded chores with a clear question and expected result, then have an expert coordinator integrate the output. It says each subagent has separate context, recommends keeping short or dependent steps in the main agent, and calls for coordination when agents edit the same files. The sample instruction limits each worker to its own release notes, specifies the fields to extract, and tells the coordinator to combine results without inventing missing details.

**Sherlock proposal (inference):** Let Luna handle read-only, independently scoped tasks such as locating a consumer/API path, extracting a bounded Rust/K/Quint/Lean example, or reporting one reproducible discrepancy. Each task card should state: one question; allowed files or evidence; required output fields and locators; and a stop condition. Route interface changes, shared-file edits, cross-layer semantics, proof claims, and native Midnight operations to expert ownership. The expert supplies only task-specific background and the relevant contract, then checks findings against the actual consumer and an independent oracle before integration. This is a small task-card policy, not a new scheduler or routine multi-vote gate.

**Limitation:** This page describes OpenAI’s Agents API, not Sherlock or Luna, and does not establish a best prompt length, Luna capability, correctness, safety, or performance gain. Its examples are guidance and API behavior, not evidence that the proposed division will work unchanged in Moriarty.
