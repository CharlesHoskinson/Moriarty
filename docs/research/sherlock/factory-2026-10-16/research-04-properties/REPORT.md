Hypothesis’ documentation distinguishes repeatable CI exploration from preserving a discovered failure: `derandomize=True` gives a stable generated set for a test until Hypothesis, Python, or the test function changes; a fixed seed reproduces cases only absent other nondeterminism. The example database replays failures, but is a cache whose entries can be dropped, so it is not a correctness guarantee. Use an explicit example for a durable regression. Shrinking is a separate test phase, and serialized reproduction blobs are version-specific and intended for temporary use.

**Factory proposal (inference):** Add one bounded, deterministic property-test target that generates small valid circuits and recursive inputs, runs each through the consumer-facing Rust path and an independently implemented evaluator, then compares the complete result: final state, emitted effects, and every execution prefix. On failure, persist the minimized circuit/input pair as a readable checked-in regression example; retain the seed and toolchain versions in the failure artifact for replay. Add a few metamorphic checks (for example, executing a no-op step preserves state and emits no effects) so some checks do not depend on cross-implementation agreement. Keep generated sizes and step counts bounded; run a fixed deterministic profile on commits and a larger varied profile separately.

**Limitation:** Differential testing only detects disagreement. If both paths share a semantic mistake, common parser/encoding, or generated expected values, they can agree on a wrong result. Metamorphic properties also cover only the relations encoded. Keep the oracle implementation and expected semantics independent where practical, and review regression cases as evidence, not proof of correctness.
