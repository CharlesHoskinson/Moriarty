# Lane 01: explicit CESK-style universal evaluator

Research predicate: a proposed machine can express a non-tail recursive tree fold, pause with pending return work, resume to the same answer, and execute tail recursion without adding return frames. This is a design proposal; no model or evaluator was executed.

**Source facts.** Might's author-written [CEK account](https://matt.might.net/articles/cek-machines/) separates control, environment and continuation; closures pair function code with the defining environment. His [CESK account](https://matt.might.net/articles/cesk-machines/) adds a store, maps variables to addresses, and uses explicit continuation application for return. Its `letrec` presentation allocates binding addresses before constructing closures in the extended environment. The [Lurk circuit specification](https://www.lurk-lab.com/blog/circuit-spec/) describes expression/environment/continuation pointers, tagged continuation variants and a persistent expression/continuation DAG. Its current page explicitly labels this a historical 2022 specification; it is architectural evidence, not evidence about today's implementation or Moriarty compatibility.

**Recommendation.** Define the universal machine as `M = (mode, control, env, heap, kont, budget, outcome)`, with modes `Eval | Return | Halt | Fault`. `control` holds either an expression reference or a returned value reference. `env : Name -> Addr`; `heap : Addr -> Object`, where objects include primitive values, tagged constructor nodes, closures `(codeRef, envRef)`, and continuation frames. `kont` is an address of an immutable linked frame, ending at `Halt`. Keep source AST, runtime data and addresses as distinct sorts. A recursive datatype is an inductive constructor signature; a runtime value is a finite graph satisfying that signature. Address indirection represents sharing and recursive function environments without infinitely expanding closure terms. Cyclic data requires a separate explicit language decision and is unnecessary for the initial tree demonstrator.

Call evaluates callee and arguments in a specified left-to-right order, then enters closure code under its saved environment extended with fresh parameter bindings. A non-tail caller retains its pending computation in defunctionalized frames such as `Arg`, `Let`, `Match`, `PrimLeft`, `PrimRight`. Return consumes exactly the top frame, restores its saved environment, and resumes its next operation. Tail call reuses the current continuation; it creates no extra return frame. Recursive calls use these same rules. For recursive closure groups, reserve all addresses first, then install closures whose environments contain the complete group.

Define language `eval` only if intended: evaluate its code operand to a validated AST value, evaluate an explicit environment operand, then enter that AST with the existing continuation. An omitted environment must have an explicit rule, preferably the empty environment; Lurk uses that convention. Reflective eval needs AST validation and a specified accepted grammar. A universal interpreter need not expose reflection merely because its own input is code.

**K and Quint.** K should model each machine transition, including intermediate argument evaluation, allocation, lookup, match, return, terminal outcomes and budget exhaustion. Suggested cells are `<control>`, `<mode>`, `<env>`, `<heap>`, `<kont>`, `<budget>`, `<outcome>`. Avoid a big-step host function that silently performs recursive evaluation. Quint can bound addresses, expressions and frame depth and check transition determinism, valid references, tail-call frame preservation and resume equivalence; this remains a finite abstraction with explicit correspondence gaps.

**Demonstrator.** `sum(Node(Leaf(2),Node(Leaf(3),Leaf(4)))) = 9`. During the first leaf return, retain `AddPending(rightSubtree, savedEnv, parentKont)`. After producing 2, evaluate the right subtree under `AddKnown(2,parentKont)`. Snapshot that state, resume, and require 9. Pair this with a tail-recursive list sum and require constant continuation depth relative to its caller.

**Counterargument and work split.** Direct recursive terms and K's computation stack simplify the first semantics; a SECD-style operand stack is another candidate. Explicit heap frames add allocation and reference obligations, but make persistent pending returns inspectable. Their usefulness does not establish circuit cost. Parsing, closure conversion and serialization are compiler/host work; constrained dispatch, object access, primitive operations and continuation transitions need separately specified native circuit support. No foreign proof-system port or VerifyProof prerequisite follows from this design.
