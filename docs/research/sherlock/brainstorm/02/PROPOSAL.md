# Lane 02: recursive data, specified-only candidate

**Recommendation.** Give the interpreter inductive tagged data and an immutable, shared DAG representation. Distinguish recursion in data, recursive function calls, and recursive proof composition. Existing ledger9 recursion is available without a VerifyProof prerequisite; this proposal adds no such prerequisite and assumes no foreign proof-system port.

**Source facts.** [Lurk's circuit specification](https://www.lurk-lab.com/blog/circuit-spec/) describes two-field tagged references, compound objects addressed through hashes, host hash-map interning, and circuit operations supplied with object contents instead of executing that host map. Its “Store implementation” explicitly calls the representation a Merkle-DAG. These are facts about the documented Lurk design, not measured properties of a Moriarty implementation. [Aiken's custom-types documentation](https://aiken-lang.org/language-tour/custom-types) presents lists as empty-or-head/tail linked structures, constructor pattern matching, and tagged `Constr` serialization; it also describes a list encoding that avoids a constructor wrapper for some records. Aiken is a functional smart-contract comparison, not evidence of a zk implementation. [NockApp's primary description](https://nockchain.org/writings/nockapp) identifies its application state as a noun, a binary tree of unsigned integers, transformed by a pure state/event function. That supports a small structural core as an ecosystem precedent, without importing its platform claims.

**Candidate algebra and representation.** Use scalar values plus declared constructor tags with zero, one or two child values. Define `Nil`, `Cons(head,tail)`, `Leaf(value)` and `Fork(left,right)` as ordinary declarations; nested lists need no new primitive. Lower constructors with more fields into binary products, recording the lowering in the compiler manifest. Keep source type/constructor identity distinct from the runtime scalar/node tag. A value is an immediate scalar or a typed structural reference. Host storage maps immutable local handles to bounded-width nodes and interns repeated structures. The circuit-facing reference is a tag plus a structural digest; its exact encoding/hash remains a separate native design choice. Local handles are not portable addresses.

**Explicit policy.** Sharing is permitted and observable only through cost, not pointer identity: two edges may reference the same immutable node. No mutable cells, pointer casts, forward references, or cyclic data in the initial language. Constructors accept already-created children; external data enters in topological order. Recursive function bindings are code/environment machinery, not permission to build cyclic data. Equality must be specified separately: scalar/tag comparison is primitive; arbitrary structural comparison is a fuel-charged traversal unless a later digest-equality contract is adopted.

**K and Quint.** Proposed K terms are `imm(s)`, `ref(l)`, `node(t,children)`, `construct(t,args)`, and `case(ref(l),arms)`, with `<k>`, `<env>`, `<heap>`, `<nextLoc>`, `<kont>`, `<fuel>`, and `<limits>` cells. One constructor transition allocates/interns one node; one case transition reads one node and selects its tag arm. K should expose allocations and reads rather than silently copying an entire tree. Quint can use four locations, two scalar representatives, a finite constructor set, bounded continuation frames and fuel. `Allocate`, `ReadCase`, `Return`, and `Exhaust` retain repeated child IDs, making sharing explicit. This finite lifecycle abstraction omits digest arithmetic, arbitrary depth and general type checking; no correspondence or checking result is claimed.

**Implementation boundary and demonstrations.** Compiler work covers constructor tables, exhaustiveness/type checks and match lowering. Runtime work covers interning, serialization and accounting. A universal circuit needs bounded node construction/destruction and tag dispatch in addition to existing scalar operations; whether native facilities already supply them is uninspected. List sum, tree fold, map, append and flatten remain library programs. Specify ordinary tests for sum `[1,2,3]=6`, empty sum, a two-leaf fold, nested `[[1],[],[2,3]]`, shared-subtree reuse, invalid tags and allocation/fuel exhaustion. These tests are unrun.

**Counterargument.** Tags, references, interning tables and node records can outweigh small payloads; binary lowering adds allocations, while hash computation may dominate short traversals. Packed arrays may be better for dense financial vectors. Retain them as a later representation alternative, and compare total bytes/allocations/steps before selecting this candidate. No measurements or security conclusions are supplied.
