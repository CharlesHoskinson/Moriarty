# Lane 07 — Recursive values and matching, first design wave

**Proposal, not selected architecture.** Start with a small expression interpreter whose values are finite immutable inductive data and whose functions can recurse over proper subvalues. Lists, nested lists, binary trees, options, and records must work without a program-specific unrolling depth. Do not make the first demonstrator a new blockchain VM or a full UPLC, Aiken, Michelson, or OCaml port.

The three primary captures suggest a useful separation. Aiken presents custom variants, record destructuring, exhaustive `when` matching, and lists as empty/nonempty alternatives. Its “Customizing Encoding” section separately explains constructor tags, ordered fields, explicit `@tag`, and a list encoding alternative. Therefore source names and declaration order cannot silently define a universal wire ABI [Aiken](https://aiken-lang.org/language-tour/custom-types#customizing-encoding). UPLC’s current term declaration contains `Constr` with a `Word64` tag and term list, plus `Case` with branch vectors; “Supported case-expressions” distinguishes sums-of-products from evolving builtin matching [UPLC source](https://plutus.cardano.intersectmbo.org/haddock/master/plutus-core/src/UntypedPlutusCore.Core.Type.html). Michelson documents list/option operations, records and sums encoded through annotated pair/option/or components, and a recursive-lambda example [Octez](https://octez.tezos.com/docs/active/michelson.html#field-and-constructor-annotations). These are representation examples, not an equivalence claim.

Use a typed declaration layer: `List<A> = Nil | Cons(A,List<A>)`, `Tree<A> = Leaf(A) | Node(Tree<A>,Tree<A>)`, `Option<A> = None | Some(A)`, and single-constructor records. Lower them into one generic runtime constructor form `ctor(typeId, tag, orderedFields)`, with primitive integers/bytes and an immutable declaration table fixing tag, arity, and field types. A K draft could instead give every constructor its own syntax production; that makes small examples readable but expands the semantics per datatype. Prefer the generic option for source-language generality while retaining type checking before execution. Type identity must qualify tags: `None` and `Nil` may both use zero without becoming interchangeable.

Specify strict constructor fields evaluated left-to-right and evaluate only the selected match branch. Labels lower to declaration-indexed fields even if source construction spells labels in another order. This is a proposed core policy, not inferred UPLC semantics: strict Haskell AST fields in the captured implementation are not evidence of object-language evaluation order. An adapter must preserve its source’s effects, errors, laziness, and evaluation order explicitly. OCaml-like variants fit the declaration vocabulary; full OCaml compatibility remains unresearched in this three-source lane.

Give values structural equality and no observable pointer identity. Sharing may be an implementation choice, but cannot change results; logical traversal charges follow occurrences until a separate accounting design says otherwise. First-version inputs and constructors describe finite acyclic trees, including repeated equal subtrees. Cyclic graph values and identity tests are outside the value language; an eventual graph decoder must report unsupported cyclic inputs rather than invent a fold result.

Proposed K cells are `<k>`, `<env>`, `<decls>`, `<kont>`, and `<result>`; continuations represent pending field evaluation, match selection, recursive calls, and fold combination. Structural-recursion validation permits calls on constructor children and list tails. Quint should abstract tags, bounded child indices, traversal stack, remaining fuel, and running/returned/error status. It can check that no parent completes before its pending children and that terminal states do not resume. Finite bounds do not establish arbitrary-depth recursion or full K correspondence.

Demonstrate `sumNested([[1,2],[],[3]]) = 6` and a tree fold `Node(Leaf(2),Node(Leaf(3),Leaf(5))) = 10`, including empty lists, both tree branches, and a record containing `Some(tree)`. Expected initial work is interpreter semantics and frontend/host lowering. No circuit-change conclusion follows before mapping these transitions onto the existing native interface. Counterargument: generic tags relocate mistakes into declarations and decoding, whereas dedicated typed K constructors expose shape directly. Keep both representations in the review; freeze the small semantics before the later optimization wave.
