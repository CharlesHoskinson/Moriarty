# Candidate 03: explicit frames and bounded small steps

Draft proposal; architecture research only. No machine, model, prover, native backend or repository product change was executed. Security evaluation belongs to Opus. This proposal does not depend on VerifyProof or ledger10.

Cairo illustrates a small custom ISA: `pc`, allocation pointer `ap`, and frame pointer `fp`; CALL saves the previous frame pointer and return PC, and RET restores them. Its instruction encoding is compact, although importing its field arithmetic, unified memory and write-once discipline would introduce unnecessary correspondence work [Cairo, Registers; Instructions and Opcodes]. Wasm offers the better semantic vocabulary: explicit call frames hold return arity and local/module context; labels carry branch continuations. The specification permits separate operand/control/call stacks when their stack-height bookkeeping remains explicit [Wasm, Stack; Labels; Call Frames]. Neither requires an interpreter implementation to recurse through an entire source-language call in one machine transition.

RISC Zero documents sequential RV32IM execution, aligned code/memory access, code/heap/stack in guest memory, and ECALL dispatch. Its current page contains contradictory legacy wording about privileged modes followed by a user/kernel split: do not inherit that ambiguity [RISC0, Execution Model; User/Kernel Split; Memory Layout; Memory Model]. SP1’s shard documentation describes instruction-indexed trace tables and consistency with RISC-V and global memory [SP1, Shard Proofs]. Borrow the separation of instruction dispatch from global execution state; adopting their CPUs, toolchains, proof formats or foreign recursive verifiers is unnecessary. The attempted RISC Zero continuations page returned 404, so this lane makes no detailed current segment-format claim. A program return continuation and a segment resume snapshot should be distinct specification types regardless.

Candidate Moriarty machine: immutable `code : PC → Instruction`, eight typed word registers, bounded arena of immutable tagged nodes, operand/local slots, and explicit frame vector. A frame contains `(returnPC, savedLocals, resultSlot)`; the active context holds `(pc, locals)`. Initial instructions: CONST, MOVE, ADD, EQ, LOAD_FIELD, BRANCH_ZERO, JUMP, CALL, RETURN, HALT. Arithmetic uses an explicitly selected finite word width and overflow rule. Node allocation is host input preparation initially; no guest allocator, byte addressing, floating point, indirect calls or full CPU are needed for the two demonstrations.

Every transition fetches and dispatches exactly one instruction. CALL pushes one frame and starts the target with explicit argument slots. RETURN pops one frame and installs one result. Neither instruction recursively executes its callee/caller. A run of arbitrary eventual depth consists of many finite transitions; the bounded demo separately sets maximum frames, nodes and fuel, and capacity exhaustion has a specified terminal status. Segment suspension, if later needed, preserves the complete machine state without changing the guest call stack; resume is not guest CALL.

For recursive data, use arena node IDs with `Nil | Cons(value,next)` and `Leaf(value) | Branch(left,right)`. Immutable DAG sharing works naturally. Nested serialized trees avoid address machinery but require decoding rules; mutable linear memory enables general programs but expands aliasing and write semantics. Start with arena reads and make traversal explicit: summing Cons(2,Cons(3,Nil)) produces 5; evaluating Branch(Leaf(2),Branch(Leaf(3),Leaf(4))) by recursive sum produces 9. Both are normal programs in the same instruction set and exercise branch, call, local preservation and return. The tree demo must retain its left result across the right call.

Proposed K cells: `<code>`, `<pc>`, `<locals>`, `<frames>`, `<arena>`, `<fuel>`, `<status>`, `<result>`; one computational rule per instruction plus explicit terminal rules. Quint uses bounded maps/sequences for those same components and actions dispatch/call/return/halt/exhaust. Correspondence requires each Quint dispatch action to match one K transition; mathematical K values versus bounded words and capacity are stated gaps. This is not correspondence to older experimental Core/4 models or Rust Core/2.

Host/codegen work: assemble instruction vectors, encode arena inputs, produce reproducible traces and expected outputs. New native transition constraints, memory/state commitments and dispatch integration are separate future circuit work; a K draft alone does not supply them. Counterargument: a custom ISA loses Rust/Wasm compiler reuse and risks permanent adapter maintenance. Keep the initial encoding deliberately small and assess instruction/trace expansion before choosing it over a restricted Wasm frontend.
