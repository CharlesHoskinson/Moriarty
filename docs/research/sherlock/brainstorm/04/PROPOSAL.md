# Lane 04: explicit closure machine, typed lowering boundary

Status: first design-wave proposal; specified-only. No source profile/version is selected; stable /1 and /2 remain untouched. No K/Quint execution, backend execution, proof claim or security verdict accompanies this note.

**Source facts.** Plutus's published CEK implementation separates values (`VCon`, `VDelay`, `VLamAbs`, `VBuiltin`, `VConstr`), environments and continuation frames (`FrameAwaitArg`, `FrameAwaitFunTerm`, `FrameForce`, `FrameConstr`, `FrameCases`); its budget spender is an explicit parameter [P]. OCaml's pinned interpreter has distinct `CLOSURE`, `CLOSUREREC`, `APPLY`, `APPTERM`, `RETURN`, `RESTART` and `GRAB` cases; `CLOSUREREC` places several code entries beside shared captured values [O]. Michelson specifies sequential stack transformations and fixed stack types, while its recursive-lambda example uses `LAMBDA_REC` and `EXEC` [M]. These observations motivate alternatives; they establish no correspondence to Moriarty.

**Candidate recommendation.** Specify a deterministic CESK reference machine first, with immutable term/code tables and explicit store addresses. Candidate terms are `Const`, `Var(index)`, `Lam(body)`, `App(fun,arg)`, `Let(rhs,body)`, `LetRec(functionGroup,body)`, `Constr(tag,args)`, `Case(scrutinee,arms)`, `Prim(op,args)`, `If`, `Perform(effect,args)`, `Return` and `Fail(reason)`. Evaluation is left-to-right call-by-value. Frame variants distinguish function, argument, let, branch, constructor-field and primitive-argument evaluation; a terminal result, rejection or exhaustion has no successor. One transition performs one named semantic operation; collection traversal requires explicit cursor steps.

**Program/data representation.** A canonical envelope contains format identity, semantic profile identity, typed constant pool, constructor declarations, code blocks, entry block and declared bounds. Numeric code indices replace host pointers. Heap nodes are `Scalar(value)`, `Node(tag,fieldRefs)`, `Closure(block,envRef)` or `RecEnv(capturedRefs,blockVector)`. Each recursive closure refers to its group environment plus function index, avoiding an unspecified host-language fixed point. Letrec initially admits function RHSs only; strict arbitrary recursive values need a separately specified initialization/error policy. Constructor arity, references, bounds and canonical serialization need explicit judgments; a digest alone establishes none of them.

**Concrete competing bytecode.** A small typed stack IR could use exactly `CONST(c)`, `LOCAL(i)`, `BIND`, `UNBIND`, `CLOSURE(block,captures)`, `REC_GROUP(blocks,captures)`, `CALL`, `RETURN`, `CONSTR(tag,n)`, `CASE(arms)`, `PRIM(op,n)`, `BRANCH(t,f)`, `JUMP(block)`, `EFFECT(kind,n)`, `FAIL(reason)`, `HALT`. Blocks carry input/output stack signatures and environment layouts. Primitive and effect enums are closed, versioned tables, not arbitrary host callbacks. Start with unary functions; multiargument syntax lowers to nested lambdas/applications. Recursive calls load the appropriate group closure. Ordinary let lowers to RHS, `BIND`, body, `UNBIND`; function return restores its caller environment explicitly.

**Compiler contract and Moriarty expansion.** Alpha-renaming and closure conversion preserve binding, argument order, returned values, explicit rejection, effect order and resource observations through a stated simulation relation. Typed IR validation checks every block edge and capture layout. `UInt(width)` remains width-tagged; checked arithmetic, comparisons, division-definedness and conversions follow the eventual selected source profile, never field arithmetic by accident. `Bool` remains its own tag and branch requires it. Effects expand beyond pure evaluation into a typed ordered journal carrying authority, nonce, financial deltas, fees and residual duties; phase commit/rejection rules must be specified separately. This work requires compiler/host representation changes; constrained instruction dispatch, range checks, heap access and journal transitions would require new circuit relations, whose implementation is outside this lane.

**Models and demonstrators.** Proposed K cells: `<control>`, `<mode>`, `<env>`, `<store>`, `<kont>`, `<program>`, `<effects>`, `<fuel>`, `<bounds>`, `<status>`. A total decoder chooses exactly one transition or explicit malformed-state rejection. Quint abstracts bounded block/closure IDs, tag/arity, stack depth, fuel, journal length and lifecycle status. Preserve step labels and terminal outcomes; abstract numeric contents and financial deltas only with explicit gaps. Demonstrate captured-variable shadowing, factorial with exhaustion, mutual even/odd recursion, list fold, malformed capture, and an effect followed by rejection.

**Counterargument/open choice.** Bytecode removes AST dispatch but adds verifier, compiler and environment-layout obligations. CESK retains a larger syntax yet exposes binding and evaluation order directly. Select neither as the deployed representation before comparing concrete traces and accounting contracts. No optimization wave is attempted here.
