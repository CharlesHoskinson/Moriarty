# Sherlock lane 08: rebuild execution families and cost-aware chunks

**Status: research proposal, specified-only.** Candidate A freeze SHA256 `57d830f46fee57c56ed8b854d21f5dd7a695d2977d061b1ef6905eaecd7de30e` remains the comparison baseline. Read design, model coverage, required Clean stage and optimization05/06/10. This adds fresh online implementation evidence to those proposals; it adopts no architecture and supplies no execution, benchmark, theorem or security judgment. Four primary families support independently rebuilding organization algorithms. No proof-system port is necessary: the existing Midnight native IVC/custom-decider route remains the integration premise.

**Source facts: finite execution families.** [Arecibo's SuperNova implementation](https://github.com/lurk-lang/arecibo/blob/8997d733aa69c3b6db5a44e06f7c0f74ad315d6f/src/supernova/circuit.rs#L46) exposes `StepCircuit.arity`, `circuit_index`, and `synthesize(pc,z) -> (next_pc,next_z)`. `NonUniformCircuit` enumerates families through `num_circuits`/`primary_circuit`; `mod.rs:405–415` sizes a shared commitment key from the largest member. This is concrete organizational precedent, including shared maximum-size overhead. The SuperNova paper PDF was blocked; no full-paper reading is claimed.

**Source facts: grouping and padding.** The [Nexus January2024 paper](https://nexus-xyz.github.io/assets/nexus_whitepaper.pdf), §1.3 and Figure5/PDFpage7, describes optional dedicated instruction components. Separately, [current Nexus source](https://github.com/nexus-xyz/nexus-zkvm/blob/f2ad12652c39dc516a116447a53f8557f64a7f7d/vm/src/trace.rs#L60) provides `UniformTrace{k,blocks}`, `BBTrace`, `split_by(n)` and `k_trace`. Lines299–301 explicitly distinguish padding from executed instructions. Historical paper architecture and current implementation are distinct evidence; neither establishes Sherlock costs.

**Source facts: cost vectors and shape selection.** [Current SP1](https://github.com/succinctlabs/sp1/blob/02fa30185ecd658174b211d56128b14867ab8e81/crates/core/executor/src/vm/shapes.rs#L25) tracks per-component heights/costs, total trace area, maximum height and preprocessing overhead. `check_shard_limit:240` compares both area and height, conditioned on its own commit flag. `ShapeCluster.find_shape` selects allowed component heights covering observed heights. Its [architecture draft](https://github.com/succinctlabs/sp1-ef-whitepaper/blob/80fe297ea3ab6a79ca14526aa36303ad2c99eb59/vanillaVM-W1/w1-vanilla.tex#L127) describes contiguous execution shards and instruction tables. Preserve dissent: that repository's README calls the vanilla material illustrative, while PROJECT.md describes SP1 adaptation. Use source implementation for these narrow engineering facts; upstream thresholds and commit semantics are not Sherlock defaults.

**Source facts: separate session and segment storage.** [RISC Zero source](https://github.com/risc0/risc0/blob/3bbcd44d6459b9ef6ac0df3846dc9215514934e8/risc0/zkvm/src/host/server/session.rs#L40) distinguishes Session, Segment and pluggable `SegmentRef.resolve`. It records rows, padding and instructions separately; execution-time documentation explicitly excludes memory-image hashing. Fresh documentation recaptures extend older optimization05/06 citations with actual pinned source rather than merely reusing their captures.

**Recommendation: P1, rebuild a common dispatch interface** (optimization05/10; UIREQ-001/010/023/024/026):

```text
Family = Schedule | Scalar | CallBind | FrameReturn | DataMatch
FamilyStep(state, programView) -> {next, ruleId, logicalCharge, stop}
ChunkPlan = {family, capacity, layoutVersion, physicalBudget}
ChunkResult = {next, activeCount, referenceRuleIds, stop, costVector}
```

Classify by control phase and top-frame tag, including pending pushes/returns, rather than source opcode alone. Keep one bounded state envelope and common decode interface across families. First author the rule-to-family table and intermediate-state expectations independently of realization code. Then implement one-step family adapters using the existing reference schedule. Required Lean semantic definitions and separately bounded Clean representation remain development tasks in the existing private integration destination; no private contents were accessed.

**Recommendation: P2, independently rebuild prefix-preserving superinstructions** (optimization06; UIREQ-004/012/013/016/024). Recognize reusable sequences such as literal scheduling followed by operand-frame handling, or scalar return followed by its pending continuation. Define each sequence as up to m reference transitions, initially m1/2/4/8. At every internal position apply the original outcome/fuel/frame-cap precedence, record actual charges, and stop at the earliest reference outcome or source boundary. Final-value publication and explicit errors remain observable at zero fuel; stack-cap error4 retains its current meaning. Padding contributes physical capacity only. Do not replace a sequence with final arithmetic and retrospective charging.

**Recommendation: P2, rebuild cost-aware layout selection and streaming** (optimization05/06/10; UIREQ-014/015/016). Maintain a vector of component events, estimated rows, maximum component occupancy and snapshot bytes. Select the smallest configured layout covering the realized prefix, reserving finalization capacity; calibrate Sherlock coefficients later. A technical cut exports the complete control/environment/frame/value image and unchanged cumulative budgets through `ChunkStore.put/get`. Resume preserves caller locals, pending operands and work counters. Cost estimates select organization; they never manufacture reference exhaustion. Unmetered lookup/equality helpers prevent claiming that m alone bounds physical work.

**Comparison and counterargument.** Family crossings, maximum shared state width, shape inventory, padding and snapshot I/O may outweigh smaller components. Compare per-program, universal and fixed-family realizations over identical normal reference traces, including factorial pending multiplication, tree pending-right-call, caller-local restoration and two distinct function tables. Equality requires matching decoded intermediate prefixes, first outcomes/reasons, exact work and frame depth. Future financial comparison additionally retains ordered effects, fees/gross debits, committed prefixes, duties and existing `/2` await boundaries; chunking creates no financial commit. Pure K lacks that extension and Quint's Waiting abstraction is unmatched.

Adoption requires lower stated complete-path cost with equal observations. Separately measure preparation, host execution, helper visits, allocation/I/O, active/padded rows, degree, keys, memory, native composition/proving/verification, checkpoint latency and endpoint DUST. All are unmeasured. Rebuild the algorithms independently; backend differences and observed licenses do not discard the concepts. No external code is proposed for copying.
