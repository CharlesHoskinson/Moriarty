# Lane 09: general recursive constructors and ordered match plans

**Recommendation — P1:** independently rebuild a declaration-driven ADT elaborator and a small match-plan IR before specializing constructor layouts. This is a source-grounded proposal, not an adopted architecture, implementation, execution result, or cost winner. It extends optimization 02’s indexed program image, 03’s immutable arena, and 04’s explicit frame/environment mapping. Candidate A’s dedicated UInt list/tree forms do not already implement arbitrary nominal declarations. UIREQ-007/008/022/026 remain open at that boundary.

**Fresh source facts.** Maranget’s [ML’08 paper](https://cambium.inria.fr/~maranget/papers/ml05e-maranget.pdf), §§2–4, defines ordered clause matrices, constructor specialization/default decomposition, occurrence paths, and decision nodes `Leaf/Fail/Switch/Swap`. Decomposition retains row order; the selected action belongs to the first matching row. Decision trees avoid repeated tests of a subterm, but can expand code. Its measurements concern its compiler/configuration, not Sherlock. The paper deliberately abstracts arm bodies to action numbers; it does not supply Sherlock’s strict evaluation or fuel semantics.

At [OCaml commit ccd44ad7e24c0604462700caefa8cb07928ed7ab](https://github.com/ocaml/ocaml/tree/ccd44ad7e24c0604462700caefa8cb07928ed7ab), `typing/types.mli:585–660` separates type declarations, nominal constructor IDs, ordered arguments, and representation choices. `typing/typedecl.ml:1276` processes declaration groups; `typing/datarepr.ml:101–153` assigns constant/block tags and arities. `lambda/translcore.ml:294–318` lowers constructor applications. `lambda/matching.ml:16–88` documents ordered precompilation, specialization, switches and fallback chaining. This is implementation evidence, not an instruction to copy OCaml’s runtime or evaluation conventions.

At [MLton commit 5fe943391e539a502699327a6266b6e8e97939e1](https://github.com/MLton/mlton/tree/5fe943391e539a502699327a6266b6e8e97939e1), `mlton/match-compile/match-compile.sig:56–68` exposes constructor-to-type and type-to-constructor callbacks plus arm-building callbacks. `match-compile.fun:734–755` chooses column zero and finishes the first all-wildcard rule; lines 879–935 distribute constructors/wildcards with an ordered fold. `mlton/backend/rep-type.sig` separately exposes widths, sequences, sums and object references. **Proposed APIs — recommendation.** Use these as reviewable specifications:

```text
TypeDecl { nominalId, parameters, recursiveGroup, constructors[] }
CtorLayout { nominalId, ctorId, tag, fields:[{fieldId,type,slotKind}], width }
MatchPlan { sourceMatchId, scrutineeType, nodes[], entry, armTable, workMap }
PlanNode = Switch(occurrence, cases, default) | Bind(binderId, occurrence, next)
         | Select(sourceArmId, bodyExprId) | NoMatch
```

`TypeDecl` is semantic; `CtorLayout` is profile-specific. Begin with closed monomorphic nominal groups, including mutual references. Parameterized declarations need a separately bounded instance/monomorphization pass; finite source text alone does not ensure finite specialization. Keep source constructor IDs distinct from compact tags. A finite program has finite declaration/layout tables while recursive values require explicit arena capacity, depth/frame and scalar bounds; no finite table magically bounds recursive data.

**Rebuild sequence — recommendation.** First assign stable declaration, constructor, field, binder and expression-occurrence IDs; resolve recursive groups and field types. Second emit a plain tagged-node layout with inline exact UInt128/Bool payloads and typed child references; reconstruct semantic finite trees by unfolding references. Third compile ordered patterns to a first-column baseline using specialization/default matrices, preserving every row’s source index. Generate bindings from occurrence paths, then enter only `Select`’s arm body. Fourth experiment with alternative test columns and shared plan suffixes only after retaining the baseline as an independent comparison target. Keep mutable values, closures, GADTs and or-pattern extensions outside this first adapter’s stated coverage.

**Exact mapping obligations — specified only.** Constructor frames evaluate fields strictly left-to-right, once, before allocation; `CtorLayout.fields[i]` denotes source field `i`, irrespective of packing. Match evaluation first completes the scrutinee once. Selection returns the minimum matching source arm index, binds its declared fields in a fresh arm environment, and restores the saved caller environment on exit. Plan switches inspect completed immutable values; they cannot execute arm expressions or move constructor-field evaluation. Structural identity compares nominal type, constructor, ordered children and scalar contents, never node addresses or sharing.

Occurrence keys are `(sourceMatchId, sourceArmId, fieldPath)`, not arena indices. `workMap` relates optimized switches/bindings to an ordered reference-event cursor, retaining original stopping positions and existing fuel charges. If a reference match traverses the same shared child through two paths, record two logical occurrences. Sharing physical tests never silently removes reference charges. Candidate A’s pure helper traversal is currently outside semantic fuel: record helper visits separately until an explicit versioned schedule resolves this gap; do not retroactively invent charges. This supplies concrete UIREQ-022 obligations and the UIREQ-026 inductive-value/bounded-table interface inventory, without claiming correspondence is established.

**Normal discriminator — unexecuted.** Add `Schedule = Done | Pay(UInt128,Schedule) | Both(Schedule,Schedule)`. Ordered arms `Both(Pay(x,_),_)→x; Both(_,r)→sum(r); Pay(x,t)→x+sum(t); Done→0` return **4** on `Both(Pay(4,Done),Pay(5,Done))`; only arm one executes. A separate structural sum returns **9**. Shared and separately allocated `Both(Pay(4,Done),Pay(4,Done))` both sum to **8**, with both occurrences retained. These examples require a genuinely new declaration, nested pattern and frame layout, rather than another dedicated tree primitive.

**Cost predicate and dissent.** Compare direct ordered matching, baseline plans, heuristic trees and shared plans on identical admitted programs/inputs/bounds: preserve complete outcomes, selected arms, ordered evaluations, structural results, reference work and suspension positions. Measure preparation bytes/work, plan nodes, physical tag reads, arena reads, frame high-water mark, host time and later actual target cost separately. Adopt a variant only when its measured benefit exceeds an explicitly chosen preparation/capacity budget. Direct matching may win for small or rarely used matches; decision-tree expansion and reference-work cursor maintenance can erase gains. Prioritize semantic tables and baseline plans P1; heuristic ordering, unboxing and packing P2.
