**Fresh source facts and the useful differences.** [Clean current public source](https://github.com/Verified-zkEVM/clean/tree/1a6c28426372bb99af79e533aa7b9a0788eff0d7) is pinned independently of the earlier local comparison checkout; that comparison identifier was not verified as a public upstream pin. `ProvableType` fixes `size` and provides `toElements/fromElements` (`Clean/Circuit/Provable.lean:16`); `ProvableStruct` and `ProvableVector` provide structured fixed shapes. `FormalCircuitBase.main` and `InductiveTable.step` are component/transition interfaces. Critically, basic operation JSON discards witness computation, while `Operations.witgenJson?` includes structured programs and rejects native closures (`Json.lean:53`, `WitnessExport.lean:136–175`). WitnessIR's U64 arithmetic wraps; this is no ready-made exact UInt128 implementation. Circom's `processOps` explicitly refuses lookup/interact (`Backends/Circom/R1CS.lean:80–81`). Current README lists PLONK custom gates and Plonky3 support for generalized tables as further work. These are distinct export surfaces, not interchangeable backend support.

[Clap's 2024 paper](https://arxiv.org/html/2405.12115v2), §II/Figs2–3, separates circuit trace generation, constraint generation and tabulation: `gen_trace`, `gen_cs`, `tabulate`. §VI describes inlining and gate conversion; §VII's evaluations concern its Rust/Boojum hash configurations, not Sherlock. The authors report a compositional Agda-model theorem conditional on component properties; no theorem is assessed here and no result transfers to Sherlock. The [current clap-lean repository](https://github.com/Clap-lang/clap-lean/tree/c1a92e7877bb037d1e3cce802dc5c84007bbcc35) explicitly calls the paper old Rust work and describes its Lean compiler as work in progress. Actual `Circuit.toCs`, `Circuit.toWg`, `Wg.run` are in `Clap/Compilation.lean:308–370`; `R1Serialize/R1CS.lean:121,256` serializes R1CS and witnesses. The paper's Plonkish custom-gate story cannot be assumed to describe this current serializer.

[zkLean's public source](https://github.com/GaloisInc/zkLean/tree/014fa397fa30e60964310dc2ff5d70aeed3c8022) supplies a complementary import-oriented architecture: `ZKBuilder = FreeM ZKOp`, with equality/R1CS, materialized/MLE lookups and RAM operations (`zkLean/zkLean/Builder.lean:24–43`). `Semantics.lean:35–105` interprets these primitives against supplied witnesses/state. Its README and [Galois's March2026 article](https://www.galois.com/articles/zklean-a-dsl-for-zk-statement-verification) describe Jolt extraction and LLZK interchange, and separate SHA3 specification/circuit/proof modules. The README notes binary-operation components in another fork; importer coverage and concrete LLZK revisions were not independently acquired here. A primitive in this DSL is not evidence that a Sherlock/Midnight exporter realizes it.

**P0 recommendation/inference — freeze a small export inventory first** (optimization07/09/10; UIREQ-022/023/025/026). Borrow Clap's separation, not its whole compiler. Proposed modules:

```text
Semantic/{Syntax,State,Step,Run}
Representation/{Bounds,Layout,Encode,Decode}
Circuit/{StepComponents,StepTable}
Export/{ConstraintPlan,WitnessPlan,BackendCapabilities,Manifest}
```

One integrator owns `compileStep(layout,component) -> ConstraintPlan × WitnessPlan` and `emit(backend,plans) -> ArtifactBundle | UnsupportedFeature`. Manifest records exact public component source membership, layout/version, field, ordered inputs/outputs, operation inventory, witness-program kind, emitted format and source locations for each translation. Keep actual private integration evidence privately. Record lookup, interaction, custom-gate and witness-IR support separately. Basic constraint JSON cannot stand in for a witness plan. Unsupported output is a named engineering result, not a portable artifact. This extends optimization07's host schema and optimization09's mechanical inventory without generating the semantic oracle.

**P1 recommendation/inference — give the bounded image its own API** (optimization09/10; UIREQ-001/006/007/009/010/012/013/026). Keep recursive Lean list/tree meanings and fuel-run separate from `MachineImage bounds F`. Define fixed vectors for code, nodes, environments and ordered frames; include control, tags, active lengths, counters, outcome and explicit scalar layout. Expose `encode : SemanticState -> Option MachineImage` and `decode : MachineImage -> Option SemanticState`, with a separately named relation to the reference state. Clean's `ProvableType` can supply flattening; it does not choose arena capacities, UInt128 encoding, structural sharing meaning or helper granularity. Start with a scalar/frame step and the existing independent normal examples, then extend component coverage. All cross-layer obligations remain unproved.

**P2 comparison and counterargument.** Retain Clean as the required stage; inspect Clap for compilation split and zkLean for importer/module boundaries before borrowing code. A second IR/importer creates maintenance and conversion work; complete replacement would duplicate the required Clean path. Direct Clean components may therefore be cheaper to maintain than a general interchange layer. No timing winner follows from the sources.
