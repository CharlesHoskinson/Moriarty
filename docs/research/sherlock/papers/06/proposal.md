**Proposed API, inference and recommendation:**

```text
prepare(program, profile, encoding) -> ProgramImage + OperationManifest
advance(ProgramImage, MachineImage) -> StepRecord
plan(StepRecord, LayoutSchema) -> WitnessIR + ConstraintSliceId
evaluate(WitnessIR, InputBindings, CacheScope) -> CandidateRow + HostDiagnostics
emit(ConstraintSliceId, BackendCapabilities) -> ConstraintArtifact | Unsupported
stream(artifact, rows, publicBindings) -> ResourceManifest
```

`ProgramImage` preserves original function-table order, first-match lookup behavior, source membership and layout version. `StepRecord` names the exact reference rule/site, complete pre/post logical states, ordered frames and environments, outcome, fuel/work and capacities. It is not merely the final result. `OperationManifest` gives every lowered operation a domain, ordering, witness dependencies, constraint-component locator and explicit unsupported status. Initial names include FieldAdd, FieldMul, AssertZero, LimbExtract, CheckedU128Add/Sub/Mul, Select, ArenaRead and FrameRestore. Checked arithmetic, arena/frame operations and helper-cost mapping require new Sherlock components; no source supplies them automatically.

Lower only serializable structured Clean WitnessIR; report native closures as unsupported export. Keep constant/layout preparation cached separately from input-dependent values. Scope dynamic caches by exact program/profile/encoding and immutable input bindings; retire entries after their last consumer, borrowing CirC scheduling and SIEVE lifetime ideas. Streaming rows does not imply bounded prover memory: report parser buffers, live values, retained frames and backend allocation separately. Caches preserve occurrence-based logical work even when physical computation is reused.

A host predicate such as `rowGenerated`, `referenceResultMatches`, or `cacheHit` belongs in diagnostics. The constraint interface instead identifies actual emitted polynomial/lookup components and backend capabilities. Unknown plugins, black boxes, lookup/interact export, unsupported fields, checked UInt128 lowering and financial suspension mapping remain explicit omissions until inventoried. Exporter `Unsupported` is a tooling outcome, not a reclassified A exhaustion. None of these formats establishes Clean-to-Midnight/ZKIR compatibility or a proof-system port.

**Independent rebuild plan.** Reimplement a small typed dependency DAG and stable topological scheduler for structured Clean WitnessIR, a last-use counter with an instrumented row sink, and separate witness-evaluation/constraint-emission visitors. Keep operation semantics in manually reviewed component definitions; generate only tags, field layouts and source-locator tables under optimization09. Preserve independent semantic fixtures rather than generate their expected results from that DAG. This borrows concepts without requiring upstream code or backend adoption. Licenses matter if actual code is copied; backend mismatches identify adapter work, not a reason to discard these methods.

**Priority, counterargument and measurement.** P0: deterministic uncached plans and operation coverage; P1: dependency scheduling and streaming; P2: cache/lifetime tuning. Additional IRs can duplicate maintenance and serialization costs, so initially borrow interfaces rather than adopt a compiler stack. A later falsifiable predicate compares complete decoded StepRecords, outcomes, work and caps across uncached/cold/warm paths for all eight frozen examples, two programs reusing function IDs, and pending tree-right traversal. Compare preparation time, witness time, copies, bytes, peak live values/RSS and I/O separately from circuit rows/degree, proof/key bytes, native time/memory and DUST. No improvement is measured; independent expectations precede execution.
