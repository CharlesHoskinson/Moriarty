**Fresh source facts: CakeML paper [S1].** Gómez-Londoño et al., OOPSLA 2020, analyze space at DataLang after earlier call optimizations, obtaining frame sizes from later compilation. Sections 2.3–2.5 explicitly explain why a uniform source-level cost would be imprecise. Their semantic clock supports evaluating potentially divergent programs; it is not a promise to preserve a particular caller-supplied fuel threshold. Section 5 records stack maxima, including helper calls for structural equality. It warns that local-environment size is insufficient to predict physical frame size and that a tail call can increase physical stack usage when the callee has a larger frame. This supports a separate physical-resource description, not substitution of CakeML's clock or resource outcomes for Sherlock's.

A `layoutFrame(functionId,continuationTag)` returns physical slots and byte counts; `decodeFrame` still reconstructs Candidate A's ordered frames and saved maps. Every old charged rule still costs one reference unit. A helper-metered schedule receives a new schedule identity. Additional input or arena caps explicitly narrow the admitted profile. The manifest is reporting and specification data, not evidence that any missing capacity bound has been established.

**P2 inference, mapped to optimization06/09.** Extend the rule inventory with `ReferenceSlice = {orderedRuleIds, prefixWork, boundaryPositions}`. A grouped physical operation may associate a separate target-cost estimate with this slice. Before each reference charge it checks remaining fuel and logical frame caps, publishing the earliest reference outcome. A single cost label for an entire fused group cannot recover an interrupted prefix. Retain prefix locations or defer fusion. This preserves Sherlock's schedule while using CerCo's provenance idea; it does not reuse CerCo's costs or assume additive circuit rows.
