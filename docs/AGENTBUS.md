# AgentBus in DoctorWatson

Date: 2026-10-22. Status: source implementation with observed synthetic validation; source publication and live activation remain separate evidence. AgentBus is optional coordination, shared from ProjectFenrir `tools/agentbus`; Moriarty adds only [agentbus_adapter.py](../models/doctorwatson/agentbus_adapter.py).

Use the assigned shared run, separate DID identity binding and existing checkout. Context/review helpers do not need a new branch/worktree merely to communicate. The lead/operator provisions any binding with `FENRIR_SPIKE=/home/charl/Moriarty fenrir-spawn new --run R --as helper-1 --role helper --existing-worktree /home/charl/Moriarty` and supplies its printed startup environment. `AGENTBUS_IDENTITY_DIR` selects the external identity root; invalid explicit bindings must not become the checkout owner's identity.

`FENRIR_SPIKE` must explicitly name the absolute canonical main repository root; the existing checkout must share that repository Git common directory. Use a task-owned `FENRIR_WT_ROOT` if the lead assigns a binding root, and narrow `--claims` to the assigned canonical file prefix when file claims are needed. Invalid or missing repository mapping refuses before provisioning. 

For an authorized live task, use `agentbus doctor`, `agentbus recv` and `agentbus claims --mine`. Source-only review does not access live inboxes, identities or services. Claim an assigned shared file before mutation, save its `hold` and deadline, and pass the original `hold` to `agentbus renew RESOURCE --hold HOLD` and `agentbus release RESOURCE --hold HOLD`. A queued response or timeout is not granted. Claims are run-local advisory coordination, not cross-run exclusion or filesystem fencing. Old token-omitting clients retain legacy behavior.

Record the task/attempt/source base, changed paths, checks/outcomes and limits in canonical evidence before sending a public handoff. The adapter's typed schema `doctorwatson.agentbus.advisory/1` admits `handoff`, `source-ready`, `review-ready`, `blocked` and `claim-lost`. It correlates run, task, attempt, fingerprint, integration base and sender; stable event IDs distinguish retries from new application events. Only a current advisory can request `inspect-canonical-state`. Duplicate/stale/invalid messages have no action.

The five adapter functions are `make_notice`, `classify_notice`, `publish_notice`, `claim_owned_files` and `cleanup_retention`; see their checked keyword signatures in the module. There is no new CLI command, daemon or scheduler. Publishing is a single injected `send`, with explicit disabled/published/unavailable outcome. Published means transport acknowledgement, not recipient acceptance. Owned-file validation occurs before claim effects; partial failures preserve grant receipts and uncertainty. Use the grant's `hold`, never substitute a renewal command's `request`.

DoctorWatson plans, attempt history, source fingerprints, local CI, reviews, integration records and Git remain authoritative. A bus message cannot execute another attempt, adopt a review, complete a task, close EARS or authorize cleanup. After timeout, claim loss or unavailability, preserve work, stop the affected shared mutation and reconcile canonical state through the authorized lead path. Do not automatically repeat ambiguous mutations. Missed notices are recovered by ordinary canonical inspection.

An active observed claim can add positive worktree retention. The adapter always returns `leases_known=false`; an empty, expired or stale snapshot cannot establish inactivity or full inventory across providers/runs. Independent canonical inventory must establish cleanup completeness. `fenrir-spawn reap` revokes/retires the identity and preserves checkout files, branches and registrations; it is not a deletion command.

Broker restart may lose queued undelivered traffic under the existing memory-backed session configuration. Local inbox/log persistence covers records accepted locally. QoS 1 permits redelivery, so stable IDs and canonical correlation remain necessary. DIDs attribute keys, not a model/vendor identity; same-UID processes are not isolated. Peer content remains untrusted data, and messages/references contain no credentials, recovery material or private evidence. Lint is not a complete secret detector.

Shared documentation and EARS live with ProjectFenrir's AgentBus source: `README.md`, `SKILL.md`, `docs/DOCTORWATSON.md` and `openspec/changes/agentbus-refinement/`. [The dated design record](../wiki-llm/agentbus-design-2026-10-22.md) explains the selected boundaries. [Adapter tests](../models/doctorwatson/test_agentbus_adapter.py) use fake transports and synthetic observations; passing them does not establish host activation or native/proof acceptance.

Observed refinement validation: 177 shared AgentBus offline tests, 264 Moriarty factory/adapter tests, bounded Quint checks and a full bounded fuzz campaign passed. Exact source pins, counts and limits are in the [shared portable results](https://github.com/CharlesHoskinson/projectfenrir/blob/main/tools/agentbus/docs/audit/refinement-20261022/RESULTS.json). This does not establish live service activation or native/proof acceptance.
