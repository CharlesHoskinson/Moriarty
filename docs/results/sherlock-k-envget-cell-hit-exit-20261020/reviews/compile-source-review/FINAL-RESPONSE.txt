### Checks that pass

- **State carriers and field map**
  - `egSnapshot(Admission, RunId, CSOwnedState)` keeps admission and run identity as whole immutable `EGJSON` trees.
  - `ctRoot` is used with its 17 positions consistently: control, origin, env root, stack limit, outcome, initial fuel, remaining work, consumed work, helper work, helper visits, reference cursor, alloc, active, segment active/alloc/consumed, and frames at `arg16`.
  - `dpTables` maps data, data fields, env, and value slots in that order.
  - `csHelperTables` maps helper, result, and tasks in that order.
  - All 23 image fields in the supplied mapping are therefore represented, including raw frames.

- **Cell transition**
  - It requires `EnvGet` with `chTriPending()`.
  - On the stated hit premise, `egHitRef(chIndexSome(Index), Binder, Tables)` selects `dpEnvCell(Binder, Value, _)` from the env table and produces `chRefSome(Value)` with `chTriPositive()`.
  - Cursor, common record, binder, result, tasks, tables, admission, and run ID are retained.
  - This matches the supplied owner `env_get_cell` hit branch: set `found`, set status Positive, retain cursor and other helper fields.

- **Exit transition**
  - It requires `chTriPositive()` with `chRefSome(Value)`, clears the helper, and writes `chSomeResult(chResultEnvFound(Value))`.
  - Tasks and all unrelated state are preserved.
  - This matches the supplied owner `env_get_exit`.

- **Owner charges**
  - `egChargeRoot` is the same root update for both rows: remaining work −1, consumed work +1, helper work +1.
  - Cell adds helper visits +1; Exit adds helper visits +0.
  - Reference cursor, alloc counters, frames, outcome `ctRunning()`, control, origin, env root, and all other root fields are retained.
  - This matches the normative Cell base deltas `[-1, 1, 1, 1, 0, …]` and Exit base deltas `[-1, 1, 1, 0, 0, …]`.

- **Events: all 28 fields, in order**
  - Both events use `egStepId(RunId, Consumed)` from their own prestate. For Exit, that is the after-Cell consumed value, which is the correct Exit prestate ordinal.
  - Cell: Cell rule, `HelperVisit`, `EvalVar`, `EnvGet`, `Applied`, work/helper-work/visits/reference-cursor deltas `1/1/1/0`, zero alloc deltas, zero value-slot writes, unchanged depth and task count, phase Pending→Positive, cursor Some→same Some, no result tag.
  - Exit: Exit rule, `HelperExit`, `EvalVar`, `EnvGet`, `Applied`, deltas `1/1/0/0`, zero alloc/value-slot changes, unchanged depth and task count, phase Positive→none, cursor prestate cursor→none, `EnvFound` result tag.
  - Both use the live helper common `origin_reference_cursor`, not the root reference cursor, in accordance with the supplied current event-ABI bridge.
  - Both use `control_origin` as `source_expr_id` and derive source occurrence from `admission.view.occurrences[control_origin]` plus the exact `occurrence_paths[start:start+len]` slice.
  - Both use no exhaustion, Running outcome tag/payload, and no boundary, matching a post-state that remains Running.

- **Linked window and laws**
  - `egTwoEventWindow` computes Exit from the computed after-Cell state, rather than independently reconstructing it.
  - The three UNRUN laws are general preservation/join predicates, as claimed. They are not treated here as an independent finite oracle or observed test result.
