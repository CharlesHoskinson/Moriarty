## 1. The two changed items: literal deltas (B044–B047)

### `prepare_core` (B045)
There are exactly three changes:
- dedicated `Match` rows gain `plan: None`;
- parameter sorts and return types pass through `TypeIdC::from_source_sort`;
- `ProgramView` gains 11 extension tables, each initialised to `Vec::new()`.

None of these touches the parts that carry the predicates:
- C1 preorder traversal and occurrence-row allocation;
- C2 child slots, filled by iterating `child_ids` in argument order;
- C3 arm and pattern order;
- C4 occurrence paths;
- C5 function and parameter table construction, which enumerates `p.functions` in source order, keeps every row, and only interns names through the sorted, deduplicated name table;
- C6 literal constants;
- the representation of calls as `Call{function_name, args}`.

`from_source_sort` takes only a `SortTag` and has no access to the program or any image, so it cannot evaluate anything. The builtin sorts map to type ids 0–3. This follows from the current checker: dedicated views use `n_types = 4`, constructor constants must have `type_id.0 >= 4`, and `decode_source_sort` matches the four builtin constants.

### `check_program_view` (B047)
Every addition falls into one of three groups:
- **Generic diversion.** An `is_generic` branch diverts to `check_program_view_ext`.
- **Rejections of extended content in a dedicated view.** These cover a match plan, `Construct`, `Wildcard`, `Constructor` patterns, constructor constants, and sorts ≥ 4.
- **Checks `prepare_core` output already satisfies.** These are the `params ≤ max_arity` check, the return/parameter sort range check, and the orphan-pattern check.

For any `prepare_core` output, all 11 tables are empty, `plan` is `None`, and no extended rows exist. The generic branch is therefore unreachable on the dedicated routes.

For dedicated views, the original checks are retained:
- V2 child ordering and the single-parent rule;
- V3 owner and path equality;
- V4 contiguous parameters and function-root checks;
- V5 `patterns == arms`;
- V7 strictly ascending names, no unused name;
- the V8 round trip `view == prepare_core(decode(view))`.

The delta adds no function-name uniqueness check, no reordering, and no evaluator call.

### Observation
Ops 15/16 directly observe both changed items on these programs:
- admission succeeded;
- both the wire projection and the independent projection equal the frozen `program_view`;
- each of the 11 tables is asserted empty by `empty_table` before projection.
