# Verdict: ACCEPT, with conditions

The source is correct for this finite cohort. Compile/link is eligible now. Capture is eligible only after the conditions below. I found **no mandatory source defect** in the Rust consumer, the Python glue (all three imported files) or `financial_projection.rs`.

## Source findings

**`sherlock_core2_boundary_capture.rs`**
- It reads each input once. It parses the scenario and selection with `mori_core::json::parse` followed by `serde_json::from_value`, decodes the event with `stage::decode::event`, and loads the program with `stage::load`. Any failure returns `Err` before anything reaches stdout, so it fails closed with no partial capture.
- `input_record` hashes the same strings that are parsed. The recorded bytes are therefore the consumed bytes.
- Resume is reached only by matching on `start.raw_result()` = `Ok(Waiting{continuation,..})`. Its continuation is a clone of the start-returned one. No caller, expected or synthetic continuation can enter, and a non-Waiting start publishes `resumePublication: null`.
- The partial moves out of `selection` are legal because `Selection` has no `Drop`. `case_id` is still used after the moves, which is fine.
- `Selection` deliberately lacks `deny_unknown_fields`, so the annotation keys are ignored. A misspelled optional key would silently become `None`. I verified that `startCap`, `resumeCliAction` and `resumeCliCap` are spelled correctly. The cap actually used is also visible in `financial_observation.input.Start.cap`, so any slip would show up as a mismatch.
- Output is `serde_json::to_writer` followed by LF. The LF forces a LineWriter flush and its error propagates. An explicit `flush()?` would be an optional nit.

**`financial_projection.rs`**
- `publication()` matches the contract's G4 envelope field by field (Waiting/Complete/Rejected top level, `financial_observation`, `await_prefix`, labels).
- The `ProducedInvocation` private fields mean the same-call relation holds structurally.
- The exhaustive destructuring matches the catalog.
- False Waiting maps to `NoPublishedSegment`/`NoAdvancedSegment` with `published_segment: null`. No synthetic Execution is created.

**Python glue**
- The `_row` field sets match every serialized declaration: FinancialObservation, AwaitPrefixObservation, Segment/Execution/Step/Statement/Effect/Snapshot/Continuation/Logical.
- `canonical_bytes` (sort_keys, compact, `ensure_ascii=False`, lowercase `\u00xx`, slash unescaped) equals contract C(x) for this ASCII cohort. Byte equality keeps `true` distinct from `1` and `1.0`.
- Whole-publication equality runs on the raw parsed capture and does not depend on the normalizer's output.
- For the false-resume B06 side, the only nullary tag reachable is `NoSegment`, which is in `Q_NULLARY`.

## H2/H3/H4/H6: the cohort can be captured unchanged

I don't have the H-item texts, so this disposition is against their stated themes (scalar, unit, diagnostic, provenance) and the supplied source. It is a nonowner finding. If Root's process requires the designated owner's own record, this does not substitute for it.

- **H2 (scalar):** Every scalar is small and canonical: UInt 0/5/23/37/64, Bool false, u8 scale, u16 site and index. Nothing is near the u128 bounds and there are no noncanonical forms or floats. The only scalar risk is fail-closed: whether `UInt`'s Deserialize accepts an owned string through `from_value`. If it doesn't, the run errors before Start and publishes nothing.
- **H3 (unit):** Every expression is a single `Name` node. There are no binary, And/Or or shared ExprIds, no cache-hit subtleties, no CLI cap, and the stored cap is comfortably above any plausible total for this three-statement action. Unit-rule ambiguities are not exercised. Any divergence surfaces as a comparison mismatch, not as a pre-capture blocker.
- **H4 (diagnostic):** The cohort is success-only. Error text is never compared. Any rejection or load failure is a mismatch and must be recorded as one, never skipped.
- **H6 (provenance):** Same-call binding comes from `ProducedInvocation` plus the consumer's sum elimination. Input identity comes from the in-capture SHA-256 of the consumed bytes. Authentication, consumption and binary attestation stay out of scope and depend on Root's pins.

**Admission premises.** I walked the inputs against the contract's admission premises qualitatively and found no violated premise:
- Lexical cohort and identifiers: no keyword collision.
- Scenario state and types: exact match.
- Asset identity: declared.
- Liability rows: both names exist in the source-wide registry via the uncalled `declareDuties`, with matching identity, ascending order and zero-row retention.
- R4/R5 for `gate(ready: Bool)`: satisfied.
- Trace cells and emission size: trivially within bounds.

This is not an independent establishment. Byte-level lexical facts (no TAB, CR or non-ASCII) must come from the prefreeze record, not from rendered text.

## Limits (not mandatory)

- **Comparator coupling:** Core-only whole-publication equality cannot be computed without a Quint ITF, because `--quint-itf` is dereferenced unconditionally. A normalizer exception also suppresses the whole-equality booleans. Both behaviours fail closed and lose diagnostics only.
- **`json.loads` on the expected file** accepts duplicate keys (last wins) and NaN. Root should record that the expected document is well-formed under the contract's types. Equality alone does not establish this.
- **Expected-file envelope:** the comparator requires `startPublication`/`resumePublication` keys. A schema mismatch surfaces as a KeyError after the freeze and needs a reviewed adapter, not a fix to the actual capture.
- **`hash_bytes` output** may be hex or a byte array. Compare it in whatever representation it actually has.
- **Adopted-contract copies:** `publication/REFERENCE-CONTRACT.md` and `PUBLIC-WIRE-DECLARATIONS.txt` must be byte-identical to the ADOPTION pins (43087 B `5b7309…`, 15097 B `ce5586…`). The body's stale "not adopted" status text is superseded by `ADOPTION.json`.
- **Still open:** Error/rejection cases, broader lexical, scalar and unit cohorts, authentication, consumption, financial, native, proof and target questions, and EARS closure. Nothing here infers full runtime, admission or financial correctness.
