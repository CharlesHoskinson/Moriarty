## 2. Source verdict: ACCEPT, scoped to H2 Core Bool `_scalar` only

**Diff identity.** Comparing Body 1 to Body 3 by eye, the only difference is the two guard lines in the Bool branch. Every other function is text-identical, including `_uint`, every caller, `quint_typed_wire`, `Q_NULLARY` and `main`. The hunk line numbers check out against the preimage: `def _scalar` is line 39 and the `UInt` check is line 41. Both the author's `-39,7` header and the selected `-41,6` header are correct.

**Semantics against Core serde (Body 5).**
- `Value` is adjacently tagged with `deny_unknown_fields`, and `Bool(bool)` is the Bool variant. serde_json accepts only a JSON `true` or `false` for that variant.
- Python's `json.loads` maps exactly those two values to `bool`.
- `type(x) is bool` is exact, and Python does not allow subclassing `bool`. So the guard accepts exactly what the Rust side accepts and rejects everything else: `int`, `float` (including NaN and Infinity from `json.loads`), `str`, `None`, `list` and `dict`.
- This fixes a real defect in the preimage. Because `1 == True` in Python, the old code passed through `{'BoolValue': 1}`, and that value compares equal to `{'BoolValue': True}`.

**Ordering is unchanged.** `_row` still raises its shape error first. The `UInt` branch and the unknown-type `raise` behave exactly as before. The returned object is the input `bool` itself.

**Idiom.** The guard matches the style of `_uint` (`type(value) is not str`) and the decoder's `tag == 'BoolValue' and type(value) is bool`. Its error message also follows the existing style.

**All callers.** Every caller of `_scalar` now gets strict Bool checking:
- `_named` (frame captures, continuation captures, prefix captures)
- `_snapshot.state` (pre/post/boundary/committed_boundary/step snapshots)
- `_effect` State `before`/`after` and Emit `value`
- `_step.value` via `_option`, where `None` becomes `'NoScalar'` before `_scalar` is called

Real Core serde output never contains a non-bool Bool payload, so genuine producer output should behave the same as before. Full caller compatibility remains **UNESTABLISHED**, as the scope already states.

### Mandatory findings

None of these blocks this slice.

- **F1 (scope).** The Quint path (`quint_typed_wire`) passes `BoolValue` payloads through without a type check. This is part of the still-open H2 Quint work.
- **F2 (pre-existing, H4).** `_row` accepts any iterable whose set of elements equals `{'type', 'value'}`. A list `['type', 'value']` therefore reaches `value['type']` and raises `TypeError` instead of `ValueError`. Similarly, `_input_decl` raises `KeyError`. Both are untouched by this change.
- **F3 (pre-existing, H4/H5).** Duplicate-key JSON is resolved last-wins by `json.loads`, which may not match serde's duplicate-field handling. This is untouched.

Conditions, which the operator must meet:
