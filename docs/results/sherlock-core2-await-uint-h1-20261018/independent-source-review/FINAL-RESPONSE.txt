## Semantic assessment of `_uint`
It is equivalent to the Rust `UInt` deserializer (Body 4). Both accept exactly `"0"` ∪ `[1-9][0-9]*` with value < 2¹²⁸, from a JSON string only.

- **Non-string inputs:** `type(value) is not str` rejects int, bool, float, None, bytes and list. JSON yields exact `str`, so excluding subclasses is fine.
- **Digit check:** `isascii() and isdigit()` together are exactly ASCII `0-9`.
  - Empty string fails `isdigit`.
  - Non-ASCII digits (`\u0661`, `\uff11`, `\u00b2`) fail `isascii`.
  - Sign, whitespace, `_`, `.`, `e` and `x` fail `isdigit` before `int()` can be lenient about them.
- **Leading zeros:** the check matches the Rust `s.len() > 1 && starts_with('0')`.
- **Range:** `>= 1 << 128` is the correct bound. `int()` keeps full precision.
- **Callers:** every UInt site routes through `_uint`: `_scalar`, `_balance`, `_liability`, the `_effect` Transfer/Fee/Liability arms, `_logical` (cap via `_option`, committed), all three `core2_result` arms, and `core2_await_prefix.attempted`. `_error` offset/step still use `int` (H2, open). The Quint path does not use `_uint`; `decode_itf` yields `int`, so the representations align.

## Non-blocking findings and limits
- **N1. Rejection of `'9'*5000` does not exercise the range branch.**
  - On Python ≥ 3.11 (or a security backport), `int()` raises `ValueError` from the 4300-digit `int_max_str_digits` limit instead.
  - The test only checks for `ValueError`, not the message. The range branch is therefore discriminated only by the 2¹²⁸ and 2¹²⁹ cases. This is still adequate, including against `>` vs `>=` mutants.
  - Suggestion: pre-check `len(value) > 39` and use `assertRaisesRegex`.
- **N2. Mutation discrimination is otherwise good.**
  - The old `return int(value)` fails many subtests: `'00'`, `'-1'`, `' 1'`, `'1_000'`, `'\u0661'`, `0`, `True`, `1.0`, `b'1'`.
  - Dropping `isascii` is caught by `\u0661` and `\uff11`.
  - Dropping the leading-zero check is caught by `'00'` and `'01'`.
  - Dropping the type check is caught by `b'1'` (accepted) and `0` (AttributeError).
  - An off-by-one bound is caught by the MAX and 2¹²⁸ cases.
- **N3. The tests exercise only the private `_uint`.** No caller-integration assertion exists; caller coverage rests on review alone.
- **N4. Callers now reject inputs they previously coerced.** That includes JSON numbers. The prior 54298-byte fixture and the six tests were not supplied and are not replayed, so consumer-level regression or compatibility is **unestablished**. This is not a defect of the cut, but it must not be claimed.
- **N5. H2–H6 remain open and unwaived.** That covers `Bool` values, `index`/`site` fields, `Error` integers, unit shape, diagnostics parity (messages differ from Rust), canonical comparison, and provenance.
