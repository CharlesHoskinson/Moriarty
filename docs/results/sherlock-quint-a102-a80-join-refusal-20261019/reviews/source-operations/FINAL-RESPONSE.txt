## (1) Source disposition: **APPROVE**

This covers `literalJoinRefusal.qnt` and `literalJoinRefusalTest.qnt`, as model-only, same-author, source-exposed consistency evidence within the declared UInt7/context[17,29]/fixed-shape domain. It is not production correspondence, admission, security, or EARS/SCON closure.

### Verified basis

**`literalStartAllowed`**
- Pins `programImage == uintProgram` and `contextLimbs == contextInput`.
- Requires the existing `initPremise`, which includes `fuelNumber(fuelBytes(init)) > 0`, remaining == initial, byte range, the Machine::new root lanes and all-zero tables.
- For `zeroFuelInitial = initFor(zeros)`, every conjunct except `fuel > 0` is identical to `uintInit`. So the refusal is attributable to fuel alone.

**`completeJoinAllowed`**
- Shape guards come first, with lazy `if … else false`, so no `nth`/`slice` runs on mis-shaped input.
- Then it checks, in order:
  - the start premise on `left.before`;
  - `left.program == bound` and `right.program == bound`;
  - full structural `Image ==` between `left.after` and `right.before`, covering root plus every allocated row, including inactive rows;
  - fuel byte ranges (lanes 9..40) on all four images;
  - the unchanged B20 `relation` over bound/left.before/left.after/right.after and both child envelopes.
- No digest, active-prefix or renumbering substitute is used.
- `relation` never reads `right.before` or either child Program. The only conjuncts sensitive to those inputs are the explicit equalities, so they are what make those inputs non-ignored.
- This matters because the UInt8 and UInt7 programs share Expressions row 0. Under F2/N4, `relation` cannot distinguish them; only the explicit program equalities can.

**Charge distinction (checked directly)**
- `literalStepChecked` requires `checkedLiteralReady`, which re-applies `literalStartAllowed` to `states[0]`. That state is A102's pre, so the guard requires fuel > 0. This matches `literal_step.rs`: the gated `all_zero == 0` refusal, the bytewise borrow chain, and `charge == 1`.
- `checkedPublicationReady` re-checks the *origin* premise. It range-checks `states[1]` and requires `states[1] == literalAfter(program, states[0])`. It places **no** fuel > 0 condition on the middle state, so there is no blanket current-fuel guard on A80.
- This matches the composer and bridge:
  - `done_rem == mid_rem`;
  - `expected_mid_rem = init − RULE_CHARGE` only;
  - a total-charge constant;
  - the step2 envelope, whose admission text reads "step-2 wire tag 0 with charge 0 (line 80)";
  - `complete_representation` accepts init fuel ≥ 1 with middle = init − 1 and done = middle. For init fuel 1, that means A80 runs at middle fuel 0.

**Quint semantics (bodies 018–022)**
- `then` raises QNT513 if its first action is false.
- `expect` raises QNT508 if its action is false or its predicate is false, then restores the snapshot.
- `actionAll` restores the snapshot on the first false conjunct, so `initWith`/`literalStep` are never evaluated after a false guard.
- Eager `fail` is `!bool`. It produces no successor.
- The negative tests assert the complete input `execution`, then end at `fail()`, with no post-fail state read. This is consistent with the supplied fragments.

**Syntax and type risk**
- Every annotated operator has a return type. This was the B20 r01 defect, and it is absent here.
- Block, record-spread, trailing-comma `all {}` and multi-line `and` forms all mirror B20 forms that previously passed.
- No new top-level name collides with any name imported from Images, Inputs or JoinRefusal.
- Lambda and parameter names are unique, so there is no repeat of F5-style shadowing.
- Both new files are direct mains in operations 1 and 2, so the N1 dropped-import-error path does not apply to them.

### Non-blocking findings (no change required for this approval)

- **J1 (LOW): envelope exactness uses the B20 named constants.** The positive test checks envelopes against `literalEnvelope`/`returnEnvelope`, not handwritten `{ruleTag:3,charge:1}` and `{ruleTag:0,charge:0}`. The constant values are visible in pinned, unchanged body 002. A future hardening could add literal equalities.
- **J2 (LOW): "exactly one scalar" is not asserted at runtime.** It holds by construction: `replaceCell`/`changeTableCell` change at most one in-range cell, and `≠` proves at least one changed.
  - `stateMutantNames == List(…)` is a self-tautology; names bind to mutants only by source position.
  - A single fold means a failure would not identify *which* mutant failed. Under fail-stop, diagnosing a failure would need a new reviewed proposal.
- **J3 (LOW): the bound-Program rejection is overdetermined.** Both the pin to `uintProgram` and the two child equalities reject it. The left and right tests do isolate the child equalities individually.
- **J4 (LOW): A80 grounding is indirect.** `return_publication_step.rs` is not in this package, so "no fuel guard inside the A80 emitter" is grounded by the composer and bridge equations and constants, not by the child body. I do not withhold on this, because the three designated modules suffice for the composed-path charge0/fuel0 claim.
- **J5 (LOW): EARS mapping overclaims.** The phrase "reject … every213-cell intermediate" holds at the predicate level only. The tests sample 8 single-cell `right.before` mutants plus one Constants-cell Program mutant. They include no `left.after`, `right.after`, envelope or context negatives.
- **J6 (INFO): end-of-run behavior is a premise.** What happens after a terminal `fail()` with unassigned next vars depends on `Evaluator.test` and the trace recorder, which were not supplied. This is the documented use of `fail()`, and any mishandling would fail closed (error or failed status), not produce a false pass. The same holds for the eager-builtin left-propagation wrapper, which was also not supplied.

## (4) Remaining limits (unchanged by this review)

- **Model-only seam.**
  - The B20 unchecked `init`/`initWith`/`literalStep`/`step` remain enabled at zero fuel.
  - The checked actions are not wired into any init/step simulation entry, so the refusal is a property of the checked actions only.
  - It is not A84 `Exhausted(Fuel)`, line-84 startup exhaustion, or terminal/error precedence.
  - The domain is pinned to `uintProgram`, so Bool/fuel256 cannot use the checked path.
- **Join predicate.** The explicit pair join is a new model predicate, not a Rust API; Rust aliases its intermediate. The predicate has no independent initial-state argument, no returned-state argument, no explicit charge-sum argument, and no first-discontinuity reporting. Those are SCON-007 elements, and they remain open.
- **Sensitivity gaps.**
  - F2 and N4 are retained: valueRef (0,0) and exprId 0 make selection/copy/publication insensitive, and UInt8 vs UInt7 differ only through Program equality.
  - Arena preservation vs zeroing remains insensitive in a normal run from an all-zero Init. The inactive-cell mutants test join equality, not transition preservation.
- **Expectations.** They are same-author, source-exposed and copied from B20 test source. They are not a blind oracle and have not been compared against production or ITF.
- **Host and tooling.** N1 still applies to Images/Inputs, which are never mains. Node, loader, OS and dependency semantics are premises. The installed manifest is pinned but not semantically audited.
- **Not established:** general uiValid, admission or ranges; source/context authentication; StepInv, OBL.G4, prepareA or projectA; the other 37 rules and dispatch; recursion, native, ledger or stagenet; finance F01/F02; whole EARS/SCON; any actual PASS.
