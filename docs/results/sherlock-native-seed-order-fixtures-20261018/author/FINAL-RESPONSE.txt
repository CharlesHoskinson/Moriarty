## 2. What the fix changes

**Root cause.** The seed replaced every file's mtime with one of two normalized tiers:
- build scripts and markers at …010 s;
- deps and fingerprints at …020 s.

That inverts real build-dependency edges. Each build-dependency rlib ended up newer than the script binary that depends on it.

**Supplied actual archive data shows the original order is correct.** In each case the preserved r3 mtimes have the dependency older than the binary:
- `libversion_check…rlib` `…335.107394486` < generic-array script `…335.371394444`
- `libautocfg…rlib` `…341.719393475` < num-traits script `…341.771393467`
- The cc, cmake, dunce and fs_extra rlibs (≤ `…341.427393514`) < aws-lc-sys script `…342.061812584` < its run `invoked.timestamp` `…342.067393428`

**The repair.** Each seeded copy gets back its own preserved successful-r3 mtime (the archive's `lstat` value, which Root's all-3498 join verified). This reproduces the relative order of the build that produced those bytes. Three new checks fail closed:
- The mtime must be strictly newer than `SOURCE_EPOCH_NS`.
- In production, it must lie inside the verified r3 range.
- The source mtime must be unchanged after the copy, and the destination mtime must equal it.

**Left unchanged.** `verify_post_compile_no_script_reexec` is unchanged and still strict. So are all hash, size, mode, partition, count, host-output, dep-info and run-unit checks, the old-ELF exclusion, and the receipt schema. `TARGET_MIN_EPOCH_NS` and `TARGET_FINGERPRINT_EPOCH_NS` stay defined, so no name is removed.

## 5. Honest limits and remaining prerequisites

**Per-file mtime binding.** The helper takes each mtime from the archive `lstat`. It enforces the r3 range, the source-epoch bound and post-copy equality. Exact per-file equality with the original R3 inventory rests on Root's join (`719f0fe7…`). The helper does not re-derive it from the NUL stat table, because parsing that table would need an API I was not shown.

**Sufficiency against Cargo is [C]-qualified.** The fix assumes three things:
- Cargo's freshness is mtime ordering between dependency outputs and unit outputs, plus source mtimes against outputs.
- The final state of the successful R3 build is Cargo-fresh.
- `reconstitute_source_home` actually stamps sources at `SOURCE_EPOCH_NS`. I did not see its body; a reviewer must confirm this.

Other uncovered cases:
- `rerun-if-changed` paths outside source_home.
- Environment or rustc differences.

P8's 26 fresh run units and 28 fresh scripts support the mechanism, but do not prove the fix. Only a future fresh run, judged by the unchanged strict postcheck, can show it suffices. If it does not, the postcheck fails closed again.

**Unseen code.**
- I could not see the full 93 KB helper or the 61 KB test file. Reviewers must check whether any other code or test asserts the tier values. Any such hit must be reported, not silently edited.
- The existing and new fixture tests assume the host clock is later than October 2025, so that fixture-written mtimes exceed `SOURCE_EPOCH_NS`.
