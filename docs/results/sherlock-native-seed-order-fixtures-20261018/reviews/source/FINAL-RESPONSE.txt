  - Each seeded file receives `src_st_before.st_mtime_ns`.
  - That value is bracketed: `digest` re-checks `stable_stat` (which includes mtime) while reading, and `src_st_after` must match the inode, mode and mtime after the copy.
  - The destination mtime is re-read and must equal the preserved value.

  - The archive stays unwritten and keeps its 0o400/0o444 mode check.
- **Predicate 2 (bounds):**

### Qualifications

These are non-blocking observations, not required fixes.

1. **The mtime is not pinned per file in code.**
   - The contents are hash-pinned. The mtime is only checked against the range, held stable while seeding, and is greater than the epoch.
   - Equality to the original R3 values is established externally, by the 2026-10-18 all-3498 join (`mtime_or_bytes_differences: []`). No code checks it.
   - The owner can still run `utime` on a 0o400 file within the range; the fixture itself does this. A touch to the current time would land above `hi` and be refused.
   - So "authenticated" here means pinned contents, range-bounded and seeding-stable mtimes, and equality as of the external readback.
   - Optional hardening, if wanted later: bind each file's `mtime_ns` to the pinned stat inventory.
2. **A refusal can leave a partial target.** The epoch/range refusal fires after the copy. That matches the existing fail-closed pattern, since retries require a fresh empty target.
3. **Helper seal: consistent with the record, but the line was not read.**
   - The old value is the ccb preimage SHA (`4d34…`). The new value is the ccb afterimage SHA (`82cc…`).
   - `bounded_sdk_compile.py` stays at 96012 bytes, and the materialization reports the replacement as unique.
   - I did not literally confirm the line.

## Q2: Ordinary four — not ELIGIBLE_ORDINARY_FOUR as submitted; two corrections needed

### The test bodies are meaningful and safe as written

- **Test A, `test_seed_reapplies_preserved_r3_mtimes_in_dependency_order`:**
  - It fails under the old code, because every seeded mtime must equal its supplied value.
  - It checks the source mtime and the 0o400 mode both before and after.
  - It covers the run-unit snapshot, a passing postcheck, and refusal of a same-byte script whose mtime increased by 1 ns.
  - The output/invoked/stderr ordering asserts only restate the supplied data. They document the expected order but add no extra test of the code.
- **Test B, `test_preserved_seed_mtime_bounds_and_actual_r3_build_dependency_edges`:**
  - It checks the exact inclusive `lo`/`hi` bounds: `±1` is refused with a range and accepted without one.
  - It checks the epoch boundary: `SOURCE_EPOCH-1` and `SOURCE_EPOCH` are refused, `+1` is accepted.
  - Its edge literals match the readback. The literal-versus-literal comparisons are data facts, not tests of the code.
- **Test C, `test_seed_refuses_preserved_mtime_not_newer_than_source_epoch`:**
  - It fails under the old code.
  - It checks the refusal message and path.
  - It confirms the archive is unmutated and that no seed receipt was written.
- **Test D, `test_target_partition_excludes_mori_workspace_and_preserves_quarantine_modes`:**
  - It is byte-unchanged and still valid: creation-time mtimes are later than `SOURCE_EPOCH`, and `TARGET_MIN+9999` still differs from the preserved mtime.

### Execution scope

- Everything runs under TMPDIR. There are no production paths, no subprocess and no I/O at import.
- `-I -B -S` keeps the run off user site-packages and stops `.pyc` files from altering the three-file staging set.
- Fixture writes are far below FSIZE 1 MiB.
