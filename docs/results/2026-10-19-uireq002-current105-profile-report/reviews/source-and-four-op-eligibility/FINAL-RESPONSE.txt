## Source applicability

`compile_draft_host` → `prepare_draft_pair` → `parse_draft_config` → `prepare_checked_draft_bounded` → `admit_checked_draft_bounded` → owner `admit` → owner `admit_run` → `project_draft_pair` → `project_admitted_preparation` → `prepared.observe()` → `draft_profile::report(&config.fields)`.

**The report is only produced after admission succeeds.** `project_admitted_preparation` is reached only after parse, typecheck, copy, `admit` and `admit_run` all return `Ok`, and after `observe_bound_image` succeeds. Any `Tooling` or `HostViolation` error returns a `CompileFailure` and produces no report. This matches the clause's "WHEN a program is admitted".

**`supported_profile` depends only on the parsed config and static literals.** It is a pure function of `DraftExecutionConfig`: `profile`, `grammar`, `bounds`, `layout` (the wire struct), `fuel`, `stack` and `preprocessing`. It does not read the source, the admitted pair, the target or `LayoutSchemaC`.

- `Layout::owner` hard-codes `ext_capacities: None`.

- The report serializes the wire `Layout`, not `LayoutSchemaC`.
- `LayoutObservation` also has no `ext_capacities` member.

`config.rs` has now been read, so it belongs in 002's pinned set.

## C1: required correction for ops 03 and 04

This is a composition change only. It does not touch argv, source, tests, expectations or `PROPOSED.json`.

**The defect.** `run_selected_13.py:test_membership` reads `op['expected']['exactTest']`, but ops 03 and 04 carry the key `expectation`. If these op records are passed in as they are, the call raises `KeyError` after the test binary has already run. Under serial fail-stop with no retry, that ends the single attempt with nothing accepted. It fails closed, but the attempt is lost.

**The helper also never checks `filtered_out`.** It returns the value without asserting it.

**What the composition must do.**
1. Call `test_membership(dict(op, expected=op['expectation']), phase)`.
2. Assert that the returned dict equals exactly:
   `{exactTest: <name>, selected: 1, passed: 1, failed: 0, ignored: 0, measured: 0, filtered_out: 1}`
3. Before checking 03 or 04, require that the frozen output of op 02 contains that exact name.
