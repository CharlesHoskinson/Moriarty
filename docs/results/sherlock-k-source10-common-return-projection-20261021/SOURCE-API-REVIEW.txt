### 1. Source & API Correctness Audit

1. **Zero Imports, Pure Return-Only Execution, No I/O or Mutation:**
   - `source/common_return_projection.py` (`643b83f11cc622cb806f46c18f735718e79a68d1747551be017122ae8f5579ea`, 9890 bytes) contains zero `import` statements, performs no file/environment/process I/O, and does not invoke K, parsers, or receivers.

If any check fails at any depth in the iterative worklist, `ProjectionDomainError` is raised before returning, preventing partial outputs.

2. **Target Node Schema Alignment (`TARGET-NODE-SCHEMA.public.json`):**
   - `UInt` projects to `{"kind": "UInt", "runtimeTypeId": 0, "value": str(g)}` after checking `type(n) is int`, `type(g) is int`, `n == g`, and `0 <= g < (1 << 128)`, producing canonical unsigned base-10 decimal strings and rejecting `bool` (`type(False) is bool is not int`).
   - `Bool` projects to `{"kind": "Bool", "runtimeTypeId": 1, "value": g}` after checking `type(n) is bool`, `type(g) is bool`, and `n == g`.
   - `Nominal` projects to `{"kind": "Constructor", "runtimeTypeId": tid, "runtimeCtorId": cid, "fields": children}` with no extra wrapper or field-name sorting.

3. **Runtime / Declaration Identity & Same-Name Disambiguation:**
   - `tid` and `cid` are taken exclusively from `ng["Nominal"]["type_id"]` and `ng["Nominal"]["ctor_id"]` via `_index` (`0 <= value < (1 << 64)`), never recovered by name lookup.
   - Distinct declarations sharing the same surface type and constructor names (`Coin`/`Mint` at `(6, 3)` vs `(7, 4)`) remain distinct in the projected output (`runtimeTypeId: 6, runtimeCtorId: 3` vs `runtimeTypeId: 7, runtimeCtorId: 4`).
   - Builtin runtime type IDs `0` (`UInt`) and `1` (`Bool`) are pinned against `ported["type_rows"]` (`types.get(0) == {"kind": "UInt"}` and `types.get(1) == {"kind": "Bool"}`).

4. **NP Type Names, Generic Argument Order, and Runtime ID Links (`_np_type`):**
   - `_np_type(metadata, types)` iteratively traverses the `type_rows` entry for `tid`, verifying at every generic argument wrapper `{"runtime_type_id", "type"}` that `arg["runtime_type_id"]` exists in `types` and `arg["type"] == types[arg["runtime_type_id"]]` before erasing the wrapper to match the `NPType` shape (`np_type_ast` / `BUILD_NPTYPE`).
   - Pushing arguments in `reversed(args)` onto the LIFO `tasks` stack and slicing `values[-count:]` in `"build"` preserves exact generic argument order and multiplicity, and `n["type"] != _np_type(types[tid], types)` enforces exact structural equality.

5. **Normalized Source Constructor Ownership, Field Slices, and Declared Field Types:**
   - For every nominal node `(tid, cid)`, `project_return_pair` verifies `(tid, cid) in ctors`, `cid < len(raw_ctors)`, and `raw_ctors[cid]["owning_type"] == tid`.
   - Field arity `count = raw_ctors[cid]["field_len"]` is checked against `len(np_fields)`, `len(ng_fields)`, and `len(metadata["fields"])`.
   - Zero-arity constructors (`count == 0`, e.g., `Absent` with `field_start: 77, field_len: 0`) do not dereference `raw_fields`; non-empty constructors verify `start + count <= len(raw_fields)` and bind each child's `declared_tid = raw_fields[start + ordinal]["type_id"]`, which is checked when the child task is popped (`tid != declared_tid` raises `ProjectionDomainError`).
   - Positional field order is preserved by pushing `ordinal in reversed(range(count))` onto the LIFO stack and checking `field["name"] == metadata["fields"][ordinal]`.
   - Zero-arity nominal variants (`Absent`, `fields: []`), value-bearing variants (`Present(0)`), and scalar `UInt(0)` remain distinct.
   - Unsupported value tags (e.g., `Unit`, `Option`, `Ref`, `List`, `Tree` raw host forms) raise `ProjectionDomainError`.
