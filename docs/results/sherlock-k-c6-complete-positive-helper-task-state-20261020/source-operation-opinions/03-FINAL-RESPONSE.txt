## Fix 1 judgment — unit00 stderr gate: SATISFIED

In the new caller, `unit00_stderr_ok(stderr)` operates on the full retained `stderr` bytes read from the phase stream. It is not a suffix, clipped sample, proxy, or hash.

It returns true only when all of the following hold conjunctively:

- the bytes decode as UTF-8;
- the nonempty stripped line sequence is nonempty and its final line is exactly `OK`;
- exactly one line starts with `Ran `;
- that line is exactly `Ran 15 tests` or starts with `Ran 15 tests in `;
- no stripped line starts with `FAIL:`, `ERROR:`, or `FAILED`.

The phase-00 acceptance block is gated by the pre-existing clean state first: `unit00_ok = unit00_stderr_ok(stderr) if ok else False`, where `ok` already requires clean F03 exit, return code 0, no timeout, no containment breach, no remaining processes, no unexpected files, and the declared product condition. It then persists `UNIT00-ACCEPTANCE.json`, records `unit00_stderr_ran15_final_ok`, and folds the result into acceptance with `ok = ok and unit00_ok`. If that is false, `results[-1]['accepted']` is false and the existing fail-stop raises before the next loop iteration, so phase 01 is not dispatched.

This satisfies the prior condition: actual 15-run evidence, final `OK`, and no failure/error result are required from the complete stream. It does not falsely approve a no-run: empty stderr, `OK` without a `Ran 15 tests` line, a `Ran` line without final `OK`, a wrong count, duplicate `Ran` lines, non-UTF-8 bytes, or a failure/error line all fail closed. The acceptance receipt reuses the single conjunctive boolean for its subfields; that is a reporting compression, but it cannot create a false acceptance because the gate itself is the same conjunction.
