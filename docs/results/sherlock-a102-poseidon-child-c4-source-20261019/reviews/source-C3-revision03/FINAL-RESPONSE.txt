## R1: early proof-size refusal (`sherlock_child.rs::verify_sherlock_child`)

- **The bound runs first.** The first statement is `if child.proof.is_empty() || child.proof.len() > MAX_PROOF_BYTES { return Err(error("proof", ...)) }`. It runs before `prepare`, so before `LiteralLayout::new`, `ir.k()`, the SRS load and `setup_vk`. `ChildKey::verify` repeats the check, which is harmless.
- **The test locks the ordering.** In `a102_child_verify_refuses_unbounded_proof_before_reconstruction`, both cases (empty and `MAX_PROOF_BYTES + 1`) assert `err.code == "mori::backend::proof"`.
  - If the bound regressed, `prepare` would reach `LiteralLayout::new → decode_digest("")`. That call fails with `unhex`'s `"signature"` code, so the test would fail before any `ir.k()` or SRS access.
  - The test itself does no native work.
- **Identity effect.** The edit changes `ADAPTER_SOURCE`, which changes `adapter_source_sha256` and therefore instance lane 0. The child VK is a function of `IrSource`, architecture, k and SRS, so by source it is unaffected. No child artifact exists yet.
- **Optional, not mandatory (R1b).** A garbled claim still pays for `ir.k()` (stdlib `optimal_k`, a loop of `cost_model` calls) before it is refused.
  - Comparing the k-independent claim fields before `ir.k()` would refuse earlier.
  - The test path already does these joins before native work (`join_frozen_a102_child`), so this only matters for other API callers.

## Security re-check of the adapter

- **Carrier matches what the circuit reads.** `child_witness` fills exactly what `IrSource::circuit` reads:
  - `PublicInput` reads `preproc.memory.get(output)`;
  - `pi_push` checks `preproc.pis[idx]`, with index 0 holding the binding;
  - `binding_input`;
  - `comm_comm: None`, matching `do_communications_commitment == false`.
- **Sparse memory is safe.** `mem_insert` only compares ids that are present in memory, so leaving other ids out only skips debug alignment checks. Constraint authority stays with the circuit.
- **Instance order is consistent.** `once(binding).chain(statement)` is used by `prepare`, by `prove` (through `scalars`) and by `verify`.
- **Guard comparison is valid.** `*guard != Operand::Immediate(Fr::from(1u64))` compares field equality against the emitted `immediate(1)`.
- **The consumer reconstructs independently.** It rebuilds the claim and instance, compares them before the SRS, then rebuilds the VK and compares it bytewise, then calls stdlib `verify`. That function enforces `pi.len() != vk.nb_public_inputs` and transcript EOF (`BlstPLONK::verify` calls `transcript.assert_empty()`).
- **Unchanged.** The relation's nine `include_str!` members, `literal_bridge`, the Blake2b claim and its key location are unchanged. A2 cross-graph compatibility remains **UNOBSERVED** and is not a prerequisite here.

## API, borrow and visibility (source level, not compiled)

These all check out against the supplied bodies:

- **Crate-private items.** `crate::digest` is a root-private function and visible to descendants. `crate::parameters::OfflineParameters` is `pub(crate)` inside the private `mod parameters`. `crate::proving::{hex, validate_json_profile}` are `pub(crate)`. The `pub(crate)` `LiteralLayout` fields are reachable.
- **SRS reference.** `&params.0` coerces from `Arc` to `&ParamsKZG<Bls12>`. The borrow ends before `params` moves into `Self`.
- **VK round trip.** `MidnightVK::read(&mut &vk_bytes[..], Processed)` type-checks.
- **Turbofish with `impl Trait` arguments.** `stdlib_prove::<IrSource, ChildTranscript>(…, rand::rngs::OsRng)` is fine. Explicit generics alongside `impl Trait` arguments have been stable since Rust 1.63, and the stdlib doc example uses the same form.
- **Transcript bounds.** The `Hashable<PoseidonState<Fq>>` and `Sampleable` impls exist in registry circuits 7.2.4 `poseidon_cpu.rs`.
- **Test file.**
  - `read_a102_child_inputs`: `disjoint` is a `Copy` closure that only captures `&output_dir`. It is used before `output_dir` moves. `Option::is_none_or` needs Rust 1.82 or later; the toolchain is 1.99.
  - `read_frozen_a102_child`: the `FnMut` `read` closure's borrow of `files` ends before `Value::Object(files)`.
  - Negatives: `drop(key)` sits inside a diverging branch, so the later `key.verify` use is fine.
  - Every `json!` value is taken by reference, so later field uses are fine.
- **Names and imports.** The suffix imports (`Fr`, `Operand`, `IrValue`, `Identifier`, `Instruction`, `Component`, `decode_digest`, the child items, `CapacityRecord`, `LiteralTransitionRequest`, `LiteralValues`, `MAX_PROOF_BYTES`) do not collide with the prefix. `ImageValues` is already imported by the prefix. ## TESTSOURCE (R2)

**Sound as written**

- **Selector split.** The three ignored selectors are:
  - producer: reconstruct, then prove including self-verify;
  - frozen verify-only: one `verify_sherlock_child`;
  - frozen negatives: one reconstruct, a join, one honest control and eight tampered cases.
- **Environment contract.**
  - Canonical `max_k`: at most 2 digits, no leading zero, in 1..=19.
  - Output directory: `symlink_metadata` must be exactly `NotFound`.
  - Output parent: canonical, an existing directory, not readonly.
  - Disjointness from the SRS and input directories in both directions.
- **Bounded reads.** Reads use `O_NOFOLLOW|O_NONBLOCK`, require a regular nonempty file, and read through `take(cap + 1)`. The caps are: VK 1 MiB, proof 262144, JSON 1 MiB. Lanes must be canonical LE hex.
- **Artifact lifecycle.**
  - Writes use `create_new`, then file sync, then directory sync.
  - The input record is written before native work.
  - Public artifacts are written before host assertions, and the report before the assertion.
  - `child.error.json` is written when a native call returns `Err`.
  - Keys are dropped before the report.

**Findings (none mandatory for compile)**

**T1. Phase progress is insufficient for a bounded retry.**
- In `native_a102_poseidon_child_producer_proves_and_persists`, `ChildKey::reconstruct(..)` is followed directly by `key.prove()`. Nothing is persisted between them.
- `verify_sherlock_child` is a single opaque call.
- So a timeout reproduces P14's information state: only `child.input.json` survives. Nothing distinguishes which phase was running:
  - `ir.k()`
  - SRS load
  - `setup_vk`
  - SDK check
  - `setup_pk`
  - prove
  - self-verify
- libtest captures stdout and stderr by default and prints them only when a test finishes, so markers printed with `println!` are lost on a kill unless the argv includes `--nocapture`. Only synced file markers are durable.
- **Test-only fix.** It changes no adapter, relation or ledger identity:
  - In the producer, write `child.vk` (from `key.vk_bytes()`) and `child.claim.json`/`child.instance.json` (from `key.claim()`/`key.instance()`), plus a small synced phase record, right after `reconstruct` returns and before `prove`.
  - Then remove the later writes of those files, because `create_new` would panic on a duplicate.
  - In negatives, add a synced phase record after the reconstruct/join and after the control verify.
- **Verify-only has no test-level boundary** unless the test bypasses the public API. The negatives selector's control verify is effectively the phase-observable consumer.
- **Owner decision.** If Root wants this before the native producer runs, apply it before the single compile so a second compile is not needed.

**T2. Proof salvage stops at self-verify.**
- `ChildKey::prove` executes `self.verify(&p.instance, &proof)?;` before it returns the proof. A timeout or `Err` during self-verify therefore loses completed proof bytes.
- Fixing this needs an adapter API split (for example a `prove_unverified` returning the bytes, followed by a separate `verify`). That changes `adapter_source_sha256`.
- Optional. The independent consumer verifies anyway.

**T3. Panics leave no error record.**
- The SDK panics inside `setup_vk` (`expect("keygen_vk should not fail")`) and `setup_pk` (`expect("keygen_pk should not fail")`). Write-helper panics behave the same way.
- These leave only the input record plus the panic text in captured output, which libtest does print when a test fails.
- Optional fix: `catch_unwind(AssertUnwindSafe(..))` around the native calls to persist `child.error.json`, as `task4_native_resource_gated_entry` does.

**T4. The canonical-path check is lexical, not textual.**
- `assert_canonical_absolute` uses `path.components()`, which normalizes away interior `.`, `//` and a trailing `/`.
- It then compares `real.as_path() == path`, which also compares by components.
- So `/a/./b`, `/a//b` and `/a/b/` pass, even though the doc says "without `.` or `..`".
- These forms resolve to the same location, but the recorded `display()` strings could be non-canonical text.
- Optional fix: compare `as_os_str()` bytes against the canonicalized path.

**T5. Doc nit in the C1a top doc.**
- The top doc says "the Sherlock child carrier and proof-bound cases, exercise the real A102 witness producer on positive and semantically corrupted transitions…".
- The proof-bound case uses neither the producer nor a corrupted transition.
- The rest of the C1a text is accurate:
  - `ir.k()`, SRS, keygen and verify for all ignored native selectors;
  - prove only in the two producer selectors.
- Fix only if the file is being touched anyway.

**T6. Informational.**
- The verify-only selector and the negatives control both pay for `ir.k()`, the SRS load and `setup_vk`.
- The ordinary carrier tests each run `build_positive_fixture` (SDK check over about 4 MB of ZKIR).
- All new selectors, ordinary and ignored, are UNRUN. The author fixtures and frozen P14 identities are input identities, not independent goldens.

**Source facts, not performance claims.**
- The child path calls `ir.k()` once in `prepare` and then calls stdlib `setup_vk` directly. The P14 literal verify path called it twice.
- `optimal_k` iterates `cost_model` from k = 9 until `rows < 2^k`.
- No speedup, phase attribution, RSS, wall time or native eligibility follows from this.
