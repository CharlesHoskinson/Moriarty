## 1. Source and API checks on the changed bytes

### Producer (`native_a102_poseidon_child_producer_proves_and_persists`)

**Lifecycle**
- The sequence is: `begin_a102_child_output` (creates the directory, syncs the parent, writes `child.input.json`), then `ChildKey::reconstruct`, then the VK, instance and claim files, then `child.phase.1-reconstructed.json`, then `key.prove()`, then `child.proof`, then `child.report.json`, then the assertion.
- Each name is written exactly once through `write_synced_artifact(dir: &Path, name: &str, bytes: &[u8]) -> String`. That helper does `create_new`, `write_all`, file `sync_all`, `drop`, then `sync_dir`.
- The revision03 post-prove VK, instance and claim writes are removed, so `create_new` cannot hit a duplicate.
- On an `Err`, each error path writes `child.error.json` once and then panics.

**What gets serialized**
- **VK:** `ChildKey::vk_bytes(&self) -> &[u8]`, which is the processed `write_vk` bytes after the round-trip check in `from_prepared`.
- **Instance:** `key.instance().iter().map(field_hex)`, with `field_hex(&Fr) -> String` imported from `crate::sherlock_child`. This is the same idiom as `SherlockChildProof::instance_hex`, so the bytes equal the serialization the frozen consumer decodes. The consumer applies `decode_digest`, `Fr::from_le_bytes` and a canonical round-trip check.
- **Claim:** `to_vec_pretty(key.claim())` with `claim(&self) -> &ChildClaim`. Because `ChildClaim` is `Serialize` with fixed field order, the output is deterministic.

**Truthfulness of the phase record**
- It records `reconstruct_returned_ok: true` and `prove_returned: false`.
- Its role is "reconstruction outputs only". Both statements are true at the moment it is written.

**Join with the returned child**
- `prove` returns clones of `p.claim`, `p.instance` and `self.vk_bytes`.
- `persisted_ok` checks four things against the pre-prove bytes and hash:
  - child VK bytes equal `key.vk_bytes()`;
  - the child VK SHA-256 equals `vk_sha256`;
  - the re-serialized `child.instance_hex()` equals `instance_text`;
  - the re-serialized `child.claim` equals `claim_text`.
- `lanes_ok`, `instance_ok` and `claim_ok` (including `public_values`) are retained.
- `passed` is now a strict superset of the revision03 conjunction.

**No unverified promotion**
- `child.proof` is written only after `prove` returns `Ok`, which happens only after the internal `self.verify(..)?`.
- If `prove` errs, panics or times out, the directory holds VK, instance and claim but no proof.
  - Both frozen consumers call `read_frozen_a102_child`, and `read_bounded_child_file` opens all four files before `begin_a102_child_output` and before any native call.
  - A missing proof therefore panics on open, before any native work. That is a fail-closed result.

### Negatives (`native_a102_poseidon_child_frozen_negatives_reject_tampering`)

**Three marker files.** Each is unique and synced, and each is written after the call it names returns:
1. `phase.1` after `reconstruct` returns `Ok`. If the join then fails, the existing `reconstruction-join` error record is written and the test panics, so `phase.2` never appears.
2. `phase.2` only after the join passes.
3. `phase.3` after control returns, carrying the actual outcome:
   - `control.is_ok()`;
   - `control.as_ref().err().map(|e| json!({"code": e.code, "message": e.message}))`. Here `e` is `&Error`, and the field access is by reference. An `Option<Value>` serializes as `null` or as the object.

**Unchanged.** The control and case semantics, `all_rejected`, and the final assertion are unchanged. `control` is not moved: `.is_ok()` and `.as_ref()` borrow, and `match &control` still follows.

### Macro and API facts relied on

- **`json!` takes values by reference.** It expands each value to `to_value(&expr)`. That is why `vk_sha256`, `instance_sha256`, `claim_sha256` and `phase` stay usable afterwards. Unchanged P13 code already depends on this (`"verification": verification`, then `verification.proof_bytes`). Trailing commas in nested objects are used the same way in the unchanged prefix.
- **`Error` usage is already established.** The `code` and `message` fields, their `Serialize` use, and `{e:?}` Debug are all used by the unchanged `control_json` and `persist_a102_child_error`.
- **`persist_a102_child_phase` types.** It takes `(&Path, &str, &str, serde_json::Value)` and returns `String`. Every call site matches, and every return value is bound and used in the reports.
- **No new imports.** `field_hex`, `hex`, `Sha256`/`Digest` and `Path` are already in scope, and no new unused bindings are introduced.
