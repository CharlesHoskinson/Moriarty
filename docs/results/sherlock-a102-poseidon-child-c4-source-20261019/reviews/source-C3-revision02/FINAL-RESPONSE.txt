## Source / security

### Relation and statement (Moriarty M1, `sherlock_child.rs`)

- **Same relation, unchanged context.** `prepare` calls the unchanged `LiteralLayout::new → statement → emit(CircuitMode::LocalPublic)`. The child proves the identical `IrSource`.
  - The context limbs are fixed inside the circuit: `ConstrainEq { a: operands[0].clone(), b: immediate(lo) }`.
  - So pinning the child VK also pins the context, the layout, the relation hash and the source identities.
  - None of the nine relation-hash members changes. The adapter is registered in `lib.rs` (`pub mod sherlock_child;`), which is not one of the `include_str!` members in `literal_host.rs::LiteralLayout::new`. `mod.rs` is untouched.
- **Instance order and count.** The instance is `std::iter::once(binding).chain(statement…)`, which gives 2078 lanes for the fixture.
  - This matches `IrSource::circuit`: `pi_push(binding_input, …)` first, then one `pi_push` per `Impact`, then `constrain_as_public_input` over all of them.
  - It also matches the stdlib `verify` check `pi.len() != vk.nb_public_inputs`.
  - There is no truncation and no digest.
- **The binding lane is semantically opaque in circuit.** `let binding_input = std.assign(layouter, binding_input_value)?` is a free witness that is only exposed publicly.
  - On the Moriarty side it binds `ChildClaim`, because `verify_sherlock_child` recomputes it.
  - On the Fenrir side it is an arbitrary public lane. Fenrir never reconstructs the claim.
  - This is truthful as written. The child's Fenrir-level meaning is "VK-fixed circuit + 2077 statement lanes", not the claim.
- **Carrier (`child_witness`).** It fills exactly what the supplied `circuit` body reads:
  - `PublicInput` reads `preproc.memory.get(output)`;
  - `pi_push` reads `preproc.pis[idx]`;
  - `binding_input`;
  - `comm_comm` stays `None` because `do_communications_commitment` is false.

  It refuses guarded, non-Native or private inputs, non-`Immediate(1)` Impact guards, publication-order mismatch, and skips.

  The sparse memory only removes the debug-level `mem_insert` misalignment checks. Constraint authority stays with the circuit. `pi_skips` is never read by the circuit, which agrees with the inventory.

  The guard comparison `Operand::Immediate(Fr::from(1u64))` against the emitted `immediate(1)` (`Fr::from(1u128)`) compares equal field elements under the derived `PartialEq`.
- **Proving path.**
  - The SDK `ProofPreimage::check` runs under the real binding before `setup_pk` and `prove`.
  - It does not use `prove_unchecked`, does not fork the SDK, and does not interpret instructions in shadow.
  - It calls `stdlib_prove::<IrSource, ChildTranscript>`, so the type `H` is generic, as the author intended.
  - The Blake2b literal claim, its binding, its key location and `literal_bridge.rs` are all untouched. The binding domains differ (`CHILD_BINDING_VERSION` vs `BINDING_VERSION`), and the test asserts that.
- **Key and reconstruction.**
  - `setup_vk(kzg, &prepared.ir)` runs against the exact-k pinned SRS, followed by a `vk.k() != k` check and a Processed write/read/write round trip.
  - `verify_sherlock_child` compares claim and instance before any SRS access, then the VK bytes, then runs `verify`.
  - The independent reconstruction is in-process, so it rests on deterministic recomputation by the same binary, not on a separate run.

### Fenrir consumer (F1, `sherlock_child.rs`)

- **Off circuit.** `verify::<RawInstance, Pos>` (count and transcript), then `inner::verify_offcircuit(.., false)`. Both pass the full instance. `SherlockChild::from_bytes` checks the pinned digest before `vk_from_bytes` and requires the bytes to round-trip.
- **In circuit.** `SherlockChildRelation::circuit`:
  1. assigns `n` cells;
  2. calls `verify_child_incircuit(s, l, &self.child_vk, &self.name(), &inst, proof, false)`;
  3. constrains the same cells, then `acc`, as public.

  So the public child lanes are the verified instance lanes. No 16-field `NodeRelation` truncation is used.

  `instance()` mirrors this order through `prepare_offcircuit(.., false)`. That is the same resolve-then-collapse sequence, though the `carried=false` in-circuit path has no prior use in the supplied Fenrir code.
- **What "deferred pairing" means here.**
  - The wrapper proof only says that the child's KZG check reduces to the published collapsed (A, B).
  - It is child validity only after a terminal step subgroup-checks A and B and checks `e(A,[τ]₂)·e(B,−[1]₂)=1`, as `DeciderRelation::circuit` steps 2–3 do.
  - The test `sherlock_child_wrapper_binds_the_child_statement_and_defers_the_pairing` says this honestly. The forged statement case only prints the wrapper MockProver verdict and asserts that the pairing refuses. There is no shortcut that treats the wrapper as validity.
- **Lane count is not tied to the child VK.** `n_child_instance` is not checked against the child VK's public-input count, and `MidnightVK.nb_public_inputs` has no accessor in the supplied API. The in-circuit gadget's length enforcement is unsupplied.
  - For this child, a truncated tail fails, because the last lanes (`rule_tag=3`, `charge=1`) are circuit-forced nonzero.
  - Over-long zero padding would be a representation ambiguity, not a false statement.
  - Recommended (R4).

### Cross-graph compatibility

The byte boundary is a sound way to keep Fenrir's patched circuits off the Moriarty side, and the patched circuits matter for the wrapper's BLS MSM.

Compatibility itself is **UNOBSERVED** for three things:

- Processed-VK `transcript_repr` and CS reconstruction (`MidnightVK::read` → `ZkStdLib::configure` in Fenrir's graph);
- Poseidon transcript point hashing across proofs 0.8.3 and 0.8.2;
- the `truncated-challenges` closure.

The visible mismatch modes fail closed (round-trip, verify or pairing refusal). Fail-closed cannot be proven universally because the proofs and circuits transcript bodies are absent (A2).
