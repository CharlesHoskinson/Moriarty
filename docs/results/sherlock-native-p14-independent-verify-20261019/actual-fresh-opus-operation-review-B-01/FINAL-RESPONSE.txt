## 2. Exact process and resource envelope

### Verify chain

1. The harness `Popen` uses `start_new_session=True`.
2. `systemd-run --user --scope` registers the scope over the user bus, then execs, keeping the same PID.
3. `timeout` is the session leader. Its `setpgid(0,0)` is a no-op, so harness `killpg` still reaches the whole chain.
4. `timeout` forks; the child runs `prlimit`, which sets the limits on itself and execs.
5. `env -i` runs, then the ELF.

### Limits on the ELF

| Limit | Effect |
|---|---|
| `RLIMIT_CPU` 300:300 | Process-wide across all threads; at 4 threads it can be hit after about 75 s wall. Because soft equals hard, the kernel sends SIGKILL, which is not a core-dumping signal. |
| `RLIMIT_AS` 8 GiB | Counts virtual reservations: glibc arenas, thread stacks, and the PT_LOAD segments of the debug ELF. A hit shows as `memory allocation of N bytes failed` followed by SIGABRT. That is not an OOM and not a verifier Err. |
| `RLIMIT_FSIZE` 64 MiB | Outputs are KB-scale. |
| `RLIMIT_CORE` 0 | No core file through the normal path. |
| Scope | MemoryMax 8G, MemorySwapMax 0, TasksMax 1024, CPUQuota 400%. |
| Wall | TERM at 300 s, KILL at 310 s, harness deadline 330 s, leaving a 20 s margin. |

**Listing join.** All of the following must hold:

- stdout contains `running 1 test`.

- Under `--nocapture`, the line `A102 frozen-bundle verify-only returned Ok: k=18 proof_bytes=P out=<OUT>` sits between `test <sel> ... ` and `ok`.
- The run uses a new exact parser; the `run_tail_four` parser does not apply.

### B3. Accounting in kill paths

A `RUSAGE_CHILDREN` delta includes the ELF only if `timeout` reaped it. That covers a normal exit, a 300/310 s timeout, RLIMIT_CPU and an OOM kill of the ELF alone.

The ELF may instead be reaped by a subreaper, and its CPU will then be missing from the waited-child delta, in these cases:
- the harness ran `killpg` at the 330 s wall or on the stream cap
- Root killed the scope
- systemd OOMPolicy stopped the whole scope

In those cases:
- mark the measured CPU as a lower bound
- charge the cap conservatively: 300 s for verify, 8 s for listing
- never refund

Root must reap explicitly, because the `capture()` `wait(0.001)` can return `None`. Append to the retained hybrid ledger, keep residual 6, and keep these deltas separate from the earlier raw cgroup counters.

## 6. Limits of result claims

**A PASS shows only the following.** This ELF, with max_k 18 and the pinned 2p18 SRS, rebuilt the A102 request from host fixtures without reading the bundle claim. It reproduced the claim exactly, derived the VK with `keygen_vk`, and the Midnight verifier accepted the frozen proof for the binding plus the 2077-lane statement.

**A PASS does not show any of the following:**
- **Implementation independence.** "Independent" means independent of the bundle's data, not of its code. The same `LiteralLayout`/`emit`/`prepare` code and the same binding derivation produced the original claim.
- **No check replay inside the request builder.** "No check replay" holds at consumer level only. `literal_witness.rs`, which contains `build_checked_literal_transition_request`, was not supplied to me.
- **Wider guarantees.** It is not evidence of soundness, refinement, closure of `OPEN_OBLIGATIONS` / Am10 / T3 / k17 / C4 / R2, ledger-9, stagenet, or recursion.
- **A benchmark.** Resource figures from this run are a single observation, not a benchmark.
- **The cause of the P13 kill.** At most it shows that verify alone fits this envelope in a fresh process.

**On failure:** only the `verification` class is negative evidence about the frozen proof. Even then, this operation cannot separate a bad proof from dependency drift between the P13 and P14 ELFs.

## 7. Non-blocking notes

- **N1.** Setting AS equal to MemoryMax adds an abort mode, and an abort is a core-dumping signal. For pipe-based `core_pattern` handlers, the kernel ignores `RLIMIT_CORE=0`, so capture depends on the handler (WSL may use its own). The probability is low because verify needs much less memory than prove. Do **not** set CPU soft below hard: that would introduce a core-dumping SIGXCPU.
- **N2.** Re-hash the copy after listing and before the positive run. It is cheap.
- **N3.** The scope has no network isolation. That is acceptable given the sources; record it.
- **N4.** On PASS, record stderr; it should contain no panic or abort text. Treat empty stderr as expected rather than as a gate unless Root decides otherwise.
