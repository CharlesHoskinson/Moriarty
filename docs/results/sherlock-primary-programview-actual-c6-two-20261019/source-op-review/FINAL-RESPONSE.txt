## Source assessment against the two actual captures

I traced `program_view_to_ngprogram.py` through every table of both `/canonicalProgramView` values. These are predictions about the subject, not about the hidden oracle.

**Shape**
- Each view has exactly the 23 `PROGRAM_FIELDS` keys, so `record()` passes.
- `occurrences` and `expressions` row counts agree: 33/33 and 38/38.
- Every naturals table is integers only, and `names` is strings only.
- `type_args` is `[]` and every `decl_param_counts` entry is 0 in both captures.

**Slice bounds**
- Every slice ends within its table. The tightest are:
  - `occurrence_paths`: 62+3=65 and 83+1=84
  - `ctor_fields`: 9+2=11 and 12+2=14
  - `children`: 8+1=9 and 13+3=16
  - `constant_fields`: 4+2=6 and 8+2=10
  - `pattern_children`: 10+2=12 and 6+2=8
- `Match.plan` references 0/11 and 0/7 are within the `plan_nodes` tables (20 and 14 rows).

**Expression forms present**
- The captures use only Let, Literal, Var, Call, Match, Construct and `Binary.Add` (Add appears in capture 1 only).
- There is no If, Unary, other Binary op, or dedicated builtin form.
- Predicted result: zero issues, `status = ported`, exit 0 for both 01 and 02.

**Constants**
- All constant rows are marker-free U128 decimal strings or `Constructor` rows, and the constant graphs are acyclic.
- In capture 1, constant 8 is `Both(Pay(4,Done), Pay(5,Done))`.
- In capture 2, constants 15–20 are reachable only through `Construct.constant` caches. They are ported as rows but do not appear in `ng_program`, consistent with the SAFE disposition "cached reference unmappable, retained".

**Patterns and arms**
- **Recursive Wildcard and Bind patterns.** These are present and preserved in order:
  - Capture 1, arm 0: `C(4,6,[C(4,5,[Bind14,Wildcard]),Wildcard])`.
  - Capture 2, arm 2: `C(4,5,[W,W])`. It is shadowed by arm 1 under the plan (no `Select` targets arm 2), but it is retained as source data. No reachability claim is made.
  - Top-level `Bind23` arms: capture 2, arms 3 and 7.
  - Nullary constructor arms: capture 1, arms 3 and 4; capture 2, arms 0 and 4.
- **Global ArmRow caveat.** This is genuinely exercised: the second `Match` in each capture starts at arm row 4, so `source_arm_id` is 4..6 or 4..7, not local ordinals.

**Functions**
- Nonzero parameter slices are present: `params (1,1)`, and `(2,3)` for the three-argument `pack` with sorts 4, 5 and 0.
- Return type IDs are 0, and 4, 5, 6.

**Declarations and SCC-min groups**
- Type-slice ownership agrees with constructor `owning_type` in both captures, so the R1 inconsistency risk from the prior review is absent here.
- Builtin rows 2 and 3 have `decl = null`, and constructors 0–3 match the builder (Nil, Cons, Leaf, Branch).
- I traced the iterative Kosaraju on capture 2. The finish order is `[0,1,2,3,5,4,6,7]`, and the reverse pass gives `{4,5}→4`.
- Predicted groups: capture 1 → 2, 3, 4, 5 (all singletons); capture 2 → 2, 3, 4, 4, 6, 7.
- Capture 2 is the only nontrivial SCC exercised.

**Retention**
- `source_document` is the entire 12-key wrapper (canonicalProgramView, configuration, factory, genesis, genesisLogicalImage, identity, preparation, qualification, report, report_owner_equals_genesis, schema, unbound), retained as typed JSON. No projection or fixture-ID logic exists.
- No floats are present. Large integers are exact in Python.

## Comparator assessment

- `exact()` enforces strict `type()` identity (bool ≠ int), unordered object key sets and ordered arrays over the whole `ng_program`. It reports a path and a kind only, never a cell value.
- `pin()` hashes the same raw bytes it then parses, for inputs, actuals and expected bodies. This means the freeze pins attest exactly what was compared.
- Before the exclusive freeze write, it checks:
  - The whole `source_document` against the pin-verified input
  - The pointer and `source_file` pin
  - The 23-field inventory against the input's key set
  - The complete input-only origin rows: expressions, owner rows, paths, patterns, constants, functions with ordered parameters, declarations with type arguments, constructors with fields, and the whole ordered arm list
- It opens no expected path before that write.
- Both expectations are positive (`{ng_program: NGProgram}`), so the null-expectation branch is not reached.
- If an expected body's shape is wrong, the comparator raises a `KeyError` after the freeze. That is a fail-closed abort, not a PASS.
