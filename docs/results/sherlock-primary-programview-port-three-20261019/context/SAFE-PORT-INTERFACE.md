# ProgramSnapshot to NGProgram interface contract

This is a data port, with no evaluator, admission authentication, runtime state projection, model step, work clock or expected execution cells. It accepts a complete JSON document and an explicit JSON Pointer to its public ProgramSnapshot. The output retains the entire document unchanged as typed JSON and records that pointer. Every one of the 23 ProgramSnapshot fields remains in that source carrier, including tables without a current K carrier. Unknown Program fields and unsupported variants are diagnosed; no NGProgram is emitted when such issues exist, even for an unreachable expression or constant. The full language objective remains open beyond this declared common positive profile.

Expression IDs and NG occurrence IDs preserve the primary expression/occurrence row index. The compiler's C4 occurrence row stores the function owner and root-first source path; those complete rows and path slices remain in origins. NG arm IDs preserve the primary global ArmRow index. They are explicitly primary row IDs, not an invented original source-arm ID or the IDs of older SAFE examples. Function names, binders, type IDs and constructor IDs preserve their primary integers. All array, parameter, argument, constructor-field, arm and pattern-child order is retained.

UInt is primary/K type 0, Bool type 1; builtin List/Tree types 2/3 are represented by their actual constructor tables. Builtin constructor IDs are 0 Nil, 1 Cons, 2 Leaf, 3 Branch, exactly as declared by the source type builder. Every nominal TypeRow index is kept. Scalar rows 0/1 have no NG declaration; their complete original rows remain in the source carrier. Generic instances use the already resolved concrete type IDs; declaration templates, parameter counts, constructor counts, original type arguments and names remain complete sidecars. No new generic substitution is performed.

NG recursive_group has no primary counterpart. Its explicit port convention is the minimum TypeId in each strongly connected component of the concrete constructor-field type graph. This is derived metadata, not a primary declared/canonical group. Type IDs and field type IDs are not changed.

Supported expression data: Literal, Var, Let, If, Call, Match, Construct and Binary.Add. Dedicated Binary.Cons/Branch and Unary.Leaf desugar to their declared constructor/type IDs with all operands in order; original operator tags remain in origins and the source carrier. Sub/Mul/Eq/Lt/Not and any new form are explicit missing counterpart cases, not filtered. Construct.constant is retained as its primary cached reference, with no new evaluation. Match.plan and plan_nodes/plan_cases/field_paths remain exact source data; no plan equivalence or helper-work claim is made.

Pattern data: PVar maps to Bind, Wildcard maps to true Wildcard, Constructor recursively follows pattern_children in order. Dedicated PNil/PCons/PLeaf/PBranch map to the declared constructor IDs, retaining binder names and field positions. Source pattern row IDs and paths remain origins; no matching or binding evaluation is run.

Constant data: marker-free U128 decimal-string literals map exactly to NG UInt integers, Bool stays Bool, and constructor constants recursively follow constant_fields. Dedicated Nil/Cons/Leaf/Branch constants use declared builtin IDs. U128OutOfRange or marker-bearing/unhandled constants have no port. Every constant row is examined, including unused rows, and every original field remains in the source carrier. Positive admission, finite acyclic constants/patterns, valid resolved references and in-range Add behavior are external premises; this port is not their proof or replacement.

Output fields: format, profile, partial_counterpart, source_authenticity, source_document, program_pointer, ng_program (or null), origins, field_inventory, unhandled, premises. Status reports a data-port result only. The CLI uses a single input file, explicit pointer and one exclusively created output; it launches no child or model.
