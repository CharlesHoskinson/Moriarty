### Mandatory defects

**M1 — `core2_await_boundary_wire.py`, `supplied_itf_record`: negative indices silently select the wrong record.**

`document['states'][state_ordinal]` and `[...]['records'][record_index]` accept negative Python indices. argparse `type=int` passes them through.

- `--state-ordinal -1` selects the last (terminal) state.
- The envelope records `rawStateOrdinal: -1`.

This is exactly the implicit terminal selection the predicate forbids ("raw ordinal/record index must remain exact"). It is a concrete counterexample to that predicate.

Correction, placed first in the function:
```python
if type(state_ordinal) is not int or type(record_index) is not int or state_ordinal < 0 or record_index < 0:
    raise ValueError('explicit raw ITF state ordinal and record index must be non-negative integers')
```
Also add an `assertRaises(ValueError)` case for `-1` in the tests.

**M2 — `test_core2_await_boundary_wire.py`, `test_handwritten_cross_format_boundary_and_explicit_itf_ordinal`: the test's comments overstate what it checks.**

- (a) The first comment says "No expected value calls either codec". But the assertion's expected side is `wire.core2_observation(core)`, which is a codec call. The test is cross-codec equality over literal inputs.
- (b) The comment "No stutter removal or terminal/result search changes the selected ordinal" is not discriminated. The fixture has two states and selects the last one, at record index 0. A "last state", "terminal" or "first non-empty records" heuristic would also pass.

Correction:
- Reword (a).
- Add a third state after the selected one with a different record list, and select a record index greater than 0. Alternatively, narrow the claim to "selects the given index; does not mutate state 0".

The run can be recorded only with the narrowed claim until this is fixed.

### Hardening (non-blocking; out of scope only because of the stated positive canonical-serializer premise)

- **H1 — `_uint` is far looser than `ir.rs:19-31`.** `int()` accepts floats (truncating `2.5` to 2), `True`, `"1_0"`, `" 7"`, `"+7"`, `"007"` and Unicode digits. It also accepts values ≥ 2¹²⁸. A future real capture that lost precision upstream (a JSON number) would be accepted silently.
  - Fix: require `type(v) is str` and ASCII `0|[1-9][0-9]*`, and enforce ≤ 2¹²⁸−1. Use `type(v) is int` for `Error` offset/step.
- **H2 — no type checks on several scalar fields.** `_scalar` Bool, `advanced`, and the ExprId/`site`/`index`/`scale` fields are not type-checked. Python `False == 0`, so bool-as-int would also survive dict equality.
  - Fix: add `type(...) is bool` and `type(...) is int` checks.
- **H3 — `quint_typed_wire` drops nullary payloads without checking them.** The payload of `Q_NULLARY` tags is discarded unchecked. Assert that it decodes to `()` or `{}`.
- **H4 — inconsistent shape diagnostics.** Unknown Core `kind`/`ty` values raise `KeyError`, not `ValueError`. The Quint side does no shape validation at all. Inequality would still surface a mismatch, but it is not diagnosed.
- **H5 — comparisons should use canonical bytes.** Cross-format comparisons, both in test 6 and in Root's later comparison, should compare `json.dumps(sort_keys=True)` bytes, not Python `==`. This avoids `True==1`, `0==False` and `1==1.0` conflation, which matters because the declarations say "never bool-as-int".
- **H6 — `selectedRecord` is not a normalized wire.** In that provenance field:
  - Scenario `state`/`inputs` maps stay as dicts.
  - A Scenario map whose keys are exactly `{tag, value}` would be misread as a variant.
  - Non-`Q_NULLARY` unit tags (`NotAdvanced`) render as `{"NotAdvanced": []}`.

  This field is not compared. It should be described as provenance only.
