## Design faithfulness: disposition of F1–F6

**F1 — header/count same-lane cascade: fixed in the actual code.**  
In current `step`, every predicate and transition reads the entry register file `org`, and writes only into `nxt`. The four header increments test `org.phase`, so one lane cannot advance through multiple header phases. The 22 `count_step` calls also test only `org.phase`; a zero count selects that table’s zero-successor for the *next* lane, and a non-zero count stores `rem = lane` and selects only its row phase. The distinct-headers plus 22 zero-counts positive, truncation, and trailing-lane discriminations in Unit 4 therefore match the code. After `PH_END`, a further supplied lane is gated-rejected by the END assertion; stopping before END fails the final gated `phase == PH_END`.

**F2 — declaration/TypeExpr substate cascade: fixed in the actual code.**  
`string_step` now returns only a completion event. It does not itself advance the declaration phase. The following blocks discriminate on `org.phase`/`org.sub`, so a completion lane is not reinterpreted as the parameter-count, constructor-count, field-count, or TypeExpr tag lane. `PH_DECL_PARAMCNT`, `PH_DECL_CTORCNT`, and `PH_DECL_FIELDCNT` consume only a later lane whose entry phase is that count phase. Field-name completion selects `PH_TYPEEXPR` for the next lane and sets `te_need = 1`; the TypeExpr block in the same step still tests `org.phase`, so it does not consume that completion lane as a tag.

**F3 — length-as-byte: fixed in the actual code.**  
Current `string_step` computes `is_len`/`is_byte` once from `org.sub`. The length lane only performs cumulative length accounting, resets UTF-8 state, and stores `srem = lane`. Only an entry byte lane runs `check_lt(...,256)`, `utf8_step`, and the `srem` decrement. The TypeExpr string code uses the same entry-state discipline through `org.sub` for its length/byte/arity substates. One-byte and two-byte strings therefore consume length plus exactly their bytes in every string role reached by this code.

**F4 — empty strings never complete: fixed in the actual code.**  
In `string_step`, `len_done = cond_len && lane == 0` is a completion event and resets `sub` to 0 without entering byte state. The same rule is used for declaration name, parameter, constructor name, field name, and names-table strings. The TypeExpr unfolded string has the corresponding `str_done_now` path for zero length, including Named/Param/Apply names. Empty strings are therefore not forbidden and do not trap the machine in a length state.

**F5 — fixed/var rows advance irrespective of remaining count: fixed in the actual code.**  
Current `fixed_step` and `var_step` decrement `rem` only on the last sub-lane of a row, and select the next table/count phase only when that decrement reaches zero; otherwise they remain in the same row phase with `sub = 0`. This covers fixed-width rows, variable-width rows, and one-lane tables. The two-row counterexample now reads the second row’s tag lane as a row lane, not as the next count lane. Adjacent non-zero tables and mixed-width rows follow from the same entry-state transition discipline.

**F6 — constant `usize` omissions: fixed in the actual code.**  
`PH_CONST_ROW` is now included through the constant-payload exclusion logic: tag (`sub 0`), marker (`sub 1`), raw U128 payload (tag 0, `sub 2`), and Bool payload (tag 1, `sub 2`) are excluded from the generic `check_usize` payload domain, while Constructor type/ctor and Cons/Leaf/Branch slice start/len lanes receive `check_usize`. That matches `Reader`: program slices read **only two `usize` values** in `Reader::slice`, with no end, table, arity, membership, admission, or `StepInv` check. No DATA/HELPER slice-end validation has been imported into the program parser.

Otherwise, the static codec correspondence is present in code: 4 header lanes; 22 tables in `ProgramSnapshot` order; expression widths `[2,2,4,4,3,4,4,6,7]`; pattern widths `[2,1,3,2,3,1,5]`; plan widths `[8,6,3,2]`; constant widths `[3,3,2,4,4,4,6,2]`; declaration parameter/field and Apply arity under `max_arity`; declaration constructors under `max_names`; separate cumulative name-byte and template-byte budgets; global TypeExpr node budget; full Rust UTF-8 roles including NUL and multibyte scalars; option presence with absent-zero padding where the codec has `opt_usize`; and exact end by final phase plus END-lane rejection.

CTX is also exact as coded in `emit`: 22 lanes; header magic/version/tag gated; presence boolean gated; absent requires lanes `4..=19` zero; present checks lanes `4..=17` and `19` as `usize`; lane `18` is raw beyond the unconditional 128-bit lane range; lanes `20` and `21` are always `usize` budget lanes under the gate; absent and present-zero remain distinct at lane 3. ## Security: all-path operand-domain assessment

The new arity hunk is necessary but **not IR-identical**. In the TypeExpr arity block it inserts one `TestEq` (`te_zero`) and one `CondSelect` (`safe_raw`) immediately before the existing 128-bit `LessThan`, after the existing lane-cap `LessThan`, capped select, `te_need - 1` add, and `raw_need` add. Later temp serials in that emitted step shift by two. The normative stored relation is preserved for legitimate arity states: when `org.te_need != 0`, `te_zero = 0`, so `safe_raw = raw_need` exactly, and the following selector still stores `sel(rwithin, raw_need, bound)`.

I independently checked the frontier invariant rather than accepting the owner statement. `te_need` is set to `1` only on entry to `PH_TYPEEXPR` from field-name completion. On a leaf or completed Named/Param node it is decremented by one; if that decrement reaches zero, `apply_after_field` selects a non-TypeExpr successor phase for the next lane. On Apply, the arity lane replaces the consumed Apply frontier node by `te_need - 1 + capped_arity`; if the result is zero, the arity event again exits TypeExpr. Stored `te_need` is otherwise capped at `bound = max_type_expr_nodes + 1` by the existing selector. By induction over reachable TypeExpr entry/tag/string/arity states, an arity lane is reached only with `te_need ∈ [1, bound]`, except for the explicitly guarded dead zero state. Hence for nonzero reachable frontier states, `base ∈ [0, bound-1]`, `capped ∈ [0, bound]`, and `raw_need < 2*bound`, far below `2^128` under the host refusal of `usize::MAX` for used caps. For `te_need = 0`, `safe_raw = bound`, the comparison is in-domain, and the unchanged selector stores the bound sentinel only under the arity substate selector. The owner’s zero-state counterexample disposition is therefore correct, and I do not find the same field-minus-one operand feeding the guarded `LessThan` on the reachable paths above.

The other limited primitives and registers do not show a remaining width defect on the supplied code:

- Every supplied PROG lane receives `ConstrainBits(128)` immediately before its step, and every CTX lane receives it before CTX checks in `emit`.
- `cum_next_bounded` first caps the lane contribution at `limit + 1`, stores only a value in `[0, limit+1]`, and compares a raw sum below `2^65`; this applies to name/template cumulative budgets and the TypeExpr node counter.
- UTF-8 continuation arithmetic selects `safe_low ∈ [0,64)` only when the byte is in continuation range; the candidate codepoint is capped at `CP_CAP = 0x20_0000` before storage or minimum/maximum/surrogate comparison; `utf_min` is selected only from `{0, 0x80, 0x800, 0x10000}` or its prior value; `utf_pending` remains in the small pending set on reachable byte paths.
- `rem`, `cnt`, `cnt2`, `cnt3`, `srem`, and counter decrements feed `TestEq` or bounded reselection, not a 128-bit `LessThan` as a raw field-negative value.
- Program slices remain two raw `usize` lanes only. Separately, Push frame slices in Unit 2 use the field sum of two 128-bit lanes with a 129-bit comparator (`gated_lt_end` / `less_than_129`), which is the correct distinct frame contract and is not a program-codec strengthening.
- Gate behavior is coherent: gate is boolean-constrained; PROG/CTX lanes are range-constrained unconditionally; canonical assertions are gated; register transitions are total `CondSelect`s over `org`. Gate 0 therefore imposes no canonicality beyond raw 128-bit ranges in this leaf, while still evaluating bounded intermediate computations.
