### A. Specific Kernel & Source Analysis: `os.set_blocking(fd, False)` + `SECCOMP_IOCTL_NOTIF_RECV` (`L36–72`, `L213`, `L252`)

1. **`SECCOMP_IOCTL_NOTIF_RECV` Completely Ignores `O_NONBLOCK` (`os.set_blocking(fd, False)`)**:
   - In the supplied Linux `kernel/seccomp.c` (`PUBLIC-SOURCE-EXACT-RECV-WAIT-IOCTL-POLL.txt`, lines 1826–1835), `seccomp_notify_ioctl(struct file *file, unsigned int cmd, unsigned long arg)` extracts `struct seccomp_filter *filter = file->private_data;` and invokes `seccomp_notify_recv(filter, buf)` **without passing `file` or checking `file->f_flags & O_NONBLOCK`**.
   - Inside `seccomp_notify_recv(filter, buf)` -> `recv_wait_event(filter)` (lines 1524–1550), the kernel never inspects `O_NONBLOCK`. Thus R140's claim that `os.set_blocking(fd, False)` makes `fcntl.ioctl(fd, SECCOMP_IOCTL_NOTIF_RECV, buf, True)` non-blocking is **false**.
2. **Why Calling `SECCOMP_IOCTL_NOTIF_RECV` When `POLLIN == 0` (at `L213` and `L252`) Can Block and Lose Already-Collected Observations**:
   - In `recv_wait_event(filter)` (lines 1529–1547), `SECCOMP_IOCTL_NOTIF_RECV` sleeps in `schedule()` (`TASK_INTERRUPTIBLE`) whenever `atomic_dec_if_positive(&filter->notif->requests) < 0` **and** `refcount_read(&filter->users) > 0` (or on older/WSL kernels that lack the `refcount_read(&filter->users) == 0` early-return check).
   - In `run_case()`, `inspect_listener(listener)` is called both inside the selector loop (`L213`, before `proc` or its descendants have necessarily dropped `filter->users` to `0`) and **unconditionally** after `proc.wait()` and subreaper reaping (`L252`: `post_wait_listener = inspect_listener(listener)`).
   - If `refcount_read(&filter->users) > 0` when `L213` or `L252` runs with `requests == 0` (or if the running WSL kernel blocks in `recv_wait_event` even on `POLLHUP`), `fcntl.ioctl(fd, SECCOMP_IOCTL_NOTIF_RECV, ...)` **blocks in `schedule()` until the 4.0s `SIGALRM` fires**, raising `TimeoutError("4s internal wall cap")` and **discarding all `p2_at_l711` and `reparented_reaped` observations already collected in `run_case()`**!
3. **Pure `select.poll()` (`poll.poll(0)`) Suffices and Aligns With Production `network_pending()`**:
   - Unlike `SECCOMP_IOCTL_NOTIF_RECV`, `select.poll().poll(0)` is guaranteed non-blocking by the VFS `do_sys_poll` zero-timeout contract and calls `seccomp_notify_poll()` (lines 1855–1882), which immediately returns the exact bitmask: `EPOLLIN | EPOLLRDNORM` if any notification is in `SECCOMP_NOTIFY_INIT`, and `EPOLLHUP` when `refcount_read(&filter->users) == 0`.
   - Furthermore, the production guard `bounded_sdk_compile.py` (`087f3a37...`, lines 633–636) uses pure `select.poll()` (`any(events & select.POLLIN for _, events in poll.poll(0))`) and never calls `SECCOMP_IOCTL_NOTIF_RECV`.
   - Replacing `inspect_listener(fd)` with a pure `poll.poll(0)` inspector that records `revents`, `pollin` (true on any of `POLLIN | POLLPRI | POLLERR | POLLNVAL` so error/priority bits also fail closed), `pollhup`, and `pollerr` completely eliminates the blocking `ioctl` hazard while preserving both existing callers (`L213` and `L252`).
