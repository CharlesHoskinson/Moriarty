## SOURCE_SECURITY: **APPROVE** (with qualifications)

### Explicit inputs and no defaults

**What the source checks**
- All three variables are required: missing, non-UTF-8 or empty values panic. Every check happens before any host or native work.
- The SRS directory must be absolute and an existing directory.
- The degree cap must be 1–2 ASCII digits in the range 1..=19.

- The source contains no defaults, downloads, retries, fallbacks, cap changes or SRS generation.

**Validation versus permission**
- The degree-cap check is source validation only.
- `prepare` refuses when `ir.k()` exceeds the cap, before any SRS load or keygen.
- A cap of 19 or 17 grants nothing. Root's caps decide what is allowed.

**Qualifications (not mandatory)**
- The `starts_with` check is lexical: it does not follow symlinks or `..` components. This is an ordinary harness check, consistent with the stated scope.
- `"07"` is accepted as degree 7.

### SRS loader

The regular loader in `parameters.rs` does the following:
1. Opens with `O_NONBLOCK` and runs `is_file` on the opened descriptor.
2. Reads at most 128 MiB + 1.
3. Requires the pinned SHA-256 for `k` (20 entries, indices 0..=19).
4. Checks the 4-byte little-endian degree before the unchecked decode.
5. Requires the decoder to consume the full snapshot.

Given the pinned hash, symlinked SRS paths are harmless. `get_params` refuses any other degree. The test adds no SRS logic of its own.

### Task4 hook (verified independently from the complete body in 15)

**What `charge()` does**
- It locks `BUDGET` and does work only when the value is `Some`.
- When it is `None`, there is no slot lookup, no write, no counter and no panic.
- `.unwrap()` would panic only on a poisoned mutex.

**When `BUDGET` can become `Some`**
- The only write is in `begin()`.
- `begin()` is reached only from the ignored `task4_native_resource_gated_entry`.
- Before calling `begin()`, that entry must find `MORIARTY_TASK4_CASE`, and `begin()` must then match the binary SHA and admission environment values.
- The new test calls none of this.
- Every other `BUDGET` access is a read.

**Effect on this test**
- In a fresh process running only this selector, both `params_load` calls and all three `params_get` calls are no-ops.
- The only path to a poisoned mutex is through an armed Task4 run, which this selection does not include.
- The bridge charges nothing for keygen, prove or verify.

This hook closure is complete. No Task4 admission is inherited.

## Artifact sequencing and cleanup applicability

**Order of operations**
1. `create_dir` refuses if the directory already exists, so a race after the earlier existence check is safe.
2. The parent directory is fsynced.
3. The L4 program bytes and the zkir are written, each with create-new, file `sync_all`, then directory `sync_all`.
4. Prove runs.
5. The bundle is written **before** verification, so the proof is kept if verification fails.
6. Verify runs.
7. The report is written only after verify returns Ok and every assertion passes.
8. If prove or verify returns `Err`, `a102_native_error.json` is written with the stage and the Debug text (which includes the error code, so a k-cap limit, missing parameters or a keygen failure can be told apart), and the test then panics.

**Cleanup**
- Nothing deletes or overwrites anything; partial artifacts are always kept.
- The test writes nowhere except the fresh output directory.
- Root's existing retention can keep these artifacts without any source change.

**Qualifications (not mandatory)**
- An SDK panic, an abort (for example an allocation failure under `RLIMIT_AS`), or a host assertion failure after the bundle is written produces no error record. Only the captured panic or stderr remains.
- If `persist_native_error` itself fails, its panic replaces the original native error message.

**Input and setup facts Root must supply (ordinary facts, not new guards)**
- The output directory's parent must exist and be writable.
- Both the output directory and the SRS directory should be on a Linux-native filesystem. On this WSL2 host, avoid `/mnt/*` drvfs/9p mounts: directory `File::open` plus `fsync` may fail there and would panic.
- The SRS directory must hold the pinned `bls_midnight_2p{k}` for whatever `k` `ir.k()` returns. That `k` is unknown before running. If the file is missing, the test records a `parameters` error after the cost-model `ir.k()` and before keygen.
- Recommended invocation: `--ignored --exact <selector>` with `--test-threads=1`.
  - Even an unfiltered `--ignored` run could not arm Task4, because `MORIARTY_TASK4_CASE` and the env checks in `begin()` fail first.
  - It would still add a failing test, so exact selection is the right choice.
