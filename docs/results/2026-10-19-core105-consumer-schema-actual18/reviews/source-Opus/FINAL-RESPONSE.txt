### NOT eligible as specified: ops 15 and 16 — **CHANGES_REQUIRED (operations only)**

**The defect.** With `--test-threads=1`, libtest's pretty formatter writes `test NAME ... ` *before* running the test. With `--nocapture`, the test's own `println!` output then lands on that same line, and `ok` arrives on a later line.

**Effect on each op**, given the helper's `test_membership` regex `^test (\S+) \.\.\. (\S+)$`:

| Op | First test output | Regex outcome | Result |
|---|---|---|---|
| 15 Core1 | `actual_compile_only_artifact={...}` (JSON containing spaces) | no match | `results == []` → postcheck fails |
| 16 Twins | `complete_step_events_debug_path=/…` (no spaces) | matches, with that text as the result field | `results == [(name, "complete_step_events_debug_path=…")]` → postcheck fails |

A correctly passing test would therefore be rejected, triggering a fail-stop under the serial no-retry rule.

**Required fix — choose one, then record and pin it before selection:**
- **(a) Preferred.** In ops 15 and 16, replace `--nocapture` with `--show-output`. Captured output then moves to a `successes:` block, the result line stays clean, the existing `test_membership` works unchanged, and diagnostics are still retained.
- **(b) Alternative.** Keep `--nocapture` and specify the exact replacement check for these two ops:
  - stdout has the line `running 1 test`;
  - stdout begins a line with `test <exact name> ... `;
  - a standalone `ok` line appears before the summary line;
  - the summary is `1 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out`.

**Unaffected by the fix:** the Debug output policy is sound. Each env var has a fresh `create_new` path under the 16 MiB cap, and the file is written before assertions.
