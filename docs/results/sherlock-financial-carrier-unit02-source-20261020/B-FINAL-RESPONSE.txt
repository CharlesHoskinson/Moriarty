## 1. SOURCE_DESIGN_FAITHFULNESS — APPROVE

The chosen sealed immutable construction is actually implemented:

- `FinBoundSource`, `FinSnapshot`, and `FinAdmittedExtras` have private fields.
- The parent change is exactly `pub mod fin_carrier;` to `pub(crate) mod fin_carrier;`.
- `FinBoundSource` is constructible through `bind_fin_source`; `FinSnapshot` through `FinSnapshot::from_core` or checked mutations of an existing snapshot; `FinAdmittedExtras` through `FinAdmittedExtras::new`.
- Getters return immutable slices or references, or a `Copy` capacities value. Cloning preserves the checked values and does not create a mutation path.
- `FinAdmittedExtras::new` first calls `validate_fin_plan`, then enforces exact action count, order, and `FinActionPlan.name == FinActionBinding.text`.
- `bind_fin_source` now checks profile, strictly sorted names, `name_rows`, `name_bytes`, state/asset capacities, duplicate state declarations, duplicate asset declarations, cross-kind state/asset name collisions, duplicate asset identities, duplicate actions, initial scalar type against declared state type, and resolves the program name, state names, asset names, and action names into local `NameId` values before pushing bindings. This resolves the prior two-phase-borrow concern at source level.
- `FinSnapshot::from_core` clones the producing `FinBoundSource` into the snapshot. The identity actually enforced is structural equality over `names`, `states`, `assets`, `actions`, and `capacities`. That scope is correctly not promoted to full `ProgramView`, expression, occurrence, digest, cryptographic, admission, or V8 identity.
- The internal balance order is `(bound AssetId, account)`, and liability order is `name`. `to_core` therefore emits Core-canonical balance ordering even when declaration `FinAssetRowId` order differs from `AssetId` order, as exercised by `uc05_multi_asset_balance_liability_core_roundtrip`.

The owner statement that “no direct index remains” is literally false. The code still indexes `b.assets` in `FinSnapshot::from_core` sorting/duplicate detection and in `check_fin_snapshot`. Approval does **not** rest on that prose. It rests on the bound proof below.

## 2. SECURITY_AND_REFUSAL_COMPLETENESS — APPROVE

Sealing plus consumer rechecking is coherent:

- Production code outside `fin_carrier` cannot construct forged field vectors because the fields are private and the module is crate-private. The `#[cfg(test)]` child module can access private fields, but no such forged-vector test is claimed and test-module access is not a production construction path.
- Every consumer entry point calls `check_fin_snapshot`: `FinSnapshot::to_core`, `apply_set_state`, `apply_liability_add`, and `apply_transfer`.
- `check_fin_snapshot` checks stored-source equality, state length and types, balance/liability capacities, asset-row ranges, strict balance ordering by `(AssetId, account)`, and strict liability ordering by `name` before indexing bound assets in its ordering loop. The preceding range check makes those indexes bounded on that path.
- In `FinSnapshot::from_core`, each balance row’s `FinAssetRowId` is produced by `b.asset_row_of(&x.asset)`. In a genuinely bound source, `bind_fin_source` sets each binding’s `row` to its enumeration index in `b.assets`; therefore those later `b.assets[x.asset.0]` accesses are bounded for sealed production values. State conversion no longer silently truncates: `to_core` first requires shape equality and then verifies the rebuilt map length.
- `FinSnapshot::to_core` is now `Result`-returning and uses `b.assets.get(...)` for conversions.
- `apply_set_state` checks the snapshot, bound row, and scalar type before `get_mut` assignment.
- `apply_liability_add` checks source/shape first; existing-row addition validates the binary-search position and full `(name, asset, debtor, creditor)` identity, computes `checked_add` before assignment, and preserves sorted insertion with capacity checking on the `None` path.
- `apply_transfer` computes both `checked_sub` and `checked_add` before either assignment. For distinct rows, the later `if let Some(slot) = s.balances.get_mut(f/t)` assignments use positions obtained from the same exclusively borrowed vector with no intervening length change, so the missing-slot branch is unreachable on the current path and no partial debit/credit is introduced. Self-transfer checks sufficiency, performs no net movement, and still returns the transfer effect.
- Cross-source use is refused as `SourceMismatch` in `to_core`, `apply_set_state`, `apply_liability_add`, and `apply_transfer` when the two sources differ in any carried structural field. Structurally identical sources are intentionally interchangeable under the owner’s stated equality scope; that is not upgraded to authentication.

No concrete production counterexample in the six UC classes remains in the current module.
