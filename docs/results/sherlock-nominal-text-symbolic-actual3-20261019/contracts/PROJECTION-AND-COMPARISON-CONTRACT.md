# Nominal text capture to independent source-symbolic comparison

Status: declaration-only comparison design. No compiler/runtime implementation, populated expected body, predicted source-author outcome or actual capture was read for this task. The independent oracle remains unchanged. A different ordinary source author must implement this passive comparator; the oracle author will not implement or approve its own semantic comparator. Root selects actual capture, freezes it durably, then separately binds the sealed expected input.

## Inputs and fixed output

Inputs are the complete two original source byte strings under the original safe manifest, their retained admitted source/program identity and declaration tables, complete initial image, every actual before/event/after record and terminal image, and the opaque expected document bound by SAFE-BINDINGS. The declaration-only actual wire/type inventory must pin every consumed field/variant. No omitted record can be replaced by a summary, and no total or expected value can be reconstructed from a producer summary.

The implementation has two phases in one finite pass over saved JSON. Phase A accepts only source and frozen actual files. It produces an actual-derived source-symbolic document, a physical association ledger, diagnostics and exact input/output pins. Phase A cannot open the expected path. Root durably freezes those outputs. Phase B may open the exact opaque expected document and compare only the declared source-symbolic fields. No producer/compiler/evaluator/model/prover is invoked, imported or re-entered in either phase. This is a data consumer, not another source evaluator.

The source-symbolic output uses the existing sherlock-nominal-text-symbolic-expectation/1 case field shapes. Author/scope/pins are provenance; comparison must select the semantic case fields explicitly rather than pretending independent author metadata equals producer metadata. Ordered arrays are compared in full. Symbolic environment object key order is irrelevant; names and full values are exact. No wildcard expected cell or hash-only nominal-value comparison is permitted.

## Source association before semantic recognition

1. Bind original input bytes, exact program source identity, supported grammar/profile and complete admitted program membership. A merely successful capture does not prove all those bindings.
2. Walk retained source occurrence membership and ordered child/parameter/field/arm slices. Map entry/function root and zero-based child path to exact actual source occurrence and expression identities. Resolve function names and source-scoped nominal type/constructor declarations, preserving all generic arguments and declaration field order. Store both symbolic and raw identities in the ledger.
3. Preserve the distinction between source arm ordinal, actual global ArmRow index and any compiled plan/case identity. Prove their association from retained provenance. Repeated dynamic visits reuse source identity but receive new semantic invocation identities.
4. A missing, multiply-associated, out-of-bounds, wrong-owner, wrong type application or incomplete mapping yields a located mapping gap. Do not default to row0, infer from equal values or choose whichever actual event matches an expected value. The actual-only phase must not use expected rows to disambiguate.
5. Any source syntax reconstructed from actual rows is a declaration/provenance walk, not evaluation. If the actual wire lacks the source-to-admitted association needed for a path, request an additive output declaration/association from the capture owner; do not synthesize it from expected results.

## Value and environment decoding

Decode every retained value reference through the declared active typed data/constant tables. Preserve source nominal type application, constructor and complete ordered structural fields. UInt128 is an exact decimal string; do not pass through floating point. Distinguish empty fields from missing fields. Physical sharing unfolds to structural values while the physical reference is retained in the ledger. Invalid references, cycles inconsistent with finite values, truncated fields, ambiguous constructors or unsupported scalar/value forms are located gaps, not approximate values.

Decode lexical lookup semantics from declaration-only environment representation. Produce the first-visible name-to-value map, preserving raw ordered rows separately; reject duplicate visible source-name associations without a specified shadow rule. Fresh callee parameter maps are ordered by the declared parameter slice for binding, then normalized as symbolic objects for comparison. Saved caller maps are decoded from saved frames/images rather than copied from expected parameters.

## Transition recognition obligations

Recognition must be based on declared successful transition/control/frame payloads and their exact source association. Helper steps may repeat controls; no state-scanning heuristic may count the same semantic entry twice. Every recognized semantic item carries a raw record/interval span and raw source identity in the ledger. Unrecognized relevant events must be disclosed; arbitrary omission is not allowed.

- **Call entry:** after argument accumulation, exactly the successful body-entry transition. Associate the original source Call occurrence, function, ordered completed arguments, full caller lexical map and fresh declared parameter map. Recursive calls remain separate dynamic instances. A call-start/argument-start event alone is not body entry.
- **Match selection:** exactly the winning selection after one evaluated scrutinee, under original source arm order. Decode full scrutinee, actual winning source arm association, all bindings in source-pattern preorder with full root-to-field paths, and the selected body source identity. A candidate attempt/miss is not another match invocation. Compare first-arm ordinal and binder paths, not just returned value.
- **Construction opening:** exactly the source Construct scheduling action before its first field (or the declared nullary scheduling action), assigning the next construction invocation. Preserve its original ordered field expressions, declared type/constructor application, saved lexical map and enclosing function invocation.
- **Construction completion:** exactly the successful materialization of that same pending instance, producing its complete ordered field values. Use history/stack identity and original source occurrence to pair it to its opening; repeated recursive source sites cannot be paired by source ID alone. Opening records may be completed with eventually observed field values, but cannot be falsely described as already materialized at opening. Nullary instances must follow an explicitly declared recognition rule.
- **Final value:** only a declared successful completed pure outcome with no pending source return. Decode the complete nominal value from the terminal image. Intermediate Return is insufficient.

If the current event ABI does not expose a necessary identity or boundary, the comparator must name the exact missing declaration/field and mark that comparison unbound. It must not infer an undocumented transition from implementation bodies or fit a rule to actual data.

## Pending constructor checkpoints

At each recognized function entry, derive actual pending source constructions from complete live frames/control/history. List them outermost first. For each retain opening-assigned construction invocation, original Construct path, current original source field position, complete prior field values and saved lexical map. The active field source is the original field expression, even if the last executed expression is a callee leaf. The active position excludes completed prefix and later fields; full original field-vector membership remains available in the ledger.

Also retain the actual call's caller lexical map and fresh callee parameters. Associate each expected checkpoint by its independently assigned actual source-call invocation, not by searching for expected values. All declared expected checkpoints must exist once at the defined semantic milestone; extra/missing relevant call entries are compared in the complete call array. Source checks are existential milestones, not every physical helper frame/prefix or a cost bound.

## Whole comparison and refusal

Compare complete final_value, ordered calls including full arguments/caller_environment/callee_parameters, ordered matches including full scrutinee/selected_body/bindings, construction open_order/materialize_order including complete fields/source/saved_environment/in_call, and all expected pending checkpoints. Derive ordinal spaces independently from actual recognition before expected read. Constructor IDs are assigned at opening and reused in materialization. Array lengths and every cell must match; no prefix-only or final-value-only pass.

Per case report PASS only for fields actually bound and equal, with all source/provenance/mapping checks stated. Any requested field unbound makes the complete declared projection NOT ESTABLISHED; retain the positive subchecks without claiming full comparison. First mismatch includes exact JSON path and bounded separate actual/expected excerpt after authorized unblinding. Do not repair expected data, add missing expected cells, rerun the source, mutate capture or use expected values to alter Phase A.

Raw physical rows, exact helper/control schedule, complete B microstep oracle, workMap/counters/fuel/capacity, source acceptance, circuit/native/recursive-proof/target and global EARS predicates remain outside this source-symbolic equality. Preserve those actual fields in capture and association receipts without assigning independent expected numbers.
