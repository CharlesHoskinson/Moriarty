## C. Passive comparator audit (`compare_frozen_data.py`, e9477ad9)

**uint exactness and no bool/float coercion on the actual side.** Confirmed.
- `uint()` requires `str`, matches `0|[1-9][0-9]*` exactly (ASCII digits only, no sign, whitespace or leading zeros), and requires a value below 2^128.
- `normalize()` rejects every non-string, non-list value.

**Strict typing on the expected side.**
- The 2077-lane expected statement is checked with `type(n) is int`, which excludes bools and floats.
- Image and metadata comparisons go through `json.dumps(sort_keys=True)`, which distinguishes `true` from `1` and `4.0` from `4` and fails closed.

**Whole metadata.**
- For each of the 2077 lanes, the actual lane object must equal exactly the 7-key dict built from LAYOUT (index, path, name, bits, boolean, `maximum_dec`, `value_dec`). Extra or missing keys fail.
- `value_dec` is compared with `str(actual public value)`. Combined with `valueEqual`, this transitively binds `lanes[].value_dec` to the expected value.

**Three images.**
- Program, pre and post are each compared as root plus every table, in `table_order`.
- Each is also compared against the whole flat list: 707, 683 and 683 lanes.
- The actual image key set must be exactly `{root, tables}`.

**Two context lanes plus 2075 values.**
- Exact string match on the context limbs.
- All 2077 values against the strictly typed expected statement.
- 2075-lane view against the original noncontext file.

**685 producer projection.**
- `actual[1392:]` equals return-projection-685. This is the post image followed by the envelope `3,1`.
- The IR's single Output references exactly ids 1392..2076.
- The report qualification states correctly that these are producer statement lanes, not SDK outputs. `check` exposes only `pi_skips`.

**No source-authentication claim.** Reference and K identities are labeled `ClaimIdentity`. Both the report qualification and INPUT-IDENTITIES disclaim authentication.

**Provenance.**
- Every file the comparator reads is pinned, transitively:
  - the 15 original pins via EXPECTATION-FREEZE;
  - the 4 private pins via PRIVATE-MATERIALIZATION-FREEZE;
  - the 3 actual pins via ARTIFACT-FREEZE (itself pinned by literal hash).
- All pins are re-hashed after loading, which guards against changes between pinning and reading.
- No SDK, producer or evaluator is executed.
- The layout hash 2eef6d6f… sits in the original October 18 freeze and equals the actual value. That is a genuine pre-frozen agreement.

**Report body not inline: acceptable.** The script asserts `all(checks) and not mismatches` *after* printing. Exit 0 under `timeout`/`prlimit` (which propagate status) therefore corroborates the inline stdout summary independently of the 1,246,537 B body.

**Coverage limits.** State these explicitly.
1. Only the PI, Impact, Output, inputs, outputs and communications-flag structure of the 30,289-instruction IR is compared. The remaining ~26,134 instructions (limb ConstrainEq, dispatch, the literal fragment) have no independent expectation. They are covered only by SDK satisfiability and the negative checks.
2. PI/Impact interleaving is not checked.
3. Some artifact fields are uncompared: `fixture`, `check_outcome`, `open_obligations`, `byte_counts`. They agree by eye.
4. Agreement on `context_hash` is agreement between two computations over the same pinned source bytes. It does not authenticate those bytes.
5. Timestamps of the expectation freezes are custody assertions; hashes prove content, not time.

**Hardening notes (non-blocking, no rerun).**
- **H1.** `noncontext2075`, `producerPostEnvelope685` and `stackCapacity` use Python `==`, which would accept `True == 1` or `1.0 == 1` on the expected side. This is harmless here: the pinned files visibly contain only integer tokens, and the strictly typed `all2077StatementValues` covers the same lanes.
- **H2.** `json.loads` accepts duplicate keys and NaN. This is immaterial here, since every value is fail-closed or strictly typed.
