- All 5 receipts are checked for `regular`, size and SHA before any `jload`.
- The manifest key set must equal `P11_EVIDENCE_FILE_BYTES`.
- Each evidence file is checked for `regular`, size and manifest digest before it is read.

**Cleanup state: current versus historical.**
- *Current state:* `status=='DONE'`, top-level `cleanupOwed is False`, the 4 absence/no-Cargo/no-ELF booleans, `evidence==P11_EVIDENCE_ROOT`, the teardown descriptor, and teardown `actual_exit==0`.

**Counts, stream and terminal checks.**
- `counts.result` equals the outer pin triple.
- `rawUsageUsec`, `previousHistory`, `cumulativeUsec` and `currentResidualUsec` are all tied to the constants.
- `F_precheck.stderr` bytes must equal `counts.failure`, which keeps the 112B F stream distinct from the 39B controller stream.

- Outer: `exact` 5-key schema, `id`, `actual_exit==2`, `controller_failure is None`, and `elapsed_seconds` equality (the JSON float round-trips).
- Every literal agrees with the supplied actual records: outer result, cleanup, teardown, manifest and the cpu.stat files.

### `enforce_post_p11_historical_debits`
- Layers exactly once over `enforce_post_p10` (unchanged).
- Checks the per-key sum invariant and the chained residual, stream, wall and CPU equalities.

### `cached_current_f`
- Both start and end accounting now go through P11.
- `Group.prior_cpu` is fed from `effective_phases_usec_at_start` under P11.
- RLIMIT_CPU is `min(cfg, 10547)`.

### Non-blocking observations
1. **Missing keys and wrong types.** `cleanup['counts']` and `jload(manifest)['files']` use subscripting. A missing key raises KeyError, which `main` catches as a refusal. A TypeError would not be caught, but it still fails closed with a nonzero exit. Exact pinned bytes make both moot.
2. **Raw cpu.stat files are not listed in `P11_RECEIPT_PINS`.** The exact-byte template provides equivalent strength (counts verified above).
3. **Outer `streams[]` are not cross-checked field by field.** They are covered transitively by the pinned RESULT digest, and the standalone stderr pin `9b4078…` equals the stream SHA inside RESULT.
4. **The camino A0 digest refusal in `reconstitute_source_home` is unchanged and must stay that way.** Any future native run will refuse again until a separately reviewed historical restoration route resolves it. That route is out of scope here and is not a source defect.
5. **Routing label for the security receipt (Root admission issue, not this cut).** The fallback tuple literal in `consent` is labelled `standing_opus_quota_outage_fallback`, but the actual cause was a classifier ABSTAIN. Root must not relabel that cause when it issues any security receipt.
6. **RLIMIT_CPU is a per-process bound against a cgroup-history budget.** This is the same class as before and is conservative.

**Limits on this opinion.** It is a normal (non-security) source opinion on this exact two-file cut only. It does not establish native, config, admission, cgroup, provisioning, proof or stagenet eligibility, or the behavior of the real cache or namespace.

### Meaningfulness of each test
- **Test 1.**
  - Asserts the literal carry values (1092254321, 252227979, 840026337; residual 5 and 1; 5921, 2021, 10547; 59519, 112, 39), independently of helper constants.

- **Test 2.**
  - Covers outer pin SHA, outer stderr size, a manifest extra key (after a valid re-pin), and a manifest digest versus file mismatch.

- **Test 4.** Covers outer `actual_exit`, `controller_failure`, `elapsed_seconds`, and a same-length terminal type mutation. Each is re-pinned through `sy()`, so only the target check can fail.

### Coverage limits (not blocking, recorded honestly)
1. **The 112B-versus-39B stream distinction is only tested indirectly.** No negative test covers the `F_precheck.stderr == counts.failure` equality, despite test 4's name.
2. **Several checks have no negative test.** These are `counts.phase`, `result`, `rawUsageUsec`, `previousHistory`, `cumulativeUsec`, `currentResidualUsec`, the Cargo/SDK/ELF flags, `oneShotConsumed`, outer `id`, cleanup `evidence`, the `EandSupervisorAndPhasesAbsent`, `noCargo` and `noELF` flags, and the teardown descriptor.
3. **Untested caps.** Live supervisor above `supervisor_cpu_seconds × 10⁶` and the envelope combined cap.
4. **Assertions are coarse.**
   - Refusal assertions check the type only, not the message.
   - In tests 2, 4 and 5 the positive baseline is not re-asserted between mutations. Restoration is correct by inspection.
5. **Some fixtures mirror production.**
   - The cpu.stat template and `P11_OUTER_SECONDS` are drawn from helper constants.
   - The synthetic terminal JSON is 110B, not the actual 111B.
   - The tests re-pin the receipts and evidence constants to synthetic fixtures. Binding the production literals to the actual records is established by Root's pin-check record and my own literal comparison, not by these tests.
6. **The fake guard differs from the real one.** Its `jload` has no duplicate-key hook, and its `regular` uses `is_file` semantics. The real `enforce_post_p10`/r3 layering and the real guard namespace are not exercised. This is finite owner QA, not a whole-history oracle.
