# Core2 financial observation adapter

Public Rust path: `mori_core::sherlock_financial_projection`. This module borrows
the existing local Core/2 stage carriers and derives diagnostic accounting for
one published successful segment. `stage::load`, `stage::start` and
`stage::resume` produce the program and results; projection does not execute
them or establish that a supplied program/input produced a supplied result.
See the [implementation](../../../crates/mori-core/src/sherlock/financial_projection.rs)
and [public export](../../../crates/mori-core/src/lib.rs).

## Entry points

All observation lifetimes borrow the caller's existing values.

| Function | Input and result |
| --- | --- |
| `project_execution` | `&Execution` to `ExecutionObservation` |
| `project_segment` | `&StageSegment` to `SegmentObservation` |
| `project_stage_result` | `&Result<StageOutcome, StageRejection>` to `FinancialObservation` |
| `project_resume_result` | Captured continuation, event, optional CLI action/cap and result to `ResumeFinancialObservation` |
| `project_invocation` | `&StagedProgram`, `InvocationInput` and raw result to `InvocationObservation` |
| `account_effects` | `&[Effect]` to `AccountingReport` |
| `financial_observation_matches` | Raw actual result and expected `FinancialObservation` to `bool` |
| `resume_financial_observation_matches` | Actual and expected `ResumeFinancialObservation` to `bool` |

`InvocationInput::Start` retains action, scenario and cap.
`InvocationInput::Resume` retains continuation, event, CLI action and CLI cap.
`InvocationObservation` retains the complete program reference, captured input,
raw result reference, projected outcome, accounting availability and tentative
publication classification. The original program/plan and their hashes remain
available through `StagedProgram`'s getters. The older
`ResumeFinancialObservation` omits the staged program argument; continuation
hash claims cannot substitute for that actual argument.

## Complete observations

`ExecutionObservation` retains semantics, action, full pre/post `Snapshot`s,
ordered `Step`s and ordered `Effect`s. Each step retains index, statement,
optional value, complete snapshot and effects. Snapshots retain every state
entry, balance and liability, including unaffected entries and liabilities
whose amount is present zero. `SegmentObservation` also retains action and both
`PendingFrame`s, including site and captures. These are the
[Core data types](../../../crates/mori-core/src/ir.rs) and
[stage data types](../../../crates/mori-core/src/stage/mod.rs), distinct from
Sherlock A/B machine snapshots.

| `FinancialObservation` | Preserved fields |
| --- | --- |
| `Waiting` | `advanced`, optional segment, full continuation, attempted work and ordered residual duties |
| `Complete` | Full segment, committed and attempted work, ordered residual duties |
| `Rejected` | Actual error, attempted and committed work |

A false await can return `Waiting { advanced: false, segment: None, .. }`.
It is not converted to an empty execution. A returned `Some(segment)` with zero
effects remains present and retains its steps, frames and state. Residual duties
are the stage carrier's positive-amount liabilities; complete snapshots also
retain present-zero rows.

`committed_boundary()` returns the waiting continuation boundary or complete
segment post-state, and returns `None` on rejection. `successful_segment()`
returns only this invocation's published segment. `committed_logical_work()`
returns the reported counter, not an independently validated charge. Early
resume refusal can echo an unvalidated input counter.
`ResumeFinancialObservation::input_boundary()` exposes caller input even after
rejection; that input is not a returned rollback continuation.

## Accounting and publication

`AccountingReport.effects` retains the entire original ordered effect slice.
`accounts` groups transfer and fee entries by exact `(AssetId, account)` in
first encounter order, visiting debit before credit. Rows contain
`transfer_debit`, `transfer_receipts`, `fee_debit`, `fee_receipts`,
`gross_debit`, `gross_receipts` and `net_flow`. State, liability and emit effects
remain in the raw effects; they create no monetary aggregate row. An account
without a monetary effect remains observable in the complete state.

`AmountAggregate::Exact(UInt)` uses checked addition. Overflow becomes
`AboveU128` and remains explicit; values are neither clamped nor wrapped.
`NetFlow` is `Balanced`, `Inflow(UInt)`, `Outflow(UInt)` or `Unavailable` if
either gross aggregate is unrepresentable. Fees already contribute to gross
debit/receipts. Reverse transfers do not erase gross debit. A self-transfer
records both its debit and receipt.

| Returned carrier | `AccountingAvailability` | `TentativePublication` |
| --- | --- | --- |
| Successful published segment | `PublishedSegment(report)` | `PublishedSuccessfulSegment` |
| Waiting with no segment | `NoPublishedSegment` | `NoAdvancedSegment` |
| Rejection | `RejectedNoPublishedDelta` | `UnavailableFromStageRejection` |

`StageRejection` has no failed tentative snapshot, discarded effects or
replacement continuation. The adapter synthesizes none. Accounting describes
one successful segment, not cumulative prefix history, native fees, DUST or
ledger phases. Preserve `stage::STAGE_LABELS` when publishing local stage
observations: authentication is absent and consumption is untracked.

# Observe a Core2 stage financial result

Use `mori_core::sherlock_financial_projection::project_invocation` at the actual
stage call site to retain the original program, inputs and complete returned
result. This guide uses the existing retained-payment fixture and its false
then true events. The [API reference](../reference/financial-observation-adapter.md)
defines the borrowed fields and accounting cases.

## Capture the actual calls

In a Rust application with `mori_core` and `serde_json` available, use this
complete example with the repository root as the working directory. It calls
the existing local Core/2 producer; the projection itself performs no stage
execution. The fixture's action is `pay` and its start/resume caps and CLI action
are null, represented below as `None`.

```rust
use mori_core::{stage, Scenario};
use mori_core::stage::{StageEvent, StageOutcome};
use mori_core::sherlock_financial_projection::{self as projection, InvocationInput};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let base = "crates/mori-core/tests/fixtures/financial-observation";
    let source = std::fs::read_to_string(format!("{base}/retained-payment.mori"))?;
    let scenario: Scenario = serde_json::from_str(
        &std::fs::read_to_string(format!("{base}/scenario.json"))?)?;
    let inputs: serde_json::Value = serde_json::from_str(
        &std::fs::read_to_string(format!("{base}/invocations.json"))?)?;
    let events: Vec<StageEvent> = serde_json::from_value(inputs["events"].clone())?;
    let program = stage::load(&source)?;

    let start_result = stage::start(&program, "pay", scenario.clone(), None);
    let start_view = projection::project_invocation(
        &program,
        InvocationInput::Start { action: "pay", scenario: &scenario, cap: None },
        &start_result,
    );
    println!("{:?}\n{start_view:#?}", stage::STAGE_LABELS);

    let mut continuation = match &start_result {
        Ok(StageOutcome::Waiting { continuation, .. }) => continuation.clone(),
        _ => return Ok(()),
    };
    for event in &events {
        let result = stage::resume(
            &program, continuation.clone(), event.clone(), None, None);
        let view = projection::project_invocation(
            &program,
            InvocationInput::Resume {
                continuation: &continuation, event, cli_action: None, cli_cap: None,
            },
            &result,
        );
        println!("{:?}\n{view:#?}", stage::STAGE_LABELS);
        match &result {
            Ok(StageOutcome::Waiting { continuation: next, .. }) => {
                continuation = next.clone();
            }
            _ => break,
        }
    }
    Ok(())
}
```

Retain the result and captured values for as long as a view borrows them. Passing
an unrelated result to the projection does not validate its provenance. Keep
the original full result when exporting an observation; account aggregates
alone omit steps, nonmonetary effects and unaffected state.

# About chunks, projection and financial boundaries

Draft, 2026-10-17. Final03 specifies the planned persistent boundary contracts below; production persistent storage/import remains missing.

A chunk groups a contiguous portion of machine execution. It changes where evidence is divided, not which language transition occurs. A cut before an inner call returns must preserve the caller environment, pending operation and remaining work. A cut before terminal publication must preserve that publication as pending. Restarting either case from a convenient source expression would describe a different computation.

Within one Step representation, the next record consumes the exact previous output. At a persistent boundary, the proposed projection may drop unreachable physical rows or renumber references while preserving decoded semantic meaning. That is why a correct resume needs both the original Step image and an explicitly successful canonical projection, with program/profile/layout/bounds, complete frames and helper cursors, pending result, supported origins and work/allocation counters. Physical occupancy and logical allocation are different quantities. Projection refusal is a tooling failure, not application exhaustion.

The existing public A codec supports trusted diagnostic encoding/decoding/materialization. It is not an arbitrary Machine-state importer or canonical native wire ABI. Test-only image/checkpoint/slice helpers and repeated `visit_steps` calls on one in-memory Machine do not establish persistent export/import. The later actual stream attempt includes eight passing in-memory observation tests, including a recursive cut preserving caller environments and a cut before zero-fuel publication. Its 216-run comparison adds host observation evidence while leaving persistent boundary storage/import unimplemented. Final03 retains the existing Opus-owned StepInv and canonical-boundary requirements without claiming that those obligations have been discharged.

A financial commit is a different boundary. It records the language/ledger transition that makes effects and duties persistent. Await, recovery and later-segment failure have their own phase meanings. A technical proof cut creates no payment, discharge or fee policy. A pure return also supplies no evidence of financial settlement.

The existing Core/2 load/start/resume behavior is the starting point for the financial owner's mapping; universal Commit/Yield/Await opcodes have not been selected by this explanation. The final03/R18 map distinguishes committed snapshot from tentative segment, ordered effects including supply changes, gross debit/fees/net receipts, reserves/dust, liability identity/value, pending captures/observations and residual duties. Earlier committed prefixes must retain their specified meaning when a later local segment fails before commit. Guaranteed/fallible ledger phases remain separate from local semantic outcomes.

These requirements matter even when the final balance happens to match. A refund can conceal gross debit, fees can change net receipts, and an omitted pending duty can change the next segment. Complete prefix observations explain how the outcome arose. The independent proposed financial oracle currently omits the full PassT result; a comparison must remain B/F-only until that result has its own expectation.

See [image/layout boundaries](../reference/image-layout.md), [bridge/ledger consumers](../reference/bridges-ledger.md) and [complete-observation comparison](../how-to/compare-complete-observations.md). [Observation boundaries](observation-boundaries.md) explains the narrower in-memory grouping API.

def requirement_evidence_report(repo, path):
    """Validate declared row membership/currentness, never decide semantic acceptance.

    The optional sidecar carries owner assessments. Reading matching files does
    not authenticate an audit or execute a scenario. Bare corpus/snapshot checks
    never call this function or read its catalogue/evidence dependencies.

    require(type(ledger) is dict and ledger.get('schema') == 'sherlock.current-requirement-evidence/1',
            'unknown requirement evidence schema')
    require(type(ledger.get('retainedInventory')) is list and ledger['retainedInventory'],
            'retained requirement-family inventory required')
    issues, cache = [], {}

    def issue(findings, kind, location, message, **detail):
        findings.append(dict(kind=kind, location=location, message=message, **detail))

    def pinned(ref, location, findings):
        if (type(ref) is not dict or type(ref.get('path')) is not str or not ref['path']
                or type(ref.get('sha256')) is not str
                or re.fullmatch('[0-9a-f]{64}', ref['sha256']) is None):
            issue(findings, 'invalid', location, 'reference requires path and SHA-256')
            return None
        target = Path(ref['path'])
        if not target.is_absolute():
            target = Path(repo) / target
        key = str(target)
        if key not in cache:
            try:
                cache[key] = target.read_bytes()
            except OSError as error:
                cache[key] = error
        raw = cache[key]
        if isinstance(raw, OSError):
            issue(findings, 'missing', location, 'declared file cannot be read', path=ref['path'])
            return None
        if any(key in ref for key in ('startLine', 'endLine')):
            start = ref.get('startLine', 1)
            end = ref.get('endLine', start)
            if (type(start) is not int or type(end) is not int or start < 1
                    or end < start or end > len(raw.splitlines())):
                issue(findings, 'invalid', location, 'declared line span is outside the file', path=ref['path'])
        if 'claim' in ref and type(ref['claim']) is not str:
            issue(findings, 'invalid', location, 'reference claim must be a string', path=ref['path'])
        actual = digest(raw)
        if actual != ref['sha256']:
            issue(findings, 'stale', location, 'declared file bytes changed', path=ref['path'],
                  expected_sha256=ref['sha256'], actual_sha256=actual)
        return raw

    def integrity(findings):
        return next((kind for kind in ('invalid', 'missing', 'stale')
                     if any(row['kind'] == kind for row in findings)), 'current')

    def declared_path(ref):
        candidate = Path(ref['path'])
        return candidate if candidate.is_absolute() else Path(repo) / candidate

    catalogue_raw = pinned(ledger.get('requirementCatalogue'), '/requirementCatalogue', issues)

    inventory_raw = pinned(inventory, '/refinementInventory', issues)

            (inventory, 'openspec/changes/sherlock-completion-convergence/specs/sherlock-completion/spec.md')):
        if type(ref) is dict and type(ref.get('path')) is str and declared_path(ref) != Path(repo) / expected_path:
            issue(issues, 'invalid', '/inventory', 'catalogue must name the retained canonical specification', path=ref['path'])
    require(catalogue_raw is not None and inventory_raw is not None,
            'requirement catalogue or refinement inventory unavailable')
    def sections(raw):
        result = {}
        for part in re.split(r'(?m)^### Requirement: ', raw.decode('utf-8'))[1:]:
            heading = part.splitlines()[0]
            identifier = heading.split(' ', 1)[0]
            require(identifier not in result, 'duplicate requirement heading in catalogue')
            result[identifier] = dict(heading=heading,
                scenarios=re.findall(r'(?m)^#### Scenario: (.+)$', part))
        return result
