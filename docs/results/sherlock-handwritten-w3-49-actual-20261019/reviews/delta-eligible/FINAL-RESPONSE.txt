## 1. Delta read: what the new bodies establish

### D01 `enabled_fetch.rs` (lifts F1)

**Effects.**
- The code is pure host construction: `format!` identifiers, `Vec` pushes and `checked_*` arithmetic.
- It does no I/O, touches no environment or global state, makes no SDK calls beyond type constructors, and has no `unsafe`.
- With this file read, the class `HOST_EMITTER_EVALUATOR_OR_CONSTRUCTOR_CHECK` is supported across the closure of the 22 operations (01–08, 34–37, 40–49).

**Panic freedom given `check_rows`.**
- The only indexing is `inputs.rows[row][column]`, with `row < capacity` and `column < columns.len()`.
- That is safe given the `check_rows` row and column checks (mod.rs, retained read). `selectors.len() == capacity` by construction.

**Instructions emitted.** The block emits only:
- the output of `constrain` (from mod.rs);
- `CondSelect`, `LessThan{bits:128}`, `ConstrainEq`, `Assert`, `TestEq` and `Add`.

It emits no `DivModPowerOfTwo`, `PublicInput`, `Impact` or `Output`. That removes the concrete incompatibility the prior review named for the W3-07, W3-09 and W3-12 interpreters.

I cannot freshly confirm each interpreter's match arms. Any residual mismatch would show up as a test failure, not as an eligibility or effects problem (see R4).

**Op 42 naming.** `Builder::fresh` yields `%{scope}.temp.{serial}`. The first `fresh()` call is always the `index_eff` select, which is emitted even at capacity 0. So `.temp.0` exists whenever the block is emitted. Op 42's `%…const_fetch.temp.0` and `%…data_fetch.temp.0` are consistent with this, provided the caller's scopes are `ns_s1_arith.const_fetch` and `ns_s1_arith.data_fetch`; that is the retained read of the call sites.

**Counting comments are correct.**
- Enabled block: 4 + N(C+3) temporaries. That is 4 fixed, 3 per row (`TestEq`, select, sum) and N·C lane selects.
- Unconditional block (D02): 2 + N(C+2).

**Zero capacity.** The sum is the immediate 0, and it is constrained equal to `enable`, so `enable` must be 0. `active_rows` is forced to 0. The guarded prefix assertion fails if `enable` is 1. This is consistent with the zero-capacity and disabled-branch tests. It is a source-consistency observation, not a pass prediction.

**Namespace check.** It covers `enable`, `active_rows`, `index` and every row cell. Collisions with other fragments remain the composer's documented obligation. That is the subject of op 42, and it is not a defect here.

### D04 `lib.rs`

- **Test-name prefix.** `pub mod sherlock_machine;` sits at the crate root, so the `sherlock_machine::…` prefix of all 49 names is source-supported. Op 00 remains the actual check.
- **`Type` is closed.** `Builder::range` matches `Type::UInt` and `Type::Bool` exhaustively with no wildcard, across a crate boundary. So `mori_core::Type` has exactly these two variants and is not `non_exhaustive`, which makes `constrain(…, kind)` total.
- **No startup code.** The crate root has no inline test module, no `ctor` and no `.init_array`. Dependency-level life-before-main is not proven; that is Q5.
- **N is large and unknown.** The crate declares many other public and private modules (authorization, replay, schnorr, signed_relation, stage, source_projection, liabilities, parameters, proving). They contribute tests to the same libtest binary. This sharpens R1.

### D05 and D06 manifests

- There is no `[lib] harness=false` and no custom `[profile.dev]`. So the build uses the default libtest harness with dev defaults: `panic=unwind`, `opt-level=0`, and `debug-assertions` and `overflow-checks` on. Only `insta` and `similar` get `opt-level=3`.
- **Consequence 1.** u128 overflow inside the test interpreters panics as a test failure. It is not undefined behaviour.
- **Consequence 2.** The environment has exactly three variables and no `RUST_BACKTRACE`. A panicking test therefore does not symbolize the 467 MB debuginfo under the 1 GiB address-space limit. That is a favourable note.
- **Dev dependencies.** `insta` and `proptest` are linked in. The retained full read found no file, network, environment or subprocess I/O in the selected tests, so neither is reached (see advisory A1).

## 3. Applicability judgement (F7/P4)

**I judge the existing ordinary class applicable to this 50-operation selection.**

**Limits of what results would mean.** Passes would be ordinary host-assertion results under F12 semantics. They would not be native, proof, ledger or EARS evidence.

**No sandbox.** The class has no filesystem or network namespace. Effects safety therefore rests on the source closure, bounded by the caps. That is acceptable because the reviewed closure has no I/O.

## 6. Residual risks (outcome or attempt only, not eligibility)

- **R1. `--list` overflow.** Many modules contribute tests. At about 120–140 bytes per line, roughly 940–1090 or more tests exceed 131072 bytes. That is a controller failure, consumes the attempt, and cannot be retried with a cap raise.
- **R2. `--nocapture` interleaving.** With `--test-threads=1`, libtest prints `test X ... ` before the test runs and `ok` after it. Any stdout `println!` inside a selected test splits the result line. The helper's regex would then report a mismatch and fail-stop even if the test passed. stderr output does not interfere. I cannot exclude stdout prints in the 13 bodies from this context.
- **R3. Binding deadline.** Each child costs up to 10 s, plus recurring overhead. That includes rehashing two 467 MB ELFs and the static pins per child, which is roughly 1 GB of hashing per child. So the 500 s deadline can stop launches before op 49 even when every test passes.
- **R4. Interpreter arms.** Any instruction from D01 that an interpreter does not handle fails the test, not the controller.
- **R5. F10 risks.** Timeout, stack overflow and abort under the debug build, as retained.

**Advisory A1 (not mandatory).** The post-checks cover pinned files but not new files created in the source worktree, such as insta `.snap.new` or `proptest-regressions`. The retained read found neither reachable. A worktree inventory diff would close this cheaply.
