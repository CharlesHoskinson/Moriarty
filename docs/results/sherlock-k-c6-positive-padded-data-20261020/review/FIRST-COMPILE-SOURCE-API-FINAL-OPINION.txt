### Unpack and observation

The audit point on `dpUnpack` passes source inspection.

`dpUnpack(C,L)` does **not** return the original `DPTables` argument. It reconstructs all four tables from the newly supplied lane term `L` by:

- Reading node, field, env, and value counts from header lanes `3`, `4`, `5`, and `6`.
- Dropping to data base `7` for nodes.
- Dropping to `dpFieldsBase(C)`, `dpEnvBase(C)`, and `dpValuesBase(C)` for the other partitions.
- Decoding each row from the dropped lane suffixes.

`dpObserve` first packs the input, then `dpObservePacked`:

- Retains the entire packed `CTLanes` value, including header, active rows, and inactive zero padding.
- Derives `CTActive` from the packed header count lanes.
- Uses `ctActive` only as the ordered four-Int physical-count carrier.
- Rebuilds the decoded tables through `dpUnpack` from that same packed lane value.
- Returns exactly the four observation fields represented by geometry, counts, padded lanes, and decoded tables, without a profile, case, or source-pin wrapper.

This is a positive canonical inverse path only. `dpUnpack` is not approved as an arbitrary raw-image decoder, admission gate, canonicality checker, or security boundary.
