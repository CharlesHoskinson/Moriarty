## Source checks (all satisfied)

### Order and indices
- The EnvCell lanes are [nameId, valueRef.space, valueRef.index, parent.present, parent.index]. This matches `literal_host.rs` (`env`) and `state.rs` (`EnvCell`/`EnvRoot`).
- The root positions are activeEnvCells = 2, environment.present = 6, environment.index = 7. They match the schema root order.
- The table index is 2, which is EnvCells.

### Lookup
- The lookup starts at Root.environment.
- The first match wins, which matches `if !env.contains_key(&name)`.
- A chain that ends at an absent root gives `EAbsent`, which is distinct from `EUnvisited`.
- Comparing nameIds stands in for comparing name strings only under the stated distinct-Names premise.

### Bound
- The fold runs active + 1 iterations. That is enough under the decoder's invariants: a present parent's index is below its child's, and the root index is below active.
- The z lookup needs exactly 4 = active + 1 iterations: row 2, row 1, row 0, then absent. An off-by-one bound would therefore produce `EUnvisited` and fail. The x and y lookups also discriminate the shadowing direction: last-match semantics would give `List(0,0)`.

## New disclosures (non-blocking; publish alongside D1–D7)

- **D8. `not(pCompleteStartAllowed)` is overdetermined.**
  - It already fails at selector 1 ≠ 0.
  - It also fails on root[0..5] ≠ 0, fuel 256 ≠ 512, and nonzero arenas, regardless of root[6..7].
  - Body 1's phrase "failing complete-start for its nonempty environment" overstates this. The environment conjuncts are not isolated.
  - B23 gap 5's "environment present/index ≠ 0" item **remains open**.
- **D9. The projection assertions after each step add no discrimination of the transitions.**
  - They are implied by the full-image equalities.
  - Model continuity holds by construction, because both transitions copy tables[0..5] and the root slices.
  - The independent content is limited to the hand-specified bindings on this one spine and the lookup helper's behaviour on it.
- **D10. The lookup does not check `index < active` or `index < capacity`.**
  - An out-of-capacity index gives a Quint `nth` evaluation error, not `EUnvisited`.
  - A pointer into a zero padding row could falsely match nameId 0.
  - `EUnvisited` arises only for an in-range chain that is not exhausted within the bound.
  - All of these cases are outside the stated premise.
- **D11. Row 0's Constant-space binding is admissible only in decoder Step mode.** Canonical mode refuses it with "canonical bindings use Data space". This is consistent with the README's non-canonical statement, which should name this case explicitly.
- **D12. Two further limitations:**
  - `reference.layout` is never asserted.
  - The Names/NameBytes contents are not modelled. The decoder uses `prepared.names` metadata instead.
