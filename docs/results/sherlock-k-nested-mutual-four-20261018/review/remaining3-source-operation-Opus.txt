## 4. Required Root-side gates (conditions of approval)

- **G1 — Consumer import surface.** Before every consume child, verify that the `source/` directory inventory is exactly the five pinned files, with no `__pycache__` and no extra `.py` files.
  - The consumer runs `/usr/bin/python3 -B` without `-I`, so `sys.path[0]` is `source/`. Any extra module there, such as `json.py`, shadows the stdlib.
  - `-B` still loads an existing matching `.pyc`.
- **G2 — Produced-artifact pins re-checked before every child**, not only the next one. This follows the F03 `captured-artifact-changed` semantics. In particular:
  - Pin kast stdout before reduce-0 and re-verify it before print-0 and consume-0. The consumer reads it unpinned after reduce.
  - Pin `result.kore` before print and consume; pin print stdout before consume.
  - Pin checkpoint and next query before the next reduce.
  - Before reduce-0, Root itself should also assert the OBSERVE head and `seed_query(stdout,16)==stdout`.
- **G3 — Compiled-directory inventory.** Before every child, check that `nominal-kompiled/` contains exactly the 15 pinned entries, not just that the pinned hashes match. kast or K could add a file that a hash-only recheck would not catch.
- **G4 — Dispatch from the pinned checkpoint.**
  - Root derives `CONTINUE`, `STOP_HALT`, `STOP_OUTSIDE_MODEL` or `STOP_BOUND` from the persisted checkpoint and requires consume stdout `status` to agree.
  - On any terminal status, require `completed_case_output` to exist and pin it.
  - Require `next_query=null`, and require that no `input.kore` appeared in the next (unrun) window's directory.
- **M1/M2 as stated.**
  - Precreate the 873 directories at mode 0700 only.
  - Precreate no streams, outputs, queries, checkpoints or `actual/<stem>.complete-observed-wire.json`.
  - A later reduce cwd may contain only `input.kore` plus the empty `home/` and `tmp/`.
- **Recommended (non-blocking).** Pin the argv[0] realpaths once at batch start: java, `.kore-exec-wrapped`, kprint, and `/usr/bin/python3`. F03 `PINNED_FILES` covered some of these, but only `launch` is selected here. Nix-store immutability makes drift unlikely.

## 5. Empirical risks retained (no cap or window change)

- **K temp directory in kast cwd.** K may create a `.kast-*` temp directory in the kast cwd. It is cleaned on normal exit, but a kill leaves residue, and that residue must fail closed.
- **Growth in state size.** Each state carries its cumulative events, so state size grows linearly with ordinal and per-window cost grows with it. Firstcase scale: a 16-state window took 27.5 MB of raw kore, and the full wire was 20 MB at 134 states.
  - Per-window raw kore, kprint output, `parse_printed` work and consumer RAM grow roughly linearly with ordinal.
  - The persisted prefix wire per window and the cumulative disk usage grow roughly quadratically.
  - A long case approaching 512 risks the 30 s wall and RAM/disk pressure. There is no aggregate disk or RSS cap.
- **Python recursion depth.** `PrintedTermParser.term` recurses once per cons cell, so depth is about the event count plus roughly 20. The 512 bound stays under Python's default limit of 1000; the margin is adequate but finite.
- **Batch-wide stop.** `STOP_OUTSIDE_MODEL` or any failure in case 02 forfeits cases 03 and 04 by declared policy. All unrun phases stay UNRUN, with no retry.
- **No count prediction.** The firstcase's 133 steps predict nothing for these cases.
