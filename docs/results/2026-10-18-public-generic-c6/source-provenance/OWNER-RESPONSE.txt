# (1) Diagnosis

**Defect.** One check, `check_c1_rows_written`, enforces "every Literal slot is None". Every later stage completion check inherits it:

- `check_c2_complete` → `check_c3_complete` → `check_c4_complete` → `check_c5_complete` → `check_c1_rows_written`.
- Every C6 operation calls `check_c5_complete`: `begin_literal`, `visit_literal_value`, `literal_constructor_use`, `append_core_literal`, `append_constructor_constant`, `finish_literal`, `begin_nullary_construct` and `finish_nullary_construct`.
- `check_c6_complete` also calls `check_c5_complete`, and every P method plus `check_p_complete` calls `check_c6_complete`.

`finish_literal` legitimately writes `Some(ExpressionRowC::Literal{constant})`. After that, every C6, P and finalization check rejects the completed prefix with `literal slot must remain None prior to C6`. This is a stage-lifetime contradiction in the checks, not a numeric mismatch.

**What the code implies (an inference from the code, not a captured trace):**

- **Two or more Literals.** The first C6 call after the first `finish_literal` fails. In the C6 loop that is the next `begin_literal`.
- **Exactly one Literal and at least one nullary Construct.** `begin_nullary_construct` fails.
- **Exactly one Literal and no nullary Construct.** The first `begin_match` fails, or `check_p_complete` if there is no Match.
- **No Literals.** These programs never reach the failure, because nullary `constant` writes do not affect the literal check. That explains why nullary-only routes can pass.

`public_recursive_ordered_schedule` has five Literal occurrences, so it hits the first case.

**Correction.**

- The C2–C5 structural constraints are factored into stage-neutral helpers.
- The literal-slot rule becomes an explicit `LiteralSlotPhase` passed to the C1 row check.
- The existing `check_c1_rows_written`, `check_c2_complete`, `check_c3_complete` and `check_c4_complete` keep their exact strict pre-C6 behaviour, error order and locators. All C1–C5 callers are unchanged.
- C6 operations use a new `check_c6_in_progress`.
- C6 completion and P use a strengthened `check_c6_complete` built on post-C6 structure.
- `check_c5_complete` is removed. It has no pre-C6 caller, and any unseen caller now fails to compile rather than silently changing stage.

fn uint_value(n: u128) -> ExtValue {
    ExtValue::Core { value: CoreValue::UInt { n: KIntC::InRange(n) } }
}

fn uint_literal(n: u128) -> ExtExpr {
    ExtExpr::Literal { value: uint_value(n) }
}

fn nullary(ty: &str, ctor: &str) -> ExtExpr {
    ExtExpr::Construct { ty: named(ty), ctor: ctor.into(), fields: vec![] }

fn compile_admitted(program: ExtProgram, case: &str) -> ExtCompileArtifact {
    match compile_ext_host(program, safe_config::safe_public_config(), None) {
        Ok(artifact) => artifact,
        Err(ExtCompileFailure::Preparation(_)) => {
            panic!("{}: compile_ext_host preparation/admission refused valid source", case)
        }
        Err(ExtCompileFailure::Genesis(_)) => {
            panic!("{}: preparation admitted but owner genesis refused", case)
        }
    }
}

fn assert_bound_unevaluated(artifact: &ExtCompileArtifact, case: &str) {
    assert!(artifact.observe().is_ok(), "{}: admitted/genesis pair not bound", case);
    match artifact.report() {
        Ok(report) => assert!(!report.evaluation_performed, "{}: report claims evaluation", case),
        Err(_) => panic!("{}: report projection refused bound pair", case),
    }
}
