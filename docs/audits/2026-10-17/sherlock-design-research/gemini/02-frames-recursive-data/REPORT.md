## 3. Ranked Architecture Ideas (Evidence, Tradeoffs, Proposed Text & Tests)

### Idea 1 (Rank 1 — Mandatory v1): Semantic-Boundary Cut Restriction & Two-Tier B Projection (`project_b_canonical`)
- **Primary Evidence**: In CIP-0085 ([capture-01](file:///home/charl/Moriarty/.moriarty-dev/runtime/sherlock-review-20261017/gemini-research/02-frames-recursive-data/capture-01-cip0085-plutus-sop.md#L27-L55)), Plutus Core separates internal CEK machine configurations (closures, frames, linked environments $\rho$) from boundary unlifting/serialization, which is defined only on discharged terminal/boundary states.
- **Applicability & Tradeoffs**: Restricting B proof-chunk cuts (`Yield`/`Resume`) and A/B cross-profile state projection to **semantic step boundaries** (`helper == None && result == None && tasks.is_empty()` and `control != ScheduleNext`) eliminates the need to serialize transient helper cursors into `StateBlock`, while preserving full microstep proofs within each chunk. *Tradeoff*: Minimum chunk granularity is one legacy event plus its helper sequence ($O(\text{arity} + \text{env\_depth})$ rows), which is tiny ($\le 64$ rows) vs $k=17$ circuit capacity.
- **Proposed Spec Text** (add to Candidate 02 *Representations and adapters* & *Bounded runs*):
  > **Boundary Cut & Canonical Projection Rule (`B-PROJ-1`).** Technical proof cuts (`Yield`/`Resume`) and cross-profile state comparisons (`project_b_canonical`) are admissible only at quiet semantic boundaries where `helper == None`, `result == None`, `tasks.is_empty()`, and `control` is not `ScheduleNext`. `project_b_canonical(img)` walks each reachable `EnvRootC`, keeps only the first binding per `name_id` (shadowing older cells), sorts bindings by ascending UTF-8 `Name`, unfolds reachable `RefC::Const` and shared `RefC::Data` nodes in postorder into fresh `Data`-space rows, and reverses `img.frames` to top-first order.
- **Falsifiable Tests**:
  1. `test_b_canonical_projection_shadowed_env_and_const_dag`: Execute a `Let` shadowing an outer binding and referencing a shared `RefC::Const` list in B; verify `project_b_canonical(img) == project_a(a_state)` and `decode_observed_a(project_b_canonical(img), DecodeMode::Canonical).is_ok()`.
  2. `test_b_cut_refused_mid_helper`: Attempt chunk cut while `img.helper.is_some()` or `matches!(img.control, ControlC::ScheduleNext { .. })`; assert deterministic boundary refusal.

### Idea 2 (Rank 2 — Mandatory v1): Complete the `ConstructorFields` CEK Frame Bridge & Static Pattern Linearity (`AD-ADT-LIN`)
- **Primary Evidence**: CIP-0085 ([capture-01](file:///home/charl/Moriarty/.moriarty-dev/runtime/sherlock-review-20261017/gemini-research/02-frames-recursive-data/capture-01-cip0085-plutus-sop.md#L84-L97)) formalizes $\mathrm{CONSTR\_SUB\_i}$ and $\mathrm{CASE\_EVAL}$: evaluating `(constr e t_0 ... t_n)` steps each argument $t_i \to t'_i$ left-to-right via a constructor frame before producing the tagged value, while `case` is non-strict in unselected branches: `"Note that CASE_SUB does not reduce branches and CASE_EVAL preserves only the selected case branch."`
- **Applicability & Tradeoffs**: Bridges the gap between expression evaluation in [`shared.rs`](file:///home/charl/Moriarty/.worktrees/sherlock-parallel-implementation-20261016/crates/mori-core/src/sherlock/helper_machine/shared.rs#L211) and `ControlExtC::Materialize` in [`shared_adt.proposed.rs`](file:///home/charl/Moriarty/.worktrees/sherlock-parallel-implementation-20261016/models/sherlock/generic-adt-helper-source-20261016/shared_adt.proposed.rs#L70), and prevents silent duplicate-binder shadowing in [`PlanBind`](file:///home/charl/Moriarty/.worktrees/sherlock-parallel-implementation-20261016/models/sherlock/generic-adt-helper-source-20261016/adt_payloads.proposed.rs#L321). *Tradeoff*: Adds the 10th `FrameRow` variant (`ConstructorFields`, already reserved by `ConstructorFieldsExtensionReserved` in [`shared.rs`](file:///home/charl/Moriarty/.worktrees/sherlock-parallel-implementation-20261016/crates/mori-core/src/sherlock/helper_machine/shared.rs#L209)) and a preparation-time binder-set check.
- **Proposed Spec Text** (add to Candidate 02 *Reusable handwritten realization*):
  > **GenericNominal Constructor & Pattern Contract (`B-ADT-1`).** (1) Non-zero-arity `Constructor(type_id, ctor_id, exprs)` pushes `FrameRow::ConstructorFields { type_id, ctor_id, completed: ValSliceC::empty(), remaining: exprs.tail(), saved_env, origin }`, evaluates arguments left-to-right via `BHelperAppend*`, and transitions to `ControlExtC::Materialize` only when `remaining.is_empty()` (0-arity enters `Materialize` directly). (2) `owner_prepare` enforces `AD-ADT-LIN`: every compiled `PlanNodeRowC` root-to-leaf path must have pairwise-distinct `binder` IDs (rejecting nonlinear patterns before execution, or else `PlanBind` must invoke `BHelperBindDuplicate` to raise `error8`).
- **Falsifiable Tests**:
  1. `test_adt_ctor_left_to_right_error_order`: In `Ctor(err_a, err_b)`, verify `ConstructorFields` evaluates `err_a` first and halts with `err_a` before `Materialize`.
  2. `test_adt_nonlinear_pattern_rejected`: Feed a nested constructor pattern with duplicate variable `x` (`Pair(x, Some(x))`); assert preparation refusal under `AD-ADT-LIN` (or runtime `error8`).

### Idea 3 (Rank 3 — Mandatory v1): Explicit Spine/Stack Adapter (`adapt_b_to_a_snapshot`) with Deterministic `origin`
- **Primary Evidence**: Leroy's ZINC machine ([Search 2 / RR-117](file:///home/charl/Moriarty/.worktrees/sherlock-parallel-implementation-20261016/docs/research/sherlock/papers/01/proposal.md)) shows that when an abstract machine splits control/argument scheduling into explicit push microsteps (`ScheduleNext`), equivalence with a structural evaluator requires an explicit de-scheduling map over the control/return stack.
- **Applicability & Tradeoffs**: Formally links B's `ControlC::ScheduleNext` + bottom-to-top `FrameRowC` (with `origin`) to A's `Control::Push` + top-first `Frame` (without `origin`). *Tradeoff*: Requires deterministic `occurrence_id` assignment on every AST node during admission (`ProgramImage`) so A->B translation can populate `FrameRowC.origin` to satisfy `SI-15`/`SI-20`.
- **Proposed Spec Text** (add to Candidate 02 *Representations and adapters*):
  > **Frame & Control Adapter (`AB-STACK-1`).** At any semantic boundary, `adapt_b_to_a_snapshot` maps `img.frames[0..n]` to `Snapshot.frames` in reverse index order (`n-1` down to `0`), stripping `FrameRowC.origin`. Conversely, `adapt_a_to_b_image` unrolls any `Control::Push(f, next, env)` into `ControlC::ScheduleNext` (for depth 1) and populates `FrameRowC.origin` from the unique parent `ExpressionRow.occurrence_id` recorded in `ProgramImage`.
- **Falsifiable Tests**:
  1. `test_ab_frame_stack_roundtrip_with_origin`: Across a 3-deep recursive call, assert `adapt_b_to_a_snapshot(img).frames[0]` equals `img.frames.last()` and `owner_check_step_inv` (`SI-15`, `SI-20`) holds at every step.

### Idea 4 (Rank 4 — Optional / Post-v1 P2): Pre-Allocated Frame Scratch Window (Simplicity Bit-Machine Style)
- **Primary Evidence**: O'Connor's Simplicity ([capture-02](file:///home/charl/Moriarty/.moriarty-dev/runtime/sherlock-review-20261017/gemini-research/02-frames-recursive-data/capture-02-simplicity-arxiv.md#L31)) states: `"Simplicity also includes operational semantics that are defined with an abstract machine that we call the Bit Machine. The Bit Machine is used as a tool for measuring the computational space and time resources needed to evaluate Simplicity programs."` Its read/write frame stacks pre-reserve exact type-bounded cell windows per active frame instead of copying prefixes.
- **Applicability & Tradeoffs**: In B (`environment.rs:117-160`), `BHelperAppendStep` copies `completed` (`0..len`) into a fresh slice on every argument, consuming $\frac{k(k+1)}{2}$ `value_slots` rows per $k$-ary call/constructor. Pre-reserving a `k`-slot frame window reduces `value_slots` consumption to $k$ writes (1 row per argument). *Tradeoff*: Changes `B-T02`/`B-T08` row-effect equations (`owner_runtime.rs`), so it must be deferred past v1 freeze.
- **Proposed Spec Text & Test**: Record as a post-v1 (`P2`) row-reduction amendment replacing `BHelperAppendCopy` with indexed write `value_slots[base + idx] = val`; test that a 6-arg call uses 6 `value_slots` rows instead of 21.

## 5. Clear Limited Design Verdict & Rejections/Deferrals
- **Limited Design Verdict**: **Conditionally Approve Option 3 (Converge A/B via explicit profile adapters and one developer pipeline).** Candidate 02 correctly rejects replacing the interpreter or relying on isolated leaf rules, and properly separates A semantic clocks from B helper microsteps. However, Candidate 02 is **incomplete for v1 sign-off** until it incorporates `B-PROJ-1` (quiet-boundary cuts and environment/constant canonicalization), `B-ADT-1` (`ConstructorFields` frame + nonlinear pattern rejection), and `AB-STACK-1` (`Push`/`ScheduleNext` and `origin` correspondence). All existing v1 requirements (`UIREQ-001..035`, full 39 events, `B-T01..14`, `U0..U7`, `M/MC/SP/G`, and security ownership boundaries) remain strictly preserved.
- **What Must Be Rejected or Deferred**:
  1. **Reject Scott-Encoding or Universal Untyped `Data` Encoding for ADTs**: CIP-0085 ([capture-01](file:///home/charl/Moriarty/.moriarty-dev/runtime/sherlock-review-20261017/gemini-research/02-frames-recursive-data/capture-01-cip0085-plutus-sop.md#L37-L42)) proves Scott terms are non-canonical/opaque to unlifting and `Data` encoding is $>3\times$ slower; both violate Sherlock's canonical observation (`F3`/`F4`) and bounded row budgets.
  2. **Reject Mid-Helper Proof Cuts in v1**: Cutting while `helper.is_some()` leaks internal B cursors (`dup_cursor`, `append_cursor`, `PlanStateC`) into boundary statements and breaks A/B equivalence.
  3. **Defer In-Place Arena Compaction / Mutable GC**: Mutating or compacting `img.env`, `img.data`, or `img.value_slots` in-chunk violates `AllocCounters` monotonicity (`SI-01..04`) and fixed-index witness constraints; canonical compaction belongs exclusively in the boundary projection (`project_b_canonical`).
