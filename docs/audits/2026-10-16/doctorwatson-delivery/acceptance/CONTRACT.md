# First DoctorWatson delivery-cycle acceptance

Specified before inspecting the implementation under construction, 2026-10-16.
Authority: the user's request to finish DoctorWatson and test it by building
Sherlock; checkout `AGENTS.md`, `docs/DOCTORWATSON.md`, `DOCTORWATSON-CI.md`,
`SHERLOCK-CORRECTNESS-LOOP.md`, SF-01–15, the frozen QA contract and Sherlock
UIREQ-012/013/021–026. This is an acceptance contract, not an execution receipt.
Read-only startup status reports historical SP01 blockers; they grant no execution.

**Pass predicate:** one real, reviewed, locally executed factory cycle delivers
new callable Sherlock host behavior through the ordinary consumer and a merged
PR, with independently frozen complete observations matching actual execution.
All following predicates must be observed for that bounded claim:

1. **Independent fixture → new code.** Identify the existing requirement, actual
   consumer, disjoint owners and consumed dependencies. Preserve the independent
   `sherlock-k-a/1` N01–N08 oracle documents and their QA-contract digests before
   execution: 208 complete states, 200 charged edges, eight publications and 216
   fuel prefixes. Expectations cannot come from the implementation or exporter.
   New public bounded `Machine::run_steps` behavior must be called and checked
   against independently selected literal boundaries, including zero steps and
   a technical cut followed by continuation. Its limit bounds actual progress;
   it must retain the declared complete state, work and outcome observations.
2. **Pure host build → real run.** Explicitly request the inspected local host
   build path. Record exact compiler, source/dependency inputs, command, exit and
   resulting artifact identity. Build the candidate's actual Rust Machine and
   ordinary exporter/consumer; then execute that artifact. Fixture readback,
   copied JSON, an old executable or an unrelated cached library cannot supply
   this result. Pure host compilation and execution are separate successful
   observations. Ordinary CLI integration tests must exercise the actual entrypoint,
   complete comparison and fail-stop behavior, rather than merely importing helpers.
3. **Run → complete comparison.** The approved actual host common domain starts
   at `Machine::new` **after startup**. Compare actual complete host
   `Snapshot`/`StepRecord` exports, including free publication, against the explicit
   projection of frozen expectations across all 216 prefixes. Preserve ordered
   membership and every admitted host field: code identity, control, environments,
   frames, saved values, work/fuel, raw outcomes and publication boundaries,
   including missing/present distinctions. No frozen value, digest or case count
   changes. Declare the **constructor/startup gap**: this host does not execute K
   `uiRun`/rule74 or the pre-startup `initial_configuration`. Original corpus
   provenance and administrative startup fields remain checked as source/fixture
   data; they cannot be reported as producer-executed observations. Retain actual
   output and earliest differing path, expected/actual values and raw context.
   A final return value or a test count alone cannot pass this predicate.
4. **Comparison → fresh review → PR merge.** Retain the candidate commit/tree,
   integration base, attempt identity, oracle/profile/bounds/tool identities,
   commands, terminal statuses and output digests. A fresh non-author Muse audit
   assesses the full exact candidate and actual results; Opus owns applicable
   execution-wrapper/security judgments. Resolve blocking findings. Any consumed
   input or integration change refreshes affected checks and reviews transitively.
   Record the normal GitHub PR and merged result. No Foreman, replacement
   framework or automatic hosted CI is part of this cycle.

**Observable fail-stop dispositions.** A missing tool or required input is
`blocked/not run`, never an install or inferred pass. Malformed/incomplete paired
observations or unequal fields fail nonzero with the first difference. Build,
execution, comparison, timeout or review failure stops dependent stages and
retains its receipt; cancellation, timeout and pass remain distinct. No stale
candidate or earlier-attempt result admits integration. After two same-class
failures, retain a reduced reproducer and changed approach before another broad
attempt; after two process-only cycles or thirty administration minutes, perform
eligible work or record a concrete blocker and owner (SF-14). A blocked/cancelled
task releases active write ownership without erasing history.

**Required separate dispositions.** Record current K execution, explicit finite
Sherlock Quint projection, Lean reference, Clean witness and constraint components,
handwritten circuit, native relation and stagenet rows individually as observed,
stale, unrun, unavailable or blocked. Historical passes retain their exact scope.
The DoctorWatson workflow Quint check is design evidence only; its SF-14 repair
needs fresh affected checks/review and supplies no Sherlock semantic observation.
Missing required layers leave cross-layer acceptance open even if this host cycle
passes. K runtime/full refinement, Candidate B bounds/helpers/representation,
Lean-to-Clean correspondence, bounded Clean and handwritten step adapters,
constraint/witness export, general compiler correspondence and native/qualified
Midnight stagenet proof/deploy/call/readback remain gaps until separately evidenced.
Native authority remains zero; Opus owns its boundary. This contract closes no
U0–U7, M1–M17, MC/SP/G parent exit and makes no full-V1-completion claim.
