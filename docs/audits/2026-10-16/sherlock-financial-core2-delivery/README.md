## What was compared

The consumer calls `mori_core::stage::load`, `start` and `resume`. It compares
the complete Program, StagePlan and canonical hashes, all eight full stage
results, and borrowed financial views of every result. Six resumes retain
their actual preceding continuation, event and CLI fields separately from
the expected values. States, ordered effects, source statements and ExprIds,
step values, captures, frames, residual liabilities and logical work counters
remain complete. Expected views do not call the production projection.

The 18 retained JSON records include two loads, eight invocations and eight
stage-view debug records. They cover five successful segments and three
ordinary false-await observations. A separate read-only Python comparison
then matched the actual complete JSON values directly against the original
independent `expected.json`, without using the Rust literal translator or
importing an evaluator. Its 79 checks cover both complete program/plan pairs,
all eight complete results and all six complete resume input sets. The debug
strings have no separate wire ABI and are not independently interpreted by
that Python comparison; full typed projection assertions are separate evidence.

## Limits and next work

Both programs use fictional `oracle-local` asset identities. Every resume has
null CLI action/cap overrides. There is no independent rejection expectation,
external CLI file-decoding comparison, authenticated event origin, continuation
consumption or replay-protection result. Existing local-reference-stage,
authentication-none and consumption-untracked labels control the observations.

The original freeze's `resume_input_event_pairs: 5` metadata and older review
prose conflict with the actual six resume records. Those original bytes remain
unchanged. The complete typed and JSON expectations always contained all six;
the guard derives the observed count from their fixed sequences.

This child result does not close Phase 7's full compiler predicate, financial
family coverage, K/Quint/Lean/Clean/circuit correspondence, any U/M/MC/SP/G exit,
or native/proof/ledger/Preview/Fenrir/stagenet acceptance. Next work is the
reviewed Sherlock financial control/compiler mapping and its separately
qualified comparisons, while retaining rejection, CLI-override, grammar and
target gaps. No native authority was used or created.
