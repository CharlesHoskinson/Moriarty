OPERATIVE RULE, UNIFORM FOR /3: For moriarty-core/3, bare stage admission and Sequence projection use the same domain. stage::start for a /3 StagedProgram applies the profile-appropriate canonical_boundary (REG3) for awaiting and non-awaiting actions alike, before evaluation, with attempted 0 on refusal; Sequence project_head applies the same profile-appropriate canonical_boundary at P7 before stage::start in both cases; stage::resume R7 applies the same REG3 rule to the retained continuation boundary. Therefore bare-/3 and Sequence /3 domains coincide, neither depends on await count, and a boundary admitted at /3 start remains resumable (H25). Incoming discharge-only duties with no Statement::Liability anywhere are supported in bare /3 and in Sequence only when declared by a /3 ExternalDutyDecl in REG3; without such declaration they are refused in both domains under the same registry rule. This does not narrow Sequence relative to bare stage::start for /3, because the same narrowing relative to an undeclared-duty reading applies at bare stage.

FOR /2: A Sequence-projected boundary is admissible only if it satisfies BOTH scenario_snapshot AND the profile-appropriate canonical boundary, for awaiting and non-awaiting actions alike; no /2 predicate, message, ordering or hash input is changed. Bare /2 stage admission is unchanged: stage::start applies canonical_boundary only for awaiting /2 actions, preserving bare /2 non-awaiting discharge-only admission. No /1 predicate is changed.

D1A GRAMMAR: language "moriarty/3" and semantics moriarty-core/3 add exactly one declaration, only inside the agreement block, only before the first action, in any number interleaved with state/asset declarations: duty "<name>" = { asset: <asset-word>, debtor: "<debtor>", creditor: "<creditor>" }; . duty is a parser keyword only on the /3 path; on /1 and /2 paths the existing parser still reaches its existing unsupported-declaration refusal. name, debtor and creditor are decoded JSON strings from parser.string(), each 1..=1024 UTF-8 bytes after decoding; asset is parser.word() and must name a declared AssetDecl. Repetition is allowed syntactically and refused semantically below. states+assets+actions+duties count toward MAX_DECLARATIONS=256 by the parser check; statements and expressions are counted exactly as in parse_profile; no new expression nodes are allocated by a duty declaration. Parser errors keep Parser::error codes and the offending token offset: lex from mori_lexer, profile for a wrong language string, syntax for missing duty punctuation or a non-string name/debtor/creditor; asset validation is deferred to validate_v3.

IR: ExternalDutyDecl{name:String,asset:String,debtor:String,creditor:String} with deny_unknown_fields, and Program.duties with #[serde(default, skip_serializing_if="Vec::is_empty")]. A /3 Program is constructed only by parser::parse_v3 from source text, never by JSON. Nonempty /3 duties serialize in declaration order and bind into program_hash and, through plan.program_hash, into plan_hash; a zero-duty /3 program is distinguished by language and semantics.

PARSER AND PROFILE: parse_v3 via Profile::Core3 expects LANGUAGE_3/SEMANTICS_3, handles duty before first action, does not call legacy validate. language() is unchanged and returns only /1 or /2; language_v3 returns /1,/2 or /3 and never converts. require_core3 in stage/profile.rs requires exact LANGUAGE_3/SEMANTICS_3; require_core1 and require_core2 refuse /3; require_core2 also refuses nonempty duties. Manually constructed Programs: runtime::validate and require_core1 refuse nonempty duties on /1, validate_v2 refuses duties on /2, and registry consumers require the exact (LANGUAGE_3,SEMANTICS_3) pair before REG3; this is source custody only, not consent, authentication, authority or native validity.

VALIDATION AND REGISTRY: validate_v3 first applies the /3 profile, duty first pass, then every validate_v2 check with REG3 liability-read validation. Duty first pass refuses in declaration order empty/over-1024 name/debtor/creditor, unknown asset, duplicate duty name even if identical, or duty identity conflicting with Statement::Liability, all sequence_duty_declaration. REG3 is Statement::Liability identities over all actions union Program.duties resolved through declared AssetId including scale; statement-only conflicts keep liability, duty-caused conflicts use sequence_duty_declaration. This registry agrees across validate_v3, decode::registry_for/canonical_boundary, and runtime::liability_identities/scenario_snapshot.
