## Mandatory literal source fix

**M1. `sourceCore2ReadAdd.qnt`, in `resumeGuard`. Rename the match binder `enabled`.**

```
-          | BoolValue(enabled) => if (enabled) {...charged,
+          | BoolValue(guardHolds) => if (guardHolds) {...charged,
```

- **Why:** `enabled` is a Quint built-in temporal operator (`enabled(action)`). Match arms desugar to lambdas, so this binder is a lambda parameter that shadows a built-in. Depending on how the installed resolver handles it, this is either a QNT101-style "built-in name redefined" error or a resolution of `if (enabled)` to the operator.
- **Uncertainty:** without execution I cannot confirm which way the pinned Quint version behaves.
- **Why it is still mandatory:** the preflight forbids a retry. A frontend failure would burn the operation pair for a one-token hazard. The rename has no semantic effect.
- **Root check:** the only byte change is these two tokens on one line, so the file grows from 13335 to 13341 bytes (+6). After that:
  - re-pin the file;
  - regenerate `SOURCE-ONLY-FREEZE.json`;
  - update the `sourceFreeze` pin in `EXACT-NEW-TWO-OPERATIONS.json`.

  I accept the source with exactly this change and no other byte change, so no further design review is needed.

I checked every other binder, local, top-level and constructor name in Bodies 1, 5 and 6. None collides with a Quint built-in or with any name imported from `financialBoundary`.

## Source/API correspondence audit

### RuntimeEvidence isolation: confirmed
- `sourceRequest` projects exactly the five fields identity, plan, guardCosts, input and startBoundary. `SourceRequest` has no runtime field.
- `sourceDerivedCore2SequenceSeed` reads `H::suppliedInvocations` only through `sourceRequest`.
- `deriveSourceQueue` rebuilds each `Invocation` from the request, plus `deriveRuntime` output as its runtime.
- No path in Body 5 or Body 6 reads `.runtime`. The historical seed's evidence is dead data.
- The port reads only `S::suppliedInvocations` and `S::sourceDerivationSupported`.

### No shortcuts: confirmed
- **Static costs:** the evaluator never reads `segmentCosts`, `committedBefore`, `planTotal` or `guardCosts`. Those appear only in the unchanged `normalDomain`, as falsifiable cross-checks of the dynamic `attempted` against the static plan.
- **Fixture literals:** Body 5 and Body 6 contain no fixture names or IDs.
- **Outside-fragment markers:** `OutsideSourceFragment` and `OutsideSourceQueue` are never mapped to `Failed` or `Rejected`. An unsupported request yields an empty queue, never a truncated prefix.

### Expression worklist
- **Left-first evaluation:** the worklist is a stack with `NeedExpression(L)`, then `NeedExpression(R)`, then `FinishSourceAdd` prepended. This reproduces `eval_cached`'s recursive left-then-right order.
- **Charging:**
  - a cache check happens before any charge, and a hit costs zero;
  - a first visit charges +1 before its children, matching `charge_logical` before the match arm;
  - `FinishSourceAdd` adds no charge.
- **No cycles or in-progress re-entry:** child IDs must be strictly less than `nodeId`. A second request for a node is always processed after that node's Finish has run.
- **Fresh cache:** `deriveExpression` creates `emptyMemo` on every call, so the cache is fresh per statement.
- **Arithmetic:** Add is checked against `CORE_UINT_MAX = 2^128 − 1`, which is correct. Read and Literal values must also be in range.
- **Bound 1+3·N is sufficient:**
  - total ticks equal 1 root Need, plus 2 Needs per distinct expanded Add, plus 1 Finish per Add;
  - that is 1 + 3A, with A ≤ N;
  - the extra ticks are fixed points.
  - The bound is a termination observation, not a fee.
- **Unused field:** `visited` is computed but never read. This is harmless (advisory).

### Statements and segments
- **Environment:**
  - Start uses `startBoundary.state`, then `scenario.inputs`; the Set fold is safe because the `put` operations on distinct keys commute.
  - Resume uses `continuation.boundary.state`, then captures, then event values, in list order.
  - Both match `run_segment` and G3.
- **Let/Next:**
  - each charges 1 + |R(root)|;
  - Let updates the env only;
  - Next updates both state and env and emits one `StateEffect` (before, after);
  - `Step.snapshot` is post-statement, `Step.value` is `SomeScalar(value)`, and `index` is the original ordinal;
  - `Step.statement` is the SourceProgram statement;
  - balances and liabilities are untouched.
- **Await entry:**
  - charges +1;
  - finds the site by ordinal;
  - reads the captures by name in layout order;
  - stops, with no Step.
- **Resume guard:**
  - charges 1 + |R(guard)|;
  - on true, appends a guard Step with the pre snapshot and empty effects, then continues;
  - on false, sets `NotAdvanced` with the counted `attempted` and emits no Step or segment.
  - This matches `execute_statement` + `run_segment` and the false-guard formula in G5.
- **Termination without an Await:** exit 0 with empty captures, giving Complete. An empty Start segment is permitted.
- **Initial gating:** `actionName`, `semantics` and `statementCount` are cross-checked. The resume ordinal comes from `sites.nth(site−1)`, as in Rust. A resume landing on a non-Await is unsupported.
- **Out-of-range access:** every `nth`/`get` is guarded, so there is no TS runtime crash path.

## Advisory items (do not apply without a new review)

- **A1.** `sourceSite` returns the last ordinal match, whereas Rust's `find` returns the first. They are equivalent under the premise that admitted plan ordinals are unique.
- **A2.** The port comment "no … source evaluator" is now only true of the port module itself. Leave it, to keep the reviewed diff minimal.
- **A3.** A UInt-valued guard is treated as outside the fragment, whereas Rust would publish NotAdvanced. This is a conservative choice outside admitted typing.
