## Rust observer audit (Body 1)

These points are correct against Body 10/11 and Body 4:

- **Inputs are read and checked before any call.** Each file is read exactly once. The same text is parsed and recorded in the input record. All events are decoded before `stage::load`, `start` or `resume` is called.
- **Start and Resume use the right fields.** Start uses `startCap`. Each Resume receives the same `resumeCliAction`/`resumeCliCap`. The stored continuation cap is never replaced.
- **Linkage is correct.** Each continuation is a clone of the immediately preceding `raw_result()` `Ok(Waiting)`. Any other result breaks the loop with no synthesis and no retry. Unused events are still recorded. When events run out, observation stops at a Waiting result; this is an observer cut, not completion.
- **Publications are complete.** They come from `ProducedInvocation::publication()`, so the same-call relation holds and no reduced projection is used.
- **Bookkeeping is right.** `consumedEventCount` equals the number of Resume calls executed, so the nth Resume corresponds to `eventInputs[n-1]`.
- **The writer matches the contract.** It uses `serde_json::to_writer` plus one LF. The LineWriter flushes on the final LF and write errors propagate.
- **Borrows and types look sound.** The continuation borrow ends before `current` is reassigned. `map(fs::read_to_string)` over `&String` type-checks. `&String` coerces to `&str` for `decode::event`. `Box<dyn Error>` does not collide with `mori_core::Error`.

Items left to the compile step. These are not source defects:

- **Module paths are unverified.** `mori_core::sherlock_financial_projection` is not the file path (`src/sherlock/financial_projection.rs`), and `lib.rs` was not supplied. The compile also has to resolve `json::parse`, `intent::hash_bytes` and `stage::decode::event` with compatible types. A compile failure is a recorded failure; any fix needs a fresh review.
- **The `sha256` field is provenance only.** Its representation depends on what `hash_bytes` returns, which I have not seen. It is outside the equality predicate. Root's own external pins govern, and any disagreement between the two is a capture-integrity failure.

**Optional hardening (not required).** `Selection` is the only decoder the observer owns, and it is not strict: unknown keys are silently ignored. The pinned selection's keys match the camelCase names exactly, so this is harmless for the selected input. If you apply the fix, re-pin Body 1; this review then covers exactly this one inserted line:

## Quint port audit (Body 2 against Body 3)

Interface correctness:

- **Single state variable.** `machine` is the only variable. There is no hidden driver or cursor.
- **Invariants are well formed.**
  - The prefix and position invariants check bounds before they call `nth`.
  - `queuePositionInv` matches Body 5 for both the Ready and Published phases.
- **Each step has exactly one enabled action.** The guards of `publishStep`, `advanceInput` and `finalStutter` are disjoint. `normalDomain` excludes Start with NotAdvanced, so `publishStep` can never stutter silently through the `NoResult` path.
- **Linkage is enforced on advance.** `advanceInput` requires the previous result to be Waiting, the next input to be a `ResumeInput` with exactly that continuation, and the same source context. This closes the `beginInvocation` gap described in Body 4.
- **Run bound.** A run of 2N−1 steps gives 2N full Machine states and ends at the witness, with no terminal stutter.
- **Existing model behaviour fits this cohort.** `financialBoundary` handles Start/Ran, Resume/NotAdvanced (looking up guard costs by site) and Resume/Ran (exit site = index+1, `committedAfter` = prefix through entry) consistently with the contract.

Required before any future Quint operation review:

1. **Explicit run flags.** The command must name `--init=init --step=sequenceStep --invariant=sequenceInv --witnesses=allInputsPublishedWitness`.
   - The wildcard import also brings `financialBoundary::step` (publish or stutter only) into scope. If the default `step` were used, the run would never advance past the first record.
   - `--max-steps` must be 2N−1. N = 1 + the number of event files, from the input order and the declared formula.
2. **Frontend acceptance is unverified.** I cannot confirm that `import independentCore2SequenceSeed as S from "./independentCore2SequenceSeed"` is accepted, or that importing `financialBoundary` again inside the seed raises no name conflict.

**Recommended literal port fix.** Without it, a queue that is not linked shows up only as a disabled step or a short trace. With it, the failure is a named invariant violation. The fix only adds an invariant conjunct and changes no reachable state, so the conditionally prefrozen full-Machine trace stays valid.
```quint
  pure val queueLinked = suppliedQueue.indices().forall(i => i == 0 or
    match publish(suppliedQueue.nth(i - 1)) {
      | Result(previousResult) => resumeFollows(previousResult, suppliedQueue.nth(i))
      | NoResult => false
    })
```
Then add `queueLinked` to the `and { ... }` in `queueDomain`, after the existing `foldl` conjunct.

**Not enforced by the port.** It does not require every Resume to carry identical CLI fields. That property belongs to the observer; the seed owner must supply `NoText`/`NoUInt` for each.
