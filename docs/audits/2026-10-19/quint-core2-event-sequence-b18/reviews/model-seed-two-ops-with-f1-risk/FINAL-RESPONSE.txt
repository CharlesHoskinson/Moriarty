### Open frontend risks (none of these is a source fix)

- **F1 (main risk).** `init` and `advanceInput` use `if (c) false else <action updating machine>`. The port preimage has never been through the frontend. If the installed effect checker makes both `if` branches share one update set, typecheck will reject this. I can't settle that without tools.
  - If Op A reports an effect or mode error at those definitions, this is a pre-reviewed fallback for a new cut. It is equivalent in meaning and puts the guards before `nth`:
    ```quint
    action init: bool = all { suppliedQueue.length() > 0, initInvocation(suppliedQueue.head()) }
    action advanceInput: bool = all {
      machine.phase == Published, machine.records.length() > 0,
      machine.records.length() < suppliedQueue.length(),
      resumeFollows(machine.records.nth(machine.records.length() - 1).result,
        suppliedQueue.nth(machine.records.length())),
      sameSourceContext(machine.current, suppliedQueue.nth(machine.records.length())),
      beginInvocation(suppliedQueue.nth(machine.records.length())),
    }
    ```
  - The fallback relies on `all` evaluating left to right and stopping at the first false. **Do not apply it pre-emptively.** If it is ever applied, it needs a fresh freeze and review.
- **F2.** The qualified file import `import independentCore2SequenceSeed as S from …`, and `financialBoundary` being imported both directly and through the seed, are still unverified. I expect them to be accepted.
- **F3.** At `i == 0`, `queueLinked` relies on lazy `or` so that `nth(-1)` is never evaluated. Quint's simulator evaluates `or` lazily. If it did not, the run would fail loudly at state 0 and would not pass silently.
