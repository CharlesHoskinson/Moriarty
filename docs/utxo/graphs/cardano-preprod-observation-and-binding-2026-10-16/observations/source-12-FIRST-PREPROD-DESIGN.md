# FIRST-PREPROD-DESIGN (R2 design repair, PROPOSED, no execution authorized)

## Verdict
The production source supports exactly one bounded first live flow. The R1 four-stage happy path is corrected: settlement and claim burn are one atomic transaction, and the only separate claim-burn transaction is the post-expiry refund alternative when settlement never happens. Nothing in this design executes a proof, generates a key, signs, queries a provider or submits a transaction. The first blocked boundary is a genuine secp256k1 intent through the already-compiled VI wrapper, then a fresh-context Rust proof, then the atomic C2 spend/Burn + VI + VS1..VS4 + S2p settle. Seven Aiken validators are unchanged and their compiled B9 hashes stay stable; any validator edit restarts review.

## Corrected transaction DAG
- **T0 Deploy reference scripts.** Seven separate reference-script UTxOs for C2, VI, VS1, VS2, VS3, VS4 and S2p (67028 B combined applied size). Whether 67028 B of reference scripts in one transaction fits Preprod Conway reference-script size limits, tiered reference-script fees, maxTxSize and maxTxExUnits is UNKNOWN until live protocol parameters and a concrete built transaction are measured.
- **T1 Genesis (S2p mint Genesis{seed}).** `seed` is a real funded wallet UTxO spent by T1. T1 creates the thread UTxO locked at Script(s2p_hash) with thread_id = blake2b_256(serialise_data(seed)), seq 0 and the frozen catalogue (exactly the bounded invoice action; secp256k1 account public keys frozen here - see key prerequisite). Record the T1 thread output reference from the confirmed T1: this outref, not the wallet seed, is `env.settle_outref`.
- **T2 Claim issue (C2 mint Issue, +1).** Fresh EnvV2 with predicate_digest and vk_digest from the catalogue entry, claimant_vkh = the Ed25519 Preprod wallet VKH 96a9d23c533e33a10611cdd9e88e1b8fba539b4b98346c578bb78ddb, settle_outref = the actual T1 thread outref, statement_digest = BLAKE2b-256 of the fresh Rust statement (343-byte header + program-dependent body) built from the actual thread datum, outref and seq, and expiry derived as below. Requires a fresh Rust proof; the K6/K10 proof binds a fabricated context (claimant 5555, outref 2222, settle a2a2, 2030 expiry) and cannot be reused.
- **T3 Atomic settle (the settlement transaction; no T4 follows success).** One transaction that: spends the S2p thread input (Settle) and spends the C2 claim input; executes c2.mint Burn with claim token quantity -1 and no C2 token in any output (claim.release release_burned); carries the Ed25519 claimant VKH in tx.extra_signatories (claim.release release_claimant_signs; the ledger verifies that signature); satisfies release_spent_or_expired through the first disjunct because the same T3 spends env.settle_outref; withdraws zero from ALL FIVE of VI, VS1, VS2, VS3 and VS4 with identical coverage; and produces the exact continuation and payout outputs. All seven scripts (67028 B) are referenced in T3. If T3 lands, the claim token is burned and its carrier lovelace is ordinary T3 value disposed by the builder's change/payout accounting; there is no claim UTxO left to burn later.
- **T_expire Claim refund (alternative only, mutually exclusive with T3).** If T2 landed and T3 never settles, then once the transaction validity lower bound is Finite(t) with t > env.expiry (POSIX ms), the claimant-signed C2 spend with Burn -1 reclaims the carrier value. The settle_outref test in claim.release inspects the current transaction's inputs, not chain history, so this branch depends solely on the expiry disjunct. Thread state, custody and liabilities are unchanged on this branch.

## Key and custody prerequisites (explicit)
A fresh secp256k1 intent account keypair must be generated and privately custodied, and its public key (Schnorr 32-byte x-only or ECDSA 33-byte SEC1) frozen in catalogue.accounts at T1, before any intent can be signed for T3. The Ed25519 wallet key signs Cardano transactions only: T3 extra_signatories as claimant, plus fee and collateral inputs; it never signs intents and never proves. Existing wallet keygen AUTH is spent; this design grants no use of any existing key. Proving-key access, if ever authorised, is a separate private-custody operator step under fresh exact scope, gated on descriptor and source-pin comparison (native key reuse for a changed context is UNPERFORMED).

## Expiry and time (no naive conversion)
env.expiry and every intent [not_before, not_after] are POSIX milliseconds compared against the TxInfo validity interval. Slot-to-POSIX conversion must be established from Preprod EraHistory including the Byron-to-Shelley transition; systemStart + slot * slotLength is forbidden. The K9 fixture expiry 1893456000000 (2030) is builder-chosen, unbound and retired. The settle transaction validity interval must lie inside every intent window.

## Provider and parameter premises (qualified)
Provider responses are observations, not cryptographic authentication. /address_utxos must be called with _extended = true or inline datum, reference script and asset list are absent, and its value field carries no unit conversion. /epoch_params must name the chosen epoch explicitly; value units and cost-model format are UNKNOWN until the response is inspected. Wallet funding is UNKNOWN (an earlier unfunded assertion was made without a query and is withdrawn). Genesis seed selection records provider identity and observed tip slot/hash and is cross-checked against a second source or later on-chain confirmation.
