**Tier 2 — test cleanup.**

## Problem
`RUST_GUIDELINES.md`: "Nothing under `crates/` reads files outside it; copy anything needed in." Shared programs live in `crates/fixtures/`. Instead:
- 21 files under `crates/` `include_str!` from `examples/core/...` or `deliverables/native-owner-intent-2026-10-11/...`.
- Crates read each other's test files. `mori-core/tests/metered_intents.rs` reads `crates/mori/tests/fixtures/metered-intents/public-vectors.json` (7k lines), and `mori-backend/tests/replay.rs` reads `crates/mori-core/tests/fixtures/`.
- `crates/mori/tests/{installed_call,prepare_call,signed_installed_call}.rs` mount `crates/mori-ledger/tests/support/mod.rs` with `#[path]`.
- `examples/core/continuations/normal-oracle.json` and `crates/mori-core/tests/fixtures/continuations/normal-oracle.json` are identical copies.

## Suggested fix
1. Copy every file a test reads (programs, targets, scenarios, oracles, vectors) into `crates/fixtures/<area>/...`, and point the tests there using `env!("CARGO_MANIFEST_DIR")`. Leave `examples/` for users.
2. Replace the cross-crate `#[path]` mounts of `mori-ledger/tests/support` with fixture data in `crates/fixtures` plus small per-crate helpers, or a dev-only helper crate.
3. Add a test or CI step that fails if any file under `crates/*/src` or `crates/*/tests` reaches outside `crates/` with a relative path.

## Needs input
None for the copying. Decide whether a check must keep `examples/` and `crates/fixtures/` in sync, or whether one is generated from the other.

## Done when
No file under `crates/` reads outside `crates/`, and the new check enforces it.
