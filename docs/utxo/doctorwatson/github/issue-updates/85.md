**Tier 2 — test cleanup.**

## Problem
`RUST_GUIDELINES.md`: "Never write tests that invoke the CLI binary, and never snapshot `--help`. Test the library crates; keep the CLI a thin layer over them." Yet:
- All 19 files in `crates/mori/tests/` run `CARGO_BIN_EXE_mori` (about 126 tests).
- `src/commands/core_io.rs` re-runs its own test binary to capture stderr.
- `installed_call.rs`, `prepare_call.rs` and `signed_installed_call.rs` assert on `--help` output.
- Some tests shell out to `python3`. For example, `check_compile_io.rs` uses it to set `RLIMIT_FSIZE`.

## Suggested fix
1. For each test, find the library behavior it checks and move the test to that crate (`mori-core`, `mori-backend` or `mori-ledger`), calling the function the command calls.
2. Remove the `--help` assertions.
3. Where a test checks a command's file I/O (atomic publishing, never clobbering, write faults), test the publishing helpers directly, as the unit tests in `commands/compile.rs` already do.
4. Delete each `crates/mori/tests/` file once its coverage has moved.

## Needs input
Mostly blocked on #80: tests for logic that still lives in the CLI have no library function to call. Start now with tests whose logic is already in a library, such as the compile paths in `check_compile_io.rs`, `replay.rs` and `metered_intents.rs`.

## Done when
No test runs the `mori` binary or `python3`, and coverage is kept or improved.
