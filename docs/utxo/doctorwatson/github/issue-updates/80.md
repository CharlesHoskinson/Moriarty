**Tier 3 — structural.**

## Problem
`RUST_GUIDELINES.md` says to keep the CLI a thin layer over the library crates. `crates/mori/src/commands/` has grown by about 19k lines, much of it logic that belongs in libraries:
- `inspect.rs`: the enforcement report walks Core `Expr`/`Statement` values and holds rule-text tables.
- `test.rs`: the whole Core test runner, including manifest rules and hand-built JSON.
- `init.rs`: project templates and their expected outcomes.
- `call_io.rs`: checks that request inputs match the source action.
- `verify_call.rs`, `prove_call.rs` and the `*_signed_call.rs` files: the CLI sequences the multi-step ledger protocol (`admit_context` → `admit_inspection` → `verify` → `admit_readback`) itself, with `futures::executor::block_on` and `StdRng::from_entropy`.
- `core_io.rs`: formats structured ledger errors into strings.

Problems with the command surface:
- 13 flat call subcommands (`compile-call`, `keygen-call`, `keygen-signed-call`, `prepare-call`, `prepare-signed-call`, `prove-call`, `prove-signed-call`, `verify-call`, `verify-signed-call`, …).
- `SigningOutputArgs.json` (`--json` on `intent` and `verify-intent`) is never read.
- `--review` prints prose and then JSON to the same stdout (`intent.rs`, `verify_intent.rs`).
- Flag combinations are checked by hand (`compile_call.rs`, `intent.rs`) instead of with clap groups. `--authorization` is a `String`, not a `ValueEnum`. Many arguments have no doc comment, so `--help` shows nothing for them.
- `prove`, `verify`, `simulate` and `replay` print no status line, and no new command adds anything under `--verbose`.

## Suggested fix
1. Move the enforcement report into `mori-backend` or `mori-core`, and the test runner and init templates into `mori-core`. Make the call protocol `mori-ledger` functions that take parsed inputs and return typed results. Each command then reads files, calls one function and prints.
2. Nest the call commands: `mori call {compile,keygen,prepare,prove,verify} [--signed]`.
3. Make `--json` work (status lines off, only JSON on stdout) or remove it. Send `--review` prose to stderr, or make it exclusive with JSON.
4. Use clap `ArgGroup`, `conflicts_with` and `ValueEnum`, and document every argument.
5. Add cargo-style status lines and `--verbose` timings to the commands that lack them.

## Needs input
- Command names and nesting. Scripts, `deliverables/` and other agents may already call the current names; decide whether old names stay as aliases.
- Which crate owns the call protocol.

Command modules only parse arguments, read inputs, call a library and print. #85 depends on this.
