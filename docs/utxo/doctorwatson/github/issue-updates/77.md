**Tier 3 — structural.**

## Problem
Two identities are SHA-256 hashes of Rust source text, so any edit or reformat changes them:
- `mori_ledger::proving::source_closure()` `include_str!`s about 110 files: the CLI's own sources (`crates/mori/src/...`), the root `Cargo.toml` and `Cargo.lock`, `mori-core`, `mori-lexer`, all Sherlock files and (since #74) the backend files the ledger reuses. It becomes the `build` field of local deployment and static-compile manifests (`local_deployment.rs`, `static_compile.rs`, `signed/deployment.rs`). A library depends on the bytes of its consumer, and a `cargo fmt` or lockfile bump invalidates saved manifests. `tests/source_closure_coverage.rs` pins the member list.
- `mori_ledger::layout::templates_hash()` hashes the text of `ops.rs` and is part of every static `abi_hash`. A one-line change in e9a2b80b left `examples/core/static-compile/*.bindings.json` and `examples/core/fee-pool/*static-bindings.json` stale and broke 4 tests until #74 regenerated them.

## Suggested fix
1. `templates_hash`: hash a canonical serialization of the templates `ops.rs` produces, or a declared template-set version that is bumped when templates change. Add a test that a whitespace-only change to `ops.rs` leaves it unchanged.
2. `source_closure`: replace it with a declared toolchain identity (crate versions, the `rust-toolchain.toml` channel, the Midnight entries of `Cargo.lock`) or with hashes of the artifacts the manifest describes (ZKIR, keys). Stop `include_str!`-ing CLI sources.
3. Remove `source_closure_coverage.rs`, or reduce it to what the new identity needs.
4. Regenerate the example bindings and say in the PR which saved manifests become invalid.

## Needs input
- What `build` is meant to prove. If it's "built from the reviewed source", a reviewed commit or tree hash recorded at release may be enough. The security owner should agree, because these manifests cross a trust boundary.
- How to migrate: regenerate everything at once, or accept old and new identities for a while.

## Done when
Formatting or editing an unrelated source file changes no identity, and the example bindings and tests are regenerated.
