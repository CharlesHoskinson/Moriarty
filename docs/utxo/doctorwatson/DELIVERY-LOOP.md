# DoctorWatson language delivery loop

Design, 2026-10-17. This extends the existing [DoctorWatson cycle](../../DOCTORWATSON.md) to the complete Moriarty language. It is an actionable delivery policy, not product acceptance or a claim that a background process is running. The user has authorized redesign, continuation, implementation and merging the fixed PRs without another permission round. The prior goal was cleared; the new language goal is active. The root session owns that goal's continuation and observes its runtime state; DoctorWatson remains explicit repository-local QA.

## Choice and boundary

Use the existing goal continuation, direct model calls, Git/GitHub and `scripts/doctorwatson.sh` / `scripts/doctorwatson-utxo.sh`. This preserves one continuation mechanism and the existing evidence namespaces. No Foreman, `fm-session`, Endstop, replacement scheduler, campaign dispatch, daemon or automatic hosted CI belongs in this cycle. GitHub holds source, PRs and evidence summaries; checks run locally.

Two alternatives were considered. A documentation/report-only loop is easy to keep green but cannot finish consumer behavior; reject it. A new autonomous dispatcher could redistribute work but adds an unauthorized framework and administrative work; reject it. Existing goal continuation plus native DoctorWatson commands delivers actual increments while retaining execution limits.

The [product contract](../../MORIARTY-PRODUCT-CONTRACT.md) remains controlling: public developers need no maintainer approval to author, compile, prove or deploy supported Moriarty programs. These review and resource rules govern maintainer work. Moriarty targets Midnight ZKIRv3; Cardano adaptation evidence never substitutes for Midnight acceptance.

## One cycle: a useful consumer result

1. **Select behavior.** Read the current requirement/scenario, its latest evidence and the production consumer. State one falsifiable predicate, supported profile/target and first blocked boundary. Choose the earliest ready dependency that advances public language behavior; do not select stale historical campaign `nextAction` as today's queue. A tooling fix must restore or preserve a named consumer capability, not merely generate another status artifact.
2. **Freeze expectations before executing the candidate.** A non-author derives the financial/work oracle from frozen semantics and inputs, without importing the evaluator/compiler under audit. Preserve complete affected and protected state, ordered effects, durable IDs, frame, gross debit, all fees, net receipts, dust/reserves, opening/accrued/discharged/closing liabilities, residual duties and separate logical work counters. Mark inapplicable fields explicitly. Circuit cost, DUST, service fees, recovery reservation and wall time remain distinct. Never replace independent expectations with implementation snapshots to remove a failure.
3. **Assign exact ownership.** Record requirement, consumer, predicate, exact read/write paths, dependencies, profile, oracle owner, author/reviewer identities, check closure, execution boundary and expected artifact. Shared IR, ABI, Cargo/module exports and result interfaces belong to one integrator. Independent ready disjoint source tasks run in parallel; dependencies constrain consumption and acceptance, not all source preparation.
4. **Implement the smallest useful increment.** Wire the real consumer. Preserve explicit unsupported/refusal outcomes and original diagnostics. A helper without a consumer is preparation, not delivered behavior. Source preparation remains eligible when native/proof/ledger execution is held; report the increment as source-only if its behavior cannot be observed under current authority.
5. **Run inspected local CI.** Execute only ordinary commands whose transitive effects were inspected and remain authorized. Record exact command, environment policy, tool versions, attempt ID, exit/timeout and original output digest. Run affected separate K, finite Quint, Lean/Clean and circuit checks only under their existing authority; absent layers remain UNRUN or BLOCKED, never inferred passes. `--host` and `--design` are explicit additional lanes, not implicit follow-ups to a green default check.
6. **Review exact bytes and results.** Freeze candidate commit/tree, integration base, all consumed dependency/oracle/profile digests and current attempt. A fresh non-author reviews the full candidate and actual result bytes against the requirement and independent expectations; security judgments go to the designated security owner. Preserve dissent, read limits and terminal failures. Source review, actual-result review and execution admission are distinct.
7. **Integrate one candidate.** Rebase/compose against the current integration base, resolve interfaces, rerun affected authorized checks, and obtain applicable review of the resulting tree/results. New bytes or consumed dependencies invalidate affected reviews and results transitively. Merge reviewed fixed PRs under the user's current authorization; qualify source-only merges explicitly when higher tiers are unrun. No historical draft-publication approval is relabeled as approval of a later merged candidate.
8. **Record the actual delta and continue.** Update existing requirement/evidence records and linked GitHub items only for predicates supported by actual scoped evidence. Record useful integrated behavior or source preparation, first divergence, retained gaps and next ready consumer task. Select the next ready dependency immediately; no new framework or permission round is needed for already authorized work.

Attempts are separate even when source is unchanged. Late results from cancelled/timed-out attempts cannot approve the current attempt. Terminal failures remain terminal history; upstream source changes do not reset counters or revive their execution. Cancelled/blocked tasks release active write ownership. A new source task can proceed independently without reopening a terminal native attempt.

## Limits and stops

Native authority remains **zero**. Preserve C4, exhausted R3 k17, all resource limits/counters and previous terminal outcomes. The prior broader Preprod goal's paused state is historical and that goal was cleared; the new language goal is active. Its proof and target execution remain separately unadmitted. No SDK relation/circuit run, model/degree/k query, VM/transcript execution, SRS/key/proof operation, native verification, wallet/provider/deploy/ledger action is created by this loop. Neither source concurrency nor the goal's active status grants that authority. Fenrir identities/configuration remain unknown where unestablished; Preview, Preprod, Fenrir and Midnight stagenet retain separate evidence. K/Quint/Lean-Clean are developer QA, not public deployment prerequisites.

After **two failed cycles of the same defect class**, preserve the first failing input/field, reduce a reproducer and change the approach before another broad retry. After **two process-only cycles or thirty minutes of administration**, stop process work and choose eligible consumer diagnosis/implementation. Apply these counters to each capability and integrated delivery; renaming tasks or spawning agents does not reset them. If every eligible consumer is blocked, name the exact blocked predicate, owner and next feasible source preparation; do not fabricate progress or replace execution with another orchestration project.

Mark the language goal complete only when retained product exits actually pass. The user may stop or explicitly pause it. Under the host's goal rules, the root may mark it blocked only after the same external blocker has repeated for at least three consecutive goal turns and no meaningful independent progress remains; a resumed blocked goal starts a fresh three-turn audit. Blocked status retains the unfinished obligation and is never a substitute for completion. An all-green inventory, a merged PR, a finite workflow-model pass or a temporary lack of ready work cannot complete the language goal. Runtime arming, design validation, source integration and product acceptance are separate claims.
