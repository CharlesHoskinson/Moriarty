# Proposed exact additions to Candidate 02 — architecture review of Gemini lanes 01/02/03/08

Status: proposed text for Root integration, not an adopted interface or implementation. Keep Candidate 02's mandatory refinements, owner obligations and current-v1 scope. The identifiers below name proposed design work; they do not claim callable APIs.

## D1 — Add after “Concrete public compiler increment”

Integrator I owns one versioned public source-to-Sherlock route in the existing compile command. Its grammar table must identify the current public Core grammar, the proposed recursive/nominal extension, the source/Core/execution profiles and the exact producer and consumer for each construct. The actual draft modules are sherlock_draft, sherlock_draft_types and sherlock_draft_image, registered only under cfg(test) in mori-core/src/lib.rs. They are preparation inputs, not an already public sherlock::source API.

For closed monomorphic recursive declaration groups, elaborate in two stages: register nominal declarations, ordered constructors/fields and function signatures; then check all bodies and elaborate source-ordered match plans. Calls retain function-table references, and source occurrences remain distinct. Registration must preserve the selected profile's name resolution, function source order and first-match lookup. A unique-function source subset must be explicitly identified and mapped to the execution profile; it cannot retroactively reject or reorder programs in the existing A domain. The existing draft's duplicate-parameter and duplicate-pattern-binder diagnostics describe its typed subset, not new A/B runtime error rules. NoMatch retains the specified error9 mapping. Constructor and match elaboration retain strict field order, fresh arm scope, minimum matching source arm and ordered workMap.

The new public route returns one proposed admitted-program handle carrying the source/version and execution-profile selection, immutable program-table membership, source occurrence map, bounds/layout/capability disposition and profile-specific admitted representation. Interpret and witness consumers receive that handle or a declared lossless view of it. A, B and bounded encodings may differ; their identity correspondence is explicit and never inferred from equal bytes or a common JSON shape. Preparation/admission/capacity/unsupported diagnostics remain outside runtime Outcome. Existing diagnostic Machine::new/visit_steps contracts do not acquire a new implicit admission policy. The selected public execution route requires the already designated H1 disposition before exposure; this internal condition is not public program permission.

The profile owners specify preparation and admission for their own representations. The integrator composes those existing obligations rather than replacing them with a universal unimplemented admit_program call. B admission currently enforces stepCap >= 1 and width checks against declared counter maxima, refuses unavailable bounded record widths, and refuses its unsupported boundary section. Do not substitute Gemini's proposed stepCap <= CounterWidth maximum rule for those checks.

## D2 — Add after D1

The compiler artifact contract includes a manifest plus separately identified ProgramImage/admission metadata, OperationManifest, ConstraintPlan, WitnessPlan and BackendCapabilities/export dispositions. Root and Integrator I freeze file names, versions, ordered bindings, producer/consumer locators, identity linkage and unavailable-field representation before implementation. Compilation succeeds only for the selected artifact scope. Unsupported reachable lowering returns a located tooling result; it cannot silently choose ordinary Core lowering, the literal-only relation or an evaluated constant as a substitute. Ordinary Core compilation with source-projection metadata remains separately identified.

Prepare and serialize the selected bundle before publication; use the existing new-destination/non-overwrite convention and publish the completion manifest last. A partial directory has no completed-artifact claim. This is a completion-marker contract; atomic multi-file filesystem publication is not established by the current CLI. Consumers must check the declared bundle membership and disposition. Do not change current relation/source-closure hashes, key identity or descriptor inheritance as part of plan separation.

Independent acceptance examples use the same public path for contrasting newly authored programs, plus recursive calls, an unused function body, two equal expressions at distinct sites, Schedule and a mutually recursive nominal group. The source examples and expected results are authored independently of compiler/plan metadata. Missing nominal/helper/backend consumers remain explicit unsupported scope until implemented, rather than counting dedicated List/Tree support as generic ADT completion.

## D3 — Add after “Separate A/B native implementation maps”

The GenericNominal constructor path needs an explicit continuation-frame contract before the existing Build helper payloads can become an end-to-end implementation. The current FrameRowC has exactly nine core variants and explicitly refuses the reserved ConstructorFields tag; proposed ControlExtC::Materialize already assumes evaluated fields. The schema owner must define the GenericNominal extension frame, its complete payload and all introducing, returning, failure, release and serialization transitions. At the semantic interface it retains nominal type/constructor identity, source occurrence, saved environment, evaluated field prefix, remaining field expressions or an equivalent cursor, and the eventual return context. Constructor fields evaluate strictly left-to-right; a field can call recursively while later fields remain pending. Allocation occurs only at the specified construction point after field evaluation. Do not assign new tags, widths, guards, work charges or error codes in this architecture text.

The interface owner owns the shared carrier and admission/selection/application changes; the frame/call and ADT family owners supply their disjoint payload functions against that interface. DedicatedSorts keeps its current behavior. GenericNominal admission must state its binder-linearity rule and how its accepted source domain maps to runtime matching. Existing A and dedicated B treat equal Cons/Branch binder names as a match miss; do not replace that behavior with a fabricated error8 path.

Normal correspondence cases include zero-field construction, recursive work in the first and last fields, distinct equal-looking source occurrences, cut/resume with an incomplete field prefix, nested ordered Schedule matching, and mutually recursive declarations. Record frames, saved environments, field order, helper cursor/result, work and earliest stop, not only the constructed value.

## D4 — Add after “Trace continuity, observer stops and persistent boundaries”

Cross-profile observation and persistent same-profile resume are different adapters. A B-to-A erasure declares its common domain and helper-origin treatment. An A-to-B adapter is partial and needs actual provenance where the target requires it; equal syntax and a search for a unique apparent parent cannot reconstruct missing source origins. Complete control/frame mapping includes ScheduleNext/Push semantics and nested pending frames, not merely a depth-one example. The current literal 333-carrier capture remains its existing A-specific test and is not a B-to-A adapter test.

Persistent B checkpoints retain complete pending helper, task, result and frame state under the specified representation domain. Do not impose a global quiet-helper-only cut restriction or rename a technical cut Yield/Await. A quiet-boundary-only prototype can have that declared limited scope, but it does not satisfy current-v1 complete checkpoint/resume requirements. The current B host's refusal of boundary sections is an implementation gap, not a normative removal of those requirements.

Within a resident Step representation, adjacency uses its exact prior output. ChunkStore.put/get and checkpoint resume retain Candidate 02's canonical-boundary contract and the existing A4 owner obligations. A raw-StepJoin persistence alternative would require an explicit existing-owner design change; this review does not select it. Projection preserves semantic fields and logical allocation/work history while physical row numbers may change. Cross-profile erasure cannot discard B helper state and then claim a same-profile B resume.

## D5 — Add after the reusable-realization component contract

Use a shared realization infrastructure proposal to factor repeated shape/range/fetch/preservation wiring, with a single integration owner and explicit inputs from the per-rule inventories. Evaluate common scaffolding, enabled rule-specific fetches, typed read/write/preserve sets and collision-free local naming against the existing fragments. Whether one monolithic spine or smaller reusable components is preferable remains a measured implementation choice. No expression fetch is assumed for every control rule, and charged fuel updates never apply to A80/A82/A84.

The A inventory is exactly the 39 events in the frozen full39 source adoption and layout observation table; generate work allocation from that inventory, not the Gemini example wave IDs. Full39 semantic-source adoption does not select the still-open physical mechanisms or close P2–P6/G4/F4 and its binding conditions. B core/helper and GenericNominal extension inventories remain separate, with their owner-controlled runtime integration and bounds. No missing row falls through to an unrelated leaf.

OperationManifest may connect shared operation identifiers to independently owned witness and constraint consumers. The existing B EffectPlan proposes runtime writes/deltas from an actual pre-image; it is not already a declarative ConstraintPlan or a proof of witness/constraint correspondence. Separate plans need explicit typed bindings, stable dependency order, capabilities and located omissions. Their agreement must be checked against the independent reference and normal expectations; sharing metadata cannot manufacture the oracle. Keep the deterministic uncached witness DAG baseline and the mandatory private Clean semantic/circuit/correspondence stage.

Repeated range-check source is a reason to investigate sharing, not a measured 39x cost or proof that the k=17 target fails. Scratch-window and preallocated-argument proposals are optional physical experiments after the existing behavior is recorded. They must preserve the selected profile's charges, capacities, allocation history, cut state and earliest stop, or be reviewed as a changed profile. Logical helper work is not automatically reduced by using fewer physical copy instructions.

## D6 — Replace any text that calls bounded residualization “optional next-version P2”

Bounded static residualization is current-v1 work under UIREQ-033, together with separate plans/export, slices at widths 1/2/4/8, declaration-driven matching and deterministic uncached witness dataflow under UIREQ-031–035. Implement the finite worklist and residual-size fallback baseline for the required static masks. Immutable source/code/declaration/layout facts may specialize; runtime control, values, environments, frames, fuel/work, helper cursors and financial state remain dynamic. Dynamic branches retain both successors. Size-limit fallback uses generic dispatch and does not become application exhaustion.

Compare universal, fixed-family and fixed-program realizations by complete decoded reference prefixes, origin mappings, charges, pending state and earliest stops. Witness slot numbering or physical row equality is required only when the selected physical contract requires it; semantic correspondence is not inferred from equal final values. Choosing an optimized family layout, packing, alternative pattern heuristics, cache policy or a faster specializer remains a later measured choice. No source recursion unrolling, mandatory termination proof or Scott/fixpoint replacement is introduced.

## D7 — Add after “Complete financial continuation map”

Owner H and the composition/backend owners maintain a typed interface matrix before selecting a recursive statement encoding. Distinguish: the execution-step input/output, the complete same-profile persistent checkpoint, the source financial boundary, the recursive compliance statement with predecessor inputs, and the actual ledger settlement envelope. For each, name complete semantic fields, compatibility/disposition, producer, consumer, source membership and available or missing backend capability. This is an interface inventory, not a choice of digest algorithm, byte width, accumulator format or new universal opcode.

A technical cut carries both previously committed financial state and the tentative current segment, including ordered effects, complete liabilities, pending observations/captures and attempted/committed work. Core/2 load/start/resume and the selected financial policy control successful-prefix and failure behavior. A82/A84 are pure-machine publication rules and do not themselves implement financial rollback. Do not infer a universal Commit/Await/Yield policy from their names or from a proposed digest-only record.

The composition inventory retains all five required operators and at least the required bounded two-parent case, with each operator's compatibility, parent accounting, duties and work conservation mapped explicitly. Preserve authorized compatible heterogeneous relations and harmless shared ancestry; per-stage fan-in is distinct from total ancestry. A binary decomposition is usable only when its intermediate nodes preserve that operator's financial relation and required parent coverage. k <= 2, a lineageRoot field, equal program identities or a generic fold are not an established substitute for the existing ZR/MNR and MC06 obligations. Their security interpretation and exact binding remain with the existing owner.

Separate recursive compliance/accumulation capability from ordinary final ledger-call verification and actual effects. The public literal-complete adapter uses ProofMarker::proof_verify for its named ledger operation; that does not establish a general recursive or private multi-parent implementation. Keep actual pinned-interface qualification, deferred verification closure, independent native evidence and complete settlement readback as required acceptance work. Preparation may be staged; the final ledger/native/composition requirements do not become optional. No VerifyProof prerequisite or alternative backend is introduced.
