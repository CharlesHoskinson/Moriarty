## Scope and vocabulary

The input is an admitted `stage::StagedProgram` loaded by `stage::load` from the existing `language "moriarty/2";` grammar. Its Program has language `moriarty/2` and semantics `moriarty-core/2`. The local cost profile is `moriarty-reference-logical-cost/2`. All statements below apply to this Rust Core/2 reference profile, not Sherlock B helper microsteps, K or Quint charges, circuit cost, DUST, native fees, settlement or general nominal ADTs.

Object notation below lists every field. Fields are required, including fields whose value is null. `T?` means JSON null or the representation of T. `T[]` is an ordered array; it does not sort, deduplicate or omit entries. `Map<T>` is a JSON object from exact string names to T. `UInt` is a canonical decimal JSON string in [0,2^128-1], with no sign or leading zero except `"0"`. `u8`, `u16` and `u32` are JSON integer numbers in their named ranges. Bool means true or false, not a number. Every string keeps its decoded Unicode content. There are no floats in these types.

External sums use a singleton object `{Variant: payload}`; a nullary variant is the exact JSON string `"Variant"`. Struct fields have no wrapper. Result uses `{Ok: StageOutcome}` or `{Err: StageRejection}`. This contract describes serialized output, not a new decoder or validation rule. Existing Core/1 decode types still cannot decode an Await-bearing Step.

This exclusion does not waive any broader language, hostile-input, error, H2/H3/H4/H6 or financial obligation. Successful admission/emission predicates below remain prerequisites that must be independently established for the selected input, never inferred from an actual success.

The finite source-lowering lexical cohort has at most8191 source UTF8 bytes and uses only ASCII characters. Outside quoted strings, whitespace is exactly U+0020 SPACE or U+000A LF; tabs, carriage returns and other whitespace are outside this cohort. Identifiers have the exact shape specified in the admission section. ## Program and expression identity (G1, G2)

Program is `{language:String, semantics:String, name:String, states:StateDecl[], assets:AssetDecl[], expressions:Expr[], actions:Action[]}`. All four arrays preserve declaration/parser append order. State initializers and asset scale literals are stored in declarations and do not allocate Expr rows. Action input declarations likewise allocate no expression row and no statement index. Inputs written in the signature precede any leading `input` declarations in the body's input array.

Expression IDs are the zero-based indices in one program-wide expressions array, shared across all action declarations. Start with an empty array. Parse declarations and each action's statements in source order. At each newly formed expression node, append that node and return its index. Every literal occurrence, bare-name occurrence and liability-read occurrence appends its own row; equal occurrences are not interned, folded or shared by the parser. For `not`, parse its operand before appending Not. For a binary operator, the left operand already has an ID, parse the right operand, then append Binary with those IDs. Parentheses allocate no row of their own. Every action uses the existing array; numbering does not reset per action.

The binary precedence from lowest to highest is `or`; `and`; `==`, `not =`, `<`, `<=`, `>`, `>=`; `+`, `-`; `*`. Each binary level is left associative: parsing the right operand uses minimum precedence one above that operator. Prefix `not` parses its operand at precedence6. Liability read calls have exactly the string-name argument represented by their node. Numeric literal underscores are removed before conversion to UInt. The existing lexer/grammar/admission bounds remain prerequisites; this text does not extend accepted syntax.

## Canonical digest preimages (G1)

Let J(x) be the complete serialized value of the declared type x, including every field and explicit null; no report wrapper is added. Let C(x) be these canonical JSON bytes:

1. Recursively sort every JSON object's keys in ascending Rust String order (lexicographic Unicode scalar order, equivalently UTF-8 lexicographic order for valid strings). Preserve every array's original order. Preserve types and scalar contents.
2. Encode compact JSON as UTF-8, no BOM, indentation, optional spaces or trailing newline. Object separators are colon and comma; array separator is comma. Integer JSON numbers are unsigned base10 digits. UInt values remain strings.
3. Strings use double quotes, escape quote as `\"`, backslash as `\\`, and the ASCII controls backspace/tab/linefeed/formfeed/carriage-return as `\b`, `\t`, `\n`, `\f`, `\r`. Other bytes U+0000 through U+001F use lowercase `\u00xx`. Other characters are emitted as their UTF-8 bytes; slash is not escaped, non-ASCII text is not ASCII-escaped, and no Unicode normalization is performed. This is the current `intent::canonical` compact `serde_json`1.0.151 encoding for these integer/string/bool/null-only schemas.

`program_hash = lowercase_hex(SHA256(C(Program)))`. No raw source bytes, source SHA, prefix, suffix, domain separator, length prefix or report wrapper is added. Field values such as language and semantics remain in Program and thus in the preimage.

Build and cost the complete StagePlan, then fill its program_hash with that 64-character lowercase Program digest. `plan_hash = lowercase_hex(SHA256(C(filled StagePlan)))`. StagePlan has no plan_hash member, so the plan preimage does not contain its own digest. The plan's format, ordered actions/sites/captures and full cost vectors are included. Continuation cap, boundary, captured values, event, current invocation/result and report labels are not added to either preimage. This is an exact reference representation, not authentication, canonical-source-byte identity or certified hash correspondence.

## Source sites, captures and plan (G3)

Within each action, statements have zero-based ordinal equal to their index in Action.statements, including Let, Await and every other statement. Await sites are independently numbered in increasing encounter order, starting at1; site0 denotes no pending await. AwaitSite.ordinal is that await's statement index, not its site index. ActionPlan.statement_count is the full statement array length. Program actions and plan actions keep the same declaration order.

Begin each action's pending capture layout with its input list in input order. Each slot is `{name,ty,origin:"Input",ordinal}`, with ordinal the zero-based input index. Scan statements in source order. On a Let, append its slot with inferred type, origin `"Let"`, ordinal equal to that Let's statement index. At an Await, record the current capture layout as that site's captures. AwaitSite.label is the source Await label; its binders copy exactly each source binder name and ty in source binder order. Then append the site's binders in binder order for future sites. Those appended slots have origin `"Event"` and ordinal equal to that originating Await's statement index; several event slots can therefore share an ordinal. The current await's binders are not in its pre-event capture layout. All inputs and evaluated prior lets/accepted event binders are retained; there is no live-variable filtering. State declarations alone add no capture slot.

At actual Await entry, captures are named values read from the current environment in that exact site layout order. Inputs and lets are captured by value. A start environment begins with pre.state, then action inputs. A resumed environment begins with boundary.state, then retained captures, then this event's named values. Next updates both the state row and the environment binding. A Name referring to a state after resume reads that resumed boundary state value; state names are never capture slots. Only a distinct Let/event binding carrying an earlier state-derived value, or an equal caller-supplied input, can retain that earlier value. Admitted capture names cannot shadow a state, so there is no automatic state-name capture or state-shadow exception. This documents the existing admitted no-shadow/type premises; it adds no name-admission policy.

## Ordinary expression values and static types (C3, C9)

Evaluate each statement's expression against that statement's current environment and current Snapshot, with a fresh cache indexed by ExprId. Literal returns its typed Value. Name returns the current environment binding. LiabilityPresent returns Booltrue exactly when a liability row with that name exists, including a present-zero row. LiabilityAmount returns the current row amount or UInt0 if absent; these reads add no effects. Liability-read names must have an unambiguous source-wide liability identity as an admission premise.

Not requires Bool and negates it. Add/Sub/Mul require UInt operands and use checked UInt128 arithmetic: Add/Mul failure on overflow, Sub failure on underflow. Lt/Le/Gt/Ge require UInt operands and return the corresponding comparison Bool. And/Or require Bool operands; both operands are evaluated eagerly, left before right, then combined. Eq/Ne compare the complete typed Values structurally, without Bool/UInt coercion. Static typing requires both operands to have the same type for Eq/Ne; other binary operators additionally require the operand types just stated. Arithmetic returns UInt; comparisons, Eq/Ne, And/Or and Not return Bool. No failing operation publishes a successful Step.

For Let-slot inference, begin the static type environment with declared state types, then action input types. Name resolves in that prefix environment; Literal has its Value's type; liability reads have Bool/UInt types as above. For each Let infer its expression type and then add the new name. Add an Await's binder types before typing its Bool guard, and retain these binder types for subsequent statements. Existing validation forbids any input, Let or Await binder from shadowing an existing state/local/input/binder name or asset declaration. Let CaptureSlot.ty is this inferred type, not a type guessed from a runtime value. Next must target a declared state and have that same type; Requires/Ensures/Await guards require Bool; financial amount roots require UInt; Emit permits either scalar type.

## Start Snapshot and ordinary statement transitions (C3, C4)

An empty Scenario.state selects every declared state's initial typed value. A nonempty Scenario.state must supply exactly all declared state names with their declared types and no other key. Scenario.inputs must match exactly the selected action's input names and types. The initial Snapshot contains only state, balances and liabilities, never inputs. Clone the supplied balance/liability rows, retaining every valid row including zero amounts; sort balances by (AssetId,account) and liabilities by name. All String components use the G1 bytewise Rust String order, not UTF16 or locale order. AssetId order is network, issuer, reference using that String order, then numeric u8 scale; account is compared last using that String order. Liability names use that same bytewise String order. Input Scenario array order remains unchanged in the captured call arguments; normalization applies to the execution Snapshot only.

All balance assets must be exact declared asset identities; account names are nonempty and bounded; no duplicate (asset,account) rows. Every from/to account used by any Transfer/Fee in the selected action must have an explicit balance row. Liabilities use declared assets, nonempty bounded names/parties, unique names and identities matching the source registry where applicable. An absent liability and a present-zero row remain different states. No implicit account or asset row is created.

Each successful statement transition starts from current Snapshot S and environment E and appends exactly its ordered effects below. Let evaluates its value, binds the new name in E, leaves S unchanged and has no effect. Requires/Ensures evaluate their predicate and succeed only for typed Booltrue; they leave S/E unchanged and have no effect. Await guard evaluation likewise has no effect; false produces NotAdvanced at the stage boundary, true permits the resumed segment to continue. Await entry itself has no expression evaluation or Step.

Next evaluates the new typed value, records the prior state value, updates that state in both S.state and E, and emits exactly `{kind:"State",name,before,after}`. Emit evaluates its value, leaves S/E unchanged and emits exactly `{kind:"Emit",name,value}`. Effects are collected per statement and concatenated in source order for the execution.

Transfer/Fee first evaluate their UInt amount, then resolve the statement's asset name to its exact declared AssetId. They require the source balance to cover the amount and, for different source/recipient rows, require checked addition to the recipient to fit UInt128. For different rows update debit/credit accordingly. A self-transfer/self-fee still checks source sufficiency and emits its gross effect, while balances remain unchanged; it does not perform a fictitious overflowing recipient addition. Emit exactly one Transfer or Fee effect with resolved asset, from, to and the evaluated amount.

Liability evaluates amount and resolves the asset name. If its name exists, asset/debtor/creditor must match that row; before is its current amount. If absent, before is UInt0 and a new row with the source identity is created. After is checked before+amount. Update/insert the row and retain name-sorted order; even a zero-created row remains present. Emit one Liability effect carrying name, exact asset/parties, before and after. Discharge requires the named existing row, evaluates UInt amount, computes checked before-amount, updates that same row without deleting a zero result, and emits one Liability effect using the existing row's asset/debtor/creditor. For all financial statements Step.value is the evaluated amount, not the resulting balance or debt.

## Frames, continuation and residual construction (C5)

Start frame_pre is exactly `{site:0,captures:[]}`. Resume frame_pre is `{site:c.site,captures:c.captures}` from the exact input continuation. A successfully advanced segment that stops at another Await has frame_post `{site:exit_site,captures:captures_out}`, with captures_out read by name from the current environment in that Await site's complete layout order. Complete has frame_post `{site:0,captures:[]}`. False guard publishes segment=None and therefore no returned segment frames; it does not fabricate an idle frame or a replacement empty Execution.

After a successfully advanced segment ending at a pending Await, construct Continuation with literal format above, lowercase program/plan digests, selected action name, exit_site, frame_post.captures, and boundary=execution.post. Its logical is `{profile:"moriarty-reference-logical-cost/2",cap:stored_cap,committed}`. At Start, stored_cap is the caller's supplied optional start cap; at Resume it is the input continuation's stored cap. The optional CLI resume cap never replaces the stored value in a returned continuation. The complete Continuation passes the existing emit_checked premises before being published. Every successfully evaluated Start segment that reaches an Await, including an empty segment0, returns Waiting with advanced=true and segment=Some(that complete StageSegment). Every successfully evaluated true-guard Resume segment that reaches a later Await likewise returns Waiting with advanced=true and segment=Some. Reaching the end instead returns Complete with its segment; it is not Waiting.

Advanced Waiting and Complete take residual from execution.post, retaining exactly its positive liability rows in existing name order. False Waiting takes residual from the unchanged input boundary. The unchanged input continuation, including cap, hashes, logical committed, captures and boundary, is returned exactly on false guard; attempted work is a separate result field. Complete publishes its segment/counters/residual without a synthetic continuation.

## Step and segment representation (G2)

For a successful ordinary statement, Step.index is the statement's original zero-based source ordinal; Step.statement is the exact Program statement, including its existing ExprIds. Step.snapshot is the complete post-statement Snapshot. Step.effects is only that statement's ordered effect list, which can be empty. Execution.effects concatenates the successful statement effect lists in order; snapshots retain zero-valued liabilities. Execution.semantics is Program.semantics, hence `moriarty-core/2` for this admitted profile. Execution.action is the selected action name, pre is the invocation boundary and post is the final segment boundary. It is not renumbered to segment-local indices.

Successful Step.value is Some of: Let's evaluated value; Requires/Ensures evaluated Booltrue; Next's new state value; Emit's emitted value; Transfer/Fee/Liability/Discharge's evaluated UInt amount. A successful resumed Await guard Step has Some Booltrue, the source Await statement/index, the unchanged invocation pre snapshot and an empty effect list. The Option is present in JSON as that typed Value, not a Some wrapper; None would be null. The current successful statement arms listed here return Some, including Let; this does not erase Option from the type.

Reaching a subsequent Await charges its entry and stops before its guard; it creates no Step. A false resume evaluates the guard but publishes no segment or Step history. A true resume begins its segment's steps with the guard Step described above and continues after that Await. A successful segment can have zero effects and is still Some(segment), with frames, execution, steps and full snapshots. No-segment is never replaced by an empty Execution.

## Reference logical work and plan arithmetic (G5)

### Separately adopted unit weights only

Separately adopted existing /2 unit weights, under Root record f510ad29795acd8570d82918ef56f54ada4e3cb37f83947f967de6a5a2825d5d: statement dispatch costs one logical unit; each uncached expression-node attempt within that statement costs one logical unit. A node is charged before children/operation. A fresh expression cache is used per statement evaluation. Cache hits add no unit; distinct nodes with equal values remain distinct. Binary operands are evaluated eagerly left then right, including And/Or. These are interpreter work units, not physical helper/circuit/host time charges.

Await entry costs one logical unit; a denied meter charge does not increment used.

### Proposed plan arithmetic and invocation formulas

The formulas, segment boundaries, prefix sums, cap interactions and attempted/committed rules in this subsection are Rev3 whole-contract proposal text. They are source-derived and still require correction-review/Root adoption; the narrow record f510ad29795acd8570d82918ef56f54ada4e3cb37f83947f967de6a5a2825d5d did not adopt these formulas or cap rules. Only its exact weights and listed cache/evaluation/charging semantics are separately adopted.

For successful admitted statement s with expression root r, let R(r) be the set of ExprIds reachable by following child-ID links, counting a shared ID once. Root is guard for Await, value for Let/Next/Emit, predicate for Requires/Ensures and amount for Transfer/Fee/Liability/Discharge. Its successful cost is `1 + |R(r)|`. Reaching an Await at segment exit costs only1; its guard's dispatch and nodes belong to that Await's resume segment.

For n Await sites, there are n+1 segment costs, indexed0 through n. Segment0 spans statement0 up to, excluding, the first Await and then adds that Await entry1, if any. Segment j>0 begins at site j's Await ordinal, includes that Await's dispatch/guard plus following ordinary statements up to, excluding, the next Await, and adds the next Await entry1 if any. The final segment ends at the full statement count. Empty start before an initial Await is permitted. Define committed_before[j] as the sum of segment_cost[k] for k<j, including committed_before[0]=0; plan_total is the sum of all segment costs. Arithmetic is checked UInt128; no modular wrap or saturating plan totals.

The meter records attempted work for the current invocation. After successful complete segment evaluation and the existing static-work/exit/publication checks, committed equals committed_before[entry]+segment_cost[entry]. False guard attempted work is exactly `1 + |R(guard)|`, where R is the same distinct reachable ExprId set defined above; committed and the entire input continuation remain unchanged. Failed operations count only charges already admitted before failure; a denied meter charge does not increment used. An admission rejection before evaluation attempts zero work. Existing start/resume cap and emit_checked premises remain required and unchanged; this document does not derive their success from a caller-supplied counter, bypass admission or equate a static plan with actual runtime evidence. No numeric B17 case cost or cap-success cell is supplied here.

## Owning publication envelope and field correspondence (G4)

`start_observed` and `resume_observed` retain the program, exact captured call arguments and raw result of one corresponding existing stage call. Calling observation/publication performs no new stage evaluation. An external diagnostic projection alone does not establish the same-call relation. Root must preserve that owning origin and the raw observation bytes/call inputs in any actual capture; this document creates no new provenance validator.

Every publication has exactly `qualification:"local-reference-stage"`, `authentication:"none"`, `consumption:"untracked"`, financial_observation:InvocationObservation and await_prefix:AwaitPrefixObservation, plus the appropriate variant-specific top-level fields below:

- Waiting: status=`"waiting"`, advanced:Bool, segment:StageSegment?, continuation:Continuation, attempted:UInt, committed:UInt, residual:Liability[]. committed is continuation.logical.committed.
- Complete: status=`"complete"`, segment:StageSegment, attempted:UInt, committed:UInt, residual:Liability[]. No top-level advanced or continuation member.
- Rejected: status=`"rejected"`, error:Error, attempted:UInt, committed:UInt. No top-level segment, continuation, advanced or residual member. A captured Resume input continuation remains input evidence, never a returned rollback continuation.

InvocationObservation keeps its complete program context, exact captured input, full raw Result, outcome, accounting and tentative_publication. FinancialObservation is the matching Waiting/Complete projection of the same returned fields; rejected raw Err becomes FinancialObservation.Rejected with its error/attempted/committed. It drops no fields belonging to those declared projections.

For Waiting, await_prefix is `{Waiting:{advanced,action,site,captures,logical,committed_boundary,residual,published_segment,attempted}}`. action/site/captures/logical/committed_boundary are exactly the returned continuation's action/site/captures/logical/boundary; residual, attempted and advanced are the returned result's corresponding fields; published_segment is the returned optional segment with the full SegmentObservation fields. Complete maps to the string `"Complete"`; rejection maps to `"RejectedNoReturnedCheckpoint"`. Neither gains a synthetic pending checkpoint.

When the result publishes a segment, accounting is `{PublishedSegment:{effects:thatSegment.execution.effects,accounts:AccountFlow[]}}` and tentative_publication is `"PublishedSuccessfulSegment"`. Waiting with no segment uses `"NoPublishedSegment"` and `"NoAdvancedSegment"`. Rejection uses `"RejectedNoPublishedDelta"` and `"UnavailableFromStageRejection"`. This is per-published-segment accounting, not cumulative history. For each Transfer/Fee effect in order, encounter the debit account before the credit account, creating an account row at first encounter of exact (asset,account). Transfer and fee amounts accumulate separately and in gross exactly once, retaining gross debit even for self/reverse flows. Exact sums that exceed UInt128 become `"AboveU128"`; representable sums use `{Exact:UInt}`. Net is Balanced when exact receipts equal exact debit, Inflow/Outflow of their positive difference otherwise, or Unavailable if a required gross total is AboveU128. Nonmonetary effects create no account row; complete effects and snapshots still retain them.

Residual is every positive post-boundary liability in boundary order. It does not include zero rows, although complete boundary/snapshot rows do. False Waiting has no published segment, retains its exact input continuation and separates attempted work from committed work. This source profile provides no new authenticated event provenance, continuation consumption, financial oracle, global ledger rollback, fees or settlement claim.
