## Explanation

ScalarEntry installs a Scalar helper from the current `Return` control and top frame. The five sites cover eleven shapes: RightF Add/Sub/Mul/Lt/Cons/Branch; UnaryF Leaf/Not; IfF TestBool; ReturnF TestType; and unchecked ConstructorFieldsF TestType. Eq uses Equal, and checked ConstructorFieldsF uses Append. Exact Const/Data reference identity and expected TypeId are copied, including builtin IDs 0–3 and nominal IDs from 4.

Applied entry charges remaining/consumed/helper work by one, adds zero helper visits, and preserves the reference cursor and unaffected state. At the original separately retained admission helper-work maximum, P3 installs no helper and charges nothing; only the HelperWork exhaustion outcome changes. Fuel exhaustion is a different administrative path.

The consumer offers an independent host-pair route and a public owner-record route. Host-pair encoding does not regenerate post-state or filter an encodable wrong post by running owner semantics. Owner-record validation checks internal event/snapshot consistency; publicly constructible records are not authenticated provenance. The wrapper takes one real owner step before it can refuse and promises no rollback.

Both LocalPublic and LedgerCall builders use the emitted instructions and supplied constrained post-state lanes. Derived emitter receipts remain ungated and are not used as post-state truth. LedgerCall checks use the current statement and current post-state communications commitment. The API does not authenticate a pinned circuit or establish full retained-family equality merely from matching geometry. The physical root does not cryptographically bind host `run_id` metadata.
