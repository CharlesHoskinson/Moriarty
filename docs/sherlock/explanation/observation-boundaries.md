# About machine work and observation boundaries

Draft, 2026-10-17. Final03 retains planned profile adapters; current A host behavior and the scoped stream result remain separately evidenced.

A computation has several useful clocks. Semantic fuel limits machine work. An observer budget limits how many records a caller receives. A helper schedule exposes smaller pieces of work that an abstract rule may hide. Treating these as the same clock changes what an exhaustion result means.

In `sherlock-k-a/1`, a charged event consumes one unit of semantic fuel. Empty-frame Return publishes Done through A80 at zero charge; immediate Error publishes rejection through A82 at zero charge. Those publications precede exhaustion. Other pending controls with zero fuel publish A84. A frame-cap failing push with available fuel is a charged event to Error4, followed by free rejection publication. A published terminal state has no next semantic event. Thus a free publication still matters to the observable sequence even though it adds no charged work.

`Machine::visit_steps` adds a host observation boundary. Budget zero returns Budget without a callback or advance, including on a terminal machine. After an event, terminal publication takes precedence over the observer's break request, which takes precedence over budget exhaustion. Free publication occupies one observation slot. Calling again continues the same machine and does not refill semantic fuel. The implementation retains no record history; a callback may retain records itself, so the API alone implies no end-to-end memory improvement. The later `stream-actual-01` receipt records an actual Rust 1.99.0 producer/test build, eight passing visit_steps tests and an N01–N08/216-run complete diagnostic comparison to frozen independent expectations. Its observer deliberately retains records; no memory bound or allocation improvement was measured.

A's lookup, equality, allocation and other host helpers remain unmetered by its semantic clock. The separate `sherlock-helper-microstep/1` B profile exposes owner-controlled helper work, including cursor/pending-result state. Final03 specifies a planned observation map relating a completed helper interval to an A event on an explicitly declared common domain, and an unfinished interval to its saved A origin. Its conditional relation `W_B = W_A + H_B` requires its common-domain and no-capacity-failure premises; it implies no equal-fuel result. B event aggregates alone are not complete before/after state comparisons.

Frozen `sherlock-quint-a/1` has its own charged terminal-return convention. The generic K-A Quint counterpart instead names `sherlock-k-a/1`. Neither raw step numbers nor terminal stutters should be copied across these profiles. Quint terminal stutters are model states, not extra StepRecords or extra machine work. Adapters must also account for numeric bounds, frame direction, control/outcome tags and missing fields. The current host Snapshot stores frames top-first; final03's planned common ReferenceState is not an existing shared ABI.
