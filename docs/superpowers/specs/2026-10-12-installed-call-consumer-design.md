# Source-derived installed local call consumer

Status: concrete source implementation design for independent decision. Native execution is not authorized by this document. Base is PR32 merge `b5b47acb51315dba89d8df85599226077b23f5d7`, tree `818f7663603bdc1645ce5b51f4173fa6aacd17f9`.

## Product outcome

Implement `keygen-call`, `prove-call` and `verify-call` as actual consumers of the existing source-static compiler and SDK call adapter. A developer supplies original source, explicit local seed/deployment/request/ledger parameters, offline standard prover parameters and objective work bounds. Key generation creates the complete source action map and a separately labeled installed local snapshot. Proving reopens the exported keyset through source-derived regeneration and consumes the actual raw intent. A cold verifier regenerates public keys without PK files, independently prepares the expected statement, and verifies the returned V3 call with the actual stored operation and ledger Real verifier.

Moriarty is the only implementation target. All U0–U7/M1–M17 remain active. This is a local unsigned installed-call capability, not authentic chain installation, signatures, nonce consumption, DUST payment, ledger application, settlement, recursive history or target qualification. Native APIs are authored and compiled first. Native results require separate current resource admission and actual evidence.

Independent expectations: `next-installed-consumer-expectations-01.md`, SHA256 `c52e7128771435df825f6b8bbfea55f6f8ccc0ef29e56cbc5603c4b382f1c9bf`; source manifest SHA256 `0577f9655fb34a250ca4bc89f4940892ce33cb7c1b74e2ee0fc7d1150bcfbb01`, retained in the source-proving runtime. These are an oracle/proposal, not approval. Both literal two-action programs and the exact full effects specified there are acceptance inputs.

## Alternatives and selected trust contract

1. Selected: source recompile and pinned-parameter key regeneration on reopen. Keep all derived constructors private. Compare exported opaque native keys against freshly generated keys before decoding or using attacker key bytes. This costs additional native derivations but does not need a new trust service.
2. A signed key manifest would need independently authenticated signing authority and source/key derivation evidence. No such public trust anchor exists here; introducing one would add a separate product policy.
3. Candidate-supplied expected hashes or self-consistent source/IR/VK manifests cannot establish source-to-key correspondence. Reject that importer.

The selected contract relies on the pinned SDK standard SRS digests and setup, exact bounded decoder, correct deterministic key derivation, compiler correctness and compatibility with the embedded ledger verifier. These remain explicit premises until qualified. Actual same-build canonical PK/VK reproducibility is unrun: an exact regeneration mismatch refuses, rather than silently trusting an imported key.

## Static source and profile boundary

Introduce a private validated static-binding view shared by the existing source compiler and the new local consumer. It binds source/parsed Program, semantic version, ABI/templates, toolchain, roles, assets, duties, payer and local domain. Request values, predecessor, gas and results never choose the circuit. Reuse the existing compiler and full ABI validation; do not introduce a second source parser/compiler.

The old `moriarty-ledger-call-preparation/1` schema, wrappers and installed VK/IR refusal remain. New installed input has profile `moriarty-ledger-installed-local/1`, qualification `local-source-derived-installed-unqualified`, `local-unqualified` Anchor and guaranteed-only phase policy. Public installed DTOs use strict schema/duplicate-field rejection. A serialized new profile cannot enter legacy APIs as an unproven descriptor. Shared internals receive an explicit admitted operation policy; no public Boolean, attacker map, unchecked conversion or expected-hash field disables key admission.

A private `DerivedLocalDeployment` owns every declared action's source artifact/public VK and selected-action full proving material. A private `PublicLocalDeployment` contains only all-action public artifacts, VKs and parameter/build identities. Neither has Deserialize/From/imported-map constructors. Native derivation from original source and pinned parameters is their construction route. Immutable borrows/clones share snapshots; files are not reread by resolver lookups or provider splits. Every action is compiled and admitted, even when not selected.

Each actual operation equals the independently derived `ContractOperation::new(Some(current VK), Some(exact tagged IR))`. The actual operation names equal the source names, with no absent/extra/duplicate action, missing IR/VK, mixed legacy/current key or substituted unused action. The selected operation is retained from the admitted predecessor, rather than selected by the proof bundle. Source-to-VK provenance is regeneration; a local state hash does not authenticate chain state.

## Installed snapshot construction and preparation

`keygen-call` starts from an explicitly supplied keyless local seed admitted against the complete original source/ABI/native frame and ledger parameters. Replacing only its operations with the private complete source-derived map creates a cloned local snapshot. Recompute complete state, operation and descriptor commitments from the actual new bytes. Preserve data, maintenance authority, contract balances, UTXOs, all extensions, bookkeeping and ledger parameters. Check NIGHT supply and existing bounds. Refuse a seed with any installed key/IR before replacement. This operation writes a local artifact and invokes no ledger apply or funding.

Existing seed duties or noninitial source state are supplied local snapshot premises; never relabel them constrained genesis or history evidence. Initial-genesis construction is outside this slice. Seed admission must not require a successful selected transition: invalid current action inputs must not prevent static key generation, and key generation must not invent a valid request to execute.

Installed preparation uses the same complete predecessor/frame/state/duty/role/UTXO/context validation, lowering, offer assembly, actual VM/partition checks and raw intent owner. Its additional admission requires the complete actual operation map to match the regenerated private public capability. Current state/effects/events/gas/public-input checks remain. The raw intent is expanded exactly once by SDK Intent::prove; processed calls remain inspection projections. Retain the actual admitted selected operation privately with the prepared owner.

Proving and verification delegate to the current source adapter after complete installed admission. Require current proof V3, exact whole final intent including parent randomness/offers/TTL/action order, full processed state/effects/events/gas, final SDK public inputs and final-intent-derived prospective UTXO IDs. `ProofMarker` and `ProofVerificationMode::Real` remain mandatory. Explicit dependency `proof-verifying` must remain enabled with no default features. Preimage/erased markers or mock mode cannot return verification success.

## Offline parameters, keysets and cold import

Reuse the existing `mori-backend/src/parameters.rs` pinned SDK04c9c5d standard SRS table and immutable bounded-snapshot recipe in a narrow ledger-owned module. Do not create a dependency on the alternate TransitionClaim proving path. Use an explicit directory and degree, nonblocking open followed by opened-descriptor regular-file validation, bounded bytes, pinned expected SHA256, degree header before unchecked decode, and exact EOF. No ambient cache/environment provider or on-demand network fallback. Preserve the existing pinned table and its supported degree range; a missing degree refuses. Do not silently expand that range or any legacy decoder envelope.

Strict `NativeWorkLimits` data is caller-supplied and versioned. It requires nonzero degree/SRS/key/aggregate-artifact/action/input limits with checked conversions and sums. Degree and action bounds apply before corresponding derivations; serialization/snapshot bounds are enforced while writing/reading. Native memory/time/thread budgets are separately admitted process limits, not a claim made by these byte bounds. There are no invented resource defaults or maintainer receipts in public CLI inputs.

Compile all action artifacts before parameter/key work. Determine and check each actual action degree; native k/model is itself budgeted work. Reuse exact immutable snapshots for equal degrees. No larger-degree substitution. Generate public keys for all actions, and full PK/VK for the selected action. Export opaque PK separately. PK is public cryptographic material here, not witness or wallet secrets.

Cold proving validates source/static/IR/manifest/profile/build/parameter metadata first, regenerates the complete public map and selected full pair, compares exported opaque PK/VK bytes exactly, and uses regenerated material. Untrusted PK/VK bytes must not be decoded before this comparison. Cold verification regenerates all public VKs only through keygen_vk; it neither reads PK files nor contacts a proving service. It may read pinned public SRS for derivation. Final crypto verification uses ledger embedded verifier parameters. A PK-free/SRS-free trusted import optimization is outside this design.

Candidate proof bytes do not select independently supplied source, static binding, key policy, request or predecessor. Import uses bounded canonical typed intent decoding, exact tag/version/EOF/roundtrip and full statement comparison. Weak-key rejection after cold native regeneration occurs before proving or verification under the attacker key; it cannot be promised before all native work.

## Public command contract

Use existing public seed descriptor fields to supply source/static bindings; avoid redundant independently selectable binding files. Installed descriptor carries the derived static identities and full local snapshot commitments. The source file remains independently supplied on every command.

- `mori keygen-call SOURCE --seed-deployment D --seed-state S --parameters L --action A --params-dir P --work-limits W --out K`: validate source/complete keyless seed without executing an action; derive all public keys and selected full pair; create installed local snapshot and write complete keyset.
- `mori prove-call SOURCE --deployment D2 --predecessor S2 --parameters L --request Q --action A --keyset K --params-dir P --work-limits W --out PROVEN`: cold regenerate the keyset, admit full installed map and independently prepare raw call, invoke real SDK adapter, write actual final intent and complete verification/readback artifacts.
- `mori verify-call SOURCE --deployment D2 --predecessor S2 --parameters L --request Q --action A --public-keyset K --proof PROVEN --params-dir P --work-limits W`: regenerate public map, independently prepare expected call, strictly import final typed intent and use actual stored operation/Real verifier. Work when all PK and prover-cache files are absent.

Missing inputs and unsupported modes reject. No fallback to `mori prove`/`verify` TransitionClaim statements. Old compile-call/prepare-call behavior remains. Installed preparation is a library consumer of a derived public capability; do not add a success stub permitting plain JSON key policy.

Artifacts bind source/program/static ABI/template/compiler/build/features/toolchain, per-action IR/VK/degree/standard parameter identity, complete map, actual native snapshot/parameters/request and final result identities. Use ordinal action leaf names, never raw names as paths. Independently bound individual/aggregate reads before initialization. Public-key imports do not read optional PK leaves. One file snapshot per command; no TOCTOU key rereads. New profile/envelope has its own explicit caller bounds, without globally enlarging ordinary 1MiB inputs or 16MiB outputs. Publishing is create-new and final marker last; collision/symlink/partial failure preserves existing files and never reports native success. `keygen-call` may return a derivation marker only after real key derivation; proving success requires actual proof and Real verification.

## Independent checks and complete effects

Use the independently authored two-action MeteredRemittance and ToggleCounter programs, exact bytes and literal outcomes in the oracle. Metered A1/A2 preserve the same settle source/key/full settle+freeze map: running11/charge4/balances84,19,3 and running34/charge9/balances92,11,3 respectively; eight ordered effects each. Toggle B1/B2 preserve the same step key/full step+reset map: count32/activefalse and count256/activefalse, four ordered effects and empty offers. Exercise the unused freeze/reset actions too. Repeated transfer outputs aggregate correctly; final IDs use final intent hash. Tests compare every typed state/balance/duty/effect/frame field.

Ordinary source checks cover strict input/profile/schema/work bounds; two programs and source-static reuse; all-action source map; unsupported names/paths; early source/IR/manifest/build/parameter-profile mismatches; keyless seed refusal; exact installed map helper comparisons; raw-versus-processed/envelope/gas/PI checks; publication and legacy compatibility. Test module-private opaque key bytes only as parsing/lookup comparisons, never mint a fake public derivation capability or proof-success result. Compile native consumer signatures without invoking them. Extend existing Quint QA for whole-map and cold-import purpose separation under explicit external crypto/derivation premises, with positive/negative witnesses and implementation links.

Later independently admitted native controls require full positive exported/reopened artifacts; same-key A1/A2 and B1/B2 calls; PK-free cold verification; weak-key/trivial-proof substitution; changed unused-action VK/IR; corrupt/swapped PK; wrong SRS/degree; proof-byte/version corruption; unchanged-proof PI/binding/event/gas/claim changes through the actual crypto verifier; concrete hostile-witness controls; feature-disabled/mock refusal. Ordinary preprocessor/equality rejection cannot establish a native constraint/crypto failure. Deterministic export regeneration and embedded-verifier compatibility require actual positives. Native process cost includes every all-action model/VK/key derivation and every cold repetition.
