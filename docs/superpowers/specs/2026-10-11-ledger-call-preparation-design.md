## Approaches and selection

1. **Moriarty-owned direct pinned native caller, selected.** Keep Core validation/evaluation; introduce a small `mori-ledger` crate for typed native layout, actual `Op` lowering, native unsigned offers, VM/transcript execution and full comparison. This avoids consuming mutable unpublished MinoCrab workspace paths. It produces a usable vertical preparation caller, with explicit absent proof correspondence.
2. **Portable frozen MinoCrab helper import.** Its real op encodings and kernel patterns are useful reference material. Its internal ledger tier is unstable, and publisher `call_prototype` is Signet log-only with `operation(None)`. Wholesale adoption adds unrelated publishing/signature conventions. A later reviewed immutable licensed import may reduce circuit-wire work; it is unnecessary for this bounded caller.
3. **Target descriptor or local scalar-proof wrapper.** Cheap but cannot execute financial VM effects or form actual native transcripts. Rejected: today's scalar `Impact` public slots and local ProofPreimage are not ledger op encodings.

Selected custody boundary: **one public user payer, native unshielded tokens, one contract call, one guaranteed financial phase**, with no mint/burn, contract-funded payment, shielded/private flow, sponsorship or asynchronous call. Multiple assets and recipients are admitted within existing Core bounds; every debit in every source action must use the same payer role. Native offer construction and recipient claims are integral, not storage-only balance changes. Wider custody requires its own specified relation and caller.

## Source-wide admission and typed state

Run public `mori_core::parse` and `mori_core::validate`, then inspect **all declarations, expressions and actions**, not just the selected action. Admit current UInt/Bool literals/names, checked Add/Sub/Mul, comparisons, Bool And/Or/Not and all current Let/Requires/Ensures/Next/Emit/Transfer/Fee/Liability/Discharge forms. Arithmetic is checked UInt128; multiplication is Core host arithmetic for preparation, not a nonexistent VM multiply opcode. Unsupported grammar/semantics reject before execution. Program names/hashes never select fixture-specific ops or values.

Extract all source asset identities and role strings from all Transfer/Fee/Liability statements, plus trusted duty bindings needed by Discharge and inherited duties. Admit one declared debit payer across every action; the same payer role may also be a recipient, including an application Fee recipient. Different source roles cannot map to the same native user key/address. Repeated uses of one recipient role, including Transfer and Fee to that role and payments to the payer role itself, are supported and aggregated for custody. Distinct-role alias collision, contract recipient/payer, a second payer, mint/burn, private state/inputs, cross-contract calls and charged/fallible financial policy reject as unsupported. Unused/unselected declarations must satisfy the same profile. A source state named like another category remains separated by typed key namespace.

Native ABI key hashes use exact domain byte strings `moriarty-ledger-public-abi/1:state`, `moriarty-ledger-public-abi/1:duty`, `moriarty-ledger-public-abi/1:asset`, `moriarty-ledger-public-abi/1:role`. Hash SHA256 of `u32le(domain.len)||domain||u32le(part_count)||each(u32le(part.len)||part)`; each part is exact UTF8 or native canonical tagged bytes, with scale as one u8 byte. State/duty use one name part; asset uses network/issuer/reference/scale parts; role uses role label/native tagged public key/derived tagged UserAddress parts. ABI records these domains/framing and independent byte vectors before implementation artifact freeze. Event payload uses the same length framing with domain `moriarty-ledger-public-abi/1:event`, name, action and canonical tagged native AlignedValue carrying the UInt128/Bool alignment and value. These are versioned ABI bytes, no implicit serde/display hash.

Native root layout is Array `[states_map, duties_map, extensions_map]`. States use exactly declared names, each key domain-separated SHA256 of length-framed UTF8 name; values are FAB Cell(UInt128 or Bool) using native conversions. Duties use name keys in a distinct hash domain, and Cell concatenation `(asset_digest32, debtor_role_digest32, creditor_role_digest32, amount_u128)`. Metadata maps name/role/asset digests back to complete trusted identities; reject collisions, missing metadata, duplicate names, malformed Bool, wrong alignments and unknown duty identities. The extensions map is opaque, public, preserved unchanged. Root shape is fixed; undeclared state cells reject. Preserving all declared untouched fields and all extension bytes is mandatory.

Asset digest is SHA256 over domain-separated length-framed canonical complete `(network,issuer,reference,scale)`; role digest similarly covers exact role label plus native public key/address identity. `states_map` is initialized only by a separately supplied public predecessor, never source defaults at call time. Source initializers describe layout/genesis intent; they cannot overwrite an actual supplied successor.

Duties present in native predecessor are decoded in full, including zero amounts. Existing Core forbids undeclared assets in Scenario balances/duties: project only source-declared AssetIds into Core; preserve separately typed trusted other-asset duties and UTXOs outside that projection, unchanged. A source Discharge cannot touch a duty whose AssetId is absent from source declarations. Do not augment Program behind its source/Core hash, silently omit such native duties from full readback or mutate their identity. Unknown/unbound metadata still rejects. Absence and present-zero differ. Liability creates/updates the named typed entry according to Core semantics; Discharge writes its reduced amount, retaining the entry at zero. Reserve/zero/unmentioned entries survive. No duty removal opcode is emitted. Complete metadata equality and membership are checked, not totals only. Bound inherited duties/roles/assets and their traversal by existing Core trace/declaration capacity; no implicit open-world identity creation.

Native user balances are derived by checked summing **all** predecessor UTXOs for each trusted role and complete mapped token identity. No storage balance cell is added. Preserve every unselected UTXO and metadata, unknown account, other asset, native contract balance, ledger pool, zswap, DUST, replay and other-contract component. The command never treats Scenario balances or an expected final projection as ledger authority.

1. Strictly admit source/deployment/parameters/predecessor/request; verify hashes and full native state identities; run native supply invariant. Decode a full Core Scenario from native state/duties/UTXOs plus selected action inputs.
2. Verify raw source SHA256 separately from canonical Core hash. Run the existing Core transition to compute checked ordered semantic effects and admission economics. Failed requires, arithmetic or late ensures publish no success artifact. This is a host semantic refusal, not an adversarial proof rejection.
3. Begin every action op stream with the bounded native ABI guard `Dup { n: 0 }; Size; Popeq { cached: false, result: AlignedValue::from(3u64) }`. It reads the fixed root Array3 length and consumes only the duplicate-derived Size cell, leaving `[context,effects,strong-state]` unchanged. Label all three ops ABI-guard metadata, no source financial effect; future relation binds the constant3. Layout admission separately requires Array/map types: Size alone does not distinguish an Array3 from a Map3. This nonempty guard enables genuine zero-only/empty-offer actions with no state or event statements to yield an actual guaranteed transcript, subject to native budget. Build subsequent native Ops from actual declarations and each ordered effect. Read every source-referenced state/duty value through Dup/Idx/Popeq with exact FAB values at that statement prefix, including earlier Next/Liability/Discharge updates; never reuse obsolete opening values; check duty membership separately. Next uses native nested Idx-with-path, Push(storage=true), Ins to update the states map. Liability/Discharge similarly write duties. Op::Popeq read mismatches are actual VM refusal. Emit pushes native MIP-0002 Array `[Cell(u32 version=1),Cell(u8 LogEventType::Misc),Cell(payload)]`, then Op::Log. Payload is length-framed event namespace/name, selected action identity and typed UInt/Bool value, bound to the public ABI; exact event identity/order is checked.

   For each positive effect in source order, host prefix state supplies expected prior membership, old aggregate (zero if absent), amount and checked new aggregate. Starting `[C,E,S]` (top right), the exact native sequence is:

   Idx{cached:false,push_path:true,path:[key8]}     [C,S,E,key8,M]
   Dup{n:0}; Push{storage:false,value:Cell(K)}
   Member; Popeq{cached:false,result:present_bool} [C,S,E,key8,M]
   if expected present:
       Dup{n:0}
       Idx{cached:false,push_path:false,path:[K]}
       Popeq{cached:false,result:old_u128}          [C,S,E,key8,M]
   Push{storage:false,value:Cell(K)}
   Push{storage:false,value:Cell(new_u128)}
   Ins{cached:false,n:2}                           [C,S,E_new]
   Swap{n:0}                                      [C,E_new,S]
