# Candidate A: literal per-case wrappers for the complete A4 export

Status: S2, specified-only. This design proposes a small source transformation for the actual78-case export route. No generator, model, exporter, recorder or runtime has been changed or executed during authoring. Implementation must wait until root confirms completion of the retained256 after snapshot: its original1090-file input closure includes the sources this proposal changes.

## Decision and evidence

**Recommendation.** Generate each existing `candidate_a_integrated_case_NNN.qnt` wrapper with its exact case record as `CASE_A4`, and remove only its `candidate_a_integrated_cases` import. Keep the canonical two-table inventory, all78 wrapper/module identities, the global ordinals, the complete driver and the semantic modules unchanged. Use the existing recorder's `--stage` option with fresh `literal-v1-case-NNN-export` names. Update the exporter's two exact stage-name expectations to match; introduce no recorder option, generic scheduler, runtime pruning or diagnostic-only source variant.

**Source facts.** The independent investigation [inventory/import closure](../../../.superpowers/sdd/a4-case014-inventory-closure-source-investigation-20260906.md), SHA256 `e650b8b4ed40350cc2a9d844d98a8e68a56704828e3812665be4581834f035cf`, identifies whole-module parsing, name resolution and type analysis, followed by a whole resolver-table run payload. `case_wrapper` currently selects one fixed in-bounds element from the complete installment or swap table. `quint_case(desc, steps)` already renders that exact record. The run path has no public full-flattener stage to disable.

**Repository observation.** Our source-only check `bc0e59/0` found all78 current native import graphs contain20 files, including the canonical cases module and exactly one wrapper. Removing that import gives19 files in each graph by source traversal. The driver and canonical table have the same eighteen direct semantic imports in the same order. The canonical table contains78 record literals and only two local value declarations. This is a source-graph observation, not a measured runtime improvement.

**Experiment status.** Root reported the closed run-phase diagnostic with Node signal6, recorder/outer134 and heap OOM, after load, parse and typecheck resolved Right and `runSimulator` was entered without a completion event. Independent preservation review was pending when this design was written. That observation supersedes earlier live progress; it does not identify the failing allocation. The source-supported hypothesis is that removing unused inventory can reduce both type analysis and whole-table serialization work. Remaining semantic definitions may still dominate; no success or causal claim is made here.

Alternatives considered:

| Approach | Tradeoff and disposition |
| --- | --- |
| Exact literal in each existing wrapper | Recommended: one generator transformation, unchanged semantics/interfaces except fresh receipt paths, directly usable for all78 native outputs. |
| Import a selected case name from the same inventory module | Still loads and analyzes the complete module; insufficient for the observed source-level workload. |
| Prune the runtime resolver table or split the shared semantic modules by lifecycle | Requires a larger reachability/type/runtime argument. Defer unless the literal route fails; do not combine transformations in this epoch. |

## Exact transformation and preservation obligations

Let `rows = list(instructions())`. For every integer `i` in0..77, `case_wrapper(i)` selects `(descriptor, steps) = rows[i]`, requires correspondence with `inventory()['cases'][i]`, and substitutes `quint_case(descriptor, steps)` for the driver's one `const CASE_A4: A4Case` declaration. It keeps the explicit annotation `pure val CASE_A4: A4Case`, substitutes the same integer `i` for the one `CASE_INDEX_A4` constant, and uses the same module name `candidate_a_integrated_case_%03d`. It does not add the old cases-table import. Boolean, negative, out-of-range and noninteger indices still fail.

`instructions`, `inventory`, `quint_case`, scenario/selector lowering and `quint_cases` remain unchanged. The canonical `candidate_a_integrated_cases.qnt` remains byte-identical at SHA256 `f42eedc0b0a092704c6760943e4d37242453dedcf548696639f22c1897ef7518`. Its32 installment cases/638 events and46 swap cases/919 events remain in the original order, totaling78 descriptors and1557 events. No locally renumbered swap index is used in the driver: case032 still writes32. Paired signing profiles, control mutations, step order and case-start/end events remain unchanged.

The driver remains byte-identical at SHA256 `dc2fa2c7a6bdad1912583a6470b71b69091a3867f668072d86bbc86e472c251a`. This includes all eighteen import lines and their order; `authorityState`, `latestEvent`, `caseIndex`, `cursor`; `init`; every diagnostic/ordinary/end/disabled branch in `step`; calls to `initialA4`, `startA4`, `observeA4`, `applyA4`, `endA4`; and `noDiagnosticA4`, `sourceInvariantA4`, `completeA4`. Both lifecycle implementations, safety predicates, authority checks and Core sources retain their existing pins.

**Semantics argument to discharge.** A fixed in-bounds projection of a pure literal list equals the selected literal, provided its names resolve to the same definitions and its type is unchanged. Under that condition, initialization writes identical four-variable states. Assuming equal states at a step, the unchanged driver takes the same branch and evaluates the same semantic functions on the same case and cursor, giving equal successor states and events. This preserves terminal disabling and invariants as well as ordinary actions. It is an explicit preservation obligation supported by finite source/type checks and full native replay, not a mechanized equivalence theorem or an assumption that successful parsing alone proves equivalence.

## Import and type identity

Removing a wildcard import must not silently change a surviving identifier. The pinned `names/collector.js` and `names/base.js` implement hidden imports and same-definition/conflict handling. Imports are not generally transitive; `copyNames` has an exception for constants. Source inspection found no `const` or `export` declarations in the eighteen semantic modules, and the canonical cases module defines neither types nor constructors nor exports. Its two table names are the only intended newly inaccessible names. The replacement literals use the unchanged direct semantic imports.

The implementation review must account for every nonbuiltin name in all78 moved records and the unchanged driver, including these dependencies:

| Definitions | Unchanged defining source |
| --- | --- |
| `A4Case`, `A4Step`, `A4Instruction`, evidence-mode and instruction constructors | `candidate_a_integrated_lowering.qnt` |
| `A4CaseDescriptor`, `A4Scenario`, scenario injection constructors, derivation tags and `A4Event` | `candidate_a_integrated_observer.qnt` |
| `ScenarioI`, recovery modes and installment constructors; `CommandI` | Installment fixtures and lifecycle modules |
| `ScenarioS`, disposition modes and swap constructors; `CommandS` | Swap fixtures and lifecycle modules |
| `SigningProfile`, `Principal`, `AttemptId`, `ATime` and their constructors | Policies, effects, execution and Candidate A types |
| `AAuthorityExecution` and its generic alias dependencies | Authority adapter and unchanged imported type definitions |

The equality check must compare definition identity by defining file hash, module, declaration name/kind and normalized declaration structure, rather than raw parser IDs, which can change with source traversal. Compare every moved literal reference against its reference in the pinned canonical table; compare retained driver references against the pinned original driver. Preserve all type arguments, constructor tags, record fields and ordered lists. Only parser IDs/source-location metadata and consistent bound-variable renaming may be normalized. Do not normalize actual names, field labels, constructor identities, operator bodies or import order. Missing, ambiguous, unexpectedly shadowed or differently typed names stop this transformation. Do not patch aliases, delete semantic imports or qualify names ad hoc to make this candidate pass; any such change needs its own source review.

1. **Source review and finite validation.** After root releases the retained256 freeze, implement only the generator/wrappers, fixed exporter stage prefix and meaningful test changes above. 2. **Canonical qualifying pilots, then the finite remainder.** Use fresh stages for cases014 and044, sequentially, with their exact new canonical exporter commands and unchanged admitted native resource envelope/RH002 ownership. Validate each original terminal/cleanup, source/runtime receipt, complete ITF/event sequence and independent shard replay. Then run the remaining76 once each, sequentially under the same frozen source/runtime epoch and command rule. Stop at the first nonqualifying outcome; no retry, case omission, heap escalation or claim of partial all78 acceptance. Keep successful inputs so completing the batch does not repeat the two pilots.
3. **Complete package acceptance.** Once all78 qualifying native outputs exist, use the existing stage-cases then seal-manifest export path with fresh parser receipt directories and the unchanged independent package checker. Require exactly78 ordered descriptors,1557 events, both lifecycle partitions, all input/case/receipt hashes, identical before/after source/runtime maps and actual outer terminals. Run the full required final Python controls against this source epoch, including the existing all-package control and all unchanged required node identities; report the exact new test count rather than silently reusing an old114/115 count. Nonauthor reviews the one final package. Completion means this complete finite-record agreement/authority export predicate; it does not establish model checking, cryptographic validity, solver acceptance, correspondence proof or H1.

A tiny parse/type control may support the first gate but cannot replace any canonical case. There is no additional full diagnostic series or generic evidence framework in this design. Preparation/dispatch/terminal/archive functions and actual incremental tool-response retention reuse the existing reviewed procedures. Failed native/group ownership or parser resource conditions remain hard failures with preserved originals; any later remedy is a separately reviewed change.
