## Result and boundary

Recommendation: extend the existing source-static ledger compiler with a distinct signed installed mode, fixed compiled signer policy, complete native state/duty openings, backend-only typed circuit arguments, and a constraint-only FENS verifier over the actual transition wires. A developer derives the complete signed action key map, prepares a canonical unsigned signing package from the actual native caller, signs its message externally, supplies the attachment to the same caller, proves the raw SDK intent once, and cold-verifies the complete final call with the actual independently derived operation. Every action, including state-only freeze/reset, requires authorization.

The claim is local signature possession under an immutable compiled JubJub policy for the supplied local call, plus actual financial cap constraints, subject to named SDK/compiler/hash premises. It is not authenticated account authority, chain installation, replay consumption, funding, time, settlement, recursive history or full M7/M8 acceptance. U0–U7/M1–M17 and broader MC/SPG remain open. Source implementation, ordinary checking, native proof feasibility, genuine proof results and financial ledger acceptance have separate evidence labels.

Use the existing Core parser, source validation, ledger lowering, preparation, artifact publication, source derivation and SDK adapter. Do not introduce a second financial compiler, eDSL, framework, campaign scheduler or mutable external build dependency. Preserve the adopted unsigned installed design and all its original profiles and refusal behavior.

## Alternatives

| Approach | Consequence | Decision |
| --- | --- | --- |
| Typed circuit arguments committed by the real call, constraint-only FENS, fixed compiled policy | Fits SDK `IrSource.inputs`, leaves private transcript empty, preserves one native operation per `Impact` group; R/s become part of the communications statement; requires explicit input ABI extension and additional real reads | Recommended |
| Typed `PrivateInput` transcript witnesses and separate public auth publication | Could retain an existential attachment contract, but currently both preparation and relation checking refuse the transcript; publication needs real ledger operations or a separate justified ABI, not invented auth groups | Reject for this slice |
| Standalone signed proof attached beside unsigned installed proof, or standalone `append` concatenation | Two valid independent statements do not establish authorization of one transition; standalone `11+4A` singleton `Impact` groups conflict with ledger activity/operation correspondence | Reject |

State-derived signer rotation is a later authority slice. It requires constrained reads of key/policy/nonce state and authenticated deployment/history. Its absence is not filled by caller `ExpectedAuthority` or a self-consistent manifest. Fixed policy provides a concrete local integration without asserting that unresolved mapping.

## Versioned contract and immutable policy

Define these new exact versions; no existing version is silently widened:

| Object | Version |

The signed mode preserves `moriarty/1` source grammar, bounded Core behavior and `moriarty-core/1` semantics. It adds a versioned compilation policy input, not a fixture-only source grammar. The policy contains profile, owner, beneficiary and a strict affine32LE JubJub public key. It is supplied independently at key generation and every reopen, included in the static compilation identity, and its two public key coordinates are immediate constants in every action IR. In this document **source-fixed** means fixed in the immutable source plus compilation-policy closure; the existing `.mori` text itself does not declare a JubJub key. The API and output must say this explicitly.

The new signed ABI describes the combined storage/argument/semantic-wire contract. Its underlying storage ABI remains exactly `moriarty-ledger-public-abi/1`: root slots0/1/2 and the existing `name_key`, `asset_digest`, `role_digest` and duty-cell recipes keep that domain. Do not substitute the new signed ABI label into those hashes or relabel an old storage cell under a new hash recipe. A signed descriptor carries separate `storage_abi` and `signed_abi` identities. Keyless seed admission validates the existing storage descriptor first, then constructs signed compilation bindings with economic_bounds absent and the independent fixed policy. It rejects any seed with economic_bounds=Some rather than silently altering its policy. Replacing operations preserves existing native data/frame bytes; all signed descriptor/ABI/key commitments are freshly derived. An unsigned installed descriptor is never converted into a signed capability.

A caller's policy file selects a new local compiled contract, never authority over an already authenticated deployment. Reopen checks that independently supplied original source/static bindings/policy produce the exact exported all-action map and installed operations. Candidate payload, attachment and proof cannot select or alter that independent policy. `ExpectedAuthority` from the standalone backend is neither imported nor treated as a constrained key. Changing policy/key changes IR and requires regenerated signed keys and a newly labeled local installed snapshot; signature-only policy rotation is refused.

Signed admission checks all actions before proportional allocations: valid labels (1..1024 UTF-8 bytes, no C0/C1), no asset aliases by full AssetId, at most 16 distinct declared assets and 16 registry duties, owner is the sole transfer/fee payer and sole registry debtor, and beneficiary/owner have exact admitted role identities. It checks every source liability/discharge and every immutable duty binding, including unused actions. Registry `D` is the complete frozen static duty list, keyed without collisions and deterministically ordered by name; it must include all source duty references. A preexisting bound duty need not be touched by the chosen action, but its asset must be declared, its debtor the owner, and its full identity included in signed context/caps. No unlisted native duty is permitted. Source-wide policy refusal never falls back to unsigned mode. Empty financial scope admits an empty complete cap list and still requires a signature.

Midnight native `SignatureVerifyingKey`/`UserAddress` bindings and public offer ECDSA funding authority remain separate from the JubJub policy. The compiler fixes their role mapping as local static data; a JubJub signature does not execute the offer signing closure, sign a native unshielded spend, prove control of its ECDSA key, fund DUST/NIGHT or establish deployed account authorization. Do not reuse those curve encodings or report the two authorities as equivalent.

## Acyclic identities, payload and message

Use Core canonical JSON and SHA256 for host object commitments, with strict unknown/duplicate decoded-field rejection and lowercase exact-length hashes. A digest becomes two UInt limbs: little-endian bytes0..15, then16..31. Host SHA256/JSON computations and static name/role/asset hashes are explicit reconstruction premises, not circuit preimage theorems.

The following order is mandatory:

1. Validate original source, fixed policy and static bindings; derive the complete source-wide state/duty/asset/effect descriptors and argument layout. Build signing context `C` below. Neither request nor predecessor values select layout or keys.
2. Compile each signed action with `SHA256(C)` limbs as constants, fixed signer coordinates, shared semantic-wire computation, caps and FENS. IR bytes/IR hash then exist without a payload or signature. Native degree/key derivation comes only under separate admission.
3. From supplied installed predecessor, request and native caller evaluation, reconstruct unsigned payload `P`, its canonical hash, and message `m`. Verify exported package equals this reconstruction before signing and again on attachment/proving/verification.
4. External signing produces R/s. Construct full typed call input and communications commitment. SDK proving may create final binding/parent PI; signature and proof are later values.

`C` is the canonical ordered array:

`[context_version, signed_profile, relation_version, abi_version, source_sha256, parsed_program_sha256, language, semantics, compiler_closure_sha256, pinned_toolchain, templates_sha256, fixed_policy, network, anchor, native_contract_address_hex, payer, canonical_roles, canonical_assets, canonical_duty_registry, selected_action_name, action_ordinal, ordered_argument_descriptors, ordered_semantic_wire_descriptors, native_group_template_descriptors]`.

`compiler_closure_sha256` covers the actual signed compiler/lowering/emitter/reference/codec/profile/public-consumer source closure, not generated IR/VK bytes. `native_group_template_descriptors` contain source-static opcode/layout/guard origin and replacement positions, with no request or runtime opening values. C excludes its own hash, actual IR hash, degree, SRS, keys, installed operation map hashes, predecessor/frame commitments, signature and proof. There is therefore no IR-hashes-context-hashes-IR cycle.

`P` is a strict canonical object with exactly: payload profile; installed profile/qualification; relation version and selected `ir_sha256`; ABI/context hash; source/program/semantics/compiler/toolchain identities; action/name/ordinal; fixed policy hash, owner/beneficiary/key; network/Anchor/address; complete canonical registry and asset identities; complete supplied predecessor scope/native-state hash and ledger-parameters hash; `request_sha256`; selected spends and TTL identity; nonce, not_before, not_after; complete ordered per-asset limits; complete semantic projection `V` and its hash; `signing_readback_sha256`. The request hash covers the unsigned signed-request object including action inputs, selected spends, segment, TTL, nonce, logical time/interval, block context and supplied communication/binding randomness; static gas/frame data is instead bound by the independently reconstructed signing readback. It excludes attachment, package, communications commitment and final proof. P's actual ledger/frame hashes are untrusted local snapshot identities until authenticated-state work establishes provenance. P has no VK/PK, keyset identity, final intent hash, final PI, R/s, signature hash, proof hash or self hash.

The signing readback is a dedicated projection, not a hash of the complete later prepared bundle. Its exact ordered fields are `[wire_projection_version, execution_pre, execution_post, ordered_effects, lowered_native_operations, actual_query_state, actual_query_effects, actual_query_events, measured_read_gas, declared_gas_cap, preserved_frame_commitments, prospective_balance_amounts, offer_spend_output_amounts_and_owners_without_output_ids]`. It excludes call/prototype input, communications commitment, parent binding, processed/final PI, authorization-check statuses, output IDs derived from an intent hash, signatures and proof. Every component exists after signature-free source/native evaluation. These exclusions prevent P from indirectly committing to the future R/s through a readback hash. Complete final readback, including excluded SDK fields, is checked separately after attachment and proving.

The payload's exact field names are `profile, installed_profile, qualification, relation, ir_sha256, storage_abi, signed_abi, context_sha256, source_sha256, program_sha256, semantics, compiler_sha256, toolchain, action, action_ordinal, signer_policy_sha256, owner, beneficiary, public_key_hex, network, anchor, address_hex, duties, assets, predecessor_sha256, native_state_hash_hex, parameters_sha256, request_sha256, selected_spends, ttl_hex, nonce, not_before, not_after, limits, wire_projection, wire_projection_sha256, signing_readback_sha256`. Scalar UInt values use Core's canonical decimal representation; typed wire projection records have exactly `position, descriptor, type, value` and must equal the source-derived descriptors in C. The package has exactly `profile, context, payload, payload_sha256, message_hex, signing_readback`; its message/hash fields are recomputed projections. The fixed-policy DTO fields are exactly `profile, owner, beneficiary, public_key_hex`. Unknown/duplicate/missing fields refuse on direct serde and bounded JSON entry points. Backend-only witness DTOs cannot deserialize a trusted prepared owner.

The message uses a new explicit domain `0x31434c4d` (little-endian bytes `4d4c4331`, MLC1) and version1. It is one native field:

`m = transientHash([MLC1, 1, C.lo, C.hi, P.lo, P.hi, |V|, (type_tag,V[i]) for i in order, A, (asset.lo,asset.hi,gross_cap,fee_cap,net_floor,liability_cap) for assets in strict full-AssetId order, nonce, not_before, not_after, predecessor.lo,predecessor.hi])`.

UInt tag2 and Bool tag1 preserve standalone tag meanings. V order is source action inputs in declaration order; complete pre-state in source state order; complete pre-duty pairs `(present,amount)` in D order; dynamic effect values in statement/effect order (state before/after, transfer/fee amount, liability before/after and discharge amount where represented, event value); complete post-state in source state order; complete post-duty `(present,amount)` pairs in D order. All V components are UInt/Bool. Effect descriptors distinguish an amount used by a discharge statement from its emitted liability before/after values; no extra semantic effect is invented. Native hash/point values are carried separately, not mislabeled UInt. Every count/index/type/asset/role/duty/effect identity is fixed in C/descriptors. Logical `at` is interval-checked and communications-committed, but outside m; host reconstruction still binds it in P's request hash. Actual constraints compute m directly; caller `message_hex` is a review projection, never a free message wire. Signature challenge remains `transientHash([0x46454e53,R.x,R.y,PK.x,PK.y,m]) mod r`.

P.lo/hi and predecessor.lo/hi are input limbs, range-constrained and included in m. Their correspondence to the JSON/predecessor bytes is established by independent host reconstruction at each public consumer and by the communications statement. The relation does not recompute SHA256 or authenticate a ledger root. The proof establishes the typed limb statement and actual V/cap/FENS computation under C; claiming constrained predecessor-hash preimages would be false.

The signature authorizes semantic transition and locally reconstructed request/context, not a future randomized SDK final PI. C fixes native templates; the actual V wires fix their dynamic values; real `Impact` groups constrain the corresponding actual operations; the typed argument commitment binds P/limits/nonce/interval/attachment. SDK PI then binds that communications commitment, final parent binding and processed native operation transcript. Cold verification independently reconstructs all of these and runs Real verification. These links rely on the pinned SDK/hash/compiler premises. No signing of one's own proof, VK or signature is required.

## Real financial wires and complete native openings

Extend the existing ledger compiler/lowering together, using one shared ledger Builder register allocator. Record a typed semantic projection while each source statement is compiled, then reuse those exact operands for message and caps. Do not independently re-evaluate a Scenario inside an unrelated backend relation. Compile direct action input, state update, transfer/fee amount, liability before/after, discharge amount and event value operands once; record ordered descriptors, including zero-amount effects and repeated payments before aggregation. Source role/asset identities are constants; custody claim templates consume the same amount operands and checked aggregate totals.

The signed operation order is: existing root-array ABI guard; complete state-map cardinality and pre-state reads; complete duty-map cardinality/membership/conditional reads; original source statement templates; complete post-state and post-duty observations; constraint-only message/cap/FENS emission. The same signed lowering emits real additional native reads. These observations change read gas and guaranteed-partition cost, but not semantic effects or liabilities. The full native readback/partition/gas expectation is regenerated for the signed mode; old unsigned gas receipts cannot qualify it.

State completeness: at each endpoint use `Dup(0), Idx([slot0]), Size, Popeq(number_of_declared_states)`, then native `read_cell` for every declared key in deterministic source order. Use Bool/UInt openings of actual `Popeq` results. Link initial operands to source-prefix reads and final operands to compiler updates; untouched fields equal their initial values. Size plus every distinct declared-key read excludes unknown/missing state keys. Existing root array size3 and immutable template paths remain constrained; no host-only complete-frame hash substitutes for these observations.

Duty completeness: at each endpoint use `Dup(0), Idx([slot1]), Size, Popeq(sum(member[d]))`. The count is a UInt opening, bounded by `|D| <=16`, constrained equal to the checked sum of all Bool membership openings. Emit real `membership(1,key[d])` for every registry entry. If present, emit real `read_cell` of asset/debtor/creditor/amount; if absent, omit the raw read and process its inactive groups to SDK Noops of the exact template width. Guard-select each field to zero for absence and constrain amount=0 then; for presence, metadata equals immutable registry identity and amount is UInt. Keys are distinct and registry-complete: size equal to the membership sum rules out extra unknown keys, even an extra zero-valued duty. Canonical absent and present-zero are distinct via presence bits, both amount0. Native map Size is at most16 here, so no VM u64 arithmetic is used for financial UInt128 totals.

Pre/post duty observations are linked to each touched prefix membership/read and final duty write; untouched post presence/amount equal pre presence/amount. Liability creation makes presence1 even for zero. Discharge requires membership and checked subtraction, preserves present-zero, and cannot erase registry membership unless source semantics explicitly do so. Use the existing source semantics rather than inventing deletion. All registry duties, including freeze's untouched charge9, feed closing-duty caps. The extension map and whole external ledger frame remain host-compared premises; these reads do not prove global UTXO history, full custody or authenticated chain state.

For each asset use checked UInt128 arithmetic from actual ordered effect wires:

- `F = sum(owner fee amounts)`; `T = sum(owner outgoing transfer amounts)`; `G = T+F`. Refunds never reduce G.
- `CREDIT = sum(transfers to beneficiary)`; `DEBIT = sum(transfers from beneficiary) + sum(fees from beneficiary when beneficiary != owner)`; `NET = CREDIT-DEBIT-F`, with checked nonnegative subtraction. Owner fees reduce net once; owner=beneficiary self-transfers cancel and owner fees still reduce net.
- `DUTY = sum(post_amount of every registered owner duty for that asset)`, including untouched and present-zero duties. Liability addition/discharge are not payments.
- Assert `G <= gross_cap`, `F <= fee_cap`, `NET >= net_floor`, `DUTY <= liability_cap`.

Every individual amount, cap and intermediate sum/result is range-constrained; overflow and net underflow refuse rather than wrapping modulo the field. These formulas preserve the existing standalone strict financial meanings without importing its public/private layout. A gross/net/duty proof alone does not establish real payer funding or asset-account ownership.

Interval, caps, witness and payload errors cannot fall back to local unsigned preparation.

## Attachment-specific proof contract

Choose attachment-specific communications binding. R/s and PK are inside the actual typed input and therefore its communications commitment and final native PI. A second valid signature for the same message/key is an accepted *new preparation*, but changes the commitment under the same supplied randomness and needs its own proof. Do not inherit standalone existential proof reuse for a different valid attachment.

The verifier independently re-prepares using its supplied signed attachment and request/randomness, compares the complete final native intent and communications commitment, then performs Real crypto verification. An old proof with a new attachment fails expected-statement equality; a direct future Real-verifier control with altered commitment/PI must separately fail cryptographically. Invalid external attachments fail strict host FENS even if a candidate claims identical hashes. Collision resistance is an explicit cryptographic premise. A public attachment contains no secret scalar; no private preimage/raw-input publication is added beyond the existing bounded public local artifact contract, and no claim of private witness transport confidentiality is made.
