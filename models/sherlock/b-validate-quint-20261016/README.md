## Concrete finite domain and cutpoint

One sequential machine evaluates a top-level literal expression, from a
component-entry cutpoint with no helper, result, tasks or frames, through free
publication. Its original control is retained throughout Validate. Input-only
programs declare UInt 7, Bool true, Nil, Leaf(UInt 7), Cons(UInt 7, Nil), and
Branch(Leaf(UInt 7), Leaf(UInt 7)). The last program uses the same leaf reference
twice. Each appearance is traversed independently; markerFree never skips work.
The list/tree schemas have their dedicated arities 0/1/2. Immutable expression,
constant and ordered field tables and the root source occurrence are retained.
No function is present; this slice has one code identity and entry source owner.

The cutpoint retains one inert Data UInt row, one environment cell/root and one
value slot, so ordinary tests check preservation of nonempty arenas. Their logical
allocation counters start at the lengths of those retained arenas. All work
counters and reference cursor start at zero relative to this component. This is
not a claim of canonical-genesis reachability or admission of these images.
The literal is at expression/origin 0 and its source path is empty. Arbitrary
function origins, stack frames, nested callers and nonzero entry clocks need
separate cutpoint instances and correspondence evidence.

Callers supply a Limits record to initCase. The concrete finite exploration
instance permits fuel/helper budget 0..48 and task capacity 0..4; all 22 Bounds
fields and four LayoutCapacities fields are present. Normal tests use supplied
48/48/4 and empty stack, without exercising refusal or invalid inputs. These
numbers are finite exploration parameters, not new language/runtime limits or a
resource amendment. Capacity and admission validation outside this fixed input
set is not implemented. In particular, the source cutpoint is not admitRun.

Only the initialized finite domain is intended for use. `arity(MarkerKind)`,
`rowAt(Data(_))` and impossible pure fallback arms are deliberately off-domain;
no selected transition reaches them from these six normal inputs. They are not
normative definitions on arbitrary images or a HostViolation implementation.
Negative/marker/refusal branches remain untested source translations. Their
hostile cases and security judgments belong to the designated security owner.

## Action and clock map

Each step calls pure advance once and either emits one StepEvent or returns
terminal with no event. There is no batch, hidden traversal, hidden cleanup,
recursion, memoized validation or independent task enqueue action.

| k.admin.publish.value/error | P1 branch in advance | unchanged | 0 | 0 |
| k.admin.publish.exhausted | P2 branch in advance | retained | 0 | 0 |

Every applied helper or bookkeeping row consumes one remainingWork and adds one
consumedWork and helperWork. Literal completion consumes one work, adds one
referenceCursor and no helperWork. Publication is free and precedes fuel
exhaustion. A zero-work exhaustion retains helper/result/tasks. P3 helper refusal
is uncharged; P6 positive task-cap refusal retains only P4 charge effects and
leaves parent/task cursor, helperVisits and referenceCursor unchanged. The
selected/attempted row remains the event rule on refusals. These branches are
source translations only. No refusal test or security conclusion is supplied.

The StepEvent ordinal is pre.consumedWork at this zero-clock cutpoint, consistent
with the schema: every uncharged event terminates. Neither raw step count nor
terminal stutter count is a reference/helper/work clock. A terminal step changes
only the diagnostic lastEvent to NoEvent and preserves the entire machine.

## Exact scoped field correspondence

SOURCE-FIELD-MAP.json inventories machine registers, tables, event fields,
identities, all row IDs and per-layer omissions. The complete scoped machine
record includes typed control/origin, environment/root, depth/stackLimit,
outcome, initial/remaining/consumed/helper/visit/reference clocks, logical alloc,
zero segBase, helper common/site/root/status, staged result, ordered typed tasks,
and preserved data/dataFields/env/valueSlots/frames. Physical active lengths and
taskLive are exact List lengths via active(mm)/tasks.length(). Inactive suffixes
are absent by the normative lazy-storage zero convention; no serialization is
claimed. Frame variants are not interpreted because depth is fixed at zero.

Every schema StepEvent field is represented, including RunId and ordinal,
source expression and entry occurrence, outcome tag/payload, terminal boundary,
allocation/slot/depth/task deltas, helper kind/phase/cursor, result tag and origin.
Options use explicit sum constructors except event.site, where the fixed strings
"Absent" and "EvalLiteral" encode None and Some(EvalLiteral). Present(0) remains
distinct from Absent. Phase/cursor reflect only the respective pre/post live
helper; staged-result completion has neither. helperKind/origin retain interval
identity when an exit stages a result or a legacy row consumes one. P2 retains
the result tag when a staged result survives fuel exhaustion. Refused entry
records interval helperKind/origin even when no helper is installed. Publication
without retained helper/result has absent interval metadata.

Identity has the schema's eight fields, with symbolic layoutVersion, absent
fieldId and Unselected digests. RunId retains original finite natural fuel and
stack inputs. Identity is a model projection, not an admission binding, selected
digest, codec, ABI, source authentication or physical admission handle. Full
layout/schema values, widths and ProgramView admission are omitted explicitly.
