# Provisional B-core Rust source preparation

This package contains uninstalled raw data declarations and private pure-function source. It preserves two distinct source stages; it adds no product module or public interface. It is not a schema freeze, representation adoption, B-core or family implementation, admission/StepInv implementation, or acceptance result.

`compiled/` contains 104 raw declarations, two row-to-kind projection bodies, and their private lexical harness. Root compiled exactly these three files once with direct rustc 1.99.0, edition 2024, crate-type=lib. The library compile exited 0 in 0.114 seconds. Dep-info identified exactly those three Rust inputs. Both postflights passed, seven candidate/snapshot source pairs stayed unchanged, and the recorded Python/rustc hashes stayed unchanged. The compiler reported 106 warnings; stderr contains 107 lines beginning `warning:`, including the final summary. The warnings are retained and unjudged. No test was selected and no function or compiled artifact was executed, loaded, or linked into a product.

`expanded/` contains a separate later candidate: 13 private function bodies and the two private owner-specified carriers CheckedArith and ValueRow. It retains the earlier two-body source as an exact prefix. New bodies implement checked add/sub/mul, arity, sort projection, kind/sort identity, borrowed-row kind/payload projection and shallow comparison. Fresh Opus and Muse source reviews approve only this exact source scope. These expanded bytes have NOT been compiled or executed; the earlier compile evidence must not be transferred to them. The preserved prefix header describes the earlier scope; the added comment and mapping describe the expansion.

The functions assume their six named types are available in the lexical scope. Root owns future module placement. A caller still must resolve ValueRef with its source bounds, enforce caller safeguards, handle undefined arity/sort results and stage checked-arithmetic outcomes under the owner engine contract. No arena/table interface, guard, validator, allocation policy, caller error label or capability token is supplied. Open installation questions include representation and field spelling; raw public fields are unvalidated data. Declaration order is not a wire/tag ABI.

`SOURCE-BINDINGS.json` pins the exact normative inputs and source stages. The evidence directory retains the actual compile receipt, compiler logs, dependency output, Root result check and existing plain reviews. Historical absolute runtime paths identify original files; this selected package is a source/evidence copy, not a runnable execution environment. Binary artifacts, provider raw output, prompts, private context, model launch files and execution runners are excluded. Fresh final actual-result/publication review is a separate delivery prerequisite.

Native authority remains zero. C4, U0–U7, M1–M17 and all MC/SP/G gates remain unchanged. No Cargo, SDK, backend, VM, model, proof, key or ledger execution is represented here.
