# Sherlock host client source proposal

These four source modules prepare an ordinary consumer of Sherlock's proposed host engine. They remain unregistered source proposals. A separate exact 21-file diagnostic closure containing these modules and the required owner/type/family sources produced Rust metadata; this directory is not a standalone build target. Publication does not adopt the host API or engine or establish a new product capability.

- `execution_capture.rs` supplies `capture_case`, which calls the fixed `shared::owner_host::host_owner_engine()` factory, `admit`, `admit_run`, the bound full observer and `step`. The caller supplies the typed fuel and stack limit unchanged.
- `typed_inputs.rs` supplies literal program, bounds and layout constructors for thirteen input fixtures, without an evaluator or expected results.
- `observation_json.rs` supplies pure complete typed JSON presentation for the public observation and event carriers. It is not a canonical codec or bounded encoding.
- `source_input_bridge.rs` supplies `from_program(&crate::sherlock::Program) -> CoreProgram` for every current dedicated-sort A AST constructor. Expression and tree worklists create separate owned occurrences while preserving names, values and source order. A caller can pass `parsed.program.as_ref()`; draft name, spans and provenance stay with that caller.

The capture source emits one initial full observation, then each actual returned step event with its full postimage, using the `sherlock-host-capture-v1` JSONL envelope. Initial keys are `schema`, `kind`, `case_id`, `fuel`, `stack_limit`, `observation`; event records add `event` before `observation`. The writer preserves the complete RunIntC carrier. Startup and P0 emit no StepEvent under the adopted event contract, so no event is synthesized for them. The client stops at an observed non-Running outcome and retains typed admission, host, rendering and I/O errors. A caller must keep the Result with its output; an I/O error can leave a partial final line.

The modules require the separately prepared `shared`, owner observation, `raw`, family and public A type closure, as applicable. They are intended as sibling modules. No engine, module registration, CLI or execution wrapper is included. Fresh Muse source reviews cover the individual candidates within their recorded scopes.

The [metadata-only result summary](../../../docs/audits/2026-10-16/sherlock-generic-input-bridge/README.md) records rustc exit 0, six warnings and zero errors for that exact 21-file closure. No parser, bridge function, engine or tests executed; metadata was neither linked nor loaded. Separate Opus source reviews found two unresolved defects in the engine's invariant diagnostic; correction is in progress. This metadata compile does not resolve those findings or establish engine correctness.

The existing cfg(test)-only/no-Stage-2 seam remains unresolved. A/B helper and fuel schedules differ; AST conversion establishes no same-fuel behavior or profile adoption. Model/circuit correspondence, proofs, native/target execution, financial conformance and all product/roadmap exits remain open.
