## 2. Instruction-by-instruction premise matrix (Native path only)

An off-circuit check that rejects a bad witness value is not an in-circuit constraint; a malicious or merely different witness producer that bypasses preprocessing is bound only by the synthesis constraints. Conversely, a synthesis assignment computed from `Value`s is witness generation, not enforcement. No supplied flag, label, or host-side Boolean counts as enforcement anywhere below.

## 3. Finite bounds and wrap avoidance (aux/2 arithmetic)

[MD] The aux/2 design never packs a 128- or 256-bit integer into one field element. Each relation is a per-limb field equation `E = 0 (mod p)` with all inputs range-constrained, lifted to an integer equation when `|E| < p`, and only then telescoped over the integers:

- ADD/SUB/FD-2 limbs: `E ∈ [−511, 511]`, needing `p > 511`.
- MUL column `k`: `S_k = Σ_{i+j=k} aᵢbⱼ ≤ 65025·min(k+1, 31−k) ≤ 1,040,400`; with admitted 12-bit carries `E ∈ [−1,048,575, 1,044,495] ⊂ (−2^20, 2^20)`. The exact field need is `p > 1,048,575`; the binding requirement remains `p > 2^20` (**E4**). The honest carry maximum is **4079** (attained at max×max, `c₁₆`), the inductive bound is **4080**, and both are below `2^12`; the 12-bit admitted range is complete, not merely sound.
- `hSum ≤ 4080 < p` with nonneg byte summands, so `TestEq(hSum, 0)` decides `h = 0` exactly; the full 32-column Mul (`c₀ = c₃₂ = 0`) gives `a·b = r + 2^128·h` over the integers, and checked Mul is Ok iff `h = 0`. Final carry `c₃₂ := 0` is load-bearing: without it the high word could be hidden in a carry (negative check N7).

[RA] Every step of that lifting presumes the *unconditional* ranges: input bytes 8-bit, carries/borrows Boolean or 12-bit, disabled blocks all-zero. Those ranges are part of the profile's RANGE/ZERO relations; in any concrete emitter they must be emitted unconditionally (as `literal_step.rs` does for image cells), because a range applied only on the enabled branch leaves the disabled-branch witness free to alias. Selectors (`sel*`, `uu`, `ovf`, `ltOut`, branch flags) must be *derived* from pre-state and fetched nodes via `TestEq`/`CondSelect`, never supplied as truth bits; the design's column inventory binds each added column to a forcing relation, and any emitter that accepts a supplied selector, carry, product `aᵢbⱼ`, column sum `S_k`, or `TestEq` inverse as a free witness breaks determinism (L-5) even if each individual gate is sound. Products and sums are deterministic internal instruction outputs under G4-ISA-1/2, which is a requirement, not evidence the native ISA was executed.

**Canonicalization split.** In-circuit, constraints bind field elements and their bounded integer representatives as above. Off-circuit, `ir_vm` preprocessing computes concrete `Fq` values and host-checks (Boolean, bit bounds, equality) — useful for witness generation and rejection of bad transcripts, but it is not a constraint and must not be cited as one. The Moriarty `Builder` in `source/moriarty/crates/mori-backend/src/lib.rs` illustrates the correct discipline and its limits: `range()` emits `ConstrainBits{bits:128}` for `UInt` and `ConstrainToBoolean` for `Bool` after arithmetic, `checked_mul` splits at 64 bits and constrains the high product to zero so intermediate products stay below the field, and `immediate(u128)` builds `Fr::from(n)`. Those are source facts about that consumer; they do not certify the aux/2 emitter, which does not yet exist.

## 4. Actual fetch and A102 wiring

[SF] `source/moriarty/crates/mori-backend/src/sherlock_machine/enabled_fetch.rs` (`emit_enabled_fetch_block`) is the real G3 enabled constructor; `fetch.rs` (`emit_fetch_block`) is the unconditional one. The enabled block constrains `enable` Boolean, `active_rows` and every row cell to their column types (`ConstrainBits{128}`/`ConstrainToBoolean` via the shared `constrain` helper), forms `index_eff = select(enable, index, 0)`, constrains `capacity < active_rows` to false via `LessThan{bits:128}` plus `ConstrainEq`, asserts the guarded prefix condition `select(enable, index_eff < active_rows, 1)`, builds one `TestEq(index_eff, row)` selector per row gated by `enable` through `CondSelect`, constrains the selector sum to equal `enable` by repeated `Add` and `ConstrainEq`, and folds each output lane by `CondSelect(selector, row_lane, acc)`. Selected values are returned tagged with the caller's `enable`; the header states consumers must gate every write/assertion with that enable, and that enable must come from constrained dispatch — **never a free prover witness**.
