# Deterministic candidate evaluator experiment

Experiment observation: the generic Core evaluator executes parsed and elaborated source for loan accrual, loan settlement, swap and closure. The retained tests compare every financial state field, write and effect with the independent legacy evaluator under explicit naming/asset/due-ID mappings. New settlement resolutions, PR/IP obligation records and settled tombstones, episode/agreement statuses, remaining notional, nonresetting revision/allowance and hashes are checked separately and in full-state comparisons.

`createSimulator(source,bounds)` binds original source bytes, exposes genesis/state construction helpers, and returns `Simulation { candidate, context }` from `.simulate(input)`. The contained Complete-shaped object is provisional and is never an accepted result. `unsignedExactPlan: true` is an explicit proposal mode for obtaining exact writes/effects before signing; ordinary derivation compares the exact arrays. Every derivation recompiles source and rejects rehashed substitute Core or source maps. No action dispatch depends on a financial package name.

Execution uses checked UInt128 arithmetic before division, typed local quantities, left-to-right short circuit evaluation, source-order state writes/reads and captured effects, per-action FloorDiv provenance, exact quantum conversion, obligation conservation and gross-debit/net-goal authority checks. Rejection returns one diagnostic and exposes no provisional writes/effects/after-state; the input remains unchanged.

Acceptance limitation: `evaluate` has an explicit deployment-owned `TrustedAcceptanceBackend` boundary. It discards client prechecks, obtains new authentication for the exact tuple, derives the candidate, then requires the backend to verify all mandatory claims and atomically consume state and nonce, returning matching committed identities. Backend objects must never originate in client wire input. The repository provides **no implementation** of that cryptographic/atomic backend; missing methods, client boolean verdicts and unavailable verification fail closed. The interface is not a PCD verifier or durable replay ledger. Actual MC04/MC05 implementations, ledger-asset validation, cryptographic authentication, proof-byte resolution, proof verification and independent exact Fable/GPT-6 audits remain required before acceptance claims. Tests of stale prechecks are not durable replay-protection evidence.

Validation: `semantics-tests.txt` retains 18 passing test suites; `typecheck.txt` is the empty successful strict TypeScript output. `receipt.json` pins tested files and normative inputs. `legacy-reference.json` is a byte-for-byte copy of the retained implementation-intake reference. Initial tests failed with ERR_MODULE_NOT_FOUND before evaluator implementation. Two later test-only negative-control fixtures were corrected: one changed notional without updating its derived status, and one aliased mutable genesis data between attempts. The runtime correctly rejected those fixtures at earlier binding/status checks.

This work is a candidate implementation experiment, not source-profile freeze, ACTUS or DeFi conformance, accepted Complete/PCD, backend correspondence, or ledger settlement.
