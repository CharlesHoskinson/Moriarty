## Exact retained implementation profile

- **Types and operations — repository observation:** `core.ts:1–29,158–183` (under `experiments/moriarty-developer-mock/src/language/`) stores string-valued `UInt128` and `String` fields. Bool exists only in expressions/locals, not state/argument/effect schemas. Expressions: literal, state, arg, local, remaining, eq/lt/lte/gt/gte, add/sub/mul/div, and/or/not. Instructions: guard, let, set, emit. Effects: Transfer, Fee, DueCreated, DueSettled. No fold, branch instruction, function call, collection value, signed integer, typed amount, observation input, or explicit authority input exists in this evaluator. Unknown operations/keys and schema mismatches reject. Locals are single-definition and cannot reference future locals (`core.ts:187–251`).
- **Numbers:** UInt128 range 0 through 2^128−1, canonical decimal strings of at most 39 digits; no JSON numbers (`core.ts:31–63,95–105`). Every arithmetic result, including each intermediate multiplication, must fit UInt128. Division is nonnegative floor; zero divisor, overflow and underflow reject (`core.ts:267–281`). Host BigInt performs calculations but does not provide a wider accepted Core intermediate. Thus a fitting final quotient does not excuse overflowing numerator products. Numeric-looking string literals infer UInt128, so source syntax needs explicit literal typing to represent numeric text without ambiguity (`core.ts:165–168`).
- **Finite limits:** 65,536-byte program/state/action object each; safe intake has ≤8,192 nodes, nesting depth ≤40 starting at zero, ≤64 keys per record; expression tree depth ≤16 starting at one and ≤256 total expression nodes **per entrypoint**, ≤64 instructions, ≤64 locals, ≤16 emits per entrypoint; state/argument/effect schemas and entrypoints each ≤64 fields/items (`core.ts:32,66–79,95–138,199–248`). Strings are bounded by JS `.length ≤256` where `stringValue` is called, not uniformly by UTF-8 bytes and not for every literal. Total object byte cap still applies. Schema/entry/local names use 1–64 ASCII characters, beginning with a letter; punctuation `_.:-` is allowed and reserved prototype keys reject (`core.ts:34–35`).
- **Evaluation and lifecycle:** instructions run sequentially against updated working state; and/or short-circuit; emitted fields observe the state at the emit point. A rejection exposes no partial next state/effects. A successful call increments revision by one, decrements remaining by one, and reports instruction count as `steps` (`core.ts:254–330`). It consumes one lifecycle allowance per transition, not one per instruction/event. The evaluator accepts arbitrary supplied valid UInt128 revision/remaining and does not itself authenticate genesis/history or enforce package reachable states. Loan initial allowance is 2; pool allowance is 8, with swaps requiring remaining >1 and provider closure reserved for the final slot (`packages.ts:127,150–163`). No generic global split/join measure, schedule/event budget, horizon, or pending continuation exists.
- **Outcome envelope:** atomic-only IntentIR; ≤8 authority assets, recipients per authority, goals, fee assets, and agreements; exactly the four fixed required claims and no extensions. IDs are 1–64 ASCII characters with a different alphabet from Core. Validity is [notBefore, expiresAt), UInt128 nonce/time; Ed25519 signature checks bind trusted domain/principal/key (`outcome.ts:5–56,71–94`). Trace accounting has ≤32 balance cells and ≤16 effects, checks each transfer prefix, gross principal debits including fees, every permitted recipient, and net terminal credits (`outcome.ts:124–192`). Counterparty authorization is explicitly an outer-runtime duty (`outcome.ts:1`). The actual local runtime allows exactly **one** registered swap/full-settlement action and ≤4 explicit fees; nonce table capacity 128, no eviction, local reset boundary; real acceptance returns unavailable (`outcome-runtime.ts:139–190`; intents amendment:123–143).
