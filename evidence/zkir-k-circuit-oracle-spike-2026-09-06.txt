Usage
  zkir-circuit-oracle PROGRAM.zkir PREIMAGE.json [--inject INJECT.json] [--pis PIS.json] [--binding-input DEC]
                      [--instance PIS.json] [--model-only]
  One JSON line: outcome in {preprocess-error, witness-consistency-error, synthesis-error, constraint-failure,
  panic, accepted} (+ model-only for --model-only), k, rows (2^k allocated by MockProver), usable_rows,
  elapsed_ms, preprocess_ms, optimal_k_ms, mockprover_run_ms, verify_ms, peak_rss_kb (VmHWM), message,
  failures (constraint failures as strings), injected, pis, trace_errors.
  Classification: preprocess Err -> preprocess-error; MockProver::run Err with the crate's tracing ERROR event
  "Misalignment between `prepare` and `synthesize` runs" (emitted only by mem_insert / pi_push in ir_vm.rs; captured
  with a tracing-subscriber layer) -> witness-consistency-error; any other MockProver::run Err -> synthesis-error;
  verify Err(failures) -> constraint-failure; caught panic (std::panic::catch_unwind + panic hook) -> panic.
  Exit code 0 for every classified outcome, 2 when the program or preimage file does not load.
  --inject replaces Preprocessed.memory entries (Native only) before the circuit is built; --pis / --binding-input
  replace the other public fields of Preprocessed (the MockProver instance column follows pis); --instance changes
  only the instance column handed to MockProver, which is the way to reach a genuine constraint failure.

Spike verdict
  MockProver is cheap on every circuit in the corpus: the largest corpus circuits need k=15..16 (2^16 rows), the
  ledger test programs k=10..12, the Moriarty expire circuit k=9. Wall time is dominated by the sha256/keccak table
  loads (k=15: 7 s, 140 MB); everything else runs in well under a second and under 30 MB. optimal_k costs about
  as much as the MockProver run itself (it synthesises with an unknown witness for k=9.. until the circuit fits).
  The plan's worry about 2^20 rows does not apply to the corpus. M1 can run the whole corpus, not a sample, with
  the honest preimage and every perturbation per program: 44 + 61 + 6 + 9 programs times about six runs is an
  estimated ten minutes end to end, dominated by the hash programs. Memory is not a constraint.

Classification difficulties and findings for the M1 comparison table
  1. A witness-consistency error and a synthesis error carry the same crate error value
     (Error::Synthesis("error_if_known_and") wrapped by the stdlib as "Relation::circuit error: ..."), so the
     distinction rests on the tracing ERROR event that only mem_insert / pi_push emit. The oracle installs a global
     tracing subscriber to capture it. Without tracing the two classes are indistinguishable at the API.
  2. Injected witness registers are only meaningful where the circuit reads the witness: the declared inputs and
     the public_input / private_input registers (the circuit assigns those from Preprocessed.memory). Every other
     register is recomputed in-circuit and the injection is detected by mem_insert (witness-consistency), never by a
     constraint, because MockProver never sees the injected value.
  3. A guarded public_input whose guard is off is unconstrained: injecting %amount.13 (guard %t.10 = 0) 0 -> 1 in
     expire.zkir is ACCEPTED ($B expire.zkir $SP/expire.json --inject $SP/expire_inject.json). The register's cell
     is assigned from the witness, skipped by the public-input push, and nothing else constrains it. This is
     expected behaviour (the value is a free witness cell) but it must be a named cell in the comparison table:
     K's verdict layer says nothing about skipped public inputs.
  4. Four instruction paths insert into the circuit memory without mem_insert (ir_vm.rs in-circuit
     FromBytes32, ReverseBytes, Bytes32IntoLowHigh, Bytes32FromLowHigh). An injected value on such an output
     register is silently ignored (the in-circuit value is the recomputed one); with Native outputs only
     FromBytes32 to a Native type can be reached by --inject. Another named cell for the table.
  5. To reach a genuine constraint failure the instance column must be perturbed independently of the witness
     (--instance). Perturbing pis or binding_input in Preprocessed is always caught earlier by pi_push.
  6. MockProver (0.8.2) sizes its own row count, so `k` reported is optimal_k's value used for the pow2range table
     width (max_bit_len = k - 1) and `rows` is what MockProver allocated; they agreed on every run here.
  7. MockProver::verify reports failures per cell (Equality constraint not satisfied by cell ...), which identifies
     the region name and column but not the ZKIR instruction; mapping failures back to instructions needs the
     region naming convention of midnight-circuits or the instruction index in the layouter namespace.
