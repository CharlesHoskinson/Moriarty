## R1 to R2 repairs (three only)

1. **Staging name resolution.** R1 evaluated `EXPECTED[int(role[-1]) - 1][1]` eagerly as the `dict.get` default in `stage_tool_and_inputs`, raising `ValueError` for `generatedManifest` (`int('t')`) and `scriptHex` (`int('x')`) even when the key was present. R2 resolves all nine staged names only through one literal `INPUT_STAGED_REL` mapping (`generatedManifest -> manifest.json`, `scriptHex -> script.hex`, `contextT1..T7 -> EXPECTED[0..6][1]`), reused by staging and by custody postchecks so the rosters cannot drift. No native probe is needed to fix ordinary Python eager-argument semantics.
2. **Whole staged custody.** R1 `verify_custody` checked all eleven host pins, the staged tool and the five operator files but never the nine staged input files. R2 `check_staged_inputs()` rechecks exactly those nine staged files (pinned size and SHA-256, non-link regular file, read-only mode) inside `verify_custody`, which runs at staging/pre-native time and again post-native, including on the failure path once staging is complete (`created=true`). A writable, symlinked, missing or changed staged input fails closed. Host/tool/source-five checks are unchanged; no stdlib cache, validator, build or new source-production change is added.
3. **Returned versus validated accounting.** R1 appended and counted a step only after `validate_call`, so a returned process that failed validation vanished from `RESULT.json` and reported zero returned calls. R2 appends the raw step and increments `aikenCallsReturned` immediately after the process returns and before validation, stores `validationStatus` (`VALIDATED` or `FAILED_VALIDATION`) and `validationError` on that raw step while preserving raw argv, exit code, log paths, byte counts, log hashes, wall time and captured CPU delta, and maintains the distinct `aikenCallsValidated`/`validatedCallsCount`. Only seven returned plus seven validated calls can reach `COMPLETED_AWAITING_FRESH_ACTUAL_RESULT_AUDIT`. A spawn or wait/cleanup failure without a return remains `incompleteCall` plus the launch-attempt counter with no phantom returned call, and launch intent is never equated with native start (`nativeExecutableStarted` stays `not_measured`). A stage failure before `created=true` still writes only the stdout terminal JSON with no partial-artifact reset, as in R1.

An independent ordinary pure-Python regression may, outside this operator, test all nine role mappings, one changed staged input, and one failed-validation accounting case using public bytes only, without importing the SDK/native toolchain or running the operator `main` on private paths. No such test source is added here: the five-file candidate remains the complete deliverable, and any expected failure is described here rather than implemented as mirror test machinery.

## The seven calls

Exactly seven sequential calls, one attempt each, zero retries, launch intent counted before `Popen`:

```
/tool/aiken uplc eval --cbor /inputs/script.hex '<single context term>'
```

Each term is the full content of one pinned 2649-byte generated context file, bounded-read, hash-checked, strict-UTF-8 decoded, with exactly one trailing newline stripped if present, passed as one argv element. No shell, no string evaluation, no `--flat`, `--debug` or other guessed flags. Source basis: Aiken 1.1.24 `eval.rs` (`--cbor` reads hex text, each positional argument is parsed as a term and applied, success prints one pretty JSON object, failure exits 1 with Error/Costs and optional Logs on stderr).

T1 accepts only on exit 0, empty stderr, and strict JSON with exactly `result`/`cpu`/`mem`, result exactly `(con unit ())`, and non-bool positive integer costs. T2-T7 accept only on exit exactly 1, empty stdout, and full-match stderr carrying the exact `machine/error.rs` EvaluationFailure text `the validator crashed / exited prematurely` plus strict Costs, with at most one bounded Logs section. Out-of-budget, syntax, signal, timeout or any trailing unexplained content fails closed and is preserved, never retried.

Guard labels (pairing for T2-T4, `qty == 1`, token name, VK digest) are source expectations from `claim.issue` conjunct order, the coherent positive control and each minimal changed case. They are finite-predicate support only: the runtime does not instrument named guards, and a typed-decode failure could also surface as EvaluationFailure.

All eleven pins (Aiken binary 38,299,808 B `4257cc...7677`, its data-only manifest, and the nine generated inputs) plus the staged read-only tool (mode 555), the nine staged input files and all five operator files are hashed/checked before and after; a wrong size/hash fails before any command. Release identity is parsed from the pinned data manifest (v1.1.24, target `bacbeb35...acb4a`); no `--version` or other executable probe is run, and argv never self-claims a version.

Budgets chosen by the source author: 60 s wall per call plus 10 s kill-after, parent wait 80 s, CPU 30:35, 8 GiB address space, core 0, 16 MiB file-size and per-log caps; 7x60 s planned aggregate plus 180 s staging/final reserve equals a 600 s outer bound plus 10 s kill-after, enforced by root per the R1 F4 observation rather than summed internally to 700 s. No uninterruptible-death or transitive-CPU claim is made. Isolation is `bwrap --unshare-all --die-with-parent --new-session --clearenv` with the tool and inputs read-only, only a fresh capture directory writable, and no network, keys, wallet, stdlib/build trees or host mounts.
