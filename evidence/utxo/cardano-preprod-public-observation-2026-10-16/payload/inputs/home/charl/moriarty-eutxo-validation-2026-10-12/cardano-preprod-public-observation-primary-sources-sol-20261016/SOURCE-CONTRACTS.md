# Primary contracts for a later public Preprod observation

This is a bounded **static source collection**, not a wallet, tip, balance, UTxO or protocol-parameter observation. Eight URLs were retrieved with Scrapling 0.4.15, without credentials or wallet-address parameters: three GitHub metadata/path-discovery requests and five source/configuration captures. No Koios live endpoint, faucet, node, SDK, signing or transaction operation was called. No operator or new execution authority is supplied. The contract below is evidence for the separately reviewed future public reader, not a security judgment.

**Source pin.** Koios artifacts are pinned to [`cardano-community/koios-artifacts`](https://github.com/cardano-community/koios-artifacts/tree/2e2eb57933e1e2528de5ca36ee961759841cf389), default branch `main`, commit `2e2eb57933e1e2528de5ca36ee961759841cf389`. The [captured generated Preprod OpenAPI](captures/koiosapi-preprod.yaml) identifies version `v1.4.2`; [selected contracts](extracts/selected-contracts.json) resolve the four relevant path/schema references without examples. GitHub metadata and the spec declare CC-BY-4.0; the LICENSE file itself was not retrieved. Attribution: Koios Core Team / cardano-community. Official environment configuration captures have no established license or upstream commit pin in this collection. [SOURCE-MANIFEST.json](SOURCE-MANIFEST.json) records every URL, HTTP status, UTC retrieval time, body length and SHA-256.

**Official network configuration.** The [official Preprod config](https://book.world.dev.cardano.org/environments/preprod/config.json), [captured locally](captures/preprod-config.json), declares Cardano protocol and required network magic. Its [Preprod Shelley genesis](captures/preprod-shelley-genesis.json) declares `networkMagic: 1`, `networkId: "Testnet"`; the [official Preview Shelley genesis](captures/preview-shelley-genesis.json) declares magic `2` and the same Testnet network ID. The respective configured starts are 2022-06-01 and 2022-10-25 UTC, slot length 1 second, epoch lengths 432,000 and 86,400 slots. These distinguish published configurations, not a currently connected peer or authenticated chain. Testnet address encoding does not select between them.

**Documented Koios host and access.** The spec's `servers` labels `https://preprod.koios.rest/api/v1` as Preprod, `https://preview.koios.rest/api/v1` as Preview and `https://api.koios.rest/api/v1` as Mainnet. Those are provider declarations, not live observations here. Global `security` permits `{}` or optional bearer authentication; its prose explicitly allows an unauthenticated public tier. No account or token was used. The documented public policy is 100 requests per endpoint/IP per 10 seconds, 60-second restriction after a burst breach, 1kb public request bodies (5kb for registered tiers), at most 1,000 result rows per page, and 30-second server-query timeout. Exact kb-to-byte conversion and a maximum response-body byte count are not specified. These are the pinned documentation's statements; current deployed enforcement is unobserved.

JSON is the documented default response; `Accept: application/json` selects it explicitly. Generic PostgREST query facilities include `select`, `limit`, `offset`, `order`, column filters, and `Content-Range`; a first page is not a complete-set guarantee. The four paths document JSON 200 responses and 400/401/404/413/429 errors. The global timeout prose also names 504. No automatic retry policy is specified or authorized by this collection.

| Operation relative to the Preprod base | Exact documented request shape | Response contract |
|---|---|---|
| `GET /tip` | No endpoint-specific parameters or body | Array with declared `hash`, `era`, `epoch_no`, `abs_slot`, `epoch_slot`, deprecated `block_no`, `block_time` |
| `POST /address_utxos` | `Content-Type: application/json`; object with required `_addresses` array of bech32 payment-address strings and optional boolean `_extended` | Array of `utxo_infos` records, detailed below |
| `GET /epoch_params?_epoch_no=N` | Optional query `_epoch_no` is schema type string; N denotes a chosen epoch, not an observed number here | Array of that epoch's protocol parameters; omitting the parameter requests **all epochs** |
| `GET /genesis` | No endpoint-specific parameters or body | Array of provider-reported genesis fields, including string `networkmagic` and `networkid` |

Only the methods shown are advertised for these paths. The address request shape for later review is `{"_addresses":["<exact-bech32-payment-address>"],"_extended":true}`; this is a placeholder, never transmitted. Source [address_utxos.sql](captures/address_utxos.sql) and [exact excerpts](extracts/address-utxos-source-lines.txt) establish a default of `_extended=false`, exact address equality via `ANY(_addresses)`, no rows for empty/null input, and `consumed_by_tx_id IS NULL`. Non-extended mode deliberately returns null for `inline_datum`, `reference_script` and `asset_list`; it still returns ordinary UTxO fields. Extended mode populates those details and gives an empty asset array when no assets are aggregated. The SQL's misleading “empty result” comment is qualified by its actual SELECT: it omits the extended details, not all UTxO rows.

**UTxO field shape.** The outref is the pair `tx_hash` (hex text produced by SQL) and `tx_index` (schema number; SQL smallint). Other fields are `address` string, `value` string, nullable `stake_address`/`payment_cred`, numeric `epoch_no`/`block_height`/`block_time`, nullable `datum_hash`, nullable `inline_datum` and `reference_script`, nullable/array `asset_list`, and boolean `is_spent` (the captured SQL emits false for this endpoint).

An inline datum object contains `bytes` (hex string) and `value` (JSON object in the spec). A reference-script object contains `hash`, `bytes` (hex), `type`, `size` (number, bytes), and nullable JSON `value`. Asset entries contain `policy_id` (hex string), nullable hex `asset_name`, `fingerprint`, numeric `decimals`, and string `quantity`. The SQL casts quantities to text without decimal scaling; `decimals` comes from a left-joined cache, so its possible nullability is a schema/implementation gap. SQL also makes optional datum/script fields null when absent.

**Amounts and current parameters have explicit gaps.** The UTxO spec calls `value` an ADA sum but gives only a string schema; the SQL returns `tx_out.value::text` without conversion. This source set does not establish the exact ADA/lovelace conversion for that database field. Preserve its raw string meaning; no funded balance, decimal conversion or sum is asserted here. Hex lengths, integer ranges and required-response membership are also not fully constrained by the OpenAPI file.

For a later current-epoch read, `/tip` exposes `epoch_no`, while `/epoch_params` needs the chosen epoch explicitly because its default is all epochs. This is a contract implication, not an atomic snapshot or an observation. `epoch_params` has `epoch_no`, `era`, `block_hash`, and nullable protocol fields. Relevant numeric fields include `min_fee_a`, `min_fee_b`, `protocol_major/minor`, byte-sized `max_tx_size/max_block_size/max_bh_size`, execution-memory and execution-step limits per transaction/block, `price_mem` (per memory word) and `price_step` (per step), collateral percentage/count and reference-script per-byte fee. `coins_per_utxo_size`, deposits and several monetary bounds are nullable strings; the spec does not fully define their calculation units. No current numerical values are claimed.

`cost_models` is specified only as object-or-null holding language models: language keys, vector/object layouts, coefficient order and exact numeric types are **unspecified**. The [complete selected field definitions](extracts/selected-contracts.json) include the epoch fields and their source nullability. This is not enough by itself to construct a strict ledger cost-model decoder or calculate transaction fit. The tip schema also contains deprecated `block_no` but omits `block_height`, although its prose/examples mention height. This unresolved source inconsistency is retained, not repaired from memory. Most response schemas omit `required` and `additionalProperties` constraints.

For identity, `/genesis` advertises string `networkmagic`, `networkid`, `epochlength`, `slotlength`, `maxlovelacesupply`, `activeslotcoeff`, `slotsperkesperiod`, `maxkesrevolutions`, `securityparam`, `updatequorum`, numeric UNIX `systemstart`, and `alonzogenesis` as a JSON-dump string. It does not expose a complete Conway configuration in this schema. No actual response or asserted magic value from that host was acquired.

This set provides source contracts and named gaps for a separately reviewed public reader. Provider API responses, if later collected, remain provider observations rather than authenticated ledger proofs. HTTPS, a schema and published genesis data do not establish cryptographic ledger authentication or a consistent multi-call snapshot. No new security recommendations, operator design, authority or runtime result is claimed. All 20 UTxO families, ACTUS/DeFi/general obligations, real recursion/private handoff/bounded multi-parent PCD, universal certificates and ledger-prototype qualification remain open.
