**Tier 3 — structural.**

## Problem
- `stage/validate.rs` repeats `runtime::validate` almost line for line.
- The liability identity registry is implemented three times: twice in `runtime.rs` and once in `stage/decode.rs`. `stage/decode.rs` also re-implements `validate_asset`.
- `language()` in `parser.rs` repeats the token-copy code from `parse_profile`, and its error message ignores `moriarty/2`.
- `stage/plan.rs` hard-codes `"moriarty-stage-plan/1"` instead of using `STAGE_PLAN_FORMAT`.
- The reserved-word list in `runtime.rs` is kept separately from the lexer's keywords.
- `runtime.rs` (about 1k lines) holds the checker, evaluator, scenario normalization, segment runner and replay.
- Error codes are compared as strings (`stage/admit.rs`).
- `FederationPolicy`, `Role`, `RoleGrant` and `CostPlane::{Dust, Service, External}` are public, but only `tests/authority.rs` uses them.

## Suggested fix
These are refactors that keep behavior unchanged, with the existing tests as the oracle:
1. One `validate`, parameterized by profile, shared by `/1` and `/2`.
2. One liability registry type used by the runtime and by stage decoding, and one `validate_asset`.
3. One token-copy helper, and a `language()` error message that names both profiles.
4. Use `STAGE_PLAN_FORMAT`, and derive the reserved words from `mori_lexer`'s keywords.
5. Split `runtime.rs` into `check.rs`, `eval.rs`, `scenario.rs`, `segment.rs` and `replay.rs`.
6. Replace string comparisons of error codes with an error-kind enum or constants.

## Needs input
- Whether the unused authority types are planned public API (keep them and wire them up) or can be removed.
- Items 1–6 need no decision, but #76 may supersede them. Read its outcome first.

## Done when
Each item above exists once, `runtime.rs` is split, and all tests pass unchanged.
