**Tier 3 — structural.**

## Problem
Sherlock lives in `crates/mori-core/src/sherlock/` (35 files):
- About 2.8k lines of unadopted prototypes are compiled only under `#[cfg(test)]` in `src/`: `program_image`, `image_reference`, `machine_image`, `helper_schedule`, `helper_call_adapter`, `reference_slice`, and the draft frontend.
- `lib.rs` mounts `sherlock/draft_*.rs` and `sherlock/source_adapter.rs` at the crate root with `#[path]` under other names (`sherlock_draft`, `sherlock_source`), so that `sherlock/mod.rs` has no crate dependencies. That's because `models/sherlock/reference/check-reference.py` compiles `sherlock/mod.rs` directly with `rustc --test`, outside Cargo, which also rules out insta and proptest.
- `image_reference.rs` re-implements `reference.rs`'s transition, evaluate, bind and matching. Its own comment says it mirrors the rule decomposition.
- The call stack pushes and pops at the front of a `Vec` (`frames.insert(0, ..)`, `remove(0)`), which is O(n) per step.
- Every `mori-core` source file must be in the ledger's `source_closure`, so each new Sherlock file changes ledger identities (#77).

## Suggested fix
1. Create `crates/mori-sherlock` with `reference`, `reference_types`, `compare` and `reference_display` as its library and no dependencies. `mori-lexer` is optional, for the draft frontend behind a feature.
2. Move the draft frontend and `source_adapter` into it and delete the `#[path]` mounts. `mori-backend::source_projection` depends on `mori-sherlock`.
3. Move unadopted prototypes to `experiments/sherlock/` or behind a `prototype` feature.
4. Replace `check-reference.py`'s direct `rustc` build with `cargo test -p mori-sherlock`, keeping its JSON transcription check (see #86).
5. Make `image_reference` reuse `reference.rs`'s rule helpers, or drop it if the flat-image interpreter isn't adopted.
6. Keep the top of the frame stack at the end of the `Vec`.

## Needs input
- Which prototypes are still wanted (behind a feature) and which go to `experiments/`.
- Whether the hash-pinned audit records under `docs/audits/2026-10-15/sherlock*` need new records or stay as history.

`mori-core` has no Sherlock code, no `#[path]` mounts remain for it, and Sherlock builds and tests only through Cargo.
