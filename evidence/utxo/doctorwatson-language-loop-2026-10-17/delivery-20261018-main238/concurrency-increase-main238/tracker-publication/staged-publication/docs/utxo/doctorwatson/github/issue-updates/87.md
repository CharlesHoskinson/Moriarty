## Problem
`RUST_GUIDELINES.md` requires insta snapshots that show the `.mori` source, separate success and error macros that render diagnostics through miette, and a proptest never-panic property for every phase that consumes source. The new crates have:
- Two insta snapshots in total (`mori-backend/tests/compile.rs`), both of `Debug` tuples.
- One proptest (`mori-core/tests/language.rs`, random strings into `parse`). There is none for `stage::load`, `json::parse`, continuation decoding or the Sherlock draft parser and typechecker, and none in `mori-ledger`.
- Draft-frontend and source-adapter tests that compare against hand-written Rust ASTs.

## Suggested fix
1. Add success and error snapshot macros for Core like `mori-parser`'s (source in `description`, `omit_expression`). Render errors through `GraphicalReportHandler` once #82 lands.
2. Add never-panic proptests for `mori_core::parse`, `stage::load`, `json::parse`, continuation decoding and the Sherlock draft parser. Feed them random strings, tricky fragments and damaged real programs, reusing `mori-lexer`'s strategies.
3. Change the draft-source and source-adapter tests to snapshot a tree printer.

## Needs input
None for the proptests. Error snapshots are best written after #82, so they don't need rewriting.
