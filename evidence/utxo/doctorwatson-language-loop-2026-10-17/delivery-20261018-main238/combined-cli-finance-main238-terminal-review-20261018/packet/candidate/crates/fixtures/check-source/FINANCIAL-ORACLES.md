# Normal financial check report cases

Six additive cases use the existing real-binary check-source harness. The eight
original dispatch cases and their exact stdout oracles remain unchanged.
Beta cases cover transfer and repayment local_s0 action metadata, complete
financial declaration spans and an obligation declaration. Core/1 cases cover
Transfer/Fee and multi-action Liability/Transfer/Discharge arrays. Core/2 cases
cover two contrasting financial Await actions with complete binder, statement
and local-reference-stage/none/untracked qualification fields.

The six JSON value expectations were declared before these cases were executed.
They were not generated by the tested parser, checker, evaluator or report
constructor. The author had already inspected implementation/report schemas;
these are source-derived author expectations, not blinded semantic evidence or
an independent provider review. UTF-8 offsets and SHA256 are metadata of the
literal ASCII sources. Core ExprIds are explicitly enumerated in source order:
payment0/1; loan-open0 then repayment1/2; escrow0–4; rebate0–4. Full stdout bytes
are frozen, including final newline. Beta struct field ordering and Core object
lexical key ordering follow the existing public wire format, corroborated only
for the separately captured original eight cases. New case outputs are UNRUN.

Core check reports omit the expression table, assets and states. This suite
checks complete check-report serialization, dispatch and normal source loading;
it does not compare financial execution, full Programs, continuation behavior,
compiler artifacts, native constraints, proofs or ledger effects. The separate
mori test Core/1 and staged Core/2 routes consume scenarios and expected financial
reports; this check suite does not replace those tests or establish their results.
