## Recommended exact choices

D1: use lsp-server =0.10.0 public Message::read/Message::write for Content-Length UTF-8 JSON framing, with a synchronous dispatch loop on locked stdin/stdout. This uses the maintained crate's actual framing and typed JSON-RPC envelopes. No custom frame parser, async runtime, sockets or Connection::stdio thread graph is proposed. The last points describe proposed selected calls, not a whole-library/no-I/O/security claim. Alternative D1b is full Connection::stdio, whose selected source creates reader/writer/dropper threads; D1c writes a new frame implementation over current serde_json and adds no dependency, but duplicates protocol code. Either alternative requires its own concrete implementation exposure.

D2: alias gen-lsp-types =0.11.0 as workspace lsp-types with default-features=false and no features. Its generated structs include the ordinary Initialize/Sync/Diagnostic types; without url/fluent-uri, Uri is an opaque String wrapper. Although generated from LSP3.18, emit only the explicitly specified compatible3.17 subset, and use string Diagnostic.message rather than3.18 MarkupContent. Current rust-analyzer master uses this package alias in its example dependency; the published lsp-server archive's normal dependencies do not depend on either type crate. Alternative is original lsp-types =0.97.0, which describes3.17-era types and adds bitflags1/fluent-uri0.1/serde_repr declarations. Public registry metadata says0.97.0 was published2024; this date alone is not a maintenance judgment.

D3: preserve current Rust check routing: first_token_text==language routes through Core; language==moriarty/2 uses stage::load; other language-prefixed source uses mori_core::parse; other source uses mori_parser::parse followed, when parsed, by mori_checker::check. This is exact current check scope, not an invented uniform type checker. Core1 parse_profile calls legacy validate before returning; the function lives in runtime.rs but this selected validation call does not invoke simulate. Core2 stage::load additionally admits/plans/fills cost invariants and computes program/plan digests. Those exact internal source files are captured. Legacy parsing returns one error; legacy checking returns all independent diagnostics. Core parser/loader return their existing code/message/optional offset. No simulate/runtime execution, compile, target, proof or SDK consumer is invoked. Alternative is legacy-beta-only with explicit Core unsupported diagnostics, which offers less useful coverage for current Rust Core files.

D4: Full push synchronization only. Initialize advertises positionEncoding utf-16, textDocumentSync {openClose:true,change:1}, serverInfo Moriarty Rust/version, plus experimental.moriarty analysis local-check-only/sourceProfiles list. No hover/completion/format/MCP/workspace/auth capability is advertised. Document URI is an in-memory identity and is not resolved/read. didOpen/didChange analyze supplied text; didClose drops it and publishes diagnostics[]. Each accepted increasing full document version publishes diagnostics with its version; close omits version. Existing/older versions do not replace newer state. Ordinary initialize/initialized/shutdown/exit lifecycle is required; unsupported requests get standard method-not-found, notifications do not receive response objects. Error/resource/input edge design is owner pending rather than certified by this normal contract.

D5: diagnostic mapping preserves existing error identity and original message. For MoriDiagnostic choose marked primary label, else first; map non-primary labels with text into relatedInformation at the same URI. Append existing help after a blank line in Diagnostic.message. Severity maps Error/None1, Warning2, Advice3. Diagnostic.source names moriarty-rust plus source profile. For Core errors use existing offset as a zero-width range, or source-start if absent; preserve message/code and do not invent a token end/full span. This leaves GH-I82 diagnostic-span work open. Convert byte positions into UTF16 counts with LF/CRLF/CR line rules, consistent with pinned protocol and Rust guideline. Initialize experimental profile metadata and per-diagnostic source do not claim a checked document compiles or executes.

## Mechanical exposure for designated owner, not assessment

Proposed server reads inherited stdin and writes stdout; CLI can render operational errors to inherited stderr through existing main/Shell. It retains supplied document text/diagnostics in memory, calls existing Rust lexer/parser/checker/Core2 planner/cost/digest APIs, and serializes public protocol objects. It does not propose URI-to-file reads, discovery, watches, socket APIs, provider/auth loading, SDK/runtime evaluation, proof/key or ledger calls. lsp-server::Message framing reads a declared Content-Length into a Vec before application dispatch; its limits/EOF/error behavior require separate designated-owner inspection. Choosing a maintained crate does not certify its input/resource behavior. Alternative Connection::stdio creates three threads and joins them; it is not the recommended selected API.

Pending owner scope: literal input/body/header/output and retained-document exposure, shutdown/EOF/error cleanup, logging/output presentation and future hostile/security tests. No adequacy/safety/no-I/O/resource admission conclusion is supplied. Root owns any future command bound/env/temporary-root/source/toolchain admission and no old allocation/counter/failure is reset.
