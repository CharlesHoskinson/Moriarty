## Existing typed primitives and first genuine gap

`stage/mod.rs:44–87` gives the opaque checked `StagedProgram` and real `load`. `stage/mod.rs:110–123` defines one Continuation, with one program_hash/plan_hash/action/site, captures, local logical profile/cap/committed and complete boundary. `stage/mod.rs:157–174` defines the normal Waiting/Complete results. A completed outcome contains its full segment and local committed/attempted work; a waiting outcome contains its actual continuation and optional actual segment.

`stage/admit.rs:222–281` starts exactly one selected action. It forms a normal Scenario snapshot and starts its own action with committed0 and an idle incoming frame. `stage/admit.rs:287–392` resumes exactly one pending child under its own plan. Therefore calling a successor's existing `stage::start` is already possible for an explicit caller-supplied Scenario, but it is a new local execution, not a typed proof that two parent continuations have joined. Copying parent sums into the target's normal local committed field would contradict this real call path; aggregate history/work must have a separately selected representation if a join is adopted.

Its `merge:153–180` retains complete disjoint state, balances and liabilities in current canonical order; it does not remove zero duty rows. `Pair::start:242–301` invokes both actual parent starts in its own call, then retains the actual outputs. `Pair::resume:304–349` advances one selected actual pending parent and appends its actual outcome. `report:353–391` exposes all complete member envelopes/history/effects and the full merged boundary; status is waiting if any member is Waiting, otherwise complete. That existing product status is a report property. It is not an adopted availability-vs-success rule authorizing another program to start.

The existing reporter uses a disjoint display union and labels composition as `unadopted-local-disjoint-product`. There is no typed public importer for two independently prepared pending receipts, no completion-to-successor binding and no returned continuation that preserves both parent controls plus a target control. Such parsing is not proposed as a success workaround.
