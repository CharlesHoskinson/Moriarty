The intended integration destination is `crates/mori-core/tests/financial_pair.rs`; the integrator must place the unchanged oracle packet under `crates/fixtures/financial-pair/`. The proposal uses normal public `mori_core` imports and Cargo integration-test discovery, with no library unit-test module, path-mounted source, mock interpreter or new dependency. It consumes seven frozen files: two `.mori` sources, three complete Scenario JSON inputs, `mori-tests.json` and `financial-and-work.json`.

The two proposed positive tests call the existing public `parse`, `validate`, `simulate` and `simulate_metered` APIs. They compare the exact Core/1 language/semantics labels, action, complete pre/post Snapshots and ordered effects. Both ordinary and metered executions are independently compared to the same literal oracle. Every returned statement prefix is compared for count, ordinal, statement discriminant, full Snapshot and ordered per-step effects. The metered report must exactly equal the frozen profile/cap/used object: 42 units for each invoice collection and 45 for reserve allocation.

`snapshot_from_columns` decodes the frozen compact table: identity fields come from the literal full expected post, and values/presence come directly from literal cells. It checks column lengths and identity labels, preserves exact asset identity and duty tuples, and retains the absent/present-zero distinction. It performs no arithmetic, evaluates no source expression and never takes expected data from a parser or interpreter result. Final Snapshot/effect comparisons use the full original JSON, including preserved marker, observers, balances, warranty/emergency duties, fee and multiasset residuals.

The invoice test supplies the second call with the actual first poststate's state, balances and liabilities, replacing only inputs with the frozen final inputs. It first requires that complete successor Scenario equal the independently frozen final Scenario. This establishes a proposed local sequence comparison, without authenticating its predecessor or time. The reserve test checks all fifteen financial prefixes, fee-inclusive reserve5, present-zero allocation, bond3 and emergency2 through the same public consumer.

The oracle deliberately leaves `Step.value`'s per-kind Some/None convention and raw `Step.statement` ExprIds unresolved. The proposal therefore compares statement discriminants but does not assert complete statement identity, complete serialized Execution equality, captured-local wire encoding or assertion-return wire encoding. The public `Step` DTO has no charged-work field: per-statement/cumulative logical-work table cells remain independently specified rationale, while only each call's aggregate work report is observed by the proposed test. No truncated-action surrogate or refusal test was added to imitate prefix metering. These gaps require an independent ABI/work observation contract before full trace certification.

Canonical Program/hash, native statement/ABI/relation/circuit identities, target/anchor/authorization, authenticated history/time and external/service/DUST/native costs remain unresolved or unmeasured. The test has no target or artifact consumer and no Core/2 continuation behavior. Successful future execution would establish only this finite public Core/1 financial projection, not proof, ledger, financial-family conformance, complete U2 walkthroughs or a language exit.

Verification performed here consists of frozen-packet checksum verification and source readback against the exported DTO/function declarations in the current allowed checkout.
