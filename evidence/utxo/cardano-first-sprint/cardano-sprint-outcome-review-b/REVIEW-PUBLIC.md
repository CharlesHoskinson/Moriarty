## Requirement defects requiring correction

**1. CS01/CS08 — the calibrated sibling has no defined audit status (circularity unresolved).** CS01 states the sibling changes source/program identities; CS08 stops native action when "candidate source changes"; Task 5 says dynamic outputs "instantiate the audited emitter" and that source edits do not inherit audits. It never states whether the runtime-generated sibling (new source hash, program hash, blueprint) requires a fresh full audit before Cash mint/head-open, or whether deterministic generation by the audited emitter plus hash re-verification is sufficient. As written, an implementer can either deadlock (sibling appears only after post-audit bootstrap/parity) or spend against an unaudited program. *Correction:* add an explicit clause: either (a) sibling artifacts are frozen, hashed, and re-audited by both auditors before any mint/sign/submit, or (b) the two audits must approve the deterministic substitution function and Task 5 must verify sibling hashes equal the audited function's output on the admitted bounds before funding. Pick one and make it normative.

**2. CS02/CS04 — the proposed interfaces cannot distinguish a UNIT-issued context from a production one.** `bindProductionContext` and `measureProductionBody`/`assertProductionBody` carry no `evidenceClass`/`ledgerExecution` field, and `assertProductionBody` returns `submitEligible:true` on byte/identity equality alone. Task 2 instructs verifying "positives … through runNativeCaller" offline and then replacing `PRODUCTION_FINANCIAL_CONSUMER_INCOMPLETE` with checked eligibility. A structurally perfect UNIT measurement would satisfy the stated interface and become submission-eligible, contradicting "a constructed genuine receipt is not a valid offline positive" and CS08's rule that UNIT controls remain unconfirmed. *Correction:* bind the provenance class into the context and receipt (hash-bound, not a caller flag), and require `assertProductionBody` to refuse any context not issued from authentic capture/query even when all bytes match. State that offline positives validate measurement arithmetic only and must return `submitEligible:false, ledgerExecution:false`.

**3. CS03/CS06 — "settled" and "finality" have no testable criterion.** CS03 lets "only its queried settled output" fund head-opening, and CS06 requires "named chain confirmation evidence" while denying that query presence is finality — but neither defines inclusion depth (e.g. containing block plus N confirmations, k=security parameter, or a named block/tip relationship). Every downstream gate (mint→head, head→terminal, race winner, CS09/CS10 exit) inherits this ambiguity, so two honest implementations can disagree on the same evidence. *Correction:* define one named confirmation rule for intermediate dependencies and one for final settlement (they may differ), expressed in blocks/slots against the queried tip, and require the receipt to record block hash/height and tip at confirmation.

**4. CS10 — Preview exit is not yet executable or auditable as specified.** No existing resource authority, faucet/test-ADA source, per-transaction or aggregate fee ceiling value, or endpoint binding is named; the spec defers these as "execution dependency" but the exit matrix still treats Preview as a pass/fail row. There is also no explicit Preview V3 clock-parity/sibling step analogous to the local capture, although CS01 time substitution and CS10 genesis/magic rebinding both apply, and no funding plan for four fresh instances (release, refund, cancel, race) plus collateral. *Correction:* before Task 5 Preview, record the concrete authority reference, fee ceiling (lovelace, per-tx and total), faucet source, endpoint/config identity, the Preview parity/sibling procedure, and per-instance funding amounts; mark the row blocked-by-dependency until those exist.

**5. CS07 — the valid loser-evidence cases are under-specified.** The requirement demands the "original losing submit/outcome BadInputsUTxO receipt," while the only scenario covers both submits accepted into mempool (then incomplete). It does not state that a `BadInputsUTxO` rejection returned at the loser's own original submission is a complete, valid loser receipt — the common case — nor how to classify a loser accepted then silently dropped (no receipt ever exists). *Correction:* enumerate three exhaustive outcomes: submit-time `BadInputsUTxO` on an original body = observed loser; exactly one body confirmed with full post comparison = winner; anything else (both pending, loser vanished without receipt, both confirmed-impossible ambiguity) = incomplete, no third submit.

**6. CS04/CS05 — enumerated refusal variants lack matching planned tests.** CS05 requires refusal for missing/null/noncanonical/negative/out-of-UInt128 redeemer amounts and requires required obligation quantities not to default to zero; Task 3 tests only "amount-null." CS03 requires Cash seed ≠ head seed and refusal for staked, script-locked, wrong-network, or closed-fixture seeds; no planned test names the same-seed case or the staked/script seed cases (generic "seed substitution" does not cover seed *equality*). CS04 requires freshness of "current" protocol/UTxOs, but no test covers tip advancement or seed/fee/collateral spend between measurement and signing. *Correction:* add one named negative per variant, each asserting no encode/sign/submit call and `ledgerExecution:false`.

## Insufficient test definitions to add

- UNIT-issued but byte-perfect context/body → `assertProductionBody` refuses, `submitEligible:false` (per defect 2).
- Sibling generated from admitted bounds, then any sibling hash/blueprint byte altered → funding refused before mint (per defect 1, under whichever audit rule is chosen).
- Mint output present in query but below the defined confirmation depth → head-open refused; at depth → accepted (per defect 3).
- Loser rejected at original submit with `BadInputsUTxO` → race complete with full winner comparison; loser accepted then dropped with no receipt → race incomplete, `submitCount === 2` (per defect 5).
- Redeemer amount: missing, null, noncanonical encoding, negative, and >UInt128 each refused distinctly; obligation quantity absent ≠ zero.
- Cash seed equal to head seed; staked seed; script-locked seed; wrong-network seed → funding refused with no mint acceptance reported.
- Protocol/UTxO drift (tip advance or input spent) between `measureProductionBody` and signing → prior receipt invalidated, re-measurement required.
