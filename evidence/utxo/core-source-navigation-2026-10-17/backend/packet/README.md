# Current Rust Cardano backend source map (packet v2)

This version extends the separate v1 map with `S16-circuit.rs`, whose pinned bytes supply the `compile_source` body. V1 remains unchanged. The packet is pinned at HEAD `54fc7a1a54106245abb1a5ef6e16407464e1b654`; hashes and packet-relative recovery paths are in `SOURCE-MANIFEST.json`. This graph is source navigation only, unreviewed and unpublished. It makes no runtime, proof, ledger, semantic-equivalence, or security claim.

The ordinary driver paths remain `mori-k2` → `main` → `run` → compile or inspect. Both branches read source, parse a selector/request, and call `relation::compile_selected`. That function checks the selector and calls `mori_r1cs::compile_source`. The newly supplied body calls `frontend::admit_source` and branches: `Admitted::Core1` calls `compile`, while `Admitted::Staged2` constructs a staged lowering plan for the refusal result. The Core1 compile path calls `options.compiler.checked`, `adapter.admits`, conditionally `abi2::options_ok`, `plan::plan_action`, `StatementLayout::build`, conditionally `abi2::constants`, and `probe`. `probe` calls `synthesize`, which calls `lower::lower_action`. These are literal source call-site relationships; the graph does not interpret their correctness or security.

The supplied admission body directly calls `mori_core::language`, `mori_core::parse`, `mori_core::stage::load`, `stage::require_core1`, and `mori_core::validate`. Their Core implementations are outside the packet, so navigation stops at those named boundaries. The bodies for `options.compiler.checked`, `adapter.admits`, `abi2::options_ok`, `StatementLayout::build`, `abi2::constants`, and `staged.lowering_plan` are also not included. `plan_action` and `lower_action` are identified by their supplied definitions, but this map does not expand their internal behavior.

The invoice and reserve specimens remain linked only by literal command paths and action strings in the README, source, selectors, and requests. No UTxO-family mapping is made. The source README’s dated experimental/proof statements remain quoted, scoped source assertions; later receipts are not overridden and no global absence claim is made.

Extraction re-verified all 16 source lengths and SHA-256 pins before writing. Each call/data edge carries a source ID, packet-relative file, line, literal excerpt, `EXTRACTED` classification, and confidence. README prose and command examples are marked as quoted source assertions. No source was imported or executed; no build, test, cryptographic, wallet, ledger, network, or Git operation was performed.
