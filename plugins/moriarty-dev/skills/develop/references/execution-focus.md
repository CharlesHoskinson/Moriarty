# Profiles and consumers reference

Technical reference only. Process lives in the checkout's `AGENTS.md` (the factory
loop); this file grants or blocks nothing.

| Profile or consumer | What must remain explicit |
|---|---|
| Rust Core | `moriarty/1` source and `moriarty-core/1` semantics; parser/checker/evaluator and supported public compiler path |
| Node beta | Separate Source/6 bridge to experimental TypeScript Core/5; local `PreparedUnqualified` is not Rust compilation or target qualification |
| `mori-backend` and `mori-ledger` | Different statements and admitted subsets; compare only through an explicit common-subset adapter and justified refusal boundaries |
| Public executables and tools | Resolve which `mori` executable is used; Rust LSP/MCP remain reported stubs until implemented |
| Static call export/reopen | Deterministic public serialization/reopen is static evidence; mapped-role mode remains unauthenticated, unproven and uninstalled |

A successful check or reference test in one profile does not establish compilation in
another. Map admitted grammar, numeric scope, evaluation order, positional versus
trailing postconditions, present-zero versus absent duties, field representation and each
actual consumer. Do not unify lowerings merely because both emit ZKIR.

Expected financial values must not import the evaluator or compiler under test. Include
ordered effects, affected and preserved state, gross debit, fees, net receipts, reserve
dust, opening/accrued/discharged/closing liabilities and residual duties. Separate logical
work schedules from circuit cost, DUST, service fees and recovery reservations.

Preview observations qualify only Preview. Fenrir network ID, Anchor, committee/registry
identities and target tuple stay unknown where unestablished; invent no version or
configuration.
