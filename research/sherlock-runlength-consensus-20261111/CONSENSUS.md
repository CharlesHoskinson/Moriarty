#### 1.1.1 Direct Answer to the Owner's Questions (`BRIEF.md:6-7,14`)
- **Why there is no `2^64` circuit:** Every circuit in Sherlock has a small, fixed power-of-two domain fixed once at key generation and independent of run length:
  - Universal chip leaf `U` (`S = 16` steps): `k_leaf = 16` (`65,536` rows, `65,530` usable rows; `6,511` rows at `k = 13` in the 6-rule E8 spike, `openspec/changes/sherlock-vm-consensus-20261107/design.md:129`; `k_leaf = 17` only if high-burst `N_page = 8` is chosen in 4-arena mode).
  - Self-recursive node (`SHKIVC06` / `R` / `N`): `k = 20` (`1,048,576` rows; `823,466` rows over the E8 leaf key, `design.md:130`).
  - Run decider (`SHKRUND1` / `D`): `k = 20` (`929,166` ordinary rows / `1,032,467` table rows, `design.md:131`, `research/sherlock-c6-outcome-ledger9-review-20261110/review.md:213`).
  A `2^64`-row KZG table (`ESTIMATE ~590 EB` per column) never exists; unexecuted steps never allocate rows or witness data.
- **What `2^64` actually is (`SRC-004`):** In `crates/mori-recursion/src/ivc.rs:77-79,359-376` (`H_BITS = 64`, `constrain_heights`), Halo2 constraints operate over the BLS12-381 scalar field of prime order $r \approx 2^{255}$. Without an integer range check on `prev_h`, `steps`, and `h = prev_h + steps`, a malicious prover could pick `prev_h = r - 1` and `steps = 1` so `h ≡ 0 (mod r)`, re-triggering `is_genesis = 1` mid-run or forging `n_steps` (`clean/fork/Clean/Sherlock/Aggregation.lean:1208-1213`, theorem `unchecked_prev_wraps_to_genesis`). Enforcing `prev_h < 2^64`, `1 <= steps <= S`, and `h < 2^64` (`Aggregation.lean:1196-1206`, theorem `src004_height_bridge`) costs `~24–50` rows inside the `k = 20` node (`73` rows for all `SRC-004` + `SRC-005` checks combined, `qa/sherlock/decisions/speed-levers.json:31`) and plays the exact same role as a 64-bit unsigned cycle register (`u64`) in hardware.
- **Why `2^64` steps is physically impossible:** At `S = 16` on this host (`ESTIMATE ~4.28 s/step` sequential), proving `2^64 = 1.845 × 10^19` steps would take **`ESTIMATE ~2.50 × 10^12` years** (`~181×` the age of the universe) and emit **`ESTIMATE ~11.82 ZB`** of `SRC-019` bundle proofs; even unproved native execution at `1` step per clock on a `4.004 GHz` Cortex-X925 core takes **`ESTIMATE 146.0` years**.
- **Unanimous 5/5 rejection of sub-`2^64` memory or leaf caps:** Widening dense 8-cell segment memory from `D3`'s `TOP = 17` (`2^20` padded cells) or `TOP = 32` (`2^35` cells) to **`TOP = 61` (`2^61 × 8 = 2^64` dense cells)** fits inside the **same `k_leaf = 16` domain** (`<= 65,530` usable rows), adding `ESTIMATE +4..+12` node rows (`0.001%`) and `+0` decider rows (`research/sherlock-recursion-design-review-20261110/experiments/e2-e4.md:25-35`). Every step counter (`h < 2^64`), heap-cell counter (`len < 2^64`), and `GP-4` claim occurrence counter (`n_claims < 2^64`, closing `Exploit E-1` on `research/sherlock-gp-architecture-20261110/architecture.md:100`) therefore shares one uniform `< 2^64` non-wraparound invariant, with **zero sub-`2^64` single-run ceilings and zero escape clauses**.

#### 1.1.2 Honest Three-Part Meaning of "Unbounded" Under Fixed Keys
1. **Key, Circuit & On-Chain Proof Universality (`O(1)`):** One fixed key set (`{U, R, F, N, C, D}` / `{leaf, node, decider}`) and one deployed verifier contract accept every admitted Sherlock program, on every valid input, for every outcome (`Halted(v)`, `Rejected(code)`, `Exhausted(kind)`). No proving key, verifying key, SRS, final proof byte length (`6,432 B`), or on-chain verification cost encodes any program-size, input-size, stack-depth, heap-size, leaf-count, or step-count capacity constant (`general-purpose.md:9-13`).
2. **Uniform 64-Bit Non-Wraparound Guards (`< 2^64`) with Zero Spin-Loop Address Burn:** Step height (`h < 2^64`), heap-cell frontier (`len < 2^64` via `TOP = 61`), and aggregated claim counts (`n_claims < 2^64`) enforce 64-bit unsigned integer bounds strictly to prevent finite-field wraparound modulo $r$; non-allocating compute steps and LIFO stack operations consume `0` heap cells.
3. **Linear Prover Scaling (`O(n_steps)`), Constant Streaming Memory (`O(1)` RSS), and Explicit Qualification Bounds (`SAS-001`):** A run of $N$ executed steps folds $\lceil N / S \rceil$ fixed-size leaf proofs in $O(N)$ total prover work ($O(\log N)$ parallel tree depth under `GP-4`) and $O(1)$ active prover RSS (or across multi-session continuation epochs under `GP-2` and `GP-4`), bounded in practice only by caller-supplied `fuel`/`stack_limit` in `input_d` and host wall-clock/storage budgets. Empirically tested step and allocation bounds are recorded separately in `SAS-001` / `SAS-012` (`requirements.md:65,76`), never conflating a 64-bit counter guard with a `2^64`-step execution claim.

### 1.3 Agreed Answer to `Q3`: Two-Tier Continuations, Canonical State Digest, `orig_input_d`, `CONT-FOLD` Aggregation, and C6 Outcome-Only Privacy

All five lanes agree on a two-tier continuation architecture that preserves 100% C6 outcome-only privacy (`SRC-006`, `SRC-007`) and closes every red-team attack (`Exploits E-1, E-2, E-6, E-8, E-9, E-10`):

1. **Tier 1 — Intra-Run Segment Recursion (`U -> R -> N -> D`, Default for All Single-Session Runs `< 2^64` Steps):**
   - Under `Q2(d)`, `state_d(h)` at step height `h` is a deterministic, partition-independent function of `(prog_d, input_d, h)`.
   - Any single-session run of length $1 \le N < 2^{64}$ folds $\lceil N / S \rceil$ leaves directly via linear IVC (`ivc.rs:360-376`) or `GP-4` binary tree (`architecture.md:75-85`, `R` lifting `U + U -> SEG` and `N` merging `SEG + SEG -> SEG` with `L.post_d == R.pre_d` and `0 <= L.h_lo < L.h_hi == R.h_lo < R.h_hi < 2^64`).
   - All intermediate `state_d(h)` digests are erased inside recursion before `RunDecider` seals `[prog_d, input_d, outcome_d, n_steps]`, requiring **`0` heap-serialization rows and `0` `UNFOLD` steps**.

2. **Tier 2 — Cross-Session / Multi-Epoch Continuations (`SHK_CONT_V1` + `CONT-FOLD` / `CONT_JOIN` Cut-Elimination in `N`):**
   When an operator checkpoints and resumes a multi-day computation across $M$ proving epochs ($k = 0, \dots, M - 1$) — or suspends across transactions in future profile `/2`:
   - **Orthogonal Cut Trigger (`quantum_steps`, Never `fuel` — Closing `Exploits E-2, E-6`):** All five lanes reject triggering continuations via `remaining_fuel == 0` or `WithFuel(in_0, fuel_a + fuel_b)` because `Init` sets `initial_fuel = fuel` (`design.md:229-230`), observable inside the VM, and hijacking `remaining_fuel == 0` makes terminal `Exhausted(Fuel)` (`H(O, 1, 2, 0)`) unreachable (`GP-1` violation) or allows truncated-fuel prefix settlement. Instead, epochs cut at deterministic logical step intervals `[h_lo, h_hi)` (`epoch_steps == quantum_steps`), leaving `initial_fuel`, `remaining_fuel`, and `consumed_work` untouched inside the checkpointed state.
   - **What `input_d` Is Across the Chain:** Every epoch $k \in \{0, \dots, M - 1\}$ carries the **unmodified genesis `orig_input_d = Poseidon(SHK_IN, val_d, fuel_lo, fuel_hi, stack_limit)`** (`SRC-021`, `requirements.md:46`).
   - **Disjoint Internal Continuation Claim (`"SHK_CONT_V1" != "SHK_RUN"` — Closing `Exploit E-8`):** Non-terminal epochs never emit `Halted(...)` or `SHK_RUN` claims. Each epoch emits an internal recursive claim:
     $$\text{cont\_claim}_k = \text{Poseidon}\bigl(\text{"SHK\_CONT\_V1"}, 1, \text{vk\_id}, \text{prog\_d}, \text{orig\_input\_d}, h_{\text{lo},k}, h_{\text{hi},k}, \text{pre\_ckpt\_d}_k, \text{post\_ckpt\_d}_k, \text{status}_k, \text{deps\_d}_k\bigr).$$
     `RunDecider` (`SRC-006`), `acceptRun` (`SRC-007`), and `GP-002` cross-run value consumers strictly reject `"SHK_CONT_V1"` and any `Running` status, preventing premature settlement or state-digest injection.
   - **Partition-Independent Checkpoint Digest (`ckpt_d`) & Mandatory `ALU` Range Guards (Closing `Exploit E-10`; Dissent `D-Q3.1` on Mode 1 vs Mode 2):**
     - *Mode 1 — Retained-Arena Physical-Canonical Digest (`canon_state_d(h)`, supported by 4/5 Lanes `A, B, C, D` as fast path):* When the resuming session retains the dense `M3-Tail64` arena store, `ckpt_d = canon_state_d(h)` commits `(regs_canon, fp_hash, tp_hash, arena_commitments)` in $O(1)$ (`0` `UNFOLD` rows), partition-independently (`SRC-023`).
     - *Mode 2 — Address-Free Structural Checkpoint (`sherlock-ckpt/1` `ckpt_d` + Range-Checked DAG-Memoized Lazy `UNFOLD`, agreed by all 5/5 Lanes for GC compaction, `/2` async, and closing `SRC-021` `[OPEN]` non-scan `val_d` input admission; sole Tier-2 mode in Lane `E`):* Folds live registers (`initial_fuel`, `remaining_fuel`, `consumed_work`, `stack_limit`, `AllocCounters`), `env`, `FRAMES`, and `TASKS` using creation-time `sherlock-value/1` digests `vd` (`SVM-012`, `O(live roots + stack depth)`, zero dead-heap scan, zero physical addresses). On resume (or at `h_lo == 0` for `SRC-021` `val_d`), `SEALED_VAL(vd, ty_d)` handles unfold 1 level on first inspection (`ESTIMATE ~210–280` rows/node) with: (i) **segment/epoch `vd -> local_addr` memoization** preventing $2^d$ blowup on shared DAGs; (ii) **mandatory `u128`/`u64`/boolean `RANGE` checks on every materialized scalar** (closing `Exploit E-10`, where `crates/mori-chip/src/alu.rs:6-9,111-125` `OP_LT` checks `y - 1 - x < 2^128` without re-range-checking operands); and (iii) **`UNFOLD` forbidden inside `BuildEntry..BuildExit` or `AppendEntry..AppendExit`** so single-arena `SI-12` slice contiguity holds unconditionally.
   - **Transitive In-Circuit Ancestry & Single On-Chain Settlement (`CONT-FOLD` / `CONT_JOIN` in `N`, `ESTIMATE ~250–350` node rows — Closing `Exploits E-1, E-9, E-10`):**
     - Node rule `CONT-FOLD` merges adjacent `SHK_CONT_V1` claims by verifying identical `(vk_id, prog_d, orig_input_d)`, exact boundary stitch `L.post_ckpt_d == R.pre_ckpt_d`, strict monotonic height `0 <= L.h_lo < L.h_hi == R.h_lo < R.h_hi < 2^64` (blocking state cycles `E-9` and height wrap), and `< 2^64` on `SET.n_claims` (`Exploit E-1` diamond-DAG wrap closed), erasing intermediate `(h_mid, ckpt_mid)` in $\lceil \log_2 M \rceil$ tree depth.

#### 1.4.1 Four Cross-Segment Memory Paradigms and Why Boundary-Merkle (`Q2(d)`) Is Required on Sherlock's Stack
1. **Boundary-Merkle Continuation (`RISC Zero v3.1`, `OpenVM v2.1`, `SP1 v6 dev`, `Nexus 1.0/2.0`, Sherlock `M3-Tail64`):** Authenticates inter-segment memory via a fixed-depth Poseidon/Poseidon2 Merkle root (`pre_root -> post_root`). Requires **zero Phase-2 user challenge columns** (`crates/mori-recursion/src/verifier_gadget.rs:16-17` enforces `num_challenges <= 1` on `midnight-circuits 7.3.0`), achieves **$O(1)$ genesis and halt** without $O(|M|)$ memory sweeps (`SRC-021`), and produces self-contained segment statements ready for arbitrary `GP-4` binary-tree / DAG folding.
2. **Global Offline Multiset / Elliptic-Curve Sum (`SP1 v4–v6.10 main`, `Ziren v2.0`, `Brevis Pico v3.1`, `Valida v1.0`, `ZKsync Airbender`, `Polygon ZisK`, `Lambda VM`, `Spice/Nebula`):** Sums cross-shard `(addr, val, ts)` tuples over $\mathbb{F}_{p^7}$ `SepticCurve` or persistent LogUp buses. 3. **Full-Column KZG Commitment Chaining (`zkWasm`, `Sharded Twist` `ePrint 2025/105` §2.9.3):** Enforces `C_post_img == C_pre_img` in $\mathbb{G}_1$, paying $O(|M|_{\max})$ prover rows on *every* slice (`<= 31.2 MiB` KZG RAM in zkWasm at `k = 22`) and capping steps at `eid: u32` (`2^32 - 1`).
4. **Monolithic Streaming / Write-Once Relocation (`Jolt Twist+Shout`, `Cairo/Stwo`, `Miden VM`, `Nexus 3.0 Stwo`, `Binius64/Ligerito`):** Proves one bounded trace without mutable-RAM continuations (capped by streaming sumcheck $T$, M31 circle group $\le 2^{30}$, or Goldilocks `MAX_CYCLES = 2^29`), extending via recursive bootloaders/kernels (`Cairo PIE`s, `Miden` Tx/Batch/Block).
