## Findings

### F1 Program canonicality needs an enforced admission boundary
- Category: soundness
- Severity: major
- Step(s): 1, 3, 5, 7
- Evidence: `research/sherlock-final-design-20261111/ARCHITECTURE.md:1097`: “`ty_d` and constant `vd` in ROM are trusted only through the PROG canonicality premise”; the same row says “No circuit mutant (premise).” `research/sherlock-final-design-20261111/ARCHITECTURE.md:2276`: “PROG canonicality is not proved here: it is a premise on `prog_root`,” with a host differential as its present check. `openspec/changes/sherlock-vm-consensus-20261107/design.md:195`: “Constants carry `vd` under the PROG canonicality premise. Halt copies the `vd` of the result.” `research/sherlock-final-design-20261111/ARCHITECTURE.md:1744` lists SEAL’s genesis, terminal, dependency and digest checks without a program-admission certificate. `research/sherlock-pipeline-animation-20261111/council/bundle/STORYBOARD.md:2255`: “The contract receives `prog_d` as call data.”
- Problem: ROM membership proves that the prover used the committed rows; it does not prove that those rows have consistent semantic annotations. For example, an attacker can commit an image whose constant payload represents `UInt 0` but whose cached `vd` represents `UInt 1`. Under the specified constant path, membership authenticates the inconsistent row and publication copies its cached digest. Neither hash collision resistance nor correct execution of the recursive verifier repairs that inconsistency. The universal acceptance path needs to establish the canonicality premise for the supplied program. This is a missing acceptance condition, not merely an unfinished Lean proof.
- Proposed revision: Add a PROGRAM ADMISSION kit and a mandatory certificate binding `prog_d`, `prog_root`, entry metadata, layout/profile identity and the canonical interpretation of the ROM tables. Its relation must check constant digests, type digests, constructor metadata, references and canonical padding. Check this certificate before a run can settle, and carry that obligation through both ordinary and dependency-aware sealing. Bind the certificate to the exact program of the execution segment. Make admission recursive and reusable across runs, under fixed keys; do not substitute a trusted compiler or a per-program allowlist.
- Cost of the revision: Work proportional to the admitted image, amortizable across runs; fixed-size certificates and additional recursive verification work. Kits touched: new PROGRAM ADMISSION, INIT, PAGE/ROM, VALUE DIGEST, NODE INTEGRATION and DECIDER. No exact row count follows from the bundle.

### F2 Wide input constructors have no legal authentication schedule
- Category: generality
- Severity: major
- Step(s): 1, 2, 3, 4
- Evidence: `research/sherlock-final-design-20261111/ARCHITECTURE.md:1411`: a constructor is opened “one field per call,” but “the fields are bound to `vd` only when the completion hash equals `vd`, and a rule may use a field only after that completion.” `research/sherlock-final-design-20261111/ARCHITECTURE.md:2264–2266` require no input-size bound, bounded authentication work and the reference owner-event count. `research/sherlock-final-design-20261111/ARCHITECTURE.md:599–605` require an enabled first slot, one reference rule per enabled slot, identity for disabled slots, and one counted step per enabled slot. `research/sherlock-final-design-20261111/ARCHITECTURE.md:619`: “Early close cannot repair a step that does not fit an empty leaf.” `openspec/changes/sherlock-modular-leaf-20261111/specs/sherlock-node-integration/spec.md:48` permits only the eight listed node modes.
- Problem: The input-opening fold has bounded individual calls, but the design supplies no execution mode in which arbitrarily many such calls can occur before the reference event that needs the field. A wide constructor supplied as input has no preceding construction events in this run to perform its fold. For a field read during matching, doing the entire opening inside that event makes its circuit work depend on constructor width. Spreading the opening across ordinary slots introduces extra reference steps; using disabled slots violates their identity rule. Closing leaves does not advance the fold. Thus “one field per call” alone does not provide a complete schedule under fixed keys and unchanged reference accounting.
- Proposed revision: Add administrative value-authentication work that produces a certificate binding the existing canonical `vd`, type/constructor information and an authenticated read view of the fields. Build the constructor fold in bounded recursive units, outside owner-step accounting. Bind the read-view root to the run and require its certificate before settlement; CORE may use a field only through that certified view. Specify ownership of pending authentication, completion and field retention. Preserve `sherlock-value/1`, unrestricted constructor arity, reference fuel and `n_steps`.
- Cost of the revision: At least O(m) authentication work for an m-field constructor under the existing fold encoding, spread over fixed-size proofs. Adds an administrative statement/mode and a certified-read interface. Kits touched: INIT, VALUE DIGEST, CORE, BOUNDARY COMMITMENT and NODE INTEGRATION. Authentication storage must also be covered by continuation handling.

### F3 Foreign-verifier phases need authenticated operand storage
- Category: gap
- Severity: major
- Step(s): 4, 7
- Evidence: `research/sherlock-final-design-20261111/ARCHITECTURE.md:2164` fixes the continuation digest as `H(SHK_FV, entry_d, phase, cursor, transcript_d, acc_d, pi_d, consumed_d)`, describing `acc_d` as partial arithmetic sums and `consumed_d` as a running digest of consumed proof elements. `research/sherlock-final-design-20261111/ARCHITECTURE.md:2170–2172` assigns typed element outputs to FV-PARSE, challenge outputs to FV-TRANSCRIPT, and “elements, challenges” as inputs to FV-ARITH. `research/sherlock-final-design-20261111/ARCHITECTURE.md:2179` promises that every unit continues its predecessor’s committed state. `openspec/changes/sherlock-modular-leaf-20261111/specs/sherlock-foreign-verifier/spec.md:4` repeats the fixed continuation schema and bounded-unit requirement.
- Problem: The phase interfaces pass cells, but cells from an earlier proof unit are unavailable in a later unit unless the continuation authenticates their recovery. The specified state does not provide an indexed operand store or an opening protocol for earlier commitments, evaluations and challenges. A running digest of consumed bytes is not such a protocol. For example, a commitment absorbed before a challenge must later be the same commitment used in the opening equation. Reintroducing it as a fresh witness leaves that connection unspecified; rehashing the whole consumed prefix in one unit defeats bounded work. The same seam must retain verifier intermediates across unit cuts. This is an interface omission independent of the unmeasured operation budget.
- Proposed revision: Add an authenticated verifier work-memory root and a versioned schema for phase-local registers to `fv_state_d`. FV-PARSE must write canonical typed elements at constrained indices; transcript processing must bind challenge records to its checked state transitions; FV-ARITH and FV-FINAL must read those records through authenticated addresses. Include any later-used verifying-key data under the registered `vk_d`. Assign the memory/history contract and cross-phase handoff to FV-SCHED, with explicit initialization and completion rules. Alternatively, specify a bounded replay protocol that establishes the same equalities.
- Cost of the revision: One additional commitment in the continuation plus bounded authenticated reads/writes and phase-state hashing. Total storage and proving work grow with verifier work; final proof size remains constant. Kits touched: FV-SCHED, FV-PARSE, FV-TRANSCRIPT, FV-ARITH, FV-FINAL and the FV-WORK interface of NODE INTEGRATION.

## What the design gets right

- **Step 3 — CORE and MEM:** The append-address chain supplies the one-to-one property that membership lookup cannot establish. `research/sherlock-final-design-20261111/ARCHITECTURE.md:118`: “Set inclusion does not prove that an append happened once.”
- **Steps 3–5 — BOUNDARY COMMITMENT:** The header/body split gives sealing an authenticated, bounded-cost opening without rehashing the entire machine state. `research/sherlock-final-design-20261111/ARCHITECTURE.md:1582`: the header hash is asserted equal to authenticated `post_d`.
- **Step 4 — NODE INTEGRATION:** MERGE checks program identity, boundary equality and interval adjacency separately. `research/sherlock-final-design-20261111/ARCHITECTURE.md:1743`: “equal `prog_d`; `L.post_d == R.pre_d`; `L.h_hi == R.h_lo`.”
- **Steps 4–5 — NODE INTEGRATION and DECIDER:** Deferred verification obligations remain explicit through settlement. `research/sherlock-final-design-20261111/ARCHITECTURE.md:1772`: every enabled child’s carry and new obligation are folded; `:1850`: “every accumulated obligation reaches the pairing.”
- **Steps 7–8 — GP-4 and DECIDER:** Collection shape does not create a second replay identity or an occurrence-count limit. `research/sherlock-final-design-20261111/ARCHITECTURE.md:2103` specifies JOIN with “no counter, no range check”; `:2109` states that acceptance, replay and consumption never use `shape_d`.
