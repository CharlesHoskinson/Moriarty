### F1 Untrusted `prog_d` call data paired with unproved ROM value and type digests lets a prover forge `outcome_d` and nominal types
- Category: soundness
- Severity: blocker
- Step(s): 1, 3, 6, 7
- Evidence:
  - `research/sherlock-pipeline-animation-20261111/council/bundle/STORYBOARD.md:2255`: `"The contract receives prog_d as call data, a value carried by the invocation. One contract and one key set serve every program and every input, so the program identity selects no contract and no verifier key."`
  - `research/sherlock-final-design-20261111/ARCHITECTURE.md:2754-2755`: `"Options: (a) two templates: acceptRun(prog_d, input_d, outcome_d, n_steps) with prog_d as call data, and a claims contract with root acceptance and claim opening for batches and DAGs (G:1190); (b) the claims contract only."` / `"Recommendation: (a), with prog_d as call data for the GP-1 contract"`
  - `research/sherlock-final-design-20261111/ARCHITECTURE.md:1400`: `"ROM rows: AuthRom with tbl = tbl_types for ty_d, tbl_ctors for the ordinal and arity, tbl_consts for the constant vd. All are under the PROG canonicality premise (provider: the program admission claim of O/design.md:84, OD-14)."`
  - `openspec/changes/sherlock-vm-consensus-20261107/design.md:195`: `"Constants carry vd under the PROG canonicality premise. Halt copies the vd of the result."`
  - `openspec/changes/sherlock-modular-leaf-20261111/specs/sherlock-chip-page-cache/spec.md:37`: `"ROM SHALL trust row content only through the PROG canonicality premise (OD-14)."`
  - `research/sherlock-final-design-20261111/ARCHITECTURE.md:2276-2277`: `"PROG canonicality is not proved here: it is a premise on prog_root, and its provider is the program admission claim of O/design.md:84, whose form is open (OD-14, OWNER)"` / `"Not provided: a proof that the program is well typed or admitted"`
  - `openspec/changes/sherlock-vm-consensus-20261107/requirements.md:47`: `"The published outcome of a run SHALL be outcome_d = H(O, 1, 0, vd(v)) for Halted(v) ... The proof SHALL authenticate every value record, constructor ordinal, field position and child digest used to compute vd."`
- Problem: In the per-program milestone contract, `program_d` was fixed at contract deployment, so trusting ROM rows affected only an owner who deployed a malformed `program_d`. In the universal GP-1 pipeline (`STORYBOARD.md:2255`, `ARCHITECTURE.md:2754-2755`), any caller supplies an arbitrary `prog_d` as call data to `SherlockRun.acceptRun` (or inside a `SET` collection), while no step in Scenes 1-8 checks or proves that `prog_root` inside `prog_d` is canonical. Two concrete attacks follow:
  1. Direct `SRC-022` forgery on `acceptRun`: an attacker constructs a two-row ROM `prog_root` whose entry expression `Expr(0)` returns `Const(0)` and whose `tbl_consts[0]` row stores a dummy payload alongside an arbitrary field element `X` in its `vd` column (either a non-value `Fq` element or the digest of a different value, bypassing scalar range checks and constructor fold checks). `INIT` checks only that `prog_d` opens to `prog_root`, `PAGE/ROM` authenticates the Merkle path of `tbl_consts[0]` under `prog_root`, `VALUE DIGEST` trusts `tbl_consts[0].vd = X`, and halt copies `X` into `outcome_payload`. `SherlockRun.acceptRun` accepts `outcome_d = H(O, 1, 0, X)` as a valid `Halted(v)` claim on chain, violating `SRC-022`.
  2. Cross-program GP-2 type-digest spoofing: `ty_d(T)` is program-independent (`openspec/changes/sherlock-vm-consensus-20261107/design.md:190`) so a consumer program `B` can accept nominal `Constructor` values produced by program `A` via `SEAL-WITH-DEPS` (`ARCHITECTURE.md:1984,1987`). A malicious producer `prog_A` can place a forged `ty_d(T)` in `tbl_types` (or a forged `vd` claiming `ty_d(T)` in `tbl_consts`, or a wrong `(c, arity)` in `tbl_ctors`), halt with `outcome_d' = H(O, 1, 0, vd_forged)`, and feed that ill-typed or impossible `Constructor` digest across `in_link` as `val_d` of an honest consumer `prog_B`.
- Proposed revision: Remove unverified trust in ROM value and type digests under universal `prog_d` by adopting both parts below:
  1. Drop the trusted `vd` column from `tbl_consts` (or treat it as an untrusted hint) and require `CORE` + `VALUE DIGEST` to verify `open_value_node` on constant reads (checking `n < 2^128` for `UInt`, boolean `b` for `Bool`, and child `vd` hashes from `tbl_consts` indices `< row` in topological order), so `SRC-022` holds inside `LEAF` for any `prog_d` without an external admission proof.
  2. For nominal `Constructor` rows (`tbl_types`, `tbl_ctors`), either compute `ty_d` in-circuit when a `Constructor` is built/opened from bounded schema rows in `tbl_types`, or define an explicit `SHK_ADM` program-admission claim `H(SHK_ADM, 1, prog_d)` proved once per `prog_d` by a bounded recursive ROM-walk relation under the same universal key set and required as a `DL` dependency in `SEAL` / `SEAL-WITH-DEPS` whenever `tbl_types` is non-empty.
- Cost of the revision: Part 1 touches kits `PAGE/ROM`, `CORE`, and `VALUE DIGEST`; zero extra rows on steps that do not read a constant, and one existing `VALUE DIGEST` sponge slot (already budgeted per step) when reading a constant. Part 2 touches `VALUE DIGEST` or `GP-2 hook` + `NODE INTEGRATION`; amortizes program admission to once per distinct `prog_d` while preserving universal keys and a single contract (GP-1).

### F2 Unconstrained `reg_root` across binary node children, unverified `reg_root` in `decide_run`, and split `SEAL` ownership between `NODE` and `DECIDER`
- Category: soundness
- Severity: blocker
- Step(s): 4, 5, 7, 8
- Evidence:

  - `openspec/changes/sherlock-modular-leaf-20261111/specs/sherlock-node-integration/spec.md:36-46`: `NODE-004` specifies `en_j`, `key_sel_j`, key representations, and neutral carries, and omits `reg_root` equality and any `reg_root` mismatch mutant across lines `1-70`.
  - `research/sherlock-final-design-20261111/ARCHITECTURE.md:1842-1844`: `"Requests: the root proof and its instance (M4 path: the root SEG of the linear node, opened in the decider as run_decider.rs does today, G:73; GP path: a SET root, optionally through a closing proof, section 4.2, N-5)"` / `"Provides, run entry: exactly [prog_d, input_d, outcome_d, n_steps] (SRC-006)."` / `"Provides, collection entry: [reg_root, set_root, shape_d], no claim count"`
  - `research/sherlock-final-design-20261111/ARCHITECTURE.md:1978,1981,1984`: `"Head opening: from SUB(R, x) with x a LEAF, DEP or FOREIGN form, one hash gives the head claim c"` / `"DL-STEP, chain element ... emit DL(H(SHK_DEPS, ch, c), cov', link)"` / `"SEAL-WITH-DEPS SEG + DL -> SET ... Output set_root = DEP(claim_d, n_steps, DL.cover_root, DL.in_link)."`
  - `research/sherlock-pipeline-animation-20261111/council/bundle/STORYBOARD.md:1808,1892,2068`: Scene 4 hands an unsealed 5-pin `SEG` root to Scene 5 (`"The decider receives this root so it can establish genesis, authenticate the terminal outcome"`), and Scene 5 runs `SEAL` (`:1892`) and `SEAL-WITH-DEPS` (`:2068`) inside `DECIDER`, whereas `ARCHITECTURE.md:1744,1754-1755` and `NODE-003` (`specs/sherlock-node-integration/spec.md:25-26`) place `SEAL` and `SEAL-WITH-DEPS` in `NODE INTEGRATION`.
- Problem: Two soundness holes and a structural seam conflict sit at the `NODE` / `DECIDER` boundary:
  1. Foreign-registry smuggling through Slot 1 of a binary node: `ARCHITECTURE.md:1735` constrains `keys_repr` equal in every enabled child and the parent, whereas `:1736` merely says `reg_root` is `"forwarded unchanged"`, and `sherlock-node-integration/spec.md` omits `reg_root` altogether. In binary modes (`JOIN`, `DL-STEP`, `SEAL-WITH-DEPS`), forwarding `slot_0.reg_root` without constraining `en_1 * (slot_1.reg_root - parent.reg_root) == 0` lets a dishonest prover place an honest `LEAF` or `NODE` proof carrying the contract's `reg_root` in Slot 0 and a `FOREIGN` proof authenticated against an attacker-chosen `reg_root_fake` in Slot 1 (`JOIN` or `DL-STEP`). The parent publishes `parent.reg_root == reg_root`, which passes the contract's registry check in Beat 8.6 (`STORYBOARD.md:2940`) while smuggling an unregistered foreign claim into `set_root` or `DL`.
  2. Unchecked `reg_root` (and broken GP-2 run settlement) on `decide_run`: `decide_run` publishes only `[prog_d, input_d, outcome_d, n_steps]` (`DCD-001`, `specs/sherlock-decider/spec.md:4`), with no `reg_root`. If `decide_run` accepts a GP-path `SET` root (`LEAF` or `DEP`), `reg_root` is unbound on chain, so a consumer run `B` can discharge a forged `FOREIGN` claim (under an attacker-chosen `reg_root_fake`) through `DL-STEP` and `SEAL-WITH-DEPS` and settle `B` via `SherlockRun.acceptRun` with an unverified dependency. Conversely, if `decide_run` accepts only an unsealed M4 `SEG` (`ARCHITECTURE.md:1842`), then (a) no GP-2 consumer run sealed with `SEAL-WITH-DEPS` (`DEP` form) can ever settle through `acceptRun`, contradicting `STORYBOARD.md:2068,2536-2550` and `GP-002` acceptance `(a)`, and (b) `SEAL` is implemented twice (once in `NODE` for GP, once in `DECIDER` for M4), causing `STORYBOARD.md` Scenes 4-5 to disagree with `ARCHITECTURE.md` on which circuit owns `SEAL` and `SEAL-WITH-DEPS`.
- Proposed revision:
  1. In `NODE INTEGRATION` (`ARCHITECTURE.md:1736` and `NODE-004`), constrain `en_j * is_node_or_foreign_j * (child_j.reg_root - parent.reg_root) == 0` for `j in {0, 1}` (`LEAF` children have no `reg_root` lane), and add mutant `node_mismatched_child_reg_root`.
  2. Eliminate the dual M4/GP seal split: keep `SEAL` and `SEAL-WITH-DEPS` solely in `NODE INTEGRATION` (`SEG -> SET`), so `DECIDER` always verifies a `SET` root. Update `STORYBOARD.md` Scenes 4-5 so Scene 4 seals `SEG -> SET` and Scene 5 opens the `SET` head (`LEAF` or `DEP`) and settles the accumulator.
  3. Close the `reg_root` gap on `decide_run` in one of two ways: either include a boolean `has_foreign` flag in the `SET` grammar (`0` for `LEAF`, `l.has_foreign | r.has_foreign` for `JOIN`, `cov.has_foreign` for `DEP`, `1` for `FOREIGN`) and constrain `has_foreign == 0` in `decide_run`, or bind `reg_root` in `acceptRun`'s transcript against the contract's stored `reg_root` ledger cell (keeping call data at `[prog_d, input_d, outcome_d, n_steps]`).
- Cost of the revision: Two equality gates in `NODE INTEGRATION`; removes `open_state_header` and duplicate `outcome_d` hashing from `DECIDER` (saving ~210-420 rows in `DECIDER`, replacing a 6-input header sponge with a 3- or 5-input `SET` head opening); touches kits `NODE INTEGRATION`, `DECIDER`, `GP-2 hook`, and `STORYBOARD.md` Scenes 4-5.

### F3 By-digest input admission (`OD-17(b)`) and bottom-up constructor opening (`VDG-005`) break wide constructors, read-only step budgets, step-count invariance, and input type soundness
- Category: generality
- Severity: blocker
- Step(s): 1, 2, 3, 5
- Evidence:
  - `research/sherlock-pipeline-animation-20261111/council/bundle/STORYBOARD.md:1288`: `"Input admission keeps the value as the digest val_d in that empty genesis state. When execution inspects an input node, VALUE DIGEST recomputes its canonical digest and matches it to the expected digest before use. Records enter memory through the checked append chain."`
  - `research/sherlock-final-design-20261111/ARCHITECTURE.md:1411`: `"A constructor of arity m is opened by the fold, one field per call, with the same fold cells (cursor, m, acc, ty_d, c) that construction uses; the fields are bound to vd only when the completion hash equals vd, and a rule may use a field only after that completion (the fold cells carry an opened flag that the consuming rule requires)."`
  - `openspec/changes/sherlock-modular-leaf-20261111/specs/sherlock-value-digest/spec.md:44-45`: `"open_value_node SHALL open a value held by digest one node per call. A constructor field SHALL be usable only after its opening fold reaches the digest."`
  - `research/sherlock-final-design-20261111/ARCHITECTURE.md:2259,2263-2270`: `"Main(in_fn, in_ty) requires a present input whose type is in_ty."` / `"I1. No constraint or step scans the whole input"` / `"I4. The run of prog on x has the outcome of the reference run of apply(prog, x) (O/design.md:216), and n_steps is defined by the owner-event count of that run under the chosen form, the same for every partition."` / `"Recommendation: (b), with the empty genesis memory."`
  - `openspec/changes/sherlock-vm-consensus-20261107/design.md:183-187`: `Nil` (`[V, 1, 2, 0]`), `Cons` (`[V, 1, 3, 2, vd(h), vd(t)]`), `Leaf` (`[V, 1, 4, 1, vd(x)]`), and `Branch` (`[V, 1, 5, 2, vd(l), vd(r)]`) carry no static type digest; `Constructor` folds `acc_{k+1} = H(V, 1, 7, 2, acc_k, vd(f_k))` from `acc_0 = 0` and hashes `[V, 1, 6, m, ty_d(T), c, acc_m]`.
- Problem: The storyboarded input mechanism (`STORYBOARD.md:1288`, `ARCHITECTURE.md:1411,2270`, `VDG-005`, `INIT-005`) contains four incompatible requirements:
  1. Wide constructors (`m > 8`, required by `GP-001`) cannot be opened bottom-up under `VDG-005`: the fold registers `(cursor, m, acc, ty_d, c, opened)` hold 6 scalars and cannot buffer `m` child digests for unbounded `m`. Writing the `m` child fields into append-only `MEM` during `cursor = 0..m-1` before `vd` is checked at `cursor = m` allows a dishonest prover whose run exhausts fuel mid-opening to leave unauthenticated records in `MEM` and alter `len`, violating `VDG-005` (`vd_open_field_used_before_completion`) and `MEM` determinism.
  2. Appending opened input nodes into `MEM` breaks read-only rules, `len` determinism, and `I6`/`SRC-023`: rules that only inspect data (`BHelperEqualField` reads 4 records, `BHelperMatchField` reads 2, `XAdtHelperPlanWalk` reads 2; `research/sherlock-final-design-20261111/maxima/rule_maxima.md:45-64`) append 0 records in the owner machine. Appending opened input records mutates `len` during reads, risks exceeding the per-step append bound (`a = 3`), and makes `len` (and DataNodes/DataFields exhaustion) depend on whether shared DAG nodes behind `val_d` are opened once per address or once per traversal, violating `SRC-023`.
  3. Step-count divergence (`I4`): unfolding an `m`-field input constructor across `m` steps changes `n_steps` and fuel consumption relative to `apply(prog, x)` (`openspec/changes/sherlock-vm-consensus-20261107/design.md:216`), where `x` is already materialized at entry.
  4. Uninspected input subtrees break `INIT-003` (`init_entry_input_mismatch`) and `SRC-022`: because `I1` forbids scanning `x` at `INIT` and `Cons`/`Branch`/`Leaf` omit static `ty_d`, lazy node-by-node opening never checks subtrees the program does not touch. For `fn tail(xs: List<UInt>) -> List<UInt> { match xs { Cons(_, t) => t, Nil => Nil } }`, if `Main` does not run `BHelperValidate` over all of `xs`, a prover can supply `val_d = H(V, 1, 3, 2, vd(1), GARBAGE_FQ)` where `GARBAGE_FQ` is not a valid `List<UInt>` (or not a `sherlock-value/1` preimage at all); opening the `Cons` cell succeeds in one hash and `tail` halts with `outcome_d = H(O, 1, 0, GARBAGE_FQ)`, publishing a false `Halted` claim for an input outside `in_ty`. Conversely, if `Main` runs `BHelperValidate` over all of `xs`, every `Main` call scans the entire input, violating `I1`.
- Proposed revision:
  1. Never append opened input records to the mutable `MEM` arena. Serve by-digest input reads through an immutable read-only cache region on `BUS` (parallel to `PAGE/ROM` in `sherlock-chip-page-cache`, keyed by `(vd, sub_idx)`), where each cache provider row proves its hash relation to `vd` and leaves `(len, root, tail_d)` untouched (`0` `MEM` appends, `0` owner steps).
  2. Replace bottom-up constructor opening in `VDG-005` with **top-down** peeling (or a binary Merkle field tree in `sherlock-value/1`): under the existing `sherlock-value/1` left-fold, a cache row first opens `vd = H(V, 1, 6, m, ty_d, c, acc_m)` to authenticate `(m, ty_d, c, acc_m)` immediately, and subsequent cache rows peel `acc_{k} = H(V, 1, 7, 2, acc_{k-1}, vd(f_{k-1}))` from `k = m` down to `1`, authenticating every `vd(f_{k-1})` in one 6-word hash with zero unauthenticated buffering and zero owner-step overhead (preserving `I4` `n_steps` identically to `apply(prog, x)`).
  3. Close uninspected-subtree soundness: embed static `ty_d` in every `sherlock-value/1` node (`[V, 1, tag, arity, ty_d, ...]`) and either (a) require any uninspected `val_d` passed to `Main(in_fn, in_ty)` to carry either an `in_link` producer claim of output type `in_ty` or a bounded recursive input-well-formedness proof `H(SHK_VAL_OK, 1, ty_d(in_ty), val_d)` proved once off-line under the universal node key (zero scan in `INIT`, zero extra owner steps in `LEAF`), or (b) run `BHelperValidate` as part of `Main` entry and state `I1` explicitly as "the `INIT` circuit check scans nothing; `Main` entry validation is counted execution".
- Cost of the revision: Adds one read-only input-cache provider class to `PAGE/ROM` (`K_in` rows per leaf, ~210-280 rows per opened input node) and updates `VALUE DIGEST` (`VDG-005`) and `INIT` (`INIT-003`, `INIT-005`); zero changes to `MEM` or `MEMORY BACKEND`, keeps `len_0 = 0`, preserves `a = 3` and `n_steps` of `apply(prog, x)`, and supports arbitrary-arity constructors and unbounded inputs under GP-1 and GP-2.

  3. In `NODE-004`, list the exact permitted `stmt_tag` set per `key_sel_j`: `LEAF -> {SEG}`, `FOREIGN -> {SET}`, `NODE -> {SEG, SET, SUB, DL, FV}`.
- Cost of the revision: One selector term in `shape.rs`, one fewer payload copy in `NODE INTEGRATION`, and explicit routing table entries in `NODE-004` and `SHP-002`; zero extra rows; touches kits `NODE INTEGRATION`, `GP-4 hook`, and `GP-3 general verifier`.

  1. Cross-contract replay bypass: `ARCHITECTURE.md:2754-2755` recommends two separate contracts (a run contract with `acceptRun` and a separate claims contract for collections), whereas `STORYBOARD.md:2961` assumes one shared `runs` table. In Midnight's Compact ledger model, two separate contracts have disjoint ledger state, so the same `claim_d` can be accepted once via `acceptRun` on the run contract and settled a second time via collection opening on the claims contract, violating `DCD-003`, `SRC-007`, and `GP-002` ("accepted once on-chain").
  2. Unbounded DAG depth vs fixed-depth Compact circuits: `DCD-004` forbids per-claim side effects when `acceptCollection([reg_root, set_root, shape_d])` runs, deferring per-claim settlement to subsequent openings from `set_root` (`EveryJoinedClaimOpens`, `DiamondAncestorOpenedAtMostOnce`). However, `GP-004` and `SHP-001` allow `JOIN`/`DEP` DAGs of **any depth**, while Compact 0.36 circuits have no unbounded loops and must unroll every hash path to a compile-time constant `D_open`. A naive fixed-depth `openClaim` circuit silently rejects valid collections deeper than `D_open`, violating `GP-004` completeness.
- Proposed revision: Add a 24th kit `CONTRACTS AND LEDGER` (`specs/sherlock-contracts/spec.md`) owning a **single** unified Compact contract with entry points `acceptRun`, `acceptCollection`, `peelSubroot`, and `openHeadClaim` over shared ledger state (`runs: Map<Field, RunRecord>`, `verified_subroots: Set<Field>`, `reg_roots: Set<Field>`):
  1. `acceptRun(prog_d, input_d, outcome_d, n_steps)` verifies the run decider proof, computes `claim_d`, requires `!runs.member(claim_d)`, and inserts `claim_d -> (outcome_d, n_steps)`.
  2. `acceptCollection(reg_root, set_root, shape_d)` verifies the collection decider proof, requires `reg_roots.member(reg_root)`, and inserts `set_root` into `verified_subroots` (zero per-claim loop).
  3. `peelSubroot(parent_root, steps_witness)` requires `verified_subroots.member(parent_root)`, verifies up to `K_peel` (for example `K_peel = 8`) `SHK_SET_JOIN` or `SHK_SET_DEP` Poseidon openings in a fixed-bound Compact loop, and inserts the reached child subroot into `verified_subroots`, allowing openings of arbitrary DAG depth in `ceil(depth / K_peel)` calls without capping `GP-004`.
  4. `openHeadClaim(sub_root, ...)` requires `verified_subroots.member(sub_root)`, verifies one `SHK_SET_LEAF`, `SHK_SET_DEP`, or `SHK_SET_FOREIGN` head hash to recover `claim_d`, and writes `runs` if `!runs.member(claim_d)` (idempotent or replay-refused per policy, enforcing `DiamondAncestorOpenedAtMostOnce` across both `acceptRun` and `acceptCollection`).
- Cost of the revision: Zero rows added to `LEAF`, `NODE`, or `DECIDER`; adds one Compact contract specification kit (`specs/sherlock-contracts/spec.md`) with small Compact circuits (`K_peel` Poseidon hashes per peel call) and recaptured `SRC-020` transcript templates; touches `DECIDER` (template wiring) and task `F.10`.

### F6 Unfrozen 3-word `DATA` cell packing (`e = 1`) omits limb-range lookups needed to keep `TOP = 63`
- Category: fragility
- Severity: minor
- Step(s): 3
- Evidence:
  - `research/sherlock-final-design-20261111/ARCHITECTURE.md:798,805,850`: `"WindowCfg ... WinRow { addr, act, imp, rec: [kind, a, b, c] }"` / `"A logical record wider than three words (a, b, c) takes consecutive addresses, and each address is one physical cell: every bound of this kit ... counts physical cells, not logical records ... they are not frozen here (section 4, OD-11)."` / `"With a = 3 (M-2) and e = 1, TOP = 63 leaves room for len_0 < 2^64 ... e = 2 would need TOP = 64"`
  - `openspec/changes/sherlock-modular-leaf-20261111/specs/sherlock-chip-mem/spec.md:11,62`: `"The working value SHALL be TOP = 63, gated on OD-1 (OWNER) and on e = 1 from OD-11."` / `"The record layout SHALL be three-word records at consecutive addresses (OD-11), frozen before the CORE rule families start."`
  - `research/sherlock-final-design-20261111/ARCHITECTURE.md:1405` and `research/sherlock-pipeline-animation-20261111/council/bundle/STORYBOARD.md:1154`: `"- vd: copied into the record's digest word."` / `"The resulting digest equals the digest stored with the new record, so a correct-looking record cannot carry an invented semantic value."`
- Problem: Storing the full-field `vd` in word `c` of a `DATA` record leaves only two field words `(a, b)` for all remaining `Constructor` metadata: `NodeKind` tag, `TypeIdC`, `CtorIdC`, `field_start` (up to 66 bits at `TOP = 63`), and `field_len` (unbounded arity `m`, up to 64 bits). Keeping `e = 1` (so `TOP = 63` suffices for `2^64 - 1` steps under `MEM-002`) requires bit-packing multiple fields into `a` and `b`. Every rule that writes or reads a packed word must decompose and range-check the packed subfields via `RANGE`, otherwise a malicious prover can overflow a subfield during packing or forge a split on read; those extra `RANGE` requests are not counted in `CORE`'s per-slot `RANGE` port budget. Conversely, avoiding bit-packing makes `Constructor` take two physical cells (`e = 2`), which invalidates `TOP = 63` (`MEM-002`) and halves effective `W = 1` window capacity in logical records.
- Proposed revision: Freeze the `e = 1` 3-word `DATA` layout directly in `ARCHITECTURE.md` section 1.2 (`CORE`) and `MEM-007`: for `Constructor`, set `a = node_tag + 8 * ctor_id + 2^32 * type_id` (with 3-bit `node_tag`, 29-bit `ctor_id`, 32-bit `type_id`), `b = field_start + 2^68 * field_len` (with 68-bit `field_start` and 64-bit `field_len`), and `c = vd`; constrain the packing once at `DATA` append time using ranged limbs so readers unpack deterministically, and add those limb checks to `CORE`'s per-slot `RANGE` request count.
- Cost of the revision: Adds 2-3 `RANGE` lookups on constructor-allocation steps in `CORE` (~6-9 rows per slot), preserves `e = 1` and `TOP = 63` across `MEM` and `MEMORY BACKEND`, and avoids `TOP = 64` (+280 rows per flush unit and +140 rows per cold heap line).

## What the design gets right
- **Step 3 — Kits `MEM window` and `MEMORY BACKEND` (`research/sherlock-final-design-20261111/ARCHITECTURE.md:796-803,844-849`):** Replacing padded per-leaf memory segments with one dense arena `(len, root, tail_d)` and capacity-tagged `Tree8` flushes eliminates D3 padding waste and makes the committed memory state strictly a function of the append sequence across any valid leaf partition (`SRC-023`).
- **Step 3 — Kits `CORE` and `STACKS` (`research/sherlock-final-design-20261111/ARCHITECTURE.md:606-610,712-734`):** Modeling `FRAMES` and `TASKS` as cached-top hash chains driven by one compound `StackStep` (`optional top rewrite, then none/push/pop`) plus syntactic incoming-scratch independence matches the 120 owner-machine rules one-for-one without cold stack-tree walks or cross-slot scratch leakage.
- **Step 3 — Kits `BUS` and `CORE` (`research/sherlock-final-design-20261111/ARCHITECTURE.md:240-252,553-570`):** Routing every heap and ROM read through `CORE`'s `AuthRec`/`AuthRom` certificate (`addr < len_cur` at the exact intra-step running length, pinned `kind`, ranged ROM row) and using a fixed-tag idle tuple `(TAG_DEC, 0, 0)` achieves modular soundness over set-inclusion lookups without global permutation arguments.
- **Steps 3 & 5 — Kit `BOUNDARY COMMITMENT` (`research/sherlock-final-design-20261111/ARCHITECTURE.md:1567-1585`):** Splitting `state_d` into a capacity-tagged `body_d` and a 6-word pinned header `Poseidon(dom("SHK_SD2"), outcome_tag, outcome_payload, input_d, deps_d, body_d)` lets recursion open terminal and dependency fields in three Poseidon permutations while keeping registers, stack links, and physical memory addresses opaque.
- **Steps 4, 7 & 8 — Kits `GP-2 hook` and `GP-4 hook` (`research/sherlock-final-design-20261111/ARCHITECTURE.md:1966-1985,2103-2109`):** Separating the counter-free four-form `SET` grammar (`LEAF`, `DEP`, `JOIN`, `FOREIGN`) and `DESCEND`/`DL-STEP` discharge from `claim_d = Poseidon(SHK_RUN, 1, prog_d, input_d, outcome_d)` supports diamond DAG reuse at arbitrary depth without counter overflow while keeping replay refusal independent of leaf cuts and aggregation shape.
