## Critical later amendment: read before architecture conclusions

`openspec/PCD-INTEGRATION-2026-09-11.md` and `openspec/changes/pcd-ledger-anchored-acceptance/design.md` supersede older per-step recursive-PCD mechanics. Selected planning design is a **ledger-anchored certified state machine**: fused per-operation relation (authorization + transition + effects + intent + invariant), immutable audited operation keys, constrained genesis, and head read-then-write discipline. History follows by induction over ledger-accepted steps. Ordinary contract proofs are Blake2b-transcript proofs and cannot be fed as Poseidon inner proofs to `verify_proof`. Recursion is reserved for bounded off-ledger certificates/imports, conditional on `ledger-10` functionality and resource amendment. Core acceptance no longer depends on recursive certificate stages; release still does. Planning is specified-only and charter's second independent review is pending. README/wiki contain older mechanics: explicitly reconcile this contradiction rather than treating all prose as one design.

Head planned as `(instanceId, headId, revision, stateCommit, lifecycle, programDigest, netTag)` with every write following a same-head read. Exact-head nonce is informational; outcome intents need a consumed-nonce set across heads. Program digest binds Core, bounds, property certificate, claim sets, toolchain, successor allowlist. Migration is forward-declared and cannot reset liabilities or authority. This is directly relevant to eUTXO state consumption and script identity.

Research must assess a new backend without changing the existing sole Preview execution gate. UTXO experiments remain specified-only in this task. Keep source facts separate from compatibility inference and recommendations. A path to public settlement alone does not preserve Moriarty's private financial/history guarantees.
