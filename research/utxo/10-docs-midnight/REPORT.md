## 1. Midnight already has UTXO value, but its contract state is a separate ledger structure

**Repository observation.** Midnight ledger default branch is `ledger-8`, pinned `131065ea2b292717306ad9c0c28e2fc5628241c3`. `ledger/src/structure.rs:3000` defines `LedgerState` with distinct `zswap`, `contract: Map<ContractAddress, ContractState>` and `utxo` fields. `onchain-state/src/state.rs:961` defines contract data, operations, maintenance authority and per-token balance. Thus describing Midnight as purely an account ledger or saying Moriarty must first gain UTXO value would be misleading. “Account-like contract state” is an analogy to the address-indexed contract map, not a statement that Midnight implements Ethereum accounts. [Pinned ledger state](https://github.com/midnightntwrk/midnight-ledger/blob/131065ea2b292717306ad9c0c28e2fc5628241c3/ledger/src/structure.rs#L3000), [contract state](https://github.com/midnightntwrk/midnight-ledger/blob/131065ea2b292717306ad9c0c28e2fc5628241c3/onchain-state/src/state.rs#L961).

`midnight-ledger/spec/contracts.md`, sections Deploying/Calling a contract, describes address-indexed state and ZK-backed transcripts with effects. Genesis deployment requires an empty token balance, but this is not Moriarty’s stronger signed/genesis semantic relation. Maintenance can change operations unless deployment policy removes or constrains that authority. `spec/README.md` explicitly warns the specification is incomplete and cannot reproduce all ledger behavior alone; it is not a machine-checked full-ledger specification.

**Official source fact.** [Midnight.js contract model](https://docs.midnight.network/api-reference/midnight-js), captured `midnight-js-model.extract.txt:260`, distinguishes user-local private state from public on-chain contract state. The general concepts page’s public/private-ledger prose should not be read as meaning every DApp private state value is replicated on-chain. The source implementation and focused API documentation are more precise.

**Compatibility inference.** Cardano’s consumed state output is a plausible realization of Moriarty’s same-head read/write discipline. This changes contract-state identity, uniqueness, update semantics and complete-effect construction; existing Midnight UTXO coin handling is not an eUTXO backend. Plain Plutus evaluation does not preserve private state or ZK execution. Datum commitment, state token and ledger conservation each have narrower roles than financial/history acceptance.

## 3. New stable security pin and documentary lag

[Ledger8.1.3 notes](https://docs.midnight.network/relnotes/ledger/ledger-8-1-3), captured `ledger813-notes.extract.txt`, High-level summary/Bug fixes/Known issues, describe GHSA-wr7g-rr4v-jmj8: previously proof-equivalent noncanonical field encodings could compare differently in ledger state, permitting repeated one-time operations on affected contracts. Fixes require canonical fields, reject nonempty pushed Merkle trees and zero-count noop. Existing malformed stored keys are not repaired by the upgrade. This is evidence about the documented ledger defect, **not evidence that Moriarty’s retained contracts were exploited**.
