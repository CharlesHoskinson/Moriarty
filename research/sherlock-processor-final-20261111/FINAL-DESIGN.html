Sherlock final design

Sherlock is a universal, elastic proving co-processor for Midnight. A user runs any program on the Sherlock machine, proves the run as a tree of fixed-size small-field STARK shards on the user's own GPU, compresses the tree into one last STARK layer L hashed over BLS12-381 Fr, and wraps L in a blinded midnight-proofs PLONK proof that the ledger 9.1.0.1 verifier checks. Which form of the wrap ledger 9 can read is open: it refuses a key with the G4 lane gates (check M7-0, MEASURED), and the path is owner decision OD-24.

Every number carries one mark. MEASURED: read from a run record. DERIVED: computed by a stated rule from MEASURED numbers. ESTIMATE: computed from a model with named inputs. A number that waits on a measurement says "pending" and names it. Source keys are in the last section.

One-page summary

Open BLOCKER: the ledger key reader

Ledger 9 reads an installed verifier key by rebuilding a ZkStdLib-architecture constraint system from flags in the key bytes, so a key with the G4 lane gates is not read as its own circuit. A toy G4 key (one lane, one degree-5 gate, one lookup, 1,026 public inputs) passes the library verifier and is refused by ledger 9 at key parsing under three architecture headers, MEASURED (M7R sections 1.1 and 1.3). The single-lane stdlib shape needs 2,370,944 to 3,051,763 rows at the L set, ESTIMATE (M7R section 1.2), over the 1,782,573-row k = 21 gate. The path is owner decision OD-24, with no adopted default:

  • (A) a G4 architecture in midnight-zk-stdlib and a ledger release that reads it: one wrap, G4 at k = 20 on the benchmark L, ESTIMATE; the ledger changes upstream.
  • (C) the G4 wrap of L off chain, then a ZkStdLib-architecture decider that verifies it and exposes the 1,026 public inputs: ledger 9 unchanged; two BLS12-381 PLONK layers; the existing decider proves in 68.1 to 111.8 s on a quiet CPU, MEASURED (M7R section 2), and a decider over a G4 proof is not sized.
  • (E) an Fr-terminal layer L_Fr between L and a ZkStdLib-architecture wrap, so the wrap verifies an Fr STARK natively: ledger 9 unchanged; one BLS12-381 wrap of 684,894 / 879,472 / 976,410 rows over the full interface, at most 55 percent of the k = 21 gate, ESTIMATE on D10 MEASURED inputs (M7R section 2b.2); L_Fr itself is not measured, and no stark-backend configuration with an Fr base field exists.
  • Rejected by M7: (B) the single-lane stdlib wrap, 2,457,645 rows mid, 137.9 percent of the k = 21 gate, ESTIMATE on D10 MEASURED inputs (M7R section 2b.1); (D) a return to list decoding, which reverses OD-19.
  • No option is adopted.

Each option changes a standing rule, and the owner decides which: A changes the ledger, against the rule that the co-processor needs no ledger change; C puts two BLS12-381 PLONK layers on the path, against the owner rule of one BLS12-381 wrap; E builds the Fr-terminal layer whose form A the design does not build (OD-11).

Every G4 and k = 20 wrap figure on this page is a G4 figure on the benchmark L (L_cached, no log AIRs). It holds only under option A or as the first layer of option C, and production qualification on the complete L interface is pending.

1. System context

Three places hold Sherlock. The build host (CMP, PLN) runs once per program and sees no witness. The user's machine (HST, DMN, LEAF, NODE, L, WRAP, CKP) holds the witness and every STARK proof. Midnight (LDG, CON) sees one ContractCall per call: the wrap proof and the call vector of 2 + L_TX = 1,026 Fr words.

The mechanism is a change of field in one place. LEAF and NODE are BabyBear STARKs with Poseidon2, which the GPU proves fast. L is still a BabyBear STARK, but its Merkle tree and Fiat-Shamir transcript use Midnight Poseidon over BLS12-381 Fr, so a G4 PLONK circuit verifies it at a cost of hundreds of thousands of rows, ESTIMATE on the benchmark L, where a single-lane stdlib circuit needs millions. WRAP is that circuit. It uses the proof system of the existing ledger verifier (PLONK, KZG over BLS12-381, Blake2b). That is not enough for LDG to read its key: LDG reads only ZkStdLib-architecture keys and refuses a G4 key (M7-0), so whether LDG changes depends on OD-24.

A program asks for Fr work (Poseidon over Fr, Merkle paths, Jubjub). LEAF either emulates that work in chips (tier E) or writes it to LOG, the deferred field log, which WRAP replays natively in Fr. The split is a prover choice and never enters the statement.

3. Deployment

All proving runs on hardware the user owns. The daemon (DMN) is resident: it keeps keys, the program codeword and a pool of one-use blinding slots loaded, and serves sherlock prove over a local socket. A cold call costs 19 to 98 s more than a warm one, ESTIMATE (PR section 6.3). Several GPUs that the user owns count as the user's machine; they share shards of one run. No remote helper takes any part of a proof.

4. Data flow

Each layer exposes a fixed list of public words, and the next layer checks it. LEAF exposes 54 words: binding, prog_d, pre_d, post_d, rules_d, h_pre, steps, and the leaf log (log_d, log_n). NODE checks that adjacent segments meet (post_d of one equals pre_d of the next), merges logs, checks each leaf key against key_root, and exposes a 74-word statement. A DISCHARGE node is the one exception to the merge: it proves every entry of the child log valid and outputs the child statement with an empty log, every other word unchanged. L verifies the root node, recomputes the log digest from the flattened log that it takes as private witness, binds the log to the public-value vector pv by one multilinear extension per table, and exposes 12,164 words, DERIVED at B = V = 256 and L_TX = 1,024 (AR section 1.11).

The log carries Fr work across the field change. Each entry is (op, inputs, outputs) with op one of NOP, PERM, H2, SPONGE(n), PATH(d), ECMUL, ECMULG, PUB(i), DIGEST. Its digest is a tagged onion in Poseidon2 over BabyBear carried as (d, n), so it chains through leaves, continuations, suspension and resume. FADD, FMUL, FINV and ECADD never enter the log: binding them costs more than emulating them.

The log has a fixed capacity: B = 256 entries, V = 256 values, P = 256 permutation slots and E = 0 Jubjub slots, so pv is 2B + 9V = 2,816 words, DERIVED. The planner first reserves the mandatory entries R (the anchor DIGEST entries and the public digests), then adds each discretionary Fr operation only while all four limits hold, and otherwise sends it to tier E. NOP padding hides the used count. The largest checked contract, zerocash spend, needs 111 values and 39 permutations with R counted, a margin of 2.31 times on values and 6.56 times on permutations, DERIVED (PR section 3.2).

5. Transaction lifecycle

One call

  • CMP compiles each entry to a straight-line program and writes abi.json: the step count N_e, the effect words L_e, the tape length and the builtin counts. The largest of 27 checked entry points needs 474 call-vector words of 1,024, MEASURED by a static count of compactc 0.36.0 output (PR section 7.1).
  • PLN fixes the static plan (instruction tables, shape menu, scheduling policy, log layout rule, placement rule) and the per-program keys, and binds them: plan_d = P2(DOM_PLAN, 1, itab_d, menu_d, policy_d, layout_rule_d, place_d), word lists pending ENC-5, and prog_d = P2(DOM_PROG, image_d, plan_d, key_root, machine_version). The prover makes each run's schedule (cut points, tree, padded count, resumes) from a metered run under the policy; the schedule is not in plan_d, so a longer run keeps its prog_d. The anchor value is C_P = PoseidonFr_4(SHK_PROGC, pack(P2(DOM_PROGC, r_P, prog_d))) with one secret r_P per deployment.
  • Deploy writes C_P into the anchor cell of CON and installs the one wrap key under every exported entry label.
  • HST reads the ledger values the call depends on (popeq reads), builds the tape Cons(salt, Cons(selector, args, comm_rand, witness, reads)) and the call intent, whose bytes m fix binding_input = le31(SHA256(m)).
  • DMN proves LEAF shards (with bind_label, which recomputes binding_input from m on the sha2 chip), NODE nodes, L and WRAP. A one-leaf call takes path C: one leaf, one leaf layer at internal parameters, no internal node, then L and WRAP.
  • HST balances with a second intent (fees and DUST never rebuild the call) and submits. LDG verifies the proof under the entry's key and replays the transcript: the anchor read must equal C_P, every read must be current, and the effects apply.

Chunked calls

A logical call whose transcript exceeds L_TX runs as k contract calls in one intent of one transaction on the unmodified ledger. Mode 1F puts every chunk in the fallible segment, which the ledger applies as one unit: a failure in any chunk drops all of them, and the fee is paid. Mode 1G puts every chunk in the guaranteed segment, for a callee of a guaranteed caller: a failure makes the transaction invalid. Mixed chains are refused.

  • The anchor is a lock. A_0 = A_k = C_P, and A_j = PoseidonFr_4(SHK_LOCK, pack(P2(DOM_LOCK, r_P, prog_d, run_tag, j))) for 0 < j < k, salted by r_P and a fresh run_tag. Chunk j reads A_(j-1) and writes A_j; the last chunk writes C_P back.
  • Chunk j claims chunk j+1 with (addr_c, ep_hash, comm_(j+1)) in the effect words of its claimContractCall. bind_label takes addr_c from the binding preimage and computes ep_hash from the entry label, so the claim is bound in the proof.
  • Every entry of a Sherlock contract starts with the anchor prologue, and so does every native-routed entry of a hybrid contract, which compares anchor with anchor_home. During a run the anchor holds a lock, so no other entry can run between chunks.
  • Cut only where the native run has stack depth exactly 3; hoist every context read into chunk 1. Overhead is about 30 words per chunk, so about 990 words per chunk at L_TX = 1,024, ESTIMATE (PR section 7.3).

At ledger level with proofs off, 19 cases pass: a valid 3-chunk chain applies; a forced middle failure leaves the contract state byte-equal in 1F and invalidates the transaction in 1G; a dropped last chunk fails with RealCallsSubsetCheckFailure; a dropped first chunk fails the lock read; swapped chunks fail with CallSequencingViolation; an entry without the prologue interleaves (the control) and an entry with it is refused, MEASURED (ACT section 2). The local devnet run with native keys passes as well, MEASURED (ACT). A chunk that claims a call at another contract is accepted by the ledger alone and leaves the victim locked, MEASURED (ACT case T1-n); this is why the claim address is bound in the proof.

7. Trust boundaries and zero knowledge

Zero knowledge holds end to end because no STARK proof leaves the user's machine. A STARK proof reveals its shape (per-AIR heights, the set of AIRs present) and is not masked, so LEAF, NODE and L proofs, the checkpoints and the tape are secrets like the witness. WRAP is the only proof that leaves, and it is a blinded PLONK proof with fresh CSPRNG blinders; seeded proofs exist only in a test mode.

  • WRAP has exactly the call vector as public inputs. Keygen refuses a wrap key that exposes X, mode, j, k, run_tag, key_root, plain prog_d, pre_d, post_d, a memory root, a tail digest, a length, an address or a word derived from the transcript of L.
  • The program identity is public only as C_P (salted by r_P) or a lock A_j (salted by r_P and run_tag). A public program publishes (prog_d, r_P) in its manifest; a private program keeps both secret.
  • The input enters behind input_d = P2(SHK_IN, salt, val_d, fuel_lo, fuel_hi, stack_limit), with 8 salt words from the user's CSPRNG, fixed for the run at INIT. The salt is never published on its own. outcome_d carries no salt; outcome_pub = PoseidonFr_4(SHK_OUTCOME, pack(P2(DOM_OUTHIDE, input_d, outcome_d))) hides it under the salt inside input_d, and input_pub = PoseidonFr_4(SHK_INPUT, pack(input_d)). Every partition of one run has the same salt, so a second partition of the same run has the same claim_pub and is refused as a replay.
  • n_steps is not public: the exact height leaks control flow. It stays private inside the SET forms LEAF(claim_d, n_steps) and DEP(...). Shard counts follow the padding rule of the plan's policy, and the per-run schedule stays on the user's machine.
  • The log is padded with NOP entries and zero values to capacity, so the used count and the log-or-emulate split stay hidden.
  • The trust domain is the user's own devices. No helper proves a STARK layer, sees the plain witness, holds the full sponge state, or computes an unmasked MSM, NTT, quotient or Merkle hash. Every challenge comes from the Fiat-Shamir transcript after the commitment it binds; none comes from a device random source.

8. State and storage

Machine state is a commitment state_d = P2(SHK_SD2, outcome_tag, outcome_payload, input_d, deps_d, view_root, body_d), 42 words with its tag. The header words are what NODE and INIT open; body_d = P2(DOM_STATE_BODY, schema_id, body words) holds the registers, the stack hashes and the memory state (len, root, tail_d). A seal opens view_root from the header in one hash.

Memory is write-once and append-only: one arena of kind-tagged records in a dense tail-buffered Merkle tree. A leaf imports the tail, appends new records at len_pre .. len_post - 1, and persists completed segments. A read is authenticated by the window, a heap line of the block cache, or a scalar cold read against pre.root, and the read port checks addr < len_cur for every read. Stacks keep their tops in cells and spill into a hash chain that binds the depth.

CKP stores the segment state between leaves, so a run can stop and resume: the boundary carries (d, n) of the log as well. On chain, CON holds the anchor cell (C_P, or A_j during a chunked run), anchor_home for a hybrid contract, the runs map keyed by claim_pub, the verified roots and the registry root of foreign verifier keys. Each exported entry holds the wrap key, at most 50,000 bytes; the existing decider key is 2,217 bytes, MEASURED (X9).

9. Key and parameter sets

One universal key set serves every program. The recursion circuit reads the child's constraint DAG as a cached trace, so the internal-recursive key and the L key are the same whatever app key the leaves use. Per-program keys (one app key, one leaf-layer key and one internal-for-leaf key per chip set) sit under key_root inside prog_d. The first universal node checks each leaf key by a Poseidon2 path into key_root. On path C, which has no universal node, L proves the leaf P2(DOM_KEYDAG, entry, path, enc(X)) for the child DAG commitment X, and WRAP checks that X equals the cached-trace commitment of L it reads, about 120 rows, ESTIMATE (PR section 4.3).

On a quiet host the k = 21 GPU path is about 1.35 times faster than the 111.8 s CPU path, ESTIMATE (GW section 2).

The MSM is the next floor. The stock GPU MSM takes 622 to 647 s over 45 calls on the real witness, because witness columns repeat small range-checked values and each bucket accumulates serially. The skew mask MSM(s) = MSM(s + r) - MSM(r), with a fixed vector r and MSM(r) cached per base table, brings the 45 calls to 23.2 s with unchanged proof bytes, MEASURED (GW). The built GPU MSM takes 0.479 s per 2^20 points on a loaded host, MEASURED; the 3.5 s G4 wrap at k = 20 on the benchmark L (2.45 to 4.49 s, ESTIMATE, PR section 8) needs 40 to 70 ms per 2^20 (DERIVED from the 3.5 s budget, PR section 8). The Rust rewrite (crates/mori-msm, an nvptx64 kernel with 384-bit Montgomery multiplication over 6 x 64-bit limbs) builds, loads and matches blst_fp_mul on 2^16 random pairs, 46 registers and no spills, MEASURED (MSM section 0); its bucket and window stages are pending.

G4 is the wrap shape under OD-24 option A and the first layer of option C; ledger 9 refuses a G4 key as it stands (M7-0). Wrap shape G4: 4 identical lanes of 8 advice columns over about 14 shared fixed columns, 18 permutation columns, 4 lookups into one fixed 2^16-row table, every gate and lookup of degree at most 5 so the extended domain is 4n, rotations within -1, 0, +1, and the 19-row Poseidon layout. One lane takes one query of Merkle work, one extension-field coefficient and one log slot, so each region is one program on 4 data streams, which suits the GPU. The proof is about 8 to 9 kB, ESTIMATE, against 6,432 bytes for the existing decider, MEASURED (X9).
