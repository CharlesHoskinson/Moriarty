## Executive Summary

1. **Where leaf rows go today — and where they will go once `PAGE` lands:** In the current E8 spike key (`pos_m3+r1+a1+pc`, `S = 16`, `C = 8`), the leaf uses **6,511 rows** (`k = 13`), of which **6,090 rows (93.5%)** are 87 rate-2 Poseidon permutations at 70 rows each (`crates/mori-chip/src/poseidon.rs:58-59`, `crates/mori-chip/src/m3.rs:54`, `research/sherlock-processor-analogy-20261110/experiments-4.md:53-64`). All 6,090 Poseidon rows today are **once-per-leaf boundary costs** (3,990 rows for the M3 8-cell segment update + 2,100 rows for `pre_d`/`post_d`), because the spike does not yet include `PAGE` (`experiments-4.md:319-337`). Adding uncached depth-20 Merkle openings (`22` permutations = `1,540` `ESTIMATE` rows per read, `research/sherlock-processor-analogy-20261110/experiments-3.md:205-206`) for 16 step fetches and 8 old-cell reads would add **`36,960` `ESTIMATE` rows per leaf**, immediately becoming 85% of the leaf circuit.
2. **Hard constraints of the pinned Midnight stack:** `VerifierGadget` in `midnight-circuits = 7.3.0` enforces **single-phase challenges** (`assert_eq!(cs.phases().count(), 1)` at `midnight-circuits-7.3.0/src/verifier/verifier_gadget.rs:310`) and **rotations in `{-1, 0, +1}`** (`verifier_gadget.rs:604-610`). Every added `lookup_any` costs **`+22,600` `ESTIMATE` rows** in the `k = 20` recursion node (`823,466` baseline vs `950,000` gate, `experiments-2.md:230-232`, `experiments-4.md:55`), while the `k = 20` run decider sits at **`929,166` circuit rows** and **`1,032,467` table rows** — leaving only **`16,109` table rows** below the `2^20 = 1,048,576` ceiling (`research/sherlock-c6-outcome-ledger9-review-20261110/review.md:213`).
3. **Why Sherlock `/1` is structurally a Cairo/RISC-Zero/OpenVM hybrid, not a Jolt/SP1/Airbender target:**
   - Like **Stwo-Cairo** (`starkware-libs/stwo-cairo`), Sherlock `/1` has **write-once immutable memory** (`openspec/changes/sherlock-vm-consensus-20261107/design.md:191-197`, `models/sherlock/quint/chipLeafCached.qnt:56-57`). Every region (`PROG`, old `MEM` cells, `DEC`, `ALU`, `HASH`) is a **time-invariant partial function of `(chip_tag, key)`**. Consequently, `midnight-proofs`'s existing phase-0 set-inclusion `lookup_any` (`midnight-proofs-0.8.3/src/plonk/lookup.rs:40-88`) gives **exact L1 read caching with zero timestamps, zero clock-delta range checks, zero read write-backs, zero multiplicities, and zero extra challenge phases**.
   - Unlike monolithic STARKs (Stwo, Jolt, Nexus 3.0) or 2-pass pre-committed STARKs (Airbender) or septic-curve RAM shards (SP1 Hypercube, Ziren), Sherlock must satisfy **all four GP pillars (`GP-1..GP-4`, `openspec/changes/sherlock-vm-consensus-20261107/general-purpose.md:1-58`)**, including arbitrary context-free PCD DAG composition (`GP-4`) and cross-run continuation claims (`GP-2`) under C6 outcome-only publication (`[prog_d, input_d, outcome_d, n_steps]`). A sparse Merkle state commitment (`mem_root`, `prog_root`) in `(pre_d, post_d)` — paired with an intra-leaf L1 bus cache and multi-cell block paging (as in **RISC Zero** `PagedMemory` and **OpenVM** `PersistentBoundaryChip` + `MemoryMerkleChip`) — preserves 100% leaf independence and $O(1)$ boundary handoff, whereas full-run offline memory either violates `phases == 1` (LogUp/Spice/Airbender) or requires a 243-bit Poseidon pre-hash + $O(N_{\text{alloc}})$ teardown sweep (Jubjub `y-increment` EC multiset hashing).
4. **Recommended prototype (`Q1(f)` / `Q5`):** Implement a **Write-Once Two-Tier Bus Cache** in `crates/mori-chip`:
   - **Tier 1 (Intra-Leaf L1 Bus Cache, 0 new lookups):** Deduplicated `PAGE` provider rows + `CHIP_HASH` memo/constant rows on the existing 5-column `bus` (`crates/mori-chip/src/bus.rs:47-62`), optionally folding `DEC` onto `bus` as fixed provider rows (saving `-22,600` `ESTIMATE` node rows if bus request bandwidth allows, or `0` node rows if kept separate).
   - **Tier 2 (Spatial Block Paging + Pre-Digested `PROG`/`vd` + Lazy Segment Carry + Larger `S`):** Authenticate `C = 8`-cell aligned blocks in `PAGE` (matching `m3.rs`'s `SEG_C = 8` geometry so 1 Merkle walk populates 8 bus cache rows), store `vd` inline in allocated value cells/refs and precompute `ty_d` / `const_vd` in `PROG` rows at admission, carry partial 8-cell write buffers across leaf boundaries so M3 flushes **only when 8 cells fill** (fixing both the `D3` $2^{17}$-leaf ceiling and prover partition-dependent address drift under `SRC-023`), and scale `S` from `16` to **`64`** (`k = 15`, `+0` node rows, **4x fewer node proofs per run**).

### 4.1 Jolt (`a16z/jolt`): From Lasso & Spice (`2023/1216`, `2023/1217`) to Twist & Shout (`2025/105`)

- **Primary Sources:**
  - Srinath Setty, Justin Thaler, Riad S. Wahby, *Lasso* (`https://eprint.iacr.org/2023/1216`); Arasu Arun, Srinath Setty, Justin Thaler, *Jolt* (`https://eprint.iacr.org/2023/1217`); Srinath Setty, Justin Thaler, Pengfei Zhu, *Proving CPU Executions in Small Space (Twist and Shout)* (`https://eprint.iacr.org/2025/105`); Pratyush Nair, Srinath Setty, Justin Thaler, *Proving Jolt in Small Space* (`https://eprint.iacr.org/2025/611`).
  - Upstream code (`https://github.com/a16z/jolt`, `main` @ `98ad4b0df49f48e4daf9db401f4f6efd7444b71c` and tag `v0.1.0-alpha` @ `55b9830a3944dde55d33a55c42522b81dd49f87a`):
    - Legacy Lasso/Spice: `jolt-core/src/lasso/memory_checking.rs` and `jolt-core/src/jolt/subtable/` (`v0.1.0-alpha`).
    - Current Twist: `crates/jolt-claims/src/twist/memory_checking.rs`, `crates/jolt-claims/src/twist/claim_reductions.rs`.
    - Current Shout & 55 RV64 tables: `crates/jolt-lookup-tables/src/traits.rs`, `crates/jolt-lookup-tables/src/interleave.rs`, `crates/jolt-lookup-tables/src/tables/`, `crates/jolt-prover/src/driver.rs`.
- **Why Jolt Left Lasso + Spice:** In `v0.1.0-alpha` (RV32I), Jolt used Spice (`2018/907`) for RAM/registers (~35 committed field elements per cycle + GKR grand-product trees) and Lasso/Surge (`2023/1216`) for $2^{64}$ instruction tables decomposed into $c \in \{4, 8\}$ subtables of size $2^{16}$, each running its own read/final counter offline memory check. **Twist and Shout** (`2025/105`) eliminates all grand products, LogUp fractions, and timestamp polynomials in favor of **tensor-decomposed one-hot address matrices $\mathsf{ra}_1, \dots, \mathsf{ra}_d \in \{0,1\}^{K^{1/d} \times T}$ + multilinear sumcheck**:
  1. **Shout (Read-Only Bytecode & 55 Virtual $2^{128}$ Instruction Tables):** Commits to $d$ binary one-hot chunks using pay-per-bit PCS commitments (Dory or Akita Module-SIS lattice PCS, costing $O(d \cdot T)$ group/lattice additions and **zero full scalar multiplications**). For the 55 RV64IMAC tables (`RangeCheckTable`, `AndTable`, `XorTable`, `UnsignedLessThanTable`, `ValidDiv0Table`, etc.), two 64-bit operands bit-interleave into $k \in \{0,1\}^{128}$, and Jolt runs an **8-phase 16-bit prefix-suffix sumcheck** (`PrefixSuffixDecomposition` in `crates/jolt-lookup-tables/src/traits.rs`) in $\Theta(T + 2^{16})$ field ops with **zero committed subtables**. Bytecode Shout folds ~60 decoded ELF columns into 5 Reed-Solomon fingerprints $\widetilde{\mathsf{Val}}_1 \dots \widetilde{\mathsf{Val}}_5$, and directly virtualizes register one-hot selectors (`rs1_ra`, `rs2_ra`, `rd_wa`) at **zero committed columns**.
  2. **Twist (Read/Write Registers & 8-Byte RAM):** Commits **only** to the sparse 1D write increment $\mathsf{Inc}(j) = \mathsf{wv}(j) - \mathsf{Val}(k_{\text{write}}(j), j)$ (`0` on reads) and defines virtual $\widetilde{\mathsf{Val}}(k, j)$ via $\widetilde{\mathsf{Val}}(r_{\text{addr}}, r_{\text{cycle}}) - \widetilde{\mathsf{Val}}_{\text{init}}(r_{\text{addr}}) = \sum_{j'} \widetilde{\mathsf{Inc}}(j') \widetilde{\mathsf{wa}}(r_{\text{addr}}, j') \widetilde{\mathsf{LT}}(j', r_{\text{cycle}})$. Twist's local prover updates sumcheck tables only where writes occurred, costing **$O(i)$ field multiplications** for a cell last written $2^i$ cycles ago (cache-like temporal locality in the prover without changing the circuit).
- **Lesson for Sherlock:** Shout's decomposed ALU tables and Twist's one-hot matrices rely entirely on **multilinear sumcheck + pay-per-bit PCS without a fixed-column PLONK verifier**. In `midnight-proofs` KZG PLONK, every committed column adds a dense degree-$2^k$ polynomial commitment and `+7,298` to `+15,487` node rows, and every lookup adds `+22,600` node rows — reversing Jolt's cost equation.

### 4.2 SP1 (`succinctlabs/sp1`): v3 Global LogUp $\to$ v4/Turbo $\to$ SP1 Hypercube Septic EC & LogUp-GKR

- **Primary Sources:**
  - SP1 Hypercube protocol specs: `https://docs.succinct.xyz/docs/sp1/hypercube/` (`global`, `logupgkr`, `shards`, `trace`, `jagged`, `zerocheck`, `recursion`), `https://docs.succinct.xyz/assets/files/SP1_Turbo_Memory_Argument-b042ba18b58c4add20a8370f4802f077.pdf`, Jagged PCS (`https://eprint.iacr.org/2025/917`).
  - Upstream code (`https://github.com/succinctlabs/sp1`):
    - `v3.0.0`: `crates/core/machine/src/memory/local.rs` (cross-shard LogUp).
    - `v4.0.0` (Turbo): `crates/core/machine/src/air/memory.rs`, `crates/stark/src/septic_curve.rs`.
    - `dev` (Hypercube, RV64IM over KoalaBear $p = 2^{31}-2^{24}+1$): `crates/core/machine/src/memory/consistency/columns.rs`, `crates/core/machine/src/memory/local.rs`, `crates/core/machine/src/memory/global.rs`, `crates/core/machine/src/operations/global_interaction.rs`, `crates/core/machine/src/global/mod.rs`, `crates/hypercube/src/septic_curve.rs`, `crates/core/machine/src/program/trusted.rs`, `crates/core/machine/src/bytes/mod.rs`, `crates/core/machine/src/syscall/chip.rs`.
- **Intra-Shard Memory:** Read-before-write Blum-et-al. offline checking on `InteractionScope::Local` via **LogUp-GKR** (**zero committed permutation columns**; single Phase-1 Jagged PCS commitment across variable-height chips). Each access emits `-prev_tuple` and `+curr_tuple` over 9 KoalaBear elements `(clk_high, clk_low, addr[0..3], val[0..4])` (48-bit clock, 48-bit address, 4$\times$`u16` word) and checks $0 \le \text{diff} - 1 < 2^{24}$ via `Range(16)` + `U8Range` in the $2^{16}$-row `ByteChip`. `MemoryBump` touches active registers at shard start so `RegisterAccessCols` needs only 2 timestamp columns (`prev_low`, `diff_low_limb`).
- **Why SP1 Abandoned Cross-Shard LogUp for Elliptic-Curve Multiset Hashing (v3 $\to$ v4/Hypercube):** In v3, global LogUp across shards required committing every shard's Phase-1 trace before squeezing global challenges $(\alpha, \beta)$ for Phase 2 — creating a cluster-wide synchronization barrier. SP1 v4/Hypercube replaced cross-shard LogUp with a **challenge-free deterministic multiset hash** into a prime-order **septic extension curve** $E(\mathbb{F}_{p^7}): y^2 = x^3 + 45x + 41z^3$ over $\mathbb{F}_p[z]/(z^7 - 3z - 5)$ (~217-bit security):
  - `MemoryLocalChip` emits one `Global` receive `(init_clk, addr, init_val)` and one `Global` send `(final_clk, addr, final_val)` per distinct address touched in the shard.
  - `GlobalChip` (`~242` columns/row) packs the 8-word event + `kind` + 8-bit `offset` into a width-16 **Poseidon2 permutation**, lifts the output to $x \in \mathbb{F}_{p^7}$, canonicalizes $y_6$ into the lower half-field for receives ($+P$) and upper half-field for sends ($-P$), and chains Weierstrass chord additions.
  - `MemoryGlobalInit` and `MemoryGlobalFinalize` sweep all dynamically initialized/finalized addresses in **strictly sorted order (`prev_addr < addr`)** across shards (`previous_init_addr` / `previous_finalize_addr`), while static ELF words are pre-summed into `vk.initial_global_cumulative_sum`. Dedicated **precompile shards** (`SHA`, `KECCAK`, `ED25519`, `SECP256K1/R1`, `BN254`, `BLS12381`, `UINT256`, `POSEIDON2`) communicate asynchronously over the same septic-curve `Global` bus.

### 4.3 RISC Zero (`risc0/risc0`): Two-Tier Poseidon2 Paging + Intra-Segment Offline RAM + `Lift`/`Join`/`Resolve`

- **Primary Sources:**
  - Protocol docs: `https://dev.risczero.com/proof-system/in-detail.pdf` (`https://dev.risczero.com/proof-system-in-detail.pdf`), `https://dev.risczero.com/api/zkvm/optimization`, `https://dev.risczero.com/api/recursion`, `https://dev.risczero.com/api/zkvm/composition`.
  - Upstream code (`https://github.com/risc0/risc0`, `main`, circuit `RV32IM:v2rev3___`):
    - L2 Paging & Merkle image: `risc0/binfmt/src/lib.rs`, `risc0/binfmt/src/image.rs`, `risc0/binfmt/src/sys_state.rs`, `risc0/circuit/rv32im/src/execute/pager.rs`, `risc0/circuit/rv32im/src/execute/segment.rs`.
    - L1 Zirgen circuit & LogUp `accum`: `risc0/circuit/rv32im/src/zirgen/defs.rs.inc`, `risc0/circuit/rv32im/src/zirgen/types.rs.inc`, `risc0/circuit/rv32im/src/prove/hal/mod.rs`.
    - Recursion (`lift`, `join`, `union`, `resolve`): `risc0/zkvm/src/claim/receipt.rs`, `risc0/zkvm/src/host/recursion/prove/mod.rs`.
- **Two-Tier Memory Hierarchy (Directly Analogous to Sherlock `PAGE` + `MEM` + `M3`):**
  1. **L2 Persistent Store (`MemoryImage`):** Full 4 GiB (`2^32`-byte) address space organized into **`1 KiB` pages (`PAGE_WORDS = 256` 32-bit words)** in a sparse depth-22 binary Poseidon2 Merkle tree (`MERKLE_TREE_DEPTH = 22`), with precomputed zero-subtree hashes `ZERO_CACHE.digests[0..=22]`.
     - **`PageIn` with Warm-Ancestor Short-Circuiting (`pager.rs`):** Each tree node tracks `Unloaded | Loaded | Dirty`. On the first access to a page in a segment, `PageIn` hashes the 256-word page (`322` v2 cycles) and walks ancestors upward (`13` v2 cycles/node), **stopping as soon as it reaches an ancestor already `Loaded` or `Dirty`** (`fixup_costs`). Cold `PageIn` = `608` v2 cycles (`5,130` v1 cycles).
     - **`PageOut` Only for `Dirty` Pages:** Read-only pages (code, constants, untouched stack frames) **never `PageOut`**. If the segment halts (`ExitCode::Halted`), `post_state` becomes `Digest::ZERO` and **`PageOut` is skipped completely**.
  2. **L1 Intra-Segment Cache (`MemoryIOLayout`):** Once paged in, loads and stores execute in **1 cycle with zero Merkle hashes** via in-place LogUp (`old_txn` `count = -1`, `new_txn` `count = +1` over `(addr, cycle, data_lo16, data_hi16)` + `DoCycleTableLayout` delta lookup in `[0, 2^po2)`), using 211 `data` columns (Phase 1) and 103 `accum` columns (Phase 2).
  3. **Partition-Independent PCD (`lift`, `join`, `resolve`):** Each `Segment` carries a self-contained `partial_image` + `read_record` and proves in parallel; `join` merges any adjacent `[a.pre, a.post]` and `[b.pre, b.post]` by checking `a.post == b.pre` (`SystemState { pc, merkle_root }`), while `resolve` discharges cross-run `Assumption`s in the recursion layer without running a verifier inside RV32IM.

- **Three Architectural Insights Directly Relevant to Sherlock `/1`:**
  1. **Write-Once Memory = Pure Static Graph (Zero Timestamps, Zero Sorting, Zero Read Re-Commitment):** Cairo executes over 2D relocatable segments `(segment_idx, offset)` (`segment 0` = program, `segment 1` = execution frames, `segments 2..k` = builtins & user segments), relocated post-execution into dense continuous addresses $1 \dots N < 2^{29}$.   3. **`VerifyInstruction` Deduplicated Decode Cache (`verify_instruction.rs`, `17` cols):** Stores **one row per distinct executed PC** (not one per dynamic step!), verifies the packed 64-bit instruction against write-once program memory **once**, decodes/range-checks offsets and flags **once**, and serves unlimited dynamic opcode fetches via LogUp.

### 4.8 2022–2026 Cryptographic Literature Synthesis

1. **LogUp (`https://eprint.iacr.org/2022/1530`, Haböck) & LogUp-GKR (`https://eprint.iacr.org/2023/1284`, Papini & Haböck):**
   - Replaces Plookup/Halo2 sorted-column permutations with $\sum \frac{1}{z + f_i(\vec{x})} = \sum \frac{m(\vec{x})}{z + t(\vec{x})}$ (valid when $\text{char}(\mathbb{F}) > N_{\text{reads}}$; on BLS12-381 $r \approx 2^{255}$, wrap-around is impossible). Standard PLONK LogUp requires committing $m(X)$ in Phase 1 and rational helper(s) $h_k(X)$ + running sum $\phi(X)$ in **Phase 2** after squeezing $(z, \alpha)$ — **blocked in Sherlock's leaf by `verifier_gadget.rs:310` (`phases == 1`)**. LogUp-GKR eliminates Phase-2 committed columns via a layered projective-fraction sumcheck, which requires a GKR sumcheck verifier (not present in `midnight-circuits`'s univariate PLONK `VerifierGadget`).
2. **Spice (`https://eprint.iacr.org/2018/907`, Setty et al., OSDI 2018) & Nebula (`https://eprint.iacr.org/2024/1605`, Arun & Setty, IEEE S&P 2026; building on HyperNova `https://eprint.iacr.org/2023/573`):**
   - Nebula formalizes **why randomized offline memory (`IS ∪ WS == RS ∪ FS`) breaks naive single-pass IVC**: if $(\gamma, \tau)$ were chosen before the final leaf commits, a cheating prover knowing $(\gamma, \tau)$ solves $a' + \gamma v' + \gamma^2 t' \equiv a + \gamma v + \gamma^2 t \pmod r$ online to spoof reads. Nebula's `ccIVC` fixes this via **two-pass folding**: Pass 1 (`\Pi_{\text{ops}}`) folds step execution while carrying homomorphic commitments $C_i$ to memory advice; $(\gamma, \tau)$ is squeezed from final $C_n$; Pass 2 (`\Pi_F`) re-folds the advice stream to compute grand products and checks $C'_n = C_n$.
3. **Constraint-Friendly Map-to-Curve Multiset Hashing — Groth, Malvai, Miller, Zhang (`https://eprint.iacr.org/2025/1503`, ASIACRYPT 2025, `https://github.com/Jasleen1/map-to-curve`) & El Housni, Bünz (`https://eprint.iacr.org/2026/590`, ASIACRYPT 2026, `https://github.com/yelhousni/map-to-curve`):**
   - **GMMZ (`2025/1503`, `x-increment`):** Maps $m \in [0, M)$ to $E(\mathbb{F}_q)$ via $x = mT + k$ ($0 \le k < T$), $y^2 = x^3 + ax + b$, and $y = z^2$ (assuming $q \equiv 3 \pmod 4$) so $-P = (x, -y)$ is excluded; multiset hash $H(S) = \sum P_i \in \mathbb{G}$ needs **zero Fiat-Shamir challenges**, enabling single-pass IVC!
   - **El Housni & Bünz (`2026/590`) — Three Critical Attacks & `y-increment` Fix:**
     1. *Missing $k < T$ range check* in GMMZ's reference circuit gave trivial collisions $(m, 256) \equiv (m+1, 0)$.
     2. *Standard-Model Lattice Attack on $j=0$ Curves (`bn254_forgery.sage`):* Curves with $a=0$ (BN254, Grumpkin, BLS12-381, Pasta) have CM endomorphism $\phi(x, y) = (\omega x, y) = [\lambda](x, y)$. Whenever $MT \gtrsim \sqrt{q}$, 2D lattice reduction finds $0 < x_1, x_2 < MT$ with $x_2 \equiv \omega x_1 \pmod q$ in milliseconds, yielding distinct messages $m_1 \neq m_2$ with known discrete-log ratio $P_2 = [\lambda] P_1$!
     3. *High 2-Adicity Blowup on Embedded SNARK Curves:* Embedded curves over pairing scalar fields have $q \equiv 1 \pmod{2^S}$ (**$S = 32$ on Jubjub / BLS12-381!**), forcing `x-increment` to check $y = z^{2^{32}}$ (+32 squarings and $2^{-32}$ forward witness-search probability — completely infeasible).
     - **`y-increment` Countermeasure (`2026/590`):** Encodes $y = mT + k$ ($2MT < q$). On Weierstrass, $-P = (x, -y)$ has $-y = q - y > MT$ (free inverse exclusion at **any** 2-adicity $S$!) and $\phi(x, y) = (\omega x, y)$ preserves $y$ (same message $m$).
     - **Critical Adaptation to Jubjub Twisted Edwards in BLS12-381 (`midnight-proofs`):** Note two subtleties when moving from BLS signatures to multiset hashing on Jubjub ($-x^2 + y^2 = 1 + d x^2 y^2$, $j \neq 0$, cofactor $8$): (i) on cubic Weierstrass, 3 $\mathbb{F}_q$-roots $x_1, x_2, x_3$ at horizontal line $Y = y_0$ satisfy $P_1 + P_2 + P_3 = \mathcal{O}$ (allowing $\{m, m, m\}$ cancellation unless $x$ is canonicalized!), whereas Twisted Edwards is **quadratic in $x^2$** (at most 2 roots $\pm x_0$); (ii) on Twisted Edwards, negation is $-(x, y) = (-x, y)$, so inverse + 8-torsion exclusion is achieved cleanly by witnessing $P_{\text{root}}$ with $P_0 = [8]P_{\text{root}}$ ($T = 2048 \implies (15/16)^{2048} \approx 2^{-190}$ completeness failure), $y_0 = m \cdot 2048 + k$ ($k \in [0, 2048)$), and **canonical $x_0 \in [1, \frac{q-1}{2}]$** ($2 x_0 < q$). Contrast this ~30-row relation with deterministic SVDW `hash_to_curve` in `midnight-circuits-7.3.0/src/ecc/hash_to_curve/{htc_gadget.rs:99-111,mtc.rs:55-250}`, which runs Poseidon + two full SVDW field inversions/square-roots/isogenies (**hundreds of rows per element**).
4. **Sublinear KZG Fixed-Table Lookups — Caulk (`https://eprint.iacr.org/2022/621`), Baloo (`https://eprint.iacr.org/2022/1565`), and `cq` (`https://eprint.iacr.org/2022/1763`, `https://github.com/geometryxyz/cq`):**
   - `cq` achieves $O(n \log n)$ field ops and $O(n)$ $\mathbb{G}_1$ ops independent of table size $N$ via FK20 precomputed quotient commitments, **but** requires (a) a **degree-$N$ $\mathbb{G}_2$ SRS** (`[1]_2 \dots [\tau^N]_2`, whereas Midnight Ledger 9's KZG SRS only provides `[1]_2, [\tau]_2`), (b) **5 pairings** in the verifier (incompatible with pairing-free KZG accumulator folding in `VerifierGadget`), and (c) $O(N \log N)$ per-table preprocessing (incompatible with per-program `PROG` tables under `GP-1` fixed keys).

### Detailed Candidate Analysis (`(a)`–`(f)`)

#### `(a)` Memory & Program Read Cache (`PAGE` Bus Deduplication vs Merkle Walk per Read)
- **Mechanics (`(a1)` + `(a2)`):**
  - Instead of authenticating a Merkle path inside every step slot, `PAGE` is a fixed-capacity provider region of $B$ block openings per leaf (e.g., $B = 4$ blocks of $C = 8$ contiguous cells = **32 cached provider rows** `(CHIP_PAGE, space_addr, a, b, c)` on the existing 5-column `bus`, `crates/mori-chip/src/bus.rs:47-62`).
  - Each active block opening $b \in [0, B)$ takes an aligned base `(space, block_idx)` (`space = 0` for `PROG` verified against `pre.prog_root`; `space = 1` for `MEM` verified against `pre.mem_root` with range check `(block_idx + 1) * 8 <= pre.len` or per-row `addr < pre.len` via `ALU`/`RANGE`, enforcing **Quint invariant `D2`**, `chipLeafCached.qnt:313-315`).
  - Matching `m3.rs:42-55`, opening one 8-cell block hashes its 8 4-word records + 7 binary internal nodes (`23` perms) + `TOP` path nodes (`17` perms at `TOP = 17` $\implies$ `40` perms = `2,800` `ESTIMATE` rows per 8-cell block, i.e., **`350` `ESTIMATE` rows per cached cell**; at `TOP = 29` for $2^{32}$ cells, `52` perms = `3,640` `ESTIMATE` rows per block = **`455` `ESTIMATE` rows per cached cell**). Unused block slots (`en_b = 0`) emit `ZT = (0,0,0,0,0)` (**Quint `D8`**, `chipLeafCached.qnt:134-135`) and route dummy hashes without changing `pre_d`.
  - Every step slot reading `PROG` or an old cell `< pre.len` simply emits `(CHIP_PAGE, space_addr, a, b, c)` on `L0` or `L1`. **Every temporal hit (same cell read 2–64 times in loops/helpers) and every spatial hit (7 neighbor cells in the same 8-cell block) costs `0` extra Poseidon rows.**
- **Soundness Argument:**
  1. `midnight-proofs`'s `lookup_any` proves $\forall \text{ active request } r,\; r \in \text{Providers}$ up to lookup soundness $\frac{O(2^{k_{\text{leaf}}})}{|\mathbb{F}|} \approx 2^{-241}$ (`midnight-proofs-0.8.3/src/plonk/lookup.rs`).
  2. Provider selector gating (**Quint `D1`**, `chipLeafCached.qnt:328-331`) ensures request rows cannot self-satisfy.
  3. Disjoint `chip` tags (`CHIP_MEM != CHIP_PAGE != CHIP_ALU != CHIP_DEC != 0`) and strict address partitioning (`PAGE` requires `addr < pre.len` for `space = 1`, while `MEM` assigns `addr = pre.len + k` for $k \in [0, C)$, **Quint `D2` & `D6`**, `chipLeafCached.qnt:314,323-324`) make the union of provider rows a **well-defined partial function** of `(chip, space_addr)` under Poseidon collision resistance. Because the table is a function of its key, set inclusion without multiplicities is 100% sound for arbitrary read reuse.
- **Why `(a3)` KZG `committed_instances` ROM Loses:** Although `mori-chip/Cargo.toml:14` and `mori-recursion/Cargo.toml:45` enable `"committed-instances"` and `VerifierGadget` (`verifier_gadget.rs:432-436,534-549,625-639`) supports `Expression::Instance` in `lookup_any` at $O(1)$ scalar transcript cost, a leaf committed-instance column has domain size $2^{k_{\text{leaf}}}$ (`midnight-proofs-0.8.3/src/plonk/prover.rs:420`), capping `|PROG|` at $\sim 8,186$ rows for $k=13$ (violating **`GP-1`** on larger programs), while 5 tuple columns add 5 foreign $\mathbb{G}_1$ points (`25` native limbs in `IvcState`, **`+36,500` to `+55,000` `ESTIMATE` node rows** and **`+8,000` to `+18,000` `ESTIMATE` decider rows**, threatening the decider's `16,109` table-row margin).

#### `(b)` Full-Run Offline Memory Checking Instead of a Merkle Tree
- **`(b1)` Randomized Rational Sums (LogUp) / Grand Products (Spice, Nebula `ccIVC`, Airbender 2-Pass):**
  - **Blocked in-leaf** by `verifier_gadget.rs:310` (`assert_eq!(cs.phases().count(), 1)`): neither rational helper columns $h(X) = \frac{m(X)}{\gamma + T(X)}$ nor Spice running products can draw a post-advice challenge inside a leaf on pinned `midnight-circuits 7.3.0`.
  - **Blocked across-leaf** by Nebula's causal challenge obstacle (`2024/1605`): leaf 0 cannot fold an unforgeable randomized fingerprint before leaf $L-1$ commits to its memory witness unless the architecture switches to a **two-pass global pre-commitment** (Nebula `ccIVC` = 2x node folding proofs; Airbender `MemorySubtree` = pre-commit all leaves before proving any leaf, breaking streaming proving and **`GP-4`** reusable sub-DAG proofs).
- **`(b2)` Challenge-Free Jubjub `y-increment` Elliptic-Curve Multiset Hashing (`2025/1503` + `2026/590`):**
  - **How it works cleanly on `phases == 1`:** Using native embedded Jubjub ($-x^2 + y^2 = 1 + d x^2 y^2$ over $\mathbb{F}_{r_{\text{BLS12-381}}}$, `midnight-circuits-7.3.0/src/ecc/native/edwards_chip.rs:324-420`), each memory event $m_{\text{enc}} \in [0, 2^{243})$ lifts to $P_0 = [8]P_{\text{root}} \in \mathbb{G}_{r_{\text{Jubjub}}}$ with $y_0 = m_{\text{enc}} \cdot 2048 + k$ ($k \in [0, 2048)$) and canonical $x_0 \in [1, \frac{q-1}{2}]$ ($2 x_0 < q$), accumulated into running Jubjub points `(Acc_W, Acc_R)` in `IvcState` with **0 Fiat-Shamir challenges**.
  - **Why it STILL loses to `(a2)` Merkle + Bus Cache in Sherlock `/1`:**
    1. *243-bit message ceiling forces Poseidon anyway:* A Sherlock cell `(space_addr, a, b, c)` holds up to three 255-bit field elements (`vd` value digests in `sherlock-value/1`, `design.md:198-206`) = ~829 bits $\gg 243$ bits. Every memory event must **still run 2 Poseidon permutations (`140` `ESTIMATE` rows)** to hash `(space_addr, a, b, c)` into 243 bits before lifting to Jubjub (just as SP1 Hypercube runs Poseidon2 inside `GlobalChip`), plus `4` Edwards rows + `~22` `RANGE` rows (to check $2 x_0 < q$ over non-power-of-two $q$) = **`~167` `ESTIMATE` rows/write** and **`~340` `ESTIMATE` rows/read** (for timestamped `-P(old)` / `+P(new)` re-emission). Note that write-once `[m_a] P_0` without timestamps would require leaf $i$ to know future read counts $m_a$ across the entire run, breaking **`GP-4`** DAG reuse!
    2. *$O(N_{\text{alloc}})$ teardown sweep:* Because Sherlock `/1` is write-once, $N_{\text{alloc}}$ grows linearly with run length (~0.5–2 cells/step). Closing the multiset equality `IS ∪ WS == RS ∪ FS` at `Halt` requires sweeping **every cell allocated in the entire run** into `FS` in sorted `prev_addr < addr` order (SP1 `MemoryGlobalFinalize` / Airbender `inits_and_teardowns`), adding **15–30% `ESTIMATE` extra teardown leaves** and preventing $O(1)$ state checkpointing across **`GP-2`** continuations.

#### `(c)` Instruction, Decode, Program, Type, and Constructor Tables (`DEC`, `PROG`, `ty_d`)
1. **`DEC` (`crates/mori-chip/src/dec.rs`, 108 rules in C6):** `DEC` is program-independent (`GP-1` safe). In `chipLeafCached.qnt:327`, `DEC` already lives as fixed rows on the unified bus `(CHIP_DEC, class_key, rule_id, flags, 0)`. If each step slot fits inside the existing 2 bus request lanes (`L0, L1`) — e.g., when decoded micro-flags are read once per step or folded into `PROG` normalization — moving `DEC`'s 108 rows onto `bus` eliminates `dec.rs`'s separate lookup argument and 2 fixed columns, **saving `~34,608` `ESTIMATE` node rows** (`22,600 + 2*6,004`). Even if `DEC` stays as lookup #4 so slots can issue `DEC` + `ALU` + `MEM/PAGE` in one step, widening `DEC` from 2 to 3–4 packed columns lets one lookup deliver `(rule_id, reg_mux_codes, bus_op_codes)`, shrinking `CORE` gate degree without adding lookups.
2. **`PROG` & Static Schema Tables (`crates/mori-core/src/sherlock/helper_machine/shared.rs:670-686`):** All 12 static program tables (`code_rows`, `function_rows`, `code_child_slots`, `parameter_slots`, `pattern_rows`, `match_plan_rows`, `match_arm_rows`, `type_rows`, `constructor_rows`, `constructor_field_slots`, `constant_nodes`, `constant_field_slots`) are committed under `prog_root` using tagged sub-space keys and cached on-demand in `PAGE` (`(a2)`).
3. **Pre-Digested `ty_d` and `const_vd` (`(c2)`, `dissent.md:83-101`):** Computing a nominal ADT's recursive structural type digest `ty_d` (`crates/mori-core/src/sherlock/helper_machine/shared/adt.rs:34-41`) or a constant literal's `sherlock-value/1` digest at runtime would burn multiple Poseidon permutations on every constructor build or constant load. Storing `ty_d` directly in each admitted `type_rows`/`constructor_rows` entry and `const_vd` in each `constant_nodes` entry under `prog_root` turns runtime `ty_d` and constant-digest lookup into a **free field read from the `PAGE` cache** (`140–1,120` `ESTIMATE` leaf rows saved per leaf).

#### `(d)` `ALU` and `RANGE` as Decomposed Lookup Tables (Jolt Style) vs Current Gates
- **Quantitative Rejection:** Current `alu.rs` + 1-limb running-sum `range.rs` (`crates/mori-chip/src/{alu.rs:1-120,range.rs:11-35}`) proves any 128-bit `ADD`/`SUB`/`LT`/`EQ` in **12 leaf rows** (`192` rows total for 16 ops = 2.9% of the leaf) using **1 lookup** (`4,096`-row 12-bit table) and **0 extra advice columns**. Replacing it with an $8\times 8$-bit byte lookup table ($k_{\text{ops}} \times 65,536 \ge 262,144$ rows) forces leaf `k = 13 -> 19` (**64x slower leaf proving**); using Nexus-style $4\times 4$-bit nibble tables (`<= 4,096` rows) requires **32 nibble lookups** per 128-bit op (`32` rows on 1 lookup lane = `2.7x` *more* leaf rows, or 4 lookup lanes = **`+90,400` `ESTIMATE` node rows**!). Algebraic gates + 12-bit `RANGE` strictly dominate in KZG PLONK recursion (including future 128-bit `MUL`/`DIV`/`MOD`, which need only 1 degree-2 witness gate $a = q\cdot b + r$ + two 12-bit running-sum `RANGE` checks = `24` `ESTIMATE` rows).

#### `(e)` Poseidon Hash Memoization (`sherlock-value/1`, Constructors, Zero Subtrees)
1. **Intra-Leaf `CHIP_HASH` Bus Deduplication + Fixed Constants (`(e1)`):** `PoseidonCfg` already interfaces via provider tuples (`crates/mori-chip/src/hashchip.rs:11-14`). Exposing `(CHIP_HASH, domain_tag, in0, in1, out)` on `bus` deduplicates repeated 2-to-1 compressions within a leaf (`70` `ESTIMATE` rows saved/hit), while adding ~40 fixed bus rows for `ZERO_HASH[0..37]` (empty Merkle subtree roots, as in RISC Zero `ZERO_CACHE`) and canonical scalar digests (`vd(Unit)`, `vd(Bool(false/true))`, `vd(UInt(0/1))`, `vd(Nil)`) eliminates hashing those constants forever at **`0` node/decider cost**.
2. **Run-Wide Value-Digest Memoization via Write-Once `MEM` (`(e2)`):** Storing each allocated node's `sherlock-value/1` digest `vd` directly inside its write-once cell/fat reference (`design.md:198-206`, `review.md:124`) makes `MEM` + `PAGE` a **cross-leaf, DAG-aware Poseidon cache**: shared subvalues in trees/lists/ADTs are hashed **once at allocation** (`140–280` `ESTIMATE` rows) and never re-hashed at parent construction or `Halt` (`0` halt-traversal leaves).

#### `(f)` Hybrid Winner: Write-Once Two-Tier Bus Cache + Lazy `C = 8` Segment Carry + `S = 64`
Combining `(a2) + (c2) + (e1) + (e2)` with **Lazy `C = 8` Segment Carry** and **`S = 64`**:
- **Lazy `C = 8` Segment Carry:** Carry the active 8-cell write buffer `seg_buf[0..8]` (or incremental sponge state + `sub_idx = len mod 8`) in `(pre_d, post_d)` (~8–24 extra words = `+4` to `+12` perms = `+280..840` `ESTIMATE` rows/leaf, or `+4..13` `ESTIMATE` rows/step at `S = 64`), and run the M3 tree update (`23 + 2*TOP` perms) **only when `sub_idx` wraps through 8** (gated on the M3 walk so a leaf that does not fill a segment verifies `post.mem_root == pre.mem_root` with **0 tree-walk rows**, or runs 1 gated dummy walk).
- **Why `S = 64` transforms both caching and proving speed:**
  - Because `k_leaf` in `13..=20` adds `< 30` rows to the `k = 20` node (`design.md:161`), raising `S` from `16` (`k = 13..14`) to **`64` (`k = 15`, `32,768` domain rows, `~24,500` `ESTIMATE` active rows)** costs **`~0` `ESTIMATE` node rows** and **`0` decider rows**.
  - On this host, a `k = 20` leaf proves in `66 s` (`sherlock-runlength-consensus-20261111/BRIEF.md:22`), so a `k = 15` leaf (`32x` smaller than `k = 20`) takes **`~2.1–3.0 s` `ESTIMATE`**, while **cutting `61–67 s` node folding steps by 4x** — reducing per-step wall-clock proving time from `~4.2 s/step` (`67/16`) to **`~1.1 s/step` `ESTIMATE`** (**~3.8x end-to-end throughput gain**), cutting `pre_d`/`post_d` Poseidon overhead per step by **4x**, and quadrupling the intra-leaf L1 `PAGE` cache window!

## Q3: Interaction with C6 Outcome-Only Publication, `SRC-023`, Run-Length Ceiling, `SI-12..SI-14`, and `GP-1..GP-4`

### 3.1 C6 Outcome-Only Publication & `SRC-023` Partition Independence
- Under the adopted C6 boundary (`review.md:14,49-53`), the public decider statement is `[prog_d, input_d, outcome_d, n_steps]` and `claim_d = H(SHK_RUN, 1, prog_d, input_d, outcome_d)`.
- **L1 Bus Cache Partition Independence:** Whether an execution is split at step $k$ (so step $k+1$ reads cell $a$ via `PAGE` in Leaf 2) or kept in one leaf (so step $k+1$ reads cell $a$ via `MEM` or a warm `PAGE` row in Leaf 1), both return the identical tuple `(a, b, c)`, advance `n_steps` by 1, and produce the identical `outcome_d`. Cache hit/miss counts never enter `pre_d`, `post_d`, or public inputs.
- **Fixing E8's Short-Leaf Address Drift (`SRC-023` Edge Case):** In E8 (`crates/mori-chip/src/rf.rs:92-99`, `experiments-4.md:148-153`), every leaf boundary advances `len` to the next multiple of `C = 8`. If a prover splits leaves early (`1 <= steps < S`), unused segment tail slots shift `len` (changing future raw addresses) and **prematurely exhaust a fixed segment ceiling** (turning a provable run into a capacity refusal depending on leaf split points!). **Lazy `C = 8` Segment Carry (`Q1(f)`)** increments `len` strictly by 1 per actual cell write and flushes to M3 only when `len mod 8 == 0`, making `len`, every raw address, and `mem_root` **100% invariant to where leaves close** (`SRC-023` exact state isomorphism!).

### 3.2 Run-Length and Memory Ceiling (`D3` $2^{17}$ Leaves / $2^{20}$ Cells vs $2^{64}$ Steps)
- **What $2^{64}$ is (`research/sherlock-runlength-consensus-20261111/BRIEF.md:14`):** The 64-bit step-counter bound `h < 2^64` in `SRC-004` preventing modular wraparound in recursion, never a $2^{64}$-row circuit.
- **Removing the Artificial `D3` Ceiling (`2^17` leaves / `2^20` cells):** `D3` coupled leaf count to `TOP = 17` (`m3.rs:34`). With Lazy `C = 8` Segment Carry:
  1. Pure compute/lookup steps burn **zero** memory addresses, immediately decoupling leaf count from `TOP` (up to $2^{64}$ compute steps!).
  2. Widening `TOP` from `17` ($2^{20}$ cells) to **`TOP = 37` ($2^{40}$ cells = 1 trillion cells)** adds only $2 \times 20 = 40$ Poseidon perms per 8-cell flush (`+2,800` `ESTIMATE` rows per flush) and `+70 * 20 = +1,400` `ESTIMATE` rows per cold 8-cell `PAGE` block miss (`+175` `ESTIMATE` rows per cached cell), with **`+0` node rows and `+0` decider rows**! Even **`TOP = 61` ($2^{64}$ cells — matching `h < 2^64` with zero per-run memory ceiling below $2^{64}$!)** adds only `88` perms per flush (`+6,160` `ESTIMATE` rows) and `44` perms per 8-cell `PAGE` block (`+385` `ESTIMATE` rows/cached cell), fitting comfortably inside `k = 15` (`32,768` rows) at `S = 64`!
  3. **Cache Synergy:** Deeper `TOP` (`37` or `61`) increases cold Merkle walk length, making `(a2)`'s intra-leaf L1 deduplication + 8-cell spatial block paging **2.2x–2.9x more valuable** (`3,080–4,410` `ESTIMATE` rows saved per temporal hit!). For checkpointed multi-run jobs, **GP-2** claims also compose runs cleanly without exposing intermediate raw state on chain.

### 3.3 `SI-12..SI-14` Field Slices (`dissent.md` `D-1`, `shared.rs:707-725,803-810,852-862`)
- **Problem (`openspec/changes/sherlock-vm-consensus-20261107/dissent.md:17-80`):** C6 represents `ValSliceC` / `FieldSliceC` as contiguous `(start, len)` ranges (`Append` copies `src` to `dest_start` in $O(k)$ steps per argument; `Build` scans `src` to `field_start`), creating $O(k^2)$ allocation churn when interleaved with `ENV`/`FRAME`/`TASK` writes in a single log.
- **Resolution with Two-Tier Bus Cache (`Q1(f)`):**
  1. **Inline Arity $\le 2$ + Cons-Spine Staging + Contiguous Seal at `Build`:** Store arity $0, 1, 2$ constructor fields directly inline in the `DataNode` record (>90% of constructors use **zero** slice cells!). During `ArgsF` / `ConstructorFieldsF` evaluation, stage arguments in $O(1)$ per element as a **cons-linked spine** `(TAG_STAGE, ref, vd, prev_link)` (eliminating `Append`'s $O(k^2)$ copy!). For arity $\ge 3$ constructors, `Build` writes the final constructor's fields once into a **dedicated key-prefixed sub-space `(SPACE_FIELD, field_len++)`** (which has its own monotonic counter `field_len`, unfragmented by `FRAME`/`ENV` spills!).
  2. **Why `C = 8` Block `PAGE` Excels Here:** Both `Bind` (iterating parameter/argument slices) and `Match`/`Plan` ($O(1)$ indexed projection `field_start + field_idx`, `shared.rs:832`) hit contiguous cells in `SPACE_FIELD` (or recently appended `MEM` cells inside an `S = 64` leaf), so **one 8-cell `PAGE` block opening serves up to 8 constructor fields or call arguments with 0 extra Merkle walks**.

### 3.4 Full `GP-1..GP-4` Compliance (`general-purpose.md:1-58`)
- **`GP-1` (Universal VM — 1 fixed key set, all programs/inputs/outcomes, `< 2^64` height):** Preserved in full. `prog_root` + `PAGE` handles programs of arbitrary size without changing leaf/node/decider VKs; `TOP = 61` (or `TOP = 37` + GP-2 continuations) removes the $2^{17}$-leaf cap.
- **`GP-2` (Cross-Run Composition):** Verified upstream `claim_d` values (checked by `R`/`C` nodes in `research/sherlock-gp-architecture-20261110/architecture.md:155-220`) are injected into write-once `MEM` via an advisory/input step (OpenVM `Phantom + HintStore` / RISC Zero `Assumption + Resolve` pattern) and read via `MEM`/`PAGE` like any other immutable cell.
- **`GP-3` (Foreign Proofs):** Because `(f)` adds **0 decider circuit/table rows** (`1,032,467 < 1,048,576` preserved) and keeps the `k = 20` node at `~795k–830k` `ESTIMATE` rows (`<= 950,000` gate), the GP-3 `F`/`C` foreign-verifier pathway retains its full node and decider budget.
- **`GP-4` (Any PCD DAG Shape):** Every `U` leaf depends **only** on its local `(pre_d, post_d)` boundary. Disjoint step intervals prove embarrassingly in parallel with zero Pass-1 `MemorySubtree` synchronization and zero future-multiplicity prediction, and any proven sub-tree can be reused across multiple parent runs.
