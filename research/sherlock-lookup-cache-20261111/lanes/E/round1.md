## 0. Threat Model, Measured Baseline, and Hidden Baseline Gaps

### 0.1 Threat Model
Only fixed circuit polynomial constraints, `lookup_any` relations, equality-enabled copy constraints, fixed verifying keys (`Leaf`, `SherlockIvcRelation`, `RunDeciderRelation`), and on-chain Compact ledger pins are trusted. A malicious prover has arbitrary control over:
1. Every advice column cell, unused/padding row, and non-deterministic hint in every leaf proof (`crates/mori-chip/src/rfcore.rs:1-120`, `crates/mori-chip/src/m3.rs:149-173`).
2. Leaf boundary cuts (`1 <= steps <= S_MAX` with `S_MAX = 16`, `crates/mori-recursion/src/ivc.rs:77,371-372`).
3. Child proof byte streams (`TranscriptGadget` ignores trailing bytes and assigns curve commitments via `assign_without_subgroup_check`, `midnight-circuits-7.3.0/src/verifier/transcript_gadget.rs:79-85,126-143`).
4. Arbitrary composition graphs (chains, trees, and diamond DAGs of sealed claims and foreign proofs) under `GP-1` through `GP-4` (`openspec/changes/sherlock-vm-consensus-20261107/general-purpose.md:11-55`).

### 0.2 Measured Baseline and Three Structural Constraints
From the repository's measured experiments (`research/sherlock-processor-analogy-20261110/experiments-4.md:55-76,157-159`, `research/sherlock-c6-outcome-ledger9-review-20261110/review.md:213`, `crates/mori-chip/tests/e3_spike.rs:587-609`):
- **E8 Chip Leaf (`narrow,1,pos_m3+r1+a1+pc`, `S = 16`):** `6,511` rows (`k = 13`, `8,186` usable rows), `12` advice columns, `13` equality-enabled columns (`12` advice + `1` instance), `20` fixed columns, `4` `lookup_any` arguments (`2` bus lanes in `crates/mori-chip/src/bus.rs:50-61`, `1` single-limb running-sum `RANGE` in `crates/mori-chip/src/range.rs:98-102`, `1` `DEC` table in `crates/mori-chip/src/dec.rs:27-30`), max gate degree `6`. Of the `6,511` rows, **`6,090` rows (93.5%)** are Poseidon (`87` permutations × `70` rows/permutation, `crates/mori-chip/src/poseidon.rs:59`, `crates/mori-chip/src/m3.rs:54`).
- **Recursion Node (`SHKIVC06`, `crates/mori-recursion/src/ivc.rs:64`):** `823,466` rows (`k = 20`), against the `<= 950,000` gate (`126,534` rows headroom). Node verification cost follows the measured linear fit (`research/sherlock-processor-analogy-20261110/experiments-2.md:125,230`, `experiments-3.md:174-175`):
  $$\text{Node rows} \approx 570,957 + 7,298 \cdot n_{\text{advice}} + 8,189 \cdot n_{\text{eq}} + 6,004 \cdot n_{\text{fixed}} + 22,600 \cdot n_{\text{lookup}}$$
  Each `lookup_any` argument adds `3` variable-base $\mathbb{G}_1$ commitments (`permuted_input`, `permuted_table`, `product`), `5` scalar evaluations, and `5` multiopen queries across `x`, `x * omega`, and `x * omega^{-1}` (`midnight-circuits-7.3.0/src/verifier/lookup.rs:56-161`). By contrast, increasing polynomial gate count `4x` adds only `+1,623` node rows (`experiments-2.md:125`), and increasing leaf `k` adds only `1` squaring and `1` multiplication per step of `pow(x, (1 << k) - 1)` (`midnight-circuits-7.3.0/src/verifier/verifier_gadget.rs:582-584`).
- **Terminal `RunDecider` (`SHKRUND1`, `crates/mori-recursion/src/run_decider.rs:48`):** `929,166` gate rows (`k = 20`, gate `<= 1,000,000`), **but `1,032,467` `table_rows` out of `1,048,570` usable rows** (`2^20 - 6` blinding rows; `review.md:213`).
- **Three Structural Red-Team Traps in the Stack:**
  1. **Single-Phase In-Circuit Verifier Lock (`verifier_gadget.rs:308-310`):** `VerifierGadget::parse_trace` executes `assert_eq!(cs.phases().count(), 1);` and panics on any rotation outside `{-1, 0, +1}` (`verifier_gadget.rs:604-610`). Leaf circuits **cannot** commit phase-0 trace columns, squeeze an in-leaf Fiat-Shamir challenge, and commit phase-1 running-product or LogUp columns.
  2. **The `RunDecider` `pow2range` Table Cliff (`pow2range.rs:215-236`):** In `midnight-zk-stdlib-2.4.0/src/lib.rs:1865,2121`, `RunDecider` at `k = 20` initializes `Pow2RangeChip` with `max_bit_len = 19`. `Pow2RangeChip::load_table` (`midnight-circuits-7.3.0/src/field/decomposition/pow2range.rs:220-232`) dynamically loads $2^b$ table rows for each distinct bit-length tag $b \in \text{queried\_tags}$. With `1,032,467` `table_rows` already loaded, only **`16,103` usable table rows remain** below `1,048,570`. Because $2^{14} = 16,384 > 16,103$, **any** new range check or integer decomposition in `RunDecider` whose optimal limb schedule (`midnight-circuits-7.3.0/src/field/decomposition/chip.rs:125-132`) touches a previously unqueried tag $b \in \{14, 15, \dots, 19\}$ materializes $\ge 16,384$ new table rows (`1,032,467 + 16,384 = 1,048,851 > 1,048,576` `ESTIMATE`), tipping `RunDecider` to `k = 21` and breaking compatibility with the `k = 20` ceremony SRS (`crates/mori-chip/tests/e3_spike.rs:60,89`).
  3. **Hidden Omission in the E8 `6,511`-Row Baseline (`m3.rs:52-54`):** In `crates/mori-chip/src/m3.rs:54`, `PERMS = 8 * 2 + 7 + 2 * TOP + 2 * 15 = 87` (`6,090` rows) budgets **only** the `8` appended records (`16` perms), the `7` internal segment-tree hashes, the `2 * 17 = 34` top-tree hashes for the single appended segment (`old_root` from `0` and `new_root` from `seg_root`, `m3.rs:240-259`), and the `30` `pre_d`/`post_d` carrier hashes. **Zero older-memory `PAGE` segment reads and zero `PROG` Merkle openings are wired in `m3.rs` yet.** Adding even `2` uncached older segment reads (`2 * (16 + 7 + 17) = 80` perms = `+5,600` rows `ESTIMATE`, or `2 * (2 + 3 + 17) = 44` perms = `+3,080` rows `ESTIMATE` with single-cell opening) pushes `6,511 + 3,080 = 9,591 > 8,186`, crossing `k = 13 -> k = 14`; `16` uncached reads push the leaf above `31,000` rows (`k = 15..16` `ESTIMATE`). Intra-leaf read caching is therefore mandatory for real `S = 16` execution.

### Candidate `(a)`: Intra-Leaf / Per-Leaf Memory Read & Segment Cache ("L1 Lookup Cache")

#### Q1(a) Design & Cost Estimates (`ESTIMATE`)
In `(a)`, the leaf keeps Halo2's single-phase `lookup_any` bus (`crates/mori-chip/src/bus.rs:50-61`), where lookup arguments check **set membership without multiplicities** (`models/sherlock/quint/chipLeafCached.qnt:43-45`). Instead of authenticating a Merkle path per memory read (`M1`), a leaf provisions $K_{\text{page}}$ `PAGE` cache slots (e.g., $K_{\text{page}} = 2$ cached segments or individual cells from `mem_root_pre`) alongside the intra-leaf `MEM` write region (`C` append slots) and `CORE` architectural registers (`top` frame register `D7` in `chipLeafCached.qnt:6-15`, plus current environment pointer). Every `PAGE` cache slot authenticates its opening against `mem_root_pre` once via `PoseidonCfg`, and all `S = 16` steps read any cached entry any number of times over `bus.rs` at zero extra Poseidon cost.

- **Leaf Cost (`ESTIMATE`):** Each cached single-cell opening in an 8-cell segment (`TOP = 17`) costs `2` record perms (or `1` perm if cells pack into 2 field elements) + `3` segment-internal perms + `17` top-tree perms = `22` perms (`1,540` rows `ESTIMATE`). With $K_{\text{page}} = 2$ older-memory cache slots + `1` `PROG` 4-instruction block (`18` perms = `1,260` rows `ESTIMATE`) added to E8 (`6,511` rows), the leaf totals `6,511 + 3,080 + 1,260 = 10,851` rows `ESTIMATE` (`k = 14`; or `~9,311` rows `ESTIMATE` if segment roots store 1-perm packed records). Widening `TOP` from `17` to `30` adds `13 * 4 * 70 = 3,640` rows (`~12,950–14,490` rows `ESTIMATE`, still fitting cleanly in `k = 14`, `16,378` usable rows).
- **Node & `RunDecider` Cost (`ESTIMATE`):** Reusing `bus.rs`'s existing `2` lookup lanes adds `0` lookups (`+0` lookup rows), `0` to `1` advice column (`+0` to `+7,298` node rows `ESTIMATE`), and `+2` rows from `k = 13 -> 14` (`verifier_gadget.rs:583`), yielding **`823,468` to `830,766` node rows `ESTIMATE`** and **`929,166` gate / `1,032,467` `table_rows` (`+0` delta) in `RunDecider`**.

#### Q2(a) Concrete Red-Team Exploits Against Naive `(a)` & Soundness Proof of Hardened `(a)`
Because `lookup_any` ignores multiplicities, **soundness of `(a)` collapses the instant two rows in the union provider table $\mathcal{T} = \mathcal{T}_{\text{PAGE}} \cup \mathcal{T}_{\text{MEM}} \cup \mathcal{T}_{\text{PAD}}$ share the same non-zero `(chip, key)` with distinct values, or expose a tuple not causally valid at the requesting step.** Five concrete witness attacks break unhardened `(a)`:

1. **Exploit A1 — Intra-Leaf Time-Travel Read (`addr >= cur_len` Written Later in Same Leaf):**
   - *Trace:* Suppose step $t = 0$ has `pre.len = 16` and executes `LOAD addr = 17`, while step $t = 2$ executes `ALLOC` at `addr = 16` and step $t = 3$ executes `ALLOC v = 999` at `addr = 17`. The leaf's `MEM` provider table contains row `(TAG_CELL, 17, 999, NIL, 0)` across the entire circuit. If `CORE` omits `ALU_LT(addr, pre.len)` (`MUTANT = "no_read_bound"`, `chipLeafCached.qnt:188,194`) or checks `addr < post.len` / `addr < base + C` (`MUTANT = "read_bound_final"`, `chipLeafCached.qnt:192`; `quint-check.md:228-230`), step $0$'s bus request `(TAG_CELL, 17, 999, NIL, 0)` succeeds! In C6 (`crates/mori-core/src/sherlock/helper_machine/shared/owner_runtime.rs:4744-4755`), reading a future allocation lets a `Data` node at `addr = 16` store a child reference `RefC::Data(17)` (`id >= owner`), violating `SI-13` acyclicity and causing structural equality (`owner_runtime.rs:3902`) to loop endlessly to `OutOfFuel` or forge cyclic terms.
2. **Exploit A2 — Inactive Cache Slot Forgery (`act == 0` Zero-Tuple / Active-Provider Mismatch):**
   - *Trace:* Suppose `PAGE` allocates $K_{\text{page}} = 2$ cache slots, and a leaf needs only $1$ older read (`act_0 = 1, act_1 = 0`). If slot $1$ gates its Merkle root equality as `act_1 * (walk_root_1 - pre_root) == 0` while leaving its `bus.rs` provider selector `q_prov = 1` and its bus columns `(chip_1, key_1, a_1, b_1, c_1)` unmultiplied by `act_1`, the malicious prover sets `act_1 = 0` and assigns `(chip_1, key_1, a_1, b_1, c_1) = (TAG_CELL, target_addr, forged_val, 0, 0)`. The Merkle gate evaluates `0 * (...) == 0` (satisfied), while `lookup_any` sees `(TAG_CELL, target_addr, forged_val, 0, 0)` as an active table entry, forging arbitrary reads of any address! Symmetrically, if any valid sort is assigned `chip_tag == 0` (`MUTANT = "tag_zero"`, `chipLeafCached.qnt:84,134`), every inactive padding row `(0, 0, 0, 0, 0)` on `bus.rs:51-60` forges `(key = 0, a = 0, b = 0, c = 0)`.
3. **Exploit A3 — `PAGE` / `MEM` Overlap Aliasing (`D2` Failure on Sparse Default Trees):**
   - *Trace:* `mem_root_pre` commits a sparse tree where every unallocated address $\ge \text{base}$ opens authentically to the zero record (`crates/mori-chip/src/m3.rs:73-75,208`). Suppose step $0$ appends `(TAG_CELL, base, 42, 0, 0)` into `MEM` (`cur_len` becomes `base + 1`). At step $1$, `CORE` reads `addr = base` (`base < cur_len` passes `D1`!). If `PAGE` does **not** enforce `addr < base` (`D2`, `quint-check.md:194-201`), the prover opens `addr = base` in `PAGE` against `mem_root_pre` — which authentically contains `0` at `base`! Now $\mathcal{T}_{\text{MEM}}$ has `(TAG_CELL, base, 42, 0, 0)` and $\mathcal{T}_{\text{PAGE}}$ has `(TAG_CELL, base, 0, 0, 0)`. Step $1$ matches the `PAGE` row and reads stale `0` instead of `42`, breaking write-once coherence.
4. **Exploit A4 — Cross-Sort Key Aliasing (`DATA`, `FIELDS`, `ENV`, `SLOTS`, `PROG`, `TY`):**
   - *Trace:* In the C6 physical state (`owner_runtime.rs:300-335`), address `0` exists in `img.data`, `img.data_fields`, `img.env`, `img.value_slots`, `prog.constants`, and `prog.expressions`. If two sorts share `chip_tag` on `bus.rs` without encoding a collision-free `sort_tag` into **both** the bus tuple and the Poseidon record preimage (`m3.rs:60-62`), opening `EnvCell(0)` into `PAGE` satisfies a `DataRow(0)` bus lookup, forging constructor tags and violating `SI-13`/`SI-14`.
5. **Exploit A5 — Duplicate `PAGE` Cache Keys with Unhashed Auxiliary Hints:**
   - *Trace:* Nothing stops a prover from placing the same `addr < base` into both `PAGE` slot $0$ and `PAGE` slot $1$ (avoiding an expensive sorting network over cache keys). If every bus column `(a, b, c)` is deterministically bound into `record_native` (`m3.rs:60-62`), Poseidon collision resistance forces both slots to carry identical tuples, so duplicate keys in a set-inclusion table are harmless. **However**, if a designer adds an unhashed "pre-unpacked hint" column to the `PAGE` bus tuple without a deterministic functional constraint from `(a, b, c)`, slot $0$ and slot $1$ can open the same `addr` with two different hint values, breaking functional uniqueness!

- **Soundness Theorem for Hardened `(a)`:** Let standard 1-phase Halo2 challenges $(\theta, \beta, \gamma) \in \mathbb{F}_r^3$ be squeezed after `advice_commitments` (`verifier_gadget.rs:314-329`). Enforce:
  1. `act_j * (1 - act_j) == 0` on every `PAGE` and `MEM` row;
  2. Every provider expression emitted to `bus.rs` is multiplied by `act_j` (mapping `act_j == 0` strictly to `(0,0,0,0,0)`), and every architectural sort tag satisfies `chip_tag >= 1` (`D8`);
  3. Every active `PAGE` slot checks `addr_j < base` via `RANGE` (`D2`) and verifies its bottom-up `WalkConfig` (`m3.rs:113-139`, including `ao == 0` at top level `TOP - 1` so `idx < 2^{TOP}`) against `mem_root_pre` (`TAG_DATA..TAG_SLOT`) or `prog_d` (`TAG_PROG..TAG_TY`);
  4. `MEM` row $k \in [0, C)$ has fixed offset `base + k`, `act_k == 1 <=> base + k < post_len`, and every `CORE` read at step $t$ enforces `addr < len_t` (`D1`);
  5. Every bus column of an active row is a deterministic function of the Poseidon-committed leaf record (including `sort_tag`).
  Then, conditioned on Poseidon collision resistance and Halo2 `lookup_any` soundness (error $\le \frac{(d_{\text{max}}+2) \cdot 2^k}{r_{\text{BLS}}} < 2^{-235}$ per lookup), $\mathcal{T}_{\text{PAGE}} \cap \mathcal{T}_{\text{MEM}} = \emptyset$ on keys (`addr < base` vs `addr >= base`), every `(chip != 0, key)` has **at most one** tuple in $\mathcal{T}$, and every step $t$ reads the exact logical write-once value written at some $t' < t$ (or initial `prog_d` state). $\square$

### Candidate `(b)`: Run-Wide Offline Memory Checking (LogUp / Grand-Product / Horner / EC Multiset Hash)

#### Q1(b) & Q2(b) Why Every Variant of `(b)` Either Collapses Soundness or Loses on Cost + `GP-4`

##### Variant `(b.1)`: Field-Scalar LogUp / Grand-Product / Horner with Challenges $(\gamma, \alpha)$ in Public Inputs
Because `VerifierGadget` asserts `cs.phases().count() == 1` (`verifier_gadget.rs:308-310`), a leaf cannot squeeze $(\gamma, \alpha)$ after committing its memory trace. Suppose a design passes $(\gamma, \alpha)$ in the leaf's public `instance` lanes (carried across `ivc.rs` and checked at `RunDecider`) and updates a running LogUp sum $S_{\text{post}} = S_{\text{pre}} + \sum_j \frac{m_j}{\alpha - E_\gamma(\text{op}_j)}$ where $E_\gamma(\text{sort}, \text{addr}, t, v) = \text{sort} + \gamma \cdot \text{addr} + \gamma^2 \cdot t + \gamma^3 \cdot v$.

- **Concrete Exploit B1 (O(1) Adaptive Rational Collision Forgery under Quantifier Inversion):**
  Even if $(\gamma, \alpha)$ were derived via hash from `(prog_d, input_d)` (so the prover cannot choose $(\gamma, \alpha)$ freely), **the prover knows $(\gamma, \alpha)$ BEFORE generating the leaf witnesses**! Quantifier order is inverted from $\forall \text{Trace}, \Pr_{\gamma,\alpha}[\text{collide}] \le \epsilon$ to $\forall (\gamma,\alpha), \exists \text{Trace}(\gamma,\alpha)$.
  - *Attack Construction (Write-Once LogUp with Advice Multiplicity $m_w$):* In write-once LogUp, each allocation of $x_i = (\text{sort}_i, \text{addr}_i, v_i)$ subtracts $\frac{m_{w,i}}{\alpha - E_\gamma(x_i)}$ (claiming $m_{w,i}$ reads will occur) and each read adds $\frac{1}{\alpha - E_\gamma(x_i)}$. Suppose the honest trace writes $x_0$ (`addr = 0, v = 0`) and the attacker wants to forge a read of $x^* = (\text{sort}_0, \text{addr} = 0, v^* = \text{1,000,000})$ (never written!). The forged read adds $\Delta = (\alpha - E_\gamma(x^*))^{-1} \in \mathbb{F}_r$. Because $(\gamma, \alpha)$ is already known when choosing the advice witness $m_{w,0} \in \mathbb{F}_r$ in the leaf that wrote $x_0$, the attacker sets:
    $$m_{w,0}^{\text{mal}} = m_{w,0}^{\text{honest}} + (\alpha - E_\gamma(x_0)) \cdot (\alpha - E_\gamma(x^*))^{-1} \pmod{r_{\text{BLS}}}$$
    Then $-\frac{m_{w,0}^{\text{mal}}}{\alpha - E_\gamma(x_0)} + \frac{1}{\alpha - E_\gamma(x^*)} = -\frac{m_{w,0}^{\text{honest}}}{\alpha - E_\gamma(x_0)}$ identically in $\mathbb{F}_r$! The global LogUp sum reaches **exact `0`** at `RunDecider` in $O(1)$ field operations!
  - *What if $m_{w,i}$ is range-checked to $u32$ (`[0, 2^{32})`), OR read-write timestamps (`+1` write, `-1` read, no free $m_w$) are used?* It STILL breaks!
    1. With $m_{w,i} \in [0, 2^{32})$: the attacker allocates $k = 10$ dummy scratch values $x_1, \dots, x_{10}$ (which valid Sherlock code or input structures can allocate) with known denominators $d_i = (\alpha - E_\gamma(x_i))^{-1} \in \mathbb{F}_r$, and uses standard LLL / lattice reduction (`255 / 10 < 26` bits per coefficient) to find small integers $m_{w,i} \in [0, 2^{28})$ satisfying $\sum_{i=1}^{10} m_{w,i} d_i \equiv \Delta \pmod{r_{\text{BLS}}}$ without ever reading $x_1, \dots, x_{10}$!
    2. ### Candidate `(e)`: Poseidon Hash Memoization (`AS_HASH` Bus & Inline `sherlock-value/1` `vd`)

#### Q1(e) & Q2(e) The Halo2 Worst-Case Sizing Law, Sponge Collisions, and Inline `vd`
1. **Why Intra-Leaf `AS_HASH` Memoization Saves `0` Worst-Case Leaf Rows (and Creates Two Exploits):**
   In a fixed-VK Halo2 circuit, `PoseidonCfg` row count is determined by the **worst-case** number of distinct permutations a valid `S = 16` leaf can require. Better yet, because `WB[4]` flushes strictly at logical allocation multiples `len % 4 == 0` regardless of where leaves close, **the physical carrier state `(regs, len, wb[0..3], mem_root)` at machine step $h$ is itself strictly invariant to leaf partitioning**! Both `outcome_d` (`SRC-023`) **and** internal `cur_d` become deterministic functions of `(prog, input, h)`, turning `SVM-011` refinement into a direct functional bisimulation without non-deterministic address-gap quotients.

### 3.2 Run-Length & Memory Ceiling (`D3` vs `GP-1` `< 2^64` & `sherlock-runlength-consensus-20261111`)
This design directly touches Questions `Q1`–`Q3` of the parallel study `research/sherlock-runlength-consensus-20261111/BRIEF.md:12-37`:
1. **Eliminating the Zero-Append Exhaustion / Partition-DoS Bug:** In `m3.rs:132,209`, `len_post = base + 8` burns 1 of the $2^{17}$ segments on **every** leaf even if `0` cells were allocated, capping any run at `< 131,072` leaves (`<= 2,097,152` steps at `S = 16`, or `131,071` steps if a prover slices at `steps = 1`). Under `(f)`, `did_flush == 0` leaves `mem_root` and `len` untouched: pure control/ALU runs execute up to the full `SRC-004` height counter `h < 2^64` (`crates/mori-recursion/src/ivc.rs:79,369-375`) with **zero** memory tree growth.
2. **Raising Per-Run Heap Capacity to $2^{32}$ Cells (`TOP = 30`) + Canonical Continuations:** Widening `TOP` to `30` gives $2^{32} = 4,294,967,296$ dense cells per run (`> 10,000` CPU-years of proving on current hardware `ESTIMATE`), removing `D3`'s `2^20`-cell ceiling in practice while keeping `GP-1` (`< 2^64` steps) intact. And where `sherlock-runlength-consensus-20261111` `Q3` considers chaining multi-run continuations via `GP-2`, `(f)`'s partition-independent `(regs, wb, mem_root)` provides a **canonical, partition-independent continuation snapshot digest** — whereas `D3`'s `mem_root` varies with leaf cuts!

### 3.3 `SI-12` to `SI-14` (`dissent.md` `D-1` and `mori-core` 1-Step `field_at`)
In `crates/mori-core/src/sherlock/helper_machine/shared/owner_runtime.rs:300-331`, `field_at(&RefC::Data(id), &i)` computes `pos = start + i` and indexes `self.img.data_fields[pos]` in **1 step**, and `SI-12` (`owner_runtime.rs:4698-4741`) asserts that constructor field slices partition `data_fields` contiguously (`start == field_cursor`, `field_start + src_cursor == active.data_fields` in `owner_runtime.rs:2990`).
- Under `D3` (`C = 8`), any constructor whose `BuildField` steps straddle a leaf boundary with unused `MEM` padding rows gets a gap inside `[start .. start + len)`, breaking `start + i` and `SI-12` (`openspec/changes/sherlock-vm-consensus-20261107/dissent.md:198-202`, `tasks.md:86`).
- Comparing the `D-1` alternatives under Red-Team scrutiny:
  - *Dense-ID-to-physical-address map:* Doubles memory lookups on every dereference and introduces an **aliasing attack surface** if two IDs map to one physical cell.
  - *Cons-linked slices `(TAG_SLICE, elem_ref, prev_link)` alone:* Turns random-access `field_at(r, i)` (used in structural equality `owner_runtime.rs:3902` and type validation `owner_runtime.rs:4139,4951`) from $O(1)$ into an $O(\text{arity})$ multi-step pointer chase, requiring new helper states in `mori-core`.
  - **How `(f)` (`WB[4]` Dense Allocation) Resolves `D-1` Cleanly:** Because `WB[4]` never inserts leaf-boundary padding gaps into `len`, **addresses are 100% dense across leaf boundaries**! `start + i` (`field_at`), `SI-12`, `SI-13` (`id < owner`, `owner_runtime.rs:4749`), and `SI-14` (`previous < i`, `owner_runtime.rs:4814`) hold **without multi-step pointer chasing and without an ID-translation table**! Inline child slots for arity $\le 2$ inside the 3-word `Data` cell can still be used as a pure optimization (`0` field-slice cells for `Cons`/pairs), while arity $> 2$ uses dense `start + i` in `O(1)`.

### 3.4 `GP-1` through `GP-4` (`general-purpose.md` & `architecture.md`)
None of `GP-1` to `GP-4` (`openspec/changes/sherlock-vm-consensus-20261107/general-purpose.md:11-55`) may be narrowed:
- **`GP-1` (Universal VM, one fixed VK set, every outcome `Halted`/`Fault`/`OutOfFuel`):** `(f)` keeps all program code/types behind `prog_d` (zero per-program fixed columns) and seals `Fault` and `OutOfFuel` in $O(1)$ without needing `(b)`'s $O(|M|)$ memory-teardown sweep.
- **`GP-2` (Cross-Run Composition) & `GP-4` (Arbitrary DAG / PCD, `SEG` vs `SET`):**
  In `research/sherlock-gp-architecture-20261110/architecture.md:92-120,355-365`, open linear run segments (`SEG`) close into sealed claim sets (`SET`), and `Join(SET_1, SET_2)` merges arbitrary DAG branches.
  - **Exploit G1 — Diamond Fan-Out Double-Counting & Cross-Run Splicing Against `(b)`:** Suppose sealed run $A$ feeds **both** run $B$ and run $C$, and run $D$ joins $B$ and $C$ (`A -> {B, C} -> D`, a diamond DAG explicitly protected by `GP-4`, `general-purpose.md:45`). If any deferred memory/lookup accumulator leaked from `SEG` into `SET`, `Join(SET_B, SET_C)` would **double-count $A$'s accumulator** (breaking honest diamond proofs or enabling cross-run read/write splicing where dangling writes in one run cancel forged reads in another). Under `(f)`, every lookup and memory obligation closes strictly inside each `Leaf` (`SEG`), so `SET` carries only pure, idempotent C6 claims.
- **`GP-3` (Foreign Proofs via Adapter `F`):** Foreign relations (`architecture.md:96,195-215`) verify arbitrary Midnight/Halo2 VKs (`vk_d`) that know nothing of Sherlock's internal memory bus. Local closure in `(f)` keeps `F` completely orthogonal.
- **Cross-Session Checkpoint/Resume:** Pausing a multi-hour run at leaf $k$ and resuming days later requires storing only `(regs, wb[0..3], M[0..len))` — zero Fiat-Shamir state or cross-leaf multiplicities.

### 4.2 Real-World Disclosed Lookup, Memory, and Recursion Vulnerabilities (Mapped to Sherlock)
1. **StarkWare `stwo-cairo` Unabsorbed LogUp `claimed_sum` Forgery (June 2026 regression in commit `819c080f`, patched June 2026):**

   - *Sherlock Lesson:* Any cross-component or cross-leaf sum/challenge (`Q1b`) where boundary claims or challenges are unpinned or inverted in Fiat-Shamir order allows trivial algebraic cancellation (Exploit B1).
2. **OpenVM `GHSA-fh29-29h9-qm9h` — Non-Boolean LogUp Multiplicity Time-Rewind & Unanchored Merkle Root Labels (Critical, May 15, 2026):**
   - *Source:* `https://github.com/openvm-org/openvm/security/advisories/GHSA-fh29-29h9-qm9h` and `https://zksecurity.io/research/2026-10-14-zkvm-security-2026-audits-bug-classes-disclosures/`.

   - *Sherlock Lesson:* Directly motivates Exploit A2 (`act_j` boolean check + zero-tuple gating), Exploit C1 (boolean gates on every unpacked bit), and `WalkConfig` top-level `ao == 0` enforcement (`m3.rs:135-139`).
3. **OpenVM `CVE-2026-62333` / `GHSA-396x-v8w4-9x82` — Below-Leaf Merkle Subtree Fabrication (Critical, June 26, 2026):**
   - *Source:* `https://github.com/openvm-org/openvm/security/advisories/GHSA-396x-v8w4-9x82`.
   - *Root Cause:* `MemoryMerkleAir` allowed active Merkle expansion rows at `parent_height == 0` with `expand_direction != 0`, enabling a prover to attach a fabricated hidden subtree *below* a memory leaf and mutate the committed memory root across segments with zero memory-bus operations!

4. **SP1 Fiat-Shamir, Recursion, Range-Check, and Lean-FV Precondition Bugs (`2024–2026`):**

5. **RISC Zero `CVE-2025-52484` (`GHSA-g3qg-6746-3mg9`), Nexus Store-Limb Bug, and Jolt `lui` Bug (Arguzz Fault-Injection Fuzzing, USENIX Security '26):**
   - *Sources:* `https://zksecurity.io/research/2026-10-14-arguzz-fuzzing-zkvms-soundness-completeness-bugs`, `https://arxiv.org/abs/2509.10819`, `https://github.com/risc0/risc0/security/advisories/GHSA-g3qg-6746-3mg9`.

Arguzz also caught unconstrained low store bits in Nexus (`sw`/`sh`/`sb`) and an unconstrained `lui` immediate in Jolt `v0.1.0`.
