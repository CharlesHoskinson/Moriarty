# astra-1 vote on DRAFT v1

**OBJECT**, pending the six corrections below. The objection concerns the specification's soundness claims, evidence boundaries and runnable acceptance gates, not a demonstrated exploit. I accept the overall architecture and the issue resolutions. I reviewed the 13-file bundle copied to `astra-1/review-v1/`; `review-v1.sha256` identifies that snapshot.

1. **State proof obligations and finite release gates consistently.** In `assurance.md` §1 the O2/O3 paragraph correctly keeps universal claims open, but the table still says hostile tests can close universal soundness and P1-P3 can close completeness. O1/O4 have the same problem. Rename that column to finite release evidence; state `StepInv(pre)` and valid image/configuration premises in the obligation itself. A theorem, or a genuinely exhaustive checked argument over the stated domain, is required to discharge the universal claim. In `design.md` §2.2, replace “composition is now inside one key, so ... discharged” with a required initialization, preservation and shared-carrier check. One key does not manufacture a missing constraint. Add initialization/composition evidence explicitly to task 4.6 and its traceability entry (SAS-010). This does **not** require a new universal theorem before the finite Preview release.

2. **Remove the unsupported genesis security inference and align its tests.** `design.md` §3.2(2) concludes that hashing accumulator encodings makes chosen-carry cancellation impossible. The source observation alone proves no such statement. Adopt astra-2's `accumulator-qualification.md` and `DRAFT astra-2 avoid overclaiming accumulation hash and composition`: require either constrained neutral carry, or constrained zero/ignore semantics with a recorded justification that ignored carry cannot authorize an invalid leaf/predecessor. Keeping an unscaled carry requires its own security argument. Tests must match the chosen realization, include valid baselines, and reject an invalid leaf through final pairing. Point-decoder refusal is only decoder evidence. Update SRC-005, its scenarios, task 2.3 and the assurance text together. No practical attack was established.

3. **Keep preprocessing separate from constraint rejection.** `assurance.md` §4 calls the M3 dispatch/fragment receipts “constraint check,” while §5 and SVM-006 correctly deny that credit to `ProofPreimage::check`. Add an explicit `IR preprocessing / witness execution` evidence class and use it for the current M3 receipt and matching traceability rows; actual constraint checks and native proofs remain M4/M5 obligations. Source: `crates/mori-backend/src/sherlock_machine/c6_dispatch_consumer.rs:244-285`; the inspected upstream `repos/midnightntwrk/midnight-ledger/zkir/src/ir.rs:111-116` implements `check` by `preprocess`. Also fix the SAS-013 scenario: a partition known to omit `equal_differ` value reads **fails** receipt acceptance; merely calling it heuristic is insufficient. Fix SRC-004's “synthesis or verification fails” scenario: only refusal at the claimed constraint/verifier boundary earns that credit, per SAS-003. These are assurance-gate defects.

4. **Make task order implement the agreed scope.** Task 4.4 still keys “P1-P3 rule set,” task 4.7 and M3's gate require P3 before task 6.4 authors it, and task 4.8 experiments with S=8 before the C0 profile in 5.3. Use the frozen admitted inventory R for M3/M4; run P1/P2 parity there, then P3 parity and local proof/verification after its post-freeze authorship and before its network call. Put any S>1 experiment after the S=1 complete-path profile and make it conditional. SRC-014 is satisfied at baseline S=1; the slot-3-of-8 scenario applies only when S>1 is adopted. Reconcile M2/M4 naming in SRC-013 and the decision task. These changes preserve fresh-program evidence and avoid turning an optional optimization into an exit prerequisite.

5. **Make evidence recording and deployment gates runnable.** Support astra-3's `workflow-draft-corrections.md` and fable-3's `draft-review-1.txt`: a receipt commit followed by `state-commit` must be eligible; freshness must use the declared dependency closure so evidence-only commits do not invalidate unchanged results. Add the exact evaluator-owned Preview holdout and SDK command extensions (E12/E13), and retire or replace the old B5/B9 dependency closure. Update requirements, scenarios, tasks and E7/E10 together. `evalloop.py:39-46` commits only state files, so v1's same-commit receipt condition cannot be satisfied by that command.

6. **Synchronize the remaining safety scenarios.** SAS-011 must reject a tag/schema/key mismatch with the pinned candidate and verifier, not all `ProofVersioned::V2` on ledger 9; retained-version compatibility remains possible. Merge the duplicate SWF-010 headings and make its unsafe-key scenario test the selected recovery mode and observed on-chain revocation/exposure, rather than automatic insertion plus a local retired label. SMN-007 must allow explicitly immutable contracts subject to the active-state recovery rule, rather than calling all of them disposable. These align the scenarios with the already accepted requirements and `design.md` §5.2.

The key gains are already present: complete guard dependencies and directed rule coverage; independent trace oracles and raw witness entry points; exact candidate and chain identity; preserved historical evidence; bounded integer height; whole-u128 result readback; and explicit public source/runtime provenance limits. I expect to accept once the six corrections are reflected consistently in the bundle. No implementation or proof execution is claimed by this vote.
