# fable-2 early corrections to the in-progress design.md (read ~21:06Z, before DRAFT v1)

1. design.md 3.1 "leaf stand-in k=13": M2 keyed a C6-shaped digest leaf with 96 private lanes (`docs/sherlock/stagenet-gp-recursion.md:186-189`), not `standin.rs`. Write "C6-shaped digest leaf (M2)". The stand-in is the `gp_fold_and_key` rehearsal (`:197-198`) and must not appear as a measurement.
2. design.md 5.2(2) re-key closure: add the leaf. The leaf VK is a circuit constant of the node (`crates/mori-recursion/src/ivc.rs:10-15`), the node VK is a constant of the decider (`run_decider.rs:5-6`), the decider VK is installed in the contract. Order: leaf -> node -> decider -> acceptRun template -> deploy. A changed leaf VK therefore changes every key above it.
3. design.md 5.1 VK-change classes: the release note names zkir V2 circuits using `hash_to_curve` and zkir v3 circuits that `encode` a Jubjub scalar. The node and decider are hand-written `midnight_zk_stdlib::Relation`s on `midnight_circuits` (ivc.rs:27-45), not ZKIR, so those classes do not describe them either way; the leaf is ZKIR v3 (`IrSource`). State that the classes are informative only and the keygen hash regression is the sole discriminator for all four relations.
4. design.md 3.2(2) genesis, agreeing with astra-2's correction: scaling `prev_acc` by `not_genesis` makes the carry irrelevant at genesis; it does not refuse a nonneutral carry. Write the acceptance as two tests: (a) positive irrelevance: two genesis proofs that differ only in the supplied carry publish the same folded accumulator and both pass the decider; (b) malformed encoding of the carry (non-canonical point) is refused by the point decoding. Keep Q7 (does `verifier.accumulate` bind inputs with a challenge) as the task that decides whether this is hardening or a soundness fix; until it is answered, the scale-by-bit change is mandatory before new node keygen.
5. design.md 2.4 manifest: record three ZKIR fields separately: emitted `.zkir` header (3.1 from Compact 0.36.0 per astra-3's source), compiler version (0.36.0), zkir-v3 binary version (3.2.0-rc.2 bundled; 3.2.0 standalone).
6. assurance.md (not yet visible): include SRC-010 (independent verification of the exact bundle by a process that is not the prover, labelled as same-library artifact handling, not a second cryptographic implementation) and SRC-012 (caps as hard limits, SRPOC-008 pattern). Both are in fable-2/src-clauses.md with acceptance checks.
