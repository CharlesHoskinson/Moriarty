# Workflow critique notes

These notes respond to `fable-3/position.md` and the Midnight refresh. Full cross-critique follows after all positions exist.

1. **Keep production qualification on Preview, but retain stagenet as a diagnostic target.** The independently observed stagenet runtime differs from Mainnet. Thus stagenet cannot close production compatibility. An existing working target can still isolate a regression from a platform migration. Make its use optional and scoped. Sources: [observations](observations.md), `fable-3/position.md`, `wiki/midnight-ledger-9-hardfork.md:60-76`.

2. **Do not assume every current key is invalid.** The ledger 9.1.0.0 release preserves older proof/key verification and names particular circuit operations whose regenerated keys change. Sherlock already uses ledger-v9 and handwritten relations. Qualify the exact old candidate against the selected verifier. Regenerate the affected dependency closure when required, then compare its new identities. There is no evidence here that every key in the current fixture is invalid. Sources: `Cargo.toml:27-42`, [ledger release](https://github.com/midnightntwrk/midnight-ledger/releases/tag/ledger-9.1.0.0), `fable-3/position.md` §6.

3. **Keep live network checks out of T0.** Validate the static target manifest and dependency identities in T0. Perform RPC/indexer freshness checks in target preflight and promotion. A remote endpoint outage must not block an unrelated local commit. This is a proposed placement change to I8. Existing T0 is local validation, while T3 owns target promotion. Sources: `qa/tiers/t0.sh`, `qa/tiers/t3.sh`.

4. **Treat the missing deployed-source lineage as an explicit assurance limit.** The scout reports a mismatch between the public node release branch and the deployed runtime, with the exact deployed ledger revision unavailable publicly. An available local container must not be described as an exact production replica merely because its release name resembles the target. Pin actual binary/source identities when available. Until then, distinguish local release tests, direct Preview observations and the unclosed reproduction claim. Source: `wiki/midnight-ledger-9-hardfork.md:166`, its linked source/RPC artifacts. This gap is reported by the scout, not independently reproduced by this lane.

5. **Keep a Mainnet implementation path in this change's workflow.** The brief asks for Mainnet deployment and rollback in the proposed workflow. It does not authorize a transaction during the council. Name the missing adapter, predicate, authorization and recovery tasks explicitly. An additional tier is one implementation choice, not a prerequisite imposed by Midnight. Existing tier validation is fixed to T0–T3 at `models/doctorwatson/factory/predicates.py:12`. The workflow must state its chosen extension rather than depend on an absent command.

6. **Do not let a stop-rule reset become a success target.** Re-earning F4/F11 may legitimately create a fresh predicate transition. It does not itself close the original A8/U023 failure. Keep the STOP trace, owner disposition and next discriminating hypothesis. Never reset clocks or select unrelated work solely to make `stop-rule` return zero. Source: `AGENTS.md:13-25`, `models/doctorwatson/factory/CONTRACT.md`, `fable-3/position.md` M0.

7. **Rollback must address accepted liabilities and vulnerable keys.** Reverting a fixture commit does not reverse chain state. Inserting a new key does not revoke an old accepted key. For affected cross-contract callers, Compact 0.36 requires removal of the old key or a replacement deployment. Keep the exact maintenance operation and fee compatibility in the recovery test. Sources: `docs/MORIARTY-PRODUCT-CONTRACT.md:41-47`, [Compact release](https://docs.midnight.network/relnotes/compact/toolchain-0.36.0).

Concessions: the named operation/precondition/postcondition format is clearer than my original milestone prose. The workflow should use it for deployment and calls. Preview should be the first production-compatible public qualification target. A mandatory additional stagenet submission would add cost without establishing production acceptance.
