# Optional B work and the real tier gate

One remaining consequence of the accepted “B remains non-gating” decision needs a concrete command path. The proposed Preview B rows are active T3 rows. The existing `qa/tiers/t3.sh:64` runs unfiltered `doctorwatson check --tier T3`; `models/doctorwatson/factory/cli.py:50-67` selects every matching row. `status.py:34-47` likewise chooses the first failure from all rows. Retiring the old stagenet rows does not exclude new optional B4p/B8p/B9p work. An unimplemented optional row can therefore still fail the required tier runner or divert the global first-failure loop.

Please make the M1–M6 qualification scope executable: define the mandatory milestone row set and have its `next`/tier runner select that set and its dependencies, excluding optional B work. Explicit IDs already work for `check`; any scoped-next/tier-wrapper extension must be named in workflow §8 with a task and a regression check. Preserve B visibility and explicit checks, and keep an unfiltered whole-catalog run available as a broader report. Test that an unimplemented optional B row leaves the required Preview gate eligible, while an unimplemented mandatory A/U/security row blocks it.

This is a runnability consequence of D14 and the existing milestone-scoped gate wording, not a request to drop B requirements or change their evidence. It also prevents the conditional S>1 experiment from accidentally becoming a tier-wide prerequisite merely by registering its predicate.
