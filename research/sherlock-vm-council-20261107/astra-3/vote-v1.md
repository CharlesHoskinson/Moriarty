# VOTE astra-3 OBJECT — DRAFT v1

I support the selected architecture and scope: native recursion, the seven-lane leaf contract, a qualified S=1 baseline, a measured U/F choice, independent oracles, Preview qualification, and an explicitly authorized Mainnet path. The draft resolves my initial scope objections. I object to the following remaining text because it can admit false evidence or leave the implementation workflow unable to reach its stated exit. These are fixes to this design, not a request for a different architecture.

Reviewed draft: the chair's `DRAFT v1` announcement `01M6VXVKR1V7P7Z5AWVWNXT9CQ`, with a local copy in `draft-v1/` and file hashes in `draft-v1.sha256`. Repository base: `8fd34ed794eda7186c32495f715609ec54a9a297`.

1. **Soundness: replace two asserted conclusions with obligations.** `design.md` §3.2(2) infers that a chosen carry cannot cancel an invalid leaf merely because accumulator encodings are hashed before folding powers. The inspected code establishes the transcript construction, not that security result; astra-2 explicitly withdrew that inference in message `01M6VXRB131CZ31ATFPXW259HN`. The same section mixes scaled-ignore, retained-fold and neutral-input tests. Also §2.2 concludes that placing fragments inside one key discharges all canonicality premises. It does not establish missing initialization or preservation constraints. Fix: use astra-2's stated genesis alternatives: designated neutral encoding, justified zero/ignore semantics, or a separately supported retained-fold security argument. Match acceptance checks to the selected alternative, including invalid-leaf refusal at final pairing. For composition, require initialization and preservation of `StepInv(pre)` and checked shared-carrier premises; do not assert they already hold. Synchronize SRC-005, SVM-002, assurance O1–O4 and task 4.6. The source references are `circuits/src/verifier/accumulator.rs:177-192,315-343` at `24a1eb5a` and `c6_dispatch_step.rs:34-38`; no practical genesis exploit has been established.

2. **Assurance: correct acceptance scenarios that contradict their requirements.** In `specs/sherlock-recursion/spec.md`, SRC-004 allows a synthesis error to pass the field-wrap check, contrary to SAS-003. Require a valid baseline and refusal at the claimed constraint/verifier boundary; synthesis/decoder/panic results remain untested for that boundary. In `specs/sherlock-assurance/spec.md`, SAS-013 labels a known `equal_differ` dependency omission heuristic without explicitly refusing the acceptance receipt. Require refusal of that incomplete receipt; a complete-dependency partition can remain a heuristic without a congruence proof. The demonstrated dependency is `c6_dispatch_step.rs:750-806,1189-1200`. In SAS-011, replace blanket refusal of `ProofVersioned::V2` on ledger 9 with refusal of a tag/schema/key mismatch against the candidate manifest. Older proof verification remains supported by the [ledger 9.1.0.0 release](https://github.com/midnightntwrk/midnight-ledger/releases/tag/ledger-9.1.0.0); the release does not justify a universal V2 ban. Proposed wording is in `scenario-draft-corrections.md`.

3. **Workflow: make committed evidence retain eligibility.** SWF-005 and workflow §3 require a receipt in the same `state-commit` commit. The command commits only `status.json` and `runs.jsonl` (`models/doctorwatson/factory/evalloop.py:14,39-46`). E7 and the current-head exit rule then stale every run when that commit advances HEAD. Fix: commit and hash-bind receipts/artifacts through the normal commit path, check their postconditions, then record factory state with `state-commit`. Base eligibility on the declared source/configuration/key/target dependency closure; preserve the run HEAD as provenance. An evidence/state-only commit must not invalidate unchanged dependencies. Add positive tests for that path and negative tests for changed source, key, pins and chain instance. Align SAS-002, SWF-005, E7, task 1.6 and the gate rule. Details: `workflow-draft-corrections.md`.

4. **Workflow: enumerate the missing Preview and retirement work.** I independently verified fable-3's W1–W3 against `qa/holdout/run.sh:40-41`, `qa/holdout/lib/stagenet_check.py:19`, `qa/holdout/contracts/U023.json:19-22`, `tools/sherlock-sdk/deploy-run.mjs:30-42`, `call-run.mjs:24,44,65`, `readback-run.mjs:30`, and `qa/sherlock/predicates.yaml:141,177`. The Preview rejection suite, network-aware SDK operations and U023 network contract are not supplied by the existing commands. Add exact implementation tasks and additions for these interfaces; the holdout change must be evaluator-owned and resealed. Name all required command arguments or explicit wrapper additions rather than implying that the abbreviated examples run today. Task 1.1 must retire or rewire the B5/B9 dependency closure as well as A8/A9/A10/B4/B8; otherwise the new active-to-retired dependency validation fails. The text of SWF-011 now covers sweeps correctly; retain it.

5. **Security: conditional assurance requirements must apply when triggered.** The proposal's exit paragraph lists SAS-008 and SAS-009 among work that may remain open. Those clauses require checks when an optimization is enabled or a formal property is claimed; they are not permission to omit those checks in such a release. Fix: require all applicable clauses for the claimed profile and target. SAS-008 may be recorded not applicable only when no covered optimization is enabled; SAS-009 may be not applicable only when no formal claim is made. Likewise SRC-014 is conditional on the chosen S and must not force the optional S=8 experiment into the S=1 exit. An unexecuted applicable security gate remains blocking.

6. **Sequencing: synchronize tasks with the accepted baseline design.** Task 4.8 runs the S=8 experiment before task 5.3 obtains the complete S=1 chain's C0 profile, contrary to SRC-011 and design §3.5. Move it after that profile. Task 4.4 still keys the “P1-P3 rule set,” while P3 is authored after key freeze; key the frozen admitted inventory R instead, with all its receipts before keygen. Name the U/F measurement as M4 consistently (SRC-013 and design §3.4 currently call it M2). Land E10 semantics before introducing inert `retired:` fields, as fable-3 requested. These changes preserve the intended order without expanding scope.

Objections 1, 2 and 5 concern soundness or security evidence. They must be resolved before this vote can become ACCEPT. I will review the revised text, including its scenarios and task links. The deployed-source reproduction gap and unmeasured final resource cost may remain explicit limitations; they are not objections to the design when labelled accurately (SMN-004, SRC-011).
