# Bounded classifier review

Scope: README classification guidance and CATEGORIES.md only. No case benchmark, expected-label file, implementation or source audit was inspected. The README includes illustrative cases closely resembling several prompts; this is an independent application and clarity review, **not a blinded classifier experiment**. No agreement statistic is claimed.

| Case | Object and labels | Reason and uncertainty |
|---|---|---|
| 1. Collateral-funded monetary mint | Issuance/debt module: **FIN-MON.1 + FIN-CRE.2**. Separate borrower position from money-like token. | New monetary units arise alongside principal/fee debt. Collateral and liquidation are mechanism facets. Do not add CRE.1 unless an independently scoped existing-inventory loan also exists. |
| 2. ERC-4626 lending allocator | Allocation component: **FIN-MGT.1**. Underlying isolated market components: **FIN-CRE.1**. | Allocation across markets supplies management; share interface is accounting/representation. CAP.1 is ambiguous under its current broad inclusion test if the share-minting subscription component is separately classified. |
| 3. Fixed-maturity collateralized inventory loan | Bilateral loan instance: **FIN-CRE.1**. | Funding is existing inventory. Fixed maturity, collateralization and no early liquidation are facets. Neither an option nor a derivative is established merely by those terms. Maturity default/seizure/extension terms remain unknown. |
| 4. Async two-asset external fund | Fund management component: **FIN-MGT.2 conditional on a portfolio mandate**; subscription/issuance component: **FIN-CAP.1 conditional on newly issued fund rights**. | A subscription gateway alone does not prove management authority or primary fund issuance. If “manager” controls holdings and subscriptions issue new rights, the composite receives both labels. Async entry, multiple assets, external assets and external share-token address are facets. They do not establish ERC-7540 or ERC-7575 implementation. |
| 5. Solver advances destination asset | Trade-fulfillment component: **FIN-EXC.2**; origin escrow component: **FIN-MON.3**. | Solver's reimbursement receivable introduces capital-at-risk and settlement-credit exposure. It does not alone establish a separate CRE.1 lending service. Current CRE.1 wording is broad enough that a second classifier could reasonably add CRE.1; state the settlement-versus-loan tie-break explicitly. |
| 6. Inflationary reward locking | Governance/reward-lock component: **no financial-function label established**; supporting incentive/authorization capability. | No security duty means no FIN-SEC category. No portfolio mandate, loan or capital raise is stated. Inflationary reward is a subsidy, not operating yield. A separately scoped payment-distribution service could use FIN-MON.2, but every token balance update should not automatically acquire that label. |

## Clarity defects and minimal fixes

1. **Capital formation overlaps every share subscription.** CAP.1 includes any issuer receiving funding for new rights, while the README labels an allocator MGT.1 and an external fund subscription MGT.2 + CAP.1. This is not resolved by the financial-function definitions alone. Recommended explicit convention: classify issuance/subscription components CAP.1 when a funding action creates a new investor claim; classify ongoing allocation MGT.1/MGT.2. Composite records may carry both, including ordinary vaults; the primary function remains mandate-dependent. If this is too broad, define a narrower capital-raising criterion and use it consistently rather than treating external assets as the deciding factor.
2. **Trade pre-funding versus lending lacks a tie-break.** CRE.1's “supplier funds a receivable denominated in an existing asset” also describes a solver's reimbursement claim. Add: an advance inseparable from fulfilling and settling an exchange is EXC.2 with funding/credit-risk facets; add CRE.1 only for a separately agreed financing obligation or lending component. The same rule should cover merchant settlement advances and trade-finance arrangements without guessing from the word “receivable.”
3. **CRE.1's redirect says a minting CDP “also uses CRE.2.”** That can imply both lending labels for pure debt issuance. Replace with: “A CDP funding the advance by creating debt units uses CRE.2; add CRE.1 only for a separately identifiable inventory-funded advance.”
4. **The no-label outcome and incidental payments need explicit handling.** The roots classify financial services, not every contract operation. Add a supported outcome such as `supporting_capability` or `insufficient_financial_obligation_evidence`, and say that incidental reward transfers do not automatically classify an entire governance/incentive module MON.2.
5. **Gateways do not prove mandates.** The existing MGT root correctly excludes a bare container/ABI, but case 4 shows the practical need for a short rule: an entry gateway accepting subscriptions is not enough evidence for portfolio-management authority; record the fund/manager mandate separately and label conditionally until established.

Cases 1 and 3 classify cleanly once component scope is explicit. Cases 2, 4 and 5 expose useful tie-break rules; case 6 confirms the security-duty exclusion while exposing the need for an explicit supporting-capability result. These are findings about classification clarity, not a full dossier acceptance or standards-conformance judgment.
