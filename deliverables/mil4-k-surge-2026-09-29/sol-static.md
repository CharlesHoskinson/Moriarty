# MIL/4 static K slice

**Status:** specified-only proposal, 2026-09-29. The companion [`sol-static.k`](sol-static.k) defines importable `M4S-SYNTAX` and `M4S-STATIC` modules. It has no configuration or execution cell. No parser, K execution, TypeScript comparison, circuit, or ledger result is claimed here. This slice must be reviewed with the complete MIL/4 candidate before it can become a language profile.

## Contract represented

`m4sStatic(env, formula, phase, fuel)` returns `m4sTyped(m4sProp())` only when the asset and binding tables are valid and each formula node has a known type. Failure returns `m4sRejected(code)`. The finite grammar has comparison atoms, atomic negation, conjunction, disjunction and bounded `k_of_n`. It has no quantifier, recursive user function, route term or general nonlinear expression. A caller must choose a positive fuel at most 256; threshold lists have at most 128 entries. Every recursive descent decreases fuel.

The environment contains nominal asset IDs with checked domain and decimal metadata, a cell table and a hole table. Duplicate IDs and duplicate names within each table reject. A quantity carries an asset ID and is a `u128` count of that asset's smallest unit. `Price<base,quote,scale>` uses U0's **base per quote** orientation and accepts scale 0–18. The base and quote IDs must differ. Equal metadata does not equate IDs. Comparisons require identical constructed types, so cross-asset quantities, inverted prices, distinct price scales and distinct clocks reject as `TYPE_MISMATCH`. `pre` reads a declared cell in either phase; `post` rejects in a guard with `TYPE_POST_GUARD`; an outcome may read a declared post cell. A hole must have a declared type.

The type rules cover literal quantities and prices, checked unsigned literals, add/subtract/min/max, literal multiplication, and matching-type comparisons. `Qty<a> ± Qty<a>` remains a checked unsigned `Qty<a>` expression; a negative result rejects during concrete evaluation. `Qty<a> ± Delta<a>` and `Delta<a> + Qty<a>` produce `Qty<a>` with the same range check. Same-clock instant and duration arithmetic has explicit result types. Literal multiplication applies to `Qty`, `Delta` and `UInt`; min/max also permit matching price and time types. A `Share<p,c>` constructor is named but refuses formation or comparison until a nominal share-asset registry and issue authority are specified. Formula variables resolve only through finite cell and hole bindings. An unresolved name rejects; it is never treated as an unconstrained symbol.

`m4sOracle`, `m4sOmega`, `m4sVariableProduct` and `m4sUnsupportedFormula` are explicit syntax for open MIL/4 choices. Their formation results are, respectively, `OPEN_ORACLE_PREMISE`, `OPEN_OMEGA_CERTIFICATION`, `UNSUPPORTED_PHI1` and `OPEN_FORMULA_PREMISE`. No successful rule uses an oracle assertion. In particular, certified Ω placement, source-set evidence effects, branch-independent observation admission, canonical bytes and a qualified foreign verifier remain outside this static module.

## Exact numeric relations

All arithmetic rules use mathematical `Int` with explicit finite-width guards; they do not use modular field arithmetic. `m4sCheckedAdd` and `m4sCheckedSub` accept `u128` inputs and return a `u128` value or a named overflow/underflow rejection. `m4sCheckedMul` checks two `u128` operands against an explicitly selected 128- or 256-bit product width. This is an abstract relation, not a claim that the pinned proof target supports that width.

`m4sCheckedDivMod(n,d,q,r,w,mode)` first rejects zero divisor and out-of-range witnesses. It then requires `n = q*d + r`, `0 ≤ r < d`, a `u128` quotient and a declared 128- or 256-bit bound for `n` and `d`. A forged quotient rejects with `NUMERIC_FORGED_QUOTIENT`. Floor yields `q`; ceil yields `q+1` if `r>0`, subject to `u128` range; exact mode rejects any nonzero remainder. The function is for a chosen primitive *after* that primitive fixes its rounding role. The constructor does not let a signed intent select a role.

`r` is a numerator remainder in the division equation. It is **not** an atomic asset quantity and produces no reserve transfer. `m4sReserveUnit(m4sProductRemainder(r),...)` rejects. The separate `m4sWholeUnit(asset,"protocol-reserve",units)` constructor requires a nonempty nominal asset, `u128` values and `total = allocated + units`; `m4sReserveUnit` then returns the checked integer count, not a ledger effect. The stage must prove that this tag came from a whole-unit allocation and include every reserve and counterparty line. It does not settle the open MIL/4 question of which primitive creates such a unit. Fractional value retained in pool/vault custody requires a separate versioned accounting rule.

## Boundary and intended import

The main K definition may import `M4S-STATIC` and call `m4sStatic` before evaluating a signed guard or outcome. A successful formation result is not evidence that the formula evaluates true; evaluation and authenticated reads are separate obligations. The main acceptance relation must reject every `m4sRejected` and `m4sNumericReject` result without accepted writes. It must bind the selected program, canonical signed bytes, concrete filling, current heads, complete effects, authority, history and failure duties through the six MIL/4 judgments. The static module supplies none of those judgments by itself.

Open decisions remain explicit: MIL/4 wire version and unknown tags (M4-C1), per-primitive rounding and reserve lines (M4-C2), Ω width and target cost (M4-C3), cell registry and footprints (M4-C4), and signature/evidence verification (M4-C5). Neither a working design nor these K equations admit a DeFi profile or close U0. The file was authored without running tests or K parsing, as requested for this scoped draft.

## Grok 4.7 audit disposition

The audit file `grok47-static.md` labels C1 and C2 as compile defects based on equation shape. The integration `kompile` completed before this repair, so that compile claim is a false positive; the reviewer explicitly had not run it. C2 also identified a **real semantic bypass**: direct `m4sRounded` calls could return negative or out-of-range numbers. Every successful rounding rule now checks a `u128` quotient and a nonnegative remainder. Direct bad inputs reject. The divmod caller still enforces `0 ≤ r < d` and the quotient equation. Integration must recompile these changed bytes.

S3's operator/type mismatch was real for mixed quantity/delta and same-clock instant/duration expressions. Static formation and concrete evaluation now agree on those combinations; operator names are restricted to the implemented set. Shares no longer compare through the helper. S11's empty-list fuel bypass was also real and is closed in both static formation and concrete evaluation.

S5 confuses type formation with concrete evaluation: a well-typed addition can overflow at runtime, where `m4fEvaluate` rejects it. S1 concerns direct calls to internal inference helpers; `m4sStatic` and `m4fEvaluate` are the checked entry judgments. The other audit examples mostly require profile rules outside this slice: selected observations, bound prices, exact AMM/vault/option operations, complete effects, distinct governance approvals, foreign nonreceipt and authenticated history. Bare `UInt` remains valid for dimensionless counters but does not confer financial authority. A typed literal price is a constant, not a selected oracle observation. Asset ID determines registered domain/decimals; the compatibility of a particular price scale is a profile decision, not an equation `scale = quote decimals`. Cell and hole names are separate syntactic namespaces; canonical encoding must bind their tables. Generic `k_of_n` counts formula entries; distinct signers require a governance rule. These boundaries remain open and cannot be inferred from `m4sTyped(m4sProp())`.
