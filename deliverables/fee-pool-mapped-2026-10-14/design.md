## Normative source facts

Pinned reference commit `ec8da3be532f29e5e92ff7b1804b7dff0bc89b15` contains `research/fenrir-v2/fenrir-contracts/src/fee_pool.rs` and `research/fenrir-v2/quint-spec/fee_pool.qnt`. The originally supplied bare `quint-spec/fee_pool.qnt` path does not exist at that commit; the actual tracked path is recorded above. Rust monetary amounts, counters, epoch times, aggregate weights, and balance cells are U64. Products of two U64 factors use U128. The Quint model conservatively uses 2^63-1 because its evaluator is i64; that is a model limitation, not the monetary implementation's accepted boundary.

`submit_meter` requires initialized authenticated importer, an existing unsettled epoch, kind 0..6, positive amount, globally fresh receipt, checked U64 metered sum <= gross, and a fresh immutable cost entitlement. Watcher stipend kind3 additionally binds a registered positive-weight watcher recipient, stipend limit, and once-per-(epoch, recipient), not once-per-seat. Audit5/insurance6 bind L2 treasury recipient. Cost entitlements unlock at epoch close and can only be claimed after settlement. They are reserved before the surplus split, not paid as a second service-fee charge.

`settle_epoch` requires authenticated importer and existing unsettled epoch. Let s=gross-metered. Operator=floor(55*s/100), DA=floor(10*s/100), watcher=floor(5*s/100), and L2pre=floor(15*s/100), each independently against the original s. Midnight=s-operator-DA-watcher-L2pre; it receives all percentage rounding residual (floor15% through floor15%+4). This is not cumulative-share rounding. Watcher share increases a held reserve, with checked U64 overflow rejection; it never becomes watcher seat reward. L2pre first fills backstop up to current target; remaining amount becomes immutable L2 entitlement. Midnight becomes its own entitlement. Settled membership is immutable.

`allocate_reward` is permissionless, accepts only operator0/DA1, requires settled and unfinished epoch, existing seat and fresh allocation/payout key, computes floor(categoryOriginalTotal*seatEffectiveWeight/originalAggregateWeight). Empty aggregate denominator is replaced by1; registration invariants imply all effective weights are0, hence payouts0. Allocation order cannot affect amounts. Category remaining debits by its amount and allocated counter increments, including zero payouts. Operator input uptime <=86400; attestation false gives effective weight0. Operator/DA payouts unlock epoch close+30*86400, with checked U64 timestamp arithmetic.

`finish_distribution` is permissionless and requires settled, unfinished, allocated==registered reward-seat count. Remaining operator+DA dust (watcher remaining always0) first fills backstop at its current target; remainder becomes L2 entitlement. Clears category remainders and marks finished. An empty roster can finish immediately; a roster of zero-weight seats still requires allocating each zero payout. Finishing must not remove prior unclaimed cost, treasury, or reward entitlements.

`claim` reads immutable payout and immutable settled membership, requires recipient secret hash match, positive amount, block_time>=unlock, and fresh claim key. It marks consumed and returns fixed recipient and amount; reference token withdrawal adapter itself is pending. A zero-valued payout exists but cannot be claimed. The independent monetary implementation should preserve this distinction.

`spend_watcher_pool` is authenticated, settled epoch, fresh globally shared receipt, nonzero recipient, kind7/8 only, positive amount<=reserve; debits reserve and creates entitlement to that fixed recipient. Watcher stipend kind3 cannot debit this reserve. Step-down signals and cap-normalized target truth are governance/importer boundaries; target changes preserve an existing balance above a newly lowered target without forced subtraction.

## Existing Core suffices for exact U64 arithmetic

`mori-core` UInt is checked u128 and already has +,-,*, comparisons, eager and/or, named UInt/Bool state, requires/ensures, financial effects and emit. There is no general division, conditional/select expression, import/function syntax, runtime string input, map, clock, or cryptographic authentication expression.

Set M=18446744073709551615. Before any products, range-check every monetary/weight/quotient input <=M; d>0,d<=M; require r<d (therefore r<=M). The source relation `q*d+r == n*w` uniquely constrains Euclidean quotient and remainder; neither is trusted. Maximum left side M*M+M=2^128-2^64 and maximum right side M*M both fit u128. This covers the full pinned reference domain, including non-exact division and weighted products above u64. No native arithmetic file or G1 basis change is necessary. A proposed executable source action is `proposed-u64-weighted-floor.mori`; it emits both q and r only after all constraints.

Percent uses d100 and w55/10/5/15. Per-seat allocation uses original category total and original aggregate, not current remaining amount. Denominator can be caller-proposed but is constrained `(aggregate == 0 and denominator == 1) or (aggregate > 0 and denominator == aggregate)`. Roster invariants enforce seat<=aggregate; denominator0 fails. `q*d+r` with r<d has one answer, rejecting forged q, alternate remainders, and supplied divisible-only cases.

For `route_backstop(balance,target,amount,refill)`, all four amounts are U64; require refill<=amount; let after=balance+refill; require after<=M; then require `(balance >= target and refill == 0) or (balance < target and after <= target and (refill == amount or after == target))`. Returns amount-refill. This exactly expresses min(amount,max(0,target-balance)) without evaluating target-balance when target<balance. Core boolean operators eagerly evaluate both branches; guarded underflow in an or-expression is unsafe.

Every U64 add/sub uses u128 evaluation followed by explicit <=M guards, before publishing effects. End time computes epoch+1, checks <=M, multiplies86400, checks<=M, then add2592000/check<=M for reward unlock. Snapshot inputs also need explicit U64 guards on state fields used, so an injected invalid local predecessor fails rather than silently expanding reference domain. Atomic local rejection emits no proposed financial effects; existing runtime and test consumer own this behavior.

## Proposed smallest substantive finite profile

Recommend a source-owned one-epoch instance with a fixed declared exact asset triple and explicit finite registry: two operator seats, one DA seat, one eligible watcher, two cost receipt slots (one ordinary and one watcher stipend), and one reserve-spend slot. Fixed participant account strings are source constants. Seat/receipt identifiers and epoch identity are constants or explicit immutable recorded state. One source instance corresponds to one pool identity; registry slots are distinct source actions/state names, never caller-selected arbitrary recipient strings. Source identity, asset triple, deployment/call binding, and predecessor state are preserved through existing consumers.

Deliver plain `.mori` program(s) with ordinary actions for imported intake, each seat registration, each receipt submission, settlement, each fixed seat allocation, finishing, reserve spending, and each positive-entitlement claim. Each mutable record has explicit present/settled/allocated/claimed flags. Recipient and amount for each entitlement are frozen at creation. Claims transfer to the source-bound recipient only and cannot take a replacement destination. Cost entitlement creation must not transfer money before settlement. Held watcher/backstop/reward/reimbursement state retains custody until corresponding claims; direct balance transfers and liability representation must not double-count entitlement creation as payment. Source transitions and expected complete effects must document chosen custody representation. Existing liabilities can represent fixed immutable recipient-bound duties; at most16 registered names fit the existing native liability registry, so this finite roster is deliberately below that independent limit.

Use fixed per-role/per-seat actions rather than inventing parser functions, loops or maps. Include generic fully constrained q/r as action inputs; any host witness convenience generator is optional and cannot authorize amounts. Reuse ordinary source expressions in each caller; helper-only code does not deliver FeePool behavior. A second small independently authored profile must use the same syntax/consumer path, different names/asset/weights/recipient ordering, and nondivisible values, preventing fixture selection.

Exact importer secret commitments, persistent-hash key construction, authenticated block time, and arbitrary recipient/receipt registries cannot be claimed equivalent in today's Core. Keep these as named external binding predicates and native acceptance gaps. Do not introduce `authorized: Bool` or `now: UInt` as if those authenticate anything. Local scenarios may contain explicit public clock/authority premises with unqualified labels. Signed-v2 currently has fixed signer-policy points; inspect whether action-specific importer and recipient policies are actually supported before claiming authorizer correspondence. Permissionless transfer of a claim to its immutable beneficiary is financially safe but is still a deliberate deviation from the reference's secret-authorized claim and must be labeled if chosen.

## Alternatives and consequential decisions

A: plain finite Core source profile as above, with exact financial behavior and explicitly retained authority/clock/registry binding gaps. Recommended now: source progress, no new primitive, no G1 arithmetic changes, actual CLI consumer available. Finite registry width and custody/liability representation must be explicit; do not say full reference application is implemented.

B: new general language features for bounded maps, typed identifiers, action-specific authorization, authenticated clock and recipient commitments. Required for direct general reference expression, much larger than reimbursement/split delivery; consequential grammar/ABI/native correspondence design needs current majority review. Independent source work in A need not wait for B or native acceptance.

C: new generic floor-mul-div primitive over full u128. Not required by pinned FeePool U64; would require exact u256 relation or limb arithmetic plus parser/runtime/backend/native audits, touching unrelated arithmetic boundaries. Keep for later Capacity Exchange requirements after grounding its true types. Do not silently widen or narrow FeePool to make C necessary or hide u64 failures.
