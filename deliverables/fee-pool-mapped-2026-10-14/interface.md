# Normative source-component interface addendum

This freezes alternative A's implementation interface for the next Moriarty source/library component. `design.md` remains unchanged. This is part of the full roadmap and M11; it does not replace full M11, Capacity Exchange, general registries, authority/clock support, or native acceptance. Exact machine-readable declarations, inputs, actor literals, duty mappings and owned paths are in `interface.json`. No product code is authored in this design task.

## Identity and admitted width

Use `language "moriarty/1"; agreement FeePoolU64Component`. Exact FEES asset: network `local`, issuer `fee-pool-source`, reference `SERVICE`, scale0. These are explicit local example identities, not a Fenrir deployment or authenticated network claim. Pool actor is `fee-pool`, funding actor `funding-source`; all recipients are distinct fixed source literals listed in JSON. There is one immutable imported epoch, two operator seats A/B, one DA seat, one watcher seat, one ordinary cost receipt (fixed kind0, fixed recipient `cost-provider`), one stipend receipt, and one watcher reserve spend receipt. These are fixed distinct receipt/seat names in the source identity; runtime map/hash membership is not claimed.

All 32 numeric states initially0, all22 boolean states initiallyfalse. JSON contains the exact names. Total54 states+23 actions+1 asset=78 declarations, below256. Nine static liability names below16. Every action must enforce U64 bounds on every numeric input and all32 numeric predecessor fields before arithmetic/effects; UInt syntax remains u128, so these source guards are mandatory. All flags have Bool type. Generated/handwritten source must actually count expressions<=8192 and statements/action<=1024 before acceptance; expected shape is comfortably below those bounds but no measurement has yet been run.

## Custody, immutable entitlements, and accounting

`intake` performs one real `transfer(FEES,"funding-source","fee-pool",grossAmount)`. It cannot create receipts, reimbursements, or custody via state updates alone. Gross0 is permitted by the reference. Source requires the clean genesis state for this fixed one-epoch instance: every number0, every flagfalse, and all nine source duty names absent. Exact external starting balances and authenticated predecessor provenance remain scenario/native premises; Core cannot inspect custody balance with a source expression. Existing runtime transfer rejects insufficient funds.

Every entitlement creation uses `liability(NAME,FEES,"fee-pool",FIXED_RECIPIENT,AMOUNT)` exactly once after requiring its named duty absent. It creates an immutable amount and recipient obligation; it does not transfer funds and does not reduce gross a second time. Zero-valued entitlements are deliberately present0 duties, preserving reference zero-payout existence. Each amount state is assigned only at that entitlement's creation. Nine mappings are frozen in JSON. No new Fee effect is emitted anywhere: application fee intake is already the transferred gross, while DUST/service/CX proceeds are separate streams.

Every claim requires recorded+settled, the mapping's creation flag, not its claimed flag, amount>0, the exact named duty present with amount equal its immutable state, and observedAt>=unlock. It executes in this exact financial order: `transfer(FEES,"fee-pool",FIXED_RECIPIENT,AMOUNT)` then `discharge(NAME,AMOUNT)`, then writes claimedTotal+=AMOUNT and its claimed flagtrue. The discharge retains the duty present0 in the current runtime; the flag prevents reuse. No destination, amount, asset, duty name, or epoch is caller-replaceable. Claim cannot modify other entitlements and remains legal after finishing. Finishing cannot discharge or delete older duties.

`claimedTotal` records only successful actual claim transfers. `carried` is explicit unallocated custody, initially gross at intake, decreased by each cost entitlement, replaced with opTotal+daTotal at settlement, decreased by each seat allocation, and zeroed only by finish after residual routing. Let L be the sum of all nine current `liability_amount(NAME)` values, absent contributing0. The invariant is `gross == claimedTotal + L + backstop + watcherHeld + carried`. It separates outstanding entitlements, already delivered funds, held reserves, and unallocated custody. At any reachable admitted state, actual pool balance changes by gross intake minus claims; no operation mints funds. The existing snapshot/native predecessor boundary must authenticate starting custody; forged arbitrary state roots are not legitimized by this arithmetic invariant.

Every action checks preconditions and all its proposed result ranges/invariants before its first financial/state effect. If a later transfer/discharge/check fails, existing local execution rejection publishes no financial effects or post-state. Tests must assert atomic refusal, not partial snapshots. Implement postconditions as needed, but do not rely on unsafe eager branch arithmetic.

## Exact action behavior

`intake(epochId,grossAmount,closeObservedAt,initialTarget,watcherStipendLimit)`: all inputs U64; clean genesis; compute nextEpoch=epochId+1 and require<=M, close=nextEpoch*86400 and require<=M; require closeObservedAt>=close. Transfer gross from funding-source to pool; set epoch,epochClose,gross,target,stipendLimit,carried to supplied/computed values, recordedtrue. This imports exactly one canonical closed epoch under an external importer/time premise. No fabricated boolean authorization is accepted as native authentication.

`registerOperatorA/B(weight,attested,effectiveWeight)`: recorded, notsettled, corresponding notregistered; raw weight<=86400 even if unattested. Effective input constrained `(attested and effectiveWeight==weight) or (not attested and effectiveWeight==0)`. Set slot weight/effective flag, add effectiveWeight to opWeight and increment rewardSeatCount; every next value<=M.

`registerDa(weight,attested,effectiveWeight)`: same, raw weight<=M, sets daSeatWeight and adds to daWeight; increments rewardSeatCount. `registerWatcher` same with watcherWeight and watcherRegistered; it never increments rewardSeatCount and cannot be called twice. Watcher limit in this admitted profile is exactly1. A registered zero-weight reward seat still counts and must be allocated before finish. Watcher positive weight gates stipend, never grants a percentage seat reward.

`submitOrdinary(amount)`: recorded, notsettled, notordinaryRecorded, amount>0, fresh cost_ordinary duty; nextmetered=metered+amount<=gross; create fixed kind0 entitlement and immutable ordinaryAmount; metered increases, carried decreases amount, ordinaryRecordedtrue. Its receipt slot is distinct from every other receipt; its action cannot accept kind3 or change recipient.

`submitStipend(amount)`: same metered reservation checks plus watcherRegistered, watcherWeight>0, amount<=stipendLimit, and notstipendRecorded. Create cost_stipend to fixed watcher. `stipendRecorded` is the once-per-(immutable epoch, fixed watcher recipient) guard, not merely a receipt-local flag. Every possible stipend route in this profile must share it; the ordinary action and reserve-spend action explicitly cannot carry kind3. Thus separate keys cannot pay a second stipend to the same recipient. The finite one-watcher profile intentionally admits no second watcher alias; a later registry extension must preserve recipient-based sharing even across different seat IDs.

`settle(opQ,opR,daQ,daR,watcherQ,watcherR,l2Q,l2R,refill)`: recorded, notsettled; surplus=gross-metered. Require each q/r pair has q<=M,r<100 and q*100+r==surplus*share for shares55/10/5/15. Midnight=surplus-opQ-daQ-watcherQ-l2Q. Route l2Q through exact constrained refill below. Require new watcherHeld=old+watcherQ<=M; preserve positive reserve until a valid explicit spend. Create treasury_l2 with l2Q-refill and treasury_midnight with Midnight; source amounts freeze. Set op/da/watcherTotal, opRemaining=opQ, daRemaining=daQ, carried=opQ+daQ; increase backstop and watcherHeld, set settledtrue. No stipend/reimbursement or watcher share is paid again here.

`allocateOperatorA/B(denominator,quotient,remainder)` and `allocateDa(...)`: settled, notfinished, corresponding registered, notallocated, fresh named reward duty. Denominator constrained to original opWeight/daWeight ifpositive else1; q<=M, r<denominator, q*denominator+r==originalTotal*slotEffectiveWeight. Require q<=categoryRemaining, nextAllocated<=rewardSeatCount, epochClose+2592000<=M. Create reward duty even q0; freeze slot amount; subtract q from category remaining and carried; increment allocatedCount and set slot allocatedtrue. Category total and aggregate weight are never reduced. Allocation order changes trace order only, not beneficiary amounts. A zero DA seat must allocate0 and count; its claim always rejects.

`finish(refill)`: settled, notfinished, allocatedCount==rewardSeatCount; residue=opRemaining+daRemaining and carried==residue; route residue through exact refill; create treasury_dust to L2 for residue-refill, including zero; backstop increases refill, category remaining and carried become0, finishedtrue. Existing cost/reward/treasury claimed flags, duty amounts and immutable amount states are unchanged. No seats permits immediate finish; all registered zero seats must still allocate.

`spendWatcher(kind,amount)`: recorded+settled, notspendIssued, kind7 or8, amount>0<=watcherHeld, fresh watcher_spend duty; create immediately epoch-close-unlocked entitlement to fixed watcher, reduce watcherHeld by amount, freeze spendAmount/spendIssued. This consumes no new gross and does not alter metered. It cannot use stipend kind3. The one spend receipt is explicit finite profile width, not an unlimited spending API.

`setTarget(newTarget)`: recorded, U64 newTarget, replace target only under external governance/importer premise. If balance is above a reduced target, it remains held; future refill is0. Target change cannot move any coin or erase a duty.

Nine claim actions and exact observedAt inputs are in JSON. `claimOperatorA/B/Da` require 30 days after epoch close; every other entitlement uses epochClose. The reference watcher reserve itself has no 30-day expiry or 30-day spend lock: it is held until authenticated bounty/inclusion spend. Only operator/DA rewards have the 30-day cliff. Do not invent a watcher payout at day30. Positive watcher holding and operator/DA 30-day boundaries both need tests. Creation of reward unlock overflow rejects allocation atomically; claims check observedAt<=M before comparisons.

## Exact refill and global invariants

For U64 balance,target,amount and proposed refill: require refill<=amount; let after=balance+refill; after<=M; require `(balance>=target and refill==0) or (balance<target and after<=target and (refill==amount or after==target))`. This uniquely selects min(amount,max(0,target-balance)) without unsafe target-balance. Both Core boolean branches are eager.

In addition to conservation: metered=ordinaryAmount+stipendAmount<=gross; opWeight=opAWeight+opBWeight and daWeight=daSeatWeight; unregistered weights0; rewardSeatCount equals registered operator/DA slot count; allocatedCount equals allocated flags and<=rewardSeatCount; no allocation without registration; no finished without settled; settled freezes receipt registration/metering/seat weights/category totals. Before settled, all category totals/remainders/treasury/reward allocations are0 and carried=gross-metered. After settled, independent exact floor category totals remain bound to gross-metered; opRemaining=opTotal-opAAmount-opBAmount, daRemaining=daTotal-daAmount until finish; after finish those remainders/carried0 and immutable reward amounts remain. Account for the moved residue in backstop/treasury_dust rather than reasserting unfinished remainder equalities after finish.

For every duty mapping: if notcreated then duty absent, amount state0, claimedfalse. If created and notclaimed, duty present and amount==immutable amount state; if claimed, created and positive immutable amount, duty present0. Amount0+created+unclaimed is valid. A claim flag cannot manufacture absence or a new entitlement. `claimedTotal` equals the sum of immutable amounts of all claimed slots; use safe UInt indicators supplied as witness with constraints or separate boolean implication/disjunction checks; do not introduce unchecked host totals. Counters/attestation selectors similarly need source constraints, not bool-to-UInt host trust.

Keep these invariants as source pre/post guards or equivalent per-transition source constraints established from the clean genesis root, with complete expected predecessor states in tests. They are also normative Quint properties. Authenticated history is still a separate native gate. No action may accept a self-declared poststate, effect list, success flag or trusted quotient.

## External premises and ownership

The monetary component's importer/governance calls are externally authorized premises; observedAt/closeObservedAt are unauthenticated public local inputs pending ledger-clock binding. Fixed recipient claims send only to the immutable beneficiary and use external beneficiary authorization premises; they do not implement the reference's recipient-secret hash gadget. Public source-static signed compilation does not prove those premises. General registry/hash/auth/clock language interfaces and Capacity Exchange remain owed.

Owned paths are exact in interface.json: source lane owns examples source/static bindings/README/limits; independent expectations lane owns cases+mori-tests.json; caller lane owns crates/mori/tests/fee_pool_component.rs; Quint lane owns specs/quint/fee_pool_component.qnt and _test.qnt. Freeze these names with expected/model agents before editing. Do not add a generator framework, scheduler or new harness. Actual consumers are existing mori test, simulate, and unsigned/signed-v2 all-actions static compile+inspect (public policy only, no keys/params/SRS).
