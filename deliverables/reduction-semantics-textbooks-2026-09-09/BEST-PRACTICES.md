# Applying the books to Moriarty's reduction semantics

The inspected README already has the right basic shape for this projection: instruction grammar, single-hole left-to-right contexts, primitive contractions, contextual lifting, and a packet delimiter whose failure rule discards the pending suffix. The books support clarifying the scope and obligations of those rules. They do not call for adding lambda abstraction, recursion, a mutable store or an exception-handler language to Moriarty.

The observations below refer to the README candidate with SHA-256 `bb39ad578b1b90ce41a6a6a97733b777ce865a1a5faaa60f321dd25fd8b87788`, plus the existing [K source](../../experiments/moriarty-language/formal/k/moriarty.k). Later README edits require comparing the listed observations again. All proposed checks are **specified-only**; no new Redex, Agda, Rocq, K or native-proof experiment ran in this source intake.

| **A strategy restricts where contraction can happen.** Source fact: Redex distinguishes closure in all term positions from closure in selected evaluation contexts. | Redex `redex-doc/redex/scribblings/ref/reduction-relations.scrbl`, lines 214–313, `compatible-closure` and `context-closure`; [online reference](https://docs.racket-lang.org/redex/Reduction_Relations.html). Recommendation: retain this explicit quotient/flat-list convention. Check that two false guards cannot make the later error win and that no step reduces packet data. Mere closure under every syntax constructor would change behavior. |
| **Separate local contraction, whole-program control and final observations.** Source fact: the Redex exception example erases an evaluation context while retaining the outer term context. | Redex Long Tutorial, `long-tut/wed-mor.scrbl`, lines 171–249, `Raising Exceptions`; [online tutorial](https://docs.racket-lang.org/redex/redex2015.html). Full version 9.0 PDF, pp. 55–56. | Repository observation: README `ABORT` maps `run_H(E[ensure(...false...)])` directly to `rejected`, matching K lines 55–57, which erase the pending K suffix. Recommendation: preserve the packet delimiter and terminal answer grammar. Check a failing Transfer guard followed by valid repayment: rejection returns no proposed state/effects and cannot reach `finish`. This is local preparation atomicity, not ledger rollback. |
| **No successor and successful termination are different predicates.** Source fact: PLFA defines stuck as normal but not a value and states progress for closed well-typed terms. | PLFA `src/plfa/part2/Properties.lagda.md`, `Introduction` lines 36–84, `Progress` lines 166–240, `Well-typed terms don't get stuck` lines 1324–1395; [Properties](https://plfa.github.io/Properties/). | **Determinism and termination require distinct arguments.** Source fact: PLFA supplies `det`, but progress/preservation permit infinite reduction; gas bounds the evaluator, not a universal termination theorem. | PLFA `Properties.lagda.md`, lines 68–75, `Evaluation` lines 848–972 and `Reduction is deterministic` lines 1397–1440; SF `Smallstep.v`, `step_deterministic` lines 263–295 and `Normal Forms Again` around lines 1047–1078. | Inference: assuming pure helpers are total and deterministic on admitted data, the README control relation has one next answer/state for each reachable non-answer: first `start`, then `inspect`, then exactly one Boolean guard or final `finish`. With 21 checks it uses at most 24 presentation steps: START, EXPAND, up to 21 guards, PREPARE; failure at guard j uses j+2 steps. This is a short inspection argument about abstract control, not a mechanized K correspondence proof. The two financial work units are unrelated to this count or K equational steps. |

Recommendation: keep `F`'s scalar K result distinct from codec-reconstructed effects and metadata. Check complete balances, allowance, principal/accrual/outstanding, work, effects and used IDs at successful preparation, while exposing nothing from a rejected candidate. Existing 16-case evidence supports only its recorded cases. |
| **Binding needs a definition only where the language actually binds.** Source fact: PLFA treats substitution and its preservation lemma explicitly; Redex warns that substitution is easy to get wrong. | PLFA `Lambda.lagda.md`, `Bound and free variables`/`Substitution`; `Properties.lagda.md`, `Substitution` lines 547–768; Redex `tut.scrbl` lines 639–678. | Repository observation: the shown repayment control grammar has no source-variable binder. `E[k]` is hole filling, not variable substitution. Recommendation: do not add a substitution rule to this projection. Future successor `let`/argument semantics must specify scope, shadowing and environment lookup or capture avoidance before claiming full source semantics; parser acceptance does not settle that obligation. |
| **Test all allowed successors and terminal outcomes, then search for counterexamples.** Source fact: Redex distinguishes one-step and multi-step tests; when multiple results exist they must all be listed. Random generation attempts to falsify properties. | Redex `tut.scrbl`, lines 804–952, §§1.5–1.6; version 9.0 PDF pp. 18–21; reference `ref/testing.scrbl`. | Recommendation: a later executable presentation should check one-step uniqueness, first-failure precedence, terminal irreducibility and complete outputs for both allocation policies and malformed-domain exclusions. Keep input generation bounded and record which rules fire. A passing sample or successful random run is not a proof, and constructing a second model is not itself evidence that it matches K. |

The most useful small README addition is a qualified paragraph connecting the admitted/reachable domain to unique next steps and the 24-step abstract bound. It should name helper totality/determinism as assumptions and keep mechanized correspondence open. Financial state-preservation claims need their own predicates: successful debt accounting and residual-duty preservation are not supplied by the lambda-calculus type-preservation theorem.

The source graph distinguishes `source_fact`, `repository_observation`, `inference`, `recommendation` and `open_question`.
