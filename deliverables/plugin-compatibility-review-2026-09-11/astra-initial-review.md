## Findings and acceptance cases

1. **P1: false shell dispatch recognition**, `scripts/moriarty_dev/hook.py:151`. The hook denies ordinary `rg sp05-ledger-implement .moriarty-dev/actions.json`, `printf "%s\\n" sp05-ledger-implement`, and CLI `review --action sp05-ledger-implement --receipt example.json`, because any matching token is treated as dispatch. All three were reproduced through `handle_pre_tool_use`; no shell command was launched. Require a supported simple CLI `run --action` invocation before named-action assessment, retaining exact registered raw argv denial. Search, print, source-edit, and review ingestion cases must remain available.

2. **P1: false sprint completion**, `scripts/moriarty_dev/cli.py:78-96`. A disposable fixture with SP05 stage s1 complete and `completionRequires: [SP01]` reports `status: complete`, `demonstrated: true`, and predicate `completion requirements: SP01`. Production `openspec/sprints/sprints.json:643` says these requirements govern completion. Require resolved dependencies as well as local stages. Missing references and cycles must stay open; test completed/open dependency combinations.

3. **P2: invalid input becomes ordinary no-op and event types are unchecked**, `scripts/moriarty_dev/hook.py:75-80` and `:28-32`. Malformed JSON and oversized payloads silently become `{}` and may be interpreted relative to process cwd. Direct no-event-argument invocation with object-valued `hook_event_name` emits object-valued `hookEventName`. Require bounded UTF-8 decoding, typed fields, a closed event set, common diagnostics on malformed input, and no repository processing after decode failure. Validate event-specific output against an independent closed schema, including Stop common-only output and no explicit allow.

4. **P2: installation observations disagree**, `scripts/moriarty_dev/cli.py:600` and `:624-628`. On the same installation the checked-in CLI reports `hostInstalled: false`, while the cached CLI reports true. Report uses another narrower check. Share read-only observations for source path, cached copies, and unknown activation/trust; cached presence alone does not establish active installation. Test source/cache invocation, multiple versions, missing flat legacy directory, and custom CODEX_HOME.

5. **P1: operational history identity mismatch**, `scripts/moriarty_dev/records.py:2545,2593` and `scripts/moriarty_dev/store.py:112,177-181,204-212`. In a disposable ordinary Git repository, `record_event(db, checkout, ..., defect_failure)` followed by `get_history(db, checkout, ...)` returns one failure. The actual snapshot identity is `checkout/.git`; passing that through `make_history_reader` returns `None`. The same mismatch also prevents shared worktree history from being reliably visible. Include this repair now: it breaks the core stop-rule projection. Preserve historical rows; define the database's Git-common-directory ownership once and consistently project checkout and common-directory identities. Do not merely change new writes or add the main checkout parent: existing linked-worktree rows and admin intervals also need to remain visible. Test main/linked/common identities, historical root-keyed rows, admin accounting, and isolation between two independent repositories. Deleted worktree ownership must have an explicit conservative disposition rather than silently becoming clean history.

6. **P1: generic approval clears unrelated blockers**, `scripts/moriarty_dev/store.py:272-280`. Disposable reproduction records finding FINANCIAL-SETTLEMENT on candidate `a` repeated 64 times, then ingests an independent APPROVED receipt on candidate `b` repeated 64 times with scope `documentation spelling only` and no resolution IDs. Failure count changes from one to zero. `tests/test_execution.py:test_authentic_review_clears_stable_finding` explicitly expects generic approval to clear a blocker, so this requires an intentional contract/test correction. Require explicit validated finding IDs for resolution; missing, empty, or malformed resolution lists must clear nothing. Preserve stable finding identity across candidate changes, so do not solve this with a blanket same-candidate filter. Test missing/empty/malformed lists, unknown IDs, partial resolution, stable IDs across candidates, and author events. Historical rows stay immutable; repair the read projection and ingestion checks.

## Bounded design assessment

The proposed typed hook protocol module, explicit simple dispatch recognizer, shared read-only installation diagnostics, dependency-aware sprint completion, and standalone compatibility tests are appropriate. Keep existing CLI/policy/store boundaries. The two reproduced store defects are material stop-rule failures and should join this bounded repair; no custom installer, scheduler, or admission framework is needed. Preserve old cache copies through supported upgrade procedures. Document platform limits and actual-host verification separately from Python protocol checks.

The final changed candidate still needs full tests and fresh independent exact-candidate audits. This initial review does not approve future bytes.
