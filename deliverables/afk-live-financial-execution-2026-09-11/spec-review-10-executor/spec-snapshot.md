### Requirement: Concrete one-shot runner invocation handoff
`runner.execute` SHALL create one private AF_UNIX stream socket in a new mode-0700 runtime directory inside the authenticated evidence directory, mode 0600 socket, with a cryptographically random 256-bit nonce. It passes only `MORIARTY_INVOCATION_SOCKET` and `MORIARTY_INVOCATION_NONCE` as explicitly set child environment values, overwriting any inherited values. This is a transient parent/child channel in the existing run, not a service. The fixed argv and stdin DEVNULL remain unchanged. Source inspection and an actual isolated launcher test SHALL establish that the pinned Foreman launcher inherits these environment values through strong containment; if it does not, repair/pin the minimal launcher adapter before source approval rather than assume transport exists.

Immediately before the actual Foreman `Popen`, the runner samples host `CLOCK_MONOTONIC` outer start and boot ID. After spawn, and before answering the child's handshake, it durably appends an existing-store invocation event for the current reservation and claimed master debit. The closed invocation payload is `schema=moriarty.loan-invocation/1`, `allocationId`, `actionId`, `candidateHash`, `runnerDigest`, `chargeId`, `reservationId`, `storeIdentity`, `executionContextSha256`, `projectionSha256`, `correspondenceSha256`, `authoritySha256`, `bootId`, `outerStartMonotonic`, `outerDeadlineMonotonic`, `blockDeadlineUtc`, `parentPid`, `parentStartTicks`, `launcherPid`, `launcherStartTicks` and `nonceSha256`. The outer deadline is start+1800, capped by the fixed block deadline; all identities come from current validated producer state, not caller assertions. Persist the canonical payload digest in that event. A failed append yields no handshake and retains the debit/claim as unresolved.

The child sends its nonce and immutable authority digest. The parent verifies constant-time nonce equality, authority equality, socket peer UID, and peer host PID ancestry under the actual Foreman launcher using bounded `/proc` traversal with retained process start ticks; PID reuse, a sibling or wrong launcher denies. Exactly one successful handshake is allowed. The parent sends the invocation payload and its canonical digest only after confirming the current store event, active runtime reservation, master one-shot claim and held wallet ownership still match. The child checks nonce digest, canonical payload digest against that store event, boot ID, monotonic deadline, authority, all current claim identities and same-UID private socket ownership. A process in a child PID namespace need not resolve the parent's host PID locally; the host parent proves child ancestry and the child verifies canonical state and nonce. This uses the existing same-owner host/store trust boundary, not a claim to protect against a host owner rewriting all authority records.

Keep the authenticated channel open through cleanup; bounded liveness checks distinguish parent disappearance. EOF before setup refuses startup. EOF after startup initiates owned safety cleanup and yields unknown unless a known failed main exit is already retained. The parent releases the wallet lock only after validated durable containment, and removes only its own socket/directory after completion. No mutable identity is added to runner file hashes; no environment value alone grants authority. Store/master replay controls from item 1.3 remain mandatory, including a restored or alternate SQLite store being unable to reuse the master claim.
