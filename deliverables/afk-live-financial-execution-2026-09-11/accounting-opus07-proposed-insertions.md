# Proposed O13-1..3 and O13-5 revisions

Source-only specification proposals. No shared specification, live store, wallet or grant is modified. These clauses select concrete interfaces so an isolated positive fixture is calculable. They require fresh approval on the final incorporated bytes.

## O13-1: closed identity and executable authority

The execution context SHALL add exactly `expected` and `observerExecution` to its existing field family. `expected` SHALL contain exactly `allocationId,network,roleIdentity,selectedToken,walletStateDirectory,seedPath,pendingUseDisposition`, with network exactly `{networkId,genesisHash,protocolVersion}`, roleIdentity exactly `{publicKey,address}`, selectedToken exactly `{id,unit}`, and pendingUseDisposition an immutable contained `{path,sha256}` reference already admitted in history. Paths to original seed/state are canonical absolute private-input identities, not values to publish or create. Observer output identity SHALL match this independently reviewed expectation; self-consistency between any seed and snapshot is insufficient. The eventual executor's authenticated plan SHALL match this same expected record before runtime debit.

`observerExecution` SHALL contain exactly `interpreter,entry,files,sdkClosure,launcher,argv,environment,parentEvidencePath`, with interpreter/entry/launcher exact `{path,sha256}` records, files an exact path→digest map, sdkClosure a `{path,sha256}` immutable contained manifest reference whose file map contains canonical absolute installed SDK files and hashes, argv an exact string array, environment an exact string map, and parentEvidencePath a contained exclusive evidence destination. `interpreter` SHALL be the absolute Node executable; entry SHALL equal the separately pinned observer entry. Launcher SHALL be the existing Foreman launcher, invoked with fixed `--timeout 90 --grace 5 --require-containment strong`, through its pinned interpreter. All argv file operands SHALL appear in files; external executable/SDK files are admitted only by this closed plan. Environment SHALL be constructed from its exact reviewed map, not inherited wholesale; keys that inject Node code/loaders or override network/private-input destinations SHALL reject unless explicitly part of reviewed source semantics. No secret value belongs in argv or environment. The observer reads expected input paths from the immutable context argument, not caller overrides.

The parent accounting preflight SHALL independently compute before/after digests and metadata of canonical seed and dust/unshielded snapshot bytes through strict no-symlink/owner-only file reads without printing contents, retain only digests/metadata, and compare them. It SHALL derive child containment from its actual Foreman process result and retained terminal/containment observations, not observer booleans. The observer's own child-stop result remains separately required. Parent evidence SHALL bind exact launch-plan/source/context digests, output digest, process exit and containment, canonical before/after input observations, and start/end times. Missing or inconsistent parent evidence makes receipt unavailable. `canonicalInputsUnchanged` and `childrenStopped` SHALL be derived from that evidence and cannot be supplied as authority by the child.

Each resource vote SHALL contain exactly `schema,reviewer,model,role,scope,candidateSha256,verdict,findings`, schema `moriarty.i2-resource-vote/1`, role `independent-resource-reviewer`, scope `MC02 active-envelope grant and execution context`, candidateSha256 equal the immutable projection-file SHA-256, verdict `APPROVED`, and findings a list of strings. The two fresh non-author votes SHALL identify `claude-opus-5` and `gpt-6-astra`, respectively, with actual returned identities preserved. Missing, substituted, same-author, mismatched-scope or nonterminal receipts deny. These are later resource votes, not specification votes.

The actual budget lock SHALL be `Path(projection.predecessor.path).with_suffix('.lock')`; the parent SHALL verify it equals the reviewed lock identity before opening. The wallet-use lock ownership record SHALL bind context digest, projection digest, canonical store identity, preflight reservation ID and preflight charge ID. Runtime handover SHALL atomically update that record to the committed runtime charge ID/reservation ID without releasing the operating-system lock. The executor SHALL discover this record through the immutable context's observer.lockPath and validate it against its authenticated context/projection and master claim. No dynamic argv/environment token is required; the static runner command commits the context path. Ownership mismatch or absent handover denies before wallet access. A lock-file record does not replace the held OS lock.

## O13-2: single actual caller order and occupied primary slot

The live branch of `cli.py::cmd_run` SHALL select action and authenticate the context first, compare its passed db_path to the canonical resolver/context store path, then reconstruct its history reader using the validated token/history. It SHALL reject a mismatched db_path or caller history-reader authority. Legacy branches retain current initialization. An isolated repository may resolve its own explicitly anchored fixture store.

Add a non-granting `accounting.predebit_gate` callable that verifies authenticated source/runner-plan bytes plus canonical history, repeated-defect, primary and stop predicates without requiring a runner debit. It SHALL return `PREDEBIT_ELIGIBLE` or a named denial, never final policy allow. The history/primary/retry predicate logic SHALL be shared with existing policy; no synthetic `resourcesAvailable:true` snapshot or suppression of an actual history failure is allowed. Only the post-debit existing full snapshot/policy and runner validation can admit resources.

The exact sequence SHALL be: authenticate action/context/projection/votes and factorized runner plan; non-granting predebit gate; acquire canonical primary preflight reservation and wallet-use lock; application/debit counterpart and master/projection commit; preflight master one-shot claim; bounded observer; parent evidence and validated funding receipt/correspondence; recheck source/history/own-primary/freshness; runtime debit counterpart and master/projection commit; existing full prepaid snapshot/policy and load_runner; atomic primary handover to runtime reservation; post-reservation own-primary/full resource checks; wallet-lock handover record; master one-shot runtime claim; existing execute; terminal cleanup/disposition. Failure at any stage starts no later child and never refunds committed charges.

A new `store.reserve_preflight` operation SHALL claim the same primary exclusion domain as the selected live action under BEGIN IMMEDIATE, before observer debit or child. It SHALL carry the selected action/candidate/store identity and preflight chargeId. All other primary work SHALL see it occupied. Runtime `store.reserve` handover SHALL validate the same owned preflight reservation and close/supersede it while inserting the runtime reservation in one BEGIN IMMEDIATE transaction; no unoccupied primary interval is permitted. Rechecks shall exclude only the caller's exact own reservation, never other primary owners. Failed preflight retains a terminal disposition and consumption; no second observer attempt is implied.

Set post-debit launch allowance L=30 seconds. Before runtime debit require both observedAt and syncTime ages at most90 seconds, not future, and at least30 seconds remain in every applicable absolute execution/admission deadline. Immediately before execute require both ages at most120 seconds. If work consumes the30second margin after debit, retain charged-but-unlaunched/expired disposition; do not rerun observer or refund attempt3. All boundaries SHALL use one recorded time basis with explicit UTC conversion and monotonic elapsed deadline checks.

## O13-3: durable debit counterpart and first-application marker

First grant application SHALL reserve an exclusive immutable application marker under a context-bound contained evidence directory with O_CREAT|O_EXCL|O_NOFOLLOW and fsync file/directory before modifying the master. Its path SHALL be deterministically derived from the immutable projection digest; its body SHALL bind predecessor digest, projection/amendment/context digests, canonical store identity and application ID. A surviving marker SHALL prevent a second first application even if master/projection/correspondence have been restored to predecessor bytes. It is retained on failure; ambiguous partial application requires explicit reconciliation, never delete-and-retry.

Before each master debit replacement, the existing canonical SQLite store SHALL commit a unique debit-intent counterpart keyed by chargeId through an existing event/claim transaction, binding purpose, full seconds, action/candidate/runner/envelope/store identity and owned preflight/runtime reservation identity. A counterpart is irreversible consumption intent for recovery purposes; it is not proof of child execution. Then write the matching master debit/projection/correspondence. Before any child, both copies and immutable application marker SHALL agree. Existing counterpart with absent/older/different master debit SHALL deny `resource-master-rollback-or-incomplete-debit`; no new debit, preflight or runtime launch follows. Master debit without counterpart SHALL likewise deny. An intent committed before a master-write failure remains consumed/unavailable until reviewed reconciliation and cannot silently reopen grant or attempt capacity.

The preflight SHALL no longer have a null SQLite counterpart. Runtime debit SHALL have its own counterpart before any reservation handover; do not postpone counterpart creation until runner_claims insertion. Distinguish durable debit-intent evidence from the existing final unique launch claim so creation of the intent does not falsely mean launched. Both use the existing SQLite store; no new ledger/service is introduced.

Fault tests SHALL independently roll back master/projection/correspondence after application intent, preflight debit, preflight completion, runtime debit and launch claim. The surviving immutable marker/SQLite counterpart SHALL deny reapplication, second observer and relaunch. Rolling back SQLite alone must still be denied by master/marker evidence. Joint rollback of all independently retained evidence is outside this evidence model and must not be claimed detected.

## O13-5: exact arithmetic and allocation equality

For this mode `_amendment_seconds(resourceAmendment)` SHALL equal G exactly. Binding allocation SHALL be absent/zero; successor amendment allocation SHALL be absent/zero, and no duplicate grant digest is permitted. Compute U,C,D and all comparison sums from exact original JSON numeric tokens using Decimal or Fraction, rejecting booleans/nonfinite/negative values. Do not convert through binary float before ceiling or resource comparisons. Original historical bytes remain unchanged; arithmetic representation does not rewrite their numeric text. The normative fixture SHALL include the inspected fractional planning value and test values immediately on either side of integer closure boundaries.

## Choices that need final agreement

- Wallet OS-lock handoff must specify inheritance/ownership in the actual executor contract. The selected record-based identity check alone is insufficient if the parent releases the OS lock before the executor acquires it. Retain the parent lock through executor completion, or pass an explicitly inherited descriptor supported by the existing launcher; do not invent an untested FD handoff.
- The closed observer launch plan above uses one launcher field but Foreman requires its own Node interpreter. Either pin the same interpreter for both, or give launcherInterpreter its own exact path/hash field; final text must choose explicitly.
- `L=30` is a proposed bounded allowance, not measured runtime feasibility. Denial after committed debit is still possible and honestly consumes attempt3.
