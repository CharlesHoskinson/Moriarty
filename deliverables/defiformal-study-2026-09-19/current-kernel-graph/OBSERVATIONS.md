# Import-level findings for Moriarty library scope

These are repository observations at `33b9a9550ac1ed12c83c32d15277e530741787db`, not theorem or acceptance judgments.

1. **Library adapters sit above arithmetic and typed transitions.** `lean/DefiKernel/Vault/Adapter.lean:1-4` imports Typed.Transition, Vault.Operations, Arithmetic.Quantity and Arithmetic.Reference. `Vault/Operations.lean:1` imports Conversion, which imports Arithmetic.Operations/Rounding (`Vault/Conversion.lean:1-3`). ConcentratedLiquidity.Token0Bridge similarly imports Typed.Transition, Arithmetic.Quantity and SqrtPriceMath (`ConcentratedLiquidity/Token0Bridge.lean:1-3`), which imports arithmetic operations and FullMath. This is a useful dependency seam for a Moriarty financial-library adapter; it does not establish that such an adapter already exists.

2. **Cross-family reuse includes example/audit wiring.** Vault's three direct imports of ConcentratedLiquidity.Token0Bridge occur in `Vault/Examples.lean:2`, `Vault/Verify.lean:3` and `Vault/ProofAudit.lean:8`. The module graph therefore supports an explicit example/verification connection, not an assertion that the Vault operation implementation itself depends on concentrated-liquidity behavior. Certificates.LibraryInstantiation imports Arithmetic.Operations plus Schema and TrustedHost (`Certificates/LibraryInstantiation.lean:1-3`); Certificates.KernelCorrespondence imports Check, Delivered, Soundness, LibraryInstantiation and Parallel.Compatibility (`Certificates/KernelCorrespondence.lean:1-5`). The presence of names such as Soundness/Correspondence does not validate their statement or scope.

3. **The umbrella import is not the whole current kernel inventory.** `lean/DefiKernel.lean:1-12` imports verification roots for typed transitions, composition modes, arithmetic, interfaces and Nary, plus tree recovery and capability provenance. Its textual transitive closure includes 149 other in-scope modules. All 21 Certificates, 10 ConcentratedLiquidity and 9 Vault modules are outside that closure, along with 3 foundation/recovery check modules. They must be separately inspected to understand library scope. This is not a dead-code finding or proof that package builds omit them; Lake target behavior and separate evidence commands require independent review.
