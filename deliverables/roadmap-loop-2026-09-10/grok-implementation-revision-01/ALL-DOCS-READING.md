## Additional applicable findings

1. **Keep exact model facts over generic examples.** The [Build configuration reference](https://docs.x.ai/build/settings/reference) includes a one-million context example, while [exact Grok 4.6](https://docs.x.ai/developers/grok-4-6) documents 500,000 tokens. The example does not expand model capacity. General alias documentation and catalog schemas do not establish an immutable `grok-4.6` to `grok-4.6-build` checkpoint relationship. Retain both requested and returned strings from actual receipts.

2. **HTTP storage and WebSocket continuation differ.** [WebSocket mode](https://docs.x.ai/developers/advanced-api-usage/websocket-mode) keeps the most recent response on a connection in memory and can continue it with `previous_response_id` even under ZDR or `store=false`. Older/evicted IDs can fail; the socket has a 25-minute lifetime and serializes turns. This qualifies broad claims that all ZDR continuation is unavailable. It does not add a CLI transport or change the tested native route.

3. **Resource counters have narrow meanings.** [Advanced tool usage](https://docs.x.ai/developers/tools/advanced-usage) resets the API `max_turns` count on a new request after a client-side tool handoff. Multiple tools can execute in one turn. [Management authorization](https://docs.x.ai/developers/rest-api-reference/management/auth) states that an in-flight request which exceeds a token limiter is not aborted. [Billing management](https://docs.x.ai/developers/rest-api-reference/management/billing) limits postpaid spend separately from prepaid credits. None is a replacement for the existing admitted worker/process/campaign bounds.

4. **Permission controls are product-specific.** [Remote MCP](https://docs.x.ai/developers/tools/remote-mcp) does not support Responses `require_approval`; an empty remote `allowed_tools` permits all server tools. The installed worker instead has explicit scoped CLI permissions and `--deny MCPTool`. [Skills metadata](https://docs.x.ai/build/features/skills-plugins-marketplaces) is not a grant of tool authority; model/effort metadata does not establish actual routing. The develop skill must actually be loaded/read. [Server code execution](https://docs.x.ai/developers/tools/code-execution) describes a separate Python sandbox, not isolation for local `run_terminal_cmd`.

5. **Observe long calls without interpreting silence as failure.** [Enterprise deployment](https://docs.x.ai/build/enterprise) names the CLI proxy/authentication services and discusses SSE idle timeouts; its sample 600-second idle allowance reinforces the existing rule to inspect actual liveness and admitted deadlines. Root-owned policy locks remain authoritative. Hook failure does not prove a blocked action.

6. **Preserve protocol-specific accounting.** [Direct Chat Completions](https://docs.x.ai/developers/rest-api-reference/inference/chat-completions) documents a default 128,000 visible-token completion bound, whereas [Responses](https://docs.x.ai/developers/rest-api-reference/inference/responses) includes reasoning in its 128,000 default output bound. Their examples and legacy/batch schemas differ. API `logprobs` fields are silently ignored for 4.20 and newer. Keep the tested native CLI accounting rather than normalizing from unrelated examples.

7. **No pricing extrapolation.** [Pricing](https://docs.x.ai/developers/pricing) separates priority and batch treatment; the captured batch discount list does not establish a Grok 4.6 discount. [X Search](https://docs.x.ai/developers/tools/x-search) announces a September 21 pricing change; it is not the retrieval-date rate and the source worker has search disabled. Preserve measured and unknown charges, including unsuccessful/incomplete model attempts, rather than using a zero placeholder.

8. **Examples require validation.** The [collection metadata guide](https://docs.x.ai/developers/files/collections/metadata) has conflicting logical-precedence explanation/comment; generic text comparison and current caching pages disagree about older endpoint capabilities. The [function-calling guide](https://docs.x.ai/developers/tools/function-calling) and direct REST reference also give different maximum tool counts. Some polling examples lack a terminal failure branch or deadline. These do not affect the chosen small CLI tool set, but reinforce using actual help, exact feature contracts and bounded tests instead of copying every example. No speculative infrastructure repair is added.

9. **Hosted product controls do not transfer.** [Grok Bot security](https://docs.x.ai/grok-bot/security) describes a managed serving mix without a customer model picker, user-shared cloud computers, separate network/connector policy and incomplete model-allowlist enforcement. These are neither evidence against the tested CLI model selector nor proof of CLI isolation. Voice-specific prompting conventions and hosted Bot approval defaults are not imported as new Moriarty user-confirmation requirements.
