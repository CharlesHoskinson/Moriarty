Use **`--prompt-file` or `--single`**, not a positional prompt. Installed help calls positional input interactive. No inspected official source pins that internal suffix to an immutable checkpoint.

Historical help, current 1.0.25 help and local headless docs support the following **template**, to be filled with real current paths, existing permission/resource admission and a justified turn limit before launch. This template is not dispatch-ready until the mandatory control gate below passes. These are not default resource grants:

```text
<resolved-versioned-grok-binary> --cwd <existing-isolated-checkout>
  --model grok-4.6 --reasoning-effort high
  --verbatim --prompt-file <filled-GROK-WORKER-PROMPT>
  --no-plan --no-subagents --disable-web-search
  --tools read_file,grep,list_dir,search_replace,write_file,run_terminal_cmd
  --permission-mode dontAsk
  --allow 'Read(<needed-source-path-glob>)'
  --allow 'Grep(<needed-source-path-glob>)'
  --allow 'Edit(<owned-path-glob>)' --allow 'Write(<owned-path-glob>)'
  --allow 'Bash(<exact-reviewed-offline-check-command>)'
  --deny 'Read(<absolute-private-path-glob>)'
  --deny 'Edit(<absolute-private-path-glob>)'
  --deny MCPTool --deny WebSearch --deny WebFetch
  --max-turns <admitted-main-agent-turns>
  --output-format json
```

Repeat scoped rules for actual paths/commands, including guarded startup status/next if the worker runs them. `run_terminal_cmd` is the documented internal shell ID; `Bash(...)` is its permission class. `write_file` is named in installed configuration and filesystem docs; the historical terminal-only JSON fixture verified read/edit/new-file/offline-check outcomes, not the identity of each tool used. Do not infer a `write_file` event from a created file. Native tool-call evidence is required to verify individual tool IDs. Retain documented IDs as a launch selection and revalidate task-specific paths/commands. The [source smoke](../grok-implementation-revision-01/grok-source-smoke.json) completed in 28.637 seconds/four turns with exit 0 and end_turn; [root verification](../grok-implementation-revision-01/grok-source-smoke-root-check.json) confirms changed sample, new report and unchanged passing verifier. Do not create broad shell grants to repair that uncertainty. `--tools` does not remove all MCP meta-tools; explicit MCP denial remains useful. A catch-all `--deny Bash` would override allowed shell commands, so do not combine them as an allowlist. Under `dontAsk`, calls reaching the final prompt-policy stage are denied rather than waiting for input. Built-in read-only tool/shell auto-approvals, merged permission rules and remembered project grants can approve calls without matching these explicit launch grants. Therefore scoped `Read`/`Bash` rules are not a closed allowlist or filesystem/network boundary. Inspect effective rules, hooks, project trust and existing host containment before launch. Source-inspect the selected commands, retain scoped grants, and correct a denial only within existing authority; do not broaden grants to hide the gap.
