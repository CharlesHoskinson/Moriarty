# Fresh local command completion

A fresh supported local financial command could complete all four financial stages, stop its wallet and have zero pending work, yet throw DRIVER_CLEANUP_INCOMPLETE because external containment was false. The real integration always reports external containment false. The original focused driver test reproduced this failure; historical local INCOMPLETE/CLI1 records remain unchanged.

The driver now permits FINANCIAL_COMPLETE for fresh four-stage local runs. Existing deployment recovery, initialized continuations and stale rejection keep their prior completion behavior. Integration requires a complete comparator finish, wallet stop, zero pending and an unexpired deadline after loader cleanup. Cleanup failures cannot retain a completed top-level status. A local validator checks four matching native receipts/comparisons, finality fields, native identifiers and fees, recorded reservations, false acceptance flags and the status/containment relationship. The writer validates FINANCIAL_COMPLETE before durable retention. The CLI uses this validator and checks its absolute deadline; stdout now includes containmentComplete. PASS still describes containment true. Preview behavior and source files are unchanged.

217 targeted tests passed, including12 connected local-completion tests, local/Preview drivers, integration/writer, negative financial controls and recovery/initialized/stale regressions. The connected fixture invokes the default integration branch through test-runner module interception, actual driver/native observer/comparator, writer and CLI selector. Controlled SDK/transport/reservation interfaces do not submit anything. It uses retained native loan payloads and public decoded summaries, synthetic capability commitments and controlled native state containers. All actual native IDs are retained. This is selector mapping and source behavior evidence, not an actual local command exit observation.

Controls cover stop/pending/loader/deadline failure, wrong recipient, cumulative over-fee, durable writer failure, stale/incomplete/malformed state, missing IDs/finality, source-only status, nested acceptance/accessors and deadline after durable fsync. Original RED, intermediate fixture/test failures and final GREEN logs are retained. Some old positive source fixtures now correctly return SOURCE_TEST_ONLY instead of throwing solely because external containment is false.

Local snapshot persistence is not added or asserted. Existing local wallet.stop does not itself establish persisted snapshots; this patch leaves that separate behavior unchanged. Preview coherent persistence is untouched. Actual local invocation, independent external containment, wallet persistence semantics if required for a future run, full SP05 and mandatory PCD acceptance remain outside these source-only checks. No private files, services, compilation, proofs or transactions were used. Both independent source audits are required before merge or operational use.
