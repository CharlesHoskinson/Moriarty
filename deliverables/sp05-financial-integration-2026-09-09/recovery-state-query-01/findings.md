# Exact-block contract-state lookup diagnosis

Experiment observation: before the production repair, the actual preflight wrapper and pinned SDK rejected with `RECOVERY_STATE_TYPE` in 782.645135 ms when the synthetic finalized/indexed head advanced to 20323 and the contract's only action remained its retained deployment at 20313. The loopback GraphQL server returned null for the exact 20323 contract-action lookup. Native transaction/build/constructor bytes were retained real public inputs. `exact-block-preflight-red.json` records requests, zero trapped private accesses and server closure; stderr is empty and the bounded subprocess exited 1. This reproduces the mechanism and the reported diagnostic code, but does not independently inspect the actual indexer database.

Primary-source observation: at revision `a89e1d3b3d8daf73a0e7beed9839ee70188e92c4`, `indexer-api/src/infra/api/v4/query.rs` routes an explicit block offset to an exact block lookup and no offset to the latest action. `indexer-api/src/infra/storage/contract_action.rs` requires equality with the selected transaction block ID or block height. It does not select the most recent action at or before that height. The latest query instead orders contract action ID descending and limits one. Full captured sources and SHA256 digests are in `source-manifest.json`.

Experiment observation: `sqlite-exact-block.py` extracts those three literal SQL strings from the captured Rust, without changing the SQL, then executes them over an in-memory SQLite fixture with one deployment at 20313 and an empty later block at 20323. Both exact current-block queries return null; latest and historical queries return the identical original constructor row. See `extracted-queries.json` and `sqlite-exact-block-result-02.json` (SQLite 3.46.1; 0.606611 ms; exit 0). An initial harness attempt passed positional bindings to named $1/$2 placeholders and failed before the queries ran; the empty first result file remains. The corrected harness uses named bindings and preserves SQL bytes.

Image observation: selective `docker image inspect` captured only image ID, repository digest and labels, without environment values. Installed `midnightntwrk/indexer-standalone:4.3.3` is `sha256:03afd079b00bcd229df29a24771439c5e7695c339cd89216d0763ce40731cc4b`; its revision label matches the captured source revision. A label is not an independent binary/source reproducibility attestation. No container was started or inspected for private configuration.

Acquisition limitation: this source checkout is a partial clone. An initial broad Git text search triggered lazy public-source acquisition; it was stopped after discovery. The final three source captures used narrow Git show commands with promisor fetching disabled and five-second subprocess bounds. No blockchain service, wallet, proof server or real private-store access occurred. Only new files in this evidence directory were created; prior fixtures and production sources were not edited.

The repair must retain full constructor/native-state equality and independently constrain the latest-state query to a stable finalized and fully indexed window. Changing exact-block to latest without that constraint would introduce a different correctness gap.
