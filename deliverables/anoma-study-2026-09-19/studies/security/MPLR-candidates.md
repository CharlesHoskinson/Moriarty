# Refinement candidates — no IDs allocated

These are research candidates, not accepted implementation requirements or machine-checked results. Reconcile against the existing MPLR ledger before allocation.

- **Proof acceptance must bind the intended predicate and statement.** Refine existing artifact/version binding with resource tag, creation/consumption role, action context, canonical journal encoding and chain-accepted kind table. Positive: matching predicate and instance; hostile: unrelated passing predicate or substituted table. Evidence ARM-SEC-06–09,12. This is a refinement of existing binding obligations, not a new generic “verify proofs” rule.
- **Precommit composition must remain distinct from committed-stage continuation.** Require separate types/judgments for unresolved candidate delta and accepted balanced stage. Positive: complementary candidates compose before commit; hostile: witness-only candidate submitted as settled prefix. Evidence10–11 and shielded spec. Refines partial-settlement semantics.
- **Recursive obligations need explicit residual state.** Resource balance cannot erase outstanding delivery/refund obligations. Positive: separately valid escrow/delivery stages; hostile: balanced transition silently drops obligation. An application design requirement inferred from ARM's scope, not a demonstrated ARM vulnerability.
- **Ephemeral resources need purpose-specific admissibility.** Preserve intentional zero-quantity padding and constraint carriers while proving that application mint/consume rules do not turn ephemerality into unauthorized value. Positive and hostile witnesses must avoid imposing persistent membership indiscriminately. Evidence04,21.
- **Acceptance is relative to a ledger state and an implementation tuple.** Bind root history/nullifier uniqueness plus circuit ELF/image, journal format, adapter version and external-evidence policy. Distinct HEADs are not a compatibility proof. Evidence15–18 and version findings.
- **Privacy statements must name observer and channel.** Prove verifier-facing nondisclosure separately from solver/prover witness access, calldata, events and external calls. Suppressed events are not ciphertext or deletion. Refines existing disclosure obligations rather than creating a generic privacy requirement.
- **Domain separation must be unambiguous.** Require canonical fixed-width or length-delimited domain/message encoding; prefix naming alone is insufficient. Positive fixed-domain statement; hostile alternative boundary with identical concatenation. Evidence20; application exploitation not established.
