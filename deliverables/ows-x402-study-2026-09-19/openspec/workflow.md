# Foreman/Pel workflow

Select one K package and freeze its requirements, assumptions and expected outcomes. Give the implementer only its bounded write scope. Run deterministic checks on the exact candidate. Obtain independent review of the complete result and its evidence. Permit one correction cycle; unresolved findings return needs-action.

The Pel program is a checked control-flow template. Bind artifact:approved-spec to the selected K package. Bind candidate-full to that package's actual acceptance checks. Resolve role:implementer and role:reviewer through the current authorized model policy. Record resolved identities, candidate hashes, results and unresolved findings.

Do not execute the abstract template as if those bindings existed. A successful Pel check validates orchestration syntax and structure, not financial behavior. Reviewer approval does not authorize public developers or their programs.
