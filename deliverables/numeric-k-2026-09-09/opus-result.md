## 2. Stage guarantees, exercised not asserted

- **Huge scale rejected before exponentiation.** `numeric-scale-uint128max` (scale = 2¹²⁸−1) is admitted by `codec.uint` and returns `INVARIANT` at index `-1` (trace‑12). The scale guard is the third `ensure` in `inspect`, at the state stage; `10 ^Int SCALE` lives only in `divideRepay`'s RHS, six KItems later, and `ensure(H,false,…) ~> _REST => .K` discards the whole continuation. So the power is never constructed. This is the discriminating case and it is present and green. `numeric-scale-nineteen` confirms the ordinary 19 > 18 boundary.
- **Product before division.** `numeric-conversion-product-overflow` (m = 2¹²⁸−1, n = 2, scale 18) returns `OVERFLOW` at index 1 (trace‑09) even though the mathematical quotient fits. `convertRepay` prepends `N *Int M <= maxU()` and hands the product forward; the fixture proves the guard is not skipped by a fitting-quotient shortcut.
- **Conversion stage precedes allocation.** `numeric-conversion-before-prorata-overflow` (scale 1) yields `INEXACT_CONVERSION` while `numeric-prorata-product-overflow` (scale 0, otherwise identical debt) yields `OVERFLOW`. That pair pins the boundary by observation rather than assertion.
- **No implicit cash→debt coercion.** `numeric-floor-dust` rejects `DUST` where ⌊1/10⌋=0 would otherwise erase nominal 1 for free; `numeric-ceil-rescues-dust` shows the same input funding at ceil. `numeric-insufficient-converted-funding` (converted 6 > transferred 5) rejects `INSUFFICIENT_UNALLOCATED`, confirming funding compares converted cash against the transfer, not nominal against cash. `numeric-nominal-exceeds-cash` (30 nominal, 6 cash) succeeds with dA 10 / dP 20 — nominal discharges debt, cash does not.
- **ProRata residuals and settled Transfer-only.** Traces 14/15/16/17 cover partial, exact-full, zero-principal and zero-accrued; in every one `dP + dA = N` exactly and both components stay within their existing balances. `numeric-transfer-settled-prorata` (trace‑21) preserves P0/A0/O0 `Settled` under Transfer-only with no allocation division — consistent with the kernel's Transfer contract and with `NOT_OUTSTANDING` preceding allocation on the Repay path (trace‑52).
- **First failure, no partial output.** Every rejected output contains only digest/code/index — no post state, no effects, no tentative scalars. `run.py::traces` writes `observations.json` before comparing and then `fail('EXPECTED_RESULT_MISMATCH')`; with all 64 matching, that path was not taken, and no retry or backend fallback exists in the code.

## 5. Non-blocking findings

- **(a) Codec diagnostic.** An out-of-range K scalar surfaces as `MALFORMED_INPUT` (via `uint` inside `decode`) rather than `K_OUTPUT`. Fails closed; cosmetic. README already discloses it.
- **(b) Non-atomic binding write.** `write(BINDING, …)` is `path.write_text`; a whole-cgroup SIGKILL landing inside it could truncate the counter. This run completed normally with intact matching bindings, and a damaged binding fails closed and never authorizes a retry. Atomic replace is the right later hardening.
- **(c) Retained checker limitation.** `check-k-results.py --retained` cannot rehash compiled artifacts on a fresh clone (`if actual:` guard); the 187-artifact check depends on the preserved local build. Correctly stated in the README; not a defect, but it means artifact identity is attested rather than reproducible off-machine.
- **(d) CLI receipt paths.** `check-cli-cases.mjs` removes its temp directory, so `cli-observations.json` retains argv/stdout/exit codes but not the original input paths. Disclosed; acceptable. Note it rewrites the receipt, so it must not be run over the reviewed immutable file.
