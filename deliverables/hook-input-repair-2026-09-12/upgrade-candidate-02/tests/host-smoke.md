# Actual host smoke procedure

The guarded CLI and hook protocol tests do not establish host interception. Use the current locally inspected Codex version (0.154.0 in this review cycle) with the reviewed plugin installed from the personal marketplace. A new thread must load the reviewed package and use the existing host trust decision. Do not change host internals or infer trust from a file.

1. In a disposable Git repository, register a harmless marker-producing action with genuine test bindings and two retained failures. Use the existing test fixture helpers; do not use a real financial action or wallet.
2. Through the ordinary host shell tool, request that denied action and verify a host hook denial and absence of the marker. Repeat using the host's unified shell call. A direct `hook.py` invocation only checks JSON protocol.
3. Try a permitted read-only command and a source edit that merely mentions the action ID. Both should remain available. Test code-mode composition and delegation separately; record unsupported recognition honestly.
4. Verify SessionStart status and PostToolUse reminders with a clearly test-only outbox in that disposable repo. Do not post a test ID as actual chain evidence. Stop must not initiate a new turn or action.
5. Check all previously retained cache roots still exist with unchanged bytes. Keep the source hash, host version, tool names, observed denial and marker outcomes in a public smoke receipt. Test enable/disable or a changed trust decision only when separately authorized; neither is needed for a routine upgrade smoke.

`doctor` reports `unverified` or `installed-unverified`; it deliberately cannot promote itself to verified interception. Source definitions and cached paths are not evidence that this thread loaded or trusted them. Keep a separate scoped host receipt. If a path is unsupported or trust cannot be established in this session, retain guarded CLI use and state that actual-host coverage remains unverified.

No model client, daemon, wallet, network transaction or host-internals repair is required for this procedure. The separate Moriarty repair pilot remains an acceptance condition.
