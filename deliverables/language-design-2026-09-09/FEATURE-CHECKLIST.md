# Recommended feature checklist

Status: S2 panel recommendation after blind proposals and peer critique. All 20 disposition labels converge; substantive amendments and dissent are recorded in [CONVERGENCE.md](CONVERGENCE.md). Adopt means a recommended design requirement, not implemented behavior, semantic freeze or measured usability. Every test is specified-only. The [matrix](feature-matrix.csv) and [JSON](features.json) give exact constraints, gaps, examples and confidence.

| ID | Position | Feature and user purpose | Minimum distinguishing acceptance test |
|---|---|---|---|
| F01 | adapt | **TypeScript-style external .mori** — Recognize declarations and records | Compare clause meaning and repairs across experience groups; reject host JS expressions |
| F02 | defer | **Inert TypeScript tagged template** — Embed canonical source in TS build without callbacks | Non-executing extraction yields file-equivalent source/Core; reject interpolation even with bypassed TS checking; test backticks/backslashes, raw/cooked bytes, spans and tag substitution. |
| F03 | reject | **Unrestricted TS runtime in contracts** — Keep execution and proving finite | Reject ambient clock/IO and arbitrary callback at source boundary |
| F04 | adopt | **Explicit public financial types** — See asset, amount, share and duty roles | Wrong asset/share payment rejects; valid same-unit payment preserves allocation |
| F05 | adapt | **Local inference with visible inferred types** — Reduce repeated annotations while preserving meaning | Hold public annotations, semantics, tools and training fixed; vary local inference only in the initial pilot; ambiguous inferred units reject. |
| F06 | adopt | **Pure pre-state and staged updates** — Predict all changes before acceptance | Reject pre mutation, every next read, duplicate field writes, early post access and a guard after ensures; failing final postcondition discards state/effects. |
| F07 | adapt | **Closed typed effects separate from authority** — Inspect what an action proposes and permits | Unsupported effect fails effect checking; allowed effect with wrong recipient/excess gross debit fails authority; one original outcome-intent signature suffices for an allowed route under all constraints. |
| F08 | defer | **General resumable effect handlers** — Avoid hidden multiplicity in financial code | Any future handler cannot duplicate nonce, payment or duty; bounded invocation proof |
| F09 | adapt | **Finite event inputs and schedules** — Express delayed financial actions explicitly | Reject stale/duplicate/unauthorized observations under stated policy; overflow/timeout cannot delete duties; scheduled input does not guarantee ledger execution. |
| F10 | reject | **Infinite streams or implicit lifetime reset** — Preserve finite admitted financial work | Accepted consumed work plus all distinct live successors remaining allowance cannot exceed original admitted allowance; split partitions, join cannot renew; recovery reserve is included. |
| F11 | adopt | **Checked domain duties and authorized recovery** — Know what remains owed after progress | Debt100/payment 30 derives transfer 30 and residual 70; reject unauthorized deletion. Authorized forgiveness has a separate recorded rule/effect; fees/accrual/timeout require their own cases and retained history. |
| F12 | adopt | **Checked arithmetic and named rounding** — Understand token/share conversion outcomes | Reject zero divisor, overflow and rounding-policy mismatch; permit payer-favorable rounding when the declared instrument policy requires it; identify changed duties when policy changes. |
| F13 | adapt | **Structured source diagnostics** — Repair underlying financial mistake | Evaluate initial grammar failures and financial errors; measure interpretation, first safe edit, successful repair and recurrence separately; do not suppress duties/claims. |
| F14 | adapt | **Content-addressed typed Core and dependencies** — Identify exact program and dependency closure | Local alpha-rename preserves Core only under its encoding; source changes. Changed nominal binding/dependency changes relevant commitments; ambiguous shortened refs reject before signing. |
| F15 | adopt | **Separate source/build/artifact/claim identities** — Understand what was reviewed, built and proved | Change compiler/profile/verifier/observation/immediate output individually; stale cached evidence cannot admit the new statement; same proof cannot consume an already-spent predecessor. |
| F16 | defer | **Unison-style database as primary editor workflow** — Keep ordinary source review available first | First slice review works with files/diffs; any later database workflow must export complete reviewable artifacts and demonstrate a task benefit. |
| F17 | adopt | **Explicit version and migration review** — Prevent silent reinterpretation of live duties | Alias update leaves prior duties on prior semantics; authorized migration preserves entitlement, consumed nonce/history and work while requalifying correspondence. |
| F18 | adopt | **Separate preparation from proof and settlement** — Distinguish prepared, proved, submitted and accepted results | Well-typed signed proposal with missing proof fails closed; two proposals may prepare but exclusive predecessor can accept at most once; unknown finality remains unknown. |
| F19 | adopt | **Human task evaluation before usability claims** — Verify understandable authoring and repair | Formative partial-payment comprehension/repair first; after stabilization preregister correctness/time/assistance/timeout and open-ended tasks, stratify experience and retain null findings. |
| F20 | adopt | **Profile-specific grammar and correspondence checks** — Keep published syntax and tools consistent | Grammar/lexer/parser/formatter/docs agree; formatter preserves AST, later all-layer financial observations |

Initial path: F01 authoritative external `.mori` with TS-style syntax. F02 static inert integration is deferred with exact non-executing extraction obligations; F03 unrestricted TS execution is rejected. Financial obligations and all ACTUS/DeFi/private-composition targets remain in scope despite deferring general streams, handlers and database editing.

The [complete data-level payment example](PAYMENT-FIXTURE.md) illustrates one domain allocation, automatically derived residual duties, visible authority and bounded work. It is proposed data, not admitted grammar or an executable acceptance result.
