# The ZKIR semantics in K, as built

This page records what the executable K definition of ZKIR v3 under `experiments/zkir-k/` is, how it was checked, and what the checks found. The decisions it implements are on [../zkir-k-semantics-plan.md](../zkir-k-semantics-plan.md); the instruction set, types and VM it formalises are described on [zkir-instruction-set.md](zkir-instruction-set.md), [zkir-type-system.md](zkir-type-system.md) and [zkir-vm-semantics.md](zkir-vm-semantics.md). Everything here was reproduced on 2026-09-05 with K v7.1.337 and the receipts named in each claim; the second half of the day was an eight-reviewer audit (four Claude Fable 5.1 sessions, four GPT-6 Astra sessions through Codex) whose 34 accepted findings are listed in `experiments/zkir-k/review-2026-09-05/CONSOLIDATED.md` and were fixed in the same day's second iteration (CLM-0745; experiments/zkir-k/review-2026-09-05/CONSOLIDATED.md; repository observation; reproduced; high; S1).

## Documentation

The definition is documented end to end in sixteen chapters under `experiments/zkir-k/docs/`, from `01-overview.md` (what the definition is, the map of the directory, the checking pipeline and what a green run establishes) to `15-design-rationale-and-limits.md`, with `16-compilation-target-contract.md` added by the third iteration; the first fifteen every chapter was checked against the K files, the tools and the pinned Rust sources by two independent readers, one as a developer running every command shown and one as a formal methods expert reading every rule described, and revised until no false statement remained (CLM-0752; experiments/zkir-k/docs; repository observation; reproduced; high; S1). Writing the chapters found and fixed four defects: the extension surface inherited the base panic on a non-canonical Bytes32 element where the 2ffe2d1 crate returns an error (K6); the extension `sha512` gate decoded its alignment with the off-circuit decoder instead of the in-circuit one the crate shares with `persistent_hash` and `keccak256`; two overlapping `#eqSupported` rules for `test_eq` between byte strings gave order-dependent messages; and `zkir_kast.py check --ext` could not run because `ZKIR-CHECK` did not import the extension syntax; the runner also gained `--gen` and `--depth` (CLM-0753; experiments/zkir-k/docs-surge-2026-09-05/MAINTAINER-NOTES.md; repository observation; reproduced; high; S1). After these changes every check layer was rerun: 43 of 43 unit checks, 18 of 18 known answers, 63 of 63 corpus programs, 20 of 20 divergence cases, 358 of 358 base comparisons and 418 of 418 extension comparisons (CLM-0754; evidence/zkir-k-differential-92e8bdd3-2026-09-05c.txt and evidence/zkir-k-differential-ext-2ffe2d1-2026-09-05c.txt; executed test; reproduced; high; S1). The prose of every chapter then had an editorial pass (a structural edit naming its failure patterns, a cadence revision measured by a displacement check over ten habits, and a machine-tell audit), followed by an independent comparison of each edited chapter against its original that found no changed fact, number, symbol, path, command or claim; across the set, semicolons fell by 29 percent, expletive openers by 77 percent and very short sentences by 23 percent with no habit rising (CLM-0757; experiments/zkir-k/docs-surge-2026-09-05/prose; executed test; reproduced; high; S1).

## Layout

The definition is one K definition split into modules, each with the Rust file it follows in its header (CLM-0731; experiments/zkir-k/semantics; repository observation; reproduced; high; S1):

| Module | File | Follows | Content |
|---|---|---|---|
| `ZKIR-SYNTAX`, `ZKIR-WF` | `zkir-syntax.k` | `ir.rs`, `ir_types.rs` | 34 instructions, 13 types, operands, guards, alignments; `reads`, `writes`, `encodedLen`; static well-formedness |
| `ZKIR-FIELD` | `zkir-field.k` | `transient-crypto/src/curve.rs`, midnight-curves 0.3.1 | eight moduli, modular arithmetic on K `Int`, Tonelli-Shanks square roots |
| `ZKIR-CURVES` | `zkir-curves.k` | midnight-curves 0.3.1, midnight-circuits 7.2.4 `ecc/curves.rs` | affine twisted-Edwards (Jubjub, Curve25519) and Weierstrass (secp256k1, secp256r1) arithmetic, subgroup tests, Jubjub decompression |
| `ZKIR-VALUES` | `zkir-values.k` | `ir_instructions/encode.rs`, midnight-circuits `Instantiable` | the 13 value constructors, `encode_offcircuit`, `from_public_input`, input decoding |
| `ZKIR-CONSTANTS` | `zkir-constants.k` (generated) | midnight-circuits `hash/poseidon/constants/blstrs.rs`, `ecc/hash_to_curve/mtc_params.rs` | 204 Poseidon round constants, the MDS matrix, the Shallue-van de Woestijne parameters |
| `ZKIR-HASH` | `zkir-hash.k` | midnight-circuits `poseidon_cpu.rs`, `htc_gadget.rs`, `mtc_cpu.rs`; FIPS 180-4; Keccak | Poseidon sponge (fixed and variable length), hash-to-curve, SHA-256, Keccak-256 |
| `ZKIR-OPS` | `zkir-ops.k` | `ir_instructions/*.rs` off-circuit halves, `transient-crypto/src/{fab,repr}.rs` | one function per `*_offcircuit`, boolean and bit-bound resolution, aligned byte layout for the standard hashes |
| `ZKIR-VM` | `zkir-vm.k` | `ir_vm.rs` `preprocess` | the configuration, sequencing, one witness rule per instruction, constraint emission, transcript and commitment checks, generation mode |
| `ZKIR-CONSTRAINTS` | `zkir-constraints.k` | `ir_vm.rs` `circuit`, `ir_instructions/*.rs` in-circuit halves, `used_chips` | the in-circuit relation of each gate, evaluated on the final witness |
| `ZKIR-EXT` | `zkir-ext.k`, `zkir-sha512-constants.k` | `midnight-zkir` 2ffe2d1 `zkir/src/` | Bool, Byte, Bytes<n>; and, or, xor, concat, slice, nth, reverse, load_constant, sha512 |
| `ZKIR-STATIC` | `zkir-static.k` | `ir_vm.rs` `used_chips`, the `*_incircuit` type arms | the chip set and the forward static type environment the contract decides on |
| `ZKIR-CONTRACT`, `ZKIR-CONTRACT-MAIN` | `zkir-contract.k`, `zkir-contract-main.k` | `Relation::circuit`, `keygen_vk`, the chip accessors and width assertions of midnight-circuits 7.2.4 | the target contract `targetContract(P)`, twenty-three stage-tagged obligations (third iteration) |
| `ZKIR-SYMBOLIC` | `zkir-symbolic.k` | none | the Haskell-backend main module with uninterpreted hashes and `modInt` lemmas for the claims (third iteration) |

Programs enter through `tools/zkir_kast.py`, which reads the JSON artifact and builds the `Program` term with pyk, following the serde layer of `ir.rs`: variables start with `%`, immediates are little-endian hex with an even number of hex digits and a value below r, an absent or null `guard` is no guard, unknown object members are ignored, `version` components are `u8`, the three collections must be arrays, and in the extension `Bytes<n>` takes canonical ASCII digits; the review found seven deviations from this list in the first version, all corrected, and the harness now checks that every program the script rejects is also rejected by the crate's `IrSource::load` (CLM-0732; experiments/zkir-k/tools/zkir_kast.py and experiments/zkir-k/tools/diff_test.py; repository observation; reproduced; high; S1). A run is `job(Program, Preimage)` or `checkedJob(Program, Preimage)`; the preimage mirrors `ProofPreimage` (raw inputs, binding input, optional commitment and opening, private transcript, public transcript inputs and outputs) and every integer in it must be a canonical field element, which both the Python builder and the K decoder enforce (CLM-0732).

## What a run produces

The configuration carries the seven components of the VM page as cells (`<mem>`, `<pi>`, `<skips>`, `<pubInIdx>`, `<pubOutIdx>`, `<privIdx>`, `<outputs>`) plus `<constraints>`, `<piIdx>`, `<status>`, `<chips>` and `<verdicts>` (CLM-0733; experiments/zkir-k/semantics/zkir-vm.k; repository observation; reproduced; high; S1). `job` runs any program `IrSource::load` accepts exactly as `preprocess` does, including its run-time checks (output arity, `div_mod_power_of_two` arity and bit count, `reconstitute_field` bit count) and its register semantics, in which a later write overwrites an earlier one; `checkedJob` first evaluates the static check of `ZKIR-WF` (single assignment, definition before use, immediate range, arities, bit bounds) and reports a failure as the run's error, so it accepts strictly fewer programs than the crate (CLM-0733). Each instruction first appends its gate to `<constraints>` and then runs its witness half; operands are resolved and converted one at a time in the order `preprocess` uses, inputs are bound as they are decoded, and impact values are pushed one at a time, so the first failing operand determines the error and the cells hold the same prefix `preprocess` would have built (CLM-0733). The status after the first failure is `error(msg)` where the crate returns an error and `panic(msg)` where it aborts (a transcript read past the end, a Bytes32 raw element outside the canonical form); the witness cells freeze, but every later instruction still emits its gate, and the public-input positions in those gates come from `<piIdx>`, which advances at emission time (CLM-0733). At the end the transcripts must be fully consumed and, under the commitment flag, the commitment must equal the Poseidon commitment of the raw inputs and the encoded outputs, exactly as in `preprocess`; then every gate is evaluated against the witness (CLM-0733).

Gates are instruction-level relations, not PLONKish gate rows: `gate(add(a, b, o))` states that register `o` equals the sum of `a` and `b` under the type dispatch of `add_incircuit`; `gate(assert(c))` states `c` is non-zero; `guardGate(g)` states that an impact's guard is boolean, also for an empty impact; `piGate(i, g, x)` states that public input `i` equals `x` when `g` is 1 and 0 otherwise; `bindGate(0)` pins the binding input; `commGate(1, inputs, rand)` states that public input 1 equals the Poseidon hash of the opening, the re-encoded input registers and the encoded outputs, which is the circuit's commitment and differs from the witness-side commitment over the raw input stream exactly when an input encoding is not canonical; `outputGate(vals, types)` checks the output arity and every position's runtime type (CLM-0734; experiments/zkir-k/semantics/zkir-constraints.k; repository observation; reproduced; high; S1). A verdict is one of `holds`, `violated` (the circuit exists and rejects the witness, as for `inv` of zero or a Jubjub `from_coordinates` whose exact coordinates are not on the curve), `synthErr` (the circuit cannot be built: a missing in-circuit dispatch arm, a chip that `used_chips` did not initialise, a `less_than` bound padded above 253 or a `constrain_bits` width above 255, an option alignment in a hash), `unknown` (the witness stopped before a register or public input existed) or `unsupported` (no relation modelled) (CLM-0734).

What this abstraction does not model must be stated: the circuit's auxiliary witness cells and copy wiring, the assignment constraints of each type (byte range checks, on-curve and cofactor constraints, foreign limb ranges), the fact that an assigned JubjubScalar is not proven canonical by assignment alone, hash gadget internals, and the prover-side panics of chip hints; a run therefore establishes that the honest witness satisfies the instruction-level relations, and never that no other witness does or that a hash gadget is fully constrained (CLM-0734). The third iteration turned that list into the residuals of two explicit claims. The modelled witness space `witnessSpace(verdicts, mem)` holds when every verdict is `holds` or the added outcome `unconstrained` and every register satisfies the semantic invariant `wellTypedValue` of its type (a native element below r, a Jubjub scalar below rJ, a 32-byte string, a point on its curve and in its subgroup, a foreign element below its modulus; `unit_values.py` checks that the predicate is false on `native(r)`, `jubjubPoint(pt(0, 0))`, a three-byte `bytes32` and `secp256k1Base(p)`); typing discharges the per-type assignment constraints under one assumption stated per chip, that the circuit constrains each assigned cell to its type (the byte range of `native_gadget.rs`, the cofactor clearing of `edwards_chip.rs`, the limb ranges of `field_chip.rs`). The projection from circuit cells to registers is stated in the header of `zkir-constraints.k`: a named register is the value of the cell the crate's `mem_insert` (or, for declared inputs and the four base byte instructions with the extension `reverse`, `memory.insert`, where the modelled register is the recomputed cell) binds, auxiliary cells (decomposition witnesses, limbs, lookup rows, gadget rows, hash padding cells) are existentially quantified, and copy wiring is value equality. `unconstrained` is a gate-level marker, that the gate pins the register to its type only, emitted on the JubjubScalar and foreign-typed input gates and on a `public_input` or `private_input` whose guard is 0; the transcript input gates pin the cell to its type only for every guard, whether the cell is free in the circuit is decided by its consumers, and the public transcript is bound by the ledger's re-execution and the private transcript by nobody, a residual of the observation rather than of the claims (CLM-0765; experiments/zkir-k/semantics/zkir-constraints.k and experiments/zkir-k/docs/08-constraints-and-verdicts.md; repository observation; reproduced; high; S1).

The two claims relate `Acc(P, pi)`, the cell assignments the circuit accepts with the instance `pi`, and `Mod(P, pi)`, the memories in the modelled witness space, through the projection `proj` to the named registers. (a) Soundness direction: every cell assignment the circuit of P accepts with the instance pi projects to a memory of the modelled witness space, proj(Acc(P, pi)) ⊆ Mod(P, pi), up to three residual items: JubjubScalar canonicity, foreign limb canonicity and the per-chip typing assumption. This is the claim a compiler proof uses, and its evidence is that no `violated` or `synthErr` verdict occurs on any circuit-accepted witness of the differential receipts. (b) Tightness: every memory of the space extends to an accepted cell assignment, `Mod(P, pi) ⊆ proj(Acc(P, pi))`, up to four residual items on its own side: auxiliary cells, prover-side panics, hash gadget internals and copy wiring; this is what the injection columns test (`inject-unconstrained` expects `accepted`, a `violated` verdict expects the cell the comparison table assigns). The earlier single statement, "any memory in the space is accepted up to six residual items", mixed the two directions and listed the residuals of one against the other; the definition header, chapter 08, chapter 16, the iteration plan and CLM-0763 now quote claim (a) in the same words (CLM-0766; experiments/zkir-k/semantics/zkir-constraints.k, experiments/zkir-k/docs/08-constraints-and-verdicts.md, experiments/zkir-k/docs/16-compilation-target-contract.md and experiments/zkir-k/plan-iter3/PLAN.md; repository observation; reproduced; high; S1). Both claims are tested rather than proved: the circuit oracle accepts an arbitrary value injected into the unconstrained register `%color.11` of swap `expire.zkir`, accepts an injection into a guard-0 transcript register without a consumer and rejects one with an `impact` consumer, every successful corpus run on both surfaces is in the space with no comparison outside the table, and every divergence case, including the injected cases (a hash input above its alignment atom, `inv` of zero, the two conversions of `bytes32_from_low_high`, `less_than` above the padded bound), matches (CLM-0767; evidence/zkir-k-circuit-differential-92e8bdd3-2026-09-06d.txt, evidence/zkir-k-circuit-differential-ext-2ffe2d1-2026-09-06d.txt and evidence/zkir-k-divergence-tests-2026-09-06d.txt; executed test; reproduced; high; S1).

## How it was checked

Four layers, each with its receipt:

1. Unit checks against an independent Python implementation of the same formulas (`tools/unit_values.py`): field inverses and square roots, the non-residuosity of both Edwards `d` constants, the Jubjub subgroup generator as eight times the curve generator, scalar multiples on all four curves, the order of each generator, encode and decode round trips for every type, the parity-only behaviour of Jubjub decompression, the field range of native inputs and the Bytes32 decoder panic; 43 of 43 pass (CLM-0726; the 43rd check, added on 2026-09-05, covers the strict Bytes32 decoding of K6).
2. Known-answer checks against the Rust crate for the hashes (`tools/unit_hash.py`): Poseidon on zero to three inputs, hash-to-curve on zero to three inputs, SHA-256 and Keccak-256 through one-, 32- and 232-byte aligned preimages, and the aligned byte layout; 18 of 18 pass (CLM-0726). Two reviewers extended these in memory to lengths 0 to 16 for Poseidon and to block boundaries for the byte hashes without finding a difference; the crate's Poseidon batches three partial rounds per step, which is an algebraic rewrite of the plain round function used here.
3. Differential runs against the crate's own `preprocess` (`tools/diff_test.py`) through `zkir-oracle`, a harness that also prints each register's type. For each program the harness draws typed raw inputs (seeded with the crate's own literal test inputs where a test gives them), runs the definition in generation mode until the transcript needs are stable, then runs the raw entry point and the oracle on the same preimage and compares the status, the error class when both fail (the messages are mapped to twenty classes such as variable not found, type conversion, bit bound, transcript short, commitment, panic), and on success every register's type and encoding, the public-input vector and the skip vector. After a success it also compares a raw perturbation, a typed perturbation of a random input, a wrong public transcript input and a wrong commitment. Successful-run agreements and error-run agreements are counted separately, and a run whose configuration is stuck or depth-exhausted is a failure. At 92e8bdd3 the corrected definition gives 358 comparisons that all agree: 46 successful runs (30 raw and 30 typed perturbations, 5 wrong public transcript inputs and 6 wrong commitments among the rest), 309 error-run agreements on status and error class, and no successful run with a non-holding gate (CLM-0728; evidence/zkir-k-differential-92e8bdd3-2026-09-05c.txt; executed test; reproduced; high; S1).
4. The divergence cases (`tools/divergence_tests.py`): twenty programs with preimages for the review's findings and the findings of this work, each checked for the off-circuit status on both sides, the memory on success, and the outcome of one exactly selected gate (CLM-0730).

The corpus is the 43 inline programs of the crate's tests at 92e8bdd3 (thirteen seeded with their literal inputs; the earlier count of 28 came from a regular expression that matched the suffix of `public_transcript_inputs`), the six version-3 micro-dao precompiles of midnight-zkir 2ffe2d1, the seven Moriarty escrow and swap artifacts, nine handmade programs that exercise each instruction on the types it supports, and seven handmade negatives for the static checks (CLM-0724, CLM-0728). With one exception, the escrow, swap and micro-dao programs never reach a successful witness with generated inputs, because their assertions need a consistent transaction context; the exception is the swap `expire.zkir` program, whose second attempt succeeds on both sides, and for the rest the harness compares error classes only (CLM-0728).

## What the checks found

- The arc-zkir divergence review retires its findings 1, 2 and 4 and classes 3 and 12 as non-defects; the K cases reproduce the current form of each: `assert` of 2 fails off-circuit while its gate holds, `cond_select` on Bytes32 and `constrain_eq` on JubjubScalar succeed off-circuit while their gates are synthesis errors, `bytes32_from_low_high` with a foreign `high` succeeds off-circuit while its gate is a synthesis error, `less_than` with a 3-bit bound rejects 8 off-circuit while the padded gate would accept it, a program touching secp256k1 only through `from_bytes32` succeeds off-circuit while its gate reports the chip uninitialised, the order-2 Curve25519 point is rejected on both sides, a non-canonical secp256k1 input passes `preprocess` while the commitment gate is violated because the circuit re-encodes the input canonically (CLM-0730).
- Five findings of this work, none in the review: K1, Jubjub `from_coordinates` off-circuit goes through point decompression and uses only the parity of `x` (the Agda trust base assumes the exact coordinates); K2, a transcript read past the end panics the crate; K3, a Bytes32 raw element outside the canonical form panics the decoder; K4, `jubjub_scalar_from_native` and native `from_coordinates` need the Jubjub chip that `used_chips` does not enable for them, so keygen would panic (the review's finding 13 calls `from_bytes32` the only such entry); K5, `less_than` with 253 or 254 bits is accepted by `preprocess` but its padded bound exceeds the chip's limit of 253 (CLM-0735; evidence/zkir-k-divergence-tests-2026-09-05c.txt; executed test; reproduced; high; S1). All are recorded in [../contradictions.md](../contradictions.md), together with K6, found while documenting the definition: the K3 element is an assertion panic at 92e8bdd3 but an ordinary decode error at 2ffe2d1, and the extension definition inherited the panic until `#canonical` was corrected to return `decErr` under strict decoding, verified against the 2ffe2d1 oracle (CLM-0750; evidence/zkir-k-unit-values-2026-09-05c.txt; executed test; reproduced; high; S1).
- The Rust `preprocess` does not enforce single assignment and neither does `job`; `checkedJob` and `ZKIR-WF` do, and the gate evaluation over the final memory is meaningful only for programs that pass that check (CLM-0725).
- The newer crate at 2ffe2d1 differs from 92e8bdd3 in two more ways than its added instructions: every decoded value is re-encoded and rejected if the encoding was not canonical, which closes K1 for inputs, and `test_eq` on byte strings of unequal lengths returns false off-circuit while the circuit requires equal lengths (CLM-0737).

## The extension surface

`ZKIR-EXT` is a second main module on the same definition for the standalone `midnight-zkir` crate at 2ffe2d1: the types Bool, Byte and Bytes<n> (Bytes<32> keeps the base representation so every base rule applies), the instructions `and`, `or`, `xor` over Bool, `concat` (bounded by 2^24 bytes), `slice`, `nth`, `reverse` over byte strings, `load_constant` from a typed raw encoding (its gate checks the constant's chip), `sha512`, logical `neg` on Bool, `test_eq` over Bool, Byte and byte strings, and the canonical-form check that 2ffe2d1's decoder performs; `reverse_bytes` is rejected at the preprocessor as the crate removed it (CLM-0739; experiments/zkir-k/semantics/zkir-ext.k; repository observation; reproduced; high; S1). It is checked against a second `zkir-oracle` built from that crate over its 61 inline test programs, the six micro-dao precompiles and the handmade programs: 418 comparisons that all agree, 50 successful runs, 364 error-run agreements on status and error class, no non-holding gate (CLM-0737; evidence/zkir-k-differential-ext-2ffe2d1-2026-09-05c.txt; executed test; reproduced; high; S1).

## The other oracles

The arc-zkir v3 Agda development type-checks in full with its own Nix toolchain, fifteen modules under `--safe` (CLM-0736; evidence/arc-zkir-agda-typecheck-2026-09-05.txt; executed test; reproduced; high; S1). It cannot execute programs: it is parametric over an `Assumptions` record that supplies the field, curve and hash primitives, and the repository has no concrete instance of that record, so oracle 3 of the plan remains a correspondence by reading, not by running (CLM-0736; repos/input-output-hk/arc-zkir/src/zkir-v3/Assumptions.agda; repository observation; reproduced; high; S4).

Midnight's `k-rust` (0.4.0, built from the pinned checkout) runs the K tutorial lesson in three seconds and parses terms of `ZKIR-SYNTAX` in under four, but neither `krust krun` on a one-instruction program nor `krust kcompile` of the full definition finished: the compile was killed after 25 minutes of CPU with no output, where canonical K compiles the same definition in twenty seconds (CLM-0740; evidence/k-rust-compatibility-2026-09-05.txt; executed test; reproduced; high; S1). Whether the cause is the frontend's performance on a definition of this size or an unsupported construct is not established, since the compile produced no diagnostic; running the semantics inside the Midnight TypeScript tooling stays a goal, as the plan said, not a gate (CLM-0740).

Under the Haskell backend, one reviewer of the second iteration proved a fully pinned claim about `add` in ten seconds, while a claim about `transient_hash` did not terminate because Poseidon and `modInt` unfold symbolically; the plan's uninterpreted-hash treatment was implemented in the third iteration's M3 (CLM-0746, revised 2026-09-06; experiments/zkir-k/review-2026-09-05/reports/fable-R4.md and experiments/zkir-k/semantics/zkir-symbolic.k; executed test; reproduced; high; S1).

## The symbolic backend

`zkir-symbolic.k` (module `ZKIR-SYMBOLIC`) is a main module for the Haskell backend over `ZKIR-VM`: the defining rules of the hashes, of their helpers and of scalar multiplication carry `[concrete]`, so on a symbolic argument a hash stays an uninterpreted application whose only properties are its sort, totality, functionality and the range of a digest, while `transientCommit` is a plain alias of `poseidonHash` so that the witness-side commitment check and the commitment gate meet on one term; `modInt` reduction and range lemmas let a claim state field results in reduced form and discharge the typing of every native register (CLM-0768; experiments/zkir-k/semantics/zkir-symbolic.k, experiments/zkir-k/semantics/zkir-hash.k and experiments/zkir-k/claims/README.md; repository observation; reproduced; high; S1). The claim set under `experiments/zkir-k/claims/` is fourteen modules run by `tools/run_claims.py`: the eleven verdict claims of the native arithmetic and control instructions and of `transient_hash`, each pinning every cell including the observable result `obs(status, encoded outputs, public inputs, skips)` and the witness space, with `constrain_to_boolean` stated over both boolean values as two claims in one module and `assert` on a value in `[2, r)` stated as a run that `preprocess` rejects while the gate holds; the commitment claim, a `copy` under `do_communications_commitment` with the verdicts pinned, the shape of every Moriarty artifact; and the observable instance of the compiler-obligation template `spec_compiled_observable`, which pins the `<observable>` cell and, with its `witness_space` parameter, the witness space. Every module proves and every vacuity probe, the same claim with `ensures false`, is refuted (CLM-0769; evidence/zkir-k-claims-2026-09-06d.txt and experiments/zkir-k/claims/README.md; executed test; reproduced; high; S1).

## Third iteration

The third iteration made the definition a compilation target with a checked circuit side, a target contract and a symbolic backend; its plan and milestones are on [../zkir-k-semantics-plan.md](../zkir-k-semantics-plan.md), and every result below is reproduced by a receipt with the suffix `2026-09-06d` or, for the layers rerun after the closing pass, `2026-09-06e` (`make -C experiments/zkir-k <target> SUFFIX=e`, chapter 11).

`zkir-circuit-oracle` (`experiments/zkir-k/tools/circuit-oracle/`, one source built in both pinned workspaces) runs `preprocess`, builds the stdlib's `MidnightCircuit` with the known instance and witness, and runs the halo2 `MockProver`, reporting one of six outcomes by where the run stops (preprocess-error, witness-consistency-error, synthesis-error, constraint-failure, panic, accepted) plus the harness outcome instance-length-mismatch; `--inject` perturbs Native registers of the preprocessed memory, `--instance` the instance column. K's verdict rows and the oracle's outcomes are related by the comparison table `experiments/zkir-k/plan-iter3/circuit-comparison-table.md`, written before the first run, whose every cell is an expected agreement or a named difference D1 to D10, and `tools/diff_test.py --circuit` lands every comparison in a cell or reports it as a blocking finding: 506 comparisons on the base surface and 531 on the extension surface, all in their expected cell, none outside the table and none not comparable, over the honest and perturbed preimages, the injections of a Native input, a computed register, a bypass-arm register, a guard-1 transcript register and an unconstrained register, each with a boundary value chosen by its first consumer, and the instance perturbation (CLM-0771; evidence/zkir-k-circuit-differential-92e8bdd3-2026-09-06d.txt and evidence/zkir-k-circuit-differential-ext-2ffe2d1-2026-09-06d.txt; executed test; reproduced; high; S1).

The modelled witness space `witnessSpace(verdicts, mem)` and the inclusion statement are stated in the header of `zkir-constraints.k` and chapter 08 and detailed above (CLM-0765, CLM-0766, CLM-0767): every verdict `holds` or `unconstrained` and every register well typed; the soundness direction, proj(Acc(P, pi)) ⊆ Mod(P, pi) up to JubjubScalar canonicity, foreign limb canonicity and the per-chip typing assumption, is the claim a compiler proof uses, and the tightness direction, Mod(P, pi) ⊆ proj(Acc(P, pi)) up to auxiliary cells, prover-side panics, hash gadget internals and copy wiring, is what the injection columns test. Both are tested and not proved: no `violated` or `synthErr` verdict occurs on a circuit-accepted witness in either circuit receipt, every successful run of the differential receipts is in the space (41 of 41 base, 40 of 40 extension, 375 and 428 comparisons agreeing), and the two canonicity residuals have no injection column because the typed `IrValue` interface cannot carry a non-canonical representative (CLM-0772; experiments/zkir-k/semantics/zkir-constraints.k, evidence/zkir-k-differential-92e8bdd3-2026-09-06d.txt and evidence/zkir-k-differential-ext-2ffe2d1-2026-09-06d.txt; executed test; reproduced; high; S1).

The target contract `targetContract(P)` (`zkir-contract.k`, module `ZKIR-CONTRACT`, extension arms in `ZKIR-EXT-CONTRACT`, chapter 16) has three tiers: twenty-three program-only obligations, each tagged with the stage of the crate that rejects a failing program without a witness (`keygen`, `preprocess`, `both`, `static` for the K-only layer, `none` for an info fact), the preimage-dependent tier (the `job` run succeeds and its memory is in the witness space) and the circuit tier (the oracle accepts), with the observable semantics `[[P]](pre) = obs(status, encoded outputs, public inputs, skips)` as one function over the configuration and the `ledger.commitment` fact beside them; `tools/contract_corpus.py` runs it over 163 corpus programs, 125 with every obligation met or not applicable, 30 with an expected failed obligation and 8 the preprocessor rejects, and over the seven Moriarty contexts, each with every tier met (CLM-0773; experiments/zkir-k/semantics/zkir-contract.k and evidence/zkir-k-contract-corpus-2026-09-06e.txt; executed test; reproduced; high; S1). The provability sweep `tools/provability.py` keys every parseable corpus program with `keygen_vk` and `keygen` on the official Midnight KZG parameters (`bls_midnight_2p{k}`, k = 0 to 17, fetched from srs.midnight.network and verified against the digests of base-crypto's `data_provider.rs`) and checks the outcome against the stage tags in both directions: 162 programs keyed, 137 accepted and 25 rejected, in the classes 125 clean, 2 keyed despite a preprocess-stage failure, 3 keyed despite a static failure and 25 must-reject, each rejection on the check its failed obligation names, 23 of 23 negative controls and 4 of 4 keyed-despite controls as predicted, 13 proofs produced with `Zkir::prove` and verified with `VerifierKey::verify` (the seven contexts and six spike preimages), 0 contradictions. The sweep's first stage-aware run found three contradictions, an undefined operand, a one-output `div_mod_power_of_two` and a 256-bit `reconstitute_field` that the tags let key and keygen rejects, closed by the both-stage obligations `circuit.static.defined`, `circuit.static.div_mod_outputs` and `width.reconstitute_field.assertion` (the last replacing `width.reconstitute_field.nonzero`, since the same assertion fails at 0 bits and from 255 bits up while 249 to 254 key). A verified proof here is not ledger acceptance: the statement verified is the `pis` vector `prove` returns, not the ledger's four-part statement, the ledger pushes the commitment unconditionally, and the verifier key is regenerated rather than compared with a deployed key (CLM-0774; evidence/zkir-k-provability-2026-09-06e.txt and evidence/zkir-k-provability-2026-09-06d.txt; executed test; reproduced; high; S1).

The symbolic backend is `zkir-symbolic.k` on the Haskell backend, with the hashes uninterpreted by `[concrete]` defining rules and `modInt` lemmas (CLM-0768): the fourteen claim modules under `experiments/zkir-k/claims/`, the native arithmetic and control instructions, `transient_hash`, the commitment claim and the observable instance of the compiler-obligation template `spec_compiled_observable`, prove in ten to twelve seconds each and every vacuity probe is refuted (CLM-0775; evidence/zkir-k-claims-2026-09-06d.txt; executed test; reproduced; high; S1). The seven real transaction contexts of the Moriarty escrow and swap artifacts were produced by driving the compiled contracts through `@midnight-ntwrk/compact-runtime` 0.19.100 (`tools/moriarty_preimages.mjs`, decoded by the `preimage-json` crate built in the ledger workspace; binding input 0 and commitment randomness 0 by construction): on both surfaces every honest row is ok on K and on `preprocess`, agrees on registers, public inputs and skips, and is accepted by the circuit (14 rows), every negative row, a wrong phase or a wrong witness, fails the contract's own assertion off-circuit on both sides (24 rows), and every artifact keys, proves and verifies (CLM-0776; evidence/zkir-k-moriarty-contexts-2026-09-06d.txt and evidence/zkir-k-provability-2026-09-06e.txt; executed test; reproduced; high; S1).

Two findings were added to [../contradictions.md](../contradictions.md): K7, `load_constant` of a Jubjub value on the extension surface with no Jubjub input passes `preprocess` while `used_chips` leaves the Jubjub chip disabled and keygen panics (case `k08`, the `chips.gating` obligation), and K8, `reconstitute_field` with 0 bits, which `preprocess` rejects on every value and keygen rejects by the `assert!(bit_length < F::NUM_BITS)` of the decomposition chip rather than by an error, the same assertion that fails from 255 bits up (`handmade-negative/reconstitute_bits_0.zkir`, case `f10`); the divergence suite grew from twenty to thirty-one cases, nine of them injected perturbations checked against the comparison table, and all behave as expected with their circuit outcome recorded (CLM-0777; evidence/zkir-k-divergence-tests-2026-09-06e.txt and experiments/zkir-k/plan-iter3/upstream-issues; executed test; reproduced; high; S1).
