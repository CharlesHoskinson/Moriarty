## Source findings that change the plan

**1. The production executable is `crates/mori/src/main.rs`.** It parses Clap commands and dispatches through `commands/mod.rs`; there is no inspected `mori-cli` crate. `commands/check.rs` has distinct routes: a `language` token selects Rust Core `/1` or `/2`; other authoring syntax goes through `mori_parser` and `mori_checker`. Check success in that alternate route does not establish compilation, since `commands/compile.rs` takes Core source. The public journey needs executable and profile identity at each boundary.

**2. Rust Core production support is broader than the stateless Sherlock adapter.** `mori-core/src/ir.rs` exports UInt128 and Bool, states, named assets with network/issuer/reference/scale, finite actions, lets, requires/ensures, updates, emits, transfers, fees, liabilities and discharge. Arithmetic is checked add/subtract/multiply plus comparisons and Boolean operators; no general division, source functions, branches, recursive calls or collection expressions appear in this Core enum/parser. `runtime.rs` evaluates both binary operands eagerly. A `next` update changes the current environment immediately; `ensures` checks where it occurs. Full discharge leaves a present-zero liability row. Refusal returns no committed local execution, but that local atomicity is not a ledger phase guarantee. These are concrete `/1` semantic contracts, not the successor's proposed immutable-pre/single-next/trailing-post contract.

**3. `compile_reported` is a wrapper, not a Sherlock compiler.** `commands/compile.rs` parses the program and supplied Target, then calls `mori_backend::source_projection::compile_reported`. That function first calls existing `compile` or `compile_signed`, selected by the Target, and subsequently generates optional projection metadata. `mori-core/src/sherlock/source_adapter.rs` admits only stateless `/1` actions consisting of ordered lets and one final emit value. States/assets, financial effects and other constructs become per-action `Unsupported` projection metadata. Occurrence/path budget exhaustion likewise withholds metadata without changing a successfully compiled artifact. The emit effect remains owned by Core. Metadata labels explicitly say source-static, no evaluation, and no source-function/branch/recursion/data support. Calling this restriction the whole public compiler's production subset would be wrong.

**4. The existing backend emits real source-derived ZKIR descriptions, with open execution gates.** `mori-backend/src/lib.rs` validates exact ledger-9/ZKIR 3.0.0-rc.2 pins, source/Core and asset-network agreement; selects signed or unsigned admission; builds a liability registry; lowers each action; and emits artifact/ABI/relation `/3`. Its ABI contains state/effect/balance/duty fields, and its resources retain unmeasured circuit degrees/cost. The manifest explicitly marks native proving, measured costs, authenticated ledger-frame/phase correspondence, signed intent/history verification and deployment unperformed. Source emission is not proof or target acceptance. This review inspected compilation orchestration and types, not every arithmetic constraint in the large lowerer.

**5. Native-call compilation is a second statement with a narrower domain.** `commands/compile_call.rs` calls `mori_ledger::relation::compile` for a selected action or `static_compile` for all-action exports/reopening. `relation/compiler.rs` emits source-derived operation constraints against `layout`/`StaticBindings`; it does not consume the `/3` transition artifact produced by `mori compile`. `layout::admit_bindings_inner` requires the pinned Toolchain/Limits, ledger ABI, nonempty network and anchor `local-unqualified`. Ordinary installed/native admission requires transfers/fees from the declared public payer. The separate mapped-role static route relaxes source role mapping but declares `source-static-mapped-roles-unproven-uninstalled-unauthenticated`. Its success must not be promoted into native custody support. The relation manifest itself lists unresolved predecessor/deployment, ownership, global prefix/custody, intention/history and settlement predicates.

**6. Preparation and proving have concrete APIs, but the public journey still ends before qualified submission.** `prepare_call.rs` can load/admit a source relation and call `prepare_native_call_checked`; `prepare.rs` constructs native calls/transcripts and prospective financial readback. Its preserved frame says `unchanged-supplied-ledger-not-an-applied-successor`. The readback distinguishes prospective balances, semantic/charged successors, events, gas, retained UTXOs, effect outputs and reconstruction after final intent. Prove/verify/keygen command families are registered. The inspected command dispatcher exposes no general deploy/submit/finality command. Native-call module documentation explicitly excludes funding, ledger apply and network I/O. Individual proving implementations were inventoried by symbols, not fully audited or executed.

**7. `/2` continuations are implemented source paths with separate limits.** `mori-core/src/stage` exports load/start/resume, plans, typed captures and local continuations; labels state `local-reference-stage`, authentication `none`, consumption `untracked`. `commands/compile.rs` routes `/2` to `stage::compile_staged`. This unsigned path uses the ordinary lowerer to emit N+1 successful-segment circuits for N awaits as distinct `/4` artifacts. Signed targets are explicitly refused. No conversion to `/3` makes them consumable by its proving/native APIs. `mori-ledger` requires `/1`. Therefore a source-static continuation circuit is neither a signed staged transaction nor implemented target recovery.

**8. Rich Sherlock source and circuit fragments are not a general production path.** `mori-core/src/lib.rs` places draft source parsing, typing and image bridging behind `cfg(test)`; `sherlock/mod.rs` likewise gates program images, image evaluation, helpers, machine images and layout preparation. Draft typing includes functions, branches, lists/trees and calls, but says source-only/unrun and is not admission policy. Public Sherlock host reference types are a separate `sherlock-k-a/1` reference profile. `mori-backend/src/sherlock_machine/mod.rs` exports source-only fetch/literal instruction constructors with caller obligations; its header expressly disclaims loading/checking/evaluating/compiling/proving those fragments. There is no inspected source→full Sherlock machine→complete financial ZKIR→Midnight consumer chain. A102/literal/auxiliary work can help a later compiler; it cannot be substituted for it.

**9. Node beta is useful but semantically separate.** `packages/moriarty-beta/src/bridge.ts` imports Source/6 lowering and experimental Core/5 preparation. It returns local-stipulation-only outcomes, including `PreparedUnqualified` and explicit unsupported recognized profiles. It does not call the Rust compiler. Its native signature precursor does not by itself establish source/target correspondence. Rust `lsp.rs` and `mcp.rs` still contain `todo!`. A future frontend/editor owner should either target the adopted public compiler through a justified embedding or label the distinct beta profile; do not imply automatic cross-profile support.

## Shortest delivery shape

Use the existing public Rust command and library paths as the integration spine. Do not create another application-specific compiler, run controller or acceptance schema. One integrator owns changes to Core IR, ABI, statement/result types and profile selection. Independent authors can own language specification/frontend, ordinary semantic oracles, ledger adapter, financial libraries, developer tools, and Sherlock internals on disjoint paths.

Do not require an unimplemented universal interpreter to demonstrate a useful current Core financial stage. Conversely, do not declare the existing UInt/Bool straight-line Core to be the complete language. Rich typed financial values, bounded collections/functions where adopted, conditional lifecycles, full libraries, history/privacy, optional federation and independent release remain required. Register any semantic extension as an explicit profile with its own admission and correspondence; never silently reinterpret `/1` `next`/`ensures` or substitute evaluator host work for circuit constraints.

The proposed sprint names below are capability groupings under U0–U7 and existing SP/MC owners, not a replacement task registry or execution queue. Every QA/demo exit is specified-only. Security-related acceptance and hostile cases remain the responsibility of the assigned Opus reviewers; references below preserve dependencies rather than supply a GPT security verdict.
