### Finding 1 — Shared Merkle walk cells and redundant new-walk accumulator copy (`Q3a`, SOUND)
- **Source lines**: [`crates/mori-chip/src/m3.rs:103-145`](file:///home/hoskinson/.cache/gemini-lanes/chipleaf-final-m3/crates/mori-chip/src/m3.rs#L103-L145), [`m3.rs:337-374`](file:///home/hoskinson/.cache/gemini-lanes/chipleaf-final-m3/crates/mori-chip/src/m3.rs#L337-L374).
- **Analysis**:
  1. At level `l = 0`, the old walk's `x` cell (`a[5]`) is gated to `0` by `m3 walk first` (`q_wfirst * x = 0`, `m3.rs:130`), and the new walk's `x` cell is copy-constrained from `seg_root` (`cur_x[1] = seg_root`, `p.copy_advice(..., a[5], r)` at `m3.rs:339`). At every subsequent level `l = 1..16`, `cur_x[side]` holds the squeeze output cell `out` of level `l - 1` (`m3.rs:413`), and `p.copy_advice(..., a[5], r)` (`m3.rs:340`) copy-constrains level `l`'s `x` to level `l - 1`'s output in both walks.
  2. For the old walk (`side == 0`), `m3.rs:345-355` assigns advice cells `s` (`a[6]`), `b` (`a[7]`), `acc_in` (`a[8]`), and `acc_out` (`a[9]`), and for `l > 0` copy-constrains `acc_in[l]` from `old_rows[l - 1][3]` (`acc_out[l - 1]`, `m3.rs:352`).
  3. For the new walk (`side == 1`), `m3.rs:362-373` copy-constrains `p[0]` (`s`), `p[1]` (`b`), `p[2]` (`acc_in`), and `p[3]` (`acc_out`) from `old_rows[l]` into `a[6..10]` of the new walk's absorb row.
  4. **Code subtlety in `m3.rs:364-367`**: Immediately after `p[0].copy_advice(..., a[6], r)` registers the equality constraint between the old and new sibling cells in the PLONK permutation argument (`m3.rs:363`), lines `364-367` execute `if let Some(v) = s_val { region.assign_advice(..., a[6], r, || Value::known(v))?; }`. In `midnight-proofs` / `halo2`, overwriting the cell value with a second `assign_advice` at the same `(column, row)` keeps the permutation constraint installed by `copy_advice` while allowing negative tests (`sibs_new` in [`rfcore.rs:1810-1819`](file:///home/hoskinson/.cache/gemini-lanes/chipleaf-final-m3/crates/mori-chip/src/rfcore.rs#L1810-L1819)) to supply a mismatched witness value `v != old_s` and verify that the permutation check fails.
  5. **Double constraint on `b` in the new walk**: Because `m3 walk` (`acc_in = 2 * acc_out + b`) is enabled on **both** walks (`q_walk.enable` at `m3.rs:338`), copying `acc_in` (`p[2]`) and `acc_out` (`p[3]`) from the old walk already determines `b = acc_in - 2 * acc_out` on the new walk even without copying `p[1]` (`b`). Thus `b` on the new walk is pinned both directly (by `p[1].copy_advice`) and indirectly (by `p[2..3].copy_advice` + `m3 walk`).
  6. **Free advice `in0`, `in1`**: In `m3.rs:330-335`, the compression inputs `[HIn::Val(in0), HIn::Val(in1)]` are passed as `HIn::Val` (free advice in `a[0]`, `a[1]`, `poseidon.rs:344-354`), not `HIn::Cell`. They are completely pinned on the absorb row (`off = 0`) by the `m3 walk` selector equations `in0 - (x + b * (s - x)) = 0` and `in1 - (s + b * (x - s)) = 0` (`m3.rs:119-120`, verified by `freeWalkSelectPinTest` in [`m3_test.qnt`](file:///home/hoskinson/.cache/gemini-lanes/chipleaf-final-m3/qa/gemini-quint/chipleaf-final/m3_test.qnt#L69-L77)).

### Finding 2 — 17-bit index decomposition, field wrap analysis, and `rfcore.rs:1844` test coupling (`Q3b`, SOUND)
- **Source lines**: [`crates/mori-chip/src/m3.rs:114-139`](file:///home/hoskinson/.cache/gemini-lanes/chipleaf-final-m3/crates/mori-chip/src/m3.rs#L114-L139), [`m3.rs:352`](file:///home/hoskinson/.cache/gemini-lanes/chipleaf-final-m3/crates/mori-chip/src/m3.rs#L352), [`m3.rs:384-390`](file:///home/hoskinson/.cache/gemini-lanes/chipleaf-final-m3/crates/mori-chip/src/m3.rs#L384-L390), [`crates/mori-chip/src/rfcore.rs:1842-1847`](file:///home/hoskinson/.cache/gemini-lanes/chipleaf-final-m3/crates/mori-chip/src/rfcore.rs#L1842-L1847).
- **Analysis**:
  1. At each level `l \in \{0, .., 16\}`, `m3 walk` enforces `b_l (1 - b_l) = 0` (`b_l \in \{0, 1\}`) and `acc_in[l] \equiv 2 \cdot acc_out[l] + b_l \pmod p` (`m3.rs:118, 121`).
  2. For `l \in \{0, .., 15\}`, `m3.rs:352` copy-constrains `acc_in[l + 1] = acc_out[l]`, and at `l = 16`, `m3 walk last` (`m3.rs:135-139`) enforces `acc_out[16] = 0`.
  3. Expanding from `l = 16` down to `l = 0` in $\mathbb{F}_p$:
     $$\text{acc\_in}[0] \equiv \sum_{l=0}^{16} b_l 2^l \pmod p.$$
     Because each $b_l \in \{0, 1\}$, the integer sum $I = \sum_{l=0}^{16} b_l 2^l$ satisfies $0 \le I \le 2^{17} - 1 = 131071$.
  4. At level `0`, `m3 walk first` (`m3.rs:124-134`) enforces `8 \cdot \text{acc\_in}[0] \equiv \text{base} \pmod p$, where `base` (`a[10]`) is copy-constrained from `pre_cell(0, LEN)` (`m3.rs:384`). Over the integer range, $0 \le 8 I \le 8(2^{17} - 1) = 2^{20} - 8 = 1048568$.
  5. **When does a prime let the accumulator wrap?** Wrapping occurs if and only if $p \le 8(2^D - 1)$ (or $p \le 2^D - 1$ for `acc_in[0]` itself), because then a boolean bit vector $(b_0, \dots, b_{D-1})$ can satisfy $8 \sum_{l=0}^{D-1} b_l 2^l \equiv \text{base} \pmod p$ for an unaligned or wrapped `base`. In production ($D = 17$, $C = 8$, BLS12-381 scalar field $p \approx 2^{255} \gg 2^{20}$), wrap is impossible. In our scaled Quint model ($D = 3$, $C \in \{4, 8\}$, $C(2^D - 1) \le 56$), we use $p = \text{PRIME} = 1000003 \gg 56$, so no wrap occurs in the sound model either; whereas if `m3 walk last` (`acc_out[D-1] = 0`) or booleanity (`b_l \in \{0, 1\}`) is dropped (`M4` or `M5`), modular division by $2$ ($\text{HALF} = (p + 1)/2 = 500002$) or negative field elements ($p - 3$) immediately let the prover walk an arbitrary path while keeping `C * acc_in[0] == base (mod p)`.
  6. **Observation on `rfcore.rs:1842-1847` (18-bit index negative test)**: In `m3.rs:284-289`, the witness generator computes `a[l] = m.idx >> l`. When the negative test in `rfcore.rs:1844` sets `m.idx = 1 + (1 << 17)` while leaving `slot0.regs[LEN] = base = 8`, `a[0]` becomes `1 + 2^{17}`, so **both** `m3 walk first` (`8 * a[0] - base = 8 * 2^{17} != 0`) and `m3 walk last` (`acc_out[16] = 1 != 0`) fail simultaneously. To test `m3 walk last` in isolation (as our Quint witness `cex_M4_walk_last_dropped` does), one must keep `acc_in[0] = base / C` and propagate `acc_out[l] = (acc_in[l] - b_l) * 2^{-1} mod p` upward (see Section 4).
- **Quint witnesses**: `cex_M3_base_not_8_acc`, `cex_M4_walk_last_dropped`, `cex_M5_bit_not_boolean` in [`m3.qnt`](file:///home/hoskinson/.cache/gemini-lanes/chipleaf-final-m3/qa/gemini-quint/chipleaf-final/m3.qnt#L1209-L1234).

### Finding 3 — Segment boundary pins (`0`, partial, `8` active rows) and double-guarding in the full leaf (`Q3c`, SOUND)
- **Source lines**: [`crates/mori-chip/src/mem.rs:145-185`](file:///home/hoskinson/.cache/gemini-lanes/chipleaf-final-m3/crates/mori-chip/src/mem.rs#L145-L185), [`crates/mori-chip/src/rfcore.rs:352-431`](file:///home/hoskinson/.cache/gemini-lanes/chipleaf-final-m3/crates/mori-chip/src/rfcore.rs#L352-L431), [`rfcore.rs:509-515`](file:///home/hoskinson/.cache/gemini-lanes/chipleaf-final-m3/crates/mori-chip/src/rfcore.rs#L509-L515), [`rfcore.rs:1225-1226`](file:///home/hoskinson/.cache/gemini-lanes/chipleaf-final-m3/crates/mori-chip/src/rfcore.rs#L1225-L1226).
- **Analysis**:
  1. Let $u = \sum_{i=0}^{C-1} \text{act}[i] \in \{0, \dots, C\}$ be the length of the monotone active prefix ($\text{act}[0] \ge \text{act}[1] \ge \dots \ge \text{act}[C-1]$, enforced by `mem chain` `(1 - act) * act' = 0` at `mem.rs:170`).
  2. **Case $u = 0$ (all rows padding)**: $\text{act}[0] = 0$, so `mem first` (`(1 - act[0]) * (addr[0] - len_end) = 0`, `mem.rs:178`) forces $\text{len\_end} = \text{addr}[0] = \text{base}$.
  3. **Case $1 \le u \le C - 1$ (partial segment)**: $\text{act}[u - 1] = 1$ and $\text{act}[u] = 0$, so `mem chain` (`act[u - 1] * (1 - act[u]) * (addr[u - 1] + 1 - len_end) = 0`, `mem.rs:171`) forces $\text{len\_end} = \text{addr}[u - 1] + 1 = \text{base} + u$.
  4. **Case $u = C$ (all rows active)**: $\text{act}[C - 1] = 1$, so `mem last` (`act[C - 1] * (addr[C - 1] + 1 - len_end) = 0`, `mem.rs:183`) forces $\text{len\_end} = \text{addr}[C - 1] + 1 = \text{base} + C$.
  5. Therefore, in all three cases, $\text{len\_end} = \text{base} + u$, so $\text{base} \le \text{len\_end} \le \text{base} + C$ and the active rows are precisely those with $\text{addr}[i] < \text{len\_end}$.
  6. **Why an append cannot be skipped**: Each core `PUSH`/`TPUSH` increments `LEN` by 1 (`rfcore.rs:509-515`) and emits a bus lookup `(CHIP_MEM, pre.len, w0, w1, w2)` on lane 1. Because `len_end` is copy-constrained from `slot[s].regs[LEN]` (`rfcore.rs:1226`), `u = len_end - base` equals the number of core appends in the leaf, and each appended address `base + k` ($0 \le k < u$) must be active and hold the exact bus tuple requested by the core.
  7. **Why an unrequested row cannot be active**: If row $i$ were active without a core append, $u = \text{len\_end} - \text{base}$ would exceed the number of core appends, violating the copy constraint `len_end == slot[s].regs[LEN]` (or `mem first` / `mem chain` / `mem last`).
  8. **Why padding cannot be non-zero or readable**: On any row with `act[i] = 0`, `mem row` (`mem.rs:152-158`) forces `chip = 0`, `key = 0`, and `a = b = c = 0`. A core `POP`/`TPOP` both checks `fp < pre.len` (or `tp < pre.len`) via `OP_LT` on bus lane 0 (`rfcore.rs:381, 397`) and looks up `chip = CHIP_MEM = 3 != 0` on bus lane 1 (`rfcore.rs:373, 391`), so padding rows are doubly un-readable.
  9. **Note on `mem first` vs. bus lookup in the full leaf**: In the standalone `MemSegmentChip`, `mem first` is the sole constraint preventing `act = [0, .., 0]` when `len_end > base`. ## 4. Soundness Gaps and Test Recommendations for `crates/mori-chip/src/rfcore.rs`

### 4.1 Are there any soundness bugs in the as-built Rust circuit (`mem.rs`, `m3.rs`, `rfcore.rs`)?
**No unconstrained wire, missing copy constraint, or field-wrap soundness bug was found in the as-built M3 / MEM / digest circuit.** Every constraint `C1`–`C5` identified in the earlier `chipleaf-pairrow-m3` review is closed in the Rust implementation:

- `C1` holds across `rfcore.rs` (`V0..V2` are never read by instruction gates).

### 4.2 Architectural / Open Conditions (Non-Circuit or Multi-Chip Scope)
1. **Record-kind tag (`Q3d`)**: `act` distinguishes active rows (`1`) from padding rows (`0`), but does not distinguish frame, task, and data records from each other (`experiments-4.md` §3.4, §5).
2. **Partition-dependent `len` (`C6`, `Q3e`)**: Advancing `len` to `base + 8` at the close of every leaf makes `post_d` and future memory addresses depend on where leaf boundaries fall (`experiments-4.md` §4).
3. **Cross-leaf `POP`/`TPOP` requires `PAGE`**: Without the read-only `PAGE` provider wired, a leaf can only `POP`/`TPOP` records written within the same leaf (`base <= addr < len_end`).

### 4.3 Concrete Improvement to the Rust Negative Test at `rfcore.rs:1842-1847`
In [`crates/mori-chip/src/rfcore.rs:1842-1847`](file:///home/hoskinson/.cache/gemini-lanes/chipleaf-final-m3/crates/mori-chip/src/rfcore.rs#L1842-L1847), the existing negative test for an 18-bit walk index is:
```rust
// 6. 18-bit index (bit 17 set -> acc_out at level 16 is 1 != 0).
let mut w = good.clone();
w.m3.idx = 1 + (1 << 17);
assert!( !ok(&w, &inst(&w)), "accepted 18-bit walk index" );
```
Because `M3Chip::assign` (`m3.rs:284-289`) sets `a[0] = F::from(m.idx)` while `base` (`slot0.regs[LEN]`) remains `8`, setting `w.m3.idx = 1 + (1 << 17)` causes **both** `m3 walk first` (`8 * a[0] - base = 8 * 2^{17} != 0`) and `m3 walk last` (`acc_out[16] = 1 != 0`) to fail at the same time. Thus that test would still pass even if `m3 walk last` were completely deleted!

To test `m3 walk last` in isolation (matching `cex_M4_walk_last_dropped` in `m3.qnt`), keep `a[0] = base / 8 = 1`, set a non-matching bit (e.g. `b[0] = 1, b[1] = 1`), and compute `acc_out[l] = (acc_in[l] - b[l]) * 2^{-1} mod p` in $\mathbb{F}_p$ at every level `0..16`. Then `m3 walk first` (`8 * a[0] == base`) and every level's `m3 walk` (`acc_in[l] == 2 * acc_out[l] + b[l]`) are satisfied, and **only** `m3 walk last` (`acc_out[16] == 0`) rejects the witness.

## 5. Model Abstractions and Differences vs. Rust Code and `m3seg.qnt`

### 5.1 Scaled Parameters vs. Production Rust Circuit
1. **Segment capacity `C` and slot count `S`**: Scaled to `C = 4, S = 4` in `m3_sound` and all 15 mutant instances, plus `C = 8, S = 8` (matching production `SEG = 8` in `mem.rs:28`) in `m3_sound_c8`.
2. **Top-tree depth `D`**: Scaled to `D = 3` (8 segment slots in the top tree, `base / C < 8`) vs. `TOP = 17` (`131,072` segment slots) in `m3.rs:34`.
3. **Prime field `PRIME`**: Scaled to $\mathbb{F}_{1000003}$ (`PRIME = 1000003`, `HALF = 500002`) vs. the BLS12-381 scalar field $p \approx 2^{255}$. Since $C(2^D - 1) \le 8 \times 7 = 56 \ll 1000003$, the honest accumulator never wraps modulo `PRIME`, while modular inverse attacks (`M4` using `HALF = 500002` and `M5` using `PRIME - 3`) work over $\mathbb{F}_{\text{PRIME}}$ exactly as over $\mathbb{F}_p$.
4. **Collision-free hash**: Instead of running 64-round Poseidon permutations over $\mathbb{F}_p$, `h2`, `recordHash`, `segRootFromRecs`, and `stateDigest` are modeled as injective integer encodings (`m3.qnt:142-222`), relying on the `chipleaf-hash` lane's proof that `PoseidonChip::sponge` is sound.
5. **Register file**: All 32 register words (`0..31`) are modeled in `SlotRow`, with `0..28` (`NDIG = 29`) digested in `stateDigest` and `29..31` (`V0..V2`) undigested and write-only (`m3.qnt:214-222, 502-520`).

### 5.2 Advances over Earlier `qa/gemini-quint/chipleaf-pairrow-m3/m3seg.qnt`
- `m3seg.qnt` modeled a single isolated segment with no core execution slots, no bus lookup, no `in0`/`in1` walker mux cells, no field arithmetic (`acc_in = 2 * acc_out + b (mod p)`), no level-to-level copy cells, no `pre_d`/`post_d` 30-word state digests, and no two-leaf chaining.
- [`qa/gemini-quint/chipleaf-final/m3.qnt`](file:///home/hoskinson/.cache/gemini-lanes/chipleaf-final-m3/qa/gemini-quint/chipleaf-final/m3.qnt) models the **entire wired M3 leaf pair** (`ChainW`), including two chained leaves (`leaf1`, `leaf2`), three trace partitions (`partId \in \{0, 1, 2\}`), the D7 zero-tuple spill program (`progId = 0`) and stack push/pop program (`progId = 1`), explicit per-level old and new `WalkRow` advice cells (`x, s, b, accIn, accOut, in0, in1, out, baseCell, lenPostCell`), modular field equations over $\mathbb{F}_{1000003}$, bus lookup matching between core slots and `MemSegmentChip`, and 30-input state digests (`pre_d`, `post_d`).
