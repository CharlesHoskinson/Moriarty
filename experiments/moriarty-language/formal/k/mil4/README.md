# Provisional MIL/4 S0 K stage

`s0.k` is an isolated Source/6 → Core/5 prototype for literal-fee transfer and funded AccrualFirst repayment. It is not the admitted MIL/4 composition root. The contract and independent expected cases are in `../../mil4/`.

The K request contains a signed intent template, a submitted fill with an opaque `post_head`, pre-state supplied under an external premise, a complete submitted effect vector, terminal phase, empty duty, and current round. The stage checks `stage → intent → effect → authority → history → failure`. Rejection publishes only the first judgment, a provisional code, and diagnostic work. Acceptance publishes pre-state, ordered effects, derived post-state, terminal phase, empty duty, and remaining work. Gross debit consumes allowance remaining, increases spent, uses one replay key, and advances one head. Transfer omits the zero-fee credit line. Repayment binds its explicit signed payer to the signer, credits the obligation's bound creditor, and applies accrued interest before principal. Work is metered in the state and result; it is not a submitted financial effect. A valid current round can be nonzero.

The `<external>` cell starts as `unavailable()`. Only a trusted integration may inject `authenticated(signedIntent, preState, currentRound, postHead)` after verifying the exact signed bytes, state snapshot, current round from that snapshot, and successor binding. The premise must contain the exact `Intent` term submitted to K, including its action, endpoints, caps, nonce, validity interval, version and digest; a reused digest alone cannot authenticate changed scope. Stage checks this intent, snapshot and round premise before intent and effect judgments. The submitted round must equal the authenticated round. The submitted fill must match the signed intent; its post head must match the authenticated successor at history. The syntax constructor is an abstract premise, not a verifier or a caller-supplied proof. A normal standalone run cannot reach acceptance. Actual signature verification, atomic ledger compare-and-consume, settlement and native proof qualification are outside this definition. The K version fields use `Source/6` and `Core/5`; the Source/6 presentation header is `moriarty-financial-agreement-source/6`.

All eight named first-profile families reject with `FAMILY_STAGE_ADAPTER_ABSENT`; all other unsupported requests reject at stage. This prototype has no source parser, byte codec, signature verifier, state authentication implementation, successor verifier, atomic ledger adapter, semantic trace results, or proof. The S0 wire choices and codes remain provisional under W-D0–W-D4. Transfer uses three present balance cells; repay uses two. Repay's recipient and fee positions in the shared K tuple must be empty strings, representing their absence from Source/6; its payer must differ from the authenticated obligation's creditor. Both actions reject missing endpoint cells. Selected program identity, key reference, predecessor, and Source/6 field limits remain abstract or source-side obligations in this isolated K slice.

Syntax compilation: `kompile s0.k --backend kore --main-module MIL4-S0 --syntax-module MIL4-S0-SYNTAX -o /tmp/mil4-s0-kompiled` with K v7.1.337. Compilation does not establish the behavior described above.
