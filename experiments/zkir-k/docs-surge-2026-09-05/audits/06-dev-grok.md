## Findings
### F1 major "generation supports preimage construction, not a successful ordinary-run verdict"
Claim: a generation run is not a successful ordinary-run verdict, so a reader should not treat `--gen` output as the real result.
Evidence: `tools/zkir_run.py:301` builds `genJob` when `gen=True`. `zkir-vm.k:525-527` skips transcript exhaustion and records `needComm` instead of `#commCheck`. The reconstructed trace with omitted transcripts and `--gen` printed `"status": "ok"`, `"needs": [["pubIn", 5]]`, five `holds` verdicts, and exit 0. The same preimage without `--gen` printed `"status": "error"`, `"error": "Public transcript input mismatch for input 0"`. A `do_communications_commitment` program with provisional `["0","1"]` and `--gen` printed `"status": "ok"` together with `commGate` `violated` ("communications commitment differs from poseidon(rand ++ encode(inputs) ++ encode(outputs))") and a `comm` need. `11-tooling-reference.md` already states that `--gen` can be `ok` while `commGate` is `violated`.
Fix: replace the last clause with: `--gen` can still print `status: ok` and even `holds()` on every gate, because live `#finish` skips exhaustion and the commitment check; apply the `needs` list and rerun without `--gen` before treating the JSON as an ordinary verdict.

### F2 major Three-instruction trace has no command or JSON program
Claim: a developer can replay the worked example from the K constructors and the shown preimage.
Evidence: the chapter gives the program only as `add` / `impact` / `output` constructors and the preimage `{"inputs":["2"],"binding_input":"9","public_transcript_inputs":["5"]}`. No `.zkir` file and no `uv run ... zkir_run.py` line appear. Reconstructing it required the JSON shape from `03-program-model.md` / `zkir_kast.py`: `"b": "0x03"` not `3`, output field `vals` not `values`, type `Scalar<BLS12-381>`. That artifact, run from the repository root, matched the table's final state (`status ok`, memory `%x=2` `%y=5`, `pis [9,5]`, `pi_skips [null]`, cursors `(1,0,0)`, five `holds`, `k_cell` `.K`, `outputs` `Native:5`). `--depth 1` showed `#loadInputs ~> #seedPi ~> Is ~> #verdicts`. `--depth 8` showed `#put ( "%y" , vOk ( native ( 5 ) ) )` with `pis [9]` and `constraints 2`, which matches emission-before-`#put`. Without those guesses a reader cannot type a command at this chapter.
Fix: add the JSON program (inputs `[{"name":"%x","type":"Scalar<BLS12-381>"}]`, one native output, `do_communications_commitment` false, `add`/`impact`/`output` with `"b": "0x03"` and `"vals": ["%y"]`) and the command `uv run --group zkir-k python experiments/zkir-k/tools/zkir_run.py PROG.zkir PRE.json`. Quote the final JSON keys that confirm the last row: `status`, `memory`, `pis`, `pi_skips`, `cursors`, `all_verdicts`, `k_cell`.

### F3 minor outputGate spelling in the trace versus runner pretty-print
Claim: the appended output gate is `outputGate((var("%y"), .Operands), (native(), .IrTypes))`.
Evidence: that is the two-argument constructor `outputGate(Operands, IrTypes)` in `zkir-constraints.k:39`. The runner pretty-printer flattens the list cons cells. The live `all_verdicts` entry was `"outputGate ( var ( \"%y\" ) , .Operands , native ( ) , .IrTypes )"`.
Fix: keep the constructor form, and add the pretty-printed spelling a `zkir_run.py` user will see.

### F4 minor depth-exhausted row does not name `--depth`
Claim: `depth-exhausted` is "Nonempty `<k>` with a supplied depth bound."
Evidence: `tools/zkir_run.py:315` and `:366` only set that status when `Runner.run(..., depth=N)` is used, which the CLI exposes as `--depth`. `--depth 0` on the reconstructed program printed `"status": "depth-exhausted"` with `job (...)` still in `k_cell` and a 300-character prefix of that term in `error`, exit 0. The chapter never names `--depth` (it lives in `02-getting-started.md` and `11-tooling-reference.md`).
Fix: in the table or the following paragraph, write "nonempty `<k>` when the caller passed `--depth N`" and point at `11-tooling-reference.md` for the flag.
