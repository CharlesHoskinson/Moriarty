Title: reconstitute_field with bits = 0 passes load, is rejected by preprocess on every value, and panics key generation by an assertion

Affected crate and commit

midnightntwrk/midnight-ledger, crate zkir-v3, commit 92e8bdd3a97b61b229e38916e1b180de6f448dd5 (branch ledger-9); the same code is in midnightntwrk/midnight-zkir at 2ffe2d17bbb736aec36fb300aeaca679a10d2278. midnight-circuits 7.2.4.

Expected behaviour

A program that `IrSource::load` accepts either synthesises or is rejected up front with an error; a width the preprocessor rejects on every value is rejected at load or by `Error::Synthesis` at key generation.

Actual behaviour

`reconstitute_field` with `bits: 0` loads. Off-circuit, `preprocess` bounds the divisor by `FR_BITS - bits` = 255 bits and rejects every value with "Excessive bit bound" (`resolve_operand_bits` accepts only bounds below FR_BITS). In circuit, the `ReconstituteField` arm calls `assert_lower_than_fixed(divisor, 1 << 255)`, which reaches `assign_less_than_pow2` in midnight-circuits `field/decomposition/chip.rs` and trips `assert!((bit_length as u32) < F::NUM_BITS)` (the assertion is compiled out under `cfg(test)`, so the crate's own tests do not see it). Unknown-witness key generation therefore panics instead of returning an error.

Minimal reproduction

Program (one instruction, two native inputs, no outputs):

{
 "version": { "major": 3, "minor": 0 },
 "inputs": [ { "name": "%d", "type": "Scalar<BLS12-381>" }, { "name": "%m", "type": "Scalar<BLS12-381>" } ],
 "outputs": [],
 "do_communications_commitment": false,
 "instructions": [ { "op": "reconstitute_field", "divisor": "%d", "modulus": "%m", "bits": 0, "output": "%o" } ]
}

Any preimage, for instance inputs [1, 1] and binding input 0: `preprocess` returns Err("Excessive bit bound"). `keygen_vk` on `MidnightCircuit` (or `MockProver::run` with any witness) panics with "assertion failed: (bit_length as u32) < F::NUM_BITS".

Impact

Availability: a loadable program cannot be keyed, and the failure is a panic rather than an error. The same class as the `less_than` bound of 253 or 254 bits (K5): a width that only the chip checks, by an assertion.

Suggested fix

Reject `bits == 0` (and, for symmetry, `bits >= FR_BITS`) in `IrSource::load` or in the `ReconstituteField` arm with `Error::Synthesis`, and replace the assertion in `assign_less_than_pow2` by an error for widths at or above `F::NUM_BITS`.

Found by the eight-reviewer audit of an executable specification (fable-R3, finding 2) and confirmed with the MockProver harness `zkir-circuit-oracle --keygen`.
