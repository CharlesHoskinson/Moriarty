# ZKIR K semantics, third iteration: plan (draft for critique)

## Where the definition stands

Executable K semantics of ZKIR v3 at midnight-ledger 92e8bdd3 (34 instructions, 13 types) and midnight-zkir 2ffe2d1 (42 instructions, 15 types). Off-circuit (witness) semantics complete and differential-tested against the crate's `preprocess`: 358/358 and 418/418 comparisons agree on status, error class, register types and encodings, public inputs and skips. Static well-formedness complete. In-circuit semantics exists for every instruction as an instruction-level relation with chip gating and width limits; verdicts are checked only for internal consistency and by 20 divergence cases, never against the real circuit. Not modelled: auxiliary witness cells, copy wiring, per-type assignment constraints (byte ranges, on-curve and subgroup checks at assignment, foreign limb ranges), JubjubScalar canonicity, hash gadget internals, prover-side panics. Symbolic reasoning: LLVM backend only; Haskell backend stalls on hash unfolding. Real programs: escrow, swap and micro-dao artifacts reach a successful witness in one case. Known divergences K1 to K6 recorded, none reported upstream. Compiled definitions (about 160 MB) are tracked in git by accident.

## Goal of the iteration

Make the definition usable as the compilation target in a formal specification of Moriarty. That needs three things the definition does not yet give: (1) a circuit-side semantics whose verdicts are checked against the real circuit, so that "the circuit accepts the witness" is a modelled and tested statement rather than an assumption; (2) a backend on which properties can be proved, not only tested; (3) an explicit target contract, the set of obligations a compiler must meet for its output to be well-formed, provable and semantically defined, stated once as K functions and used by the Moriarty specification.

## The soundness gap: three approaches

A. Full PLONKish model. Model the Halo2 constraint system midnight-circuits builds: rows, columns, gates, copy constraints, lookups, per chip. Faithful in principle. Cost: months, a second implementation of midnight-circuits in K, brittle under every chip change, and still not the proving system. Rejected for this iteration.

B. Relational model with a circuit oracle (recommended). Keep instruction-level relations, add the per-type assignment constraints as explicit relations (`assignGate`), keep hashes as functional relations, and define the modelled witness space W(P, pi) as the set of register assignments satisfying every modelled relation. Then check the model against the real circuit by a fourth oracle: the crate's own `Relation::circuit` run under the halo2 MockProver (midnight-proofs `dev::MockProver`, present in 0.7.3 and 0.8.x) on the same preimage. Holds must correspond to an accepting circuit, violated to a MockProver constraint failure, synthErr to a synthesis error or panic. This turns the verdict layer from untested into differentially tested, at the granularity the crate exposes (whole-circuit accept/reject on a preimage), and states soundness relative to the modelled relations and to the hash functions treated as functions.

C. Status quo plus documentation. Keep completeness-only verdicts, rely on the crate for soundness. Cheapest; leaves the Moriarty specification unable to state what the circuit accepts. Rejected.

## Milestones

M0 Housekeeping (small, first). Untrack `*-kompiled` and ignore them; add a `check` target that runs kompile of the four definitions and the six check layers in order and writes dated receipts; a script that diffs the pinned commits' instruction and type enums against the current upstream heads and reports drift; draft the six upstream issue texts for K1 to K6 from the contradictions rows (filing is the user's call).

M1 Circuit oracle. A `zkir-circuit-oracle` binary in `repos/_build/ledger-92e8bdd3` and `.../midnight-zkir-2ffe2d1`: loads a program and preimage, runs `preprocess`, builds the circuit with the crate's `Relation::circuit`, runs MockProver, prints one of accept / constraint-failure(list) / synthesis-error(msg) / panic. Extend `diff_test.py` with a `--circuit` mode comparing K's verdict summary (all holds / some violated / some synthErr / some unknown) with the oracle's outcome on the honest preimage and on the four perturbations. Exit criterion: agreement on every comparison of the base corpus, or each disagreement recorded as a finding; the 20 divergence cases each carry a circuit-oracle expectation.

M2 Assignment constraints and the soundness statement. New constraint constructor `assignGate(id, type)` emitted when a register is first assigned by an input, a decoder, or an instruction whose in-circuit arm assigns a fresh typed value; relations: Bytes32 byte ranges, points on curve and in subgroup where the chip checks it (and explicitly not where it does not, per chip), foreign limb ranges and reduction rules, JubjubScalar recorded as not canonical-checked (an explicit `unconstrained` outcome, so the gap is visible in verdicts rather than silent). `witnessSpace` stated as a predicate over memory; a documented soundness claim: any memory satisfying every modelled relation is accepted by the circuit up to the unmodelled items, tested by M1 on perturbed memories (inject a non-canonical or off-curve value where preprocess would not produce one, via a K-side injection entry point `injectJob`) and on the divergence cases. Exit: every perturbed-memory comparison agrees or is a recorded finding; the definition page's "what a green run establishes" upgraded and re-audited.

M3 Symbolic backend. A `zkir-symbolic.k` main module: defining rules of Poseidon, hash-to-curve, SHA, Keccak and curve arithmetic marked `[concrete]`; uninterpreted function symbols for the hashes with the lemmas the plan already lists (functionality, and nothing else); field simplification lemmas for `modInt` over `#r`; Haskell backend kompile; a claims suite: per-instruction lemmas for the native arithmetic and control instructions, one lemma over a three-instruction program with a hash, and the template of a compiler correctness obligation (source term, compiled program, equal observable outputs). Exit: `kprove` receipts with times for every claim, and the `transient_hash` claim that failed in iteration 2 proved.

M4 Real transaction contexts. Two steps: first the quick win, use the 17 extension test preimages already in the manifest that `extract_test_inputs.py` does not read; second, produce preimages for the seven Moriarty artifacts by driving the compiled contract's runtime (`output/contract/index.js` with the Compact runtime) or the ledger's proof-preimage construction, so each reaches a successful witness on both sides. Exit: successful-run agreements for all seven, recorded in the differential receipt.

M5 The compilation-target contract. A K function `targetContract(P)` returning the list of obligations a compiled program meets or fails: well-formedness, the chip set implied by `used_chips`, width limits, alignment restrictions in circuit, commitment flag rules, the version pin; a JSON export of the same for the Moriarty toolchain; the observable semantics `[[P]](pre)` = (status, outputs, public inputs) stated as one K function over the configuration so that a compiler correctness statement can quote it; chapter 16 of the documentation describing the contract; the seven Moriarty artifacts become first-class corpus entries with expected contract results. Exit: contract results for every corpus program, reviewed.

M6 Audit and documentation. The eight-reviewer cross-vendor audit on the changed modules (constraints, symbolic, contract), a fix iteration, chapter updates for 08, 12, 14, 15 and the new 16, the definition and plan pages, receipts with a new suffix.

## Order and dependencies

M0 first (half a day). M1 before M2 (M2's tests need the oracle). M3 independent of M1 and M2, can run in parallel. M4's quick win immediately; its second step after M1 so the new preimages also go through the circuit oracle. M5 after M2 and M3 have settled the shapes it exposes. M6 last. Critical path: M1, M2, M5, M6.

## Risks

MockProver on these circuits may be slow or memory-heavy (the ledger circuits are large); mitigate by running the corpus in the oracle once and caching. The prove/keygen API is async and takes parameters; the oracle needs the crate's test setup. Injecting perturbed memories into the circuit needs a hook the crate does not have; the fallback is perturbing preimages only, which reaches fewer assignment constraints. Haskell backend performance on the full definition; mitigate by a reduced symbolic module importing only what the claims need. Producing Moriarty preimages needs the Compact runtime and the ledger's transaction context; if that fails, the exit criterion for M4 falls back to the extension preimages plus hand-built contexts for two of the seven. Upstream drift between 92e8bdd3 and current heads may invalidate parts of the base surface; the M0 drift script decides whether to re-pin.

## Process

Same as iterations one and two: every milestone lands with a receipt under `evidence/`, a claim record on the wiki, and a differential comparison where an oracle exists; implementation by the routine lanes, cross-vendor audit before merge; commits on a branch from main, merged with `--no-ff`; source identifiers allocated from the inventory maximum.
