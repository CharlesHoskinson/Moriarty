# Feed-AB observation policy

The deployment fixes one Jubjub Schnorr controller key and a network identifier at construction. The owner's enrollment pins the deployment, its controller and provider keys, network tag, verifier keys and maintenance committee. The O5 adapter compares each with the accepted ledger before it prepares a fill. A maintenance authority that can change the verified code can change these guarantees. The controller signs the feed name, price and Unix timestamp for that network and contract address. The signature challenge includes the protocol domain, public key and announcement coordinates. Any relayer can submit the signed update.

The ledger retains the newest accepted sample. A timestamp must advance strictly after the first update. Publication and use both require block time between the sample time and thirty seconds later, inclusive. The policy reads time through Midnight’s Compact block-time comparisons. Its deadline saturates at the largest representable Unix second. The execution circuit reads the accepted feed fields and checks that the price is below three. A custody circuit includes `feed-policy.compact` and invokes `requireFeedCondition` before the transfer in the same call. A transcript prepared at an earlier price or for an expired observation fails verifying-mode replay when its ledger reads differ.

An empty or expired feed prevents execution. The controller can choose the reported price, withhold updates, or choose when to sign. The chain controls block time, transaction ordering and inclusion. The tests use a local chain clock in seconds with zero uncertainty. Price accuracy, timely publication and inclusion are external assumptions. The deployer controls which controller key users initially trust.

The O5 deployment also fixes a provider signing key. The owner authorizes the order for the deployed instance. The provider signs the same instance, complete order terms, revision and exact input and delivery. The funded local run uses the provider wallet's signed B inputs and reconciles the credits to Bob. An O5 fill supplies an execution second. The contract requires that second to equal the ledger clock so the source kernel receives the precise sample age. A later inclusion second requires fresh preparation. The changed-price test replays the original proved fill at its original second after the new price takes effect. The ledger refuses that unchanged transaction because its recorded observation timestamp no longer matches. A control run publishes a newer sample at the unchanged price: the unchanged transaction fails the same way, while a freshly prepared fill at that second succeeds. At price three a fresh preparation fails with FEED_THRESHOLD.
