How Aleo Works
Aleo is a Layer-1 blockchain designed for
private, programmable applications
. It uses zero-knowledge proofs to let developers build apps where user data stays private, while still allowing the rest of the network to verify that everything is correct.
The key architectural insight:
execute offchain, verify onchain
.
Offchain Execution, Onchain Verification
​
On most blockchains, every node re-executes every transaction to verify it. This means all data must be public, and computation is bottlenecked by the slowest node.
Aleo works differently:
A program runs
locally
on the user's device (or a delegated prover).
The execution produces a
zero-knowledge proof
that the program ran correctly with valid inputs.
Only the proof — not the inputs or execution trace — is submitted to the network.
Validators
verify the proof
onchain, which is fast and requires no knowledge of the original data.
This model provides privacy (the data never leaves the user's device) and scalability (verification is cheaper than re-execution) simultaneously.
Programmable Privacy
​
Because execution happens offchain, Aleo programs are
private by default
. Inputs, outputs, and program logic are never exposed to the network. But privacy isn't all-or-nothing. Developers can selectively make parts of their program public when transparency is needed.
This means a single program can keep user balances private while publishing a total supply publicly, or verify a credential without revealing the underlying data. The developer decides what to reveal and what to keep encrypted, not the protocol.
