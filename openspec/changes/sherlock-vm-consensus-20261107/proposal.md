## Why

Sherlock's general-purpose recursion is designed and partly measured but not finished:

- The owner's goal is Sherlock on Midnight Mainnet with full general-purpose recursion, qualified on Preview first (`dissent.md` "Resolved 2026-11-08 (5)"). It replaces the earlier goal "Sherlock on stagenet with full general-purpose recursion" (`docs/sherlock/stagenet-gp-recursion.md:11`). No general program has been proved end to end; the universal leaf has never been keyed (`docs/sherlock/stagenet-gp-recursion.md:96,235`).
- The factory has reported first failure A8 since 2026-10-26 (`qa/sherlock/status.json`, head `7e22b5823`), counts A 7/10, B 4/9, C 5/6, U 34/35, F 11/13, and `scripts/doctorwatson stop-rule` has been in STOP (exit 6) for about 295 h with no recorded escalation (`research/sherlock-vm-council-20261107/fable-3/position.md` §0).
- The U023 dispatch receipt run stopped at a 16,000 s wall cap without a receipt (`qa/sherlock/runs.jsonl`, run `20261026T105549Z-U023-dispatch-receipt`; `docs/sherlock/HANDOFF-2026-10-26.md:16`).
- Midnight Mainnet moved to ledger 9.1.0.1 on 2026-11-06 (`wiki/midnight-ledger-9-hardfork.md`; https://docs.midnight.network/relnotes/ledger-9). The workspace pins a ledger-9 release candidate: `midnight-ledger` rev `04c9c5d9` (2026-07-31), `midnight-proofs =0.8.3`, `midnight-circuits =7.2.4`, `midnight-zk-stdlib =2.3.5` (`Cargo.toml:28-42`); zkir-v3 `3.0.0-rc.2` (`crates/mori-ledger/src/profile.rs:35`). The "stagenet" the A/B evidence was earned on (`rpc.stagenet.shielded.tools`) reports specVersion 2000000, an rc-era runtime; Preview and Mainnet report 2001100 (`fable-3/position.md` §6 RPC reads, `fable-2/position.md` M6).
- The GP leaf producer emits six public lanes while the IVC node consumes seven (`crates/mori-backend/src/sherlock_c6_child.rs:817-834`; `crates/mori-recursion/src/ivc.rs:191-201`).

## What changes

1. **VM (keep, refine).** The 39-rule reference machine, the helper-microstep owner engine, the bounded images and `StepInv`, and in-circuit dispatch derived from the pre-state are kept. The leaf becomes one universal, one-hot-gated, S-step relation (or a committed finite family if measurement says so), with a versioned layout and qualification configuration bound into its identity. See `design.md` §2.
2. **Recursion (keep, close the interface).** Leaf -> linear self-recursive IVC node -> run decider -> `SherlockRun.acceptRun` is kept. The leaf statement is frozen at seven lanes including `steps`; `steps` and height are range-checked; the decider binds outcome and result from the proved state; keys are authenticated as a tuple. See `design.md` §3.
3. **Assurance (new requirements).** A typed evidence record, dependency fingerprints, honest negative-evidence accounting, dispatch coverage by committed equivalence class, and completeness/soundness stated as obligations per rule. See `assurance.md`.
4. **Workflow (factory only).** The change runs on `scripts/doctorwatson` (`next`/`check`/`heavy`/`stop-rule`); operations (mutating network steps) are separated from predicates; new T0 checks for traceability and target pins; a `network:` field and a T4 (mainnet) tier are specified as exact additions. See `workflow.md`.
5. **Midnight target.** Re-pin to the ledger 9.1.0.1 line with a keygen regression; Preview (new chain, genesis-pinned) is the qualification target; stagenet rows are frozen as history; Mainnet is an owner-authorized operation. See `design.md` §5.
6. **Speed re-plan (amended 2026-11-08 (3)).** Throughput is mandatory under the owner's caps (SRC-011: 2 h, 48 GB per process, 100 GB aggregate), memory safety lands first (SRC-016), the measured speed work and the formal design work run ahead of the universal leaf, and the tree is a measured option again. See the section below and `design.md` §3.5-§3.7.

## Speed re-plan (amended 2026-11-08 (3))

The owner called the measured recursion "way too slow" (293 node steps at about 95 s, 7.7 h for fact(3)) and said "yes, re-plan it, and reopen tree aggregation"; "48 GB per process, 100 GB aggregate"; "have some agents explore it with lean and quint ... It has to be general purpose recursion" (`dissent.md` "Resolved 2026-11-08 (3)"; planning reports in `research/sherlock-speed-replan-20261108/`). The amendment:

- **Requirements.** SRC-011 becomes mandatory with the owner's caps and a receipt that records the thread count, the concurrency and both peaks; SRC-015 adds the staged gates (node step at k=19 <= 60 s / 16 GB; `entry 7;` < 20 min; fact(3) and list123 < 2 h), SRC-016 the memory safety (cgroup caps, E11 concurrency, preflight, aggregate admission), SRC-017 general-purpose recursion with fixed keys and the formal gates (Quint F20, Lean F21, council review 2.14 before 2.3, 4.2 and 5.7), SRC-018 the GPU backend's bit-identity and fallback. SRC-013 and SRC-014 make S a keyed constant chosen once from the measured `k_U`.
- **Approach.** Primary path: S-batched linear IVC with 2-3 leaf workers proving ahead of the node chain under the 100 GB aggregate; the node trimmed to k=19 inside task 2.3 so keygen runs once; the thread sweep as lever 0. Tree aggregation (D13') as the uniform three-slot self-recursive node of `tree.md`, decided at G-A/G-B by measured criteria. One general aggregation model covers both: the linear chain is the degenerate tree. GPU: an open-source Rust MSM/NTT build (owner: "you'll have to build one in rust"), phased with kill criteria, opened only when the C0 profile shows the share, proofs byte-identical.
- **Order.** Memory guard (2.0) before any heavy run; then the C0 chain profile, thread sweep and concurrency probe (2.7-2.9, 2.13) in parallel with the Quint and Lean work (2.11, 2.12); council review (2.14); gate G-A; node fixes plus the k=19 cut (2.3); one keygen (2.4); S fixed at G-A' before the leaf is keyed (4.10, 4.2, 4.4); the throughput gates G-B and G-C in M5; OP-PV-DEPLOY depends on G-C. Gate decisions are committed under `qa/sherlock/decisions/speed-levers.json`.
- **Exit.** SRC-011, SRC-015, SRC-016 and SRC-017 join the mandatory list below; SRC-018 applies whenever the `gpu` feature is enabled for a qualified candidate; SRC-014 is unconditional (vacuous only at S=1, which G-A' may still choose).

## Exit of this change

This change is complete when the Preview qualification record for P1 (`fact(3)`), P2 (`list123`) and P3 (fresh program) exists under the new keys (U023 scenario 2, C4 flips) and every mandatory security and assurance gate for the claimed profile (`sherlock-helper-microstep/1`, the frozen inventory, Preview) passes: SVM-001..009, SRC-001..017 (SRC-011, SRC-014, SRC-015, SRC-016 and SRC-017 mandatory since 2026-11-08 (3); SRC-014 is vacuous only if gate G-A' chooses S=1), SAS-001..007, SAS-010..014, SWF-001..008, SWF-010..012, SWF-014 (added 2026-11-08 (2)), SMN-001..007. Conditional clauses apply whenever their trigger occurs and are then mandatory: SAS-008 whenever an optimization is enabled (otherwise recorded "not applicable: no optimization enabled"), SAS-009 whenever a formal property is claimed (triggered by SRC-017's F21 theorems), SRC-018 whenever the `gpu` feature is enabled for a qualified candidate (otherwise "not applicable: CPU path"). Only work outside the claim may stay open: SWF-009 and M7 (mainnet), SWF-013 (the synthetic-rollup B rows on FSYN data: mandatory for the synthetic-rollup gates, outside the C4 closure by owner decision 2026-11-08 (2)), the `/2` profile, financial and generic-ADT extensions. An explicitly open or unexecuted applicable gate does not make the change complete (astra-2, astra-3). The Mainnet operation (`SWF-009`) is specified here and executed only on owner authorization after `openspec/MORIARTY-COMPLETION-PROGRAM.md:269` is amended. The amendment was made on 2026-11-08 (`:270-283`): each mainnet operation still needs its preconditions and an explicit owner authorization when it runs.
