## 2. VM design

### 2.1 Machine model (unchanged)

The source fragment is literals, variables, let, checked UInt128/Bool primitives, conditional, named call, constructor and ordered match (`design.md:11`). State is control, environment, ordered frames, values, outcome, fuel and counters (`interfaces.md:55-88`). A step is one owner-engine event; helpers in `/1` are explicit bounded microsteps with cursors (`interfaces.md:92-96`). Outcomes: `Running | Halted(v) | Rejected(code) | Exhausted(kind)`. Error codes 4 (frame cap), 9 (no match), 10 (checked arithmetic) are fixed (`interfaces.md:7`).

Physical layout `sherlock-c6-phys/1`: image header 48 lanes, control 17 lanes, frames 13 lanes each bottom-to-top, sections META/PROG/CTX/IMAGE/DATA/HELPER (`c6_phys.rs:1-30`, `c6_phys_host.rs:1-30`). `StepInv` holds between canonical boundaries: data arena append-only and child-before-parent, frames and helper slots zeroed on release, inactive fields zero (`interfaces.md:177-193`). `decodeCanonical` only at genesis, `ChunkStore`, checkpoint resume and external claims; `decodeStep` mid-run. Internal microsteps preserve `StepInv` without canonical projection (astra-2 SND-002; `security-candidate-b.md:A4`).

### 2.2 Dispatch (one-hot)

Today the dispatch owner emits a block for one constant `RuleIdC` and each fragment is its own circuit. In the universal leaf the dispatch is computed once per step:

1. Inputs: the pre carriers (IMAGE, HELPER, DATA where a value read is gated on, PROG via the parser walk, CTX).
2. Derivation, in the order Core uses (`c6_dispatch_step.rs:9-16`): P0 `outcome == Running`; P1 publication (`Error` control -> `KAdminPublishError`; `Return` at depth 0 -> `KAdminPublishValue`); P2 `remaining_work == 0` -> `KAdminPublishExhausted`; else `owner_select` over helper group, result-reading rule, helper plan entry, legacy group.
3. Output: a one-hot vector `sel[r]` over the supported rule set `R` with `sum(sel) == enable` and each `sel[r]` boolean; `sel[r] == 1` iff rule `r`'s guard path holds. Guard paths include every value read the current per-rule blocks make (for example `equal_differ` reads UInt/Bool/type/constructor values, `c6_dispatch_step.rs:750-806`).
4. Every fragment `F_r` is emitted once and gated: its constraints are multiplied by `sel[r]`, and it produces a candidate post image `cand_r` in which lanes outside its declared write set equal the pre lanes. The step's post image is the selection `post = sum_r sel[r] * cand_r + (1 - sum_r sel[r]) * pre`. Inactive fragments therefore never constrain the shared post image (astra-2 early correction: a `post == pre` constraint under `1 - sel[r]` would block the selected fragment's writes). Test: two rules with differing write sets on the same class, valid differing writes accepted.
5. Two cases are distinct. A *disabled slot* (`enable == 0`, used for padding a short chunk) accepts the constrained identity `post == pre` and contributes zero to `steps`. An *enabled* step whose Core selection is outside the supported set (extension, financial, `XAdtHelperPlan*`, `XAdtHelperBuild*`; `dispatch_supported`, `c6_dispatch_step.rs:29-32`) has no `sel` bit, so `sum(sel) == 0` with `enable == 1` and the leaf refuses (SVM-004).
6. `rules_d` (D5) is the Poseidon digest of the S selected rule ids in order; for S=1 it is the rule id lane the node calls `rule`. The leaf derives `rules_d` and `steps`; `h_pre` is bound by the node to the bounded previous height, not by the leaf (astra-2 lane ownership).

Soundness premises carried from the per-rule design: canonicality of the pre IMAGE/HELPER/DATA sections is enforced by the gated fragment on the same lanes; PROG canonicality by the parser walk. Putting dispatch and fragments inside one key makes the "caller obligation" at `c6_dispatch_step.rs:34-38` checkable, not discharged: SAS-010 requires, for every admitted rule, evidence that `StepInv` is initialized at canonical genesis, preserved by the gated fragment under `StepInv(pre)`, and that every fragment premise refers to the shared carriers (no disconnected copies). Task 4.6 covers initialization as well as hostile transitions (astra-2).

### 2.3 S-step leaf

A leaf proves `S >= 1` consecutive owner steps on one key. Inside the leaf: `pre_0` is the digested `pre_d`; for `i < S-1`, `post_i == pre_{i+1}` lane by lane; `post_{S-1}` is digested as `post_d`. `steps` is the number of *enabled* owner-step events in the leaf; a short final chunk pads with disabled steps (`enable == 0`, identity on lanes, zero contribution to `steps`). Terminal: a step that publishes (`Halted`, `Rejected`, `Exhausted`) is the last enabled step; later slots are disabled. Charged work and fuel stay inside the state digest; `steps` and `h` are physical counts (ISSUE 5).

S is a keyed constant chosen once at gate G-A (amended 2026-11-08 (3); SRC-014): the rule is `k_U + log2 S <= 20`, with `k_U` the rows of the universal leaf at S=1 (task 4.1, modeling only), so S=8 at `k_U <= 17`, S=4 at `k_U = 18`; S=1 is the one-enabled-slot case of the same relation, not a separate baseline. The leaf is built with S slots (4.2) and keyed once (4.4). With one step per leaf fact(3) is about 293 node proofs at about 95 s each (`stagenet-gp-recursion.md:199-201`); S=8 gives 37 (ESTIMATE 37 x (95 + 47) + 100 = 5,354 s = 1.49 h serial at k_U = 16 and node k=20; `prover.md` §3). Leaf rows grow about S-fold (`k_leaf = k_U + ceil(log2 S)`), prove time about S x t_step, RSS about S x RSS(k_U); the leaf's private witness holds S copies of the carriers; the measured leaf k, time and RSS at the chosen S are recorded at 4.4 (row A20) and the cap is 16 GB per leaf prover so two or three leaf workers fit beside the node under the 100 GB aggregate (open question Q4).

### 2.4 Identity and configuration

`prog_d = Poseidon(dom, programImageDigest, layoutSchemaDigest, boundsDigest, profileId)` where the layout schema digest covers `sherlock-c6-phys/1`, `LayoutSchema.recordWidths`, the qualification host config (frames, data, env, value slots) and `Bounds`. A program image under a different layout or caps therefore has a different `prog_d`, and `SherlockRun` seals `program_d` (`sherlock-run.compact:26-47`). This replaces a separate `cfg_d` lane (fable-2 I4; fable-2 critique concession).

Leaf key identity (manifest): relation id `sherlock-leaf/1`, `sherlock-leaf-stmt/1`, layout schema digest, `Bounds`, ZKIR version (minor read from the compiled `.zkir`), `midnight-zk-stdlib`, `midnight-circuits`, `midnight-proofs` versions, SRS identity, k. The node and decider manifests add the leaf VK digest and the node VK digest respectively (SRC-008).

### 2.5 Host interface

`mori simulate` runs the owner engine; `capture(&admitted, &image)` yields a `HostSnapshot` per step; `witness_from_host_snapshot` builds the C6 witness; the witness stream `moriarty-sherlock-c6-witness-stream/1` carries witness, `RuleIdC`, `h_pre`, and digests `prog, init, pre, post` with their `StateOutcome`s (`sherlock_c6_witness_stream.rs`). The stream is the only *application* producer for the leaf prover and the digest-parity test (`sherlock_digest_parity`, commit `3c2657acb`). It is not the oracle: the holdout keeps its independent expected traces (`models/sherlock/oracles/`, `qa/holdout/`) and the hostile-witness suites keep raw witness entry points that bypass the stream (astra-3 early correction). `HostSnapshot` never appears in a public statement; the host supplies private witness only. The public digests `prog_d`, `pre_d`, `post_d` are permitted statement components because the circuit constrains them to the actual witness. Host checks (`checkStepInv`, `ProofPreimage::check`) are diagnostics with no acceptance authority (UISEC-012).

### 2.6 Fragment coverage

Gaps at `8fd34ed79`: `KAdminPublishValue`, `BHelperValidate` x4, `BHelperEqual` x4, `BHelperMatch` x10, `BHelperScalarConstruct` (`stagenet-gp-recursion.md:224-243`). WIP source exists (`36456d510`, `5d7663275`) with `native_inventory.rs` rows still `gap(...)`.

Order (astra-1 early correction, avoids the P3 circularity): first freeze the *admitted rule inventory* `R` for profile `/1` (every supported pure rule, not only the rules P1 and P2 fire), the layout, the caps and the manifests; every rule in `R` has a fragment with a compiled-and-run receipt before the universal leaf is keyed (D9); then P3 is authored from the admitted domain and must need no new key (E2). P1/P2/P3 evidence is finite cross-program evidence, not a proof that every admitted program is sound; the per-rule obligations in `assurance.md` stand beside it.

## 3. Recursion design

### 3.1 Chain

```
owner run -> witness stream -> LEAF (sherlock-leaf/1, S steps, stmt/1 seven lanes)
          -> NODE N (ivc.rs, self-recursive; [vk_N_repr, prog_d, init_d, cur_d, h, acc])
          -> RUN DECIDER D (run_decider.rs; values [prog_d, init_d, fin_d, n_steps, result_be]; Blake2b)
          -> SherlockRun.acceptRun(stmt, p, i, n, fin, r)  (Compact 0.36.0; decider VK installed)
```

Measured at `8fd34ed79` pins: one C6-shaped digest leaf with 96 private lanes (M2, not `standin.rs`) k=13, 2.55 s, 3,824 B; node k=20, 531,989 rows (7,701 over 2^19, 1.47%), ~50 s keygen, ~95 s/step, 26.2 GB; decider k=20, 833,235 rows, ~100 s, 70 lanes mutation-refused (`stagenet-gp-recursion.md:184-201`). These numbers are re-measured at the new pins (M2). The primary path (2026-11-08 (3)) is this chain with S-batched leaves and 2-3 parallel leaf workers proving ahead of the node chain under the 100 GB aggregate cap (`prover.md` F11: leaves are independent, so with P workers `T ~ max(N x t_node, N x t_leaf / P) + t_node + t_decider` and the wall is the node chain alone while `k_U <= 17`). The tree node of D13' is the measured alternative for the node layer; both are instances of the aggregation model of §3.6, so the statement, decider and `acceptRun` are the same.

### 3.2 Node fixes before new keygen (SRC-003, SRC-004, SRC-005)

1. Range checks: `prev_h`, `steps`, `h < 2^64` with `assert_lower_than_fixed` (pattern `parent.rs:665-670`); today only `steps != 0` and field addition (`ivc.rs:308-310`). Done 2026-11-09 (task 2.3, `ivc.rs` `constrain_heights`): `prev_h < 2^64`, `steps - 1 < S_MAX` (so `1 <= steps <= S_MAX`, `S_MAX = 16` a relation constant), `h = prev_h + steps < 2^64`.
2. Genesis: `is_genesis = is_zero(prev_h)`; require `prev_d == init_d` (exists, `ivc.rs:312-313`). Today `proof_acc` is scaled by `not_genesis` (`ivc.rs:343`) while the witness-supplied `prev_acc` is folded unscaled (`:318-327,364`). The normative requirement is UISEC-010: no unauthenticated deferred obligation at genesis. The implementation must either (a) constrain the supplied carry to the designated neutral encoding at genesis, or (b) constrain a zero/ignore construction (scale `prev_acc` by `not_genesis`) and justify that it cannot authorize an invalid leaf or predecessor. Tests match the chosen semantics: non-neutral refusal for (a); semantic irrelevance of a well-formed ignored carry for (b), without requiring identical folded bytes (ignored inputs may still alter transcript encodings); and invalid-leaf refusal through the final pairing for both. Retaining an unscaled supplied carry requires a separately recorded security argument. The target implementation hashes accumulator encodings before deriving folding powers (`circuits/src/verifier/accumulator.rs:177-192,315-343` at `24a1eb5a`, astra-2); this is a transcript observation, not a proof that cancellation is impossible. Malformed point-encoding refusal is classified at its actual boundary. No practical attack was demonstrated; this is hardening (astra-2, fable-2).
   **Chosen 2026-11-09 (task 2.3, node `SHKIVC06`): realization (a).** The node computes the public encoding of the carried accumulator once (`verifier.as_public_input`, the same lanes `prev_pi` absorbs and `accumulate` hashes at `midnight-circuits 7.3.0`, `verifier/accumulator.rs` `AssignedAccumulator::accumulate`) and constrains `is_genesis * (lane - neutral) == 0` for every lane, `neutral` the encoding of `trivial_acc` (`ivc.rs` `constrain_genesis_neutral`); the host `next_acc` refuses a non-neutral genesis carry too. Why (a): it is cheap (one multiply-add and one zero assertion per lane, about 60 lanes, no new MSM; the carry check measures 2,106 rows with the carried accumulator assignment, while a second `collapse` of `prev_acc`, as realization (b) would need, is a variable-base MSM like `collapse_self`, which measures 239,577 rows), it needs no new security argument, and it removes the hash from the argument entirely: at genesis the carry and the collapsed scaled `proof_acc` both equal `trivial_acc`, whose MSMs are the identity on both sides, so the folded value is `r^2 * leaf_acc` plus identity terms and the pairing holds iff the leaf's does (for `r != 0`), while the fold challenge is a function of the leaf alone (no grinding freedom). Model match: the Quint F20 `accOf` folds no carry for a genesis node (`al = []`); the circuit folds `[trivial, trivial, leaf]`, which equals that fold up to neutral terms. Lean (council fixes, `bd7703f4d`): the node fold is `AccAlgebra.nodeFold b p c l = collapse (accumulate [collapse (scale b p), collapse (scale b c), l])` and the genesis lemma is `genesis_collapse_both` (it replaces `genesis_scale_by_bit`). The circuit realizes `nodeFold` on every accepted witness: `p` is scaled by `not_genesis` and collapsed (`collapse_self`); `c` is constrained to collapsed form at every height (scalar one per side, `constrain_collapsed_carry`, so `collapse c = c` and no second MSM is needed) and to the `trivial_acc` encoding at genesis (`= collapse (scale false c)` by `collapse_scale_false`); the fold and the final collapse are the same. The range checks are the contract of `src004_height_bridge` (raw `prev_h`, `steps`, `h` below 2^64, `1 <= steps <= S`), and the linear node statement maps to the F21 chain by `lin_refines_chain`. Malformed carry encodings are refused at their decoder boundary (`acc_from_lanes`, decoder evidence only).
3. Leaf lanes: `rules_d` and `steps` are constrained inside the leaf (equated to the dispatch selector digest and the enabled-step count), not merely published (`sherlock_c6_child.rs:598-608`); `h_pre` is bound by the node to its bounded previous height.
4. `h_post = h_pre + steps` as bounded integer addition; the decider's `n_steps` equals the final `h`.

### 3.3 Decider and contract

The decider verifies the last node proof, pins `vk_N_repr`, folds and pairs the accumulator, opens `cur_d = Poseidon(SHK_SD, HALTED, result, lanes_d)` and binds `values`. The outcome tag and result are derived from the proved state, not supplied as constants (astra-2 SND-004; `sherlock_c6_child.rs:560`). `acceptRun` reads sealed `program_d` and `init_d`, refuses replay of `stmt`, writes `result` as big-endian `Bytes<16>` (`sherlock-run.compact:26-47`). The acceptRun transcript template (70 slots, `tests/fixtures/run-template.json`) is recaptured with Compact 0.36.0 / runtime 0.21.0 and diffed against `template.rs` (SMN-003).

### 3.4 Leaf shape decision (SRC-013)

Milestone M4 (task 4.4; the historical measurement label "M2" in `docs/sherlock/stagenet-gp-recursion.md` is a different numbering) measures the universal gated leaf (dispatch + every fragment of the frozen inventory `R`) at S=1: k, rows, RSS, keygen and prove time. If k <= 17: option U. Otherwise option F: each rule its own `IrSource` under a forced uniform `ZkStdLibArch` and k, the node checks the child's `transcript_repr` against a committed family table in-circuit (authenticated membership), and E2 holds because the table is fixed before P3 is written. Option F is defined for S=1; a mixed-rule chunk under F needs a separate constrained construction before S>1 is adopted there (astra-3). Both branches carry identical semantic obligations and the same seven-lane statement.

### 3.5 Throughput (SRC-011 mandatory, SRC-015, SRC-016; amended 2026-11-08 (3))

Target: a committed program of at most 320 owner steps proves its leaves, folds, decides, passes `verify_chain` and `validate_call` in under 2 h wall, 48 GB peak per process and 100 GB aggregate peak on the 20-core 120 GB host; a shortfall is a failing row (SRC-011). ### 3.6 One general aggregation model (SRC-017; owner: "It has to be general purpose recursion")

Segment composition is modeled once; the linear chain is the degenerate tree. A segment claim is `(prog_d, pre_d, post_d, h_lo, h_hi)`; a leaf certifies `(prog_d, pre_d, post_d, h_pre, h_pre + steps)` with `1 <= steps <= S` and disabled slots the identity; `link a b` is defined iff `a.post_d = b.pre_d`, `a.h_hi = b.h_lo`, `a.prog_d = b.prog_d`, and gives `(prog_d, a.pre_d, b.post_d, a.h_lo, b.h_hi)`; the identity segment `(x, x, h, h)` is its unit; the linear node is `link(carried, leaf)`; the tree node is `link(link(L, leaf), R)` with each slot optional. The decider accepts a root iff `pre_d = init_d`, `h_lo = 0` and `post_d` opens as a halted state. One fixed key set serves every program and step count: the node is self-recursive under its own key (`ivc.rs:295-301`), S is a keyed constant, depth is not a circuit parameter and the accumulator encoding is fixed-size at every level. The accumulator fold is sound for any grouping but its challenge depends on the grouping, so the shape (the fold order) is committed in the hash-bound manifest and replayed by `verify_chain` (`tree.md` F3, risk 4).

Formal targets, merged from `tree.md` §4 and `prover.md` §6b, placed per `order.md` §1b: Quint `models/sherlock/quint/aggregation.qnt` + `aggregation_test.qnt` (constants `TREE`, `S`; actions `leaf`, `fold`, `join` (guarded by `TREE`), `pad`, `decide`, `accept`, `schedule`, adversarial `forge_link`, `reuse_leaf`, `swap_children`, `empty_node`, `shape_mismatch`, `replay`; invariants I1 linkage, I2 height monotonicity and additivity below 2^64, I3 exactly-once coverage, I4 identity and padding neutrality, I5 schedule independence, I6 genesis uniqueness, I7 replay, I8 program fixity, I9 shape binding, I10 liveness witness for every L in 1..9 and every bracketing, plus fixed keys and Q-C the leaf-worker scheduler under the 48/100 GB caps; one seeded mutant per invariant; run with `TREE=false` and `TREE=true`, S in {1, 2, 4, 8}) -> row F20. Lean `clean/fork/Clean/Sherlock/Aggregation.lean` + `AggregationAxioms.lean` in `SherlockSpec` (Lean v4.33.1, installed 2026-11-08; `Step` the reference machine's step relation as a parameter, `digest` injective on the carrier domain as a premise, in-circuit verifier, accumulator and pairing as premises): L1 segment soundness for every program ("the root statement implies a valid execution of the general machine for every program", structural induction on `NodeCert`), L2 associativity of `link` with the identity as unit, L3 padding neutrality, L4 exactly-once coverage, L5 height arithmetic without wrap (`prev_h < 2^64 - S`, `1 <= steps <= S`; and that the weaker pair without the `h` check is insufficient), L6 decider pinning, L7 independence from shape and depth, L-D the genesis scale-by-bit lemma, L-E `assert_lower_than_fixed` for a non-power-of-two bound, L-C statement independence from S -> row F21 (`scripts/qa/check-lean-aggregation.sh`: `lake build SherlockSpec`, zero `sorry`, `#print axioms` within the premise file). ### 3.7 GPU track (SRC-018; owner: "you'll have to build one in rust. Search online for CUDA rust kernels for these things")

Design source: `research/sherlock-speed-replan-20261108/gpu.md` (aligned 2026-11-08; this section summarises it and gpu.md governs where they differ). Host facts measured there (§0): RTX Spark N1X, sm_121 (cc 12.1), 48 SMs x 128 = 6,144 cores, L2 24 MB, unified LPDDR5X (273 GB/s nominal, 244 GB/s read+write measured) shared with the CPU; `integrated=1`, `pageableMemoryAccess=1`: kernels address plain `malloc`/`Vec` memory with no copy; **device allocations are process RSS** (`cudaMallocManaged` 1 GiB touched on the GPU: RSS +1.3 GB, `MemAvailable` -1.2 GB; `cudaMalloc` 1 GiB: RSS +1.0 GB), so a cgroup `MemoryMax` already caps them (answers Q10 and `order.md` §7 Q4); u32 `mad` 7.36 T/s against u64 `mul`+`mulhi` 0.54 T pairs/s, so **kernels use 32-bit limbs** (Fp 12 x 32, scalar field 8 x 32, `mad.lo.cc`/`madc.hi.cc` chains). Driver 615.78.08, nvcc 13.4 V13.4.92 at `/opt/cuda` (installed by owner approval 2026-11-08), `compute_121` listed. CPU baselines on this host: BLST `multi_exp` 2^20 at 20 cores 0.51 s (39 ms of it the projective-to-affine batch conversion); `best_fft` over the scalar field 2^20 60-78 ms, 2^23 468-544 ms at 20 threads.

Route (gpu.md F1, §2, ranked): a Rust crate `crates/mori-gpu` (main workspace member; feature `cuda` default off; no `midnight-proofs` dependency) whose `build.rs` runs nvcc 13.4 (`-gencode arch=compute_121,code=sm_121`, plus `compute_120` PTX for portability; `MORI_GPU_ARCH` overrides) over a small CUDA C++ core (`cuda/field.cuh`, `curve.cuh`, `msm.cu`, `ntt.cu`, kept under about 2,000 lines) into a static library linked with `cudart`; the algorithm, dispatch, SRS cache, fallback, receipts and tests are Rust. Every pure-Rust kernel route is blocked on sm_121 today (Rust-CUDA needs a nightly and libNVVM; cuda-oxide 0.3.0 lists sm_80..sm_120a and has no mul-hi; CubeCL is alpha; rust-gpu/wgpu have no u128); a port of the kernels to one of them, with the same tests and hooks, is the migration target once one verifies sm_121 with u64 `mul_hi` on stable (gpu.md Q7). The owner's "build one in Rust" is met by owning the whole backend in a Rust crate with a small, tested CUDA core; `cudarc` is optional (NVRTC, stream wrappers), not required. Kernel sources: sppark's field, XYZZ curve and NTT templates (Apache-2.0) and the Yrrid/Snarkify ZPrize-2023 BLS12-381 MSM plan (MIT/Apache-2.0: signed 22-bit windows, sorted buckets, precomputed multiples); fallbacks ICICLE **v2.8.0 tag** (MIT) and ec-gpu (MIT/Apache), headers preserved. **Excluded**: ICICLE v3+/open-icicle CUDA backends (closed or conflicting licence), polytope-labs/gnark-cuda and the td-kwj WebGPU MSM (no licence file), Nocy's proof server (no licence), Snarkify's ZPrize-1B code (MPL-2.0). sppark and ICICLE enter as borrowed template source with attribution, never as crate dependencies (sppark declares ARM64 GPU hosts unsupported; ICICLE's current backend is licence-server gated).

Integration (gpu.md F6, §3): `msm_specific` and the `EvaluationDomain` transforms are free functions with no trait seam, and `KZGCommitmentScheme<Bls12>` is baked into the keys and gadgets, so the seam is two registries in a patched `midnight-proofs 0.8.3` (`hooks::MSM_G1: OnceLock<fn(&[Fq], &[G1Projective]) -> G1Projective>`, `hooks::FFT_FQ: OnceLock<fn(&mut [Fq], Fq, u32)>`, about 60 lines, inert when nothing is registered; `Fq`/G1 specialisations only). The patch lives in a **separate workspace `tools/gpu-prover/`** (own `Cargo.lock`, vendored `vendor/midnight-proofs-0.8.3-gpu` = registry 0.8.3 + `patches/gpu-hooks.diff`, SHA-256 checked, `[patch.crates-io]` local to that workspace; the shape of `tools/profile/`), because a `[patch.crates-io]` in the main `Cargo.toml` would rewrite `Cargo.lock` for every consumer of `midnight-proofs 0.8.3` (RPP-007; `order.md` §5.8). Its `heavy --gpu` entry calls `mori_gpu::install()` to register the hooks and then the same mori-recursion / mori-backend APIs as the CPU path. The main workspace keeps the registry crate; `scripts/qa/check-profile-isolation.py` is extended to the second vendored copy. Fallback has three levels (compile-time `cuda` off; init-time `cudaGetDeviceCount` fails or `MORI_GPU=off`; call-time `n < 2^MORI_GPU_MIN_K` (default 14) or a kernel error), each with the CPU result and a `fallbacks` count in the receipt; the GPU is never a correctness dependency. Receipts: `runs.jsonl` rows gain `gpu: {arch, driver, toolkit, msm_calls, ntt_calls, fallbacks, device_bytes_peak}`. Per GPU prover the device-side footprint is 1.5-2.5 GB (affine SRS tables 2 x 96 MB at k20, optional precompute up to 1.5 GB, NTT scratch 2 x 256 MB, MSM scratch ~0.3 GB, twiddles 0.13 GB, context ~0.3 GB), counted inside the 48 GB cap and the 100 GB aggregate; concurrent `heavy --gpu` processes take `gpu.lock` or share by time-slicing (measured at G6). General-purpose rule: the backend takes any `n <= SRS size` and any `log_n <= 32`; nothing in it knows the program or the circuit; the SRS cache is keyed by content.

Bit-identity (gpu.md F5, §0): points reach the transcript as 48-byte compressed encodings, so for the MSM "bit-identical" means **group equality** with BLST's result, checked on `to_affine()` and compressed bytes (different projective (X, Y, Z) for the same point is fine); the NTT must be bit-exact per element; proof bytes must be equal. Edge classes: identity point as base and as result, zero scalars (filtered before the call, but accepted by the kernel), duplicate bases (the XYZZ mixed add is incomplete at P = Q and must branch to a doubling), the signed-digit exceptions (digit -2^(c-1), top-window carry, scalars 1 and r-1), projective bases with Z != 1, and host- versus device-resident inputs (the ICICLE/gnark Montgomery-chunking bug class). If the prove API draws blinding from `OsRng` only, A27 degrades to "verifies and every commitment equal given logged blinding", stated in the receipt (gpu.md Q4); a seedable RNG entry through the test harness is preferred.
