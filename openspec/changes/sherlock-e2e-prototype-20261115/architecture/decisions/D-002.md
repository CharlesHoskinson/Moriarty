# D-002: Zero knowledge end to end

- Status: accepted
- Authority: OWNER
- Legacy IDs: GP-ZK; ZK-001 to ZK-019; T11-1 to T11-4; memory rule 2026-11-11

## Context and Problem Statement

A proof that leaks the witness, the program or the run shape has no use for a private ledger.

## Decision Drivers

- Owner 2026-11-11: "we need to make this zero knowledge or else its useless".
- GP-ZK (processor-final).
- T14 m7 finding: the CPU and CUDA STARK backends have no PCS masking (LOOP.md row T11).

## Considered Options

- Every STARK layer on boxes the user owns; the only published proof is the blinded wrap; seeded proofs test-only; no plain witness to a helper.
- PCS masking in every STARK layer so that STARK proofs can leave the box.

## Decision Outcome

The first option. `r_P` is fresh per deployment, the salt per run, blinders per proof; a build with feature `test-seed` refuses production proofs.

Authority: OWNER. Owner ruling 2026-11-11 (hard rule). The T11 picks T11-1 to T11-4 were confirmed by the owner on 2026-11-15 (wiki log 09:04).

### Consequences

- Good: The privacy claim does not depend on a helper.
- Bad: Proving capacity is limited to the user's boxes.

## Confirmation

- outcome: ZK-015 (EQ-ZK), ZK-014 (seeded build refuses), ERS-002 (T-PRIVATE-RECORDS). Status: planned unless the cited requirement reads MEASURED.
- conformance: ZK-012, ZK-013, ZK-016, ZK-017, ZK-019 (ZK-L2 in Lean); slice B ZKE requirements. Status: planned unless the cited requirement reads MEASURED.

## Pros and Cons of the Options

### Every STARK layer on boxes the user owns; the only published proof is the blinded wrap; seeded proofs test-only; no plain witness to a helper

- Good: The published view is the call vector and one blinded proof.
- Bad: No outsourced proving until case B is designed (D-010).

### PCS masking in every STARK layer so that STARK proofs can leave the box

- Good: Helpers become possible.
- Bad: Not built; cost not measured.
