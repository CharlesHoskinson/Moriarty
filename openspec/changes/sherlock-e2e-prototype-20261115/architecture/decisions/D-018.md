# D-018: Every proof is a fixed-size shard

- Status: accepted
- Authority: OWNER
- Legacy IDs: hard rule (LOOP.md line 102); CPR-002

## Context and Problem Statement

A circuit that grows with the run length makes a key depend on the run.

## Decision Drivers

- CPR-002 (processor-final).
- GP-001: no circuit constant bounds the run length.

## Considered Options

- Fixed-size shards; work grows by adding shards.
- Variable-height proofs.

## Decision Outcome

Fixed-size shards.

Authority: OWNER. Owner hard rule (LOOP.md line 102). The brief of this change does not list it; LOOP.md does.

### Consequences

- Good: One proof size for every batch count (T19).
- Bad: Short calls pay the fixed height.

## Confirmation

- outcome: T6 fixed shard heights (LOOP.md row T6); LPC-007. Status: planned unless the cited requirement reads MEASURED.
- conformance: CPR-002; slice B LFP and NAG requirements. Status: planned unless the cited requirement reads MEASURED.

## Pros and Cons of the Options

### Fixed-size shards; work grows by adding shards

- Good: Keys do not depend on run length.
- Bad: Padding cost on short runs.

### Variable-height proofs

- Good: Less padding.
- Bad: Refused by the hard rule.

## More Information

### Reconsideration

The owner changes the rule.
