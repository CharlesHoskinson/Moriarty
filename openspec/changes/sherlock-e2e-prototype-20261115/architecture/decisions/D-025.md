# D-025: processor-final governs where the older universal-interpreter change conflicts with it

- Status: proposed
- Authority: LEAD PICK for T15
- Legacy IDs: UIREQ-001 to UIREQ-035; Astra-A review R-05

## Context and Problem Statement

Change `sherlock-universal-interpreter-design` holds 35 requirements of an earlier interpreter design. LOOP.md names processor-final and modular-leaf as the build plans.

## Decision Drivers

- LOOP.md line 3.
- EUI-009.

## Considered Options

- processor-final governs a demonstrated conflict; every other UIREQ requirement stays in force by reference until a retention map rules on it.
- Retire the whole UIREQ set.
- Merge UIREQ into this change.

## Decision Outcome

The first option. No UIREQ requirement is retired by this change.

Authority: LEAD PICK for T15. LEAD PICK for T15.

### Consequences

- Good: COVERAGE.md maps the universal interpreter to EUI, CORE, RFB, GP-001 and the retained UIREQ set.
- Bad: The ID-by-ID map does not exist yet (gap, slice A, task A19).

## Confirmation

- conformance: EUI-009 (the UIREQ retention map). Status: planned unless the cited requirement reads MEASURED.

## Pros and Cons of the Options

### processor-final governs a demonstrated conflict; every other UIREQ requirement stays in force by reference until a retention map rules on it

- Good: No language behaviour is lost.
- Bad: The retention map is work.

### Retire the whole UIREQ set

- Good: One governing text.
- Bad: UIREQ-003, 004, 005, 008, 014 and 016 define language behaviour with host tests and no replacement in EUI.

### Merge UIREQ into this change

- Good: Self-contained.
- Bad: Restates 35 requirements (against D-026).

## More Information

### Reconsideration

The retention map finds a conflict that processor-final does not settle.
