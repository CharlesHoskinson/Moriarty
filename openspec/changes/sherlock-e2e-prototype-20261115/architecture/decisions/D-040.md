# D-040: The daemon keeps OD-13: one-use blinding slots; the slot pool is to build

- Status: accepted
- Authority: OWNER
- Legacy IDs: OD-13; PRD-002; ZK-016; T11-2

## Context and Problem Statement

OD-13 (owner decision 2026-11-12, `research/sherlock-final-design-20261111/DECISIONS.md:27`) reads "required, local socket, one-use slots". PRD-002 and ZK-016 describe a pool of one-use blinding slots. The daemon as built draws fresh `OsRng` blinders for each proof and has no pool (Moriarty `t14b` 5e54263da `tools/sherlock-wrap-gpu/src/serve.rs:114`). Slice B first proposed to amend the pool obligation for the prototype. The lead ruled on 2026-11-15 that a LEAD PICK cannot override an owner decision, so this record keeps OD-13 as stated.

## Decision Drivers

- OD-13 (owner).
- D-002 (zero knowledge end to end).
- PRD-002, ZK-016, PDM-005, PDM-009.

## Considered Options

- Keep OD-13 and PRD-002 as stated; record the missing pool as work to build.
- Amend PRD-002 for the prototype to a per-proof draw with no pool.

## Decision Outcome

OD-13 stays as the owner stated it: a resident daemon, a local socket, one-use slots. PRD-002 and ZK-016 stay in force unchanged. The blinding-slot pool is not built: it is a TO BUILD gap with owner lane T11 (`t11-zk`). The per-proof draw of the built daemon (PDM-005) is the present state of the code, not a replacement of the pool obligation. Cross-request isolation holds without condition (PDM-009).

Authority: OWNER (OD-13, 2026-11-12). Lead ruling 2026-11-15: a LEAD PICK does not depart from an owner decision. Owner question for T15, not decided here: does a per-proof draw inside the daemon, with no blinder stored before or after a proof, satisfy "one-use slots", or is the pool itself required?

### Consequences

- Good: The owner decision and the requirement text stay as written.
- Bad: The code and PRD-002 differ until the pool is built or the owner answers the T15 question.

## Confirmation

- conformance: PRD-002 and ZK-016 (one-use slots; a slot is never serialized off the machine; a helper slot is refused). Status: planned; the pool is to build (lane T11).
- outcome: PDM-005 and ZK-015 by `eq_zk` through the daemon (planned); PDM-009 by `slot_reuse` (planned).

## Pros and Cons of the Options

- Good: No owner decision is changed by a lead.
- Bad: The pool is work on the T11 lane.

### Amend PRD-002 for the prototype

- Good: The requirement text would match the code today.
- Bad: It departs from the letter of OD-13 without the owner.
