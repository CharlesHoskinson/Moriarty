# D-017: R_SL is chip set 3: 16 rules lowered to micro-op AIRs in a 6-or-9 AIR bucket

- Status: proposed
- Authority: LEAD PICK for T15
- Legacy IDs: RSL-002; MYC-CHIP-001; CF-005; ARCHITECTURE.md 1.7; rekey list

## Context and Problem Statement

Three texts list the R_SL rules: ARCHITECTURE.md 1.7 (about 14, an estimate), MYC-CHIP-001 (11 plus one per builtin) and the code (16 rules in `compile::RULES`). The universal leaf verifier sizes its proof-shape encoder by the child AIR count.

## Decision Drivers

- D-004: every app key must fit the universal leaf.
- rsl probe at 2b59f9b: a05 with 10 AIRs gave a different leaf key (`trace.rs:4-10`).
- EKT-001, EKT-002, ECC-005.

## Considered Options

- Micro-op AIRs WORD, ALU, PUBLIC, RANGE, SHA_IN plus one hash group; at most 8 app AIRs; rule table of 16 rules with digest `rules_d`.
- Rule rows of the slice CORE through DEC.

## Decision Outcome

The built design at openvm `rekey-chips` dcf1b4c. The code table is the proposed machine encoding; the other two lists are superseded when the owner confirms it. Open inside this record: secp256k1 has no rule name in the table (`R_SL_SECP` is a counter, `compile.rs:818-819`); the lane names the rule or states the micro-op path before T25.

Authority: LEAD PICK for T15. Two scopes. Confirmed by the owner on 2026-11-15 (wiki log 09:04, "Ye sif you recommend it" for the single rekey list): the rekey holds R_SL chip set 3 with its kits and SHA_IN always present. Not yet seen by the owner: the exact 16-rule table and the micro-op lowering as the machine encoding. That part is LEAD PICK for T15 (rekey-chips lane, `src/rsl/mod.rs:5-11`).

### Consequences

- Good: Compact programs prove under the universal leaf.
- Bad: The app key is per program and up to 16,346 columns (LIST.md:30).

## Confirmation

- outcome: RSL-001, RSL-002, EKT-002 (`rsl_air_count_in_universal_leaf_bucket`). Status: planned unless the cited requirement reads MEASURED.
- conformance: EKT-001 (T-RULES-D), ECC-005 (T-CHIP-RULES). Status: planned unless the cited requirement reads MEASURED.

## Pros and Cons of the Options

### Micro-op AIRs WORD, ALU, PUBLIC, RANGE, SHA_IN plus one hash group; at most 8 app AIRs; rule table of 16 rules with digest `rules_d`

- Good: One universal leaf key for every R_SL app (RSL-001).
- Bad: One hash family per program (D-024).

### Rule rows of the slice CORE through DEC

- Good: One chip model for both families.
- Bad: An R_SL step has no 476-word state, so its DEC row has no requester (`src/rsl/mod.rs:5-11`).

## More Information

### Reconsideration

A suite program needs more than 8 app AIRs, or T25 changes the leaf encoder.
