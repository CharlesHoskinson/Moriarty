# D-009: Midnight writes are batched

- Status: accepted
- Authority: OWNER
- Legacy IDs: T20; memory rule 2026-11-14

## Context and Problem Statement

One chain write per event does not scale.

## Decision Drivers

- Owner order 2026-11-14: one root per checkpoint; item data off chain.
- T20 results (branch `t20-batched` 5dc1be2ee).

## Considered Options

- `acceptCollection` per epoch, claims by membership against `claims_root`; `acceptRun` kept for a user's own run.
- One `acceptRun` per item.

## Decision Outcome

Batched writes.

Authority: OWNER. Owner order 2026-11-14.

### Consequences

- Good: Transaction count per item falls with the batch size.
- Bad: Data availability is a stated dependency.

## Confirmation

- outcome: T20 Quint models with mutants; slice C BAT requirements. Status: planned unless the cited requirement reads MEASURED.
- conformance: LPC-010 (merge of `t20-batched`). Status: planned unless the cited requirement reads MEASURED.

## Pros and Cons of the Options

### `acceptCollection` per epoch, claims by membership against `claims_root`; `acceptRun` kept for a user's own run

- Good: One write per epoch for operator jobs.
- Bad: Consumers wait for the epoch.

### One `acceptRun` per item

- Good: Simple.
- Bad: Refused by the owner for operator jobs.

## More Information

### Reconsideration

The owner changes the rule.
