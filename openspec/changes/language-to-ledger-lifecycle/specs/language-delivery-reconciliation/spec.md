## ADDED Requirements

### Requirement: Scoped merged capability status
The roadmap SHALL identify PR1 computed funded repayment, PR2 source-defined schemas, PR3 multiple named actions and PR4 financial state reads as implemented and tested local capabilities. Each entry SHALL cite its commit, exact audit and result evidence. It SHALL remove contradictory claims that these same scoped capabilities remain absent.

#### Scenario: Local implementation status
- **WHEN** the roadmap describes the merged language tree
- **THEN** it SHALL distinguish implemented local source/CLI behavior from K, authenticated authority, deployment and proof acceptance.

### Requirement: Preserve wider acceptance and user changes
Reconciliation SHALL preserve all unrelated roadmap amendments and existing MC/SP requirements. Full sprint checkboxes SHALL remain open when their required predicates remain unmet. Each new stage SHALL change status only after its actual independent result review. Proposed commands and artifacts SHALL remain specified-only before reproduction.

#### Scenario: Tests without ledger evidence
- **WHEN** all local package tests pass but required K or ledger execution has not run
- **THEN** local scope MAY be complete while the corresponding K, ledger and proof requirements SHALL remain open.

### Requirement: Persistent evidence and honest loop state
The existing native goal SHALL retain the ordered six-item objective. The record SHALL contain current worktree/commit, actual author identity, reviewed bytes, checks and next eligible task. Liveness SHALL be queried from actual runtime state. No extra scheduler SHALL be introduced. A failed gate SHALL keep its dependent item incomplete without erasing independent completed work.

#### Scenario: Resuming after a failure
- **WHEN** a process stops or a repeated defect triggers the stop rule
- **THEN** the loop SHALL preserve its evidence, reproduce the defect and change the bounded approach before another broad retry.
