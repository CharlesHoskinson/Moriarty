# Sherlock: Candidate A design

Status: SPECIFIED-ONLY; review candidate. Source contracts: [model authoring contract](../../../docs/research/sherlock/MODEL-DRAFT-CONTRACT.md), ten frozen research briefs and five unchanged Opus proposals listed in [inputs.json](inputs.json), and the separate unchanged [Opus draft](security-requirements.md). No security judgment is added here.

## Definition and scope

General-purpose means arbitrary programs composed from the supported grammar run through one unchanged interpreter relation and configuration. It does not mean every language feature, unlimited resources, or guaranteed termination. A program is an immutable table of named functions, nominal type/constructor declarations, constants, entry function and declared execution limits. Separate code, type, value and continuation identities. A bound is a runtime/profile parameter; it does not require program-specific semantic rules or source-level recursion unrolling.

Candidate expression forms are literal, variable, let, checked primitive, conditional, named call, typed constructor, and match. Function bodies are closed except for their declared parameters, locals and globally named functions. Arguments and constructor fields evaluate strictly left-to-right. Only the selected conditional/match branch executes. Recursive calls resolve through the unchanged function table. Higher-order lambdas, captured closure objects, arbitrary letrec values, reflective eval, mutable/cyclic values, indirect bytecode and foreign VMs are explicit extensions/alternatives, not implemented features. First-order self/mutual recursion is in scope now; structural-recursion validation is not required to explain all recursion because finite fuel bounds every attempted run.

UInt128 denotes exact mathematical integers from 0 through 2^128−1, with checked add/sub/mul and scalar equality/ordering. Bool is distinct. The first model need not include division, bytes, generic polymorphism or every legacy primitive. The concrete K draft instead uses dedicated ListUInt128/TreeUInt128 sorts, with no generic declaration table; they support recursive types but not arbitrary nested lists or records. Generic source ADTs need a future separately checked declaration/type/monomorphization adapter. The complete supported grammar must be enumerated rather than inferred from examples.

## Logical state and transitions

Candidate logical state is `(program, control, environment, frames, values, status, result, limits, remainingWork, consumedWork, trace)`. Status distinguishes Running, Waiting, Halted, Rejected and Exhausted; the pure fragment may omit Waiting. Control distinguishes evaluation from return of a value. Frames include pending primitive left/right operand, let body, conditional, constructor field, match and caller-return contexts. Each frame retains its required expression/value context and lexical environment. Calls evaluate arguments, retain the caller continuation, install a fresh parameter environment and enter a named body. Return consumes the appropriate frame and restores saved locals; nested calls never rely on the host call stack as their semantic representation.

The intended reference-machine contract exposes recursive source evaluation as explicit steps. Concrete K pure helpers still recurse over finite input terms for lookup, matching, validation and structural equality outside semantic fuel. Therefore a machine step is not yet demonstrated to have input-independent host or circuit cost; metered helper refinement and input-size bounds are open. Candidate pure work schedule charges one unit per declared nonterminal semantic microstep; administrative K rewrites are not the schedule. A final value with no frames is observed as Halted without an extra computational charge. Concrete K startup/publication cost zero, and its machine-section rules each consume one unit. A stack-limit breach currently yields error4; other zero-fuel nonterminal controls exhaust. Exact fixture fuel totals are not frozen. Quint charges its terminal-return tick, so the two schedules are not identical. Terminal absorption in Quint may be represented by stutter, whereas a K terminal configuration may have no successor; the adapter must state that difference.

Bounds distinguish logical work, frame depth, value/node count and serialization bytes. An attempt beyond a bound produces a named Exhausted reason and an outcome containing consumed work and the last committed state where applicable. Exhaustion is not a returned application value. The concrete pure K draft enforces fuel and every frame push, but not input node/depth/byte limits. Quint enforces its own scalar15/eight-node/eight-frame/fuel2-or32 instance. These are different boundedness contracts; exact K fixture fuel results and host/circuit bounds remain pending.

## Recursive data and representation

Semantic values are finite immutable inductive constructor terms with nominal type ID, constructor tag and ordered typed fields. In the target design lists and trees are ordinary declarations; in concrete K they are dedicated syntax/value sorts. Match evaluates its scrutinee, selects a declared arm, binds its fields and executes only that arm. Concrete K has variable, Nil, Cons, Leaf and Branch patterns, with nested patterns expressed by nested matches and source-ordered arm selection; a failed match is a defined error. Broader typing/admission remains compiler work.

A direct structural tree is the first K representation. A finite indexed immutable arena is the Quint/implementation alternative. Physical repeated references/DAG sharing must preserve structural meaning and declared occurrence-based traversal accounting; sharing does not introduce pointer equality. Concrete K exposes structural equality through a pure helper. Its traversal/cost refinement remains open; a cryptographic digest is not silently substituted for it. Source pointer identity and cyclic data are not first-draft features. Host interning, committed node references, encoding/hash selection and constraints establishing representation correspondence remain open implementation work. No concrete hash or circuit encoding is selected here; security-owned representation constraints remain in Opus's document.

## Suspension and financial extension

A return continuation is a program context waiting for a callee value. A checkpoint is a serializable machine snapshot, including control, saved frames/environments, reachable values, code/profile identity, budgets, pending observation state, and the financial prefix where applicable. A proof chunk is a backend segmentation choice. These are distinct concepts.

The pure K fragment has no financial operations or durable event wait: these requirements are UNMODELED there. Concrete Quint represents a bounded Waiting snapshot of pending factorial frames, with no financial state, duties or Commit action. Its local boundary is neither a financial commit nor a proof chunk; it establishes no Core/2 correspondence. Future universal lowering must preserve existing `/2` typed-await successful-prefix effects, duties and checkpoint atomicity. The exact universal Await/Commit/Yield instruction arrangement is OPEN for integration and designated review; this draft does not replace `/2` with a tentative-state-preserving await or assume an arbitrary raw wait is a financial boundary.

A future financial adapter must define committed financial state, tentative current-segment state, ordered event journal, residual duties, pending operations and work counters. Local failure must describe the current segment's discarded tentative effects separately from prior committed prefix effects, consumed work and residual duties; existing duties are never treated as local scratch data. Newly proposed duties and their commit conditions need an explicit transition policy. The adapter must map actual guaranteed/fallible ledger phases, retained fees and partial outcomes separately; local rollback supplies no global ledger rollback claim. Exact opcodes, serialization and phase mapping remain open obligations, not model results.

Independent normal financial specimen: reserve 100/liability 40; successful prefix pays 30 plus fee 2 and discharges 30, giving reserve 68/liability 10/gross debit 32/recipient receipts 30. A later successful segment pays 10 plus fee 1, giving reserve 57/liability 0/cumulative gross debit 43/receipts 40. A later local segment failure before its commit retains the earlier reserve 68/liability 10 prefix and reports newly consumed work. These are conditional adapter expectations for the stated explicit effects; the exact universal boundary rule remains OPEN. Gross debits, fees, net receipts, supply, liabilities and residual duties remain separate observations.

## Cross-layer architecture and work ownership

| Layer | Concrete proposed work | Evidence presently supplied |
|---|---|---|
| K semantics | Generic input function-table CEK rules, dedicated UInt list/tree sorts, frames, UInt128, fuel/frame caps | Source-inspected; eight unexecuted fixtures; no generic ADT tables |
| Quint | Three algorithm-specific transitions, fixed arena, scalar15, pending-return checkpoint | Source-inspected; eight unexecuted scenarios; no general code interpreter |
| Compiler | Admission, program tables, typed call/constructor/match lowering, future `/2` continuation adapter | Not implemented by this package |
| Host | Canonical encoding, input/state assembly, checkpoint storage, trace export/replay and resource reports | Not implemented by this package |
| Circuit relation | Fixed bounded dispatch, arithmetic, frames, node access and state transitions | Not implemented or qualified here |
| Native wrapper/endpoint | Adapt the relation to native recursion and existing ledger-9 custom-decider route | Session premise only; exact integration/correspondence pending |

The assigned circuit shape may depend on a frozen bounds/representation configuration; it must not require fresh semantic rules per program. A small relation family is an alternative if later evidence supports it. Mapping a K transition to the native relation requires a named observation projection, representation relation and preserved outcomes, not just equality of host-computed outputs. Formal constraint/proof obligations remain with the designated authors/reviewers and existing ZR/MNR contract. Source compilation, K trace generation, Quint sampling, circuit proof and target ledger observation are separate evidence classes.

## Alternatives, counterarguments and decisions

| Choice | Benefit | Cost or unresolved obligation | Disposition |
|---|---|---|---|
| Candidate A explicit first-order CEK | Inspectable nested return and future checkpoint state; direct program-input generality | Frame/environment state overhead; source/circuit adapters needed | Concrete review candidate |
| Direct AST with native K computation stack | Compact reference definition | Must expose saved environments, semantic step accounting and portable continuation state | Retained comparison |
| Typed bytecode/operand-stack machine | Compact dispatch/serialization, compiler reuse possibilities | Adds bytecode semantics, validator, lowering and correspondence boundary | Explicit alternative |
| Per-program step circuits | May avoid unused universal branches; can realize the same reference machine | New artifact per program; separate compiler/realization mapping and reuse claims | Live alternative; Opus05 recommends starting here, dissent from Opus02 universal-circuit preference |
| Small fixed relation family | Potentially cheaper opcode groups | Composition interfaces and relation identity handling require exact design | Later measured alternative |
| Higher-order closures/letrec | Greater expressivity | Captured environments, recursive binding initialization and additional constraints | Extension outside first fragment |

No option has a measured cost advantage. The freeze must settle the actual grammar, frame/value forms, rule labels/costs, bound envelope, selected model projection and open financial boundary questions. Then the requested second ten-agent optimization pass may assess dispatch, encoding, environment/frame storage, sharing, batching and specialization. Every proposal must identify preserved values, rejection/exhaustion, effects, duties, boundaries and logical costs, plus evidence and remaining circuit/target gaps. Timing improvements alone do not establish semantic preservation.

## Preserved first-wave dissent and required Clean stage

The five [Opus proposals](inputs.json) are unchanged external inputs, not approval. Opus02 recommends one code-as-data universal relation per semantics configuration; Opus05 recommends freezing the reference machine/observations first and initially using per-program step realizations, with a universal circuit or finite family as later alternatives. Sherlock semantic generality does not itself choose among these circuit realizations. Their security arguments and proposed clauses remain solely in the original documents for designated review. Opus01/03 also propose broader closure/letrec or heap/commit variants beyond the concrete first-order K fragment; those are not silently incorporated. Financial Commit/Yield/Await design remains OPEN under the existing Core/2 adapter constraint.


Sherlock includes a **required Clean stage**: K reference → Quint finite validation → Lean recursive semantic definitions and fuel-based runs, separately bounded Clean encoding/step circuit and correspondence tasks → compiler/native integration. See [clean-stage.md](clean-stage.md), UIREQ-026. No existing Sherlock proof, generic exporter or Midnight compatibility is claimed; security theorem acceptance/soundness and hostile tests remain Opus-owned.

The required Clean stage integrates in the existing **private Fenrir Clean fork/worktree**. Sherlock language/OpenSpec remains in Moriarty. Cross-repository correspondence must bind the public semantics/model hashes to privately retained exact integration pins, source/theorem membership and native consumers. The public design records that dependency and evidence class without private paths or code; no new public Clean fork is proposed.
