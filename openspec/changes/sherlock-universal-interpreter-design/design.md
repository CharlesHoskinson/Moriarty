## One machine, multiple realizations

Sherlock executes arbitrary programs in its admitted strict first-order grammar through one reference transition relation. Code, functions, environments, values, frames and control are explicit. Self/mutual recursive calls resolve through an immutable program table and retain pending returns in machine state; they are not expanded into program-specific semantic rules or source-recursion unrolling. Finite execution fuel bounds attempted runs without requiring every source recursion to be structurally decreasing.

The source forms are literals, variables, let, checked primitives, conditional, named call, constructor and ordered match. Arguments and fields evaluate strictly left-to-right; only the selected conditional/match body executes. Function bodies are closed except for parameters, local binders and globally named functions. Closed-body, unique-function-name and complete typing admission remain explicit compiler work; the existing K implementation is not such a checker. Lookup preserves first matching function-table order until a checked admission premise supports an indexed equivalent.

UInt128 has exact mathematical meaning in `[0,2^128)`, checked add/sub/mul, scalar ordering and structural equality. Bool is distinct. Recursive immutable values have nominal constructor/type identity, ordered fields and structural meaning. Sharing is storage only; two references to the same node still denote two traversal occurrences. Pointer equality and cycles are outside this source fragment. The current models' dedicated UInt list/tree types are narrower than this architecture's generic ADT extension.

One bounded `StepInput`/`StepOutput` contract serves a code-as-data universal realization, an immutable-program specialization, and a finite family classified by control/top-frame state (`Schedule`, `Scalar`, `CallBind`, `FrameReturn`, `DataMatch`). These are alternatives realizing the same reference semantics and observation contract. No backend, dispatch shape, relation family or universal/per-program cost winner is selected. Retain Opus02's universal-relation preference and Opus05's reference-first/per-program preference as recorded dissent, without converting their security arguments into this author's judgments. The existing ledger-9 custom-decider route is the intended integration premise; it requires no VerifyProof or ledger10 dependency and no foreign proof-system port.

## Program image and source provenance

Prepare the entire admitted source once into an immutable `ProgramImage`: bounded expression/function rows, ordered child/parameter slices, constants, declarations, match plans, entry and source membership. `SourceOccurrenceId` identifies a syntactic path within its original function-table owner or entry. An `ExpandedStepId` identifies one execution event. Helpers, virtual rows, repeated calls and shared records retain the originating source occurrence without conflating these identities.

Preparation does not evaluate application computations. Original function, argument, field and match-arm order survives indexing; source IDs remain distinct from compact physical tags. Code lookup may fold static facts only under a documented mapping. Two programs with the same function names cannot share preparation/witness cache entries merely because their selected path coincides. Cache identity includes exact source, profile, bounds and layout; dynamic caches additionally include immutable inputs and run scope.

The first baseline is deterministic uncached preparation and complete state/step materialization with independently frozen normal expectations. Indexing, interned nodes, compact frames, lookup decompositions and caches become replaceable implementations of this consumer. A common rule inventory names source rule, helper site, continuation tag, ordered free fields, charge and projection boundary. Shared metadata may generate tags/accessors and source locators; it must not generate both reference behavior and its independent expected results.

## Helper microsteps and versioned costs

Candidate A's K schedule, newly named `sherlock-k-a/1`, remains unchanged: one unit per machine-section rule; startup/final/error publication zero; recursive lookup, binding, argument append, validation, matching and equality helpers unmetered. Its stack-limit breach is `Rejected(error4)`. The existing finite Quint schedule, `sherlock-quint-a/1`, charges its terminal-return tick. Their fuel counters are not interchangeable.

Candidate B proposes **`sherlock-helper-microstep/1`**, with one unit per legacy machine completion plus one per explicit bounded helper event, free startup/final/error publication, and the legacy frame-cap error4 classification retained. This is a new semantic schedule. Helper controls store lookup cursors, parameter/argument cursors, partial environments, append cursors, ordered validation/equality/pattern task lists and explicit resumes. Variable lookup and binder-duplicate checks also become explicit finite scans. Each event visits one bounded record/occurrence and updates a fixed bounded payload; variable-arity field processing continues through cursors. No recursively evaluated helper remains hidden in a B step. Fixed-width UInt128 primitives remain bounded independently of data size.

The proposed mapping erases unfinished helper states to the originating A pre-state, and maps legacy completion events to the A post-state. For completed mapped intervals without intervening capacity failures, `W_B = W_A + H_B` is the intended accounting equation. This is an unproved target, not equal-fuel equivalence or an automatic refinement claim. The exact event/rule inventory and independent B fuel literals must precede implementation acceptance. A-preserving physical helper improvements are a separate path retaining A work while counting helper visits diagnostically.

`Bounds` covers code/functions/children/parameters/pattern/declaration tables, arity, data nodes/fields, environment cells, frames, helper task storage, serialization bytes and total reference work. Supported admission, unsupported features, input capacity refusal, application rejection and runtime exhaustion are distinct. New runtime data/env/helper capacities can exhaust by a named reason; they explicitly narrow the admitted bounded profile. Encoding capacity failure is not retroactively reclassified as A exhaustion. Terminal/error publication precedes zero-fuel exhaustion; charged frame-cap checks preserve error4. The detailed proposed precedence is in interfaces.md and still needs reviewed rule realization.

Logical work, helper visits, physical events, logical depth, physical frame bytes, active/padded cells, serialization, host time/memory, circuit rows/degree, proof/key sizes, native time and target fees are separate `ResourceManifest` fields. Unknown is not zero. Fewer word operations, cache misses, instructions or proof objects alone do not establish a cheaper complete path.

## Values, environments and bounded machine images

The reference state contains semantic values and full lexical maps with ordered frames. Calls evaluate arguments, save caller context, install a fresh parameter map and enter the named body. Argument frames retain completed values, remaining expressions and caller map. Return and scope frames restore caller/shadowed locals. Factorial's pending multiplication and tree recursion's pending right traversal are explicit state, never host stack assumptions.

The direct structural representation and full environments/frames remain comparison baselines. Immutable arenas, persistent environment roots, slots, packed frame payloads and activation reuse are alternatives. A frame's free-variable inventory suggests a layout; it does not justify deleting a saved semantic field. Every logical frame push still checks the same cap even when one physical activation is reused. Helper scratch and outgoing arguments count alongside saved locals in physical reporting.

`MachineImage Bounds F` has fixed-capacity code/data/environment/frame/helper vectors, bounded tags/indices/counters, active lengths and explicit scalar layout. Partial `encode`/`decode` and `RepresentationRelation` name its admitted domain and complete semantic observations. Recursive Lean values do not become unbounded circuit fields. DAG references decode by structural unfolding; encode/decode traversal is separate from fixed-step execution and has independently reported work. No whole-state decoder or recursive equality may hide inside a B step. The image and its field/layout identity are common to every realization. Concrete capacities, full round trips and step correspondence remain tasks.

The named arithmetic API is `addCarry_b`, `subBorrow_b`, `mulWide_b` for 32/64-bit words, with named low/carry/borrow/high outputs and little-endian limbs; `checkedU128Add/Sub/Mul` retain exact mathematical outcomes/error10. Full multiplication retains 256 product bits. The equations and carry-bit versus word-carry distinction are in interfaces.md. The public Clean byte representation is the baseline. Four U32 or two U64 groupings both use sixteen byte-valued fields; packed fields are separate representations. No CPU speed, modular arithmetic library or reduced multiplication count transfers a circuit-cost result.

## Witness plans, constraints and exports

Separate semantic interpretation, bounded representation, witness computation, constraint components and exporter support. `OperationManifest` names every operation's domain/order, source locators, witness dependencies, actual component locator or unsupported status. `WitnessPlan` is a typed dependency DAG with stable topological order and explicit lifetime/last-use information. `ConstraintPlan` describes ordered inputs/outputs and actual component requirements independently. `BackendCapabilities` distinguishes field/format, lookup/interact/custom-gate and structured-witness/native-closure support. Constraint and witness emission each return a located unsupported result when incomplete.

Start uncached; compare complete materialized `StepRecord`s before dependency scheduling, streaming or cache reuse. Host diagnostics such as generated-row/result-match/cache-hit are reporting fields. They are not substituted for component definitions. Structured Clean WitnessIR is an export target candidate; basic constraint JSON discards witness computation, and native witness closures are not generally serializable. Current public Circom export refuses lookup/interact. No currently inspected export surface establishes Midnight/ZKIR compatibility.

Rebuild a small typed DAG scheduler, separate witness/constraint visitors, last-use reporting and streaming row sink independently. Reuse ideas from Lurk slot planning, CirC scheduling, SIEVE lifetimes and Clap's compilation split without selecting their runtimes or proof systems. Streaming does not imply bounded prover memory. Lookup subtables and opcode event partitions remain measured alternatives; their tables, queries, collation, padding, state crossings and preparation cost all require accounting.

## Ordered slices and static residual steps

`ReferenceSlice` records ordered events, prefix work and boundary positions. Batching at 1/2/4/8 events executes every internal charge, frame/cap check and selected branch in order, stopping at the earliest outcome or source suspension. A batch may not compute its final result and charge retrospectively. Padding is physical only. A technical cut serializes complete control/environment/frames/values/counters and resumes unchanged; it creates no source suspension or financial commit. Family partitions must retain a reconstructible total order.

A bounded offline specializer produces `ResidualStepIR` from the fixed reference definition. A finite memoized worklist folds immutable program/layout/dispatch facts. Runtime control, data, environments, frames/depth, helper cursors, fuel/work and outcomes stay dynamic. Dynamic conditions retain both successors; source recursion remains machine calls/frames. The specialization key excludes recursion depth, fuel and runtime locals. A residual-size cap emits generic dispatch fallback, never application exhaustion. No source expression pre-evaluation, logical-frame deletion or charged-boundary merging is part of the initial specializer. Empty, family-only and per-program static masks support the three realizations without selecting a winner.

## Generic declarations and ordered match plans

Extend the first fragment with `TypeDecl`, representation-specific `CtorLayout`, and `MatchPlan` rather than adding another dedicated built-in data structure for each example. Begin with closed monomorphic nominal recursive groups, including mutual references. Resolve declaration/constructor/field/binder identities, construct a plain tagged layout and compile ordered pattern matrices using first-column specialization/default decomposition. Generic parameters need a separately bounded instantiation policy; finite declarations alone do not bound specialization or recursive value sizes.

The scrutinee evaluates once; constructor fields evaluate once in source order. Match selection returns the earliest matching source arm, binds fields in its arm environment, executes only that body and restores the saved outer environment. Occurrence paths are semantic field paths, not arena addresses. `MatchPlan.workMap` retains reference events/stop positions even when physical tests or suffixes share work. Heuristic columns, unboxing and layout packing follow comparison against direct ordered matching and the plain plan.

A specified normal discriminator is `Schedule = Done | Pay(UInt128,Schedule) | Both(Schedule,Schedule)`. Ordered arms `Both(Pay(x,_),_) -> x; Both(_,r) -> sum(r); Pay(x,t) -> x+sum(t); Done -> 0` give 4 on `Both(Pay(4,Done),Pay(5,Done))`; a structural sum gives 9. Shared/unshared `Both(Pay(4,Done),Pay(4,Done))` both sum to 8 with two occurrences. These are new unexecuted extension cases. Higher-order closures, arbitrary letrec values, GADTs, mutable/cyclic data, or-patterns, indirect bytecode and foreign VMs remain explicit further extensions, not implied support.

## Financial suspension and existing Core/2

A return continuation, serializable checkpoint and backend proof chunk are distinct. Pure K has no finance or durable wait. Quint's bounded factorial Waiting state has no caller environment, duties, complete effects or Core/2 adapter. Neither establishes financial suspension behavior.

The financial extension must preserve existing Core/2 typed-await successful-prefix effects, residual duties and checkpoint atomicity. Exact universal `Commit`/`Yield`/`Await` instructions remain OPEN for integration and designated review. The extension state must include committed financial state, tentative segment state, ordered effects, liabilities/duties, pending observations/operations and cumulative work. Failure describes discarded current tentative effects separately from retained prefixes, fees, work and duties. Target guaranteed/fallible phase behavior is a separate mapping; local rollback is not a ledger-global rollback claim. No residual block, chunk cut or host cache can move a financial boundary.

Retain the independent conditional example: reserve100/liability40; prefix pays30 plus fee2 and discharges30, leaving reserve68/liability10/grossDebit32/receipts30. A later success pays10 plus fee1, leaving reserve57/liability0/cumulativeGrossDebit43/receipts40. A later local failure before its commit retains the earlier reserve68/liability10 prefix and newly consumed work. These are specified adapter expectations for explicit effects; universal opcodes and target correspondence remain open. Complete financial observations retain gross/net/fees/supply/liabilities/duties separately and all existing Core/2 financial requirements.
