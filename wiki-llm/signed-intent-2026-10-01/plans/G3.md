## Required authenticated acceptance interface

Recommendation: introduce a typed backend interface whose successful values cannot be constructed from booleans in the beta caller:

1. Owner registry proof: network genesis + contract address + registry revision + `(domain,id,keyRef,algorithm,canonicalPublicKey,address,validity,revocation)` binding. Bootstrap/rotation must authenticate the existing owner or explicitly configured genesis authority in an actual ledger mechanism. A signed attacker-supplied registry JSON is insufficient. Decide wallet-owner identity versus delegated intent key and enforce native address derivation where applicable.
2. State origin: finalized block hash/height, protocol version, contract address, serialized state digest and predecessor/head identity bound to selected source/program/policy and asset colors. Indexer observation is evidence readback; it is not automatically a cryptographic light-client proof. Declare any trusted node/indexer boundary explicitly. Existing `receipt.mjs`, `recover-deployment.mjs`, `local-tip.mjs` can supply observation/readback mechanics, not a missing cryptographic finality proof.
3. Atomic acceptance state: contract-resident owner key binding/revision, head/revision, replay set or monotone scoped nonce, work remaining/spent, allowance remaining/spent, balances and duties. One circuit must check exact pre-state, signature authorization route, signed effect commitment, complete numerical transition, caps/window, and update all consumers with native transfer effects. Same pre-head competing transactions must leave at most one successful financial acceptance. Offchain compare-and-swap file state is not on-ledger acceptance.
4. Bind `/3` statement digest, complete effect order, all counterparties/assets, predecessor/successor, policy/source/compiler/VK identity to public inputs. A Rust verification success plus circuit input `accepted=true` is forbidden. Circuit must constrain the actual relation or ledger must enforce the equivalent native authenticated transaction binding; unproved host results must retain unqualified status.

Blocking capability: inspected Compact loan/swap has no registry/key lifecycle, wallet signData verification gadget, replay set or beta head/allowance mapping. Native spent-input authorization authenticates input owner but inspected contract surface has no demonstrated way to authenticate arbitrary signData bytes and tie its signer to SourceAccountBeta. Resolve one concrete route before advertising owner-authenticated beta settlement. Existing payout addresses/capability secrets cannot simply be relabeled owner registry.

## Small nonrecursive native proposal

Existing `experiments/midnight-crypto/tests/native_proof.rs` uses official pinned ZK revision **0ededef0e605701fc5139ebdcf011b11f3d86ba7** (`https://github.com/midnightntwrk/midnight-zk`), k6 ephemeral unsafe test SRS, real PLONK/KZG `create_proof`, `prepare`, `Guard::verify` final pairing. It constrains only field pre=post+gross and explicitly excludes UInt128 ranges/compiler correspondence. Ledger pin resolves registry proofs0.7.3/curves0.2.1; git ZK smoke resolves proofs0.8.0/curves0.3.0. Version and transcript/instance/VK compatibility with Preview remains a blocker.

Recommendation, specified-only: replace equality smoke with a nonrecursive **complete finite transfer relation** using limb range constraints, bounded addition/carries and equality for every financial/public pre/post field, ordered effect commitment, counters and caps. Start row accounting <=k10 with 2 Cargo jobs, external target artifacts <=8GiB, no upstream workspace suite or production SRS. Use ephemeral test SRS solely for native soundness/fit measurements; no production or Preview claim. Stop at row overflow or resource ceiling rather than increasing k. Independent reference refuses modified public values, out-of-range limbs, invalid carries, omitted fees and altered effect/registry/head commitments. Must prove relation to actual frozen compiler/Core outputs, not simply witness satisfaction of a new handwritten equation.

Inference: nonrecursive fixed transfer arithmetic can plausibly fit below k10 with economical limbs; no row count, RAM bound or full binding/hash cost has been measured. Schnorr verification, full byte hashes, authenticated registry paths and history may exceed that budget. The bounded test is viable as a narrowly labeled experiment only after exact field/commitment relation and resource allocation review; it is not a complete signed financial proof recommendation until these costs are accounted for.

No-go route: reuse R3 k17 recursion or treat k6 equality proof as native financial acceptance. Existing R3 exhausted rows is distinct from this proposal. A successful new local native proof would still require Preview-compatible exported proof/VK/transcript/public inputs and an actual contract caller; direct KZG bytes cannot be fed to `submitCallTx` merely because both say PLONK.
