# First experiments — s7-recursion wave 1

**SOURCE — Scope:** This research session fetched sources and ran [model.py](model.py). It did not build or run a prover, alter keys/contracts, install software, or submit to stagenet. Existing entry points were inspected in [check-a3-local.md](../../../raw/s7-recursion/check-a3-local.md), [check-a4-local.md](../../../raw/s7-recursion/check-a4-local.md), [sherlock_parent-local.md](../../../raw/s7-recursion/sherlock_parent-local.md), [sherlock_terminal-local.md](../../../raw/s7-recursion/sherlock_terminal-local.md) and [cli-local.md](../../../raw/s7-recursion/cli-local.md). The new comparison harness below is a **specification to implement**, not an existing executable.

**ESTIMATE — Common measurement protocol:** Use this host's 20 CPU cores, 90 GB RAM and one RTX 5090 32 GB/CUDA 13.x. Start with one proof process, CPU control and GPU disabled. Pin source revisions, Cargo.lock, Rust toolchain, CPU affinity, thread count, input public digest, VK/PK/relation digest, transcript and authenticated SRS digest. Keep private witnesses out of reports. Record cold setup separately and warm repeated proving with identical caching policy; maintain fresh production-quality randomness. Time witness generation, synthesis, PK preparation, commitments, polynomial work, opening, serialization, CPU verification and complete chain. Record peak RSS, CPU seconds, wall seconds, swapping and device high-water memory. Report median and full range of at least three paired runs; report p95 only with at least 20 observations. Run baseline and candidate in alternating order with no competing heavy job. If a failure occurs, read the trace, give one concrete hypothesis and retry with `--hypothesis`; shrink after two failures of the same kind.

**SOURCE — Factory interface:** The existing wrapper accepts `scripts/doctorwatson heavy --id LABEL --budget KEY --max-wall SECONDS -- COMMAND...`; `--gpu` additionally acquires its GPU lock. The explicit wall limit is supported. [cli-local.md](../../../raw/s7-recursion/cli-local.md). **ESTIMATE:** initial caps below are admission limits, not predicted runtimes. Begin sequentially, stop an experiment before exceeding 70 GiB host RSS or 24 GiB device allocation, and let measured factory caps tighten subsequent runs. Do not infer safe concurrency from the old 15 GB process RSS. No experimental change requires moving existing wallets, secrets or contract state.

## E1 — Fit and certify direct composition before optimizing recursion

**OPEN QUESTION — Hypothesis:** The exact fixed A102→A80 transition can be proven in one stock-architecture k15 terminal, and the complete replacement is at least 10× faster under a matched current baseline. For shared-witness synthetic 16-tx batches, direct composition may need an additional modest prover improvement to reach 10×.

1. **SOURCE — Reproduce the arithmetic now, without a prover:** from `recursion-perf`, run:

   ```bash
   python3 clusters/s7-recursion/wave-1/model.py
   ```

   **ESTIMATE — Decision:** verify the k15 7.0968% and k16 4% unscaled-share thresholds and the historical 161.729202 s recl9 target. These outputs are model results, not performance evidence.

2. **ESTIMATE — Establish one coherent baseline in the implementation checkout:** use an already authenticated local SRS and exact A2 child bundle. First inspect the current factory selection with `scripts/sherlock-next`; retain its first failing predicate separately from this experiment. The existing A3 test can be invoked without implicit artifact selection or an SRS download:

   ```bash
   export CARGO_BUILD_JOBS=4
   export RAYON_NUM_THREADS=4
   # Set these to existing authenticated, matching artifacts before executing:
   export MORIARTY_A2_LINK_DIR=/absolute/path/to/existing/children
   export MORIARTY_PARENT_SRS=/absolute/path/to/official/bls_midnight_2p20
   export MORIARTY_PARENT_OUTPUT_DIR=/absolute/path/to/new/experiment/baseline
   scripts/doctorwatson heavy --id S7E1-BASE --budget s7-e1-base --max-wall 1800 -- \
     cargo test --release --locked -p mori-recursion --features sherlock-recursion \
     --test sherlock_parent parent_verifies_both_linked_children_at_k20 \
     -- --exact --include-ignored --nocapture --test-threads=1
   ```

   **SOURCE —** These environment variables and test names exist in [sherlock_parent-local.md](../../../raw/s7-recursion/sherlock_parent-local.md). It requires official SRS hash `1cc62978558fdc1e445cd70cfd9a86ec3c2e2151b6d74811232d37faf9133ff1`, length 201326980, and k20. **ESTIMATE:** placeholders above must be replaced by actual local artifact paths; they are deliberately not guessed. Use a separate output directory per run. This test is a baseline control, not the future fused test, because it asserts k20.

3. **ESTIMATE — Implement the comparison harness in a future code task:** expose the existing fixed transition fragments through shared private cells, with both enables constrained true. Preserve program/context, 64-bit heights, pre→mid→post linkage, ordered trace, step/work counters, instance/batch binding and the terminal communication opening. Pin the exact original relation/VK version being composed. Emit only the intended terminal public template. Treat child proof provenance separately: the candidate proves the transition relation directly, not possession of old proof bytes. Use the existing ledger-reader and serialization calls from `sherlock_terminal.rs` for offline acceptance under the candidate VK, rather than the installed-key assertion for a different relation.

4. **ESTIMATE — Synthesize before proving:** sweep k14/15/16 for the fixed pair; report advice rows, every table extent, columns, maximum degree and extended-domain size. Require in-circuit rejection, then stock ledger-9 key round-trip and proof acceptance/rejection. Run three paired complete baseline/candidate chains with RAYON=4; sweep 1/8/16/20 threads only after the first control passes. Do not count repeated keygen in one side and omit it in the other. Run future heavy candidate commands under `--id S7E1-FUSED --budget s7-e1-fused --max-wall 1800` and use `--gpu` only for a distinct GPU variant.

**ESTIMATE — Deciding measurements:** accept the fixed-pair 10× hypothesis only if `median(T_candidate_complete) ≤ median(T_baseline_complete)/10`, with all soundness and local ledger checks passing. k15 is a useful screen, not the result. For historical recl9 the reference threshold is 161.729202 s, but publish a claim only against a matched new cohort. ## E2 — Search terminal placement and fflonk around the k20 threshold

**OPEN QUESTION — Hypothesis:** A four-child verifier with ≥23.626% net row reduction plus glue fits the existing residue check into k20, eliminating a whole proof without paying k21. A binary fused terminal or three-child variant may be a cheaper intermediate win.

1. **SOURCE — Pin controls:** use the homogeneous node geometry from [loki05-prior.md](../../../raw/s7-recursion/loki05-prior.md) only as a reference, and the exact PR #575 merge `1e39c12` sources in [fflonk-gadget.md](../../../raw/s7-recursion/fflonk-gadget.md) / [fflonk-pcs.md](../../../raw/s7-recursion/fflonk-pcs.md) as an inner-PCS experiment. **ESTIMATE:** retain the old outer PLONK architecture and complete full-entropy transcript; do not upgrade the ledger protocol by copying upstream wholesale. Record full resolved revision IDs before building.

2. **ESTIMATE — Implement one geometry-only harness:** for each `arity ∈ {2,3,4,8,16}`, `inner PCS ∈ {ordinary KZG, fflonk t2, fflonk t4}`, and `terminal ∈ {separate, fused}`, synthesize the same pinned relation and report advice/table rows, columns, degree, commitment count by transcript phase, nonconstant/fixed-base MSM sizes, range widths and SRS degree. Count all child-carried obligations when children are nodes. Reject unavailable general node-of-nodes configurations instead of reusing a leaf VK. Evaluate four actual leaf proofs for 16 tx; evaluate 16 proof leaves only as a separate workload.

3. **ESTIMATE — Apply explicit fit tests:** usable k20 capacity is 1048569 in the recorded configuration. For b=2, estimated verifier+pairing is 891244, leaving 157325 rows; for b=3 the verifier must save at least 34517+glue rows; for b=4 at least 226359+glue. Measure the table too. If b=4 still needs k21, retain it only if complete measured latency improves: merely having fewer proofs is not success. For t4 k17 children, verify official SRS provenance and availability through the required k19 parameter domain; do not fabricate an independent setup. If larger circuits require unavailable official powers, record infeasibility.

4. **ESTIMATE — Negative checks before proof timing:** mutate child VK, statement/order, challenge binding, carried accumulator, point encodings, subgroup membership and unit scalars; all must reject. If trying hinted scalar multiplication, create a torsion-contaminated output `Q′=[k]P+T` with nonzero small-order T, and both fixed-scalar and chosen-scalar decomposition cases from the [2026 preprint](../../../raw/s7-recursion/cofactor-eprint.md). Compare the ordinary gadget, uncorrected candidate and corrected candidate; only the corrected version's net rows count. Do not remove final subgroup checks.

5. **ESTIMATE — Prove only surviving geometries:** first run CPU controls at 4 and 20 threads, one process at a time, with new terminal and all needed child proofs timed together. Run each heavy case via `scripts/doctorwatson heavy --id S7E2 --budget s7-e2 --max-wall 3600 -- <implemented-harness-command>`; `<implemented-harness-command>` is a future runner, not a shipped command. k21/k22 candidates require measured host/device admission before proof allocation; on the 32 GB 5090, do not assume a 60 GB host projection fits VRAM. Add one GPU variant only after the corresponding CPU proof independently verifies.

**ESTIMATE — Deciding measurements:** advance the four-child candidate if actual verifier+pairing+glue and tables fit k20 under the stock reader and complete batch median improves by at least 20% over the matched control. The 20% is an engineering triage threshold, not a cryptographic requirement. Stop t4 if its increased leaf cost exceeds the eliminated-node/terminal saving. For high-arity trees, report both total proof service time and batch critical-path latency under the same thread/memory budget; choose neither by tree height alone.

## E3 — Price the complete folding wrapper before implementing the strand

**OPEN QUESTION — Hypothesis:** NeutronNova multifolding or MicroNova compression can reduce long shared-witness workloads, but only if the final Midnight bridge stays within the complete-chain budget. The 91 ms SHA-256 fold and 2.2M Ethereum gas figures do not answer that question.

1. **SOURCE — Read the concrete implementation boundaries:** [vega-neutronnova.md](../../../raw/s7-recursion/vega-neutronnova.md) describes uniform step instances, residual checks, transcript weights, one folded witness, a subsequent Spartan argument and a second zero-knowledge fold. [vega-provider.md](../../../raw/s7-recursion/vega-provider.md) exposes Hyrax/Keccak engines on other curves; [nova-current.md](../../../raw/s7-recursion/nova-current.md) lists three supported cycles. **ESTIMATE:** freeze a complete source revision and choose either a maintained Nova control or Vega's multifolding path. Do not interpret Sonobe's pending implementations as ready dependencies.

2. **ESTIMATE — Define the bridge relation before measuring folds:** enumerate every obligation of the selected final proof, including polynomial/commitment openings, all Fiat–Shamir messages and domains, final relaxed satisfiability, secondary instance where present, parameter/shape digest, step count, initial/final state and the terminal communication/anchor binding. For a raw-witness check, explicitly constrain `Az ∘ Bz = uCz+E` and commitment openings; for compressed verification, implement its actual verifier, not only the tiny folding verifier. Preserve original BLS scalar/Poseidon semantics through exact arithmetic if the inner field differs. Include canonical conversion at both field crossings.

3. **ESTIMATE — Synthesize the wrapper first in the old stock Midnight architecture:** report all rows, tables, width, degree and prospective k; then produce one independent ledger-reader-accepted outer proof with the official SRS and Blake2b. Compare a complete raw-witness decider and compressed verifier only if both are soundly implemented. No assumption that every wrapper must contain the old BLS pairing gadget, and no assumption that a pairing-free wrapper is small. Stop if the complete protocol cannot be expressed or the required setup provenance is unresolved.

4. **ESTIMATE — Measure conversion, folding, compression and wrapper at 4/16/64 chunks:** start with the actual fixed semantic workload, not only SHA-256. Record small-scalar distributions before relying on commitment shortcuts. CPU first at 4/20 threads; GPU resident commitments are a separate candidate whose curve/backend support must be demonstrated on this CUDA 13.x/5090 host. Use one process, memory caps above, and `scripts/doctorwatson heavy --id S7E3 --budget s7-e3 --max-wall 3600 -- <implemented-harness-command>`; add `--gpu` only when that path exists. This proposed command template does not imply an implementation exists today.

5. **ESTIMATE — Mutate accumulated state:** wrong final error term, missing secondary check, omitted fold, reordered steps, wrong shape/parameters, altered fold weights or transcript, wrong endpoint/count and malformed point encodings must reject in the wrapper. For FLIP as an alternative, require all witnesses under the existing custody model, its complete final proof, exact setup assumptions, and explicit sequential linkage of otherwise independent instances.

**ESTIMATE — Deciding measurements:** compute `T_total(n)=T_witness_and_conversion(n)+T_fold(n)+T_compression+T_wrapper+T_serialization_and_verification`. For a 16-step historical recl9 comparison, `16f+C+W≤161.729202 s` is only a shorthand when f/C/W already include every listed term. With illustrative C=20 s, f=1/5 s permits W≤125.729/61.729 s; these are design budgets, not expected measurements. For an accelerated matched tree `na+D`, solve `n(a−10f)≥10W−D` only after putting compression/conversion in f or W and checking both sides' actual scheduling. Advance folding only if the complete bridge beats the best E1/E2 alternative at the required workload size; otherwise retain it as longer-strand research. Do not multiply unrelated published speedups.
