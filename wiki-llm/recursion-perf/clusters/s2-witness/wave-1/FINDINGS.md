# s2-witness — wave 1 findings

ESTIMATE — **Prioritize a phase-aware, key-bound CPU witness schedule, then batch inversions at dependency frontiers.** These are plausible contributors to a combined 10× prover, but witness synthesis alone has no supported 10× end-to-end case. First measure real P/N/D synthesis, dependency width and conversion costs. Do not begin with an AVX-512 port, a generic GPU witness compiler, or replacing the reference machine.

SOURCE — This is research and source inspection, not a new proof benchmark. The supplied first reading was found at `loki/nodes/loki-09-cpu-witness-field.md`, rather than the nonexistent `loki/10x/` path. Both earlier studies are captured in [prior-loki09.md](../../../raw/s2-witness/prior-loki09.md) and [prior-astra1.md](../../../raw/s2-witness/prior-astra1.md). They already proposed lazy inversions, sparse rational buffers and a specialized witness compiler. This wave adds concrete scheduling precedents, a phase-boundary correction, a native-hint precedent, a G5 scope correction and explicit rejection tests for those proposals.

## Baselines and bounds

SOURCE — The [cuSnark source table](../../../raw/s2-witness/cusnark.md) reports a **1,135-column k20** chunk_inner circuit on a configuration with four RTX 3090s: CPU 1,762.75 s; GPU 463.13 s; GPU Generate Advice 306.44 s; Generate Lookups 56.84 s. Thus 363.28 s combines two distinct buckets. Its stage labels do not establish that all Generate Advice time is pure witness arithmetic. This is a different circuit and accelerator configuration from Sherlock/Fenrir on one RTX 5090.

ESTIMATE — Define the generous external proxy `C(s) = 463.13 / (156.69 + 306.44/s)`, treating *all* Generate Advice as accelerable witness work, and leaving lookups plus everything else unchanged. Then `C(2)=1.494×`, `C(8)=2.375×`, `C(10)=2.472×`, and `C(∞)=2.956×`. Accelerating the combined 363.28 s bucket infinitely instead gives `463.13/99.85=4.638×`. The earlier study's `1762.75/363.28=4.852×` is a different bound: the original CPU total divided by a fixed post-offload residual. These denominators must not be exchanged.

SOURCE — The historical Sherlock receipt records 882.589555363 s in `prove` and 62.328385318 s in `setup_pk`, with cache state unknown; it does not separate synthesis. Its qualified private SDK closure is not reproduced by the source snapshot alone. See [parent-receipt.md](../../../raw/s2-witness/parent-receipt.md), [source44-provenance.md](../../../raw/s2-witness/source44-provenance.md). Registry proofs 0.8.3 inspected here and historical recl9 proofs 0.8.2 must not be silently treated as the same binary; the distinction is recorded in [prior-loki09.md](../../../raw/s2-witness/prior-loki09.md).

ESTIMATE — For Sherlock use `S(f,s)=1/(1-f+f/s)`, where `f` is the **unmeasured** witness share. At `s=8`, `f=.1/.2/.5` gives `1.096/1.212/1.778×`, respectively. The earlier joint scenario remains mathematically valid: witness share .20, other bulk .78, unchanged .02, added overhead .01, bulk 20× requires witness `s≥.20/(.1-.78/20-.02-.01)=6.452×`; witness 8× yields `10.638×` jointly. It supplies a target, not evidence that witness8× is achievable. Reproduce these calculations with [calculate_bounds.py](calculate_bounds.py); outputs are [bounds.json](bounds.json).

## What the source changes about the earlier plan

SOURCE — **The stage boundary is phase-dependent.** In `parse_advices`, Midnight synthesizes and resolves the current phase, blinds and commits its advice, writes commitments, then squeezes challenges before moving to the next phase. See [midnight-prover.md](../../../raw/s2-witness/midnight-prover.md). The earlier plan already recognized challenge barriers; this source shows where they cross the proposed KeysReady → Witnessed → Committed state split.

ESTIMATE — Define the research timer as the **sum of synthesis and rational-resolution intervals across phases**, excluding commitments/transcript time. If the actual circuit has challenge-bearing later advice, a resumable witness task must yield after each phase; it cannot hand the next stage every value before the prerequisite commitments. A public `Witnessed` state can mean all phases completed, but then it is not a prerequisite for *all* advice commitments. Count the interleaving once. OPEN QUESTION — Actual phase counts for the pinned Sherlock P and Fenrir N/D remain to be measured.

SOURCE — **Two region traversals are not two evaluations of every value.** `assign_region` calls the region closure for shape and assignment; `RegionShape::assign_advice` ignores `_to`. The replay opportunity concerns region-level eager work and structural bookkeeping, not every expensive lazy value supplier. See [floor planner](../../../raw/s2-witness/midnight-floor-planner.md), [shape implementation](../../../raw/s2-witness/midnight-region-shape.md). The previous CPU study had this distinction; the supplied shorthand observation alone does not.

SOURCE — **A practical parallelism precedent exists in the same scalar-field family.** gnark's BLS12-381 solver uses dependency levels with a barrier per level, a worker pool, and a target grain of 50 constraints/task. Its native range-decomposition and log-derivative hints avoid generic big.Int conversions while keeping generic fallback paths. [Source](../../../raw/s2-witness/gnark-bls381-solver.md). This is gnark's solver/constraint representation, not Midnight's recursive witness workload, and contains no transferable speedup measurement.

ESTIMATE — Prefer region or gadget blocks over one task per scalar operation; determine the grain from measured scheduling cost. Compute `W` = total scalar-equivalent work and `D` = weighted critical path. The ideal lower bound `T20≥max(W/20,D)` exposes whether 20 workers can help. Count data dependencies through MSM ladders and sponges; independent children offer some coarse parallelism, but two or four children do not automatically fill twenty cores. Keep deterministic output order independent of execution order.

SOURCE — **Compiled witness benchmarks are circuit-specific.** Mopro's M1 Max table gives Semaphore-32 witness times of 130 ms for snarkjs, 7.1 ms for native witnesscalc and 5 ms for circom-witnesscalc; SHA256 instead takes 22 ms for witnesscalc and 32 ms for circom-witnesscalc. [Benchmark capture](../../../raw/s2-witness/mopro-performance.md). Circom-witnesscalc explicitly documents unsupported features and an in-development CVM. [README](../../../raw/s2-witness/circom-witnesscalc.md).

ESTIMATE — The relevant compiler comparison on Semaphore is `7.1/5=1.42×`, not `130/5=26×` against JavaScript; on SHA256 the graph calculator is `32/22=1.45×` slower than the native alternative. Neither result measures Midnight's already-native BLST-based prover. This supports trying a small typed recipe, not promising a universal compiler multiplier.

SOURCE — **G5 is still host observation.** `witness_stream` runs `Machine::step`, constructs pre/post display/JSON values and SHA-256 digests, and accumulates `Vec<Value>` for the whole run. Its own source explicitly excludes Poseidon lane digests, circuit emission and proof claims. Existing tests check adjacent snapshots/digests and two final-result fixtures. [Implementation](../../../raw/s2-witness/g5-stream.md), [tests](../../../raw/s2-witness/g5-stream-tests.md). The CLI obtains this as an optional report section; the inspected path is not a direct P/N witness input. [Handler](../../../raw/s2-witness/simulate-handler.md).

ESTIMATE — A typed callback avoids the G5 JSON history, but `Machine::step` may still construct full before/after records. Removing that deeper copy cost requires separate measurement and a separate change. Circuit advice storage and rotated/cross-region consumers also survive a typed sink. Reusing adjacent states is safe only after full semantic equality, not by trusting a cached digest. Do not silently change the existing diagnostic JSON contract.

## Acceptance and what would change the verdict

ESTIMATE — The acceptance target is the original relation and ledger envelope: same configured gates, layout, constants, copies, public inputs, VK, official SRS and each layer's transcript. Preserve terminal Blake2b and pairing checks; preserve an existing intermediate transcript rather than replacing it with Blake2b just because the terminal uses it. Test all constrained EC intermediate values, subgroup checks, exceptional branches, padding and zero denominators. Identical proof bytes are unnecessary in production; assignment comparison needs injected test randomness because witnesses and lookup ordering can be randomized. These obligations follow the risks identified in [prior-astra1.md](../../../raw/s2-witness/prior-astra1.md).

OPEN QUESTION — Promote the CPU recipe if E1 finds substantial dispatch/conversion work or wide inversion frontiers and E2 achieves ≥2× measured witness improvement with unchanged layout/assignment. Promote GPU witness work toward the joint 10× plan only if inclusive witness speed approaches the required 6.452× (under the earlier assumed phase budget), and later stages independently meet their budget.

OPEN QUESTION — Demote parallel/GPU witness work if measured DAG span, narrow levels, or transfer/scheduling cost consumes the witness budget. A 20-core scheduler alone needs ≥94.737% parallel work for an ideal 10×; overhead makes the requirement stricter. If shape traversal is <5% of witness time, removing it has <`1/.95=1.053×` local benefit and is not a major priority. If G5 is absent from the parent path, its optimization stays a leaf/host-stream project.

OPEN QUESTION — A different verdict requires controlled same-host measurements for both Sherlock A102/A80→P→D and Fenrir leaves→N→D, with keys ready, complete verification and separately reported cold start. No kernel, mock-proof, parent-only or host-stream result establishes ledger-9 stagenet acceptance. This wave performs no network transaction or proof run.
