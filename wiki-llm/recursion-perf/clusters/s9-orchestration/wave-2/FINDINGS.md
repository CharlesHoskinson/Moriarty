## Mechanism, attribution and overhead contract

**ESTIMATE — Choice:** Use explicit Rust RAII timers in a locally patched 0.8.3 crate, gated by an opt-in `recursion-phase-profile` feature. Use `Instant` for monotonic wall time and `clock_gettime(CLOCK_PROCESS_CPUTIME_ID)` at accounting-phase boundaries on Linux. Keep integer phase IDs, a stack, and bounded per-thread buffers; serialize after proof completion inside a separately timed `profile.flush`. Existing `tracing` is a dependency (`w2-083-Cargo-toml.md`), but C0 does not require a tracing subscriber, string formatting per event or instrumenting millions of cell operations. Feature-disabled calls compile away; the public compile/prove/deploy path remains usable without profiling tools.

**SOURCE — Clock and resource limits:** The process CPU clock includes all threads; a current-thread clock alone misses Rayon/BLST workers (`w2-linux-clock.md`). Process `ru_maxrss` is a lifetime high-water, not a resettable per-phase peak; Linux cgroup memory includes more than RSS and is not VRAM (`w2-cgroup-v2.md`, `w2-helper2-getrusage.md`). `/proc/PID/io` describes I/O, including storage-layer bytes, not all memory-controller traffic (`w2-linux-io.md`). These counters cannot substantiate an actual DRAM bandwidth claim.

**ESTIMATE — Wall conservation:** For isolated sequential baseline proofs, record coordinator/join-complete scopes. Set a phase's exclusive duration to its interval less the **union** of accountable direct-child intervals. A parallel MSM/NTT batch is one joined accounting scope; per-worker spans are diagnostic with `accounting=false`. Roll up mutually exclusive leaves plus their parents' exclusive residuals, never inclusive parents plus children. Set `unattributed=max(0,T−covered_union)`; report overlaps separately. Require `abs(sum(exclusive)−T)/T≤.05`, nonnegative exclusive times and `unattributed/T≤.05`. A catch-all `other` cannot hide missing hooks: enumerate named other tasks and also require their unexplained remainder ≤5%. Validate both create_proof and whole command boundaries. For B3, compilation, fixture, mock, process launch/exit, verification, sampler/flush and gaps are explicit command intervals. If future jobs overlap, critical-path union and per-resource demand replace summing job wall times.

**ESTIMATE — CPU attribution:** In the first profile mode, a process owns one proof at a time and no unrelated background work; nested CPU subtraction is valid only across properly nested join-complete scopes. Process CPU deltas include Rayon and BLST threads, with worker detail optional. Do not attach independent process-wide deltas to overlapping worker spans: that double counts. The factory command's process tree total comes from reaped child CPU / a dedicated cgroup `cpu.stat`, with sampler CPU reported separately. If isolation or task attribution fails, mark CPU scope `unattributable` and fail scheduler qualification. Future concurrent jobs require propagated task IDs and worker thread CPU accounting, or isolated per-job worker processes with their own measured key duplication; C0 baseline process deltas alone do not solve this.

**ESTIMATE — Memory:** Sample process RSS externally every 50 ms, plus entry/exit boundary observations; use smaps_rollup where available and record actual method/cost, falling back to proc status with a quality flag. For each phase record entry, exit, sampled maximum, `peak_delta=max(0,peak−entry)`, signed exit-entry, sample count and largest sampling gap. This is an **observed lower bound** on instantaneous RSS peaks; report lifetime `ru_maxrss` and, if available, cgroup `memory.peak` independently. A phase shorter than the sampling gap is explicitly unresolved for internal peaks. Never sum phase RSS deltas into a memory budget. Retained key/buffer bytes, allocator reserve, shared-memory ownership and future device allocations require their own lifecycle accounting before C5 admission. Unknown instantaneous peaks require conservative reserves or dedicated follow-up measurement, not a “fits” conclusion.

**ESTIMATE — Bytes moved:** Every phase has a `bytes` object. Instrument explicit copies/serialization/clone sites once per buffer, recording copied payload bytes and whether the counter is complete or partial. For known operations, aggregate `len×size_of::<T>()` without visiting elements: NTT input/output footprints, MSM scalar/base footprints, proof/SRS/key I/O. These are **logical payload/footprint counts**, not actual DRAM reads/writes; repeated cache-line traffic, FFT passes and allocator effects are not inferred. `dram_read/ write`, `h2d/d2h/d2d` are separate nullable counters with backend and coverage. CPU-only 0.8.3 has zero CUDA transfer bytes by declared backend, while DRAM bytes normally remain null. A later GPU pilot counts submitted copy sizes and uses completion events without injecting a sync at every timer; device busy intervals and VRAM reserved/live peaks are separate from host enqueue time. A bandwidth-based C7 or distributed-computation claim needs a separate supported PMU/CUPTI diagnostic run, including counter multiplexing/overhead, or an explicit ESTIMATE.

**ESTIMATE — Overhead bound:** The shipping target is an upper 95% confidence bound ≤1% for enabled versus disabled wall time, by workload and cache stratum. It is a target, not a measured property. Calibrate paired empty timer cost c, total emitted pair count N, sampler cost q at rate r, and flush cost F. Reject the chosen granularity unless `N*c/T + r*q + F/T ≤ .008`, leaving .002 for contention/other overhead. Illustrative budget only: T=100 s, N=50,000, c=5 µs, r=20/s, q=200 µs, F=.1 s gives `.0025+.004+.001=.0075` (0.75%). Small A2 calls need fewer diagnostics or aggregated transcript counters; preserve all top-level phases. No timer per scalar arithmetic operation: transcript accounting uses outermost calls or known sequential transcript blocks, with process CPU readings included in N*c. Coalesce adjacent calls if needed to meet the budget, while retaining distinct transcript ownership. If per-phase CPU remains unavailable, mark it null with a reason and leave resource qualification incomplete. The ≤1% criterion is never waived by subtracting an estimated observer cost from a result.

**ESTIMATE — Calibration protocol:** Compare pristine 0.8.3, patched-feature-off, and patched-feature-on release binaries with identical dependency resolution, compiler flags and verifier fixtures. Start with five paired ON/OFF repetitions (balanced AB/BA order); compute paired log ratios and a 95% upper bound with the prespecified reducer. If noise cannot distinguish 1%, report `inconclusive`, reduce cost or collect more repetitions only within factory caps. Event overflow, non-monotonic clocks, missing phase exits, sampler failure or absent verification invalidate the profile but must not change proof/transcript output; keep the failed receipt. No global cache dropping, wallet reset or deterministic production RNG is allowed.
