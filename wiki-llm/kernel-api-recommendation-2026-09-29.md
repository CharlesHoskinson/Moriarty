# Recommendation: land the Moriarty DeFi Kernel interface

**Status:** lead architecture recommendation, 2026-09-29. It is a conclusion from the [nine architect study](kernel-api-consensus-2026-09-29.md) and [independent research audit](kernel-api-audit-2026-09-29.md), not an adopted MIL/4 profile or a claim of native financial acceptance. The language's [product contract](../docs/MORIARTY-PRODUCT-CONTRACT.md) and [U0–U7 roadmap](../ROADMAP.md) control implementation order.

## Decisions recommended

| Decision | Recommendation | Reason and evidence |
| --- | --- | --- |
| Authority owner | Use **one Moriarty-signed authority**. The intent language owns constraints, consumption and accepted effects. The optional kernel receives that authority and may narrow it, never reinterpret or widen it. | The product contract requires direct use without a managed service. The [NEAR verifier](https://docs.near-intents.org/integration/verifier-contract/introduction) shows a concrete settlement boundary separate from routing and signing services; [Hyperliquid CoreWriter](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/hyperevm/interacting-with-hypercore) shows that a service acknowledgement can precede a financial effect. |
| API style | Adopt a **closed set of typed capability methods**: `validatePlan`, `reserve`, `buildCall`, `authorizeSign`, `dispatch`, `observe`, `reconcile`, and `recover`. Each method returns a typed receipt with operation and attempt IDs. An adapter advertises only action classes it can enforce and observe. | All nine memos converge on typed authority and distinct phase facts. A single `execute(bytes) -> success` loses recipient, fee, evidence and phase checks. See [ABI synthesis](kernel-api-consensus-2026-09-29.md#candidate-contract). |
| Signed bytes | **Reuse the language's versioned canonical signed intention** once U0/M4-C1/M4-C5 freezes it. Pin its exact bytes and digest in every kernel operation. Keep native chain transaction bytes under a separate pinned adapter codec. Do not create a second kernel-specific user-signature format. | This prevents two competing meanings of user authority. Existing `/3` review bytes are not silently changed to `/4` or CBOR; [MIL/4 M4-C1 and C5](../deliverables/mil4-successor-2026-09-29/DESIGN-MIL4-WORKING.md) already own those decisions. |
| Service transport | Use **versioned JSON with tagged records** for the first service RPC. Transport fields have no authority by themselves. If a new binary record is later needed, prefer a tightly restricted [RFC 8949 deterministic CBOR](https://www.rfc-editor.org/rfc/rfc8949.html#section-4.2) profile with independent cross-language vectors over a bespoke positional ABI. | JSON keeps the first interface inspectable and avoids adding a second canonicalization task to the critical path. The Sol and Opus ABI memos prefer restricted CBOR; Grok ABI recommends positional bytes. The byte decision is resolved for the first slice by leaving authority in Moriarty and native bytes in the adapter. |
| State and retry | Persist **an append-only fact journal** and derive status from separate authority, send, effect and recovery facts. Distinguish the logical economic effect ID from each send attempt and each venue-native effect ID. `unknown` is a durable outcome with outstanding duties. | A one-cell lifecycle cannot represent a queued action, partial delivery and unresolved send together. [Opus operations](../deliverables/kernel-api-architects-2026-09-29/opus-ops.md) adds destination-specific idempotency classes; [Grok operations](../deliverables/kernel-api-architects-2026-09-29/grok-ops.md) supplies the four-rail causal model. |
| Signing and fees | Default to **envelope-rooted narrowing grants**. A signing request names exact payload digest, domain, path, recipient, value, fee bound, nonce and key epoch. Fee sponsorship is a separate authority. Signatures, dispatch, inclusion and accepted effects have separate receipts. | The [Aeon signing probe](aeon-kernel-experiment-evidence-2026-09-29.md) caught selected field substitutions, but its native finality escape makes it authoring evidence only. [EIP-712](https://eips.ethereum.org/EIPS/eip-712) illustrates domain binding and explicitly leaves replay protection to the application. |
| Recovery | A timeout starts observation and reconciliation. A refund needs route-specific proof of terminal non-delivery or a complete final delivery count plus a signed trust premise that can exclude later delivery. Without that evidence, retain `unknown` and the reservation. | The [Aeon bridge probe](aeon-kernel-experiment-evidence-2026-09-29.md) rejected refund on timeout or zero observation. [IBC packet semantics](https://github.com/cosmos/ibc/blob/main/spec/core/ics-004-channel-and-packet-semantics/README.md) is a primary example of proof-bearing timeout. |
| First implementation | Qualify **one EVM ERC-20 transfer adapter on a public testnet** as the interface probe, then an **exact-input AMM swap** as the first DeFi action. The adapter must decode the submitted bytes independently, relate transaction and token effects to the signed leg, and retain ambiguity after a lost response. | A transfer exercises domain, asset, recipient, amount, gas/fee, signing, replay and finality with a small call shape. An AMM swap then exercises gross debit, fee and net-output acceptance against the [U3 financial discriminator](../ROADMAP.md#immediate-delivery-brief). Neither probe alone closes U5. |
| Runtime stack | For a TypeScript service, use [viem](https://github.com/wevm/viem) **inside the EVM adapter**, and a supported [PostgreSQL](https://www.postgresql.org/support/versioning/) release for reservations, attempts, outbox and evidence journal. Start with one plain worker. Add [Graphile Worker](https://worker.graphile.org/docs/requirements) only if scheduled reconciliation needs it and the Node version fits. | These are established open-source components with limited extra infrastructure. PostgreSQL handles concurrent durable state; a worker framework cannot supply native idempotency or finality. The first U5 runtime and measured load are still unverified, so package versions are selected at implementation time. |

## Priority and acceptance

1. **Publish the reviewed research as research.** Preserve the nine memos, sources, model receipts, dissent and audit. The files in this worktree are currently untracked; a research PR makes the conclusion reviewable without presenting it as adopted semantics.
2. **Finish the current language path.** The guarded SP01.6 status reports stale binding/candidate inputs, missing accounting and unavailable live resource state; `sp01-loan-report` is the allowed next action. Resolve that recorded blocker. U0–U3 then establish a direct signed financial stage and the `11 A` gross, `1 A` fee, `20 B` net discriminator before a hosted kernel can claim the same semantics.
3. **Freeze the minimum interface at one adapter.** Publish exact authority and native payload vectors, decoded field correspondence, a manifest pin, receipt/evidence schemas, and a direct Midnight comparison. Obtain the current consequential-design reviews on the exact frozen candidate.
4. **Demonstrate one actual external effect.** The public testnet trace must show signed bytes, durable pre-send attempt, submitted transaction, independently observed effect, accepted Moriarty continuation or explicit `unknown`, and hostile mutations for domain, recipient, fee, replay and late effect. Local fixture success and an Aeon type check are insufficient.
5. **Extend by conformance case.** The eight DeFi categories test the common language/kernel boundary. AMMs are the first financially useful extension; bridges require their own evidence and recovery qualification. No category receives a separate generic kernel or weaker acceptance rule.

**Release criterion:** an independent developer can express a supported intention, run it directly on Midnight, and use the optional kernel for an allowed external leg while the accepting verifier checks the same signed constraints and complete effects. A kernel outage or refusal leaves the direct path valid. U5's remaining federation, solver, OWS, x402 and epoch duties still require their separate [roadmap](../ROADMAP.md) evidence.
