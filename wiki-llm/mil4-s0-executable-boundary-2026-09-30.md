## Recommendation

Adopt the missing B01–B16 field relationships and verification sources before implementing a positive local consumer. The consumer must reject when agreement/action identity, selected program, asset scale, predecessor/head, source and Core hashes, signer/key relation, or nonce/replay scope are not authenticated. It must derive effects and footprint from the selected signed operation and authenticated pre-state, compare every submitted line and the field-26 commitment, then return a local comparison result with B17 atomic ledger consumption still pending. A caller-supplied matching hash cannot discharge those premises. The W-D2F plan is specified only and has no positive consumer execution.

The current mapping has concrete gaps: Source AST `programId` is an agreement name while Core intent `programId` is the selected action; `/3` has both actionId and coreProgramId. Source scale admits 18 while the wire/effect experiments admit 38. Source hash has no selected canonical image, and signed predecessor is not carried through Core preparation. The [W-D2F field map](../experiments/moriarty-language/formal/mil4/effect-consumer/FIELD-MAP.md) names B01–B17 and proposed first-failure behavior. These gaps block an honest full positive consumer. The [Sprint 2 inventory](../deliverables/mil4-k-quint-sprint1-2026-09-29/S2-ENTRY-INVENTORY.md) lists the shared language work that follows the S0 gate.

The [MIL/4 S0 decision sequence](../deliverables/mil4-k-quint-sprint1-2026-09-29/NEXT-DECISIONS.md) recommends strict nominal identities (W-D2G), separate noncircular Source/Core/policy images (W-D2H), and a direct Core consumer that uses verified complete replay history (W-D2F). Each specified design has two bounded reviews. The executable image codec and Source/6 adapter also have two bounded reviews each. These are still proposed choices and local content experiments, not adopted W-D2 rules or positive authenticated executions.
