# AgentBus design and DoctorWatson integration — October 22, 2026

Status: source implementation with observed synthetic validation; source publication and live activation remain distinct evidence. This dated `wiki-llm` research/design record does not replace the canonical `wiki/` provenance ledger, DoctorWatson execution records or Moriarty product gates.

The user selected a shared ProjectFenrir AgentBus implementation with a thin Moriarty adapter and practical agent instructions. The existing source uses MQTT 5, signed Ed25519 `did:key` envelopes, issuer credentials, a local SQLite inbox and transactional run-local claim arbitration. The source-only graph audit is preserved under `.moriarty-dev/runtime/doctorwatson-workflow-review-20261022/research/agentbus/graph/`; it did not inspect user keys or activate services.

The bounded refinement preserves that architecture. It repairs finite transport callback/operation state, strict JSON/JWT/IDP parsing, local persistence and arbiter acknowledgement bookkeeping; adds optional original-acquisition `hold` guards; and retires identities without deleting user work. An external identity binding allows context/review helpers to share an existing checkout. These are source behavior changes with synthetic test predicates; they do not establish release or observed host installation.

Claims remain run-local and advisory. All agents coordinating a shared mutation use one explicitly assigned run. A global cross-run lock would require a larger authorization/state/migration design and was not selected. Optional token omission preserves old callers, so stale-token protection is asserted only for supplied tokens. A current token is not filesystem fencing or permission to edit. Checks before shared mutation/handoff and canonical ownership remain necessary.

The shared transport acknowledges a broker hop. It does not prove recipient persistence, agent action, review or task completion. The existing broker template has memory-backed sessions, and a restart can lose queued undelivered traffic. No automatic ambiguous-command resend, durable producer replay service or broker migration was added. MQTT's normative QoS 1 contract permits duplicates and describes delivery per sender/receiver hop; application event IDs and canonical task correlation therefore remain necessary. [OASIS MQTT 5.0, sections 4.1 and 4.3.2](https://docs.oasis-open.org/mqtt/mqtt/v5.0/os/mqtt-v5.0-os.html).

Moriarty's [thin adapter](../models/doctorwatson/agentbus_adapter.py) validates `doctorwatson.agentbus.advisory/1` notices, stable event IDs and run/task/attempt/source/base/sender correlation. A current advisory requests only canonical inspection. It cannot dispatch, adopt reviews, complete tasks, close EARS or authorize deletion. Publishing can be disabled/unavailable without canonical mutation. Claim ownership is validated before effects; partial receipts remain explicit. Cleanup projection always emits `leases_known=false` and adds positive retention only. Empty/stale/expired bus observations never establish inactive user work.

The [operational guide](../docs/AGENTBUS.md) separates assigned task startup from setup and source-only review. Shared AgentBus README/SKILL/brief and DoctorWatson explanation separate the task loop, command reference and design limits, following the practical distinction between goal-directed how-to guidance, reference, tutorials and explanation. [Official Diátaxis application guide](https://diataxis.fr/application/). Reading the guide never itself authorizes live runtime access, identity provisioning, service changes or messages to others.

DIDs provide key attribution, not proof of model/vendor identity or an OS isolation boundary. A shared Unix account can access that account's files; lint/redaction only rejects selected patterns. Credentials, recovery material and private proof data must remain outside messages, references, logs and source control.

The shared OpenSpec amendment contains twelve EARS requirements with directed scenarios and a traceability matrix. Offline tests use temporary roots, fake transports and synthetic identities; the bounded Quint model and fuzz harness test selected abstractions/oracles. Model checking is not implementation correspondence. Observed refinement checks are 177 shared offline tests, 264 Moriarty factory/adapter tests, 35 Quint test definitions / 332 trials, 11,000 sampled traces, bounded safety depths 4 and 6, and the full finite fuzz campaign. [Portable results and source pins](https://github.com/CharlesHoskinson/projectfenrir/blob/main/tools/agentbus/docs/audit/refinement-20261022/RESULTS.json) give exact scope and limits; historical tests or checked task lists are not fresh acceptance. Native/proof/wallet work remains outside this refinement and all existing Moriarty financial, target and proof gates remain unchanged.

The [existing DoctorWatson workflow and recursion audit](doctorwatson-workflow-review-2026-10-22.md) and [cycle finalization contract](../docs/DOCTORWATSON.md#cycle-finalization--october-22-2026) remain the workflow context.
