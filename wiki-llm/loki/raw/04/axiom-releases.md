[v0.5.3](/axiom-crypto/halo2-lib/tree/v0.5.3)

[`c54cbac`](/axiom-crypto/halo2-lib/commit/c54cbac60da598e8e484b8aea858e0bf3c51a857)

Published to crates.io:

* `halo2-base@v0.5.3`
* `halo2-ecc@v0.5.3`

This release contains validation and correctness fixes for range checks, SafeType byte packing, Poseidon compact inputs, non-native field operations, and elliptic curve identity handling.

* range comparison checks now require native-field headroom, and range division rejects parameter choices that can wrap in the native field
* range lookups now fail synthesis if lookup cells were queued without a configured range lookup table
* SafeType byte packing, compact Poseidon input rows, `FpChip` limb parameters, field equality operands, and MSM scalar vectors now get stricter validation
* EC sums and cyclotomic decompression now handle identity inputs correctly
* `halo2-base` and `halo2-ecc` are bumped to v0.5.3
* README and range comparison docs are updated

**Full Changelog**: [v0.5.2...v0.5.3](https://github.com/axiom-crypto/halo2-lib/compare/v0.5.2...v0.5.3)

[`47ce225`](/axiom-crypto/halo2-lib/commit/47ce225b085b8dd0f2ab22f4adb3d1a24fc09b4c)

Published to crates.io:

* `halo2-base@v0.5.0`
* `halo2-ecc@v0.5.0`
* `zkevm-hashes@0.3.0`

The crates now support stable Rust with MSRV 1.73.0. The default toolchain is switched to 1.85.1.

* `div_ceil` is now stable, so we use it
* BREAKING CHANGE: `SafeUint` type alias removed due to limitations of stable const generics
* BREAKING CHANGE: some `From` implementations for `FixLenBytes` removed due to limitations of stable const generics.
