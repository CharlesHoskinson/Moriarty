Impeller Halo2 integration
==========================

This fork integrates the [Impeller compiler and runtime](https://github.com/SJTU-Liquid/Impeller) with Halo2 proof generation. It is the Halo2 implementation used in the ASPLOS 2027 paper **Impeller: Scalable and Efficient Zero-Knowledge Proof Computation Framework via Graph Compilation** by Liukun Yu\*, Xinwei Qiang\*, Shixuan Sun, Chen Chen, Jingwen Leng, and Jin Dong (\* equal contribution). Its `zkpoly-compiler` submodule is pinned to the matching compiler commit.

The compiler reuses GPU kernels from [FluxZK](https://github.com/SJTU-Liquid/FluxZK), the artifact for the SC 2026 paper [**FluxZK: Scalable and Efficient Zero-Knowledge Proof Computation via GPU Acceleration**](https://sc26.conference-program.com/presentation/?id=pap593&sess=sess231). See Impeller's third-party notices for code provenance and licenses.

This release starts from `tie-pilot-qxw/halo2` commit `cdaf83b54cd690b65e38ee28dcd1be7cb86b19ee` (`artifect-evaluation`).

Rust toolchain
--------------

This release pins Rust nightly `2025-09-20` in `rust-toolchain`. The debugging components use unstable features.

Dependencies Not Managed by Cargo
---------------------------------

Cargo is powerful, but not omnipotent.

CUDA Toolkit 12.8 was used for the paper evaluation; other versions have not been validated for this release.

Secondly, most of the CUDA compilation is managed by [`xmake`](https://xmake.io).
Follow the instructions on its homepage and have the `xmake` binary available on `PATH`.

Usage
-----

First clone this repository and initialize the `zkpoly-compiler` submodule:

```
git clone --recurse-submodules https://github.com/SJTU-Liquid/halo2.git halo2
cd halo2
```

Then, point your dependency of `halo2_proofs` in your Cargo.toml to this repository:

```
[dependencies]
halo2_proofs = { path = <path to this repository>/halo2_proofs }
```

However, to wield the power of GPU acceleration, some modifications to your original
calls of `create_proof` must be made.
Specifically, replace it with `halo2_proofs::plonk::jit::create_proof_gpu`,
passing a unique identifier for each circuit.
The identifier caches compilation artifacts when you create proofs for the same circuit
with different inputs (or instances, in Halo2 terms),
and it is necessary because there is no guarantee that we can tell different circuits just from their type name.

For details on the `halo2_proofs::plonk::jit` module, build its documentation by running

```
cd halo2_proofs
cargo doc --open
```

and navigate to the `jit` module.

Finally, remember to set `ZKPOLY_COMPILER_PROJECT_ROOT` to `<path to this repository>/zkpoly-compiler`
since it contains some CUDA code that needs to be compiled during runtime.
